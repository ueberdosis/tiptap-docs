Block elements define the structural layout of a document: quoted passages, preformatted code, visual dividers, and line breaks. All are included in StarterKit. Support varies across the pipeline.

## What you need

- **Extensions:** `StarterKit` (includes `Blockquote`, `CodeBlock`, `HorizontalRule`, and `HardBreak`)
- **Configuration:** None required. Page breaks require a separate extension and are covered on their [own page](/conversion/content-types/page-layout/page-breaks).
- **Integration paths:** Import and export work identically via both the [editor extension](/conversion/import/docx/editor-extension) and [REST API](/conversion/import/docx/rest-api).

## Support overview

| | Import | Editor | Export |
| --- | --- | --- | --- |
| Blockquote | Supported | Supported (StarterKit) | Supported |
| Code block | Not supported | Supported (StarterKit) | Supported (editor extension) |
| Horizontal rule | Supported | Supported (StarterKit) | Supported |
| Hard break | Supported | Supported (StarterKit) | Supported |
| Page break | See [Page breaks](/conversion/content-types/page-layout/page-breaks) | | |

## Blockquote

In Word, blockquotes are paragraphs with a "Quote" style (matched case-insensitively).

The import produces a `blockquote` node wrapping one or more `paragraph` children. Inline formatting inside the quote is preserved.

The export writes paragraphs with the "Quote" style back to DOCX. Blockquotes round-trip correctly.

A quote can hold other blocks, such as lists, code blocks, images, tables, rules and nested quotes. The editor extension keeps them inside the quote. With [computed styles](/conversion/export/docx/computed-styles), which are on by default, each block in a quote keeps the colors, borders and spacing of its own quote:

- Paragraphs, headings and images that follow each other in a quote share one box, so Word draws one border and background around them.
- Lists and rules in a quote get no extra space around them.
- A code block or nested quote at the start or end of a quote keeps the space above or below the quote.
- Two quotes next to each other stay two separate boxes in Word.

**Extension:** [`Blockquote`](/editor/extensions/nodes/blockquote) (StarterKit) | **Shortcut:** Cmd+Shift+B

## Code block

The DOCX import does not map any Word style to `codeBlock` nodes. Code blocks are available in the editor via StarterKit.

The [DOCX export editor extension](/conversion/export/docx/editor-extension) writes each `codeBlock` node as one paragraph in the "Code block" style (`CodeBlock`):

- Line breaks, blank lines, tabs and spaces at the start or end of a line stay as they are. Word line breaks separate the lines.
- With [computed styles](/conversion/export/docx/computed-styles), the `CodeBlock` style takes the font, padding and background that the editor shows for code blocks. The padding stays inside the background, so the text does not touch the edge of a dark block.
- Syntax highlighting colors stay, because the export keeps the highlighting that the editor draws in code blocks.
- Without computed styles, the style uses Courier New.

A custom node renderer or `customNodeDsl` rule for `codeBlock` still wins over this conversion.

<Callout variant="warning" title="Code blocks do not round-trip">
  The import does not create `codeBlock` nodes, so an exported code block comes back as a paragraph. If your workflow requires round-tripping code blocks, register a custom node handler on the import side.
</Callout>

**Extension:** [`CodeBlock`](/editor/extensions/nodes/code-block) (StarterKit) | **Shortcut:** Cmd+Alt+C

## Horizontal rule

Horizontal rules in Word are typically VML shapes (`v:rect` with `o:hr` attributes, `v:line` elements). The import detects these and creates `horizontalRule` nodes.

The export produces valid Word horizontal rules using VML shapes. Horizontal rules round-trip correctly.

**Extension:** [`HorizontalRule`](/editor/extensions/nodes/horizontal-rule) (StarterKit) | **Input rules:** `---`, `___`, `***`

## Hard break

A hard break (Shift+Enter) creates a new line within the same paragraph. In Word this is a `<w:br/>` element. Hard breaks round-trip correctly.

**Extension:** [`HardBreak`](/editor/extensions/nodes/hard-break) (StarterKit) | **Shortcut:** Shift+Enter

## Export

| Element | DOCX output |
| --- | --- |
| Blockquote | Paragraphs with "Quote" style |
| Code block | One paragraph with the "Code block" style and `<w:br/>` line breaks (editor extension) |
| Horizontal rule | VML horizontal rule shape |
| Hard break | `<w:br/>` within a text run |
| Page break | See [Page breaks](/conversion/content-types/page-layout/page-breaks) |
