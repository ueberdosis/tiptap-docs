Block elements define the structural layout of a document: quoted passages, preformatted code, visual dividers, and line breaks. All are included in StarterKit. Support varies across the pipeline.

## What you need

- **Extensions:** `StarterKit` (includes `Blockquote`, `CodeBlock`, `HorizontalRule`, and `HardBreak`)
- **Configuration:** None required. Page breaks require a separate extension and are covered on their [own page](/conversion/content-types/page-layout/page-breaks).
- **Integration paths:** Use the [import editor extension](/conversion/import/docx/editor-extension), [export editor extension](/conversion/export/docx/editor-extension), or REST API. Browser style capture and the code block export described below apply to the export editor extension.

## Support overview

|                 | Import                                                               | Editor                 | Export                            |
| --------------- | -------------------------------------------------------------------- | ---------------------- | --------------------------------- |
| Blockquote      | Supported                                                            | Supported (StarterKit) | Supported                         |
| Code block      | Not supported                                                        | Supported (StarterKit) | Supported by the editor extension |
| Horizontal rule | Supported                                                            | Supported (StarterKit) | Supported                         |
| Hard break      | Supported                                                            | Supported (StarterKit) | Supported                         |
| Page break      | See [Page breaks](/conversion/content-types/page-layout/page-breaks) |                        |                                   |

## Blockquote

In Word, blockquotes are paragraphs with a "Quote" style (matched case-insensitively).

The import produces a `blockquote` node wrapping one or more `paragraph` children. Inline formatting inside the quote is preserved.

The export writes paragraphs with the "Quote" style back to DOCX. Blockquotes round-trip correctly.

The editor extension also keeps nested lists, headings, code blocks, tables, images, and quotes inside a blockquote. Each block keeps its own conversion rules. With [Document styles](/conversion/export/docx/document-styles), quote paragraphs can keep the displayed border, background, padding, and spacing. A quote made of several paragraphs shares those decorations across the group.

**Extension:** [`Blockquote`](/editor/extensions/nodes/blockquote) (StarterKit) | **Shortcut:** Cmd+Shift+B

## Code block

The editor extension exports a `codeBlock` as a paragraph with the `CodeBlock` style. The default style uses a monospace font. The exporter keeps line breaks, empty lines, spaces, and tabs, including Windows line endings. With [Document styles](/conversion/export/docx/document-styles), it also reads supported syntax colors and the code block's displayed formatting.

Code blocks can appear inside lists, quotes, and table cells. A code block after a list item's paragraph does not add another bullet, number, or checkbox. Adjacent code blocks remain separate. You can replace the default appearance through `styleOverrides`, `paragraphOverrides`, or `textRunOverrides`. A custom `codeBlock` rule in `customNodes` or `customNodeDsl` takes priority over the built-in converter.

<Callout variant="info" title="Export support does not add import support">
  The DOCX importer does not map Word styles to `codeBlock` nodes. Exporting code does not make it a
  code block when imported again. If you need that round trip, add an import handler for the Word
  style you use.
</Callout>

**Extension:** [`CodeBlock`](/editor/extensions/nodes/code-block) (StarterKit) | **Shortcut:** Cmd+Alt+C

## Horizontal rule

Horizontal rules in Word are typically VML shapes (`v:rect` with `o:hr` attributes, `v:line` elements). The import detects these and creates `horizontalRule` nodes.

The export produces valid Word horizontal rules using VML shapes. Horizontal rules round-trip correctly.

**Extension:** [`HorizontalRule`](/editor/extensions/nodes/horizontal-rule) (StarterKit) | **Input rules:** `---`, `___`, `***`

## Hard break

A hard break (Shift+Enter) creates a new line within the same paragraph. In Word this is a `<w:br/>` element. Hard breaks round-trip correctly.

**Extension:** [`HardBreak`](/editor/extensions/nodes/hard-break) (StarterKit) | **Shortcut:** Shift+Enter

## Page break
