Footnotes and endnotes store extra information outside the document body. The DOCX import API returns their content as separate Tiptap JSON documents. [Pages](/pages/getting-started/overview) can display and edit the notes, and the DOCX export editor extension writes them as Word notes.

## Support overview

|           | Import                               | Editor                                            | DOCX editor export |
| --------- | ------------------------------------ | ------------------------------------------------- | ------------------ |
| Footnotes | REST response and extension callback | [Pages footnotes](/pages/core-concepts/footnotes) | Supported          |
| Endnotes  | REST response and extension callback | [Pages endnotes](/pages/core-concepts/endnotes)   | Supported          |

## Import

The [REST API](/conversion/import/docx/rest-api) returns `footnotes` and `endnotes` maps keyed by note ID. The [import editor extension](/conversion/import/docx/editor-extension#footnotes--endnotes) exposes the same maps in its `onImport` context.

Each map value is a Tiptap document with `type: 'doc'` and a `content` array. The body contains `footnoteReference` and `endnoteReference` nodes. Their `noteId` attributes link to the matching map entries.

When you call the import context's `setEditorContent()`, the extension applies the maps to Pages if the matching note feature is enabled. Without Pages, keep the maps alongside your document and provide your own reference nodes and note display. See the [invalid schema guide](/guides/invalid-schema) if your editor schema does not include the imported references.

## Editor

Enable `footnotes` or `endnotes` in `Pages.configure()`. Pages adds the reference nodes and provides editors for note content. Read the [footnote guide](/pages/core-concepts/footnotes) and [endnote guide](/pages/core-concepts/endnotes) for setup, storage, and editing commands.

Save the note maps with the body document. The body contains references, while `editor.storage.pages.footnotesJSON` and `editor.storage.pages.endnotesJSON` contain the note documents.

## Export

The [DOCX export editor extension](/conversion/export/docx/editor-extension) reads the note maps from Pages automatically. You can also pass `footnotes` and `endnotes` maps in the export options, including when you use `exportDocx()` on the server. Explicit maps take priority over Pages storage.

Each reference needs a matching note ID in its map. The exporter writes referenced notes in their first-reference order. Repeated references share the same note, and notes without a body reference do not appear in the exported file.

Notes use the normal block converters. They can contain paragraphs, lists, tables, images, and custom content that produces paragraphs or tables. If a note starts with a table, the exporter adds an empty first paragraph for Word's note reference.

With `documentStyles` enabled in a mounted browser editor, the exporter reads each displayed note's styles. Custom formatting takes priority. List numbering and supported tracked changes also pass through note conversion. Automatic font embedding can include fonts and characters used only in notes.

## Limits

Pages and Word calculate note placement separately. Word can move a note or continue it on another page when it lays out the exported document. The exporter does not guarantee the same page breaks as the editor.

Reading displayed note styles requires a matching Pages preview or active note editor. Server-side export uses the JSON and the styles you provide. Unsupported custom nodes need an export renderer, just as they do in the document body.
