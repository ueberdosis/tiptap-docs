The DOCX import extracts footnote and endnote content from imported documents. The [REST API](/conversion/import/docx/rest-api) returns it as `footnotes` and `endnotes` fields. The import [editor extension](/conversion/import/docx/editor-extension) passes the same fields to `onImport` and, with Pages, applies them to the editor. The [Pages extension](/pages/core-concepts/footnotes) renders footnotes and endnotes in the editor, and the DOCX export writes them as Word footnotes and endnotes.

## Support overview

| | Import | Editor | Export |
| --- | --- | --- | --- |
| Footnotes | Supported (REST API and editor extension, applied with Pages) | [Pages footnotes](/pages/core-concepts/footnotes) | Supported |
| Endnotes | Supported (REST API and editor extension, applied with Pages) | [Pages endnotes](/pages/core-concepts/endnotes) | Supported |

## Import

The [REST API](/conversion/import/docx/rest-api) and the import [editor extension](/conversion/import/docx/editor-extension) both return footnote and endnote data. The editor extension passes it to `onImport`, and with the Pages extension registered it also applies it to the editor.

The REST API extracts footnotes and endnotes from the DOCX and returns them as `footnotes` and `endnotes` fields in the response, keyed by note ID. Inline references in the body text are represented as `footnoteReference` and `endnoteReference` nodes with a `noteId` attribute.

<Callout variant="warning" title="Without Pages, references need a custom extension">
  Without the Pages extension, the `footnoteReference` and `endnoteReference` nodes in the body text require a [custom extension](/editor/extensions/custom-extensions/extend-existing) to render in the editor. See the [invalid schema guide](/guides/invalid-schema) for strategies.
</Callout>

Each footnote and endnote value is a Tiptap JSON document (`{ type: "doc", content: [...] }`). How you use this data is up to you. Some options include appending the notes as a numbered list at the end of the document, rendering them in a custom sidebar, or storing them for later use.

## Editor

The [Pages extension](/pages/getting-started/overview) renders footnotes and endnotes. Turn them on with `footnotes: { enabled: true }` and `endnotes: { enabled: true }`. Pages then handles the `footnoteReference` and `endnoteReference` nodes and shows the note content. See [Footnotes](/pages/core-concepts/footnotes) and [Endnotes](/pages/core-concepts/endnotes).

Without Pages, the editor schema has no node type for footnote references. You would need a custom extension that handles `footnoteReference` and `endnoteReference` nodes and shows the note content.

## Export

Export footnotes and endnotes using the [editor extension](/conversion/export/docx/editor-extension) or the [REST API](/conversion/export/docx/rest-api). A `footnoteReference` or `endnoteReference` node becomes a Word note when its `noteId` has an entry in the note content. The export leaves out references without content.

The editor extension takes the note content from Pages when Pages footnotes or endnotes are on. Pass the `footnotes` and `endnotes` options to set the content yourself. Each is an object keyed by note id, and each value is a Tiptap JSON document. The REST API takes the same shape in its [`footnotes` and `endnotes` fields](/conversion/export/docx/rest-api#footnotes-and-endnotes).

The editor extension keeps the content of a note:

- Tables and lists in a note export as Word tables and lists, with their numbering and start numbers.
- Two tables next to each other in a note stay two tables.
- With `repeatTableHeaderRows` on, the header rows of a table in a note get Word's "Repeat as header row" property.
- A note that starts with a table gets an empty first paragraph, because Word puts the note number in the first paragraph.

## Workarounds

If your workflow requires footnote-like content in the editor and exported documents but you do not use Pages, consider these alternatives:

- **Inline parenthetical notes**: Convert footnote content to parenthetical text within the body. This survives the full round-trip.
- **Endnote section**: Append a manually maintained "Notes" section at the end of the document using regular paragraphs and numbered text.
- **Custom handling**: Use the import callback to extract footnote data, store it alongside your document, and inject it back during a custom export step.
