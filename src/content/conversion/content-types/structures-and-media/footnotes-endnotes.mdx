## Support overview

| | Import | Editor | Export |
| --- | --- | --- | --- |
| Footnotes | Editor extension and REST API | [Pages footnotes](/pages/core-concepts/footnotes) | DOCX editor extension only |
| Endnotes | Editor extension and REST API | [Pages endnotes](/pages/core-concepts/endnotes) | DOCX editor extension only |

## Import

Both the [editor extension](/conversion/import/docx/editor-extension#footnotes-and-endnotes) and the [REST API](/conversion/import/docx/rest-api) return footnote and endnote data. The editor extension passes it to the `onImport` callback as `context.footnotes` and `context.endnotes`, and applies it automatically when Pages has footnotes or endnotes enabled.

The REST API extracts footnotes and endnotes from the DOCX and returns them as `footnotes` and `endnotes` fields in the response, keyed by note ID. Inline references in the body text are represented as `footnoteReference` and `endnoteReference` nodes with a `noteId` attribute.

<Callout variant="warning" title="Without Pages, references need a custom extension">
  Without Pages, the `footnoteReference` and `endnoteReference` nodes in the body text require a [custom extension](/editor/extensions/custom-extensions/extend-existing) to render in the editor. See the [invalid schema guide](/editor/guides/invalid-schema) for strategies.
</Callout>

Each footnote and endnote value is a Tiptap JSON document (`{ type: "doc", content: [...] }`). How you use this data is up to you. Some options include appending the notes as a numbered list at the end of the document, rendering them in a custom sidebar, or storing them for later use.

## Editor

The [Pages extension](/pages/getting-started/overview) renders [footnotes](/pages/core-concepts/footnotes) and [endnotes](/pages/core-concepts/endnotes): markers in the body, footnote content in per-page areas, and endnotes at the end of the document. Without Pages, there is no node or mark type for footnote references or footnote content.

To render footnotes without Pages, build a custom extension that handles `footnoteReference` and `endnoteReference` node types and provides a UI for displaying the note content.

## Export

The [DOCX export editor extension](/conversion/export/docx/editor-extension) writes footnotes and endnotes as real Word notes. It takes them from Pages automatically, or from its `footnotes` and `endnotes` options. The [REST API](/conversion/export/docx/rest-api) does not export them yet.

## Workarounds

If your workflow requires footnote-like content in the editor and exported documents, consider these alternatives:

- **Inline parenthetical notes**: Convert footnote content to parenthetical text within the body. This survives the full round-trip.
- **Endnote section**: Append a manually maintained "Notes" section at the end of the document using regular paragraphs and numbered text.
- **Custom handling**: Use the import callback to extract footnote data, store it alongside your document, and inject it back during a custom export step.
