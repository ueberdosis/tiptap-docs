Word stores equations as OMML (Office Math Markup Language). Tiptap uses LaTeX notation rendered by KaTeX. The conversion pipeline currently supports export but not import.

## What you need

- **Extensions:** `@tiptap/extension-mathematics` (not in StarterKit)
- **Dependencies:** `katex` (`^0.16.4`) for rendering

```bash
npm install @tiptap/extension-mathematics katex
```

## Support overview

|             | Import        | Editor                   | Export                 |
| ----------- | ------------- | ------------------------ | ---------------------- |
| Inline math | Not supported | Supported (`inlineMath`) | Editable Word equation |
| Block math  | Not supported | Supported (`blockMath`)  | Editable Word equation |

## Import

Math equations are not imported on either the [editor extension](/conversion/import/docx/editor-extension) or the [REST API](/conversion/import/docx/rest-api).

<Callout variant="warning" title="Math equations are not imported from DOCX">
  The import converter has no OMML handling. Math elements in the DOCX XML are not recognized by the
  parser and are not included in the output. No math nodes appear in the output. If your documents
  contain equations, they will be missing from the imported Tiptap document.
</Callout>

The DOCX import converter does not include any OMML parsing. When the parser encounters math markup in the document XML, it does not recognize the elements and skips them entirely. No `inlineMath` or `blockMath` nodes are produced.

If your workflow requires importing math from DOCX, you would need to build OMML parsing and OMML-to-LaTeX conversion from scratch. There is no existing math infrastructure in the import converter to extend.

## Editor rendering

The [`Mathematics`](/editor/extensions/nodes/mathematics) extension provides two node types. It is not included in StarterKit.

The extension provides:

- **`inlineMath`** renders within text. Type `$$E = mc^2$$` to create via input rule.
- **`blockMath`** renders as a standalone block. Type `$$$\sum_{i=1}^{n} x_i$$$` to create via input rule.

Both store content as LaTeX strings in a `latex` attribute and render using KaTeX.

```ts
import { Mathematics } from '@tiptap/extension-mathematics'
import 'katex/dist/katex.min.css'

const editor = new Editor({
  extensions: [StarterKit, Mathematics],
})
```

Without the Mathematics extension, math nodes are not recognized by the schema. See the [invalid schema guide](/guides/invalid-schema).

## Export

Export math equations using the [editor extension](/conversion/export/docx/editor-extension) or the [REST API](/conversion/export/docx/rest-api). The editor extension can read the equation rendered by KaTeX. A JSON-only export uses the node's LaTeX instead.

The editor extension looks for MathML in the mounted `inlineMath` or `blockMath` node view. It converts supported MathML into Word equations that the reader can edit. This can also preserve a custom macro after KaTeX has expanded it into a supported equation shape.

Supported rendered shapes include text, numbers, operators, fractions, square roots, indexed roots, subscripts, superscripts, combined subscripts and superscripts, brackets, and matrices with equal column counts. The exporter checks the MathML before using it. Unsupported elements, attributes, or layouts make it fall back to the source LaTeX.

With [Document styles](/conversion/export/docx/document-styles), the editor extension also reads equation font size, color, and block alignment. Setting `documentStyles: false` turns off those measured styles but still allows rendered MathML content and colors declared inside the equation. This browser capture does not apply to a REST request.

If rendered MathML is unavailable or unsupported, the exporter reads the `latex` attribute and uses the LaTeX converter. A server-side export has no editor node view and uses this path too.

Supported LaTeX features:

| LaTeX                            | OMML output                 |
| -------------------------------- | --------------------------- |
| `\frac{a}{b}`                    | Fraction                    |
| `\sqrt{x}`, `\sqrt[n]{x}`        | Radical                     |
| `x^{2}`                          | Superscript                 |
| `x_{i}`                          | Subscript                   |
| `\begin{matrix}...\end{matrix}`  | Matrix                      |
| Greek letters, operators, arrows | Unicode via 200+ symbol map |

The editor extension's LaTeX parser handles nested groups in fractions, roots, and scripts, including escaped braces and spaces before an argument. If it cannot parse an equation, the exporter writes the original LaTeX as plain math text instead of dropping it.

<Callout variant="info" title="LaTeX coverage is not exhaustive">
  The LaTeX converter supports common notation, not every LaTeX command or environment. A custom
  macro can work through the editor's rendered MathML, but the source LaTeX fallback does not expand
  custom macros. Complex alignment or unsupported MathML can still use the fallback. Check your
  equations in the exported Word file.
</Callout>

`blockMath` nodes export as a standalone paragraph containing a math element. `inlineMath` nodes export as math elements within the parent paragraph alongside regular text runs.
