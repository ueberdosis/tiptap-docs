Word stores equations as OMML (Office Math Markup Language). Tiptap uses LaTeX notation rendered by KaTeX. The conversion pipeline currently supports export but not import.

## What you need

- **Extensions:** `@tiptap/extension-mathematics` (not in StarterKit)
- **Dependencies:** `katex` (`^0.16.4`) for rendering

```bash
npm install @tiptap/extension-mathematics katex
```

## Support overview

| | Import | Editor | Export |
| --- | --- | --- | --- |
| Inline math | Not supported | Supported (`inlineMath`) | Supported (LaTeX to OMML) |
| Block math | Not supported | Supported (`blockMath`) | Supported (LaTeX to OMML) |

## Import

Math equations are not imported on either the [editor extension](/conversion/import/docx/editor-extension) or the [REST API](/conversion/import/docx/rest-api).

<Callout variant="warning" title="Math equations are not imported from DOCX">
  The import converter has no OMML handling. Math elements in the DOCX XML are not recognized by the parser and are not included in the output. No math nodes appear in the output. If your documents contain equations, they will be missing from the imported Tiptap document.
</Callout>

The DOCX import converter does not include any OMML parsing. When the parser encounters math markup in the document XML, it does not recognize the elements and skips them entirely. No `inlineMath` or `blockMath` nodes are produced.

If your workflow requires importing math from DOCX, you would need to build OMML parsing and OMML-to-LaTeX conversion from scratch. There is no existing math infrastructure in the import converter to extend.

## Editor rendering

The [`Mathematics`](/editor/extensions/nodes/mathematics) extension provides two node types. It is not included in StarterKit.

The extension provides:

- **`inlineMath`** renders within text. Type `$$E = mc^2$$` to create via input rule.
- **`blockMath`** renders as a standalone block. Type `$$$\sum_{i=1}^{n} x_i$$$` to create via input rule.

Both store content as LaTeX strings in a `latex` attribute and render using KaTeX.

```ts
import { Mathematics } from '@tiptap/extension-mathematics'
import 'katex/dist/katex.min.css'

const editor = new Editor({
  extensions: [
    StarterKit,
    Mathematics,
  ],
})
```

Without the Mathematics extension, math nodes are not recognized by the schema. See the [invalid schema guide](/guides/invalid-schema).

## Export

Export math equations using the [editor extension](/conversion/export/docx/editor-extension) or the [REST API](/conversion/export/docx/rest-api). Both convert LaTeX to OMML. This section describes the editor extension.

The export writes each `inlineMath` and `blockMath` node as a Word equation.

When the Mathematics extension shows the equation in the editor, the `exportDocx` command converts the MathML that KaTeX renders. So macros from `katexOptions.macros` export as the math they stand for. With [computed styles](/conversion/export/docx/computed-styles), the equation also keeps the font size and color that the editor shows, and a block equation keeps its alignment, margin, padding and background.

The export converts the LaTeX in the `latex` attribute instead when it has no rendered equation, for example on a server, in a headless editor or when you call the `exportDocx` function yourself. It also converts the LaTeX when KaTeX shows an error, or when the rendered MathML holds something that the export does not support.

These LaTeX features export as Word math:

| LaTeX | OMML output |
| --- | --- |
| `\frac{a}{b}`, also nested | Fraction |
| `\sqrt{x}`, `\sqrt[n]{x}`, also nested | Radical |
| `x^{2}`, `x_{i}`, `x_i^2` | Superscript, subscript or both |
| `\begin{matrix}...\end{matrix}`, `pmatrix` | Matrix |
| `\begin{cases}...\end{cases}` | Matrix in a brace |
| `\begin{aligned}...\end{aligned}` | Matrix or equation array |
| `\hat{x}`, `\overline{AB}` | Accent or bar |
| `\underbrace{a+b}_{c}`, `\overbrace{a+b}^{n}` | Brace below or above |
| `\boxed{x}` | Box |
| `\left( ... \right)` | Brackets that grow with their content |
| `\mathbb`, `\mathcal`, `\mathfrak`, `\mathsf`, `\mathtt` | Word math font: double-struck, script, fraktur, sans-serif or monospace |
| `\,` | Thin space |
| `f'` | Prime |
| Greek letters, operators, arrows, and number sets such as `\mathbb{R}`, also in scripts | Symbols |

When the export cannot convert part of a formula, that part appears as text in the Word equation. An unknown command such as `\unknown{x}` shows as `unknown{x}`. A formula that converts to nothing, such as `\label{eq}`, also shows its command text, here `label{eq}`. A formula nested more than 256 levels deep keeps its LaTeX source as the text of the equation.

<Callout variant="info" title="LaTeX coverage is not exhaustive">
  The converter supports common mathematical notation. A custom environment, or a macro that the editor does not render, may not convert perfectly. Test your specific equations before relying on export for production workflows.
</Callout>

`blockMath` nodes export as a standalone paragraph containing a math element. `inlineMath` nodes export as math elements within the parent paragraph alongside regular text runs.
