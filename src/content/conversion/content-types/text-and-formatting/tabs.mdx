Word documents use tab characters for alignment, indentation, and columnar layout within paragraphs. Tiptap and HTML do not have a native tab stop concept, so tabs are converted to spaces during import.

## What you need

- **Extensions:** No additional extensions required. Tab content is converted to plain text.
- **Configuration:** None.

## Support overview

|                                     | Import                                                                | Editor                             | Export                                                         |
| ----------------------------------- | --------------------------------------------------------------------- | ---------------------------------- | -------------------------------------------------------------- |
| Tab characters (mid-paragraph)      | Converted to four spaces                                              | Plain text (spaces)                | Spaces remain as spaces                                        |
| Tab characters (start of paragraph) | Converted to four spaces in the JSON; visually collapse in the editor | Not visible by default (see below) | Spaces remain as spaces                                        |
| Literal `\t` in text JSON           | Imported Word tabs become spaces instead                              | Display depends on whitespace CSS  | DOCX exporter writes a Word tab                                |
| Tab stop positions                  | Not preserved                                                         | Imported positions are unavailable | DOCX extension supports a default stop and paragraph overrides |

## Import

Import tabs using the [editor extension](/conversion/import/docx/editor-extension) or the [REST API](/conversion/import/docx/rest-api). Both handle tabs identically.

When the import converter encounters a `<w:tab/>` element in a text run, it replaces it with four space characters. Word's tab stop positions (left, center, right, decimal, and bar tabs defined in paragraph or style properties) are not extracted or preserved.

The conversion is positional-agnostic: a tab at the start of a paragraph and a tab in the middle of a paragraph both produce four space characters in the JSON. The visual outcome differs because of how the browser renders whitespace (see Editor rendering below).

## Editor rendering

Tab characters become spaces on import, so the editor receives regular text content. Your application can still place a literal `\t` in a text node. Its appearance depends on the editor's whitespace rules and `tab-size`.

<Callout title="Leading spaces in a paragraph are not visible by default" variant="info">
  The four spaces produced from a tab character live in the JSON and reach the editor unchanged, but the browser collapses runs of whitespace under default `white-space: normal`. A tab at the start of a paragraph therefore renders as if it were a single space hugging the paragraph's left edge, which visually looks like the tab was dropped. This is the standard HTML whitespace rule, not import-side trimming. A tab in the middle of a sentence is also collapsed to a single space, which usually reads correctly because there is text on either side.

To preserve the visual indentation, either set `white-space: pre-wrap` on your editor's paragraph styles, or transform leading spaces into non-breaking spaces (` `) in your `onImport` callback before loading content into the editor.

</Callout>

## Export

Spaces remain spaces in the exported DOCX. The exporter does not turn the four spaces from an imported tab back into a tab.

A literal `\t` in a text node becomes a Word tab during DOCX export. With [Document styles](/conversion/export/docx/document-styles), the editor extension measures the shared paragraph `tab-size` in the current font to set the document's default tab stop.

Set `defaultTabStop` to choose the distance yourself, in twips. Use `paragraphOverrides.tabStops` for specific Word tab positions:

```ts
ExportDocx.configure({
  defaultTabStop: 720,
  paragraphOverrides: {
    tabStops: [{ type: 'left', position: 1440 }],
  },
})
```

The example uses a half-inch default gap and a left tab stop one inch from the margin. This sets new export positions; it does not restore positions lost during import.
