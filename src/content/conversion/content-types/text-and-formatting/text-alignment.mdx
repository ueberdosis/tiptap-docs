Text alignment is a paragraph-level attribute that round-trips between DOCX and the editor. Configure the TextAlign extension and alignment is preserved through import, editing, and export.

## What you need

- **Extensions:** [`ConvertKit`](/conversion/import/docx/convertkit) bundles `TextAlign` and preconfigures it with `types: ['paragraph', 'heading']`.
- **Configuration:** None required.
- **That is it.** Alignment works end-to-end with the standard ConvertKit setup.

## Support overview

|         | Import    | Editor    | Export    |
| ------- | --------- | --------- | --------- |
| Left    | Supported | Supported | Supported |
| Center  | Supported | Supported | Supported |
| Right   | Supported | Supported | Supported |
| Justify | Supported | Supported | Supported |

## Import

Import text alignment using the [editor extension](/conversion/import/docx/editor-extension) or the [REST API](/conversion/import/docx/rest-api). Both produce identical output.

The conversion service reads the `<w:jc>` element from each DOCX paragraph and maps it to a `textAlign` attribute on the corresponding Tiptap node.

| Word `<w:jc>` value | Tiptap `textAlign`                                           |
| ------------------- | ------------------------------------------------------------ |
| `left`              | `left`                                                       |
| `center`            | `center`                                                     |
| `right`             | `right`                                                      |
| `both`              | `justify`                                                    |
| `start`             | `start` (passed through, may not be recognized by TextAlign) |
| `end`               | `end` (passed through, may not be recognized by TextAlign)   |

The `textAlign` attribute is set on both `paragraph` and `heading` nodes.

<Callout title="Right-to-left text direction is not imported" variant="warning">
  The importer does not read DOCX paragraph direction or text run direction. Your app must apply the
  desired direction in the editor, for example with `dir="rtl"` or CSS. With Document styles
  enabled, the browser DOCX exporter captures supported direction settings from the rendered editor,
  including individual blocks and text segments. See [Document
  styles](/conversion/export/docx/document-styles).
</Callout>

## Editor rendering

The [`TextAlign`](/editor/extensions/functionality/textalign) extension adds `textAlign` as a global attribute on the node types you specify. It renders as an inline `style="text-align: ..."` on the HTML element. ConvertKit registers it with `types: ['paragraph', 'heading']` so imported alignment renders out of the box:

```ts
import { ConvertKit } from '@tiptap-pro/extension-convert-kit'

new Editor({ extensions: [ConvertKit] })
```

If you need different types (e.g. table cells), override the slot:

```ts
ConvertKit.configure({
  textAlign: { types: ['paragraph', 'heading', 'tableCell'] },
})
```

<Callout title="Disabling textAlign drops the attribute" variant="warning">
  If you set `ConvertKit.configure({ textAlign: false })`, the `textAlign` attribute from import isn't recognized by the schema and won't be applied. No error is thrown. See the [invalid schema guide](/guides/invalid-schema) for more on this behavior.
</Callout>

## Export

Export text alignment using the [editor extension](/conversion/export/docx/editor-extension) or the [REST API](/conversion/export/docx/rest-api). Both accept stored paragraph alignment. Only the browser editor extension can also read rendered CSS.

The exporter reads `node.attrs.textAlign` from each paragraph and heading and maps it back to the DOCX alignment type. No additional configuration is required. If import and editor are configured correctly, export follows automatically.

A paragraph or heading without `textAlign` uses captured browser alignment when available, otherwise its Word style. Document styles can capture different alignments on individual paragraphs and headings. For example, `text-align: justify` on a rendered paragraph exports as justified text. See [Document styles](/conversion/export/docx/document-styles).
