Paragraphs are the most fundamental content type in any document. In Word they carry formatting like spacing, indentation, borders, and alignment. In Tiptap they map to the `paragraph` node, which [ConvertKit](/conversion/import/docx/convertkit) registers automatically, with a custom variant that surfaces the DOCX-aware attributes the importer produces.

## What you need

- **Extensions:** [`ConvertKit`](/conversion/import/docx/convertkit). Its custom Paragraph renders all the imported attributes (spacing, indentation, line height, font size, contextual spacing) and the bundled `TextAlign` is preconfigured for `['paragraph', 'heading']`.
- **Configuration:** None required.

<Callout title="Paragraph formatting needs ConvertKit's custom Paragraph" variant="hint">
  Text content and alignment round-trip with any paragraph node. Paragraph-level spacing,
  indentation, line height, and contextual spacing are extracted during import and rendered as
  inline CSS by ConvertKit's custom Paragraph. If you swap ConvertKit's Paragraph for a stock one
  (or disable the slot), those attributes stay in the JSON but are stripped on `setEditorContent()`.
  The [Styling converted content](/conversion/getting-started/guides/styling-converted-content)
  guide covers how to extend the schema for additional attributes. Paragraph spacing, indentation,
  contextual spacing, and line height also work on export. Line height supports both proportional
  and fixed values. See the support overview below.
</Callout>

## Support overview

|                                      | Import                                                       | Editor (with ConvertKit)                                     | Export                                                                                                                             |
| ------------------------------------ | ------------------------------------------------------------ | ------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------- |
| Text content                         | Supported                                                    | Supported                                                    | Supported                                                                                                                          |
| Text alignment                       | Supported                                                    | Supported (TextAlign)                                        | Supported                                                                                                                          |
| Line height                          | Supported (paragraph attr)                                   | Supported (`line-height: <value>`)                           | Proportional values use a minimum height based on font size; fixed `px`/`pt` values use an exact height                            |
| Paragraph spacing (before/after)     | Supported (`spacingBefore`, `spacingAfter` attrs)            | Supported (`margin-top` / `margin-bottom`)                   | Supported                                                                                                                          |
| Indentation                          | Supported (`indent`, `indentRight`, `firstLineIndent` attrs) | Supported (`padding-left` / `padding-right` / `text-indent`) | Supported (left, right, first-line; a hanging indent imports as a negative first-line indent and exports back as a hanging indent) |
| Contextual spacing                   | Supported (`contextualSpacing` attr)                         | Supported (`data-contextual-spacing` + injected CSS rule)    | Supported                                                                                                                          |
| Keep with next / keep lines together | Supported (`keepNext`, `keepLines` attrs)                    | Kept in the JSON, no visual effect                           | Supported                                                                                                                          |

## Import

Import paragraphs using the [editor extension](/conversion/import/docx/editor-extension) or the [REST API](/conversion/import/docx/rest-api). Both produce identical paragraph output.

When a DOCX file is imported, each Word paragraph becomes a `paragraph` node. The conversion service reads properties from the Word markup and maps them to node attributes.

The resulting JSON for a basic paragraph:

```json
{
  "type": "paragraph",
  "attrs": {
    "textAlign": "left"
  },
  "content": [
    {
      "type": "text",
      "text": "This is a paragraph."
    }
  ]
}
```

### What is preserved

- All text content and inline formatting (bold, italic, links, and other marks)
- Text alignment when the paragraph has explicit alignment in Word

### What is lost

The conversion service extracts paragraph-level attributes like `spacingBefore`, `spacingAfter`, `lineHeight`, `indent` (left), `indentRight` (right), `firstLineIndent`, `contextualSpacing`, `keepNext`, and `keepLines` from the Word source. A hanging indent is imported as a negative `firstLineIndent`. Values from the paragraph's named style (for example spacing or indentation carried by the "Normal" or a "Body" style) are resolved onto these attributes too, not only direct formatting. ConvertKit's custom Paragraph renders all of them as inline CSS, except `keepNext` and `keepLines`, which stay in the JSON for export and have no visual effect. If you replace it with the stock Paragraph (or disable the slot via `ConvertKit.configure({ paragraph: false })`), the values stay in the raw JSON but are stripped when content loads into the editor. Paragraph-level borders and background colors are not extracted during import in either setup.

## Editor rendering

The [`Paragraph`](/editor/extensions/nodes/paragraph) extension is registered by [`ConvertKit`](/conversion/import/docx/convertkit) and renders each paragraph as a `<p>` element. ConvertKit substitutes a custom Paragraph that adds the DOCX-aware attributes; the standard Paragraph is the fallback if you disable the slot.

### Text alignment is bundled

ConvertKit also registers `TextAlign` and preconfigures it for `['paragraph', 'heading']`, so the `textAlign` attribute from Word renders without further setup. If you disable the bundled `textAlign` slot, the attribute stays in the JSON but isn't applied. See the [invalid schema guide](/guides/invalid-schema).

### Visual differences from Word

The editor renders paragraphs with your CSS styles, not Word's document styles. Word's "Normal" style typically includes specific font, size, and spacing values that will not carry over to the editor. Structure and text content are preserved. Visual appearance is yours to control through your editor's CSS. See the [Styling converted content](/conversion/getting-started/guides/styling-converted-content) guide for how to manage this.

## Export

Export paragraphs using the [editor extension](/conversion/export/docx/editor-extension) or the [REST API](/conversion/export/docx/rest-api). The extension supports [`paragraphOverrides` and `textRunOverrides`](/conversion/export/docx/styles#element-overrides) for fine-grained control over paragraph and text run defaults. The REST API does not accept element overrides. To customize paragraph styling via the REST API, use [`styleOverrides`](/conversion/export/docx/styles) to redefine the "Normal" document style.

During DOCX export, each `paragraph` node becomes a Word paragraph with the "Normal" style. In the browser, [Document styles](/conversion/export/docx/document-styles) read the shared paragraph styles and the formatting of each paragraph. A class or inline style can give one paragraph a different color, border, spacing, or direction. This does not require a `.tiptap` CSS scope.

Without captured CSS, Normal uses Arial 11pt, 10pt after-paragraph spacing, and 1.15 line height, unless your custom styles change those values.

### What round-trips

- All text content and inline marks
- Text alignment is read from the paragraph node attributes and mapped to Word alignment
- The exporter reads `lineHeight` from the paragraph attribute. A `textStyle.lineHeight` mark on the block takes priority. Proportional values such as `1.5` or `150%` use the paragraph's font size to calculate a minimum line height. Fixed values such as `24px`, `18pt`, or `1cm` use an exact line height. Stored `em` and `rem` values need browser measurement or a custom export style.
- If a paragraph has no explicit block line height, a uniform `textStyle.lineHeight` on all its text can set its line height. Mixed or incomplete inline values leave it to the captured paragraph or named style. The exporter does not apply different line spacing to separate words in one paragraph.
- Paragraph spacing (`spacingBefore` / `spacingAfter`), left, right, and first-line indentation (`indent` / `indentRight` / `firstLineIndent`), and contextual spacing (`contextualSpacing`) are read from the paragraph node attributes. A negative first-line indent is written as a hanging indent. These attributes also apply to styled paragraphs such as blockquotes.
- Keep with next (`keepNext`) and keep lines together (`keepLines`) are written as Word's pagination hints.

<Callout title="Line spacing is preserved, exact rendering is not" variant="info">
  Line spacing carries over, but the exported document will not match the editor pixel for pixel. A
  word processor and a web browser measure fonts and lay out lines differently, so the same line
  height can occupy a slightly different amount of vertical space in each. This applies to
  proportional and fixed line heights alike.
</Callout>

### What is not exported

In the browser, document styles can read a paragraph's displayed border and background. The exporter does not treat arbitrary JSON attributes as CSS. Your node extension must render those attributes, or you must map them through custom export styles or overrides.

### Customizing export styles

You can override the default paragraph styling using `styleOverrides` in the export configuration:

```ts
ExportDocx.configure({
  styleOverrides: {
    paragraphStyles: [
      {
        id: 'Normal',
        name: 'Normal',
        run: {
          font: 'Calibri',
          size: 24, // half-points (24 = 12pt)
        },
        paragraph: {
          spacing: {
            after: 200, // twips
            line: 276, // 240ths of a line (276 = 1.15 line height)
            lineRule: 'auto',
          },
        },
      },
    ],
  },
})
```

Set `lineRule` together with `line` when you change line spacing. Captured browser styles may use `atLeast`; `auto` makes the value a multiple of a line.

These named styles apply above captured CSS. They merge nested properties, so changing space after a paragraph keeps its captured line height. A direct `paragraphOverrides.spacing` object replaces the whole spacing object instead.
