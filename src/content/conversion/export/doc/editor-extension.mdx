<Callout title="Consider using DOCX instead" variant="info">
  The DOC format is a legacy format from Microsoft Word 97-2003. For modern use, we recommend
  exporting to [DOCX](/conversion/export/docx/editor-extension) instead. Use DOC only when
  compatibility with older systems requires it.

Use Tiptap's `@tiptap-pro/extension-export-doc` to export your editor's content as a `.doc` file. This extension integrates DOC export functionality into your editor. It builds a DOCX file with the [DOCX export extension](/conversion/export/docx/editor-extension) and sends that file to the Tiptap convert service for conversion.

You can also use the [REST API](/conversion/export/doc/rest-api) instead if you'd prefer to handle the conversion on your end.

## Install the DOC Export extension

The Conversion extensions are published in Tiptap's private npm registry. Integrate the extensions by following the [private registry guide](/guides/pro-extensions).

Once done you can install and import the **Export DOC** extension package. The DOC export needs the **Export DOCX** extension too, because it converts the DOCX file that `ExportDocx` builds. The DOC package does not include the DOCX exporter, so install both packages.

```bash
npm i @tiptap-pro/extension-export-doc @tiptap-pro/extension-export-docx
```

```js
import { ExportDoc } from '@tiptap-pro/extension-export-doc'
import { ExportDocx } from '@tiptap-pro/extension-export-docx'
```

<Callout title="Register ExportDocx in the same editor" variant="warning">
  Without `ExportDocx` in the editor's extensions, `exportDoc` does nothing: it sends no request,
  does not call `onCompleteExport` and resolves to `false`.
</Callout>

## Configuring the extension

The `ExportDoc` extension can be configured with an `ExportDocOptions` (`object`) as an argument to the `configure` method with the following properties:

```ts
import { ExportDoc } from '@tiptap-pro/extension-export-doc'
import { ExportDocx } from '@tiptap-pro/extension-export-docx'

const editor = new Editor({
  extensions: [
    // Other extensions ...
    ExportDocx,
    ExportDoc.configure({
      region: 'eu', // 'eu' or 'us'
      token: 'YOUR_TOKEN',
      // Leave out styleOverrides, pageSize, pageMargins and customNodes to use the
      // ExportDocx settings and the Pages page format.
      // An empty object or array counts as set and replaces them.
      onCompleteExport: (result) => {
        // Handle the exported Blob
      },
    }),
    // Other extensions ...
  ],
})
```

| Parameter          | Type                     | Description                                                                                      | Default                               |
| ------------------ | ------------------------ | ------------------------------------------------------------------------------------------------ | ------------------------------------- |
| `endpoint`         | `string`                 | The Tiptap API endpoint for conversion. When set, it overrides `region`                          | `undefined`                           |
| `region`           | `'eu' \| 'us'`           | The Tiptap Cloud region used when `endpoint` is not set                                          | `'eu'`                                |
| `token`            | `string`                 | The Tiptap JWT for authentication, see [Authentication](/authentication)                                                                | `''`                                  |
| `styleOverrides`   | `IStylesOptions`         | Style overrides to apply to the export                                                           | `undefined`                           |
| `headers`          | `HeaderConfig`           | Not used. `ExportDoc` does not pass it to `ExportDocx`, see [HeaderConfig](#headerconfig)        | `undefined`                           |
| `footers`          | `FooterConfig`           | Not used. `ExportDoc` does not pass it to `ExportDocx`, see [HeaderConfig](#headerconfig)        | `undefined`                           |
| `pageSize`         | `PageSize`               | Page size configuration                                                                          | `undefined`                           |
| `pageMargins`      | `PageMargins`            | Page margins configuration                                                                       | `undefined`                           |
| `pageColor`        | `string`                 | Page background color, passed to `ExportDocx`                                                    | `undefined`                           |
| `customNodes`      | `CustomNode[]`           | Custom node definitions for the DOCX file that `ExportDocx` builds                               | `undefined`                           |
| `onCompleteExport` | `(result: Blob) => void` | Callback that receives the exported file as a Blob                                               | Throws error if not provided          |

### HeaderConfig

<Callout title="Set headers and footers on ExportDocx" variant="warning">
  `ExportDoc` does not pass its `headers` and `footers` options to `ExportDocx`, so the values
  below do not reach the file. The DOC file gets the headers and footers that `ExportDocx`
  exports: the ones set on `ExportDocx`, or the [Pages](/pages/getting-started/overview) headers
  and footers when the Pages extension is installed.
</Callout>

| Property             | Type      | Description                                                                                                                                                                              |
| -------------------- | --------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `evenAndOddHeaders`  | `boolean` | Whether to use different headers for odd and even pages                                                                                                                                  |
| `differentFirstPage` | `boolean` | Whether to use a different header on the first page. When `true`, the `first` value is used on page one instead of `default`.                                                            |
| `default`            | `string`  | The standard default header on every page, or header on odd pages when `evenAndOddHeaders` is active. Accepts a plain text string or stringified Tiptap JSONContent for rich formatting. |
| `first`              | `string`  | The header on the first page. Only used when `differentFirstPage` is set to `true`. Accepts a plain text string or stringified Tiptap JSONContent for rich formatting.                   |
| `even`               | `string`  | The header on even pages when the `evenAndOddHeaders` option is activated. Accepts a plain text string or stringified Tiptap JSONContent for rich formatting.                            |

### FooterConfig

| Property             | Type      | Description                                                                                                                                                                              |
| -------------------- | --------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `evenAndOddFooters`  | `boolean` | Whether to use different footers for odd and even pages                                                                                                                                  |
| `differentFirstPage` | `boolean` | Whether to use a different footer on the first page. When `true`, the `first` value is used on page one instead of `default`.                                                            |
| `default`            | `string`  | The standard default footer on every page, or footer on odd pages when `evenAndOddFooters` is active. Accepts a plain text string or stringified Tiptap JSONContent for rich formatting. |
| `first`              | `string`  | The footer on the first page. Only used when `differentFirstPage` is set to `true`. Accepts a plain text string or stringified Tiptap JSONContent for rich formatting.                   |
| `even`               | `string`  | The footer on even pages when the `evenAndOddFooters` option is activated. Accepts a plain text string or stringified Tiptap JSONContent for rich formatting.                            |

### PageSize

| Property | Type     | Description                                                                                          | Default    |
| -------- | -------- | ---------------------------------------------------------------------------------------------------- | ---------- |
| `width`  | `string` | The width of the page. Must be a positive number followed by a valid unit (cm, in, pt, pc, mm, px).  | `"21cm"`   |
| `height` | `string` | The height of the page. Must be a positive number followed by a valid unit (cm, in, pt, pc, mm, px). | `"29.7cm"` |

### PageMargins

| Property | Type     | Description                                                                                                         | Default |
| -------- | -------- | ------------------------------------------------------------------------------------------------------------------- | ------- |
| `top`    | `string` | The top margin of the page. Can be negative. Must be a number followed by a valid unit (cm, in, pt, pc, mm, px).    | `"2.54cm"` |
| `bottom` | `string` | The bottom margin of the page. Can be negative. Must be a number followed by a valid unit (cm, in, pt, pc, mm, px). | `"2.54cm"` |
| `left`   | `string` | The left margin of the page. Must be a positive number followed by a valid unit (cm, in, pt, pc, mm, px).           | `"3.17cm"` |
| `right`  | `string` | The right margin of the page. Must be a positive number followed by a valid unit (cm, in, pt, pc, mm, px).          | `"3.17cm"` |

The defaults come from `ExportDocx`. The export uses the `pageSize` and `pageMargins` objects set on `ExportDoc`, or else the ones on `ExportDocx`. One `pageMargins` object replaces the other as a whole. With the [Pages](/pages/getting-started/overview) extension installed, each margin that neither object sets comes from the Pages page format, and the page size comes from Pages when neither sets `pageSize`.

## Export a DOC file

With the extension installed, you can export your editor's content to `.doc` using the `exportDoc` command.

```ts
/**
 * Export the current document as a DOC file via the Tiptap convert service.
 *
 * @param options - All extension-level options can be overridden per-invocation
 * @example editor.commands.exportDoc({ onCompleteExport: (result) => {} })
 */
exportDoc: (options?: ExportDocCommandOptions) => ReturnType
```

The `ExportDocCommandOptions` interface extends `ExportDocOptions`, so every configuration option can be overridden per-command invocation:

| Property           | Type                     | Description                                               |
| ------------------ | ------------------------ | --------------------------------------------------------- |
| `endpoint`         | `string`                 | Override the API endpoint for this specific export        |
| `region`           | `'eu' \| 'us'`           | Override the region for this specific export              |
| `token`            | `string`                 | Override the JWT token for this specific export           |
| `styleOverrides`   | `IStylesOptions`         | Override style overrides for this specific export         |
| `headers`          | `HeaderConfig`           | Not used, see [HeaderConfig](#headerconfig)               |
| `footers`          | `FooterConfig`           | Not used, see [HeaderConfig](#headerconfig)               |
| `pageSize`         | `PageSize`               | Override page size for this specific export               |
| `pageMargins`      | `PageMargins`            | Override page margins for this specific export            |
| `pageColor`        | `string`                 | Override the page background color for this specific export |
| `customNodes`      | `CustomNode[]`           | Override custom node definitions for this specific export |
| `onCompleteExport` | `(result: Blob) => void` | Override the callback for this specific export            |

```js
import { ExportDoc } from '@tiptap-pro/extension-export-doc'
import { ExportDocx } from '@tiptap-pro/extension-export-docx'

const editor = new Editor({
  extensions: [
    // Other extensions ...
    ExportDocx,
    ExportDoc.configure({
      token: 'YOUR_TOKEN',
      onCompleteExport(result) {
        // Download the DOC file
        const url = URL.createObjectURL(result)
        const a = document.createElement('a')

        a.href = url
        a.download = 'document.doc'
        a.click()

        URL.revokeObjectURL(url)
      },
    }),
    // Other extensions ...
  ],
})

// Use the extension-level callback
editor.chain().exportDoc().run()

// Or override options for a specific export
editor
  .chain()
  .exportDoc({
    pageSize: { width: '8.5in', height: '11in' },
    onCompleteExport(result) {
      // Custom handling for this specific export
      const url = URL.createObjectURL(result)
      window.open(url)
    },
  })
  .run()
```

### How it works

When you call `exportDoc`, the extension runs the `exportDocx` command of `ExportDocx` to build a DOCX file in the browser. It passes `styleOverrides`, `pageSize`, `pageMargins`, `pageColor` and `customNodes` to `exportDocx`. An option that you leave unset on `ExportDoc` takes the value set on `ExportDocx`. An object or array that you set, even an empty one, replaces the `ExportDocx` value as a whole. The DOCX file gets the editor's [computed styles](/conversion/export/docx/computed-styles) unless you turn them off on `ExportDocx`. The extension then uploads the DOCX file to the Convert service, which returns the resulting `.doc` file as a binary blob. The `onCompleteExport` callback receives the blob directly. When the export fails, the promise that the command returns rejects with the error, and the callback is not called. Use `await editor.commands.exportDoc()` to catch it. With `editor.chain().exportDoc().run()`, the rejection goes unhandled.

## What to expect

- **Authentication required** (`token` JWT). Generate JWTs server-side. See the [Conversion install guide](/conversion/getting-started/install).
- **HTTP responses to handle:** `401` (missing or invalid JWT), `403` (operation not permitted for your app — typically a format your plan doesn't include), `5xx` (transient server-side error; retry with backoff).
- **Each request is processed end-to-end before responding.** Plan for longer round-trips on large documents.

## What not to expect

- **Round-trip identity.** DOC is a 1997–2003 binary format with rendering quirks of its own; we aim for faithful, not byte-identical, output.
- **Modern Word features.** DOC predates many Word features; advanced layout, comments, revisions, and styled metadata are simplified or dropped. Use [DOCX](/conversion/export/docx/editor-extension) when targeting modern Word versions.

## Support & Limitations

| **Feature**                      | **Support**                                                                 |
| -------------------------------- | --------------------------------------------------------------------------- |
| **Text content**                 | ✓ Basic text, spacing, punctuation                                          |
| **Text formatting**              | ✓ Bold, italic, underline, strikethrough, alignment, line height            |
| **Block elements**               | ✓ Paragraphs, headings (1–6), blockquotes, ordered and unordered lists      |
| **Tables**                       | ✓ Basic structure, header rows, colspan                                     |
| **Links**                        | ✓ Hyperlinks                                                                |
| **Media (Images)**               | ✓ Embedded images, size preserved                                           |
| **Styles**                       | ✓ Font families\*, Font colors, font sizes, background colors, line heights |
| **Headers & Footers**            | ✓                                                                           |
| **Math**                         | ✓                                                                           |
| **Page Breaks**                  | ✓                                                                           |
| **Sections**                     | ✗                                                                           |
| **Footnotes & Endnotes**         | ✗                                                                           |
| **Comments & Revisions**         | ✗                                                                           |
| **Table of Contents**            | ✗                                                                           |
| **Advanced Formatting**          | ✗ Columns, text direction, forms, macros, embedded scripts                  |
| **Metadata**                     | ✗                                                                           |
| **Text Boxes, Shapes, SmartArt** | ✗                                                                           |

<span style={{ fontSize: '1rem' }}>
  * Font families are supported as long as the target font is installed on the operative system when
  the exported file is opened.
</span>

For a detailed per-feature breakdown, see the [Supported features](/conversion/getting-started/feature-support-matrix) matrix. `ExportDoc` has no options for the element overrides (`paragraphOverrides`, `textRunOverrides`, `tableOverrides`, `tableCellOverrides`, `imageOverrides`) of the [DOCX export extension](/conversion/export/docx/editor-extension). The DOCX file that the DOC conversion starts from uses the element overrides set on `ExportDocx`.
