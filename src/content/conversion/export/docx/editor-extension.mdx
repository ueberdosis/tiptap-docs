Use Tiptap’s `@tiptap-pro/extension-export-docx` to export the editor’s content as a `.docx` file. The extension sends your document to the Convert service, which builds the file and sends it back.

You can also export with the [REST API](/conversion/export/docx/rest-api). Both run on the Convert service and take the same export options.

|                           | Editor extension | REST API        |
| ------------------------- | ---------------- | --------------- |
| Runs in                   | Convert service  | Convert service |
| Shared export options     | Yes              | Yes             |
| Measures the editor’s CSS | Yes              | No              |

Both take these export options: `customNodeDsl`, `styleOverrides`, `cssStyles`, the seven plain-object overrides (`paragraphOverrides`, `textRunOverrides`, `tableOverrides`, `tableRowOverrides`, `tableCellOverrides`, `imageOverrides`, `headerFooterOverrides`), `numberingFormats`, `listLevels`, `outline`, `defaultTabStop`, `pageColor`, `pageSize`, `pageMargins`, `pageSetup`, `footnotes`, `endnotes`, `comments`, `embedFonts` and `onImageError`.

- The extension adds `token`, `appId`, `endpoint`, `region`, `exportType`, `documentStyles`, `fonts`, `onCompleteExport`, `onError` and `onWarning`.
- The REST body adds `document`, `assets`, and the fields the extension measures in the browser: `documentCss`, `cellParagraphIds` and `listParagraphOverrides`.

Use the editor extension when you export from the editor. The file then looks like what you see on screen. Use the REST API when you export from your server without an editor.

To render custom nodes, describe them with [`customNodeDsl`](/conversion/export/docx/custom-nodes-dsl).

## Install the DOCX Export extension

The Conversion extensions are published in Tiptap’s private npm registry. Integrate the extensions by following the [private registry guide](/guides/pro-extensions).

Once done, install the **Export DOCX** extension package:

```bash
npm i @tiptap-pro/extension-export-docx
```

```js
import { ExportDocx } from '@tiptap-pro/extension-export-docx'
```

## Configuring the extension

<Callout title="Upgrading from 0.x?" variant="hint">
  Some options are gone in `1.0.0`. See [Migrate to v1](/conversion/export/docx/migrate-to-v1) for
  what replaces each one.
</Callout>

Pass your options to `ExportDocx.configure`. `token` and `onCompleteExport` are required.

```ts
import { Editor } from '@tiptap/core'
import { ConvertKit } from '@tiptap-pro/extension-convert-kit'
import { ExportDocx } from '@tiptap-pro/extension-export-docx'

const editor = new Editor({
  extensions: [
    ConvertKit,
    ExportDocx.configure({
      token: 'YOUR_JWT',
      appId: 'YOUR_APP_ID',
      onCompleteExport: (result) => {
        if (!(result instanceof Blob)) return
        const url = URL.createObjectURL(result)
        const link = document.createElement('a')
        link.href = url
        link.download = 'export.docx'
        link.click()
        URL.revokeObjectURL(url)
      },
    }),
  ],
})
```

| Parameter               | Description                                                                                                                                                                                                            | Default     |
| ----------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------- |
| `token`                 | **Required.** A signed token that allows the `Convert:Export:Docx` action. See [Authentication](/conversion/getting-started/install#authentication).                                                                   | `undefined` |
| `appId`                 | Your Tiptap app ID, sent as the `X-App-Id` header.                                                                                                                                                                     | `undefined` |
| `endpoint`              | The base URL of a custom or on-premises Convert service. When set, it overrides `region`. A base that ends in `/v2` or `/v2/convert` maps to `/v3` or `/v3/convert`.                                                   | `undefined` |
| `region`                | `'eu'` or `'us'`. Picks the Tiptap Cloud host when you don't set `endpoint`.                                                                                                                                           | `'eu'`      |
| `onCompleteExport`      | **Required.** Receives the exported file.                                                                                                                                                                              | Throws      |
| `exportType`            | The shape of the file you get: `'blob'` gives a `Blob`, `'base64'` a base64 string, `'string'` a binary string, `'buffer'` a `Uint8Array`. [`'stream'` is gone](/conversion/export/docx/migrate-to-v1#removed-stream). | `'blob'`    |
| `onError`               | Receives the error when the export fails. The command never throws. Without `onError`, the error is an unhandled promise rejection, so always pass it. See [Errors](#errors).                                          | `undefined` |
| `onWarning`             | Receives each warning, from the browser and from Convert. Without it, warnings go to `console.warn`. See [Images that cannot be exported](#images-that-cannot-be-exported).                                            | `undefined` |
| `documentStyles`        | Measures your editor’s CSS and sends it with the document, so the file matches the editor. `false` skips it.                                                                                                           | `true`      |
| `cssStyles`             | CSS rules as a plain object, compiled into DOCX styles. See [CSS to DOCX](/conversion/export/docx/css-to-docx).                                                                                                        | `undefined` |
| `styleOverrides`        | Custom styles for the exported document. See [Export styles](/conversion/export/docx/styles).                                                                                                                          | `undefined` |
| `customNodeDsl`         | Rules that describe how custom nodes render. See [Custom nodes DSL](/conversion/export/docx/custom-nodes-dsl). [`customNodes` is gone](/conversion/export/docx/migrate-to-v1#removed-customNodes).                     | `undefined` |
| `paragraphOverrides`    | A plain object applied to every paragraph. See [Export styles](/conversion/export/docx/styles).                                                                                                                        | `undefined` |
| `textRunOverrides`      | A plain object applied to every text run.                                                                                                                                                                              | `undefined` |
| `tableOverrides`        | A plain object applied to every table.                                                                                                                                                                                 | `undefined` |
| `tableRowOverrides`     | A plain object applied to every table row, for example `cantSplit` or `height`.                                                                                                                                        | `undefined` |
| `tableCellOverrides`    | A plain object applied to every table cell.                                                                                                                                                                            | `undefined` |
| `imageOverrides`        | A plain object applied to every image.                                                                                                                                                                                 | `undefined` |
| `headerFooterOverrides` | Plain-object overrides for header and footer content only. A field you leave out uses the body-wide value.                                                                                                             | `undefined` |
| `numberingFormats`      | Multilevel numbering formats for ordered lists. Formats registered in the editor are added for you. See [Ordered list numbering](/conversion/export/docx/ordered-list-numbering).                                      | `undefined` |
| `listLevels`            | Marker and text indents per list kind and depth.                                                                                                                                                                       | `undefined` |
| `outline`               | Outline numbering. Read from the editor when you leave it out.                                                                                                                                                         | From editor |
| `defaultTabStop`        | The default tab stop of the document.                                                                                                                                                                                  | `undefined` |
| `pageColor`             | The page background color.                                                                                                                                                                                             | `undefined` |
| `pageSize`              | Page `width` and `height`.                                                                                                                                                                                             | `undefined` |
| `pageMargins`           | Page margins: `top`, `bottom`, `left`, `right`, `header` and `footer`.                                                                                                                                                 | `undefined` |
| `pageSetup`             | The document's page layout setup. Read from the editor when you leave it out.                                                                                                                                          | From editor |
| `footnotes`             | Footnote content keyed by note ID (`Record<string, JSONContent>`).                                                                                                                                                     | `undefined` |
| `endnotes`              | Endnote content keyed by note ID (`Record<string, JSONContent>`).                                                                                                                                                      | `undefined` |
| `comments`              | Comment threads to export. Read from the comments extension when you leave it out.                                                                                                                                     | From editor |
| `fonts`                 | TTF, OTF or WOFF2 fonts to embed. See [Fonts](/conversion/export/docx/fonts).                                                                                                                                          | `undefined` |
| `embedFonts`            | Finds the fonts the document uses and embeds them. See [Fonts](/conversion/export/docx/fonts).                                                                                                                         | `false`     |
| `onImageError`          | `'skip'` leaves out an image that can't be used and reports it. `'throw'` fails the export. See [Images that cannot be exported](#images-that-cannot-be-exported).                                                     | `'skip'`    |

Overrides take plain objects. The extension drops a function override and reports an `unsupported` warning. See [function overrides](/conversion/export/docx/migrate-to-v1#removed-function-overrides).

## Export a DOCX file

Call the `exportDocx` command to export the document:

```ts
exportDocx: (options?: ExportDocxCommandOptions) => ReturnType
```

The command takes the same options as `ExportDocx.configure`. An option you pass to the command wins. An option you leave out falls back to the configured one.

The command returns right away. The file arrives in `onCompleteExport` once Convert sends it back.

```ts
// Export with the configured options
editor.commands.exportDocx()

// Export as a Uint8Array instead of a Blob
editor.commands.exportDocx({
  exportType: 'buffer',
  onCompleteExport: (result) => {
    // result is a Uint8Array
  },
})
```

### How it works

The extension measures your editor’s styles, sends them with the document to Convert, and hands you the file. It also reads fonts, and images Convert can't reach, in the browser and sends them along.

| Parameter          | Description                                                                                   |
| ------------------ | --------------------------------------------------------------------------------------------- |
| `onCompleteExport` | Receives the file. With the default `exportType`, it's a `Blob` you can download or upload.   |
| `exportType`       | Picks the shape of the file. The default `'blob'` gives a `Blob`.                             |
| `documentStyles`   | On by default, so the file matches the editor’s styles. Pass `styleOverrides` to change them. |

### Errors

When the export fails, `onError` receives the error. A failed request gives you an `ExportDocxRequestError` with a `code`, and a `status`, `path` and `docsUrl` when Convert sends them. `NETWORK_ERROR` means the request never reached Convert.

```ts
import { ExportDocx, ExportDocxRequestError } from '@tiptap-pro/extension-export-docx'

ExportDocx.configure({
  token: 'YOUR_JWT',
  onCompleteExport: (result) => {
    /* save the file */
  },
  onError: (error) => {
    if (error instanceof ExportDocxRequestError) {
      console.error(error.code, error.status, error.path)
    }
  },
})
```

## Server-side export

To export from your server, call the REST API with `fetch`. Send the Tiptap JSON as `document`, plus any of the shared export options.

```ts
const response = await fetch('https://api.tiptap.dev/v3/convert/export/docx', {
  method: 'POST',
  headers: {
    Authorization: `Bearer ${token}`,
    'X-App-Id': appId,
    'Content-Type': 'application/json',
  },
  body: JSON.stringify({ document: tiptapJson }),
})

const docx = await response.arrayBuffer()
```

Your server has no editor to measure, so the request has no `documentCss`. Convert then styles the file with `styleOverrides`, `cssStyles` and the plain-object overrides. See the [REST API](/conversion/export/docx/rest-api#export-docx-v3) for every body field. The `exportDocx` function is gone, see [Migrate to v1](/conversion/export/docx/migrate-to-v1#removed-exportDocx).

## Images that cannot be exported

Convert fetches each image by its `src`. The extension reads the images Convert can't reach in the browser and sends them with the request: `blob:` URLs, large `data:` URLs, and images on your page's own origin, relative URLs included.

Some images can't be used: the URL returns a 404, the host does not answer, or the format is one DOCX cannot embed. Word writes EMF for pasted charts and equations, so documents that came from Word often carry one.

By default the export leaves that image out and carries on, so one broken picture does not
cost you the whole file. If the image was the only thing in its paragraph, the paragraph
goes too, leaving no blank line behind.

Pass `onWarning` to find out which images were skipped:

```js
ExportDocx.configure({
  token: 'YOUR_JWT',
  onCompleteExport: (result) => saveAs(result, 'export.docx'),
  onWarning: (warning) => {
    console.log(warning.code, warning.src)
  },
})
```

Image warnings carry:

| Field         | Description                                                                                    |
| ------------- | ---------------------------------------------------------------------------------------------- |
| `code`        | `image-missing-src`, `image-request-failed`, `image-fetch-failed`, or `image-unsupported-type` |
| `message`     | Readable summary, safe to log                                                                  |
| `src`         | The image URL, when the node had one                                                           |
| `status`      | HTTP status, when the host answered with a failure                                             |
| `contentType` | The detected type, for an unsupported format                                                   |

Without `onWarning`, warnings go to `console.warn`. Exceptions thrown
inside `onWarning` are swallowed, so a mistake in your handler cannot break an export.

To fail the export instead, set `onImageError: 'throw'`. `onError` then receives the error:

- An image the browser can't load stops the export before the request is sent. You get an `ImageRequestError`, or an `ImageFetchError` when the host answered with an error status. Both extend `ImageConversionError`.
- An image Convert can't use fails the request. You get an `ExportDocxRequestError`.

```js
import { ImageConversionError } from '@tiptap-pro/extension-export-docx'

editor.commands.exportDocx({
  onImageError: 'throw',
  onError: (error) => {
    if (error instanceof ImageConversionError) {
      console.log(`Could not use ${error.src}: ${error.code}`)
    }
  },
})
```

## Node attribute inference

The DOCX export automatically respects node-level attributes set by the editor, rather than always computing values from scratch. This means resized images, adjusted table columns, and other editor-level customizations are preserved in the exported document.

| Feature                                        | Description                                                                                                                                                                                                                |
| ---------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Image `width`/`height`**                     | When an image has been resized in the editor, the user-set dimensions are used. Priority: `imageOverrides.transformation` > `node.attrs.width/height` > intrinsic dimensions                                               |
| **Image `alt` text**                           | Mapped to the docx `altText` property for accessibility metadata                                                                                                                                                           |
| **Table cell `colwidth`**                      | Per-cell pixel array from editor-resized columns produces precise column widths in the export. On a fluid table the columns keep their proportions                                                                         |
| **Table cell `rowspan`**                       | Cells spanning multiple rows are correctly exported                                                                                                                                                                        |
| **Table `width`**                              | A table with an explicit `width` exports at that fixed width; a table with no width exports full width (fluid) so it reflows to the page                                                                                   |
| **Table borders**                              | The table's own borders (outer edges plus the inside horizontal and vertical grid) are exported; a borderless table stays borderless                                                                                       |
| **Table cell `background`**                    | Exported as cell shading                                                                                                                                                                                                   |
| **Table cell borders**                         | Per-side cell borders (`width` / `style` / `color`) are exported; a cell border that differs from the table's is kept as an override                                                                                       |
| **Table cell `verticalAlign`**                 | `top` / `middle` / `bottom` exported as the cell vertical alignment                                                                                                                                                        |
| **Table row `height` / `heightRule`**          | Row height is exported; `exact` clips to the height, `atLeast` treats it as a minimum                                                                                                                                      |
| **Table cell margins**                         | `cellMarginTop` / `cellMarginRight` / `cellMarginBottom` / `cellMarginLeft` on the table node are exported as the table's cell margins. A table without them uses Word's default                                           |
| **Paragraph `textAlign: 'justify'`**           | Correctly mapped to `AlignmentType.JUSTIFIED` (previously fell through to left alignment)                                                                                                                                  |
| **Text run `backgroundColor`**                 | `textStyle` mark `backgroundColor` exported as solid character shading                                                                                                                                                     |
| **Paragraph/heading `lineHeight`**             | Proportional line height (a unitless multiple such as `1.5` or a percentage such as `150%`) is written as a relative line that scales with the font size. A fixed `px`/`pt` line height is written as an exact line height |
| **Paragraph/heading spacing**                  | `spacingBefore` and `spacingAfter` are written as space before/after the paragraph                                                                                                                                         |
| **Paragraph/heading indentation**              | `indent`, `indentRight`, and `firstLineIndent` are written as left, right, and first-line indentation; a negative `firstLineIndent` becomes a hanging indent                                                               |
| **Paragraph/heading `contextualSpacing`**      | Suppresses spacing between adjacent paragraphs of the same style in the export                                                                                                                                             |
| **Paragraph/heading `keepNext` / `keepLines`** | Written as Word's keep-with-next and keep-lines-together pagination hints                                                                                                                                                  |

## What to expect

- **Needs a Convert token.** Every export goes to the Convert service, so you need a `token` that allows `Convert:Export:Docx`.
- **The file matches your editor.** The extension measures your editor’s CSS and sends it with the document.
- **Callback delivery.** `onCompleteExport` receives the file as a `Blob`, a `string` or a `Uint8Array`, depending on `exportType`.

## What not to expect

- **Round-trip identity.** Importing a DOCX, editing it, and exporting it back is not byte-identical. A handful of attributes (tab stops, and fixed `px`/`pt` line heights) are extracted on import but not written on export today. See the [feature support matrix](/conversion/getting-started/feature-support-matrix) for the full list.
- **Pixel-perfect Word match.** We aim for visually faithful round-trips on the supported feature set; absolute parity with Word's rendering engine is out of scope.
- **Header and footer options.** Headers and footers come from the document's page layout. The `headers` and `footers` options are gone, see [Migrate to v1](/conversion/export/docx/migrate-to-v1#removed-headers).

## Limitations

- **Doesn't work offline.** The export needs a connection to Convert.
- **Overrides take plain objects.** The extension drops a function override and reports an `unsupported` warning.

For a detailed breakdown of which document features are supported at each stage of the pipeline, see the [Supported features](/conversion/getting-started/feature-support-matrix) matrix.
