Use `@tiptap-pro/extension-export-docx` to export Tiptap content as a Word `.docx` file. The editor command runs in the browser. The package also provides an async `exportDocx()` function for browser and server use.

When the editor is visible on the page, [Document styles](/conversion/export/docx/document-styles) reads its supported CSS styles by default. CSS can use `.tiptap`, another class, or global selectors. Set `documentStyles: false` to skip this step. Word may wrap text and arrange pages differently from the browser.

## Choose an integration

You can also export through the [REST API](/conversion/export/docx/rest-api). Its options differ from the editor extension.

| Feature                                | Editor extension                                              | REST API                                                                                                       |
| -------------------------------------- | ------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| Runs in                                | Your app                                                      | Tiptap Cloud                                                                                                   |
| Editor CSS                             | Read from a mounted browser editor by default                 | No access to your editor's DOM or CSS                                                                          |
| Named Word styles                      | `styleOverrides`                                              | `styleOverrides`                                                                                               |
| Function-based custom nodes            | [`customNodes`](/conversion/export/docx/custom-nodes)         | Not accepted                                                                                                   |
| Element override objects and callbacks | [Supported](/conversion/export/docx/styles#element-overrides) | See the [endpoint's supported fields](/conversion/export/docx/rest-api). JavaScript callbacks are unavailable. |
| Headers and footers                    | Word objects, callbacks, or content from Pages                | See the endpoint's supported options                                                                           |
| Footnotes and endnotes                 | Content from Pages or explicit JSON options                   | See the endpoint's supported options                                                                           |

Use the [REST API reference](/conversion/export/docx/rest-api) to check which options it accepts.

## Install the DOCX Export extension

After you [set up the private registry](/guides/pro-extensions), install the package:

```bash
npm install @tiptap-pro/extension-export-docx
```

DOCX generation runs in your app and does not require Conversion credentials. Automatic WOFF2 font conversion is an optional service call that requires credentials. See [Fonts](/conversion/export/docx/fonts).

## Configuring the extension

Pass options to `ExportDocx.configure()`. Provide `onCompleteExport` here or when you call the command. This example uses an existing `<div id="editor"></div>` container.

```ts
import { Editor } from '@tiptap/core'
import StarterKit from '@tiptap/starter-kit'
import { ExportDocx } from '@tiptap-pro/extension-export-docx'

const editor = new Editor({
  element: document.querySelector('#editor'),
  extensions: [
    StarterKit,
    ExportDocx.configure({
      exportType: 'blob',
      documentStyles: true,
      onCompleteExport: (result) => {
        console.log('DOCX export ready', result)
      },
      onError: (error) => {
        console.error('DOCX export failed', error)
      },
    }),
  ],
  content: '<p>Hello, Word.</p>',
})
```

### Output and error options

| Option             | What it does                                                                                      | Default                                   |
| ------------------ | ------------------------------------------------------------------------------------------------- | ----------------------------------------- |
| `onCompleteExport` | Receives the file after the async export finishes.                                                | Required at configuration or command time |
| `exportType`       | Chooses `blob`, `buffer`, `stream`, `string`, or `base64`. Use `buffer` and `stream` on a server. | `'blob'`                                  |
| `onError`          | Receives an export error. Without it, the error becomes an unhandled promise rejection.           | Unset                                     |
| `onWarning`        | Receives a warning about a skipped image or unavailable editor styles.                            | `console.warn`                            |
| `onImageError`     | `'skip'` leaves an unusable image out. `'throw'` fails the export.                                | `'skip'`                                  |

### Style and content options

| Option                | What it does                                                                                       | Default                                                           |
| --------------------- | -------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------- |
| `documentStyles`      | Reads supported styles from the mounted browser editor.                                            | `true`                                                            |
| `cssStyles`           | Sets styles with CSS properties. `readFromStylesheets` reads supported `.tiptap` stylesheet rules. | Unset                                                             |
| `styleOverrides`      | Sets named Word styles above editor styles and `cssStyles`.                                        | `{}`                                                              |
| `paragraphOverrides`  | Sets paragraph properties with an object or a `(node, context)` callback.                          | Unset                                                             |
| `textRunOverrides`    | Sets text properties with an object or a `(node, context)` callback.                               | Unset                                                             |
| `tableOverrides`      | Sets table properties with an object or a `(node, context)` callback.                              | Unset                                                             |
| `tableRowOverrides`   | Sets row properties with an object or a `(node, context)` callback.                                | Unset                                                             |
| `tableCellOverrides`  | Sets cell properties with an object or a `(node, context)` callback.                               | Unset                                                             |
| `imageOverrides`      | Sets image properties with an object or a `(node, context)` callback.                              | Unset                                                             |
| `customNodes`         | Supplies JavaScript functions that convert custom nodes.                                           | `[]`                                                              |
| `customNodeDsl`       | Supplies JSON rules that convert custom nodes. A matching `customNodes` function takes priority.   | Unset                                                             |
| `customNodeDslLimits` | Changes the DSL resource limits.                                                                   | Package limits                                                    |
| `numberingFormats`    | Supplies custom ordered-list formats. Formats registered by ConvertKit are also read.              | Unset                                                             |
| `listLevels`          | Sets marker and text positions at each list depth.                                                 | Measured editor positions when available, otherwise Word defaults |

See [Styles](/conversion/export/docx/styles) for callback context and how properties combine with stored node attributes and marks. Named style overrides merge nested properties. Direct element overrides replace nested objects such as `borders` or `indent`.

### Page and document part options

| Option                  | What it does                                                                                                                     | Default                                                         |
| ----------------------- | -------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------- |
| `pageSize`              | Sets page width and height. Explicit values take priority over Pages settings.                                                   | Pages page format when available, otherwise A4                  |
| `pageMargins`           | Sets body margins and header/footer positions. Explicit values take priority over Pages settings.                                | Pages body margins when available, otherwise package defaults   |
| `pageColor`             | Sets the page background color.                                                                                                  | Editor background when captured, otherwise unset                |
| `defaultTabStop`        | Sets the distance between default tab stops in twips.                                                                            | Captured CSS tab width when available, otherwise Word's default |
| `headers`, `footers`    | Supplies Word objects or callbacks for default, first, and even pages.                                                           | Read from Pages when available                                  |
| `headerFooterOverrides` | Sets properties for header/footer converters. Omitted fields use body overrides. Captured styles keep properties you do not set. | Unset                                                           |
| `footnotes`, `endnotes` | Supplies note content as `Record<string, JSONContent>`, keyed by `noteId`.                                                       | Read from Pages when the matching note feature is enabled       |
| `comments`              | Supplies comment threads. Pass `{ threads: [] }` to omit them.                                                                   | Unarchived CommentsKit threads when available                   |

See [Page layout](/conversion/export/docx/page-layout), [Headers and footers](/conversion/export/docx/headers-footers), and [Footnotes and endnotes](/conversion/content-types/structures-and-media/footnotes-endnotes).

### Font options

| Option       | What it does                                                             | Default |
| ------------ | ------------------------------------------------------------------------ | ------- |
| `fonts`      | Supplies named TTF/OTF font files to embed.                              | Unset   |
| `embedFonts` | Finds and embeds fonts used by the export. Browser only.                 | `false` |
| `appId`      | Supplies the Conversion app ID for WOFF2 conversion.                     | Unset   |
| `token`      | Supplies the Conversion JWT for WOFF2 conversion.                        | Unset   |
| `endpoint`   | Sets the service URL for WOFF2 conversion. Takes priority over `region`. | Unset   |
| `region`     | Selects `'eu'` or `'us'` when `endpoint` is unset.                       | `'eu'`  |

Automatic WOFF2 conversion needs both `appId` and `token`. TTF/OTF embedding does not need that service call. See [Fonts](/conversion/export/docx/fonts).

## Export a DOCX file

Call the command after the editor mounts:

```ts
editor.commands.exportDocx()
```

The command returns `true` when it starts the export. It does not return the file or wait for completion. The file arrives through `onCompleteExport`; failures arrive through `onError`.

Pass an `ExportDocxCommandOptions` object to change options for one export. An option you omit uses its configured value:

```ts
editor.commands.exportDocx({
  documentStyles: false,
  onCompleteExport: (result) => {
    console.log('DOCX export ready', result)
  },
})
```

### How it works

The command captures the document when it starts. Later edits do not change that export. In a command chain, changes made before `exportDocx()` are included. `editor.can().exportDocx()` checks command availability without starting an export.

## Server-side export

Call the async `exportDocx()` function with Tiptap JSON. Supply `document`, `exportType`, `customNodes`, and `styleOverrides`:

```ts
import { writeFile } from 'node:fs/promises'
import { exportDocx } from '@tiptap-pro/extension-export-docx'

const result = await exportDocx({
  document: {
    type: 'doc',
    content: [{ type: 'paragraph', content: [{ type: 'text', text: 'Hello, Word.' }] }],
  },
  exportType: 'buffer',
  customNodes: [],
  styleOverrides: {},
})

if (Buffer.isBuffer(result)) {
  await writeFile('document.docx', result)
}
```

The direct function has no editor to read. It does not collect Pages content or CommentsKit threads automatically. Pass those values yourself. In the browser, use [readEditorDocxStyles](/conversion/export/docx/document-styles#use-the-standalone-exportdocx-function) when you need editor styles with the direct function.

Use `try` and `catch` to handle errors from the direct function. `onError` belongs to the editor command.

## Images that cannot be exported

The exporter fetches images by `src`. By default, it skips images with missing sources, failed requests, or unsupported formats and reports a warning. A paragraph containing only a skipped image is also removed.

```ts
editor.commands.exportDocx({
  onWarning: (warning) => {
    console.warn(warning.code, warning.message)
  },
})
```

| Warning field | What it contains                                                                                                          |
| ------------- | ------------------------------------------------------------------------------------------------------------------------- |
| `code`        | `image-missing-src`, `image-request-failed`, `image-fetch-failed`, `image-unsupported-type`, or `document-styles-failed`. |
| `message`     | A description of the warning.                                                                                             |
| `src`         | The image source, when available.                                                                                         |
| `status`      | The HTTP status for a failed response, when available.                                                                    |
| `contentType` | The detected type for an unsupported image, when available.                                                               |

Exceptions in `onWarning` do not stop the export. Set `onImageError: 'throw'` to fail instead of skipping an image. The package exports `ImageConversionError` and its subclasses: `ImageMissingSrcError`, `ImageRequestError`, `ImageFetchError`, and `UnsupportedImageTypeError`.

<Callout title="Use reachable image URLs" variant="hint">
  Use image sources the export environment can fetch. A server has no browser origin to resolve a
  relative URL such as `/img/chart.png`.
</Callout>

## When the export fails

The command calls `onError` when conversion fails, including failures while it collects export data. It does not call `onCompleteExport` for that failed export.

Unavailable editor styles are a warning rather than a failed export. The exporter keeps the content, uses fallback styles, and still applies your explicit style settings. See [Document styles warnings](/conversion/export/docx/document-styles#warnings).

## Node attribute inference

The exporter uses supported node attributes as well as captured browser styles:

| Content                 | Export behavior                                                                                                                                                                                                                                     |
| ----------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Images                  | Keeps dimensions and alt text. With Document styles, supported rendered dimensions also include CSS sizing. Explicit `imageOverrides.transformation` takes priority.                                                                                |
| Tables                  | Keeps column widths, row and column spans, borders, cell backgrounds, vertical alignment, row heights, and cell margins. Captured styles also cover individual tables, rows, and cells.                                                             |
| Paragraphs and headings | Keeps alignment, spacing, indentation, `contextualSpacing`, `keepNext`, and `keepLines`. Explicit `false` values in `paragraphOverrides` can reset inherited paragraph settings.                                                                    |
| Line height             | A unitless or percentage value sets a minimum line height based on the paragraph font size. Absolute units such as `px` or `pt` set an exact height. Uniform inline `textStyle.lineHeight` can supply the paragraph height when the block has none. |
| Lists                   | Keeps ordered-list `start` and `type`, custom numbering formats, nesting, and content after the first block in an item.                                                                                                                             |
| Code blocks             | Keeps line breaks, empty lines, tabs, and spaces. Captured syntax colors and supported text formatting can also be exported.                                                                                                                        |
| Math                    | Exports supported equations as editable Word math. Unsupported structures fall back to source LaTeX text.                                                                                                                                           |

See the [content reference](/conversion/content-types/overview) for details and limits.

## What to expect

DOCX generation runs locally in your app. Images and automatic font loading can still make network requests. The export completes asynchronously.

Document styles copies supported formatting, including styles on individual nodes and text segments. It does not guarantee identical line wrapping or page counts in Word. Your explicit styles, node attributes, and marks still affect the result.

## What not to expect

Importing, editing, and exporting a document does not recreate the original file byte for byte. Some Word features have no matching Tiptap node or export mapping.

On-screen page boundaries are not saved as automatic Word page breaks. Pages supplies page settings and document parts; Word arranges the exported content using its own page layout. Add [explicit page breaks](/conversion/export/docx/page-breaks) where you need them.
