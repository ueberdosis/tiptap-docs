The `@tiptap-pro/extension-export-docx` extension includes built-in support for customizing the headers and footers of the exported document.

<CodeDemo isPro path="/Extensions/ExportDocxCustomHeaderFooter" />

When adding this extension it will allow you to configure your `ExportDocx` with some additional properties:

## Headers Configuration

The `headers` object allows you to customize the headers of your exported DOCX document:

| Property | Type | Description |
| --- | --- | --- |
| `evenAndOddHeaders` | `boolean` | Whether to use different headers for odd and even pages |
| `differentFirstPage` | `boolean` | Whether to use a different header on the first page. When `true`, the `first` value is used on page one instead of `default`. |
| `default` | `Header \| ((overrides?: ResolvedHeaderFooterOverrides) => Promise<Header>)` | The standard default header on every page, or header on odd pages when the `evenAndOddHeaders` option is activated. Can be a `Header` object or an async function that returns a `Header`. The function receives the [resolved overrides](#pass-the-overrides-on) |
| `first` | `Header \| ((overrides?: ResolvedHeaderFooterOverrides) => Promise<Header>)` | The header on the first page. Only used when `differentFirstPage` is set to `true`. Can be a `Header` object or an async function that returns a `Header` |
| `even` | `Header \| ((overrides?: ResolvedHeaderFooterOverrides) => Promise<Header>)` | The header on even pages when the `evenAndOddHeaders` option is activated. Can be a `Header` object or an async function that returns a `Header` |

## Footers Configuration

The `footers` object allows you to customize the footers of your exported DOCX document:

| Property | Type | Description |
| --- | --- | --- |
| `evenAndOddFooters` | `boolean` | Whether to use different footers for odd and even pages |
| `differentFirstPage` | `boolean` | Whether to use a different footer on the first page. When `true`, the `first` value is used on page one instead of `default`. |
| `default` | `Footer \| ((overrides?: ResolvedHeaderFooterOverrides) => Promise<Footer>)` | The standard default footer on every page, or footer on odd pages when the `evenAndOddFooters` option is activated. Can be a `Footer` object or an async function that returns a `Footer`. The function receives the [resolved overrides](#pass-the-overrides-on) |
| `first` | `Footer \| ((overrides?: ResolvedHeaderFooterOverrides) => Promise<Footer>)` | The footer on the first page. Only used when `differentFirstPage` is set to `true`. Can be a `Footer` object or an async function that returns a `Footer` |
| `even` | `Footer \| ((overrides?: ResolvedHeaderFooterOverrides) => Promise<Footer>)` | The footer on even pages when the `evenAndOddFooters` option is activated. Can be a `Footer` object or an async function that returns a `Footer` |

Word has one "different first page" setting and one "different odd and even pages" setting, which headers and footers share. The export turns each setting on when `headers` or `footers` asks for it.

For headers and footers you pass yourself, the export does not copy content between them. When `headers` turns on a different first page or odd and even pages, also pass `footers.first` or `footers.even`, or those pages get an empty footer. The same holds the other way: when `footers` turns a setting on, pass the matching `headers` slot, or those pages get an empty header.

## Where headers and footers come from

The export chooses the headers and the footers separately. For each of them, it uses the first source that is set:

1. `headers` or `footers` passed to the `exportDocx` command.
2. `headers` or `footers` set with `ExportDocx.configure()`.
3. The headers or footers of the [Pages extension](/pages/core-concepts/page-header-footer), when Pages is installed.

A command value replaces the configured value as a whole, its flags included. An empty object, such as `headers: {}`, also counts as set, so the file gets no headers even with Pages. You can configure your own headers and still export the Pages footers.

With Pages, the export takes each header and footer variant from Pages: default, first page, odd and even pages. Pages can turn on a different first page, or different odd and even pages, for the header and the footer apart. When only one of them uses such a setting, the export turns the Word setting on and the other one repeats its normal content on those pages.

With [computed styles](/conversion/export/docx/computed-styles), Pages headers and footers keep the styles the page shows for them. Headers and footers that you pass yourself use the styles of the document body.

# Usage Examples

## Extension Configuration

Headers and footers are configured through the `ExportDocx.configure()` method. You can use direct `Docx` namespace objects like `Docx.Header` and `Docx.Footer` for full control:

<Callout title="Note about Header and Footer Objects" type="info">
The `Header`, `Footer`, `Paragraph`, and `TextRun` objects are accessed through the `Docx` namespace exported from `@tiptap-pro/extension-export-docx`. You can customize them with any valid content including paragraphs, text runs, and more if available within the standard elements that can be used within a DOCX header or footer.

Build them with this `Docx` export. The export throws an error for a `Header` or `Footer` built with another copy of the `docx` package, because such an instance would write an empty header or footer.
</Callout>

```javascript
import { ExportDocx, Docx } from '@tiptap-pro/extension-export-docx'

const editor = new Editor({
  extensions: [
    // ... other extensions
    ExportDocx.configure({
      onCompleteExport: result => {
        // Handle the export result
        const blob = new Blob([result], {
          type: 'application/vnd.openxmlformats-officedocument.wordprocessingml.document',
        })
        const url = URL.createObjectURL(blob)
        const a = document.createElement('a')
        a.href = url
        a.download = 'export.docx'
        a.click()
        URL.revokeObjectURL(url)
      },
      headers: {
        evenAndOddHeaders: true,
        differentFirstPage: true,
        default: new Docx.Header({
          children: [
            new Docx.Paragraph({
              children: [
                new Docx.TextRun({
                  text: "Default Header",
                  bold: true,
                }),
              ],
            }),
          ],
        }),
        first: new Docx.Header({
          children: [
            new Docx.Paragraph({
              children: [
                new Docx.TextRun({
                  text: "First Page Header",
                  size: 24,
                  bold: true,
                }),
              ],
            }),
          ],
        }),
        even: new Docx.Header({
          children: [
            new Docx.Paragraph({
              children: [
                new Docx.TextRun({
                  text: "Even Page Header",
                }),
              ],
            }),
          ],
        }),
      },
      // The header settings also turn on the first page and even page footers
      footers: {
        default: new Docx.Footer({
          children: [
            new Docx.Paragraph({
              children: [
                new Docx.TextRun({
                  text: "Default Footer",
                }),
              ],
            }),
          ],
        }),
        first: new Docx.Footer({
          children: [
            new Docx.Paragraph({
              children: [
                new Docx.TextRun({
                  text: "First Page Footer",
                }),
              ],
            }),
          ],
        }),
        even: new Docx.Footer({
          children: [
            new Docx.Paragraph({
              children: [
                new Docx.TextRun({
                  text: "Even Page Footer",
                }),
              ],
            }),
          ],
        }),
      },
    }),
  ],
})

// Trigger export
editor.commands.exportDocx()
```

### Using Helper Functions (Alternative Approach)

For easier handling of Tiptap-style content, you can use the `convertHeader` and `convertFooter` helper functions that automatically handle mark conversion, links, and other Tiptap features.

```javascript
import { ExportDocx, convertFooter, convertHeader } from '@tiptap-pro/extension-export-docx'

const editor = new Editor({
  extensions: [
    // ... other extensions
    ExportDocx.configure({
      onCompleteExport: result => {
        // Handle the export result
        const blob = new Blob([result], {
          type: 'application/vnd.openxmlformats-officedocument.wordprocessingml.document',
        })
        const url = URL.createObjectURL(blob)
        const a = document.createElement('a')
        a.href = url
        a.download = 'export.docx'
        a.click()
        URL.revokeObjectURL(url)
      },
      headers: {
        evenAndOddHeaders: true,
        differentFirstPage: true,
        default: async overrides =>
          convertHeader({
            ...overrides,
            node: {
              type: 'paragraph',
              content: [
                {
                  type: 'text',
                  text: 'Header',
                  marks: [{ type: 'textStyle', attrs: { color: 'red' } }],
                },
              ],
            },
          }),
        first: async overrides =>
          convertHeader({
            ...overrides,
            node: {
              type: 'paragraph',
              content: [
                {
                  type: 'text',
                  text: 'First Page Header',
                  marks: [{ type: 'bold' }],
                },
              ],
            },
          }),
        even: async overrides =>
          convertHeader({
            ...overrides,
            node: {
              type: 'paragraph',
              content: [
                {
                  type: 'text',
                  text: 'Even Page Header',
                  marks: [{ type: 'textStyle', attrs: { color: 'blue' } }],
                },
              ],
            },
          }),
      },
      footers: {
        default: async overrides =>
          convertFooter({
            ...overrides,
            node: {
              type: 'paragraph',
              content: [
                {
                  type: 'text',
                  text: 'Footer',
                  marks: [{ type: 'textStyle', attrs: { color: 'red' } }],
                },
              ],
            },
          }),
        first: async overrides =>
          convertFooter({
            ...overrides,
            node: {
              type: 'paragraph',
              content: [
                {
                  type: 'text',
                  text: 'First Page Footer',
                  marks: [{ type: 'bold' }],
                },
              ],
            },
          }),
        even: async overrides =>
          convertFooter({
            ...overrides,
            node: {
              type: 'paragraph',
              content: [
                {
                  type: 'text',
                  text: 'Even Page Footer',
                  marks: [{ type: 'textStyle', attrs: { color: 'blue' } }],
                },
              ],
            },
          }),
      },
    }),
  ],
})

// Trigger export
editor.commands.exportDocx()
```

The `convertHeader` and `convertFooter` helper functions expect a Tiptap node, which in this case it's a paragraph, and they will automatically handle:
- Mark conversion (bold, italic, colors, etc.)
- Link conversion
- Text styling and formatting
- Complex Tiptap node structures

This makes it much easier to create rich headers and footers using familiar Tiptap JSON structure. The node can also be a `doc` node. The helpers then convert every block in it, lists and tables included.

<Callout title="Important note!">
    `convertHeader` and `convertFooter` return a `Promise`, because they load the images in the content. Call them inside a function, as in the example above. The export calls the function and waits for the result.
</Callout>

### Pass the overrides on

The export calls each header and footer function with one argument, the resolved overrides. They hold the body-wide overrides with your [`headerFooterOverrides`](/conversion/export/docx/styles#headerfooteroverrides) applied, `styleOverrides`, `onWarning` and `onImageError`. Spread them into `convertHeader` or `convertFooter`, as the example above does.

The argument also carries what the export shares across the whole file. Without it, the header or footer misses these:

- Tracked changes. With the argument, suggestions in the header or footer export as Word revisions, with revision ids that are unique in the whole file. Without it, the text exports without revisions, and deleted text appears as normal text. See [Export tracked changes](/conversion/export/docx/tracked-changes).
- [`customNodeDsl`](/conversion/export/docx/custom-nodes-dsl) rules. With the argument, they render custom nodes in the header or footer.
- List number types. With the argument, an ordered list keeps the number type of its `type` attribute, such as `I` for upper roman numbers. Without it, the list counts in decimal numbers. Its `start` number works either way. See [Ordered list numbering](/conversion/export/docx/ordered-list-numbering#list-starts-and-number-types).

The argument does not carry `customNodes`, `pageSize`, `pageMargins`, `numberingFormats`, `listLevels` or `placeholders`. Pass them yourself when the header or footer needs them. The headers and footers that the export takes from Pages get all of these.

### `ConvertHeaderOptions` and `ConvertFooterOptions`

`convertHeader` takes a `ConvertHeaderOptions` object and `convertFooter` a `ConvertFooterOptions` object. Both types are exported from the package and have the same fields:

| Field                                                                                                                       | Type                         | Description                                                                                                                                         |
| --------------------------------------------------------------------------------------------------------------------------- | ---------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| `node`                                                                                                                      | `JSONContent \| null`        | The content. A `doc` node converts every block in it, any other node converts on its own. `null` gives an empty header or footer.                    |
| `customNodes`                                                                                                               | `CustomNode[]`               | Render functions for custom nodes in the content.                                                                                                   |
| `styleOverrides`                                                                                                            | `IStylesOptions`             | The Word styles of the document. The overrides argument carries them.                                                                               |
| `pageSize`, `pageMargins`                                                                                                   | Same as the export options   | The page geometry, which sizes tables in the content.                                                                                               |
| `paragraphOverrides`, `textRunOverrides`, `tableOverrides`, `tableRowOverrides`, `tableCellOverrides`, `imageOverrides`     | Same as the export options   | Element overrides for the content. The overrides argument carries the values for headers and footers.                                              |
| `onWarning`, `onImageError`                                                                                                 | Same as the export options   | What happens with images that cannot be exported.                                                                                                   |
| `numberingFormats`, `listLevels`                                                                                            | Same as the export options   | Numbering formats and list positions for lists in the content.                                                                                      |
| `placeholders`                                                                                                              | `DocxPlaceholders`           | Turns `{page}` and `{total}` into live page number fields. See [Custom token names](#custom-token-names).                                          |

## Advanced Examples

### Dynamic Headers and Footers with Async Functions

You can also provide asynchronous functions that return `Header` or `Footer` objects. This is useful for dynamic content generation, such as fetching user data, formatting current dates, or processing images.

<Callout title="Async Function Benefits" type="tip">
Using async functions for headers and footers enables powerful use cases like: Fetching user information from APIs, including current timestamps or dynamic dates, processing and embedding images, calculating document statistics, retrieving data from databases or external services.
</Callout>

```javascript
import { ExportDocx, Docx } from '@tiptap-pro/extension-export-docx'

// Function to fetch user information
async function getCurrentUser() {
  // This could be an API call, database query, etc.
  return {
    name: 'John Doe',
    department: 'Engineering',
    email: 'john.doe@company.com'
  }
}

const editor = new Editor({
  extensions: [
    // ... other extensions
    ExportDocx.configure({
      onCompleteExport: result => {
        // Handle the export result
        const blob = new Blob([result], {
          type: 'application/vnd.openxmlformats-officedocument.wordprocessingml.document',
        })
        const url = URL.createObjectURL(blob)
        const a = document.createElement('a')
        a.href = url
        a.download = 'export.docx'
        a.click()
        URL.revokeObjectURL(url)
      },
      headers: {
        default: async () => {
          const user = await getCurrentUser()
          const currentDate = new Date().toLocaleDateString()
          
          return new Docx.Header({
            children: [
              new Docx.Paragraph({
                children: [
                  new Docx.TextRun({
                    text: `Document prepared by: ${user.name} (${user.department}) on ${currentDate}`,
                    size: 20,
                  }),
                ],
              }),
            ],
          })
        },
      },
      footers: {
        default: async () => {
          const user = await getCurrentUser()
          
          return new Docx.Footer({
            children: [
              new Docx.Paragraph({
                children: [
                  new Docx.TextRun({
                    text: `Contact: ${user.email} | Generated: ${new Date().toISOString()}`,
                    size: 16,
                    italics: true,
                  }),
                ],
              }),
            ],
          })
        },
      },
    }),
  ],
})

// Trigger export
editor.commands.exportDocx()
```

<Callout title="Async function lifecycle">
    The export calls the asynchronous functions after it has converted the document body, and before it builds the file.
</Callout>

### Mixed Static and Dynamic Headers/Footers

You can combine static headers/footers with dynamic ones for different pages:

```javascript
import { ExportDocx, Docx } from '@tiptap-pro/extension-export-docx'

const editor = new Editor({
  extensions: [
    // ... other extensions
    ExportDocx.configure({
      onCompleteExport: result => {
        // Handle the export result
        const blob = new Blob([result], {
          type: 'application/vnd.openxmlformats-officedocument.wordprocessingml.document',
        })
        const url = URL.createObjectURL(blob)
        const a = document.createElement('a')
        a.href = url
        a.download = 'export.docx'
        a.click()
        URL.revokeObjectURL(url)
      },
      headers: {
        differentFirstPage: true,
        // Static first page header
        first: new Docx.Header({
          children: [
            new Docx.Paragraph({
              children: [
                new Docx.TextRun({
                  text: "Company Confidential Report",
                  size: 24,
                  bold: true,
                }),
              ],
            }),
          ],
        }),
        // Dynamic default header for subsequent pages
        default: async () => {
          const reportData = await fetchReportMetadata()
          
          return new Docx.Header({
            children: [
              new Docx.Paragraph({
                children: [
                  new Docx.TextRun({
                    text: `${reportData.title} - Generated ${reportData.timestamp}`,
                    size: 18,
                  }),
                ],
              }),
            ],
          })
        },
      },
      footers: {
        // Static first page footer, because the header turns on a different first page
        first: new Docx.Footer({
          children: [
            new Docx.Paragraph({
              children: [
                new Docx.TextRun({
                  text: "Internal use only",
                  size: 14,
                }),
              ],
            }),
          ],
        }),
        // Dynamic default footer for subsequent pages
        default: async () => {
          const stats = await getDocumentStats()
          
          return new Docx.Footer({
            children: [
              new Docx.Paragraph({
                children: [
                  new Docx.TextRun({
                    text: `Page Count: ${stats.pages} | Word Count: ${stats.words}`,
                    size: 14,
                  }),
                ],
              }),
            ],
          })
        },
      },
    }),
  ],
})

async function fetchReportMetadata() {
  // Simulate API call
  return {
    title: 'Quarterly Business Report',
    timestamp: new Date().toLocaleDateString()
  }
}

async function getDocumentStats() {
  // Simulate document analysis
  return {
    pages: 10,
    words: 2500
  }
}
```

## Page Numbering

The export supports two ways to emit live page-number fields:

1. **`{page}` / `{total}` tokens in header and footer text**: works automatically with headers and footers from the [Pages extension](/pages/getting-started/overview). For your own Tiptap JSON, convert it with `convertHeader` / `convertFooter` and pass `placeholders: {}`. The export converts each token to a live `PAGE` / `NUMPAGES` field, so Word renders the actual current page and total page count. `headers` and `footers` do not accept plain-text strings. The export fails when it gets one.
2. **The `Docx.PageNumber` API**: required when you build header/footer content manually with `new Docx.Header()` / `new Docx.Footer()`, or when you need formatting around the field that goes beyond the bare token. The `convertHeader` / `convertFooter` helpers do not currently process `Docx.PageNumber` references, so pass the `Docx` instance directly.

### Page numbers via `{page}` / `{total}` tokens

Headers and footers auto-extracted from the Pages extension, such as one set via `editor.commands.setHeader('Page {page} of {total}')`, render the tokens as live page-number fields in the exported DOCX. For your own headers and footers, convert Tiptap JSON with `convertHeader` / `convertFooter` and pass `placeholders: {}` to turn on the default token names:

```javascript
import { ExportDocx, convertFooter, convertHeader } from '@tiptap-pro/extension-export-docx'

const text = value => ({ type: 'paragraph', content: [{ type: 'text', text: value }] })

const editor = new Editor({
  extensions: [
    // ... other extensions
    ExportDocx.configure({
      onCompleteExport: result => {
        const blob = new Blob([result], {
          type: 'application/vnd.openxmlformats-officedocument.wordprocessingml.document',
        })
        const url = URL.createObjectURL(blob)
        const a = document.createElement('a')
        a.href = url
        a.download = 'export.docx'
        a.click()
        URL.revokeObjectURL(url)
      },
      // `placeholders: {}` converts `{page}` and `{total}`
      // to live `PAGE` / `NUMPAGES` fields on export.
      headers: {
        default: overrides =>
          convertHeader({
            ...overrides,
            node: text('Confidential | Page {page} of {total}'),
            placeholders: {},
          }),
      },
      footers: {
        default: overrides =>
          convertFooter({ ...overrides, node: text('Page {page} of {total}'), placeholders: {} }),
      },
    }),
  ],
})

// Trigger export
editor.commands.exportDocx()
```

The same conversion runs automatically when headers/footers are auto-extracted from the Pages extension, so a footer set via `editor.commands.setFooter('Page {page} of {total}')` exports with live page numbers without any extra configuration.

### Custom token names

If your editor renames the built-in tokens via `Pages.configure({ placeholders: { total: 'pages' } })` (see [Pages → renaming placeholders](/pages/core-concepts/page-header-footer#renaming-or-disabling-placeholders)), the export honors the same token names: `{pages}` becomes a live `NUMPAGES` field, and the original `{total}` stops being recognized. There is no `placeholders` option on `ExportDocx` itself; configuring on Pages keeps the editor preview and the exported `.docx` consistent.

This applies to the headers and footers that the export takes from Pages. When calling `convertHeader` / `convertFooter` directly (for example, in your own header functions, or from server-side code without an editor), you can pass `placeholders` explicitly. The overrides argument of a header function does not carry them:

```javascript
import { convertFooter } from '@tiptap-pro/extension-export-docx'

const footer = await convertFooter({
  node: { type: 'paragraph', content: [{ type: 'text', text: 'Page {page} of {pages}' }] },
  placeholders: { total: 'pages' },
})
```

Pass `placeholders: false` to disable substitution and emit the tokens as literal text. Omitting `placeholders` entirely on a direct `convertHeader` / `convertFooter` call also disables substitution; you opt in explicitly.
