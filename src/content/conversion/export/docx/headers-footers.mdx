The headers and footers of your exported `.docx` come from the document's page layout. You don't build them in `ExportDocx`. To change how their content looks, use `headerFooterOverrides`.

<Callout title="Upgrading from 0.x?" variant="hint">
  The `headers`, `footers` and `placeholders` options are gone in `1.0.0`, and so are
  `convertHeader` and `convertFooter`. See [Removed options](#removed-options).
</Callout>

## How headers and footers are exported

`ExportDocx` reads the document's page layout from the editor and sends it to Convert with the document. Convert writes the headers and footers into the file. When you call Convert yourself, send the source document with its section bands as `document`, and the page geometry as `pageSetup`.

## Style header and footer content

By default, header and footer content uses the same element overrides as the body. Set `headerFooterOverrides` to style it differently. It takes the same six fields as the body overrides: `paragraphOverrides`, `textRunOverrides`, `tableOverrides`, `tableRowOverrides`, `tableCellOverrides` and `imageOverrides`. A field you leave out uses the body-wide value.

This example keeps a border on body tables and removes it from tables in the headers and footers:

```ts
import { Editor } from '@tiptap/core'
import { ConvertKit } from '@tiptap-pro/extension-convert-kit'
import { ExportDocx } from '@tiptap-pro/extension-export-docx'

const border = { style: 'single', size: 4, color: '000000' }
const noBorder = { style: 'none' }

const editor = new Editor({
  extensions: [
    ConvertKit,
    ExportDocx.configure({
      token: 'YOUR_JWT',
      appId: 'YOUR_APP_ID',
      onCompleteExport: (result) => {
        /* save the file */
      },
      tableOverrides: {
        borders: { top: border, bottom: border, left: border, right: border },
      },
      headerFooterOverrides: {
        tableOverrides: {
          borders: { top: noBorder, bottom: noBorder, left: noBorder, right: noBorder },
        },
        textRunOverrides: { size: 18 },
      },
    }),
  ],
})
```

Each field is a plain object. A function is left out of the export and reported through `onWarning` with the `unsupported` code. See [function overrides](/conversion/export/docx/migrate-to-v1#removed-function-overrides).

See [Export styles](/conversion/export/docx/styles#element-overrides) for every element override.

## Pages v1

If you use the [Pages extension](/pages/getting-started/overview), `1.0.0` doesn't export its headers and footers. Its footnotes and endnotes still export. See [Migrate to v1](/conversion/export/docx/migrate-to-v1#pages-v1).

## Removed options

These options and helpers are gone in `1.0.0`:

- `headers` and `footers`. The extension leaves them out of the export and reports an `unsupported` warning. See [`headers`](/conversion/export/docx/migrate-to-v1#removed-headers) and [`footers`](/conversion/export/docx/migrate-to-v1#removed-footers).
- `placeholders`, which renamed the `{page}` and `{total}` tokens. See [`placeholders`](/conversion/export/docx/migrate-to-v1#removed-placeholders).
- `convertHeader` and `convertFooter`. See [`convert*` functions](/conversion/export/docx/migrate-to-v1#removed-converters).
- `Docx.Header`, `Docx.Footer` and `Docx.PageNumber`. See [`Docx` namespace](/conversion/export/docx/migrate-to-v1#removed-Docx).

## Limitations

- Headers and footers from the Pages extension aren't exported.
- `headerFooterOverrides` takes plain objects. Function values are left out.
