Use `@tiptap-pro/extension-export-docx` to include headers and footers in your Word document. You can export content from [Pages](/pages/core-concepts/page-header-footer) or provide your own `Docx.Header` and `Docx.Footer` objects.

## Export from Pages

When Pages is installed, `editor.commands.exportDocx()` reads its default, first-page, and odd/even headers and footers. With `documentStyles` enabled, the exporter reads each part's own displayed styles. A header can use a different font, color, or paragraph layout from the document body.

The exporter copies the Pages content before waiting for fonts. Edits made after the export starts do not replace the content being exported. If the exporter cannot find a matching preview or active editor for a part, it still converts that part's JSON but cannot read its displayed styles.

Explicit `headers` or `footers` options take priority over Pages content. This applies to both `ExportDocx.configure()` and a single `exportDocx()` call. Supplying `headers` replaces the automatic header configuration as a whole; it does not replace only one slot. Footer options work the same way.

## Header configuration

The `headers` object allows you to customize the headers of your exported DOCX document:

| Property             | Type                                          | Description                                                                                                                   |
| -------------------- | --------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| `evenAndOddHeaders`  | `boolean`                                     | Whether to use different headers for odd and even pages                                                                       |
| `differentFirstPage` | `boolean`                                     | Whether to use a different header on the first page. When `true`, the `first` value is used on page one instead of `default`. |
| `default`            | `Header \| ((overrides?) => Promise<Header>)` | Header for every page, or odd pages when `evenAndOddHeaders` is enabled.                                                      |
| `first`              | `Header \| ((overrides?) => Promise<Header>)` | First-page header. Use with `differentFirstPage: true`.                                                                       |
| `even`               | `Header \| ((overrides?) => Promise<Header>)` | Even-page header when `evenAndOddHeaders` is enabled.                                                                         |

## Footer configuration

The `footers` object allows you to customize the footers of your exported DOCX document:

| Property             | Type                                          | Description                                                                                                                   |
| -------------------- | --------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| `evenAndOddFooters`  | `boolean`                                     | Whether to use different footers for odd and even pages                                                                       |
| `differentFirstPage` | `boolean`                                     | Whether to use a different footer on the first page. When `true`, the `first` value is used on page one instead of `default`. |
| `default`            | `Footer \| ((overrides?) => Promise<Footer>)` | Footer for every page, or odd pages when `evenAndOddFooters` is enabled.                                                      |
| `first`              | `Footer \| ((overrides?) => Promise<Footer>)` | First-page footer. Use with `differentFirstPage: true`.                                                                       |
| `even`               | `Footer \| ((overrides?) => Promise<Footer>)` | Even-page footer when `evenAndOddFooters` is enabled.                                                                         |

## Header and footer styles

Use `headerFooterOverrides` to give these parts their own paragraph, text, table, table-row, cell, or image formatting. An omitted field falls back to the corresponding body override. A field you provide replaces that body override. Captured Document styles for the part remain available, and your explicit values take priority.

Header and footer factories receive the resolved formatting as an optional `ResolvedHeaderFooterOverrides` argument. Pass it to `convertHeader` or `convertFooter` to use that formatting:

```ts
import { ExportDocx, convertHeader } from '@tiptap-pro/extension-export-docx'

ExportDocx.configure({
  headerFooterOverrides: {
    textRunOverrides: { font: 'Arial', size: 20 },
  },
  headers: {
    default: async (overrides) =>
      convertHeader({
        ...overrides,
        node: {
          type: 'doc',
          content: [{ type: 'paragraph', content: [{ type: 'text', text: 'Project report' }] }],
        },
      }),
  },
  onCompleteExport: (result) => {
    // Download or save the exported file.
  },
})
```

Completed `Docx.Header` and `Docx.Footer` objects keep the formatting you used to build them. The exporter does not apply these overrides to their existing contents.

## Usage examples

### Extension configuration

Headers and footers are configured through the `ExportDocx.configure()` method. You can use direct `Docx` namespace objects like `Docx.Header` and `Docx.Footer` for full control:

<Callout title="Use the exported Docx classes" type="info">
  Import `Docx` from `@tiptap-pro/extension-export-docx` to create headers, footers, paragraphs, and
  text runs. Use these bundled classes so the exporter can recognize your objects.
</Callout>

```javascript
import { ExportDocx, Docx } from '@tiptap-pro/extension-export-docx'

const editor = new Editor({
  extensions: [
    // ... other extensions
    ExportDocx.configure({
      onCompleteExport: (result) => {
        // Handle the export result
        const blob = new Blob([result], {
          type: 'application/vnd.openxmlformats-officedocument.wordprocessingml.document',
        })
        const url = URL.createObjectURL(blob)
        const a = document.createElement('a')
        a.href = url
        a.download = 'export.docx'
        a.click()
        URL.revokeObjectURL(url)
      },
      headers: {
        evenAndOddHeaders: true,
        differentFirstPage: true,
        default: new Docx.Header({
          children: [
            new Docx.Paragraph({
              children: [
                new Docx.TextRun({
                  text: 'Default Header',
                  bold: true,
                }),
              ],
            }),
          ],
        }),
        first: new Docx.Header({
          children: [
            new Docx.Paragraph({
              children: [
                new Docx.TextRun({
                  text: 'First Page Header',
                  size: 24,
                  bold: true,
                }),
              ],
            }),
          ],
        }),
        even: new Docx.Header({
          children: [
            new Docx.Paragraph({
              children: [
                new Docx.TextRun({
                  text: 'Even Page Header',
                }),
              ],
            }),
          ],
        }),
      },
      footers: {
        default: new Docx.Footer({
          children: [
            new Docx.Paragraph({
              children: [
                new Docx.TextRun({
                  text: 'Default Footer',
                }),
              ],
            }),
          ],
        }),
      },
    }),
  ],
})

// Trigger export
editor.commands.exportDocx()
```

### Use Tiptap JSON

Use `convertHeader` and `convertFooter` to create these parts from Tiptap JSON.

```javascript
import { ExportDocx, convertHeader, convertFooter } from '@tiptap-pro/extension-export-docx'

const editor = new Editor({
  extensions: [
    // ... other extensions
    ExportDocx.configure({
      onCompleteExport: (result) => {
        // Handle the export result
        const blob = new Blob([result], {
          type: 'application/vnd.openxmlformats-officedocument.wordprocessingml.document',
        })
        const url = URL.createObjectURL(blob)
        const a = document.createElement('a')
        a.href = url
        a.download = 'export.docx'
        a.click()
        URL.revokeObjectURL(url)
      },
      headers: {
        evenAndOddHeaders: true,
        differentFirstPage: true,
        default: async () =>
          convertHeader({
            node: {
              type: 'paragraph',
              content: [
                {
                  type: 'text',
                  text: 'Header',
                  marks: [{ type: 'textStyle', attrs: { color: 'red' } }],
                },
              ],
            },
          }),
        first: async () =>
          convertHeader({
            node: {
              type: 'paragraph',
              content: [
                {
                  type: 'text',
                  text: 'First Page Header',
                  marks: [{ type: 'bold' }],
                },
              ],
            },
          }),
        even: async () =>
          convertHeader({
            node: {
              type: 'paragraph',
              content: [
                {
                  type: 'text',
                  text: 'Even Page Header',
                  marks: [{ type: 'textStyle', attrs: { color: 'blue' } }],
                },
              ],
            },
          }),
      },
      footers: {
        default: async () =>
          convertFooter({
            node: {
              type: 'paragraph',
              content: [
                {
                  type: 'text',
                  text: 'Footer',
                  marks: [{ type: 'textStyle', attrs: { color: 'red' } }],
                },
              ],
            },

        first: async () =>
          convertFooter({
            node: {
              type: 'paragraph',
              content: [
                {
                  type: 'text',
                  text: 'First Page Footer',
                  marks: [{ type: 'bold' }],
                },
              ],
            },
          }),
        even: async () =>
          convertFooter({
            node: {
              type: 'paragraph',
              content: [
                {
                  type: 'text',
                  text: 'Even Page Footer',
                  marks: [{ type: 'textStyle', attrs: { color: 'blue' } }],
                },
              ],
            },
          }),
      },
    }),
  ],
})

// Trigger export
editor.commands.exportDocx()
```

`convertHeader` and `convertFooter` accept a single node or a `doc` with several blocks. They convert paragraphs, headings, lists, tables, images, and other supported content. Pass the factory's `overrides` argument as shown above to use the export's styles and list numbering.

<Callout title="These helpers return a promise">
  Use an async header or footer factory when calling `convertHeader` or `convertFooter`. The
  exporter waits for the result, including images that need to load.
</Callout>

## More examples

### Load content in an async function

You can also provide asynchronous functions that return `Header` or `Footer` objects. This is useful for dynamic content generation, such as fetching user data, formatting current dates, or processing images.

<Callout title="Load content before creating the header" type="tip">
  An async factory can fetch user details or images, then build a header or footer from that data.
</Callout>

```javascript
import { ExportDocx, Docx } from '@tiptap-pro/extension-export-docx'

// Function to fetch user information
async function getCurrentUser() {
  // This could be an API call, database query, etc.
  return {
    name: 'John Doe',
    department: 'Engineering',
    email: 'john.doe@company.com',
  }
}

const editor = new Editor({
  extensions: [
    // ... other extensions
    ExportDocx.configure({
      onCompleteExport: (result) => {
        // Handle the export result
        const blob = new Blob([result], {
          type: 'application/vnd.openxmlformats-officedocument.wordprocessingml.document',
        })
        const url = URL.createObjectURL(blob)
        const a = document.createElement('a')
        a.href = url
        a.download = 'export.docx'
        a.click()
        URL.revokeObjectURL(url)
      },
      headers: {
        default: async () => {
          const user = await getCurrentUser()
          const currentDate = new Date().toLocaleDateString()

          return new Docx.Header({
            children: [
              new Docx.Paragraph({
                children: [
                  new Docx.TextRun({
                    text: `Document prepared by: ${user.name} (${user.department}) on ${currentDate}`,
                    size: 20,
                  }),
                ],
              }),
            ],
          })
        },
      },
      footers: {
        default: async () => {
          const user = await getCurrentUser()

          return new Docx.Footer({
            children: [
              new Docx.Paragraph({
                children: [
                  new Docx.TextRun({
                    text: `Contact: ${user.email} | Generated: ${new Date().toISOString()}`,
                    size: 16,
                    italics: true,
                  }),
                ],
              }),
            ],
          })
        },
      },
    }),
  ],
})

// Trigger export
editor.commands.exportDocx()
```

<Callout title="Async function lifecycle">
  The exporter calls these functions after converting the body. It waits for their results before
  building the Word document.
</Callout>

### Mix fixed content and async content

You can combine static headers/footers with dynamic ones for different pages:

```javascript
import { ExportDocx, Docx } from '@tiptap-pro/extension-export-docx'

const editor = new Editor({
  extensions: [
    // ... other extensions
    ExportDocx.configure({
      onCompleteExport: (result) => {
        // Handle the export result
        const blob = new Blob([result], {
          type: 'application/vnd.openxmlformats-officedocument.wordprocessingml.document',
        })
        const url = URL.createObjectURL(blob)
        const a = document.createElement('a')
        a.href = url
        a.download = 'export.docx'
        a.click()
        URL.revokeObjectURL(url)
      },
      headers: {
        // Static first page header
        differentFirstPage: true,
        first: new Docx.Header({
          children: [
            new Docx.Paragraph({
              children: [
                new Docx.TextRun({
                  text: 'Company Confidential Report',
                  size: 24,
                  bold: true,
                }),
              ],
            }),
          ],
        }),
        // Dynamic default header for subsequent pages
        default: async () => {
          const reportData = await fetchReportMetadata()

          return new Docx.Header({
            children: [
              new Docx.Paragraph({
                children: [
                  new Docx.TextRun({
                    text: `${reportData.title} - Generated ${reportData.timestamp}`,
                    size: 18,
                  }),
                ],
              }),
            ],
          })
        },
      },
      footers: {
        default: async () => {
          const stats = await getDocumentStats()

          return new Docx.Footer({
            children: [
              new Docx.Paragraph({
                children: [
                  new Docx.TextRun({
                    text: `Page Count: ${stats.pages} | Word Count: ${stats.words}`,
                    size: 14,
                  }),
                ],
              }),
            ],
          })
        },
      },
    }),
  ],
})

async function fetchReportMetadata() {
  // Simulate API call
  return {
    title: 'Quarterly Business Report',
    timestamp: new Date().toLocaleDateString(),
  }
}

async function getDocumentStats() {
  // Simulate document analysis
  return {
    pages: 10,
    words: 2500,
  }
}
```

## Page numbering

The export supports two ways to emit live page-number fields:

1. **`{page}` / `{total}` tokens in plain-text headers and footers**: works automatically with content extracted from the [Pages extension](/pages/getting-started/overview) and with plain-text strings passed to `headers` / `footers`. The export converts each token to a live `PAGE` / `NUMPAGES` field, so Word renders the actual current page and total page count.
2. **The `Docx.PageNumber` API**: required when you build header/footer content manually with `new Docx.Header()` / `new Docx.Footer()`, or when you need formatting around the field that goes beyond the bare token. The `convertHeader` / `convertFooter` helpers do not currently process `Docx.PageNumber` references, so pass the `Docx` instance directly.

### Page numbers via `{page}` / `{total}` tokens

Any plain-text header or footer (including those auto-extracted from the Pages extension via `editor.commands.setHeader('Page {page} of {total}')`) renders as live page-number fields in the exported DOCX:

```javascript
import { ExportDocx } from '@tiptap-pro/extension-export-docx'

const editor = new Editor({
  extensions: [
    // ... other extensions
    ExportDocx.configure({
      onCompleteExport: (result) => {
        const blob = new Blob([result], {
          type: 'application/vnd.openxmlformats-officedocument.wordprocessingml.document',
        })
        const url = URL.createObjectURL(blob)
        const a = document.createElement('a')
        a.href = url
        a.download = 'export.docx'
        a.click()
        URL.revokeObjectURL(url)
      },
      // Plain-text headers/footers: `{page}` and `{total}` are converted
      // to live `PAGE` / `NUMPAGES` fields on export.
      headers: {
        default: 'Confidential | Page {page} of {total}',
      },
      footers: {
        default: 'Page {page} of {total}',
      },
    }),
  ],
})

// Trigger export
editor.commands.exportDocx()
```

The same conversion runs automatically when headers/footers are auto-extracted from the Pages extension, so a footer set via `editor.commands.setFooter('Page {page} of {total}')` exports with live page numbers without any extra configuration.

### Custom token names

If your editor renames the built-in tokens via `Pages.configure({ placeholders: { total: 'pages' } })` (see [Pages → renaming placeholders](/pages/core-concepts/page-header-footer#renaming-or-disabling-placeholders)), the export honors the same token names: `{pages}` becomes a live `NUMPAGES` field, and the original `{total}` stops being recognized. There is no `placeholders` option on `ExportDocx` itself; configuring on Pages keeps the editor preview and the exported `.docx` consistent.

When calling `convertHeader` / `convertFooter` directly (for example, from server-side code without an editor), you can pass `placeholders` explicitly:

```javascript
import { convertFooter } from '@tiptap-pro/extension-export-docx'

const footer = await convertFooter({
  node: { type: 'paragraph', content: [{ type: 'text', text: 'Page {page} of {pages}' }] },
  placeholders: { total: 'pages' },
})
```

Pass `placeholders: false` to disable substitution and emit the tokens as literal text. Omitting `placeholders` entirely on a direct `convertHeader` / `convertFooter` call also disables substitution; you opt in explicitly.
