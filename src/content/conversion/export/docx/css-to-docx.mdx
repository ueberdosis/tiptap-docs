## What this does

`cssStyles` converts CSS rules into named Word styles, such as `Heading1` and `Normal`. You can pass rules as an object or read supported rules from browser stylesheets. Word users can edit those styles in the exported document.

To use the CSS shown in an editor on a web page, use [Document styles](/conversion/export/docx/document-styles). Your CSS does not need a `.tiptap` prefix. Use `cssStyles` when you want to supply style values on a server or replace values read from the editor.

You can also use it with [CSS injection on import](/conversion/import/docx/css-injection). The two conversions support different properties, so they do not preserve every style through an import and export cycle.

## How it works

1. The exporter combines rules passed in `styles` with rules read from browser stylesheets. For each property, values in `styles` take priority.
2. It converts supported selectors and properties to Word styles. It warns in the console when a value in `styles` is unsupported.
3. It combines these styles with the other export settings. `cssStyles` takes priority over document styles. `styleOverrides` takes priority over `cssStyles`.

```ts
import { ExportDocx } from '@tiptap-pro/extension-export-docx'

ExportDocx.configure({
  cssStyles: {
    styles: {
      h1: { fontSize: '32px', fontWeight: 'bold', color: '#1a1a1a' },
      p: { fontSize: '16px', marginTop: '0pt', marginBottom: '8pt' },
      blockquote: { fontStyle: 'italic', color: '#555' },
    },
    // Also read supported .tiptap rules from browser stylesheets.
    readFromStylesheets: true,
    // Resolve em and rem lengths with this size in pixels.
    baseFontSize: 16,
  },
})
```

You can pass `cssStyles` to `ExportDocx.configure()`, the `exportDocx` command, or the standalone `exportDocx()` function.

### Read rules from stylesheets

`readFromStylesheets: true` reads supported top-level rules in `document.styleSheets`. A selector must start with `.tiptap` and leave a supported selector after that prefix:

```css
.tiptap h1 {
  color: #1f2937;
}
.tiptap p {
  font-size: 16px;
}
```

The automatic reader skips `h1`, `.my-editor h1`, and `.wrapper .tiptap h1` rules. It also skips grouped selectors such as `.tiptap p, .tiptap h1`. These rules can still affect [Document styles](/conversion/export/docx/document-styles), which read the CSS shown in the editor.

For another scope, read the rules yourself and pass them as `styles`:

```ts
import { ExportDocx, readTiptapStylesheetRules } from '@tiptap-pro/extension-export-docx'

const styles = readTiptapStylesheetRules({ scope: '.my-editor' })

ExportDocx.configure({
  cssStyles: { styles },
})
```

This reads `.my-editor h1`, for example. In a `styles` object, use a supported selector such as `h1` without the `.my-editor` prefix.

## What works

`cssStyles` supports 16 selectors:

`p`, `h1`, `h2`, `h3`, `h4`, `h5`, `h6`, `blockquote`, `ul li`, `ol li`, `strong`, `em`, `u`, `s`, `a`, `code`

Each selector can use the properties below. Both camelCase names such as `fontSize` and CSS names such as `font-size` work. Values are strings.

| Property                    | Result                                                                                                                                |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| `fontSize`                  | Word font size. Supports `px`, `pt`, `em`, and `rem`.                                                                                 |
| `color`                     | Text color.                                                                                                                           |
| `fontFamily`                | Font name.                                                                                                                            |
| `fontWeight`                | Bold for `bold`, `bolder`, or a numeric weight of 600 or more. `normal`, `lighter`, and lower numeric weights clear bold.             |
| `fontStyle`                 | Italic formatting.                                                                                                                    |
| `textDecoration`            | Underline and strikethrough.                                                                                                          |
| `backgroundColor`           | Text background shading.                                                                                                              |
| `letterSpacing`             | Character spacing.                                                                                                                    |
| `textAlign`                 | Paragraph alignment.                                                                                                                  |
| `marginTop`, `marginBottom` | Space before and after the paragraph. Negative values become zero.                                                                    |
| `lineHeight`                | A Word line-spacing value. Supports unitless values, `%`, `em`, `px`, and `normal`. `px` uses `baseFontSize` to calculate a multiple. |

Length properties use `baseFontSize` to resolve `em` and `rem`. Its default is `16` pixels. Supported units differ by property; `lineHeight` does not support `pt` or `rem`. For exact line spacing, set both `spacing.line` and `spacing.lineRule` in [`styleOverrides`](/conversion/export/docx/document-styles#how-your-options-combine-with-your-css).

Both `ul li` and `ol li` map to Word's `ListParagraph` style. When both are present, their properties merge and the later entry wins for shared properties.

## What won't work

These limits apply to `cssStyles`. [Document styles](/conversion/export/docx/document-styles) read the CSS shown in the browser and support more formatting.

- The stylesheet reader skips rules the browser cannot access, including blocked cross-origin stylesheets. Pass those rules through `styles` instead.
- The reader does not enter media queries, supports rules, imported stylesheets, or other nested rule groups.
- Pseudo-classes, pseudo-elements, and selectors outside the supported list do not map to styles.
- The exporter cannot calculate CSS variables, `calc()`, or values inherited from parent elements. Pass the final values.
- The reader combines matching rules in stylesheet order. It does not use the browser's rules for selector priority.
- To style tables, images, code blocks, or individual nodes, use document styles, custom renderers, or export overrides. The supported selector list does not cover them.

## What to expect

- Named styles in the DOCX file for supported values.
- One entry for each Word style, with shared selectors such as `ul li` and `ol li` merged.
- Console warnings for unsupported selectors, properties, and values passed in `styles`.
- On a server, `readFromStylesheets` reads no rules. Explicit `styles` still work.

## What not to expect

- An unchanged import and export cycle. The importer's CSS injection supports a different set of values, especially on inline marks.
- A full browser stylesheet in Word. Word has its own layout rules and no CSS media queries.
- Automatic creation of a Word theme from your CSS colors and fonts.

## Configuration reference

| Option                | Default | Description                                              |
| --------------------- | ------- | -------------------------------------------------------- |
| `styles`              | None    | CSS properties keyed by supported selectors.             |
| `readFromStylesheets` | `false` | Read supported `.tiptap` rules from browser stylesheets. |
| `baseFontSize`        | `16`    | Size in pixels for converting relative lengths.          |

The exported types are `CssRulesOptions`, `CssRules`, and `CssProperties`.

### Convert rules yourself

Use `createDocxStylesFromRules` when you need the Word style definitions without exporting a file:

```ts
import { createDocxStylesFromRules } from '@tiptap-pro/extension-export-docx'

const styleOverrides = createDocxStylesFromRules({
  styles: {
    h1: { fontSize: '32px', color: '#1f2937' },
  },
})
```

This returns DOCX `styleOverrides`. To read styles from an editor on a web page, use [`readEditorDocxStyles`](/conversion/export/docx/document-styles#use-the-standalone-exportdocx-function).
