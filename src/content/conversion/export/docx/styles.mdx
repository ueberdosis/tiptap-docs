Use custom Word styles to set the fonts, colors, and spacing in your exported documents.

In the browser, [Document styles](/conversion/export/docx/document-styles) read your editor's CSS. The options on this page take priority over those styles.

## Per-node overrides with a function

Every element override accepts a function or an object. That includes `paragraphOverrides`, `textRunOverrides`, `tableOverrides`, `tableRowOverrides`, `tableCellOverrides`, and `imageOverrides`. A node is an item in your Tiptap JSON, such as a paragraph or an image. The function receives the original node and returns its formatting.

With document styles, the exporter can split one text node into several Word text runs. These runs hold pieces of text with different formatting. The exporter calls `textRunOverrides` once with the original text node and applies the result to every run from that node.

```ts
ExportDocx.configure({
  onCompleteExport: (result) => {
    /* ... */
  },
  imageOverrides: (node) => ({
    // Give Word the image's alternative text.
    altText: { name: node.attrs?.alt, description: node.attrs?.alt },
  }),
  paragraphOverrides: (node) => ({
    keepNext: node.attrs?.keepWithNext === true,
  }),
})
```

The exporter applies the returned object in the same way as an object passed directly. An empty object keeps the formatting. A `textRunOverrides` callback may also return `undefined` to keep it.

Named `styleOverrides` combine nested properties with the editor styles. Element overrides replace the properties you supply, including nested objects. For example, `paragraphOverrides: { spacing: { after: 200 } }` replaces the whole `spacing` object read from the editor. It removes that object's line height and space before. Formatting stored on nodes and marks can still affect the final result. See [How your options combine with your CSS](/conversion/export/docx/document-styles#how-your-options-combine-with-your-css).

### Where the node sits

The function receives a second argument, `context`, that describes where the node sits in the document:

| Field            | Description                                                                                                                                  |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| `documentIndex`  | Index of the top-level block that holds the node, `0` for the first block. Missing in header, footer, footnote, endnote, and comment content |
| `table`          | The closest `table` node that contains the node                                                                                              |
| `tableRow`       | The `tableRow` node around the node                                                                                                          |
| `tableCell`      | The cell around the node. Its `type` is `tableHeader` for a header cell                                                                      |
| `rowIndex`       | Index of the row in its table, `0` for the first row                                                                                         |
| `cellIndex`      | Index of the cell in its row. Under a `rowspan` from an earlier row, this is not the grid column the cell sits in                            |
| `block`          | The paragraph or heading around a text run. Available to `textRunOverrides` when the built-in text converter has that parent.                |
| `paragraphStyle` | The selected paragraph style, such as `Quote`, `CodeBlock`, or `ListParagraph`.                                                              |

Outside a table, the table fields are absent. The context can still include `documentIndex`, `block`, and `paragraphStyle`. You can read `context`, but you cannot change it. Changing it causes an error.

```ts
ExportDocx.configure({
  onCompleteExport: (result) => {
    /* ... */
  },
  // Italic text in header cells only
  textRunOverrides: (node, context) =>
    context.tableCell?.type === 'tableHeader' ? { italics: true } : {},
  // Repeat the first row of every table at the top of each page
  tableRowOverrides: (node, context) => (context.rowIndex === 0 ? { tableHeader: true } : {}),
})
```

Use only `node` when you do not need `context`.
