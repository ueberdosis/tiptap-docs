When exporting to `DOCX`, you can define custom styles that will be applied to the exported document. This is useful when you want to have a consistent look and feel across your documents.

In the browser, the export already takes its styles from your editor's CSS, see [Document styles](/conversion/export/docx/document-styles). The options on this page apply over those styles.

## Per-node overrides with a function

Every element override accepts a function as well as a static object. That covers `paragraphOverrides`, `textRunOverrides`, `tableOverrides`, `tableRowOverrides`, `tableCellOverrides` and `imageOverrides`. The function gets the node being converted and returns the overrides for that node, so you can change them per node based on its attributes. The object form still works the same way.

```ts
ExportDocx.configure({
  onCompleteExport: (result) => {
    /* ... */
  },
  // `node` is the image node currently being converted, including its `attrs`.
  imageOverrides: (node) => ({
    // Carry the editor's alt text into Word's accessibility metadata.
    altText: { name: node.attrs?.alt, description: node.attrs?.alt },
    // Derive the rendered size from the dimensions set on the node.
    transformation: {
      width: Number(node.attrs?.width),
      height: Number(node.attrs?.height),
    },
  }),
  // The function receives the matching node for every override type.
  paragraphOverrides: (node) => ({
    keepNext: node.attrs?.keepWithNext === true,
  }),
})
```

The export applies what the function returns exactly like a static object, with the same precedence. If it returns an empty object, the node keeps every default.

### Where the node sits

Since v0.33.0, the function also receives a second argument, `context`, which describes where the node sits in the document:

| Field           | Description                                                                                                                        |
| --------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| `documentIndex` | Index of the top-level block that holds the node, `0` for the first block. Missing in header, footer, footnote and comment content |
| `table`         | The innermost `table` node around the node                                                                                         |
| `tableRow`      | The `tableRow` node around the node                                                                                                |
| `tableCell`     | The cell around the node. Its `type` is `tableHeader` for a header cell                                                            |
| `rowIndex`      | Index of the row in its table, `0` for the first row                                                                               |
| `cellIndex`     | Index of the cell in its row. Under a `rowspan` from an earlier row, this is not the grid column the cell sits in                  |

Outside a table, `context` holds only `documentIndex`. The context is read-only, and a callback that writes to it throws.

```ts
ExportDocx.configure({
  onCompleteExport: (result) => {
    /* ... */
  },
  // Italic text in header cells only
  textRunOverrides: (node, context) =>
    context.tableCell?.type === 'tableHeader' ? { italics: true } : {},
  // Repeat the first row of every table at the top of each page
  tableRowOverrides: (node, context) => (context.rowIndex === 0 ? { tableHeader: true } : {}),
})
```

A function that takes only `node` keeps working.

<Callout title="Function form is DOCX-only">
  The function form of the element overrides is supported by the DOCX export. Other export formats
  accept the static object form.
</Callout>
