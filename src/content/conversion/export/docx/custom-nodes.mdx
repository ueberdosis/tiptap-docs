Describe how each custom node in your Tiptap schema becomes DOCX content, so application-specific content keeps its look in the exported Word file.

<Callout variant="hint" title="Custom nodes are described as JSON">
  Custom nodes are described as JSON, so they can travel to Convert. The Convert service builds the
  DOCX file and renders each node from your rules. If you used the `customNodes` option before
  `1.0.0`, see the [migration guide](/conversion/export/docx/migrate-to-v1#removed-customNodes).

## Export custom nodes to .docx

<CodeDemo isPro path="/Extensions/ExportDocxCustomNode" />

Pass your rules to the `customNodeDsl` option of `ExportDocx`. Each rule names a node type and describes the DOCX element it becomes.

<CustomNodeConversionGuide />

### Describe the custom node with the DSL

Write each rule with the builder from `@tiptap-pro/extension-export-docx/dsl`. This example renders the `hintbox` block node as a styled paragraph, and an `inlineExtensionNode` inline node as a highlighted text run:

```ts
import { Editor } from '@tiptap/core'
import { ConvertKit } from '@tiptap-pro/extension-convert-kit'
import {
  multiplierToLineSpacingUnits,
  pixelsToHalfPoints,
  pointsToTwips,
} from '@tiptap-pro/extension-convert-kit/ooxml-registry'
import { ExportDocx } from '@tiptap-pro/extension-export-docx'
import {
  childrenInline,
  docxNode,
  paragraph,
  template,
  textRun,
} from '@tiptap-pro/extension-export-docx/dsl'

import { Hintbox } from './hintbox'
import { InlineExtensionNode } from './inline-extension-node'

const editor = new Editor({
  extensions: [
    ConvertKit,
    Hintbox,
    InlineExtensionNode,
    ExportDocx.configure({
      token: 'YOUR_JWT',
      appId: 'YOUR_APP_ID',
      onCompleteExport: (result) => {
        if (!(result instanceof Blob)) return
        const url = URL.createObjectURL(result)
        const link = document.createElement('a')
        link.href = url
        link.download = 'export.docx'
        link.click()
        URL.revokeObjectURL(url)
      },
      customNodeDsl: {
        dslVersion: '1.0',
        nodes: [
          docxNode('hintbox')
            .block()
            .emit(paragraph({ style: 'Hintbox' }).children(childrenInline({ marks: 'default' })))
            .toJSON(),
          docxNode('inlineExtensionNode')
            .inline()
            .emit(
              textRun({
                text: template('[{node.textContent}]'),
                color: '000000',
                highlight: 'cyan',
              }).applyMarks('node'),
            )
            .toJSON(),
        ],
      },
      styleOverrides: {
        paragraphStyles: [
          {
            id: 'Hintbox',
            name: 'Hintbox',
            basedOn: 'Normal',
            next: 'Normal',
            quickFormat: false,
            run: {
              font: 'Aptos',
              size: pixelsToHalfPoints(16),
            },
            paragraph: {
              spacing: {
                before: pointsToTwips(12),
                after: pointsToTwips(12),
                line: multiplierToLineSpacingUnits(1),
              },
              border: {
                // DOCX colors are hex values without the leading #
                top: { style: 'single', size: 1, color: 'b8d8ff', space: 5 },
                bottom: { style: 'single', size: 1, color: 'b8d8ff', space: 5 },
                right: { style: 'single', size: 1, color: 'b8d8ff', space: 5 },
                left: { style: 'single', size: 1, color: 'b8d8ff', space: 5 },
              },
              shading: {
                type: 'solid',
                color: 'e6f3ff',
              },
            },
          },
        ],
      },
    }),
  ],
})
```

Here is what each part does:

- `docxNode('hintbox')` matches nodes of type `hintbox`. `.block()` and `.inline()` declare what kind of node it is.
- `.emit()` sets the DOCX element the node becomes. `paragraph({ style: 'Hintbox' })` uses the `Hintbox` paragraph style you declare in `styleOverrides`.
- `childrenInline({ marks: 'default' })` renders the node's content with its usual bold, italic and other marks.
- `template('[{node.textContent}]')` builds the run's text from the node's text. `.applyMarks('node')` applies the marks on the node itself to the run.
- `.toJSON()` turns each rule into the JSON that the extension sends to Convert.

Then export the editor content to a `DOCX` file:

```ts
editor.chain().exportDocx().run()
```

The [DSL builder](/conversion/export/docx/custom-nodes-dsl-builder) page lists every element, helper and value expression. The [custom nodes DSL](/conversion/export/docx/custom-nodes-dsl) page documents the JSON the builder produces, its errors and its limits.

## Limitations

- Rules are JSON. They can't run your own JavaScript code.
- A rule can emit only the elements the DSL supports: `paragraph`, `textRun`, `externalHyperlink`, `table`, `tableRow`, `tableCell` and `pageBreak`.
- The Convert service sets the limits for rule count, nesting depth and string length. See [resource limits](/conversion/export/docx/custom-nodes-dsl#resource-limits).
