Word only renders a font that's installed on the reader's machine, unless the font is **embedded** into the document itself. `@tiptap-pro/extension-export-docx` can embed the fonts your content uses so the exported `.docx` looks the same everywhere, even where those fonts aren't installed.

There are two ways to do it:

- **[Manual](#manual-embedding)**: you supply the font bytes via the `fonts` option. Full control over which file is embedded.
- **[Automatic](#automatic-embedding)**: set `embedFonts: true` and the export detects, fetches, and embeds the fonts your document uses for you.

Either way, the extension uploads the font files with the export request and Convert embeds them. On your server, upload fonts to the [REST API](#on-your-server) instead.

## Manual embedding

Pass a `fonts` array, one entry per font family, each with its raw TTF, OTF or WOFF2 bytes. The font is obfuscated into the document package (`word/fonts/font<N>.odttf`, per the OOXML spec) and bound to every run that uses the matching family name.

```ts
import { ExportDocx } from '@tiptap-pro/extension-export-docx'

// In the browser: fetch the font and hand its ArrayBuffer straight to the export.
const data = await fetch('/fonts/PlayfairDisplay-Regular.ttf').then((response) =>
  response.arrayBuffer(),
)

editor
  .chain()
  .exportDocx({
    fonts: [{ name: 'Playfair Display', data }],
  })
  .run()
```

### `DocxFontDefinition`

```ts
interface DocxFontDefinition {
  name: string
  data: Uint8Array | ArrayBuffer
  characterSet?: DocxFontCharacterSet
}
```

| Field          | Description                                                                                                                                                                                                                                                                                                                                 |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `name`         | The font family name. **Must exactly match** the font name used by your content: the first family of a `textStyle` mark's `fontFamily` (quotes stripped, so `'"Playfair Display", serif'` resolves to `Playfair Display`) or the `font` set via `styleOverrides` / `textRunOverrides`. A mismatch silently falls back to a substitute font. |
| `data`         | Raw **TTF, OTF or WOFF2** bytes, as a `Uint8Array` or an `ArrayBuffer` (so `await fetch(url).then((r) => r.arrayBuffer())` works directly in the browser). Convert turns a WOFF2 font into TTF before it embeds it. WOFF data is not accepted.                                                                                              |
| `characterSet` | Optional Word charset code as a string, written as `<w:charset>` in the font table. Leave unset for ordinary Latin fonts. See [Character sets](#character-sets).                                                                                                                                                                            |

### Character sets

Pass the code as a string, such as `'A1'` for Greek. The `CharacterSet` constant is gone, see [`CharacterSet`](/conversion/export/docx/migrate-to-v1#removed-CharacterSet).

| Code   | Character set       | Code   | Character set  |
| ------ | ------------------- | ------ | -------------- |
| `'00'` | ANSI                | `'A1'` | Greek          |
| `'01'` | Default             | `'A2'` | Turkish        |
| `'02'` | Symbol              | `'A3'` | Vietnamese     |
| `'4D'` | Mac                 | `'B1'` | Hebrew         |
| `'80'` | Japanese (JIS)      | `'B2'` | Arabic         |
| `'81'` | Korean (Hangul)     | `'BA'` | Baltic         |
| `'82'` | Korean (Johab)      | `'CC'` | Russian        |
| `'86'` | Simplified Chinese  | `'DE'` | Thai           |
| `'88'` | Traditional Chinese | `'EE'` | Eastern Europe |
| `'FF'` | OEM                 |        |                |

Convert rejects any other code.

### On your server

The `exportDocx` function is gone, see [`exportDocx`](/conversion/export/docx/migrate-to-v1#removed-exportDocx). On your server, send each font as a binary part of a `multipart/form-data` request to the [REST API](/conversion/export/docx/rest-api#export-docx-v3). Describe it with a font entry in `assets`: `id`, `kind: "font"`, `part`, `name` and an optional `characterSet`. See [Assets](/conversion/export/docx/rest-api#assets). With `embedFonts: true`, Convert looks up the families you didn't upload on Google Fonts.

## Automatic embedding

Set `embedFonts: true` and the export does the work: it collects every font family the document references, locates each font's file, converts it to an embeddable format if needed, and embeds it, with no per-export font plumbing.

```ts
ExportDocx.configure({
  token: 'YOUR_JWT',
  embedFonts: true,
  onCompleteExport: (blob) => {
    /* download blob */
  },
})
```

### How it works

1. **Detect**: collects the families used across `textStyle` `fontFamily` marks, [CSS styles](/conversion/export/docx/css-to-docx), and run-level style overrides. Generic keywords (`serif`, `monospace`, …) and families you already passed via `fonts` are skipped.
2. **Locate**: finds each font's file from the page's readable `@font-face` rules, picking the regular face. When a family is split into per-language subsets (as Google Fonts, and many self-hosted setups, are), the subset that covers the characters your document actually uses is chosen: a Latin document embeds the Latin glyphs, a Cyrillic document the Cyrillic glyphs, and so on. A family with no readable rule (the usual case for a Google Fonts `<link>`, whose cross-origin stylesheet can't be read from JavaScript) is looked up on [Google Fonts](https://fonts.google.com) by Convert.
3. **Upload**: the browser downloads each font file it found and sends it with the export request.
4. **Embed**: Convert embeds `TTF` and `OTF` files as they are and converts `WOFF2` files to TTF itself. The fonts are embedded exactly as if you'd passed them through the manual `fonts` option. Manually supplied fonts always win over found ones with the same name.

### Browser only

Finding fonts on the page is browser only. The extension reads `document.styleSheets` to find the `@font-face` rules. Outside a browser, it uploads only the fonts you pass in `fonts`.

<Callout title="Embedding never breaks an export">
  Every font is resolved independently. A font the browser can't fetch, or that isn't TTF, OTF or
  WOFF2, is left out and reported through `onWarning` with the `font-fetch-failed` code. The export
  continues, and the affected text falls back to Word's font substitution.
</Callout>

<Callout title="One font used for multiple scripts">
  A DOCX embeds one file per font family. If the **same** family is used for text in more than one
  script (for example Latin and Cyrillic) within a single document, the subset covering the most of
  that text is embedded and text in the other scripts falls back to Word's substitution. To embed
  full coverage for such a family, supply one complete (non-subset) font file: self-host it as a
  single `@font-face`, or pass it through the manual [`fonts`](#manual-embedding) option. Families
  used for only one script each are unaffected.
</Callout>

### Options

| Parameter    | Description                                                                                  | Default     |
| ------------ | -------------------------------------------------------------------------------------------- | ----------- |
| `embedFonts` | Finds the fonts the document uses and embeds them. Reading the page's fonts is browser only. | `false`     |
| `fonts`      | Fonts to embed, one entry per family. See [Manual embedding](#manual-embedding).             | `undefined` |

## Make the editor match the export

For the editor preview to match the embedded output, load the same font in the page with an `@font-face` rule (this is also what automatic embedding reads to locate self-hosted fonts):

```css
@font-face {
  font-family: 'Playfair Display';
  src: url('/fonts/PlayfairDisplay-Regular.ttf') format('truetype');
  font-weight: 400 900;
  font-style: normal;
  font-display: swap;
}
```

Then apply the family to content with the `fontFamily` mark; its sanitized name is what both the editor and the export bind to:

```ts
editor.chain().focus().setFontFamily('Playfair Display').run()
```

## Convert a font yourself

The export converts WOFF2 fonts for you. To get an embeddable font file for another use, call the font endpoint directly:

`POST {endpoint}/fonts/convert`

- **Body:** `multipart/form-data` with a `file` field (the font binary) and an optional `fontFamily` field.
- **Response:** the embeddable font as `font/ttf`. TTF/OTF uploads are returned unchanged, WOFF2 uploads are converted to TTF.
- **Auth:** the same `Authorization: Bearer <token>` header as the other conversion endpoints. The token needs the `Convert:Fonts` permission.

See [Convert a font](/conversion/export/docx/rest-api#convert-a-font) for the request and its errors.

## Limitations

- A font file can be up to 25 MB.
- An export can upload up to 64 files, fonts and images together. Fonts past the limit are left out with a `font-fetch-failed` warning.
