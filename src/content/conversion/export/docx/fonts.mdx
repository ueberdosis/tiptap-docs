You can include font files in your DOCX export with `@tiptap-pro/extension-export-docx`. Word can then use those fonts on a computer that does not have them installed. Font embedding helps preserve the text's appearance, but it does not guarantee the same page layout in every Word version.

There are two ways to do it:

- [Manual embedding](#manual-embedding) uses font files you supply through the `fonts` option. It works in the browser and on the server.
- [Automatic embedding](#automatic-embedding) finds and fetches fonts when you set `embedFonts: true`. It needs the browser's stylesheets.

<Callout title="Only the regular variant is embedded">
  The exporter embeds one regular font file per family, normally weight 400. Word creates bold and
  italic versions from that file. This API does not embed separate bold or italic files.
</Callout>

## Manual embedding

Pass a `fonts` array with one entry per font family. Each entry contains the TTF or OTF file bytes. The exporter adds that file to the DOCX and connects it to text that uses the same family name.

```ts
import { ExportDocx } from '@tiptap-pro/extension-export-docx'

// In the browser: fetch the font and hand its ArrayBuffer straight to the export.
const data = await fetch('/fonts/PlayfairDisplay-Regular.ttf').then((response) =>
  response.arrayBuffer(),
)

editor
  .chain()
  .exportDocx({
    fonts: [{ name: 'Playfair Display', data }],
  })
  .run()
```

On the server, read the file into a `Buffer` instead:

```ts
import { readFile } from 'node:fs/promises'
import { exportDocx } from '@tiptap-pro/extension-export-docx'

const data = await readFile('./fonts/PlayfairDisplay-Regular.ttf')

await exportDocx({
  document: editorJSON,
  exportType: 'buffer',
  customNodes: [],
  styleOverrides: {},
  fonts: [{ name: 'Playfair Display', data }],
})
```

### `DocxFontDefinition`

```ts
interface DocxFontDefinition {
  name: string
  data: Buffer | Uint8Array | ArrayBuffer
  characterSet?: DocxFontCharacterSet
}
```

| Field          | Description                                                                                                                                                                                                        |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `name`         | Family name that matches your content or export styles. The exporter uses the first name in a CSS font list and removes surrounding quotes. For example, `'"Playfair Display", serif'` becomes `Playfair Display`. |
| `data`         | TTF or OTF file bytes as a Node `Buffer`, `Uint8Array`, or `ArrayBuffer`. The manual option does not accept WOFF or WOFF2. See [automatic embedding](#automatic-embedding) for WOFF2 conversion.                   |
| `characterSet` | Optional Word character set. Leave it unset for ordinary Latin fonts. Use a `CharacterSet` value such as `CharacterSet.GREEK` when needed.                                                                         |

## Automatic embedding

Set `embedFonts: true` to find and embed the fonts used by the export. The exporter checks text marks, [Document styles](/conversion/export/docx/document-styles), custom styles, and fonts returned by formatting callbacks. It also reads fonts used in list markers, headers, footers, notes, and comments when the exporter converts their content.

If you provide `Docx.Header` or `Docx.Footer` objects, add their fonts through `fonts` or your export styles.

```ts
ExportDocx.configure({
  embedFonts: true,
  // These credentials are needed when a font uses WOFF2.
  appId: 'your-convert-app-id',
  token: 'your-jwt',
  region: 'eu', // optional. 'eu' or 'us'
  onCompleteExport: (blob) => {
    /* download blob */
  },
})
```

### How it works

1. The exporter collects font names and the characters used with them. It skips generic names such as `serif` and `monospace`, and families you already supplied through `fonts`.
2. It reads `@font-face` rules from accessible document and adopted stylesheets. It follows active `@media`, `@supports`, `@layer`, and `@import` rules. It skips disabled stylesheets, inactive conditions, and rules the browser blocks from JavaScript.
3. It selects a regular face and the font subset that best covers the used characters. Within the selected rule, it tries supported `src` URLs in order. If a source cannot be fetched or converted, it tries the next source. If none works, it tries [Google Fonts](https://fonts.google.com).
4. TTF and OTF files are embedded directly. WOFF2 files go through the Convert Service's `POST /fonts/convert` endpoint to become TTF. The exporter checks the downloaded bytes, so a font URL does not need a file extension. WOFF files are not supported.
5. The exporter adds the resolved files to the DOCX. A font you supply manually always takes priority over an automatically found font with the same name.

### Requirements and credentials

- Automatic embedding needs browser stylesheets. Use the manual `fonts` option on the server.
- WOFF2 conversion needs both `appId` and `token`. The token needs the `Convert:Fonts` permission. Self-hosted TTF and OTF files do not need a Convert Service call.
- Your endpoint must use Convert Service v2.25.0 or later for WOFF2 conversion.

<Callout title="Missing fonts do not stop the export">
  The exporter resolves each font separately. If it cannot find, fetch, or convert a font, it logs a
  warning and continues without that font. Word chooses a substitute for the affected text. Other
  export errors can still stop the export.
</Callout>

<Callout title="One font used for multiple scripts">
  The exporter embeds one file per font family. If a family has separate Latin and Cyrillic subsets,
  the exporter chooses one subset based on the used characters. Word uses a substitute for
  characters missing from that file. Supply a complete font file through
  [`fonts`](#manual-embedding) or a single `@font-face` rule if your document needs several scripts
  in the same family.
</Callout>

### Options

| Parameter    | Description                                                                                              | Default     |
| ------------ | -------------------------------------------------------------------------------------------------------- | ----------- |
| `embedFonts` | Enable automatic detection and embedding. Browser only.                                                  | `false`     |
| `appId`      | Convert app ID. Required with `token` when a WOFF2 font needs conversion.                                | `undefined` |
| `token`      | Tiptap Convert JWT sent as the `Authorization` bearer token. Required with `appId` for WOFF2 conversion. | `undefined` |
| `endpoint`   | Tiptap Convert REST endpoint base used for WOFF2 → TTF conversion. When set, it overrides `region`.      | `undefined` |
| `region`     | Tiptap Cloud region used for WOFF2 → TTF conversion when `endpoint` is not set, `'eu'` or `'us'`.        | `'eu'`      |

## Make the editor match the export

For the editor preview to match the embedded output, load the same font in the page with an `@font-face` rule (this is also what automatic embedding reads to locate self-hosted fonts):

```css
@font-face {
  font-family: 'Playfair Display';
  src: url('/fonts/PlayfairDisplay-Regular.ttf') format('truetype');
  font-weight: 400 900;
  font-style: normal;
  font-display: swap;
}
```

Then apply the family to content with the `fontFamily` mark; its sanitized name is what both the editor and the export bind to:

```ts
editor.chain().focus().setFontFamily('Playfair Display').run()
```

## Convert Service endpoint

Automatic embedding's WOFF2 conversion is backed by a REST endpoint you can also call directly:

`POST {endpoint}/fonts/convert`

- Send `multipart/form-data` with a `file` field containing the font bytes and an optional `fontFamily` field.
- The response contains the font as `font/ttf`. TTF and OTF uploads stay unchanged. The service converts WOFF2 uploads to TTF.
- Send `Authorization: Bearer <token>` and `X-App-Id: <appId>`. The token needs the `Convert:Fonts` permission.

Available on Tiptap Cloud and on-premises from Convert Service v2.25.0.
