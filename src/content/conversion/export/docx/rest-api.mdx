The DOCX export API converts Tiptap JSON documents into `.docx` (Microsoft Word) files. Options are plain JSON, so JavaScript functions aren't accepted. Two versions are available: v3 and v2.

## Export DOCX (v3)

`POST /v3/convert/export/docx`

Send a Tiptap document to this endpoint and get a `.docx` file back. Version `1.0.0` of the [editor extension](/conversion/export/docx/editor-extension) calls it for you. Call it directly when you export from your own server. Available from Convert Service **`<MIN_CONVERT_VERSION>`**.

The cloud base URLs are `https://api.tiptap.dev/v3/convert` (EU) and `https://api-us.tiptap.dev/v3/convert` (US). The service also answers on `POST /v3/export/docx`.

### Required headers

| Name            | Description                                                                                                                                        |
| --------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Authorization` | `Bearer <token>`. The token must allow the `Convert:Export:Docx` action. See [Authentication](/conversion/getting-started/install#authentication). |
| `X-App-Id`      | Your Tiptap app ID. Set it when you use Tiptap Cloud.                                                                                              |
| `Content-Type`  | `application/json` or `multipart/form-data`.                                                                                                       |

### Request formats

Send the options as an `application/json` body. To upload fonts or images, send `multipart/form-data` instead:

- One `options` part with the same JSON you would send as the body.
- One binary part per uploaded font or image. Name each part after the `part` value of its entry in `assets`.

Every part other than `options` must have an `assets` entry that points at it, and each part can be sent only once.

### Body

`document` is required. Every other field is optional.

| Name                     | Type                | Description                                                                                                                        |
| ------------------------ | ------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| `document`               | `Object`            | The Tiptap document as JSON, with `type: "doc"`. With a page layout, send the source document with its section bands.              |
| `pageSetup`              | `Object`            | The document's page layout setup.                                                                                                  |
| `outline`                | `Object`            | Outline numbering, with `types`, `levels` and `ignore`.                                                                            |
| `numberingFormats`       | `Object[]`          | Numbering formats. See [Ordered list numbering](/conversion/export/docx/ordered-list-numbering).                                   |
| `listLevels`             | `Object`            | List levels.                                                                                                                       |
| `defaultTabStop`         | `Number`            | The default tab stop, as a positive number.                                                                                        |
| `pageColor`              | `String`            | The page color.                                                                                                                    |
| `pageSize`               | `Object`            | Page `width` and `height`, each a number or a measure like `2.5cm`.                                                                |
| `pageMargins`            | `Object`            | Page `top`, `bottom`, `left`, `right`, `header` and `footer`. `top` and `bottom` can be negative.                                  |
| `styleOverrides`         | `Object`            | Style overrides. See [Export styles](/conversion/export/docx/styles).                                                              |
| `cssStyles`              | `Object`            | CSS styles, with `styles` and `baseFontSize`. See [CSS to DOCX](/conversion/export/docx/css-to-docx).                              |
| `documentCss`            | `Object`            | The CSS the editor measured in the browser.                                                                                        |
| `cellParagraphIds`       | `String[]`          | Cell paragraph IDs, sent with the CSS the editor measured in the browser.                                                          |
| `listParagraphOverrides` | `Object[]`          | Paragraph overrides for list paragraphs, each with a `path` and `overrides`, sent with the CSS the editor measured in the browser. |
| `tableOverrides`         | `Object`            | A plain-object override for tables.                                                                                                |
| `tableRowOverrides`      | `Object`            | A plain-object override for table rows.                                                                                            |
| `tableCellOverrides`     | `Object`            | A plain-object override for table cells.                                                                                           |
| `paragraphOverrides`     | `Object`            | A plain-object override for paragraphs.                                                                                            |
| `textRunOverrides`       | `Object`            | A plain-object override for text runs.                                                                                             |
| `imageOverrides`         | `Object`            | A plain-object override for images.                                                                                                |
| `headerFooterOverrides`  | `Object`            | A plain-object override for header and footer content.                                                                             |
| `footnotes`              | `Object`            | Footnote content as Tiptap JSON, keyed by note ID.                                                                                 |
| `endnotes`               | `Object`            | Endnote content as Tiptap JSON, keyed by note ID.                                                                                  |
| `comments`               | `Object`            | Comment threads, as `{ threads: [...] }`.                                                                                          |
| `customNodeDsl`          | `Object`            | Rules for custom nodes. See [Custom nodes DSL](/conversion/export/docx/custom-nodes-dsl).                                          |
| `embedFonts`             | `Boolean`           | Embeds fonts. See [Fonts](/conversion/export/docx/fonts).                                                                          |
| `onImageError`           | `"skip" \| "throw"` | What to do with an image that can't be used.                                                                                       |
| `assets`                 | `Object[]`          | One entry per binary part in a `multipart/form-data` request. See [Assets](#assets).                                               |

Any other field returns `400 INVALID_EXPORT_OPTIONS`. The fields below are no longer accepted and return `400 REMOVED_EXPORT_OPTION`:

- [`customNodes`](/conversion/export/docx/migrate-to-v1#removed-customNodes). Use `customNodeDsl`.
- [`headers`](/conversion/export/docx/migrate-to-v1#removed-headers) and [`footers`](/conversion/export/docx/migrate-to-v1#removed-footers). Headers and footers come from the document's page layout.
- [`placeholders`](/conversion/export/docx/migrate-to-v1#removed-placeholders).
- [`customNodeDslLimits`](/conversion/export/docx/migrate-to-v1#removed-customNodeDslLimits).
- `exportType` and `doc`.

#### Assets

Each `assets` entry describes one binary part. `id` and `part` must be unique across entries.

| Kind  | Shape                                             | Accepted files             |
| ----- | ------------------------------------------------- | -------------------------- |
| Font  | `{ id, kind: "font", part, name, characterSet? }` | TTF, OTF or WOFF2          |
| Image | `{ id, kind: "image", part, src }`                | PNG, JPEG, GIF, BMP or SVG |

Convert uses an image part instead of fetching that `src`. Convert turns a WOFF2 font into an embeddable font itself.

### Example (cURL, JSON)

```bash
curl --output example.docx -X POST "https://api.tiptap.dev/v3/convert/export/docx" \
    -H "Authorization: Bearer YOUR_TOKEN" \
    -H "X-App-Id: YOUR_APP_ID" \
    -H "Content-Type: application/json" \
    -d '{
      "document": {
        "type": "doc",
        "content": [
          { "type": "paragraph", "content": [{ "type": "text", "text": "Hello from Tiptap" }] }
        ]
      }
    }'
```

### Example (cURL, multipart)

This request uploads one font. The `part` value in `assets` matches the name of the binary part.

```bash
curl --output example.docx -X POST "https://api.tiptap.dev/v3/convert/export/docx" \
    -H "Authorization: Bearer YOUR_TOKEN" \
    -H "X-App-Id: YOUR_APP_ID" \
    -F 'options={"document":{"type":"doc","content":[{"type":"paragraph","content":[{"type":"text","text":"Hello from Tiptap"}]}]},"assets":[{"id":"inter","kind":"font","part":"font-1","name":"Inter"}]}' \
    -F "font-1=@Inter.ttf"
```

curl sets the `multipart/form-data` content type for you.

### Response

On success the API returns the `.docx` file as a binary download:

- **Status**: `200 OK`
- **Content-Type**: `application/vnd.openxmlformats-officedocument.wordprocessingml.document`
- **Content-Disposition**: `attachment; filename=export-{timestamp}.docx`

#### Warnings

When the export has warnings, the `X-Export-Warnings` header carries them as a base64-encoded JSON array. `X-Export-Warnings-Truncated: true` means Convert left out some warnings to keep the header small. Browsers can read both headers.

### Error responses

| Status | Code                         | Body                                                                                                                               |
| ------ | ---------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| 400    | `INVALID_EXPORT_OPTIONS`     | Convert couldn't read or validate the body or the multipart request. `path` points at the field when there is one.                 |
| 400    | `REMOVED_EXPORT_OPTION`      | The body uses a field v3 no longer accepts. `path` names the field. `docsUrl` links to the replacement when there is one.          |
| 400    | `DOCX_DSL_*`                 | A `customNodeDsl` rule failed to compile. `dslPath` points at the rule.                                                            |
| 422    | `DOCX_DSL_*`                 | A `customNodeDsl` rule failed while rendering. `dslPath` points at the rule. `nodePath` and `nodeType` point at the document node. |
| 422    | `FAILED_TO_EXPORT_DOCX_FILE` | The export failed.                                                                                                                 |

`INVALID_EXPORT_OPTIONS`, `REMOVED_EXPORT_OPTION` and `FAILED_TO_EXPORT_DOCX_FILE` responses have this shape. `path` is optional, and only `REMOVED_EXPORT_OPTION` can carry `docsUrl`:

```json
{
  "success": false,
  "code": "REMOVED_EXPORT_OPTION",
  "error": "`customNodes` is not supported by the v3 export",
  "path": "customNodes",
  "docsUrl": "https://tiptap.dev/docs/conversion/export/docx/custom-nodes-dsl"
}
```

`customNodeDsl` errors have this shape:

```json
{
  "error": "Expected TextRun.size to be number, got string.",
  "code": "DOCX_DSL_INVALID_PROP",
  "dslPath": "nodes[2].render.emit.props.size",
  "nodePath": "doc.content[4].content[2]",
  "nodeType": "mention"
}
```

A `DOCX_DSL_*` code returns `400` when the rule fails to compile and `422` when it fails while rendering. See [Custom nodes DSL errors](/conversion/export/docx/custom-nodes-dsl#error-codes) for what each one means.

| Code                             |
| -------------------------------- |
| `DOCX_DSL_UNKNOWN_VERSION`       |
| `DOCX_DSL_INVALID_SHAPE`         |
| `DOCX_DSL_DUPLICATE_NODE_TYPE`   |
| `DOCX_DSL_UNKNOWN_ELEMENT`       |
| `DOCX_DSL_UNKNOWN_OPERATION`     |
| `DOCX_DSL_RESERVED_SHAPE`        |
| `DOCX_DSL_INVALID_PROP`          |
| `DOCX_DSL_INVALID_ENUM`          |
| `DOCX_DSL_INVALID_REF`           |
| `DOCX_DSL_INVALID_TEMPLATE`      |
| `DOCX_DSL_INVALID_UNIT`          |
| `DOCX_DSL_INVALID_TRANSFORM`     |
| `DOCX_DSL_INVALID_CONTEXT`       |
| `DOCX_DSL_INVALID_OP_ARITY`      |
| `DOCX_DSL_RUNTIME_TYPE_MISMATCH` |
| `DOCX_DSL_RESOURCE_LIMIT`        |
| `DOCX_DSL_RENDER_FAILED`         |

A missing or invalid token returns the shared Convert `401` and `403` responses. See [Authentication errors](/conversion/getting-started/install#error-responses).

### Limitations

- `assets` needs a `multipart/form-data` request. A JSON body with `assets` returns `400 INVALID_EXPORT_OPTIONS`.
- A request can carry up to 64 assets.
- The `options` part can be up to 10 MB.
- A font part can be up to 25 MB. An image part can be up to 20 MB by default.
- A `data:` image in the JSON over 5 MB returns `400 INVALID_EXPORT_OPTIONS`. Send it as an image part instead.

<Callout title="Which version am I on?" variant="info">
  `@tiptap-pro/extension-export-docx` `1.0.0` and later call the v3 endpoint above. `0.34.x` builds
  the file in the browser. Server-side callers on v2 use `POST /v2/convert/export/docx`, documented
  below. It hasn't changed.
</Callout>

## Export DOCX

`POST /v2/convert/export/docx`

The `/v2/convert/export/docx` endpoint converts Tiptap documents into `DOCX` format. Users can `POST` documents to this endpoint and use various parameters to customize how different document elements are handled during the conversion process.

<Callout title="Export customization support" variant="info">
  The `/v2/convert/export/docx` endpoint accepts [style overrides](/conversion/export/docx/styles),
  page size/margins, headers/footers, the five element-level overrides (`tableOverrides`,
  `paragraphOverrides`, `textRunOverrides`, `tableCellOverrides`, `imageOverrides`), and
  [custom-node rendering via the JSON DSL](/conversion/export/docx/custom-nodes-dsl). It does not
  accept JavaScript-function options. The function-based `customNodes` option of editor extension
  `0.34.x` is gone in `1.0.0`, see the [migration
  guide](/conversion/export/docx/migrate-to-v1#removed-customNodes).
</Callout>

### Example (cURL)

```bash
curl --output example.docx -X POST "https://api.tiptap.dev/v2/convert/export/docx" \
    -H "Authorization: Bearer YOUR_TOKEN" \
    -H "Content-Type: application/json" \
    -d '{
      "doc": "{\"type\":\"doc\",\"content\":[{\"type\":\"paragraph\",\"attrs\":{\"textAlign\":\"left\"},\"content\":[{\"type\":\"text\",\"text\":\"Welcome to this demonstration of our editor ability to export a wide array of formatting options to DOCX, ensuring that your content retains its intended appearance in Word.\"}]}]}",
      "exportType": "blob"
    }'
```

<Callout title="Subscription required" variant="warning">

</Callout>

#### Headers and footers

The headers and footers objects allows you to configure a set of headers and footers options for your exported DOCX.

##### Headers Configuration

The `headers` object allows you to customize the headers of your exported DOCX document:

| Property             | Type      | Description                                                                                                                                                                                            |
| -------------------- | --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `evenAndOddHeaders`  | `boolean` | Whether to use different headers for odd and even pages                                                                                                                                                |

<Callout title="`{page}` / `{total}` tokens become live Word fields" variant="info">
  The REST API translates `{page}`, `{total}`, and the `{numpages}` synonym inside plain-text
  headers/footers into live Word `PAGE` / `NUMPAGES` fields in the exported `.docx`. Custom token
  names (e.g. `{p}` / `{pages}`) require passing the optional `placeholders` rename map. See [Custom
  token names](#custom-token-names-placeholders) below. Pass `"placeholders": false` to ship the
  tokens as literal text instead.
</Callout>

#### Custom token names (`placeholders`)

When the editor renames the built-in tokens via [`Pages.configure({ placeholders })`](/pages/core-concepts/page-header-footer#renaming-or-disabling-placeholders), forward the same rename map to the REST API so the wire format stays aligned. The wire field has the same name and shape as the editor option:

```json
{
  "doc": "{\"type\":\"doc\",\"content\":[]}",
  "footers": { "default": "{p} of {pages}" },
  "placeholders": { "page": "p", "total": "pages" }
}
```

When the map is omitted, the service falls back to recognizing `{page}`, `{total}`, and `{numpages}` (Word's spelling for the total-pages field, kept as a synonym so direct REST API callers can mirror what `/import/docx` emits). Renaming `total` removes the `{numpages}` synonym so stale tokens render literally; the rename is strict. Pass `"placeholders": false` to disable substitution on every slot so all `{page}` / `{total}` text ships literally with no live fields.

**Example cURL with custom footers:**

```bash
curl --output example.docx -X POST "https://api.tiptap.dev/v2/convert/export/docx" \
    -H "Authorization: Bearer YOUR_TOKEN" \
    -H "Content-Type: application/json" \
    -d '{
      "doc": "{\"type\":\"doc\",\"content\":[{\"type\":\"paragraph\",\"content\":[{\"type\":\"text\",\"text\":\"Document with custom footers\"}]}]}",
      "exportType": "blob",
      "footers": {"evenAndOddFooters": true, "default": "Default Footer", "first": "First Page Footer", "even": "Even Page Footer"}
    }'
```

### Comments

Pass a `comments` object to embed comment threads as native Word comments in the exported `.docx`. Each thread is anchored to the text it belongs to through the document's own comment markers: an `inlineThread` mark whose `data-thread-id` matches the thread `id`, or a `blockThread` node. The `comments` field supplies the thread bodies, authors, dates, and resolved state.

The shape mirrors the editor's export extension:

| Field                  | Type               | Description                                                                                                                    |
| ---------------------- | ------------------ | ------------------------------------------------------------------------------------------------------------------------------ |
| `threads`              | `Array`            | The comment threads to embed.                                                                                                  |
| `threads[].id`         | `String`           | Thread id. Must match the `data-thread-id` on the matching `inlineThread` / `blockThread` in `doc`.                            |
| `threads[].resolvedAt` | `String \| null`   | When set, the thread is exported as resolved.                                                                                  |
| `threads[].comments`   | `Array`            | The thread's messages, root first, then replies in order.                                                                      |
| `comments[].id`        | `String`           | Message id.                                                                                                                    |
| `comments[].content`   | `String \| Object` | The message body as plain text or Tiptap JSON.                                                                                 |
| `comments[].data`      | `Object`           | Optional metadata: `author`, `initials`, `dateIso`, `dateUtc`, and round-trip identities (`originalWId`, `originalDurableId`). |

When omitted, the export contains no comments, so existing requests are unaffected.

**Example cURL with a comment thread:**

```bash
curl --output example.docx -X POST "https://api.tiptap.dev/v2/convert/export/docx" \
    -H "Authorization: Bearer YOUR_TOKEN" \
    -H "Content-Type: application/json" \
    -d '{
      "doc": "{\"type\":\"doc\",\"content\":[{\"type\":\"paragraph\",\"content\":[{\"type\":\"text\",\"text\":\"Reviewed text\",\"marks\":[{\"type\":\"inlineThread\",\"attrs\":{\"data-thread-id\":\"T1\"}}]}]}]}",
      "exportType": "blob",
      "comments": {
        "threads": [
          {
            "id": "T1",
            "resolvedAt": null,
            "comments": [
              {
                "id": "c1",
                "content": "Please cite a source.",
                "data": { "author": "Ada Lovelace", "initials": "AL", "dateIso": "2026-01-01T00:00:00.000Z" }
              }
            ]
          }
        ]
      }
    }'
```

### Response

On success the API returns the DOCX file as a binary download:

- **Status**: `200 OK`
- **Content-Type**: `application/vnd.openxmlformats-officedocument.wordprocessingml.document`
- **Content-Disposition**: `attachment; filename=export-{timestamp}.docx`

### Error responses

| Status | Code                             | Description                          |
| ------ | -------------------------------- | ------------------------------------ |
| 400    | `NO_DOCUMENT_PROVIDED`           | No document was provided in the body |
| 422    | `FAILED_TO_PARSE_DOCX_FILE`      | Failed to parse JSON inputs          |

## Convert a font

`POST /v2/convert/fonts/convert`

Converts a font into a form that can be embedded into a DOCX file: `TTF` / `OTF` uploads are returned unchanged, and `WOFF2` uploads are converted to `TTF`. You can call it directly. Available from Convert Service **v2.25.0**.

<Callout>
  The endpoint is stateless: nothing is stored. Each request is converted and the temporary files
  are cleaned up immediately.
</Callout>

### Required headers

```bash
Authorization: Bearer <your-jwt>
```

### Body

`multipart/form-data`:

| Field        | Type     | Description                                           | Required |
| ------------ | -------- | ----------------------------------------------------- | -------- |
| `file`       | `File`   | The font binary (`TTF`, `OTF`, or `WOFF2`). Max 25MB. | Yes      |
| `fontFamily` | `String` | Font family name, used for logging only.              | No       |

### Example (cURL)

```bash
curl --output MyFont.ttf -X POST "https://api.tiptap.dev/v2/convert/fonts/convert" \
  -H "Authorization: Bearer <your-jwt>" \
  -F "file=@MyFont.woff2" \
  -F "fontFamily=My Font"
```

### Response

On success the API returns the embeddable font as a binary download:

- **Status**: `200 OK`
- **Content-Type**: `font/ttf`

### Error responses

| Status | Code                      | Description                                            |
| ------ | ------------------------- | ------------------------------------------------------ |
| 400    | None                      | Request validation error (e.g. no `file` field)        |
| 413    | `FONT_FILE_TOO_LARGE`     | The uploaded font exceeds the 25MB limit               |
| 422    | `UNSUPPORTED_FONT_FORMAT` | The upload is not a recognized TTF, OTF, or WOFF2 font |
| 422    | `FONT_CONVERSION_FAILED`  | The WOFF2 → TTF conversion produced no output          |
| 500    | `FONT_CONVERSION_FAILED`  | Unexpected error during conversion                     |
