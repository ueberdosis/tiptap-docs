A Word file has named styles such as Heading 1 and Normal. The `cssStyles` option extracts them as CSS rules, so imported text looks like the original without inline formatting on every node.

<Callout title="Experimental" variant="info">
  The extracted selectors and properties may change between releases. Pin the package version if you
  depend on them.
</Callout>

## Turn it on

Set `enabled` to `true`. With `autoInject`, the import adds the rules to the page as a `<style>` tag.

```ts
ImportDocx.configure({
  token: 'CONVERT_TOKEN',
  cssStyles: {
    enabled: true,
    autoInject: true,
    selector: '.tiptap',
  },
})
```

| Option       | Type      | What it does                                               |
| ------------ | --------- | ---------------------------------------------------------- |
| `enabled`    | `boolean` | Asks Convert for the styles. Required in `cssStyles`.      |
| `autoInject` | `boolean` | Adds the rules to a `<style>` tag in the document head.    |
| `selector`   | `string`  | The selector the rules sit under. Defaults to `'.tiptap'`. |

You can set the same keys for one import. They merge over the configured ones.

```ts
editor.commands.importDocx({
  file,
  cssStyles: { enabled: true, autoInject: false },
  onImport: ({ cssStyles, setEditorContent }) => {
    setEditorContent()
    console.log(cssStyles)
  },
})
```

## Inject the rules

With `autoInject`, the import writes the rules after the document is written. It keeps one `<style data-tiptap-style-import-docx>` tag. A later import with rules replaces the content of that tag. The tag goes away when the editor is destroyed.

Nothing is injected outside a browser, or when Convert finds no styles.

Every rule sits under `selector`, as in `.tiptap h1 { ... }`. Set `selector` to the class of your editor element. A selector such as `body` styles the whole page.

## Apply the rules yourself

Without `autoInject`, the `onImport` context has the raw `cssStyles` object. It is `null` when you didn't turn extraction on. To build and inject rules from it, use `buildCssRules` and `injectCssStyles`.

```ts
import { buildCssRules, injectCssStyles } from '@tiptap-pro/extension-import-docx'

editor.commands.importDocx({
  file,
  cssStyles: { enabled: true },
  onImport: ({ cssStyles, setEditorContent }) => {
    setEditorContent()
    if (cssStyles) injectCssStyles(buildCssRules(cssStyles, '.tiptap'))
  },
})
```

`buildCssRules` also drops the properties a mark shouldn't carry. `strong` keeps `fontWeight`, `em` keeps `fontStyle`, and `u` and `s` keep `textDecoration`. `a` keeps `color` and `textDecoration`. `code` keeps `fontFamily`, `color`, `fontSize` and `backgroundColor`.

## What is extracted

The object has one entry for each of these selectors.

| Kind   | Selectors                                         |
| ------ | ------------------------------------------------- |
| Blocks | `p`, `h1` to `h6`, `blockquote`, `ul li`, `ol li` |
| Marks  | `strong`, `em`, `u`, `s`, `a`, `code`             |

Each entry holds some of these properties, depending on what the style sets.

| Property                    | Value                                                        |
| --------------------------- | ------------------------------------------------------------ |
| `fontSize`                  | Pixels, such as `16px`.                                      |
| `marginTop`, `marginBottom` | Points, such as `12pt`.                                      |
| `lineHeight`                | A multiplier, or points for an exact or minimum line height. |
| `color`, `backgroundColor`  | A hex color. The automatic color is skipped.                 |
| `fontFamily`                | The font name.                                               |
| `fontWeight`, `fontStyle`   | `bold` or `normal`, and `italic` or `normal`.                |
| `textDecoration`            | `underline`, `line-through` or both.                         |
| `textAlign`                 | `left`, `center`, `right` or `justify`.                      |

A style that is based on another style includes what it inherits. Files written in other languages work too, because Convert matches the styles by their built-in names.

## Limits

- Only the 16 selectors above are extracted. Table styles, numbering styles and custom styles are not.
- Extraction never fails the import. If Convert can't read the styles, the object comes back empty.
- Formatting set directly on a paragraph or run in Word stays on the node as attributes and marks. The rules don't override it.
- The rules describe the imported file. They don't change when the user edits the document.
- Letter spacing isn't extracted.
- The rules can clash with your own stylesheet. Check the cascade order.

For the Word styles that decide headings and paragraphs, see [Word styles](/conversion/v3/content-reference/structures-and-media/word-styles).
