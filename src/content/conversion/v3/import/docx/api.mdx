This page lists everything `@tiptap-pro/extension-import-docx` exports. For a walk through, start with [Import DOCX](/conversion/v3/import/docx/editor-extension).

## ImportDocx.configure

`ImportDocx.configure` takes `ImportDocxOptions`. Every option is optional, but a `token` is needed to import.

| Option              | Type                                           | Default  | What it does                                                                                        |
| ------------------- | ---------------------------------------------- | -------- | --------------------------------------------------------------------------------------------------- |
| `token`             | `string`                                       |          | The JWT for Convert. The import fails before any request without it.                                |
| `appId`             | `string`                                       |          | Your Tiptap app id, sent in the `X-App-Id` header.                                                  |
| `endpoint`          | `string`                                       |          | The base URL of your own Convert server. It wins over `region`.                                     |
| `region`            | `'eu' \| 'us'`                                 | `'eu'`   | The Tiptap Cloud region, when you don't set `endpoint`.                                             |
| `imageUploadConfig` | `ImageUploadConfig`                            |          | Where Convert uploads the images. See [image handling](/conversion/v3/import/docx/image-handling).  |
| `prosemirrorNodes`  | `Record<string, string>`                       |          | Renames nodes. See [custom node mapping](/conversion/v3/import/docx/custom-node-mapping).           |
| `prosemirrorMarks`  | `Record<string, string>`                       |          | Renames marks. See [custom node mapping](/conversion/v3/import/docx/custom-node-mapping).           |
| `cssStyles`         | `ImportCssStylesOptions`                       |          | Extracts the Word styles as CSS. See [CSS styles](/conversion/v3/import/docx/css-styles).           |
| `trackedChanges`    | `'auto' \| 'preserve' \| 'accept' \| 'reject'` | `'auto'` | What to do with tracked changes. See [tracked changes](/conversion/v3/import/docx/tracked-changes). |
| `taskLists`         | `'auto' \| 'import' \| 'ignore'`               | `'auto'` | Whether checkbox lists become task lists. See [task lists](/conversion/v3/import/docx/task-lists).  |
| `onError`           | `(error: unknown) => void`                     |          | Receives the error when an import fails.                                                            |
| `onWarning`         | `(warning: ImportDocxWarning) => void`         |          | Receives every warning. Without it, warnings go to the console.                                     |

See [install](/conversion/v3/getting-started/install#connect-to-convert) for `token`, `appId`, `region` and `endpoint`.

## importDocx

`editor.commands.importDocx` takes `ImportDocxCommandOptions`. It returns `true` right away, and the import runs in the background. A callback you leave out falls back to the one of `ImportDocx.configure`.

| Option           | Type                                           | What it does                                                                      |
| ---------------- | ---------------------------------------------- | --------------------------------------------------------------------------------- |
| `file`           | `File`                                         | Required. The `.docx` file to import.                                             |
| `cssStyles`      | `Partial<ImportCssStylesOptions>`              | Merges over the `cssStyles` of the configuration for this import.                 |
| `trackedChanges` | `'auto' \| 'preserve' \| 'accept' \| 'reject'` | Overrides the configured mode for this import.                                    |
| `taskLists`      | `'auto' \| 'import' \| 'ignore'`               | Overrides the configured mode for this import.                                    |
| `onImport`       | `((context: ImportContext) => void) \| null`   | Receives the document. Without it, the document is written as soon as it arrives. |
| `onError`        | `(error: unknown) => void`                     | Receives the error. Wins over the configured `onError`.                           |
| `onWarning`      | `(warning: ImportDocxWarning) => void`         | Receives every warning. Wins over the configured `onWarning`.                     |

## ImportContext

`onImport` receives an `ImportContext`. Check `error` first. It is `null` when the import worked.

```ts
editor.commands.importDocx({
  file,
  onImport: (context) => {
    if (context.error) return
    context.setEditorContent()
  },
})
```

When the import fails and no `onError` is set, the context is `{ content: null, error }` and has no other field.

On success, it has these fields.

| Field                                | Type                                  | What it holds                                                                                             |
| ------------------------------------ | ------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| `content`                            | `JSONContent`                         | The document as Convert returned it.                                                                      |
| `error`                              | `null`                                | Always `null` on success.                                                                                 |
| `setEditorContent`                   | `(content?: JSONContent) => void`     | Writes the document. Without an argument, it writes `content`. It throws when a newer import has started. |
| `logs`                               | `ImportLogs`                          | The entries Convert logged: `info`, `warn` and `error`. `info` is always empty.                           |
| `cssStyles`                          | `DocxCssStylesOutput \| null`         | The extracted styles, or `null` when you didn't turn extraction on.                                       |
| `pageLayout`                         | `PageLayout \| null`                  | The page size and margins, or `null` when the file has none.                                              |
| `numberingFormats`                   | `NumberingFormatDefinition[] \| null` | The numbering formats of the ordered lists, or `null` when the file has none.                             |
| `commentThreads`                     | `ImportedCommentThread[]`             | The comment threads. Empty when the file has no comments.                                                 |
| `header`, `footer`                   | `JSONContent \| null`                 | The default header and footer.                                                                            |
| `headerFirstPage`, `footerFirstPage` | `JSONContent \| null`                 | The header and footer of the first page.                                                                  |
| `headerEven`, `footerEven`           | `JSONContent \| null`                 | The header and footer of even pages.                                                                      |
| `headerOdd`, `footerOdd`             | `JSONContent \| null`                 | Always `null`. Read `header` and `footer` for odd pages.                                                  |
| `footnotes`                          | `Record<string, JSONContent>`         | The footnote bodies, keyed by note id. Empty when the file has none.                                      |
| `endnotes`                           | `Record<string, JSONContent>`         | The endnote bodies, keyed by note id. Empty when the file has none.                                       |

`setEditorContent` registers `numberingFormats` with the editor when the editor has a `registerNumberingFormats` command. With Page Layout, it also writes the notes. Without it, the notes stay in `footnotes` and `endnotes`. See [import with Page Layout](/conversion/v3/import/docx/page-layout) and [import without Page Layout](/conversion/v3/import/docx/without-page-layout).

For the content of the header, footer, notes and comment fields, see the [headers and footers](/conversion/v3/content-reference/page-layout/headers-footers), [footnotes and endnotes](/conversion/v3/content-reference/structures-and-media/footnotes-endnotes) and [comments](/conversion/v3/content-reference/structures-and-media/comments) pages.

### PageLayout

All sizes are in twips. A twip is 1/1440 inch.

| Field         | Type                        | What it holds                                                                   |
| ------------- | --------------------------- | ------------------------------------------------------------------------------- |
| `width`       | `number`                    | The page width.                                                                 |
| `height`      | `number`                    | The page height.                                                                |
| `orientation` | `'portrait' \| 'landscape'` | The page orientation.                                                           |
| `margins`     | `object`                    | `top`, `right`, `bottom`, `left`, `header`, `footer` and `gutter`, all numbers. |

### ImportedCommentThread

| Field       | Type                       | What it holds                                              |
| ----------- | -------------------------- | ---------------------------------------------------------- |
| `id`        | `string`                   | The thread id. It matches `data-thread-id` in the content. |
| `durableId` | `string`                   | The durable id from the file, when it has one.             |
| `resolved`  | `boolean`                  | Whether the thread is resolved.                            |
| `messages`  | `ImportedCommentMessage[]` | The root comment first, then the replies by date.          |

Each `ImportedCommentMessage` has these fields.

| Field  | Type          | What it holds                                                                                        |
| ------ | ------------- | ---------------------------------------------------------------------------------------------------- |
| `wId`  | `string`      | The id of the comment in the Word file.                                                              |
| `id`   | `string`      | The id from the Document Server. Set only when the import created the thread there.                  |
| `body` | `JSONContent` | The message as Tiptap JSON.                                                                          |
| `data` | `object`      | `author`, and when present `initials`, `providerId`, `userId`, `dateIso` and `dateUtc`, all strings. |

## ImportDocxWarning

The object `onWarning` receives. See [warnings and errors](/conversion/v3/import/docx/warnings-and-errors#warnings) for the fields.

## ImageUploadConfig

| Field         | Type                     | What it holds                                        |
| ------------- | ------------------------ | ---------------------------------------------------- |
| `url`         | `string`                 | Required. An `http` or `https` address.              |
| `headers`     | `Record<string, string>` | Headers for every upload. A plain object of strings. |
| `method`      | `string`                 | The HTTP method. Defaults to `POST`.                 |
| `queryParams` | `Record<string, string>` | Query parameters added to `url`.                     |

## ImportCssStylesOptions

| Field        | Type      | What it holds                                              |
| ------------ | --------- | ---------------------------------------------------------- |
| `enabled`    | `boolean` | Required. Turns on the extraction.                         |
| `autoInject` | `boolean` | Adds the rules to a `<style>` tag in the document head.    |
| `selector`   | `string`  | The selector the rules sit under. Defaults to `'.tiptap'`. |

See [CSS styles](/conversion/v3/import/docx/css-styles) for `DocxCssStylesOutput` and the helpers below.

## Helpers

| Export                               | What it does                                                                     |
| ------------------------------------ | -------------------------------------------------------------------------------- |
| `buildCssRules(cssStyles, selector)` | Builds a CSS string from a `cssStyles` object, with every rule under `selector`. |
| `injectCssStyles(css)`               | Adds the CSS to the one `<style data-tiptap-style-import-docx>` tag in the head. |
| `removeCssStyles()`                  | Removes that tag.                                                                |
| `DOCX_IMPORT_META`                   | The transaction meta key of the import write. Its value is `'docxImport'`.       |

## Errors

| Class                              | What it means                                                                                                     |
| ---------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| `ImportDocxRequestError`           | Convert refused the import, or the request never reached it. Has a `code` and, when Convert answered, a `status`. |
| `ImportDocxSupersededError`        | A newer import replaced this one before it finished.                                                              |
| `ImageUploadConfigValidationError` | `imageUploadConfig` is not valid.                                                                                 |

See [warnings and errors](/conversion/v3/import/docx/warnings-and-errors#errors) for when each one is thrown and the request error codes.
