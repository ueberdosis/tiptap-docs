A Word checkbox list can import as `taskList` and `taskItem` nodes, with the ticked state kept. The `taskLists` option decides.

## Choose a mode

Set `taskLists` on `ImportDocx.configure`, or on one `importDocx` call. The call wins.

```ts
ImportDocx.configure({
  token: 'CONVERT_TOKEN',
  taskLists: 'auto',
})

editor.commands.importDocx({ file, taskLists: 'ignore' })
```

| Value      | Result                                                             |
| ---------- | ------------------------------------------------------------------ |
| `'auto'`   | Task lists when the editor has `taskList` and `taskItem`. Default. |
| `'import'` | Always task lists.                                                 |
| `'ignore'` | Bullet or numbered lists, as Word draws the markers.               |

## What `'auto'` does

`'auto'` looks for the `taskList` and `taskItem` nodes in the editor schema. With both, it uses `'import'`. Without them, it uses `'ignore'`. When you renamed the nodes with `prosemirrorNodes`, it looks for your names.

Don't force `'import'` in an editor without the nodes. The editor then rewrites the task nodes into paragraphs and loses the ticked state.

Add `TaskList` and `TaskItem` from `@tiptap/extension-list` to the editor to get task lists. Turn on `nested` for `TaskItem`, so imported sublists are valid. See [task lists](/conversion/v3/content-reference/text-and-formatting/task-lists) for the setup, the checkboxes that convert and how they export.

## Limitations

- A checkbox outside a list isn't converted.
- A checkmark character such as `✔` isn't a checkbox. It stays as text.
