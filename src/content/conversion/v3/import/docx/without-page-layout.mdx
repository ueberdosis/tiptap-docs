In an editor without [Page Layout](/pages/v2/getting-started/overview), `setEditorContent` writes the body with `setContent`. Headers, footers, notes and the page setup are left out.

## Import into the editor

Call `setEditorContent` from `onImport`. Without `onImport`, the import does the same as soon as the document arrives.

```ts
editor.commands.importDocx({
  file,
  onImport: (context) => {
    if (context.error) return
    context.setEditorContent()
  },
})
```

The import never records the write as tracked changes, even when the tracked changes extension is on the editor.

If the editor refuses the document, the import fails and the error reaches `onError`.

## What the import leaves out

The import returns a Page Layout document. A plain editor can't hold the nodes only Page Layout has, so `setEditorContent` leaves them out with their content.

- `sectionBreak`, with the page setup, and the `pageFurniture` nodes inside it, with the headers and footers.
- `footnoteReference` and `footnoteCollection`, with the footnotes and endnotes.
- `pageBreak`, `columnBreak` and `pageNumber`.

`onWarning` receives one `unsupported` warning for each node type it left out. `context.content` still has the whole document, so you can read these parts yourself. To keep them in the editor, add Page Layout. See [import with Page Layout](/conversion/v3/import/docx/page-layout).

## Content the editor can't hold

The import rewrites the content to fit the editor schema before it writes. A node with content that the schema doesn't know becomes a paragraph and keeps its children. The import drops a node without content, and any mark the schema doesn't know. `onWarning` receives one `unsupported` warning for each type.

Add the extension for a type to keep it.

## Numbering formats

Numbered lists import with default numbering. Custom numbering formats from the file are not imported yet. See [lists](/conversion/v3/content-reference/text-and-formatting/lists).
