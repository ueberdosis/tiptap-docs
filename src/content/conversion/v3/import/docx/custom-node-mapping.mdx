Import creates nodes and marks with fixed names, such as `paragraph` and `bold`. If your schema uses other names, map them with `prosemirrorNodes` and `prosemirrorMarks`.

## Rename a node or a mark

Each option is an object. The key is the name import uses. The value is the name in your schema.

```ts
ImportDocx.configure({
  token: 'CONVERT_TOKEN',
  prosemirrorNodes: { blockquote: 'quote' },
  prosemirrorMarks: { bold: 'strong' },
})
```

With this setup, a Word quote becomes a `quote` node and bold text gets a `strong` mark. Your schema needs the node and the mark you name.

### Node keys

The keys are the default node names.

- Text blocks: `paragraph`, `heading`, `blockquote`, `hardBreak`, `horizontalRule`.
- Lists: `bulletList`, `orderedList`, `listItem`, `taskList`, `taskItem`.
- Tables: `table`, `tableRow`, `tableCell`, `tableHeader`.
- Other content: `image`, `bookmark`, `tableOfContents`, `pageBreak`, `columns`, `column`.
- Notes and comments: `footnoteReference`, `endnoteReference`, `blockThread`.

### Mark keys

The keys are the default mark names, except `strikethrough`, which renames the `strike` mark.

- Text formatting: `bold`, `italic`, `underline`, `strikethrough`, `code`, `superscript`, `subscript`.
- Other marks: `link`, `inlineThread`, `suggestion`.

The `taskLists` and `trackedChanges` options look for your renamed `taskList`, `taskItem` and `suggestion` names, so a rename doesn't break `'auto'`. See [task lists](/conversion/v3/import/docx/task-lists) and [tracked changes](/conversion/v3/import/docx/tracked-changes).

## Map a Word style to a node

A key that isn't in the lists is the name of a Word paragraph style. Every paragraph with that style becomes a node of the type you give. The node gets the paragraph's text and attributes.

```ts
ImportDocx.configure({
  token: 'CONVERT_TOKEN',
  prosemirrorNodes: { Hintbox: 'hintbox' },
})
```

A paragraph in the Word style `Hintbox` now imports as a `hintbox` node. Your schema needs a node named `hintbox` that holds inline content. The style name is case sensitive.

If the node isn't in the schema, the editor keeps its text as a paragraph. `onWarning` receives an `unsupported` warning for it.

## Limitations

- The options work on the import of a `.docx` file only.
- The import rewrites a node or mark the schema doesn't know. See [warnings and errors](/conversion/v3/import/docx/warnings-and-errors#unsupported-content).
