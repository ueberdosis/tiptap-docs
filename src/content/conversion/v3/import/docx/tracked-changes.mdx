A reviewed Word file records who inserted and deleted what. On import, you choose to keep that record as suggestions, apply it or discard it.

## Choose a mode

Set `trackedChanges` on `ImportDocx.configure`, or on one `importDocx` call. The call wins.

```ts
ImportDocx.configure({
  token: 'CONVERT_TOKEN',
  trackedChanges: 'auto',
})

editor.commands.importDocx({ file, trackedChanges: 'preserve' })
```

| Mode         | What happens                                                                          |
| ------------ | ------------------------------------------------------------------------------------- |
| `'preserve'` | Insertions and deletions become suggestions, with their author and date.              |
| `'accept'`   | Insertions become ordinary text and deletions are removed.                            |
| `'reject'`   | Deletions come back as ordinary text and insertions are removed.                      |
| `'auto'`     | `'preserve'` when the editor can show suggestions, `'accept'` when it can't. Default. |

## What `'auto'` does

`'auto'` looks for the `suggestion` mark in the editor schema. If the mark is there, it uses `'preserve'`. If not, it uses `'accept'`. When you renamed the mark with `prosemirrorMarks`, it looks for your name.

The editor drops marks it doesn't know and keeps their text. Preserving suggestions in an editor that can't show them would turn every deletion back into ordinary text. `'auto'` avoids that.

<Callout title="Preserving suggestions needs the tracked changes extension" variant="info">
  Add [`@tiptap-pro/extension-tracked-changes`](/tracked-changes/getting-started/overview) to keep
  the changes as suggestions. Without it, use `'accept'` or `'reject'`.
</Callout>

The write of the import itself is never tracked as a change. To send suggestions back to Word, see [tracked changes on export](/conversion/v3/export/docx/usage#tracked-changes).

## What a suggestion looks like

Text with a change carries a `suggestion` mark.

```json
{
  "type": "text",
  "text": "brave ",
  "marks": [
    {
      "type": "suggestion",
      "attrs": {
        "id": "docx-suggestion-1",
        "type": "add",
        "userId": "ada lovelace",
        "createdAt": "2026-07-27T10:00:00Z",
        "updatedAt": "2026-07-27T10:00:00Z",
        "userMetadata": { "name": "Ada Lovelace" }
      }
    }
  ]
}
```

`type` is `add` for an insertion and `delete` for a deletion. A replacement arrives as a deletion followed by an insertion.

Word knows reviewers by display name only. `userMetadata.name` holds that name, and `userId` is the name trimmed, with single spaces, in lower case. Two reviewers with the same display name share a `userId`. A change without an author gets `anonymous` as `userId` and `null` as `userMetadata`.

Word writes one record for each run of text. Neighbouring records of the same type from the same author merge into one suggestion.

Inserted or deleted images and other content without text carry the same data as node attributes: `suggestionId`, `suggestionType`, `suggestionUserId`, `suggestionCreatedAt`, `suggestionUpdatedAt` and `suggestionUserMetadata`.

## Where suggestions are kept

Suggestions are kept in the body of the document, including table cells.

Headers, footers, comments and notes run on schemas without a `suggestion` mark. Import accepts the changes there, so a deletion in a header arrives as removed text. The content is never lost.

## Limits

- Splits and joins of paragraphs, and formatting changes such as making a word bold, import as they are. The record that they were changes is not kept.
- Moves aren't recognized. Check a moved passage before you rely on it.
- Changes in headers, footers, comments and notes are accepted. They never become suggestions.
- Suggestions on images and other content without text come in as node attributes, not as a mark.
