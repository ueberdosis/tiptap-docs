When the editor has [Page Layout](/features/page-layout/getting-started/overview), `setEditorContent` replaces the source document with the imported file. Its sections, headers, footers, page setup and notes go in with it.

## Import into the source document

Call `setEditorContent` from `onImport`. Without `onImport`, the import does the same as soon as the document arrives.

```ts
editor.commands.importDocx({
  file,
  onImport: (context) => {
    if (context.error) return
    context.setEditorContent()
  },
})
```

The write is one transaction. The cursor moves to the start of the document, and the user can undo the import.

The import never records the write as tracked changes, even when the tracked changes extension is on the editor.

## What the import brings in

The imported document holds the whole page setup of the file. `setEditorContent` writes it all in the same step.

- Each section starts with a `sectionBreak` node. It holds the paper size, orientation, margins, columns, page numbering and the distance of the header and footer from the page edge.
- The headers and footers of a section are `pageFurniture` nodes inside its section break. Each section keeps its own default, first page and even page versions.
- The page color of the first section comes in too. Word has one page color for the whole document.
- Word's page fields, `PAGE`, `NUMPAGES` and `SECTIONPAGES`, become `pageNumber` nodes, so they keep counting.
- Page breaks and column breaks stay inside the paragraph where Word has them, as `pageBreak` and `columnBreak` nodes.

See [page structure](/conversion/v3/content-reference/page-layout/page-structure) and [headers and footers](/conversion/v3/content-reference/page-layout/headers-footers).

### Notes

The import rebuilds footnotes and endnotes as the [footnotes extension](/features/footnotes) holds them. See [footnotes and endnotes](/conversion/v3/content-reference/document-structure/footnotes-endnotes).

The import leaves out a note without a reference, and a reference without a note. `onWarning` receives a `notes-dropped` warning.

## Not imported yet

- Custom list numbering formats. Numbered lists import with default numbering.
- Bookmarks. `onWarning` receives a `bookmarks-dropped` warning. Cross-references keep the text Word shows.
- The binding gutter of the page margins. `onWarning` receives a `gutter-dropped` warning.

See [warnings and errors](/conversion/v3/import/docx/warnings-and-errors#warnings) for every warning code.

## When the import fails

The import fails with an error in these cases.

- The editor has Page Layout registered but its engine isn't ready, for example before the editor mounts. Import after the editor has mounted.
- The imported document doesn't fit the source document schema.
- The engine doesn't apply the write.

An error thrown inside `onImport`, including by `setEditorContent`, reaches `onError`. Without `onError`, the import rethrows it as an unhandled rejection.

## Content the source document can't hold

Before the write, the import rewrites the content to fit the source document schema. A node with content that the schema doesn't know becomes a paragraph and keeps its children. The import drops a node without content, and any mark the schema doesn't know. `onWarning` receives one `unsupported` warning for each type.
