When the editor has [Page Layout](/pages/v2/getting-started/overview), `setEditorContent` replaces the Source Document with the imported file. The footnotes and endnotes go in with it.

## Import into the Source Document

Call `setEditorContent` from `onImport`. Without `onImport`, the import does the same as soon as the document arrives.

```ts
editor.commands.importDocx({
  file,
  onImport: ({ error, setEditorContent }) => {
    if (error) return
    setEditorContent()
  },
})
```

The write is one transaction. The caret moves to the start of the document, and the user can undo the import.

The import never records the write as tracked changes, even when the tracked changes extension is on the editor.

## Notes

Footnotes and endnotes are rebuilt as the [footnotes extension](/pages/v2/extensions/footnotes) holds them. See [footnotes and endnotes](/conversion/v3/content-reference/structures-and-media/footnotes-endnotes) for the details.

A note without a reference, or a reference without a note, is left out. `onWarning` receives an `unsupported` warning that names the note id.

## What you place yourself

The import doesn't write these into the editor. They arrive in the `onImport` context.

- The headers and footers, in `header`, `footer` and the other header and footer fields. See [headers and footers](/conversion/v3/content-reference/page-layout/headers-footers).
- The page size, orientation and margins, in `pageLayout`. See [page structure](/conversion/v3/content-reference/page-layout/page-structure).

Import doesn't create section breaks. A file with several sections arrives as one flow of content.

## When the import fails

The import fails with an error in these cases.

- The editor has Page Layout registered but its engine isn't ready, for example before the editor mounts. Import after the editor has mounted.
- The imported document doesn't fit the Source Document schema.
- The engine doesn't apply the write.

An error thrown inside `onImport`, including by `setEditorContent`, reaches `onError`. Without `onError`, it is thrown as an unhandled rejection.

<Callout title="Page breaks can make the import fail" variant="warning">
  A page break in the Word file imports as a block `pageBreak` node. The break of Page Layout sits
  inside a paragraph, so the import can fail. See [page
  breaks](/conversion/v3/content-reference/page-layout/page-breaks).
</Callout>

## Content the Source Document can't hold

Before the write, the import rewrites the content to fit the Source Document schema. A node with content, that the schema doesn't know, becomes a paragraph and keeps its children. A node without content, and any mark the schema doesn't know, is dropped. `onWarning` receives one `unsupported` warning for each type.

A section with several columns imports as a `columns` node that holds one `column` node. The Columns extension of Page Layout can't hold that shape. See [page structure](/conversion/v3/content-reference/page-layout/page-structure#section-columns).
