`ImportDocx` adds the `importDocx` command. It sends a `.docx` file to the Convert service and writes the result into your editor.

## Set up the editor

Install `@tiptap-pro/extension-import-docx` and get a token as described in [install](/conversion/v3/getting-started/install). Then add the extension.

```ts
import { Editor } from '@tiptap/core'
import StarterKit from '@tiptap/starter-kit'
import { ImportDocx } from '@tiptap-pro/extension-import-docx'

const editor = new Editor({
  element: document.querySelector('#editor'),
  extensions: [
    StarterKit,
    ImportDocx.configure({
      token: 'CONVERT_TOKEN',
      appId: 'APP_ID',
      imageUploadConfig: { url: 'https://example.com/upload' },
      onWarning: (warning) => console.warn(warning.code, warning.message),
      onError: (error) => console.error(error),
    }),
  ],
})
```

`token` is required. Every other option is optional and listed in the [API reference](/conversion/v3/import/docx/api).

<Callout title="Import calls the v2 endpoint" variant="info">
  Import and export use different versions of the Convert API. One `endpoint` ending in `/v2` works
  for both. See [install](/conversion/v3/getting-started/install#which-url-each-extension-calls).
</Callout>

## Import a file

Pass a `File` to the command.

```ts
document.querySelector('#import')?.addEventListener('change', (event) => {
  if (!(event.target instanceof HTMLInputElement)) return
  const file = event.target.files?.[0]
  if (file) editor.commands.importDocx({ file })
})
```

The command returns `true` right away. The import runs in the background and replaces the whole document when it finishes.

Without `onImport`, the import writes the document as soon as it arrives. Problems reach `onWarning` and `onError`.

## Write the document yourself

Pass `onImport` to decide when the import writes the document. It receives a context with the converted document and a `setEditorContent` function. The import writes nothing until you call it.

```ts
editor.commands.importDocx({
  file,
  onImport: (context) => {
    if (context.error) return
    context.setEditorContent()
  },
})
```

Pass a document to `setEditorContent` to write your own version of it. Use it to change the content before it reaches the editor. Without an argument, it writes `content` as Convert returned it.

`onImport` also receives what the editor doesn't take on its own, such as headers, footers, the page size and the comment threads. The [API reference](/conversion/v3/import/docx/api#importcontext) lists every field.

Where the document goes depends on the editor.

- With Page Layout, it replaces the source document. See [import with Page Layout](/conversion/v3/import/docx/page-layout).
- Without Page Layout, it goes in with `setContent`. See [import without Page Layout](/conversion/v3/import/docx/without-page-layout).

## What the editor keeps

The editor keeps only the nodes and marks its schema knows. Add the extensions for the content you expect. The [content reference](/conversion/v3/content-reference/overview) names the extension each kind of content needs.

Content the schema doesn't know doesn't fail the import. The import rewrites it to fit the schema and reports each lost node or mark type to `onWarning` as an `unsupported` warning. See [warnings and errors](/conversion/v3/import/docx/warnings-and-errors).

## Overlapping imports

The newest import wins. If you start a second import before the first response arrives, the first one writes nothing and reports an `ImportDocxSupersededError`.
