Export writes Word styles, such as Normal and Heading 1, so the `.docx` file looks like your editor. By default, it takes them from the CSS your editor renders with. Every option on this page works in `ExportDocx.configure()` and on the `exportDocx` command.

## Match your editor's formatting

By default, `exportDocx()` measures the CSS of the editor as the browser shows it, after the page's web fonts have loaded, and the file gets Word styles from it.

The measurement covers the page, text, paragraphs, headings, blockquotes, code blocks, lists, task lists, tables, horizontal rules, images and marks.

An editor created without an `element`, an editor that is not mounted and an editor on a server have nothing to measure. The command then skips the measurement without a warning, and the file gets the Conversion service's default styles.

When the measurement fails, the file gets the defaults too, with a `document-styles-failed` warning.

To turn the measurement off, set `documentStyles: false`, and set the styles with the options on this page. The file then looks the same wherever it is exported.

Browser layout and Word layout differ, so the file comes close to the editor but does not match it exactly. The measurement can miss what a custom node view or a CSS pseudo-element, such as `::before`, draws. [Check what the command measures](#check-what-the-command-measures) shows how to look at it.

## Set Word styles

The `styleOverrides` option sets Word style definitions directly, such as the font of the whole document or of Heading 1. It takes the `IStylesOptions` object of [`docx`](https://docx.js.org/#/usage/styling-with-js), the library that writes the Word file.

The `default` field of `IStylesOptions` holds `document`, `title`, `heading1` to `heading6`, `listParagraph` and other built-in styles, and `paragraphStyles` adds styles of your own. Font sizes in Word styles are half-points, so `24` is 12 pt:

```ts
editor.commands.exportDocx({
  styleOverrides: {
    default: {
      document: { run: { font: 'Arial', size: 24 } },
      heading1: { run: { font: 'Georgia', size: 36, bold: true } },
    },
  },
})
```

`IStylesOptions` has no named export, so type a variable that holds it as `ExportDocxOptions['styleOverrides']`.

## Set default formatting

The six override options set fixed properties on every element of one kind, whatever its style. Each takes the options of one class of [`docx`](https://docx.js.org):

| Option               | Applies to                                                 | Takes the options of |
| -------------------- | ---------------------------------------------------------- | -------------------- |
| `paragraphOverrides` | Every paragraph                                            | `Paragraph`          |
| `textRunOverrides`   | Every text run, which is a stretch of text with one format | `TextRun`            |
| `tableOverrides`     | Every table                                                | `Table`              |
| `tableRowOverrides`  | Every table row                                            | `TableRow`           |
| `tableCellOverrides` | Every table cell                                           | `TableCell`          |
| `imageOverrides`     | Every image                                                | `ImageRun`           |

Their values use Word's units: twips, which are 1/1440 inch, for spacing, margins and indents, and half-points for font sizes. This example puts 6 pt of space after each paragraph and 4 pt of padding into each table cell, at the top and bottom:

```ts
editor.commands.exportDocx({
  paragraphOverrides: { spacing: { after: 120 } },
  tableCellOverrides: { margins: { top: 80, bottom: 80 } },
})
```

Each override must be a plain object, because the command sends it as JSON. A function is left out with an `unsupported` warning that names the option. To give one node type its own output, write a rule, as [Render custom nodes](/conversion/v3/export/docx/custom-nodes) explains.

## Header and footer formatting

The `headerFooterOverrides` option formats the content of headers and footers differently from the body. Headers and footers reach the file only with Page Layout, as [With Page Layout](/conversion/v3/export/docx/editor-extension#with-page-layout) explains. The option takes the same six override fields:

```ts
editor.commands.exportDocx({
  paragraphOverrides: { spacing: { after: 120 } },
  headerFooterOverrides: {
    paragraphOverrides: { spacing: { after: 0 } },
    textRunOverrides: { size: 18 },
  },
})
```

A field you set replaces the body's field of the same name, and a field you leave out uses the body's. Here, header and footer paragraphs get no space after them and 9 pt text, while body paragraphs keep 6 pt after them.

A function in a field is left out with an `unsupported` warning.

## Describe styles with CSS

The experimental `cssStyles` option describes styles with CSS properties for a fixed set of selectors, instead of Word's style objects. Use it when your styles already exist as CSS. `styleOverrides` reaches more styles and properties, and wins over `cssStyles`. Property names may be camelCase or kebab-case:

```ts
editor.commands.exportDocx({
  cssStyles: {
    styles: {
      p: { color: 'red', fontSize: '16px' },
      h1: { fontFamily: 'Inter', 'font-size': '2rem' },
    },
  },
})
```

`cssStyles` takes these fields:

| Field                 | Default | What it does                                                                                                      |
| --------------------- | ------- | ----------------------------------------------------------------------------------------------------------------- |
| `styles`              | None    | The properties for each selector.                                                                                 |
| `extractFromDocument` | `false` | Also reads the rules for these selectors under `.tiptap` from the page's stylesheets. `styles` wins per property. |
| `baseFontSize`        | `16`    | The size in pixels that `rem` and `em` resolve against. It must be greater than 0.                                |

[SupportedSelector](/conversion/v3/export/docx/types#supportedselector) lists the selectors, such as `p`, `h1` to `h6` and `blockquote`. [CssPropertyMap](/conversion/v3/export/docx/types#csspropertymap) lists the properties, such as `color`, `font-size` and `margin-top`.

## Which setting wins

When several settings set the same style, a later one in this order wins:

1. The measured CSS.
2. `cssStyles`.
3. `styleOverrides`.

The six override options and `headerFooterOverrides` go on each element directly, not into a style, so they win over all three. A node's own attribute, such as a paragraph's text alignment, still wins over them.

`listLevels`, `pageColor` and `defaultTabStop` win over the measured CSS. They set list indents and markers, the page background and the distance between tab stops, as [Lists](/conversion/v3/content-reference/text-and-formatting/lists), [Page color](/conversion/v3/content-reference/page-layout/page-structure#page-color) and [Tabs](/conversion/v3/content-reference/text-and-formatting/tabs) describe.

## Embed fonts

Embed a font when the people who open the file may not have it, so Word still shows it. Pass the font files in `fonts`, and the command uploads them. In this example, the path and the family name stand for your font:

```ts
const data = await fetch('/fonts/inter-regular.ttf').then((response) => response.arrayBuffer())

editor.commands.exportDocx({
  fonts: [{ name: 'Inter', data }],
})
```

`name` must match the family name the document uses. `data` holds TTF, OTF or WOFF2 bytes, as a `Uint8Array` or an `ArrayBuffer`. Word embeds the regular variant and synthesizes bold and italic from it.

To embed the fonts you don't pass in `fonts`, set `embedFonts: true`. It is `false` by default. Export then looks for each family:

- **In the browser**, the command uploads the `@font-face` file of each family set in the document and its notes, or in `cssStyles`, `styleOverrides` and `textRunOverrides`. A family in the document is the `fontFamily` of a `textStyle` mark. Generic families such as `serif` are skipped.
- **On Google Fonts**, the Conversion service looks up the families still missing, at most 20. This lookup also finds the editor's body font in the measured CSS.

A family found in neither place is not embedded, without a warning.

A font file that is unreadable, not TTF, OTF or WOFF2, over 25 MB or past the limit of 64 files is left out with a `font-fetch-failed` warning. Word then shows another font.

## Check what the command measures

When the file looks different from the editor, call `getDocumentCss()` to see the measured CSS the command sends:

```ts
import { getDocumentCss } from '@tiptap-pro/extension-export-docx'

const css = await getDocumentCss({ editor })
console.log(css.paragraph, css.headings[1])
```

`getDocumentCss()` throws outside a browser, and when the editor is destroyed, not mounted or not laid out. Its options are in [CSS helpers](/conversion/v3/export/docx/api#css-helpers).

To change what export writes, set `styleOverrides` or the override options, or set `documentStyles: false`. The `adjustProbe` option of `getDocumentCss()` changes only what that one call measures, not what the command sends.
