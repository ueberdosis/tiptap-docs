`ExportDocx` adds the `exportDocx` command. It sends the document to the Convert service and hands you the finished `.docx` file.

## Set up the editor

Install `@tiptap-pro/extension-export-docx` and get a token as described in [install](/conversion/v3/getting-started/install). The export runs where `fetch`, `Blob` and `FormData` exist, such as a modern browser.

Add the extension to your editor.

```ts
import { Editor } from '@tiptap/core'
import StarterKit from '@tiptap/starter-kit'
import { ExportDocx } from '@tiptap-pro/extension-export-docx'

const status = document.querySelector('#status')

const editor = new Editor({
  element: document.querySelector('#editor'),
  extensions: [
    StarterKit,
    ExportDocx.configure({
      token: 'CONVERT_TOKEN',
      appId: 'APP_ID',
      exportType: 'blob',
      onCompleteExport(result) {
        if (!(result instanceof Blob)) return
        const url = URL.createObjectURL(result)
        const link = document.createElement('a')
        link.href = url
        link.download = 'report.docx'
        link.click()
        setTimeout(() => URL.revokeObjectURL(url), 1000)
        if (status) status.textContent = 'Document exported.'
      },
      onError(error) {
        if (status) status.textContent = String(error)
      },
    }),
  ],
  content: '<h1>My report</h1><p>Hello from Tiptap.</p>',
})
```

Replace `CONVERT_TOKEN` with your Convert token and `APP_ID` with your app id. Leave `appId` out if you don't have one.

`token` and `onCompleteExport` are required. You can pass `onCompleteExport` to the command instead of `ExportDocx.configure`. Without it, the default callback throws an error once the file arrives, and `onError` doesn't catch it. The other options are in the [API reference](/conversion/v3/export/docx/api).

## Export the document

Call the command from a button.

```ts
const button = document.querySelector('#export')

const save = () => {
  if (status) status.textContent = 'Exporting...'
  editor.commands.exportDocx()
}

button?.addEventListener('click', save)
```

Click the button and your browser downloads `report.docx`. Open it in Word, or another app that opens `.docx` files, to see the heading and the paragraph.

The command returns `true` right away. The file arrives later through `onCompleteExport`. A missing token, a network failure or a refused request reaches `onError`.

Without `onError`, the command rethrows the error as an unhandled rejection. Always set it.

Remove the listener and destroy the editor when you remove the UI.

```ts
button?.removeEventListener('click', save)
editor.destroy()
```

## Choose the result type

`exportType` sets what `onCompleteExport` receives.

| `exportType` | `onCompleteExport` receives                   |
| ------------ | --------------------------------------------- |
| `'blob'`     | A `Blob` with the DOCX content type. Default. |
| `'buffer'`   | A `Uint8Array`.                               |
| `'base64'`   | A base64 string.                              |
| `'string'`   | A binary string, one character per byte.      |

Any other value fails the export through `onError`.

## Options on the command

Every option you set on `ExportDocx.configure` also works on the command. An option you pass to the command wins.

```ts
editor.commands.exportDocx({
  exportType: 'buffer',
  onCompleteExport: (bytes) => upload(bytes),
})
```

## Region and endpoint

The export uses the EU region by default. Set `region: 'us'` for the US region, or set `endpoint` when you run your own Convert server. [Install](/conversion/v3/getting-started/install#which-url-each-extension-calls) lists the URL rules.

## With Page Layout

When the editor runs [Page Layout](/pages/v2/getting-started/overview), the command sends the source document and the page setup. Convert builds the page size, margins, headers and footers from that setup. There is no separate option for header or footer content. Footnotes and endnotes come from the document too.

Without Page Layout, the command exports the editor document and you set the page options yourself. See [control the output](/conversion/v3/export/docx/usage).

## What the document needs

The export writes the nodes and marks your editor has. The [content reference](/conversion/v3/content-reference/overview) names the extension each kind of content needs and says what Word keeps. For a node type your application defines, see [custom nodes](/conversion/v3/export/docx/custom-nodes).
