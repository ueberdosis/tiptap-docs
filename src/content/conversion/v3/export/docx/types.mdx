`@tiptap-pro/extension-export-docx` exports the TypeScript types of its options, warnings, errors and helpers, so your own code can name them. Import them from the package. A field marked `?` is optional. [Export DOCX API](/conversion/v3/export/docx/api) describes what each option does and its default.

`SourceThread` and some of the measured CSS types have no named export, and their sections say so.

Some types build on the option types of `docx`, the library that writes the Word file, such as `IParagraphOptions` and `IStylesOptions`. These `docx` types have no named export either. Name one through the type that uses it, such as `ParagraphOverrides` or `ExportDocxOptions['styleOverrides']`.

## Export options

These types describe what `ExportDocx.configure()` and the `exportDocx` command take.

### ExportDocxType

The shape `onCompleteExport` receives the file in:

```ts
type ExportDocxType = 'blob' | 'base64' | 'string' | 'buffer'
```

### ExportDocxOptions

The options of `ExportDocx.configure()`, with the connection and the callbacks:

```ts
interface ExportDocxOptions extends ExportRequestInput {
  token?: string
  appId?: string
  endpoint?: string
  region?: 'eu' | 'us'
  exportType: ExportDocxType
  onCompleteExport: (result: Blob | string | Uint8Array) => void
  onError?: (error: unknown) => void
  onWarning?: OnExportDocxWarning
}
```

`token` is optional in the type, but every export needs it. `onCompleteExport` is required in the type. `ExportDocx.configure` and the command both take partial options, so you can set it in either place.

### ExportDocxCommandOptions

The argument of the `exportDocx` command, where every option is optional:

```ts
interface ExportDocxCommandOptions extends Partial<ExportDocxOptions> {}
```

### ExportRequestInput

The options that shape the request.

```ts
interface ExportRequestInput {
  pageSetup?: Record<string, unknown>
  outline?: {
    types: Record<string, unknown>
    levels: unknown
    ignore: unknown
  }
  numberingFormats?: readonly NumberingFormatDefinition[]
  listLevels?: ListLevels
  defaultTabStop?: number
  pageColor?: string
  pageSize?: { width?: PageMeasure; height?: PageMeasure }
  pageMargins?: {
    top?: SignedPageMeasure
    bottom?: SignedPageMeasure
    left?: PageMeasure
    right?: PageMeasure
    header?: PageMeasure
    footer?: PageMeasure
  }
  styleOverrides?: IStylesOptions
  cssStyles?: CssStylesOptions
  documentStyles?: boolean
  fonts?: readonly DocxFontDefinition[]
  tableOverrides?: TableOverrides
  tableRowOverrides?: TableRowOverrides
  tableCellOverrides?: TableCellOverrides
  repeatTableHeaderRows?: boolean
  paragraphOverrides?: ParagraphOverrides
  textRunOverrides?: TextRunOverrides
  imageOverrides?: ImageOverrides
  headerFooterOverrides?: HeaderFooterOverrides
  footnotes?: Record<string, JSONContent>
  endnotes?: Record<string, JSONContent>
  comments?: { threads: SourceThread[] }
  customNodeDsl?: CustomNodeDsl
  embedFonts?: boolean
  onImageError?: ImageErrorPolicy
}
```

`IStylesOptions` is the Word style type of `docx`. It has no named export, so name it as `ExportDocxOptions['styleOverrides']`, as [Set Word styles](/conversion/v3/export/docx/styles#set-word-styles) shows. `outline` is the `outlineNumbering` storage of the [Outline Numbering](/features/outline-numbering) extension, passed through as it is. The Conversion service does not use it.

### SourceThread

The thread shape `comments` takes. It has no named export.

```ts
interface SourceThread {
  id: string
  resolvedAt?: string | null
  comments: Array<{
    id: string
    content: JSONContent | string
    data?: {
      author?: string
      userName?: string
      initials?: string
      dateUtc?: string
      dateIso?: string
      createdAt?: string
      originalWId?: string
      originalDurableId?: string
    }
    createdAt?: string
  }>
}
```

`originalWId` and `originalDurableId` come from a DOCX import. Export writes them back, so Word matches the comment again. [Comments](/conversion/v3/content-reference/structures-and-media/comments) says what export does with the other fields.

## Page and list types

These types describe page lengths and the numbering and positions of lists.

### PageMeasure

A measure with a unit, such as `'21cm'` or `'8.5in'`, or a number of twips:

```ts
type PageMeasure = PositiveUniversalMeasure | `${number}` | number
```

### SignedPageMeasure

Like `PageMeasure`, but it may be negative:

```ts
type SignedPageMeasure = UniversalMeasure | `${number}` | `-${number}` | number
```

### NumberingBaseStyle

A Word numbering format string, such as `'decimal'`, `'lowerRoman'` or `'bullet'`.

### NumberingMarkerFont

The formatting of a list marker:

```ts
type NumberingMarkerFont = Omit<IRunOptions, 'text' | 'children'>
```

### NumberingLevelDefinition and NumberingFormatDefinition

A `NumberingFormatDefinition` has a unique `id` and a `levels` array. A list points at it through its `numberingFormat` attribute. A depth deeper than the array reuses the levels in order. No extension defines `numberingFormat`. An import keeps it in the list's `preservedAttrs`, and export turns it back into the attribute before sending.

```ts
interface NumberingFormatDefinition {
  id: string
  levels: NumberingLevelDefinition[]
}
```

Each level has these fields. `NumberingBaseStyle` is the format and `NumberingMarkerFont` is the marker font. Indents are twips or a measure with a unit.

| Field              | Type and default                          | Meaning                                                                      |
| ------------------ | ----------------------------------------- | ---------------------------------------------------------------------------- |
| `baseStyle`        | `NumberingBaseStyle`                      | The counter format, such as `'decimal'`. Required.                           |
| `textTemplate`     | `string`                                  | The marker text. `%1` to `%9` stand for the counter at that depth. Required. |
| `startAt`          | `number`, `1`                             | The first counter value.                                                     |
| `alignment`        | `'left' \| 'center' \| 'right'`, `'left'` | Marker alignment.                                                            |
| `numberIndent`     | `number \| PositiveUniversalMeasure`      | Distance from the page margin to the marker.                                 |
| `textIndent`       | `number \| PositiveUniversalMeasure`      | Distance from the page margin to the text.                                   |
| `markerFont`       | `NumberingMarkerFont`                     | Font formatting for the marker only.                                         |
| `suffix`           | `'tab' \| 'space' \| 'nothing'`, `'tab'`  | What follows the marker.                                                     |
| `isLegalNumbering` | `boolean`                                 | Writes every referenced counter as a decimal number.                         |
| `linkedStyle`      | `string`                                  | A Word style, such as `'Heading1'`, that numbers at this level.              |

### ListLevelGeometry

Where the marker and the text of one list level sit. Indents are measured from the left margin, and a number is twips. In `text`, `%1` stands for the level's number:

```ts
type ListLevelGeometry = {
  textIndent?: number | PositiveUniversalMeasure
  numberIndent?: number | PositiveUniversalMeasure
  rightIndent?: number | PositiveUniversalMeasure
  text?: string
  markerFont?: NumberingMarkerFont
  format?: NumberingBaseStyle
}
```

### ListLevels

The positions for each kind of list, with one entry per list depth:

```ts
type ListLevels = {
  bullet?: readonly ListLevelGeometry[]
  ordered?: readonly ListLevelGeometry[]
  task?: readonly ListLevelGeometry[]
}
```

## Override types

Each override is a plain object of `docx` properties.

```ts
type ParagraphOverrides = Omit<IParagraphOptions, 'children'>
type TextRunOverrides = Omit<IRunOptions, 'text'>
type TableOverrides = Omit<ITableOptions, 'rows'>
type TableRowOverrides = Omit<ITableRowOptions, 'children'>
type TableCellOverrides = Omit<ITableCellOptions, 'children'>
type ImageOverrides = Omit<IImageOptions, 'data' | 'type' | 'fallback'>
```

### HeaderFooterOverrides

The six overrides for header and footer content. A field you leave out uses the body's value:

```ts
type HeaderFooterOverrides = {
  tableOverrides?: TableOverrides
  tableRowOverrides?: TableRowOverrides
  tableCellOverrides?: TableCellOverrides
  paragraphOverrides?: ParagraphOverrides
  textRunOverrides?: TextRunOverrides
  imageOverrides?: ImageOverrides
}
```

## Font types

These types describe the fonts `fonts` embeds.

### DocxFontCharacterSet

A Word charset code string, such as `'00'` for ANSI or `'01'` for the default charset.

### DocxFontDefinition

A `DocxFontDefinition` describes one font file. `name` is the family name the document uses, and `data` holds TTF, OTF or WOFF2 bytes:

```ts
interface DocxFontDefinition {
  name: string
  data: Uint8Array | ArrayBuffer
  characterSet?: DocxFontCharacterSet
}
```

## Document types

These types are plain Tiptap JSON shapes.

### Node

A node of the document:

```ts
interface Node extends JSONContent {}
```

### Mark

A mark on a node:

```ts
interface Mark {
  type: string
  attrs?: Record<string, unknown>
}
```

## Warning and error types

These types describe what `onWarning` and `onError` receive. [Export warnings and errors](/conversion/v3/export/docx/warnings-and-errors) explains each code.

### ExportDocxWarning

One warning, with the fields that fit its code:

```ts
interface ExportDocxWarning {
  code:
    | ImageErrorCode
    | DocumentStylesWarningCode
    | UnsupportedWarningCode
    | ListParagraphPathWarningCode
    | WarningsTruncatedCode
    | FontWarningCode
    | NumberingFormatWarningCode
  message: string
  src?: string
  family?: string
  status?: number
  contentType?: string
  nodeType?: string
  attribute?: string
  value?: unknown
  path?: number[]
  formatId?: string
  noteId?: string
}
```

### Warning codes

Each warning code has a type of its own:

```ts
type ImageErrorCode =
  | 'image-missing-src'
  | 'image-request-failed'
  | 'image-fetch-failed'
  | 'image-unsupported-type'
type DocumentStylesWarningCode = 'document-styles-failed'
type UnsupportedWarningCode = 'unsupported'
type ListParagraphPathWarningCode = 'list-paragraph-path-missing'
type WarningsTruncatedCode = 'warnings-truncated'
type FontWarningCode = 'font-fetch-failed'
type NumberingFormatWarningCode = 'numbering-format-invalid'
```

`onWarning` also receives codes from the Conversion service that are not in this type, such as `image-resized`. [Warning codes](/conversion/v3/export/docx/warnings-and-errors#warning-codes) lists all of them.

### OnExportDocxWarning

The type of `onWarning`:

```ts
type OnExportDocxWarning = (warning: ExportDocxWarning) => void
```

### ImageErrorPolicy

The type of `onImageError`:

```ts
type ImageErrorPolicy = 'skip' | 'throw'
```

### ExportDocxRequestError

The error for a request that did not reach the Conversion service, or that it refused:

```ts
type ExportDocxRequestErrorCode = 'NETWORK_ERROR' | 'HTTP_ERROR' | (string & {})

class ExportDocxRequestError extends Error {
  readonly name: 'ExportDocxRequestError'
  readonly code: ExportDocxRequestErrorCode
  readonly status?: number
  readonly path?: string
  readonly docsUrl?: string
}
```

`cause`, the standard `Error` field, holds the original error of a `NETWORK_ERROR`. [ExportDocxRequestError](/conversion/v3/export/docx/warnings-and-errors#exportdocxrequesterror) describes each field and code.

### Image errors

The image error classes, which all extend `ImageConversionError`. [Image errors](/conversion/v3/export/docx/warnings-and-errors#image-errors) says when the export fails with one:

```ts
abstract class ImageConversionError extends Error {
  abstract readonly code: ImageErrorCode
  readonly src?: string
  readonly cause?: unknown
}

class ImageMissingSrcError extends ImageConversionError {
  readonly code: 'image-missing-src'
}

class ImageRequestError extends ImageConversionError {
  readonly code: 'image-request-failed'
}

class ImageFetchError extends ImageConversionError {
  readonly code: 'image-fetch-failed'
  readonly status: number
}

class UnsupportedImageTypeError extends ImageConversionError {
  readonly code: 'image-unsupported-type'
  readonly contentType?: string
}
```

## Custom node types

`CustomNodeDsl` and the types it uses are exported from `@tiptap-pro/extension-export-docx`. Their JSON shape is described in [Render custom nodes](/conversion/v3/export/docx/custom-nodes).

```ts
interface CustomNodeDsl {
  dslVersion: '1.0'
  nodes: CustomNodeRule[]
}

interface CustomNodeRule {
  type: string
  nodeKind?: 'block' | 'inline' | 'auto'
  render: RenderProgram | null
}

interface RenderProgram {
  emit?: RenderNode | RenderNode[] | null
}

type RenderNode = ElementNode | ChildrenOp | TextOp | FragmentOp | IfOp | SwitchOp | null
```

The parts of `RenderNode` are exported too: `ElementNode`, `ChildrenOp`, `TextOp`, `FragmentOp`, `IfOp` and `SwitchOp`. [Choose the output shape](/conversion/v3/export/docx/custom-nodes#choose-the-output-shape) describes them.

The other exported names are `ApplyMarksPolicy`, `ApplyMarksPolicyObject`, `ChildrenKind`, `DslVersion`, `ElementName`, `MarkOverride`, `MarkPolicy`, `MarkPolicyObject`, `MarkType`, `NodeKind`, `OpExpr`, `OpName`, `RefExpr`, `TemplateExpr`, `TransformName`, `UnitExpr`, `UnitName`, `ValueExpr` and `ValueSwitchExpr`.

`CustomNodeDslLimits` is also exported. It names the limits the Conversion service applies, and no export option takes it.

## CSS style types

These types describe the experimental `cssStyles` option.

### CssStylesOptions

The value of `cssStyles`:

```ts
interface CssStylesOptions {
  styles?: CssStylesInput
  extractFromDocument?: boolean
  baseFontSize?: number
}
```

`extractFromDocument` defaults to `false`. When `true`, the command reads `.tiptap` rules from the page's stylesheets, and `styles` wins per property. `baseFontSize` resolves `rem` and `em` values. Its default is 16 pixels.

### SupportedSelector

The selectors `cssStyles.styles` takes:

```ts
type SupportedSelector =
  | 'p'
  | 'h1'
  | 'h2'
  | 'h3'
  | 'h4'
  | 'h5'
  | 'h6'
  | 'blockquote'
  | 'a'
  | 'code'
  | 'ul li'
  | 'ol li'
  | 'strong'
  | 'em'
  | 'u'
  | 's'
```

### CssStylesInput

An object with one optional `CssPropertyMap` per `SupportedSelector` key:

```ts
import type { CssStylesInput } from '@tiptap-pro/extension-export-docx'

const styles: CssStylesInput = {
  p: { color: 'red', fontSize: '16px' },
  h1: { fontFamily: 'Inter', 'font-size': '2rem' },
}
```

### CssPropertyMap

String values for these properties, in camelCase or kebab-case: `color`, `font-size`, `font-family`, `font-weight`, `font-style`, `line-height`, `text-align`, `margin-top`, `margin-bottom`, `background-color`, `text-decoration` and `letter-spacing`.

## Measured CSS types

These types describe what `getDocumentCss()` returns, which is the measured CSS the command sends. Measurements are CSS pixels unless a field says otherwise.

The parts of `DocumentCss` use these helper types:

```ts
type TextAlignCss = 'left' | 'center' | 'right' | 'justify'
type UnderlineCss = {
  style: 'solid' | 'double' | 'dotted' | 'dashed' | 'wavy'
  color: HexColor
} | null
type StrikethroughCss = 'single' | 'double' | null
type VerticalAlignCss = 'baseline' | 'sub' | 'super' | number
type FloatCss = 'none' | 'left' | 'right'
type CellVerticalAlignCss = 'baseline' | 'top' | 'middle' | 'bottom'
type WritingModeCss =
  | 'horizontal-tb'
  | 'vertical-rl'
  | 'vertical-lr'
  | 'sideways-rl'
  | 'sideways-lr'
type TableLayoutCss = 'fixed' | 'auto'
type TableAlignmentCss = 'left' | 'center' | 'right'
type ColumnsCss = { count: number; gap: number }
```

These helper types have no named export.

type BoxCss = TextCss & {

### DocumentCss

The whole measurement, one entry for each kind of content. `firstBlock` is `null` when the document is empty:

```ts
type DocumentCss = {
  page: PageCss
  text: TextCss
  paragraph: BlockCss
  headings: Record<1 | 2 | 3 | 4 | 5 | 6, BlockCss>
  blockquote: {
    container: BoxCss
    paragraph: BlockCss
  }
  codeBlock: {
    container: BlockCss
    code: TextCss
  }
  bulletList: ListCss
  orderedList: ListCss
  taskList: TaskListCss
  table: TableCss
  horizontalRule: RuleCss
  image: ImageCss
  marks: {
    bold: TextCss
    italic: TextCss
    underline: TextCss
    strike: TextCss
    code: TextCss
    link: TextCss
    highlight: TextCss
    subscript: TextCss
    superscript: TextCss
  }
  firstBlock: FirstBlockCss | null
}
```
