Each row links to the section of a detail page that names the extension the feature needs. To add import and export to an editor, see [Import DOCX](/conversion/v3/docx/import) and [Export DOCX](/conversion/v3/docx/export).

When the editor has no extension for some content, import keeps it as preserved content, a node the editor stores and shows as a placeholder.

When an extension doesn't define an attribute, import keeps the attribute in the node's `preservedAttrs`, which the editor stores without showing. Export writes both back, as [Content the editor cannot show](/conversion/v3/docx/preserved-content) explains.

## Text formatting

Character formatting arrives as marks on the text. [Text formatting](/conversion/v3/docx/elements/text-formatting) has the details.

| Feature                                                                                                             | Import | Export | Notes                                                                                                                                                             |
| ------------------------------------------------------------------------------------------------------------------- | ------ | ------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [Bold, italic, strikethrough](/conversion/v3/docx/elements/text-formatting#bold-italic-underline-and-strikethrough) | Yes    | Yes    | Double strikethrough doesn't import.                                                                                                                              |
| [Underline](/conversion/v3/docx/elements/text-formatting#bold-italic-underline-and-strikethrough)                   | Yes    | Yes    | Underline styles such as double or dotted import as `underlineType`, which `Underline` doesn't define, so the editor keeps it in `preservedAttrs`.                |
| [Subscript, superscript](/conversion/v3/docx/elements/text-formatting#subscript-and-superscript)                    | Yes    | Yes    | Needs `Subscript` and `Superscript`.                                                                                                                              |
| [Text color](/conversion/v3/docx/elements/text-formatting#text-color-and-highlight)                                 | Yes    | Yes    | Needs `TextStyle` and `Color`. A theme color without a hex value doesn't import.                                                                                  |
| [Highlight](/conversion/v3/docx/elements/text-formatting#text-color-and-highlight)                                  | Yes    | Yes    | Import also reads Word's character shading, a background color behind text, as a highlight. Needs `Highlight` with `multicolor: true` for the color.              |
| [Font family, font size](/conversion/v3/docx/elements/text-formatting#font-family-and-size)                         | Yes    | Yes    | Needs `TextStyle`, `FontFamily` and `FontSize`. Import rounds sizes to whole pixels. Theme fonts, which Word's styles name as body or heading font, don't import. |
| [Letter spacing](/conversion/v3/docx/elements/text-formatting#export)                                               | Partly | Partly | Import keeps `letterSpacing` in `preservedAttrs`, but export doesn't write it. Export writes the letter spacing your editor's CSS sets for all text.              |
| [Embedded fonts](/conversion/v3/docx/export-styles#embed-fonts)                                                     | No     | Yes    | Export embeds fonts when you set `embedFonts` or pass `fonts`.                                                                                                    |

## Paragraphs and styles

Paragraph formatting arrives as attributes of the `paragraph` and `heading` nodes. [Paragraphs and styles](/conversion/v3/docx/elements/paragraphs) has the details.

| Feature                                                                                      | Import | Export | Notes                                                                                                                                                                                                    |
| -------------------------------------------------------------------------------------------- | ------ | ------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [Paragraphs](/conversion/v3/docx/elements/paragraphs#import)                                 | Yes    | Yes    |                                                                                                                                                                                                          |
| [Headings](/conversion/v3/docx/elements/paragraphs#headings)                                 | Yes    | Yes    | Title, Subtitle and other styles import as paragraphs. A heading of level 7 to 9 exports as a paragraph.                                                                                                 |
| [Text alignment](/conversion/v3/docx/elements/paragraphs#text-alignment)                     | Yes    | Yes    | Needs `TextAlign` with `types`.                                                                                                                                                                          |
| [Line spacing](/conversion/v3/docx/elements/paragraphs#spacing-indents-and-line-spacing)     | Yes    | Yes    | Needs `LineHeight` with `paragraph` and `heading` in `types`.                                                                                                                                            |
| [Spacing before and after](/conversion/v3/docx/elements/paragraphs#show-spacing-and-indents) | Yes    | Yes    | Kept in `preservedAttrs` and written back, but the editor shows the spacing only once you define the attributes.                                                                                         |
| [Indentation](/conversion/v3/docx/elements/paragraphs#show-spacing-and-indents)              | Yes    | Yes    | Left, right, first-line and hanging indents, kept in `preservedAttrs`.                                                                                                                                   |
| [Keep with next, keep lines together](/conversion/v3/docx/elements/paragraphs#what-you-need) | Yes    | Yes    | No extension defines the attributes, so the editor keeps them in `preservedAttrs`.                                                                                                                       |
| [Paragraph borders](/conversion/v3/docx/elements/paragraphs#limits)                          | No     | Partly | Import ignores them. Export writes the paragraph borders your editor's CSS draws.                                                                                                                        |
| [Named styles](/conversion/v3/docx/elements/paragraphs#node-types-from-word-styles)          | Partly | Partly | Heading and Quote styles import as nodes, and other paragraph styles as their formatting. Export writes your editor's look into Word's built-in styles.                                                  |
| [Tabs](/conversion/v3/docx/elements/paragraphs#tabs)                                         | Partly | Yes    | A tab imports as four spaces, and tab stops don't import. Export writes a tab character as a Word tab.                                                                                                   |
| [Right-to-left text](/conversion/v3/docx/elements/paragraphs#right-to-left-text)             | No     | Partly | Import ignores the text direction. Export marks every paragraph right to left when the editor's CSS renders it right to left, such as with `direction: rtl`.                                             |
| [Blockquotes](/conversion/v3/docx/elements/paragraphs#blockquotes-rules-and-breaks)          | Yes    | Yes    | Import reads Word's Quote style, and export writes it.                                                                                                                                                   |
| [Horizontal rules](/conversion/v3/docx/elements/paragraphs#blockquotes-rules-and-breaks)     | Yes    | Yes    |                                                                                                                                                                                                          |
| [Hard breaks](/conversion/v3/docx/elements/paragraphs#blockquotes-rules-and-breaks)          | Yes    | Yes    | A line break that the file stores as a carriage return imports as a `hardBreak` too.                                                                                                                     |
| [Code blocks](/conversion/v3/docx/elements/paragraphs#blockquotes-rules-and-code)            | No     | Yes    | Export writes one paragraph in the Code Block style, with a line break for each newline. Import reads it back as a plain paragraph.                                                                      |
| [Inline code](/conversion/v3/docx/elements/paragraphs#blockquotes-rules-and-code)            | Yes    | Yes    | Export writes Word's Code character style, and import reads it back as the `code` mark. On import, a mark that `code` doesn't allow with it, such as `bold`, is left out with a `mark-excluded` warning. |

## Lists and task lists

Lists arrive as list nodes, and checkbox lists as task lists. [Lists and task lists](/conversion/v3/docx/elements/lists) has the details.

| Feature                                                                      | Import | Export | Notes                                                                                                                                                                                                                                                                                             |
| ---------------------------------------------------------------------------- | ------ | ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [Bullet lists](/conversion/v3/docx/elements/lists#bullet-and-ordered-lists)  | Yes    | Yes    |                                                                                                                                                                                                                                                                                                   |
| [Ordered lists](/conversion/v3/docx/elements/lists#bullet-and-ordered-lists) | Yes    | Yes    | Import sets `start` and, for letters and Roman numerals, `type`. Export numbers from `start` but doesn't read `type`.                                                                                                                                                                             |
| [Numbering formats](/conversion/v3/docx/elements/lists#numbering-formats)    | No     | Yes    | Import doesn't bring the file's numbering formats, so lists use default numbering. Export writes the formats you pass in `numberingFormats`.                                                                                                                                                      |
| [Nested lists](/conversion/v3/docx/elements/lists#export)                    | Yes    | Yes    | Export writes up to nine levels.                                                                                                                                                                                                                                                                  |
| [Task lists](/conversion/v3/docx/elements/lists#task-lists)                  | Yes    | Yes    | With the default `taskLists: 'auto'`, an option of `ImportDocx`, import makes task lists. Without `TaskList` and `TaskItem`, the editor keeps them as preserved content, ticked states included.                                                                                                  |
| [Numbered headings](/conversion/v3/docx/elements/lists#numbered-headings)    | Partly | Partly | A numbered heading from Word imports as a list item, and the heading becomes the item's paragraph, with a `restructured` warning. Headings numbered by the [Outline Numbering](/features/outline-numbering) extension export without numbers, unless a numbering format links the heading styles. |

## Images and math

Images and formulas each arrive as nodes of their own. [Images and math](/conversion/v3/docx/elements/images-and-math) has the details.

| Feature                                                                | Import | Export | Notes                                                                                                                                                                                       |
| ---------------------------------------------------------------------- | ------ | ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [Inline images](/conversion/v3/docx/elements/images-and-math#images)   | Yes    | Yes    | Import needs `imageUploadConfig`, the option of `ImportDocx` that names your upload endpoint. Without it, each image is left out with an `image-skipped` warning.                           |
| [Floating images](/conversion/v3/docx/elements/images-and-math#images) | Partly | No     | Import adds a floating image inline, without its position. It skips images behind the text unless the `behindTextImages` option of `ImportDocx` is `'import'`. Export writes images inline. |
| [Image size](/conversion/v3/docx/elements/images-and-math#images)      | Yes    | Yes    |                                                                                                                                                                                             |
| [Image cropping](/conversion/v3/docx/elements/images-and-math#limits)  | Yes    | No     | Import keeps the crop attributes in `preservedAttrs`. Export writes the whole image.                                                                                                        |
| [Math](/conversion/v3/docx/elements/images-and-math#math)              | No     | Yes    | Import leaves Word equations out, without a warning. Export writes the `inlineMath` and `blockMath` nodes of the Mathematics extension as Word equations.                                   |

## Page layout

[Page Layout](/features/page-layout/getting-started/overview), the extension that shows the document on pages, holds sections, page setup, headers and footers. Import brings them into it, and export writes them from it. Without Page Layout, import keeps them as preserved content. [Word files with Page Layout](/conversion/v3/docx/page-layout) has the details.

| Feature                                                               | Import | Export | Notes                                                                                                                                                                         |
| --------------------------------------------------------------------- | ------ | ------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [Page breaks](/conversion/v3/docx/page-layout)                        | Yes    | Yes    | Column breaks convert too. Without Page Layout, add `@tiptap-pro/extension-pagebreak` to keep page breaks as its `pageBreak` node, or import keeps them as preserved content. |
| [Page size, orientation and margins](/conversion/v3/docx/page-layout) | Yes    | Yes    | For each section. Import leaves out the binding gutter, with a `gutter-dropped` warning.                                                                                      |
| [Sections](/conversion/v3/docx/page-layout)                           | Yes    | Yes    | A section that Word starts on an even page, on an odd page or in a new column imports as a section that starts on the next page.                                              |
| [Section columns](/conversion/v3/docx/page-layout)                    | Yes    | Yes    | Word's Layout > Columns, kept as settings of each section's `sectionBreak` node.                                                                                              |
| [Headers and footers](/conversion/v3/docx/page-layout)                | Yes    | Yes    | Each section's own, with first page and even page versions.                                                                                                                   |
| [Page number fields](/conversion/v3/docx/page-layout)                 | Yes    | Yes    | Word's fields for the page number, the number of pages and the number of pages in the section import as Page Layout's `pageNumber` nodes, which export as live fields.        |
| [Other fields, such as dates](/conversion/v3/docx/page-layout)        | Partly | No     | Import keeps the text Word last showed, which no longer updates. Export writes that text, not a field.                                                                        |
| [Page numbering](/conversion/v3/docx/page-layout)                     | Yes    | Yes    | Number format, start number, and Word's "Include chapter number", such as `2-5` for page 5 of chapter 2. A custom Word number format imports as the default.                  |
| [Page color](/conversion/v3/docx/page-layout#page-color)              | Yes    | Yes    | Import puts Word's one page color on the first section. Export writes the `pageColor` option, or else the first section's color.                                              |

## Review

Comments and tracked changes convert through the Comments and Tracked Changes extensions. [Tracked changes and comments](/conversion/v3/docx/tracked-changes-and-comments) has the details.

| Feature                                                             | Import | Export | Notes                                                                                                                                                                                                                                                                          |
| ------------------------------------------------------------------- | ------ | ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| [Comments](/conversion/v3/docx/tracked-changes-and-comments)        | Yes    | Yes    | Import marks the commented text and passes the threads to `onImport` as `commentThreads`. [Import comments](/conversion/v3/docx/tracked-changes-and-comments#import-comments) says how they become threads in the editor. Export writes the threads of the Comments extension. |
| [Tracked changes](/conversion/v3/docx/tracked-changes-and-comments) | Partly | Partly | Insertions and deletions in the body convert as suggestions of the Tracked Changes extension. Formatting changes and moves don't convert.                                                                                                                                      |

## Limits

These Word features convert only partly or not at all. Where import leaves something out without a warning, it is a known limit that is being fixed.

| Feature                                                                                                 | What happens                                                                                                                                                                                             |
| ------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Table of contents                                                                                       | Import keeps the entries as plain paragraphs, with a `toc-flattened` warning. Export drops a `tableOfContents` node with an `unsupported` warning.                                                       |
| Text boxes                                                                                              | Import leaves them out with their text, without a warning.                                                                                                                                               |
| Shapes, SmartArt, WordArt                                                                               | Import leaves them out, without a warning.                                                                                                                                                               |
| Symbols inserted with Word's Symbol command                                                             | Import keeps each symbol as its character in the symbol's font, so it shows correctly only where that font is installed, as [Text formatting](/conversion/v3/docx/elements/text-formatting#limits) says. |
| Text in custom XML tags, which mark parts of a file for other software, and in text direction overrides | Import keeps the text, but a text direction override loses its direction.                                                                                                                                |
| Hidden text                                                                                             | Import leaves it out, without a warning.                                                                                                                                                                 |
| Content controls and form fields                                                                        | Import keeps the text and drops the control.                                                                                                                                                             |
| Document properties, such as author and title                                                           | Import doesn't read them, and export doesn't write them.                                                                                                                                                 |
