The custom node builder comes from `@tiptap-pro/extension-export-docx/dsl`, as [Custom node DSL](/conversion/v3/docx/custom-nodes/dsl) describes.

## ExportDocx

`ExportDocx` is the extension, named `'export-docx'`. It adds the `exportDocx` command, and no storage or events. [Export DOCX](/conversion/v3/docx/export) shows how to set it up.

Every option on this page works in `ExportDocx.configure()` and on the command. An option passed to the command wins for that export, and replaces the configured value as a whole. [Commands](/conversion/v3/reference/commands) describes the `exportDocx()` command.

## Connection

These options say where the command sends the document, and with which credentials:

| Option     | Type           | Default  | Description                                                                                                   |
| ---------- | -------------- | -------- | ------------------------------------------------------------------------------------------------------------- |
| `token`    | `string`       | Required | The Conversion token. Without it, the export fails through `onError`.                                         |
| `appId`    | `string`       | None     | Your app ID, sent as `X-App-Id`. Only a legacy token needs it.                                                |
| `region`   | `'eu' \| 'us'` | `'eu'`   | The Tiptap Cloud region, used when `endpoint` is not set.                                                     |
| `endpoint` | `string`       | None     | The base URL of your own Conversion service, such as `https://convert.example.com/v3`. It wins over `region`. |

`token` is optional in the TypeScript type, but every export needs it.

A token you sign as [Install Tiptap Conversion](/conversion/v3/getting-started/install) shows, with the audience claim `aud: "Convert"`, needs no `appId`. A legacy token is one signed with the secret of an app ID. Tiptap Cloud refuses a legacy token without `appId`, with status `401` and the code `missing_app_id`.

[Region and endpoint](/conversion/v3/getting-started/install#region-and-endpoint) says which of `region` and `endpoint` to set, and which base URL your own server takes.

## Callbacks

These options receive the result:

| Option             | Type                                             | Default                          | Description                                                                                                                                                   |
| ------------------ | ------------------------------------------------ | -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `exportType`       | `'blob' \| 'buffer' \| 'base64' \| 'string'`     | `'blob'`                         | What `onCompleteExport` receives: a `Blob`, a `Uint8Array` for `'buffer'`, or a string. [Save the file](/conversion/v3/docx/export#save-the-file) shows each. |
| `onCompleteExport` | `(result: Blob \| string \| Uint8Array) => void` | Throws an error                  | Receives the file. Set it, because the default throws when the file arrives. An error thrown here does not reach `onError`.                                   |
| `onError`          | `(error: unknown) => void`                       | None                             | Receives the error when the export fails. Without it, the error becomes an unhandled promise rejection.                                                       |
| `onWarning`        | `(warning: ExportDocxWarning) => void`           | Logs each warning to the console | Receives each warning. An error thrown inside it is ignored. See [Warnings](/conversion/v3/reference/warnings).                                               |

Each override option must be a plain object. The command leaves out a function, with an `unsupported` warning that names the option.

The command sends only the options on this page. It leaves out any other key without a warning, except the [removed 0.x options](#removed-0x-options).

## Node types

The Conversion service converts these node types itself, and a `table` with its rows and cells. Any other node type needs a rule, as [Custom nodes in Word files](/conversion/v3/docx/custom-nodes) explains. `image` and `pageBreak` appear in both rows, because they can be a block or sit inside text:

| Kind   | Types                                                                                                                                                                                                              |
| ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Block  | `paragraph`, `heading`, `blockquote`, `codeBlock`, `bulletList`, `orderedList`, `taskList`, `taskItem`, `listItem`, `table`, `image`, `horizontalRule`, `pageBreak`, `blockMath`, `blockThread`, `pageNumberFrame` |
| Inline | `text`, `hardBreak`, `image`, `inlineMath`, `footnoteReference`, `endnoteReference`, `bookmark`, `pageBreak`, `columnBreak`, `pageNumber`                                                                          |

`blockThread` is a commented block of the Comments extension, and `pageNumberFrame` a page number that Page Layout places in a header or footer.

No Tiptap extension defines a `bookmark` node, and import drops Word bookmarks, so only JSON you write yourself holds one. [Links and bookmarks](/conversion/v3/docx/elements/links-and-bookmarks) says what export writes for bookmarks.

## Removed 0.x options

The command leaves these 0.x options out and reports an `unsupported` warning that names the option, so the Conversion service does not refuse the request for them. [Migrate export from Conversion v2](/conversion/v3/getting-started/migrate-from-v2/export) walks through the changes.

| Removed option        | Use instead                                                   |
| --------------------- | ------------------------------------------------------------- |
| `customNodes`         | `customNodeDsl`.                                              |
| `customNodeDslLimits` | None. The Conversion service applies its own limits.          |
| `headers`, `footers`  | The header and footer content of the Page Layout setup.       |
| `placeholders`        | None.                                                         |
| Function overrides    | Plain objects. For output per node type, use `customNodeDsl`. |

## Endpoint helpers

`resolveConvertV3Endpoint()` returns the base URL the command sends to, from the `endpoint` and `region` options. The command then calls `<base>/export/docx`. For your own server, set `endpoint` to its URL followed by `/v3`, as [Region and endpoint](/conversion/v3/getting-started/install#region-and-endpoint) shows. Use the function to check where a custom `endpoint` leads:

```ts
import { resolveConvertV3Endpoint } from '@tiptap-pro/extension-export-docx'

resolveConvertV3Endpoint({ endpoint: 'https://convert.example.com/v2' })
// 'https://convert.example.com/v3'
```

`resolveConvertV3Endpoint()` takes one object with these fields:

| Field      | Type           | Default | Description                                         |
| ---------- | -------------- | ------- | --------------------------------------------------- |
| `endpoint` | `string`       | None    | A custom base URL. It wins over `region`.           |
| `region`   | `'eu' \| 'us'` | `'eu'`  | The Tiptap Cloud region when `endpoint` is not set. |

Without `endpoint`, it returns the region's URL: `https://api.tiptap.dev/v3/convert` for `eu`, and `https://api-us.tiptap.dev/v3/convert` for `us`. `CONVERT_V3_REGION_ENDPOINTS` holds the same map.

With `endpoint`, it rewrites the version at the end of the path to v3, and keeps a query string or hash:

- A base that ends in `/v2` or `/v3` becomes `/v3`.
- A base that ends in `/v2/convert` or `/v3/convert` becomes `/v3/convert`.
- Any other base stays as it is, with one console warning for each base.

## CSS helpers

`extractTiptapCssStyles()` reads the supported rules from the page's stylesheets, and returns them as a `CssStylesInput`, the shape `cssStyles.styles` takes. Its optional argument is an object with `scope`, the selector a rule must start with, which defaults to `'.tiptap'`.

Outside a browser, `extractTiptapCssStyles()` returns an empty object, and it skips stylesheets it can't read.

`cssStyles: { extractFromDocument: true }` does the same with the default scope. Call the function yourself to read the rules under another selector:

```ts
import { extractTiptapCssStyles } from '@tiptap-pro/extension-export-docx'

editor.commands.exportDocx({
  cssStyles: { styles: extractTiptapCssStyles({ scope: '.my-editor' }) },
})
```

`getDocumentCss()` returns a promise of the `DocumentCss` that `documentStyles` measures and the command sends. It waits for the page's web fonts first. [Check what the command measures](/conversion/v3/docx/export/styles-and-fonts#check-what-the-command-measures) shows how to use it. It takes one object with these fields:

| Field         | Type                           | Default  | Description                                                                                                                                                                                                           |
| ------------- | ------------------------------ | -------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `editor`      | `Editor`                       | Required | The mounted editor to measure.                                                                                                                                                                                        |
| `listDepth`   | `number`                       | `9`      | How many list depths to measure, an integer from 1 to 9. Another value throws.                                                                                                                                        |
| `adjustProbe` | `(probe: HTMLElement) => void` | None     | Changes the hidden sample elements the measurement reads, so they match what your custom node views render. Keep their `data-css` attributes. The command does not use it, so it changes only what this call returns. |

`getDocumentCss()` throws outside a browser, and when the editor is destroyed, has no view, is not mounted or is not laid out, such as inside an element with `display: none`.
