## Set the page

This example runs on the editor from [Set up the editor](/conversion/v3/docx/export#set-up-the-editor). It sets an A4 page with margins of 2 cm at the top and bottom and 2.5 cm at the sides:

```ts
editor.commands.exportDocx({
  pageSize: { width: '21cm', height: '29.7cm' },
  pageMargins: {
    top: '2cm',
    bottom: '2cm',
    left: '2.5cm',
    right: '2.5cm',
    header: '1cm',
    footer: '1cm',
  },
})
```

Both options also work in `ExportDocx.configure()`, as [Export DOCX](/conversion/v3/docx/export) shows.

Without them, the page is A4 with margins of 2.54 cm at the top and bottom and 3.17 cm at the sides. A size or margin you leave out keeps its default, so `pageSize: { width: '8.5in' }` keeps the A4 height of 29.7 cm.

`header` and `footer` set how far the header and footer sit from the page edge. Without them, Word uses its own default.

## Measures

A measure is a string with the unit `mm`, `cm`, `in`, `pt` or `pc`, such as `'2cm'`. A number is twips, which are 1/1440 inch, and so is a numeric string such as `'1134'`.

These measures fail the export with 400 `INVALID_EXPORT_OPTIONS`:

- A `px` measure.
- A negative `left`, `right`, `header` or `footer`.

A number `0` means the default, without a warning, so write `'0cm'` for a margin of zero. This is a known limit that is being fixed.

## Negative margins

Only `top` and `bottom` may be negative. With a negative top margin, Word starts the body text at that distance from the edge, even when the header is taller, so the header and the text can overlap. A negative bottom margin does the same with the footer.
