Export writes Word styles, such as Normal and Heading 1, so the `.docx` file looks like your editor. By default, it takes them from the CSS your editor renders with. Every option on this page works in `ExportDocx.configure()` and on the `exportDocx` command, as [Export DOCX](/conversion/v3/docx/export) shows.

## Match your editor's formatting

By default, `exportDocx()` measures the CSS of the editor as the browser shows it, and the file gets Word styles from it.

The measurement covers the page, text, paragraphs, headings, blockquotes, code blocks, lists, task lists, tables, horizontal rules, images and marks.

An editor created without an `element`, an editor that is not mounted and an editor on a server have nothing to measure. The command then skips the measurement without a warning, and the file gets the Conversion service's default styles.

When the measurement fails, the file gets the defaults too, with a `document-styles-failed` warning.

To turn the measurement off, set `documentStyles: false`, and set the styles with the options on this page. The file then looks the same wherever it is exported.

Browser layout and Word layout differ, so the file comes close to the editor but does not match it exactly. The measurement can miss what a custom node view or a CSS pseudo-element, such as `::before`, draws. [Check what the command measures](#check-what-the-command-measures) shows how to look at it.

## Set Word styles

The `styleOverrides` option sets Word style definitions directly, such as the font of the whole document or of Heading 1. It takes the `IStylesOptions` object of [`docx`](https://docx.js.org/#/usage/styling-with-js), the npm library the Conversion service writes the Word file with. Its docs describe every field.

The `default` field of `IStylesOptions` holds `document`, the formatting that Normal and every other style start from, such as the body font. It also holds `title`, `heading1` to `heading6`, `listParagraph` and other built-in styles. `paragraphStyles` adds styles of your own.

Font sizes in Word styles are half-points, so `24` is 12 pt:

```ts
editor.commands.exportDocx({
  styleOverrides: {
    default: {
      document: { run: { font: 'Arial', size: 24 } },
      heading1: { run: { font: 'Georgia', size: 36, bold: true } },
    },
  },
})
```

`@tiptap-pro/extension-export-docx` doesn't export `IStylesOptions` by name, so type a variable that holds it with the options type of the extension:

```ts
import type { ExportDocxOptions } from '@tiptap-pro/extension-export-docx'

const styles: ExportDocxOptions['styleOverrides'] = {
  default: { document: { run: { font: 'Arial' } } },
}
```

## Set default formatting

The six override options set fixed properties on every element of one kind, whatever its style. Each takes the options of one class of [`docx`](https://docx.js.org):

| Option               | Applies to                                                 | Takes the options of |
| -------------------- | ---------------------------------------------------------- | -------------------- |
| `paragraphOverrides` | Every paragraph                                            | `Paragraph`          |
| `textRunOverrides`   | Every text run, which is a stretch of text with one format | `TextRun`            |
| `tableOverrides`     | Every table                                                | `Table`              |
| `tableRowOverrides`  | Every table row                                            | `TableRow`           |
| `tableCellOverrides` | Every table cell                                           | `TableCell`          |
| `imageOverrides`     | Every image                                                | `ImageRun`           |

Their values use Word's units: twips for spacing, margins and indents, and half-points for font sizes. A twip is 1/20 pt, or 1/1440 inch, so `120` is 6 pt. This example puts 6 pt of space after each paragraph and 4 pt of padding into each table cell, at the top and bottom:

```ts
editor.commands.exportDocx({
  paragraphOverrides: { spacing: { after: 120 } },
  tableCellOverrides: { margins: { top: 80, bottom: 80 } },
})
```

Each override must be a plain object, because the command sends it as JSON. A function is left out with an `unsupported` warning that names the option. To give one node type its own output, write an export rule for that node, as [Custom nodes in Word files](/conversion/v3/docx/custom-nodes) explains.

## Header and footer formatting

The `headerFooterOverrides` option formats the content of headers and footers differently from the body. Headers and footers reach the file only with Page Layout, as [Word files with Page Layout](/conversion/v3/docx/page-layout) explains. The option takes the same six override fields:

```ts
editor.commands.exportDocx({
  paragraphOverrides: { spacing: { after: 120 } },
  headerFooterOverrides: {
    paragraphOverrides: { spacing: { after: 0 } },
    textRunOverrides: { size: 18 },
  },
})
```

A field you set replaces the body's field of the same name, and a field you leave out uses the body's. Here, header and footer paragraphs get no space after them and 9 pt text, while body paragraphs keep 6 pt after them.

A function in a field is left out with an `unsupported` warning.

## Describe styles with CSS

The `cssStyles` option describes styles with CSS properties for a fixed set of selectors, instead of Word's style objects. It is experimental, so its shape may change in a later version.

`cssStyles` doesn't need the measurement. Use it when the measurement can't run, such as for an editor that isn't mounted, or with `documentStyles: false`, and your styles exist as CSS. `styleOverrides` reaches more styles and properties, and wins over `cssStyles`. Property names may be camelCase or kebab-case:

```ts
editor.commands.exportDocx({
  cssStyles: {
    styles: {
      p: { color: 'red', fontSize: '16px' },
      h1: { fontFamily: 'Inter', 'font-size': '2rem' },
    },
  },
})
```

`cssStyles` takes these fields:

| Field                 | Default | What it does                                                                                                                                                                |
| --------------------- | ------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `styles`              | None    | The properties for each selector.                                                                                                                                           |
| `extractFromDocument` | `false` | Also reads the rules for these selectors under `.tiptap` from the page's stylesheets, as the exported function `extractTiptapCssStyles()` does. `styles` wins per property. |
| `baseFontSize`        | `16`    | The size in pixels that `rem` and `em` resolve against. It must be greater than 0.                                                                                          |

[SupportedSelector](/conversion/v3/docx/export-options/types#supportedselector) lists the selectors, such as `p`, `h1` to `h6` and `blockquote`. [CssPropertyMap](/conversion/v3/docx/export-options/types#csspropertymap) lists the properties, such as `color`, `font-size` and `margin-top`.

## Which setting wins

When several settings set the same style, a later one in this order wins:

1. The measured CSS.
2. `cssStyles`.
3. `styleOverrides`.

The six override options and `headerFooterOverrides` go on each element directly, not into a style, so they win over all three. A node's own attribute, such as a paragraph's text alignment, still wins over them.

`listLevels`, `pageColor` and `defaultTabStop` win over the measured CSS. They set list indents and markers, the page background and the distance between tab stops, as [Lists and task lists](/conversion/v3/docx/elements/lists), [Page color](/conversion/v3/docx/page-layout/sections#page-color) and [Paragraphs and alignment](/conversion/v3/docx/elements/paragraphs) describe.

## Embed fonts

Embed a font when the people who open the file may not have it, so Word still shows it. Pass the font files in `fonts`, and the command uploads them. In this example, the path and the family name stand for your font:

```ts
const data = await fetch('/fonts/inter-regular.ttf').then((response) => response.arrayBuffer())

editor.commands.exportDocx({
  fonts: [{ name: 'Inter', data }],
})
```

`name` must match the family name the document uses. `data` holds TTF, OTF or WOFF2 bytes, as a `Uint8Array` or an `ArrayBuffer`. A font has no field for a weight or a style, so pass the regular file. Word embeds it and synthesizes bold and italic from it.

To embed the fonts you don't pass in `fonts`, set `embedFonts: true`. It is `false` by default. Export then looks for each family in two places:

- **In the browser**, the command uploads the `@font-face` file of the families it finds in these places:
  - a `textStyle` mark in the document or its notes,
  - `cssStyles` and `textRunOverrides`,
  - the `document` style and your own styles of `styleOverrides`.
- **On Google Fonts**, the Conversion service looks up the families still missing, at most 20, including the editor's body font from the measured CSS.

The browser step skips generic families such as `serif`, and it uploads the regular file of a family. A family you pass in `fonts` isn't looked up, so your file wins.

A family found in neither place is not embedded, without a warning. The body font that your CSS sets is not on the browser list, so a self-hosted body font is embedded only when Google Fonts has it.

To embed it from your own file, pass it in `fonts`, or set it as the `font` of `default.document` in `styleOverrides`, as in [Set Word styles](#set-word-styles).

A font file that is unreadable, not TTF, OTF or WOFF2, over 25 MB or past the limit of 64 files is left out with a `font-fetch-failed` warning. Word then shows another font.

## Check what the command measures

When the file looks different from the editor, call `getDocumentCss()` to see the measured CSS the command sends:

```ts
import { getDocumentCss } from '@tiptap-pro/extension-export-docx'

const css = await getDocumentCss({ editor })
console.log(css.paragraph, css.headings[1])
```

`css.headings` holds the headings by level, so `headings[1]` is `h1`.

`getDocumentCss()` throws outside a browser, and when the editor is destroyed, not mounted or not laid out. Its options are in [CSS helpers](/conversion/v3/docx/export-options#css-helpers).

To change what export writes, set `styleOverrides` or the override options, or set `documentStyles: false`.
