The extension, its types, helpers and error classes come from `@tiptap-pro/extension-import-docx`.

Most editors set the token, an upload endpoint for images and the two callbacks. In this example, `CONVERSION_TOKEN` is your Conversion token, which [Get a Conversion token](/conversion/v3/getting-started/install#3-get-a-conversion-token) shows how to get:

```ts
import { ImportDocx } from '@tiptap-pro/extension-import-docx'

const importExtension = ImportDocx.configure({
  token: CONVERSION_TOKEN,
  imageUploadConfig: { url: 'https://example.com/upload' },
  onWarning: (warning) => console.warn(warning.code, warning.message),
  onError: (error) => console.error(error),
})
```

The options are grouped by where you pass them:

| Topic                                                                                       | Options                                                                                                                                                                                     |
| ------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [ImportDocx options](/conversion/v3/docx/import-options#importdocx-options)                 | `token`, `appId`, `endpoint`, `region`, `imageUploadConfig`, `prosemirrorNodes`, `prosemirrorMarks`, `cssStyles`, `trackedChanges`, `taskLists`, `behindTextImages`, `onError`, `onWarning` |
| [importDocx command options](/conversion/v3/docx/import-options#importdocx-command-options) | `file`, `onImport`, and the overrides `cssStyles`, `trackedChanges`, `taskLists`, `behindTextImages`, `onError`, `onWarning`                                                                |
| [ImportCssStylesOptions](/conversion/v3/docx/import-options#importcssstylesoptions)         | `enabled`, `autoInject`, `selector`                                                                                                                                                         |

## ImportDocx options

`ImportDocx.configure()` takes `ImportDocxOptions`. Only `token` is required.

[Connection options](/conversion/v3/getting-started/install#connection-options) explains `token`, `appId`, `region` and `endpoint`, which the import takes only from `ImportDocx.configure()`. [Region and endpoint](/conversion/v3/getting-started/install#region-and-endpoint) lists the URLs the import calls.

### token

`string` · Required

The Conversion token. Without it, the import fails before it sends a request.

### appId

`string` · Default none

Your app ID, sent in the `X-App-Id` header. Only for a token from [Legacy authentication](/authentication/legacy).

### endpoint

`string` · Default none

The base URL of your own Conversion service. It wins over `region`.

### region

`'eu' | 'us'` · Default `'eu'`

The Tiptap Cloud region, when you don't set `endpoint`.

### imageUploadConfig

`ImageUploadConfig` · Default none

Where the Conversion service uploads the images of the file. Without it, import skips every image. [Images in imported files](/conversion/v3/docx/import/images) shows the request your endpoint receives and the response it returns.

An `ImageUploadConfig` has these fields:

#### url

`string` · Required

The `http` or `https` address that receives each image.

#### headers

`Record<string, string>` · Default none

Headers the service adds to every upload. A plain object of strings, not a `Headers` instance.

#### method

`string` · Default `'POST'`

The HTTP method of the upload.

#### queryParams

`Record<string, string>` · Default none

Query parameters the service adds to `url`.

### prosemirrorNodes

`Record<string, string>` · Default none

Renames nodes. See [Custom nodes on import](/conversion/v3/docx/custom-nodes/import).

### prosemirrorMarks

`Record<string, string>` · Default none

Renames marks. See [Custom nodes on import](/conversion/v3/docx/custom-nodes/import).

### cssStyles

`ImportCssStylesOptions` · Default none

Extracts the Word styles as CSS. Off when unset. Its fields are under [ImportCssStylesOptions](/conversion/v3/docx/import-options#importcssstylesoptions). See [Word styles as CSS](/conversion/v3/docx/import/word-styles).

### trackedChanges

`'auto' | 'preserve' | 'accept' | 'reject'` · Default `'auto'`

What happens to tracked changes. See [Tracked changes](/conversion/v3/docx/elements/tracked-changes#import).

### taskLists

`'auto' | 'import' | 'ignore'` · Default `'auto'`

Whether checkbox lists become task lists. See [Checkbox lists](/conversion/v3/docx/import#checkbox-lists).

### behindTextImages

`'import' | 'ignore'` · Default none

`'import'` keeps images behind the text, such as watermarks. Unset, import skips them. See [Images behind the text](/conversion/v3/docx/import/images#images-behind-the-text).

### onError

`(error: unknown) => void` · Default none

Receives the error when an import fails.

### onWarning

`(warning: ImportDocxWarning) => void` · Default none

Receives every warning. Without it, warnings go to `console.warn`.

## importDocx command options

`editor.commands.importDocx()` takes `ImportDocxCommandOptions`. The command returns `true` right away and imports in the background, as [Import a file](/conversion/v3/docx/import#import-a-file) explains.

Each option except `file` and `onImport` overrides the configured option of the same name for this import. When you leave one out, the import uses the configured value:

- [`cssStyles`](/conversion/v3/docx/import-options#cssstyles) takes a `Partial<ImportCssStylesOptions>`, which the command merges over the configured `cssStyles`.
- [`trackedChanges`](/conversion/v3/docx/import-options#trackedchanges), [`taskLists`](/conversion/v3/docx/import-options#tasklists) and [`behindTextImages`](/conversion/v3/docx/import-options#behindtextimages) take the same values as in `ImportDocx.configure()`, and override the configured mode.
- [`onError`](/conversion/v3/docx/import-options#onerror) receives the error, and wins over the configured `onError`.
- [`onWarning`](/conversion/v3/docx/import-options#onwarning) receives every warning, and wins over the configured `onWarning`.

### file

`File` · Required

The `.docx` file to import.

### onImport

`((context: ImportContext) => void) | null` · Default none

Receives the document. Without it, the import writes the document when it arrives. See [The onImport context](/conversion/v3/docx/import/review#the-onimport-context).

## ImportCssStylesOptions

`cssStyles` takes an `ImportCssStylesOptions`. [Word styles as CSS](/conversion/v3/docx/import/word-styles) shows what the service extracts and the helpers that apply it.

### enabled

`boolean` · Required

Asks the Conversion service for the styles.

### autoInject

`boolean` · Default none

When `true`, adds the rules to a `<style>` tag in the document head.

### selector

`string` · Default `'.tiptap'`

The selector the rules sit under.

## Warnings and errors

`onWarning` receives an `ImportDocxWarning`, with a `code`, a `message` that is safe to log, and a `nodeType` or `markType` for the warnings of the editor. `onError` receives an `ImportDocxRequestError`, an `ImportDocxSupersededError`, an `ImageUploadConfigValidationError` or an `Error`. [Warnings](/conversion/v3/reference/warnings) lists every code, and [Errors](/conversion/v3/reference/errors) says when each error happens.
