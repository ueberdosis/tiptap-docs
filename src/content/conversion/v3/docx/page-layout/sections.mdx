Section columns flow a section's text through several columns side by side, as Word's Layout > Columns does. Each section keeps its own headers and footers, as [Headers and footers](/conversion/v3/docx/page-layout/headers-and-footers) shows.

## Import sections

Import puts a `sectionBreak` node in front of each section, the first at the very start of the document. Each one holds its section's setup in these attributes, with lengths in pixels:

| Setting              | Attributes                                                                                                |
| -------------------- | --------------------------------------------------------------------------------------------------------- |
| Paper size           | `formatId`, `pageWidth`, `pageHeight`                                                                     |
| Orientation          | `orientation`                                                                                             |
| Margins              | `marginTop`, `marginRight`, `marginBottom`, `marginLeft`                                                  |
| Section break kind   | `kind`: `nextPage` or `continuous`                                                                        |
| Section columns      | `columnCount`, `columnGaps`, `columnWidths`, `columnRule` for the line between columns                    |
| Page numbering       | `pageNumbering`, an object with `format`, `start` and `chapter`                                           |
| Different first page | `differentFirstPage`                                                                                      |
| Note placement       | `notePlacement`: `bottomOfPage` or `belowText`                                                            |
| Note numbering       | `footnoteNumbering` and `endnoteNumbering`, each `null` or an object with `format`, `start` and `restart` |
| Page color           | `themePage`, a hex color such as `#fff8e8`, on the first section only                                     |
| Header and footer    | See [Headers and footers](/conversion/v3/docx/page-layout/headers-and-footers)                            |

`formatId` is the id of a Page Layout paper size, such as `A4` or `Letter`, when the Word paper matches one. Other paper gets an id of its own. A `null` note numbering means Page Layout's default: `1, 2, 3` for footnotes and `i, ii, iii` for endnotes.

`columnGaps` holds the space after each column but the last, in pixels. `columnWidths` holds one share of the text width for each column, such as `[0.6, 0.4]`, so the widths follow the paper size.

A section's columns are settings on its `sectionBreak`. Its blocks aren't wrapped in column nodes, and Page Layout flows them through the columns, as [Section columns](/features/page-layout/section-columns) explains.

`pageNumbering.format` is the number format, such as `decimal` or `lowerRoman`. `start` is the first page number, or `null` to continue from the section before.

`pageNumbering.chapter` is Word's "Include chapter number", which puts the number of the current chapter heading before the page number, such as `2-5` for page 5 of chapter 2. It is `null`, or an object with the heading `level` that starts a chapter and the `separator` between the two numbers: `hyphen`, `period`, `colon`, `emDash` or `enDash`.

A Word file that sets no section properties, so no paper or margins, imports as one US Letter section with 1-inch margins. An "at least" top or bottom margin imports as a fixed margin of the same size.

Some settings change to ones Page Layout has, each with a warning:

- A section that starts on an even or odd page starts on the next page, with `section-start-even-odd`.
- The binding gutter of the margins is left out, with `gutter-dropped`.
- A section break inside a table is ignored, with `section-in-table-cell`, because Word doesn't end a section there.

Two more settings change without a warning, which is a known limit that is being fixed:

- A section that starts in the next column starts on the next page.
- A custom Word number format, such as `001`, imports as the default for its kind: decimal for pages and footnotes, lowercase Roman for endnotes.

## Export sections

Export writes the settings of the [Import sections](#import-sections) table back, with two exceptions. The note settings don't export, and the page color follows the rules in [Page color](#page-color).

Export writes the paper size from `pageWidth` and `pageHeight`, so it doesn't need `formatId`. The chapter number exports with its `separator`. A `nextPage` section starts a new page. A `continuous` one stays on the sheet and takes the paper of the section before it, because paper can't change halfway down a sheet.

Page numbers use the section's number format, such as `decimal` or `lowerRoman`. A format without an exact Word match is written as the closest one, with an `unsupported` warning.

To export on other paper than the sections hold, see [Export on other paper](/conversion/v3/docx/page-layout#export-on-other-paper).

## Page color

Word has one page color for the whole document. Import puts it on the first section as `themePage` when Word stores a hex color. A page color of `auto`, or a theme color without a hex value, gives none.

Export writes the `themePage` of the first section, such as one from an import. To set the color yourself, pass `pageColor` to the command of an editor set up as in [Export DOCX](/conversion/v3/docx/export). `pageColor` wins over `themePage`:

```ts
editor.commands.exportDocx({ pageColor: '#fff8e8' })
```

Export drops a different page color on a later section, with an `unsupported` warning. It also drops the text and accent colors Page Layout can give a section, `themeText` and `themeAccent`, with one `unsupported` warning for each kind. Word prints the page color only with its print background setting on.

## Page breaks and column breaks

A page break the user inserted in Word imports as a `pageBreak` node and exports back as a Word page break. A column break converts the same way, as a `columnBreak` node. Page Layout has both as inline nodes, with the `insertPageBreak()` and `insertColumnBreak()` commands, as [Breaks](/features/page-layout/breaks) shows.

Import keeps a page break inside its paragraph, where Word has it:

```json
{
  "type": "paragraph",
  "content": [{ "type": "text", "text": "End of part one" }, { "type": "pageBreak" }]
}
```

A paragraph set to start on a new page, directly or by its style, gets a `pageBreak` at its start. A page break in a table cell stays in the cell's paragraph.

Import doesn't read the soft page breaks Word saves from its last layout, because they are Word's layout, not content.

On export, a `pageBreak` inside a paragraph writes the break at that place. A `pageBreak` between blocks exports as a paragraph with a Word page break. A `columnBreak` exports as a Word column break.

In an editor without Page Layout, see [Page breaks without Page Layout](/conversion/v3/docx/page-layout#page-breaks-without-page-layout).
