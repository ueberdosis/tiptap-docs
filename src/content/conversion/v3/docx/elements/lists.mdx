Bullet lists, ordered lists and Word's checkbox lists convert in both directions, with their nesting. A checkbox list imports as a task list with the ticked state kept, and a task item exports as a Word checkbox the user can tick in Word. Export can also write numbering formats you define, such as `1)` then `a)`.

## What you need

`StarterKit` has the nodes for bullet and ordered lists. Task lists and numbering formats need more:

| Element                        | Extension                                                    | Node or attribute                       |
| ------------------------------ | ------------------------------------------------------------ | --------------------------------------- |
| Bullet lists and ordered lists | `BulletList`, `OrderedList` and `ListItem` from `StarterKit` | `bulletList`, `orderedList`, `listItem` |
| Task lists                     | `TaskList` and `TaskItem` from `@tiptap/extension-list`      | `taskList`, `taskItem`                  |
| Numbering formats              | An extension of your own                                     | `numberingFormat` on the list           |

`StarterKit` is enough for nested lists with plain numbering. For task lists, set `nested: true` on `TaskItem`, so a task item can hold a nested checkbox list:

```ts
import StarterKit from '@tiptap/starter-kit'
import { TaskItem, TaskList } from '@tiptap/extension-list'

const extensions = [StarterKit, TaskList, TaskItem.configure({ nested: true })]
```

With the default `nested: false`, a task item holds only paragraphs. Import then puts the items of a nested checkbox list into their parent item as plain paragraphs, without checkboxes, with a `restructured` warning. `onWarning`, an option of `ImportDocx.configure()`, receives it, as [Warnings and errors](/conversion/v3/reference/warnings-and-errors) shows.

An editor without the list nodes, or without `TaskList` and `TaskItem`, keeps those lists as preserved content, ticked states included, with a `preserved` warning that names the `nodeType`. They become lists and task lists once you add the extensions, as [Content the editor cannot show](/conversion/v3/docx/preserved-content) explains.

[Numbering formats](#numbering-formats) adds the `numberingFormat` attribute.

## Import

Import turns Word's numbered paragraphs into lists, and its checkbox lists into task lists.

### Bullet and ordered lists

Import turns paragraphs that share a Word numbering into one list, and the level of each paragraph sets its nesting. A Word file can store two parts of a list as two numberings that continue one count. Import keeps them as one list, and empty paragraphs between its items don't split it either.

The kind of list follows the marker:

- A bullet, no marker or an empty marker gives a `bulletList`.
- Any other marker, such as numbers, letters or Roman numerals, gives an `orderedList`.

The outermost list gets these attributes:

| Attribute         | Value                                                             |
| ----------------- | ----------------------------------------------------------------- |
| `numberingFormat` | The id of the list's numbering format, such as `docx-num-1x7k2qd` |
| `start`           | The first number of the first level. Left out when it is `1`.     |
| `type`            | `a`, `A`, `i` or `I` for letters and Roman numerals               |

`OrderedList` defines `start` and `type`, so the editor shows the first number and letter or Roman lists as Word does.

Bullet lists and ordered lists both get `numberingFormat`. No Tiptap extension defines it, so import keeps it in the list's `preservedAttrs` attribute, which holds the attributes the editor's extensions don't define. Export uses the id to pick a numbering format you pass, as [Numbering formats](#numbering-formats) shows.

### Task lists

The `taskLists` option decides what a checkbox list becomes. Set it on `ImportDocx.configure()`, or on one `importDocx` call, which wins. In this example, `CONVERSION_TOKEN` stands for your Conversion token, `editor` for your editor and `file` for the `.docx` file the user picked:

```ts
import { ImportDocx } from '@tiptap-pro/extension-import-docx'

const importExtension = ImportDocx.configure({
  token: CONVERSION_TOKEN,
  taskLists: 'ignore',
})

editor.commands.importDocx({ file, taskLists: 'import' })
```

The option takes these values:

| Value                  | Result                                                 |
| ---------------------- | ------------------------------------------------------ |
| `'auto'` or `'import'` | Task lists. `'auto'` is the default.                   |
| `'ignore'`             | Bullet or numbered lists, with the markers Word draws. |

`'auto'` and `'import'` do the same, also in an editor without the two nodes. There, the task lists are kept as preserved content, as [What you need](#what-you-need) says.

### Which checkboxes convert

Word writes a checkbox in three ways, and import reads all of them:

- **A box character as the list marker.** These are the Wingdings boxes and the Unicode ballot boxes `U+2610` for unticked, and `U+2611` and `U+2612` for ticked. The ticked state comes from the character.
- **A checkbox content control**, which current versions of Word insert. The ticked state comes from the control.
- **A legacy form-field checkbox.** The ticked state comes from the field, or from its default when it has no current value.

A content control or form field converts only when it is the only checkbox in the paragraph and comes before the text. So a row such as `Yes ☐ No ☐`, or a box after a sentence, imports as text.

A checkbox in a paragraph without list numbering also imports as text. A paragraph with a hanging indent is the exception: the indent puts the box where a list marker sits, so the paragraph becomes a task item.

Checkmark characters, such as the Wingdings `✔`, don't convert, because Word uses them as decoration. They stay as text.

A numbered list item that starts with a single checkbox becomes a task item, and loses its number. To keep the numbers, import with `taskLists: 'ignore'`.

### Numbered headings

A numbered heading from Word, which is a heading style linked to Word's numbering, imports as a list item. When the list item has to start with a paragraph, as the `ListItem` of `StarterKit` does, the heading becomes that paragraph, with a `restructured` warning. Its text is kept, but it is no longer a heading.

## Export

Export writes each list as a Word list with its nesting, and each task item as a Word checkbox.

### Bullet and ordered lists

Word has nine list levels, so a list nested deeper exports on the ninth level.

Each ordered list numbers on its own, so two lists in one document don't continue each other. To continue the count by hand, set `start` on the second list, because a list without a numbering format numbers from its `start` in Word's default style.

### Numbering formats

A numbering format sets the marker of each list level. A list uses one when its `numberingFormat` attribute matches the format's `id`. No Tiptap extension defines `numberingFormat`, so add it with an extension of your own:

```ts
import { Extension } from '@tiptap/core'

const ListNumberingFormat = Extension.create({
  name: 'listNumberingFormat',
  addGlobalAttributes() {
    return [
      {
        types: ['orderedList', 'bulletList'],
        attributes: { numberingFormat: { default: null } },
      },
    ]
  },
})
```

Then set the attribute on a list, and pass the format in the `numberingFormats` option of `ExportDocx.configure()` or of the `exportDocx` command. In the examples on this page, `editor` is an editor with `ExportDocx` and the extension above, as [Export DOCX](/conversion/v3/docx/export) sets it up:

```ts
editor.commands.updateAttributes('orderedList', { numberingFormat: 'report' })

editor.commands.exportDocx({
  numberingFormats: [
    {
      id: 'report',
      levels: [
        { baseStyle: 'decimal', textTemplate: '%1)' },
        { baseStyle: 'lowerLetter', textTemplate: '%2)' },
      ],
    },
  ],
})
```

Export reads the attribute only on the outermost list. `updateAttributes` sets it on the ordered list around the cursor, so put the cursor in a top-level item. In stored JSON, set it in the list's `attrs`, such as `{ "type": "orderedList", "attrs": { "numberingFormat": "report" } }`.

In `textTemplate`, `%1` to `%9` stand for the counter of that level. `baseStyle` is Word's counter format, such as `decimal`, `lowerLetter`, `lowerRoman` or `bullet`. A list deeper than the levels you define reuses them in order. [Export types](/conversion/v3/docx/export-options/types#numberingleveldefinition-and-numberingformatdefinition) lists every field of a level, such as `startAt` and `markerFont`.

Formats you pass to the `exportDocx` command replace all formats from `ExportDocx.configure()`, instead of adding to them. The Conversion service, the server that builds the file, leaves out a format the Word file can't hold, and its lists get Word's default numbering. `onWarning` then receives a `numbering-format-invalid` warning, whose `formatId` names the format.

An imported list exports with its `numberingFormat` id, but import doesn't return the format behind it, as [Limits](#limits) says. So the list gets Word's default numbering from its `start`. To give it a format, set its `numberingFormat` to the `id` of a format you pass.

### List indents

Export measures where your editor draws each list level. To set the positions yourself, pass `listLevels`, with one entry per level for `bullet`, `ordered` and `task` lists:

```ts
editor.commands.exportDocx({
  listLevels: {
    ordered: [
      { numberIndent: 360, textIndent: 720 },
      { numberIndent: '0.5in', textIndent: '1in' },
    ],
  },
})
```

`numberIndent` places the marker, `textIndent` the text and `rightIndent` the right edge, measured from the left margin. A plain number here is twips, a twentieth of a point, not pixels as in the [paragraph attributes](/conversion/v3/docx/elements/paragraphs#paragraph-and-heading-attributes). A string with a unit, such as `'0.5in'`, also works.

Your entries repeat in order for deeper levels, and a field you leave out keeps the measured value. An entry can also set the marker, with `text`, `markerFont` and `format`, as [ListLevelGeometry](/conversion/v3/docx/export-options/types#listlevelgeometry) shows.

### Task lists

A task item exports as a Word checkbox control followed by its text. The user can tick and untick it in Word, and it shows the state you exported.

The items use Word's List Paragraph style with a hanging indent, and a nested task list gets a deeper indent. When an item holds several blocks, the checkbox goes on the first block, and the other blocks line up under its text.

Export writes every checkbox as a control, so a file that arrived with box-character markers leaves with controls. Both kinds import again as task lists.

### Outline numbering

Numbered headings, such as `1`, `1.1` and `1.1.1`, arrive in Word without their numbers when the [Outline Numbering](/features/outline-numbering) extension numbers them. The extension draws the numbers and doesn't store them on the headings, and export doesn't write them.

To number headings in Word, pass a numbering format whose levels have `linkedStyle`, the id of a Word paragraph style such as `Heading1`. Word then numbers every paragraph in that style at that level, so each `heading` of level 1 gets the first level's number. All lists in that format share the same count.

This example numbers Heading 1 and Heading 2 as `1.` and `1.1`:

```ts
editor.commands.exportDocx({
  numberingFormats: [
    {
      id: 'headings',
      levels: [
        { baseStyle: 'decimal', textTemplate: '%1.', linkedStyle: 'Heading1' },
        { baseStyle: 'decimal', textTemplate: '%1.%2', linkedStyle: 'Heading2' },
      ],
    },
  ],
})
```

A style can link to one level of one format only. When such a file is imported again, its headings are numbered headings, which become list items, as [Numbered headings](#numbered-headings) says.

## Limits

Export doesn't read `type`, so a letter or Roman list without a numbering format exports with numbers.

Import doesn't return the definitions of the file's numbering formats, so imported lists show default numbering, apart from `start` and `type`. There is no warning. This is a known limit that is being fixed.

Headings numbered by the Outline Numbering extension export without their numbers. A numbering format with `linkedStyle` numbers them in Word instead, as [Outline numbering](#outline-numbering) shows.
