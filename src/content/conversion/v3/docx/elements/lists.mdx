Bullet lists, ordered lists and Word's checkbox lists convert in both directions, with their nesting. A checkbox list imports as a task list with its ticked states, and a task item exports as a Word checkbox the user can tick.

Export can also write numbering formats you define, such as `1)` then `a)`.

## What you need

`StarterKit` has the nodes for bullet and ordered lists. Task lists and numbering formats need more:

| Element                        | Extension                                                    | Node or attribute                       |
| ------------------------------ | ------------------------------------------------------------ | --------------------------------------- |
| Bullet lists and ordered lists | `BulletList`, `OrderedList` and `ListItem` from `StarterKit` | `bulletList`, `orderedList`, `listItem` |
| Task lists                     | `TaskList` and `TaskItem` from `@tiptap/extension-list`      | `taskList`, `taskItem`                  |
| Numbering formats              | [An extension of your own](#numbering-formats)               | `numberingFormat` on the list           |

`StarterKit` is enough for nested lists with plain numbering. For task lists, set `nested: true` on `TaskItem`, so a task item can hold a nested checkbox list:

```ts
import StarterKit from '@tiptap/starter-kit'
import { TaskItem, TaskList } from '@tiptap/extension-list'

const extensions = [StarterKit, TaskList, TaskItem.configure({ nested: true })]
```

With the default `nested: false`, a task item holds only paragraphs. Import then puts the items of a nested checkbox list into their parent item as plain paragraphs without checkboxes. The `onWarning` option of `ImportDocx.configure()` receives a [`restructured` warning](/conversion/v3/reference/warnings) for it.

Without the list nodes, or without `TaskList` and `TaskItem`, import keeps those lists as [preserved content](/conversion/v3/docx/preserved-content), ticked states included, with a `preserved` warning that names the `nodeType`. They become lists and task lists once you add the extensions.

## Import

Import turns Word's numbered paragraphs into lists, and its checkbox lists into task lists.

### Bullet and ordered lists

Paragraphs that share a Word numbering become one list, and each paragraph's level sets its nesting. Two numberings that continue one count also stay one list, and empty paragraphs between items don't split it.

A bullet, no marker or an empty marker gives a `bulletList`. Any other marker, such as numbers, letters or Roman numerals, gives an `orderedList`.

The outermost list gets these attributes:

| Attribute         | Value                                                             |
| ----------------- | ----------------------------------------------------------------- |
| `numberingFormat` | The id of the list's numbering format, such as `docx-num-1x7k2qd` |
| `start`           | The first number of the first level. Left out when it is `1`.     |
| `type`            | `a`, `A`, `i` or `I` for letters and Roman numerals               |

`OrderedList` defines `start` and `type`, so the editor shows the first number and letter or Roman lists as Word does.

Bullet and ordered lists both get `numberingFormat`. No Tiptap extension defines it, so import keeps it in the list's `preservedAttrs`, which holds the attributes no extension in the editor defines. Export uses the id to pick a [numbering format](#numbering-formats) you pass.

### Task lists

The `taskLists` option decides what a checkbox list becomes. Set it on `ImportDocx.configure()` or on one `importDocx` call, which wins. In this example, `CONVERSION_TOKEN` stands for your Conversion token, `editor` for your editor and `file` for the `.docx` file the user picked:

```ts
import { ImportDocx } from '@tiptap-pro/extension-import-docx'

const importExtension = ImportDocx.configure({
  token: CONVERSION_TOKEN,
  taskLists: 'ignore',
})

editor.commands.importDocx({ file, taskLists: 'import' })
```

The option takes these values:

| Value                  | Result                                                 |
| ---------------------- | ------------------------------------------------------ |
| `'auto'` or `'import'` | Task lists. `'auto'` is the default.                   |
| `'ignore'`             | Bullet or numbered lists, with the markers Word draws. |

`'auto'` and `'import'` do the same, also in an editor without the two nodes, which keeps the task lists as [preserved content](#what-you-need).

### Which checkboxes convert

Import reads each way Word writes a checkbox:

- **A box character as the list marker**: a Wingdings box, or the Unicode ballot box `U+2610` unticked, `U+2611` or `U+2612` ticked. The character sets the ticked state.
- **A checkbox content control**, the kind Word inserts. The control sets the ticked state.
- **A legacy form-field checkbox.** The field sets the ticked state, or its default when it has no current value.

A content control or form field converts only when it is the only checkbox in the paragraph and comes before the text. So a row such as `Yes ☐ No ☐`, or a box after a sentence, imports as text.

A checkbox in a paragraph without list numbering also imports as text, unless the paragraph has a hanging indent. The indent puts the box where a list marker sits, so the paragraph becomes a task item.

Checkmark characters, such as the Wingdings `✔`, stay text, because Word uses them as decoration.

A numbered list item that starts with a single checkbox becomes a task item, and loses its number. To keep the numbers, import with `taskLists: 'ignore'`.

### Numbered headings

A numbered heading from Word, a heading style linked to Word's numbering, imports as a list item.

When the list item must start with a paragraph, as the `ListItem` of `StarterKit` does, the heading becomes that paragraph, with a `restructured` warning. It keeps its text but is no longer a heading.

## Export

Export writes each list as a Word list with its nesting, and each task item as a Word checkbox.

### Bullet and ordered lists

Word has nine list levels, so a list nested deeper exports on the ninth level.

Each ordered list numbers on its own, so two lists don't continue each other. To continue the count, set `start` on the second list. A list without a numbering format numbers from its `start` in Word's default style.

### Numbering formats

A numbering format sets the marker of each list level. A list uses the format whose `id` matches its `numberingFormat` attribute. No Tiptap extension defines `numberingFormat`, so add it with an extension of your own:

```ts
import { Extension } from '@tiptap/core'

const ListNumberingFormat = Extension.create({
  name: 'listNumberingFormat',
  addGlobalAttributes() {
    return [
      {
        types: ['orderedList', 'bulletList'],
        attributes: { numberingFormat: { default: null } },
      },
    ]
  },
})
```

Then set the attribute on a list, and pass the format in the `numberingFormats` option of `ExportDocx.configure()` or of the `exportDocx` command. The examples on this page need an editor with `ListNumberingFormat` and with `ExportDocx`, as [Export DOCX](/conversion/v3/docx/export) sets it up:

```ts
editor.commands.updateAttributes('orderedList', { numberingFormat: 'report' })

editor.commands.exportDocx({
  numberingFormats: [
    {
      id: 'report',
      levels: [
        { baseStyle: 'decimal', textTemplate: '%1)' },
        { baseStyle: 'lowerLetter', textTemplate: '%2)' },
      ],
    },
  ],
})
```

Export reads the attribute only on the outermost list, and `updateAttributes` sets it on the ordered list around the cursor. So put the cursor in a top-level item. In stored JSON, it goes in the list's `attrs`: `{ "type": "orderedList", "attrs": { "numberingFormat": "report" } }`.

In `textTemplate`, `%1` to `%9` stand for the counter of that level. `baseStyle` is Word's counter format, such as `decimal`, `lowerLetter`, `lowerRoman` or `bullet`. A list deeper than the levels you define reuses them in order. [Export types](/conversion/v3/docx/export-options/types#numberingleveldefinition-and-numberingformatdefinition) lists every field of a level, such as `startAt` and `markerFont`.

Formats you pass to the `exportDocx` command replace all formats from `ExportDocx.configure()`.

The Conversion service, the server that builds the file, leaves out a format the Word file can't hold, and its lists get Word's default numbering. `onWarning` then receives a `numbering-format-invalid` warning whose `formatId` names the format.

An imported list exports with its `numberingFormat` id, but import doesn't return the format behind it, as [Limits](#limits) says. So the list gets Word's default numbering from its `start`. To give it a format, set its `numberingFormat` to the `id` of a format you pass.

### List indents

Export measures where your editor draws each list level. To set the positions yourself, pass `listLevels`, with one entry per level for `bullet`, `ordered` and `task` lists:

```ts
editor.commands.exportDocx({
  listLevels: {
    ordered: [
      { numberIndent: 360, textIndent: 720 },
      { numberIndent: '0.5in', textIndent: '1in' },
    ],
  },
})
```

`numberIndent` places the marker, `textIndent` the text and `rightIndent` the right edge, measured from the left margin. A plain number here is twips, a twentieth of a point, not pixels as in the [paragraph attributes](/conversion/v3/docx/elements/paragraphs#paragraph-and-heading-attributes). A string with a unit, such as `'0.5in'`, also works.

Your entries repeat in order for deeper levels, and a field you leave out keeps the measured value. An entry can also set the marker, with `text`, `markerFont` and `format`, as [ListLevelGeometry](/conversion/v3/docx/export-options/types#listlevelgeometry) shows.

### Task lists

A task item exports as a Word checkbox control in its exported state, followed by its text. The user can tick and untick it in Word.

The items use Word's List Paragraph style with a hanging indent, and a nested task list gets a deeper indent. When an item holds several blocks, the checkbox goes on the first block, and the other blocks line up under its text.

Export writes every checkbox as a control, so a file that arrived with box-character markers leaves with controls. Both kinds import again as task lists.

### Outline numbering

Headings numbered by the [Outline Numbering](/features/outline-numbering) extension, such as `1`, `1.1` and `1.1.1`, arrive in Word without their numbers. The extension draws the numbers without storing them, so export doesn't write them.

To number headings in Word, pass a numbering format whose levels have `linkedStyle`, the id of a Word paragraph style such as `Heading1`.

Word then numbers every paragraph in that style at that level, so each `heading` of level 1 gets the first level's number. All lists in that format share one count.

This example numbers Heading 1 and Heading 2 as `1.` and `1.1`:

```ts
editor.commands.exportDocx({
  numberingFormats: [
    {
      id: 'headings',
      levels: [
        { baseStyle: 'decimal', textTemplate: '%1.', linkedStyle: 'Heading1' },
        { baseStyle: 'decimal', textTemplate: '%1.%2', linkedStyle: 'Heading2' },
      ],
    },
  ],
})
```

A style can link to one level of one format only. When such a file is imported again, its headings become list items, as [Numbered headings](#numbered-headings) says.

## Limits

Export doesn't read `type`, so a letter or Roman list without a numbering format exports with numbers.

Import doesn't return the definitions of the file's numbering formats, so imported lists show default numbering, apart from `start` and `type`, without a warning. This is a known limit that is being fixed.

Headings numbered by the Outline Numbering extension export without their numbers, unless a numbering format with `linkedStyle` [numbers them in Word](#outline-numbering).
