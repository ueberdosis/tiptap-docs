## What you need

`StarterKit` from `@tiptap/starter-kit` has the heading node. The formatting a Word style sets reaches the text as marks:

| Element                         | Extension                                                                                    | Node, mark or attribute |
| ------------------------------- | -------------------------------------------------------------------------------------------- | ----------------------- |
| Headings of levels 1 to 6       | `Heading` from `StarterKit`                                                                  | `heading` with `level`  |
| Font, size and color of a style | The text style extensions on [Text formatting](/conversion/v3/docx/elements/text-formatting) | The `textStyle` mark    |

The alignment and line spacing of a heading need `TextAlign` and `LineHeight`, as [What you need](/conversion/v3/docx/elements/paragraphs#what-you-need) on Paragraphs and alignment shows.

Without the `heading` node or the `textStyle` mark, import keeps that content as preserved content, as [Content the editor cannot show](/conversion/v3/docx/preserved-content) explains.

## Import

Import chooses each paragraph's node type from its Word style, then sets the paragraph's formatting as attributes on the node and as marks on its text.

### Node types from Word styles

A Word style is a named set of formatting, such as Normal or Heading 1. Import chooses the node type from the name of a paragraph's style, whatever its capitalization:

| Word style             | Node         |
| ---------------------- | ------------ |
| `Heading` and a number | `heading`    |
| `Quote`                | `blockquote` |
| Any other style        | `paragraph`  |

A style you map to a node type with `prosemirrorNodes`, an option of `ImportDocx.configure()`, comes first, as [Map a Word style to a node](/conversion/v3/docx/custom-nodes/import#map-a-word-style-to-a-node) shows. A paragraph without a style counts as Normal.

Import decides by the style's own name and keeps no style names. So a paragraph in the style Title, Subtitle or any other style imports as a `paragraph`, also a custom style based on Heading 1. To import such a style as a heading, rename it to Heading 1 to Heading 6 in Word, or map it with `prosemirrorNodes`.

A style can be based on another style. Import follows that chain and merges the formatting of each style in it, then the document defaults. Formatting set on the paragraph itself wins.

When a run, a stretch of text with the same formatting, doesn't set its font, size, bold, italic or color, the style's value reaches the text as a mark. Spacing and indentation reach the paragraph as attributes, as [Spacing, indents and line spacing](/conversion/v3/docx/elements/paragraphs#spacing-indents-and-line-spacing) lists.

[Text formatting](/conversion/v3/docx/elements/text-formatting) shows the marks, and its [Character styles](/conversion/v3/docx/elements/text-formatting#character-styles) section says what import does with a run's own style, such as Strong.

### Headings

A paragraph becomes a heading when its style name is `Heading` followed by a number, such as `Heading 2`. The match ignores case and the space, so `heading2` matches too. The bold of the heading style arrives as a `bold` mark, and its font, size and color on a `textStyle` mark:

```json
{
  "type": "heading",
  "attrs": { "level": 2, "textAlign": "center" },
  "content": [
    {
      "type": "text",
      "text": "My heading",
      "marks": [
        { "type": "bold" },
        {
          "type": "textStyle",
          "attrs": { "fontFamily": "Arial", "fontSize": "19px", "color": "#2E74B5" }
        }
      ]
    }
  ]
}
```

Heading 7 to Heading 9 keep their number, so Heading 7 imports with `level: 7`. `StarterKit` draws such a heading as `<h1>`, as [Limits](#limits) says.

To lower the level, change it in `onImport`, the callback of the `importDocx()` command that receives the converted document. This example does it for the headings at the top level of the document, with `file` as a `.docx` file the user picked:

```ts
editor.commands.importDocx({
  file,
  onImport: (context) => {
    if (context.error) return
    context.content.content?.forEach((node) => {
      if (node.type === 'heading' && node.attrs && node.attrs.level > 6) node.attrs.level = 6
    })
    context.setEditorContent()
  },
})
```

A numbered heading, which is a heading style linked to Word's numbering, imports as a list item, as [Lists and task lists](/conversion/v3/docx/elements/lists#numbered-headings) describes.

### Word styles as CSS

To make your editor's paragraphs and headings look like the file's, turn on the experimental `cssStyles` option of `ImportDocx.configure()`, which is off by default. In this example, `CONVERSION_TOKEN` stands for your Conversion token:

```ts
import { ImportDocx } from '@tiptap-pro/extension-import-docx'

ImportDocx.configure({
  token: CONVERSION_TOKEN,
  cssStyles: { enabled: true, autoInject: true },
})
```

The option takes these keys:

| Key          | What it does                                                                                      |
| ------------ | ------------------------------------------------------------------------------------------------- |
| `enabled`    | `true` passes the file's styles to `onImport` as `context.cssStyles`. Without it, that is `null`. |
| `autoInject` | `true` adds the styles to the page as a `<style>` element when `setEditorContent()` runs.         |
| `selector`   | The selector every rule is scoped by. The default is `.tiptap`.                                   |

`context.cssStyles` maps each selector, such as `h1`, to its CSS properties in camelCase, such as `fontFamily` and `lineHeight`. The rules cover `p`, `h1` to `h6`, `blockquote`, `a`, `code`, `ul li`, `ol li`, `strong`, `em`, `u` and `s`.

Without `autoInject`, turn them into CSS yourself with `buildCssRules()` from `@tiptap-pro/extension-import-docx`, for example to give each of several editors its own stylesheet. This call, with `file` as a `.docx` file the user picked, scopes the rules to `.report-editor`:

```ts
import { buildCssRules } from '@tiptap-pro/extension-import-docx'

editor.commands.importDocx({
  file,
  cssStyles: { enabled: true, autoInject: false },
  onImport(context) {
    if (context.error) return
    if (context.cssStyles) {
      const style = document.createElement('style')
      style.textContent = buildCssRules(context.cssStyles, '.report-editor')
      document.head.appendChild(style)
    }
    context.setEditorContent()
  },
})
```

[Word styles as CSS](/conversion/v3/docx/import/word-styles) on Import DOCX has the details.

## Export

Export writes each node as a Word paragraph in a fixed Word style, with the attributes of the node. A heading with `level` 1 to 6 becomes a paragraph in the Word style Heading 1 to Heading 6, with its alignment and inline formatting.

### Word styles from your editor's CSS

Each node type and mark writes a fixed Word style:

| In the editor               | Word style                |
| --------------------------- | ------------------------- |
| `paragraph`                 | Normal                    |
| `heading`, levels 1 to 6    | Heading 1 to Heading 6    |
| Paragraph in a `blockquote` | Quote                     |
| List item paragraph         | List Paragraph            |
| `codeBlock`                 | Code Block                |
| `horizontalRule`            | Horizontal Rule           |
| `code` mark                 | Code character style      |
| `link` mark                 | Hyperlink character style |

Export doesn't write back a style from the imported file. A paragraph imported from a Legal Disclaimer style exports as Normal.

Export writes your editor's look into these Word styles: the font, size, color and spacing the browser shows for each element of the editor on the page. So a paragraph without attributes of its own looks in Word as the user sees it.

The styles of `h1` to `h6` go into the Word heading styles. A heading whose text has no `textStyle` mark looks like your editor in Word. An imported heading keeps the font, size and color of its marks, so it still looks like the file.

An editor that isn't on the page has nothing to show, such as a headless editor on a server, or one not yet mounted in the page. Export then uses its own defaults:

- Normal starts as Arial 11pt with 10pt after each paragraph and a line height of 1.15.
- Heading 1 to Heading 5 start as bold Arial in the color `2E74B5`, at 16, 14, 13, 12 and 11pt.

To use these defaults in a mounted editor too, set the `documentStyles` option of `ExportDocx.configure()` or `exportDocx()` to `false`. [Export styles and fonts](/conversion/v3/docx/export-styles) lists the defaults and shows how to set fixed values or change a style with `styleOverrides`.

Export has a `cssStyles` option of its own, which sets Word styles from CSS properties you write. It is a different option from the import's `cssStyles`, as [Describe styles with CSS](/conversion/v3/docx/export-styles#describe-styles-with-css) shows.

So the file's look survives a round trip when the import uses `autoInject: true`. The file's styles then apply to the mounted editor, and export writes them back into these Word styles. The style names of the file are still lost.

## Limits

Styles and headings have these limits:

- Import keeps no style names, so a custom style exports as Normal.
- Only a style named `Heading` and a number, or `Quote`, changes the node type, unless you map a style with `prosemirrorNodes`.
- The `Heading` node of `StarterKit` allows levels 1 to 6. It draws any other level, such as an imported `level: 7`, as `<h1>`, unless you lower it on import as [Headings](#headings) shows. A heading with `level` 7 to 9 exports as a normal paragraph.
