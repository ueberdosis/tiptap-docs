## 1. Set up the registry

The two packages are Tiptap Pro packages, so npm installs them from Tiptap's private registry. Point your project at the registry once, in an `.npmrc` file:

```ini
@tiptap-pro:registry=https://registry.tiptap.dev/
//registry.tiptap.dev/:_authToken=${TIPTAP_PRO_TOKEN}
```

`TIPTAP_PRO_TOKEN` is an environment variable that holds your registry token, and npm reads it from the environment when it installs. [How to integrate Tiptap Pro extensions](/guides/pro-extensions) says where to get it. Keep the token out of source control, and set `TIPTAP_PRO_TOKEN` in your CI environment too.

## 2. Install the packages

Install Export DOCX to save Word files and Import DOCX to open them. This command installs both:

```bash
npm install @tiptap-pro/extension-export-docx @tiptap-pro/extension-import-docx
```

The complete example in step 4 also needs Tiptap itself. An existing Tiptap editor already has it, and a new project installs it:

```bash
npm install @tiptap/core @tiptap/pm @tiptap/starter-kit
```

## 3. Get a Conversion token

A Conversion token is a JWT, a signed token, that lets the editor call the Conversion service. The registry token from step 1 only installs the packages. Without a Conversion token, every export and import fails.

Your server signs the token with a private key from the Tiptap dashboard. When you create a secret there, you get an ECDSA (P-256) private key as a PEM file, as [Authentication](/authentication) shows.

The token names `Convert` as its audience (`aud`), the service it is for, and lists the actions it allows:

- `Convert:Export:Docx` for the export.
- `Convert:Import:Docx` for the import.

A token with one action does not allow the other. The example allows both, for an editor that exports and imports, and an editor that only exports needs only `Convert:Export:Docx`.

This example signs the token with `jose`, a JWT library for Node.js. `TIPTAP_PRIVATE_KEY` holds the PEM text of the private key, and `TIPTAP_ENVIRONMENT_ID` the ID of your Tiptap environment from the dashboard.

The Conversion service doesn't scope its actions by resource, so the permissions use `resource: '*'`:

```js
import { SignJWT, importPKCS8 } from 'jose'

export async function createConversionToken() {
  const privateKey = await importPKCS8(process.env.TIPTAP_PRIVATE_KEY, 'ES256')

  return new SignJWT({
    permissions: [
      { action: 'Convert:Export:Docx', resource: '*' },
      { action: 'Convert:Import:Docx', resource: '*' },
    ],
  })
    .setProtectedHeader({ alg: 'ES256' })
    .setIssuer(process.env.TIPTAP_ENVIRONMENT_ID)
    .setAudience('Convert')
    .setIssuedAt()
    .setExpirationTime('12h')
    .sign(privateKey)
}
```

A token written into your frontend code is visible to everyone who opens the page, so the browser fetches it at runtime instead. Return it as plain text from a route of your own server, behind your app's login.

This route uses Express, a Node.js web framework. `app` stands for your Express app, and `requireLogin` for your login check:

```js
app.get('/api/conversion-token', requireLogin, async (req, res) => {
  res.type('text/plain').send(await createConversionToken())
})
```

The two extensions read the token at different times, which decides how long it should live:

- **Export.** `exportDocx()` takes `token` per call, so the example in step 4 fetches a fresh token for each export.
- **Import.** `importDocx()` has no `token` option and reads it from `ImportDocx.configure()`, which is set when you create the editor. So sign the token with an expiry longer than an editing session, such as the `12h` in the example. After it expires, the import fails with a `401` error until you create the editor again with a new token.

## 4. Build a first editor

This editor saves its document as a `.docx` file when the user clicks a button, and opens a `.docx` file the user picks. The page needs an element for the editor, a button and a file input:

```html
<div id="editor"></div>
<button id="export">Export</button>
<input id="import" type="file" accept=".docx" />
```

The script fetches a Conversion token from the route of step 3, `/api/conversion-token`, and gives it to both extensions. It is a module, so it can use `await` at the top level, as a bundler such as Vite builds it:

```ts
import { Editor } from '@tiptap/core'
import StarterKit from '@tiptap/starter-kit'
import { ExportDocx } from '@tiptap-pro/extension-export-docx'
import { ImportDocx } from '@tiptap-pro/extension-import-docx'

async function getConversionToken() {
  const response = await fetch('/api/conversion-token')
  return response.text()
}

function download(blob: Blob) {
  const url = URL.createObjectURL(blob)
  const link = document.createElement('a')
  link.href = url
  link.download = 'report.docx'
  link.click()
  setTimeout(() => URL.revokeObjectURL(url), 1000)
}

const token = await getConversionToken()

const editor = new Editor({
  element: document.querySelector('#editor'),
  extensions: [
    StarterKit,
    ExportDocx.configure({
      onCompleteExport: (result) => {
        if (result instanceof Blob) download(result)
      },
      onError: (error) => console.error(error),
    }),
    ImportDocx.configure({
      token,
      onError: (error) => console.error(error),
    }),
  ],
  content: '<h1>My report</h1><p>Hello from Tiptap.</p>',
})

document.querySelector('#export')?.addEventListener('click', async () => {
  editor.commands.exportDocx({ token: await getConversionToken() })
})

document.querySelector('#import')?.addEventListener('change', (event) => {
  if (!(event.target instanceof HTMLInputElement)) return
  const file = event.target.files?.[0]
  if (file) editor.commands.importDocx({ file })
})
```

`onCompleteExport` receives a `Blob`, because the default `exportType` is `'blob'`. Its type also allows a string or a `Uint8Array` for the other export types, so the `instanceof` check narrows it.

`onCompleteExport` is required, because without it the finished export throws an error. The [Export DOCX](/conversion/v3/export/docx/editor-extension) and [Import DOCX](/conversion/v3/import/docx/editor-extension) pages explain the other options.

## What you see when it works

A click on Export downloads `report.docx`, which opens in Word with the heading and the paragraph. A `.docx` file picked in the file input replaces the editor's content with the content of the file.

Export hands the file to `onCompleteExport` as a `Blob`, and import writes the document into the editor. A missing token, a refused request or a network failure goes to `onError`.

[Export warnings and errors](/conversion/v3/export/docx/warnings-and-errors) and [import warnings and errors](/conversion/v3/import/docx/warnings-and-errors) list what it receives.

A Word table in this StarterKit editor keeps its text as preserved content, because the editor has no table extension. [What the editor keeps](/conversion/v3/content-reference/overview#what-the-editor-keeps) shows how to style it and how it turns back into a table.

## Connection options

Both extensions take the same four connection options in `configure()`. `exportDocx()` also takes them per call, and its values win over the configured ones. `importDocx()` takes them only from `configure()`:

| Option     | Type           | Default     | Description                                                                                                                                                                                                                                           |
| ---------- | -------------- | ----------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `token`    | `string`       | Required    | The Conversion token. Export takes it in the `exportDocx()` call, as step 4 does, or in `configure()`. Import takes it in `configure()`. Export needs `Convert:Export:Docx`, and import `Convert:Import:Docx`.                                        |
| `appId`    | `string`       | `undefined` | Your app ID, only for a token from [Legacy authentication](/authentication/legacy), signed with an App ID's secret. The extensions send it in the `X-App-Id` header. Tiptap Cloud refuses a legacy token without it, with `401` and `missing_app_id`. |
| `region`   | `'eu' \| 'us'` | `'eu'`      | The Tiptap Cloud region. See [Region and endpoint](#region-and-endpoint).                                                                                                                                                                             |
| `endpoint` | `string`       | `undefined` | The base URL of your own Conversion service. It wins over `region`.                                                                                                                                                                                   |

## Region and endpoint

The extensions call Tiptap Cloud in the EU unless you set `region` or `endpoint`. Set `region: 'us'` to use the US region:

| `region` | Export calls                                       | Import calls                                       |
| -------- | -------------------------------------------------- | -------------------------------------------------- |
| `'eu'`   | `https://api.tiptap.dev/v3/convert/export/docx`    | `https://api.tiptap.dev/v3/convert/import/docx`    |
| `'us'`   | `https://api-us.tiptap.dev/v3/convert/export/docx` | `https://api-us.tiptap.dev/v3/convert/import/docx` |

Set `endpoint` to the base URL of a Conversion service on your own server, such as `https://convert.example.com/v3`. `endpoint` wins over `region`. Export then calls `<endpoint>/export/docx` and import `<endpoint>/import/docx`, so one `endpoint` serves both extensions.

Your own server serves the same endpoints under `/v3` and `/v3/convert`, so either works as the base. [REST API overview](/conversion/v3/rest-api/overview#your-own-server) shows how to run it.

Export DOCX needs the Conversion service 2.50.0 or later on your own server. The service has the v3 export endpoint since 2.48.0, but the extension sends `repeatTableHeaderRows` with every export, and the service accepts it since 2.50.0.

On your own server, 2.48 and 2.49 refuse the export with `400` and `INVALID_EXPORT_OPTIONS`. An older service answers `404`, which reaches `onError` as an `HTTP_ERROR` with `status` 404.

A base URL from a v2 setup, ending in `/v2` or `/v2/convert`, works unchanged, because the extensions call the v3 endpoints of the same server.

Any other base URL, such as a path on a proxy, is used as it is. The extension then logs a console warning that it found no version in it.

## Packages

The table lists what the two extensions need, with the kind of dependency and the version:

| Package                                   | Kind                                      | Version             |
| ----------------------------------------- | ----------------------------------------- | ------------------- |
| `@tiptap-pro/extension-export-docx`       | Dependency                                | `^1.0.0`            |
| `@tiptap-pro/extension-import-docx`       | Dependency                                | `^1.0.0`            |
| `@tiptap-pro/extension-preserved-content` | Dependency of Import DOCX and Export DOCX | Installed with them |
| `@tiptap/core`                            | Peer dependency                           | `^3.0.7`            |
| `@tiptap/pm`                              | Peer dependency                           | `^3.0.7`            |

Import DOCX adds the `PreservedContent` extension to the editor, which keeps imported content the editor has no extension for. Export DOCX doesn't add it, but turns preserved content back before it sends the document, so the `.docx` file keeps it.

**An editor that loads imported documents without Import DOCX needs `PreservedContent`**, such as an export-only editor or a read-only viewer. Without it, the editor replaces such a document with an empty one. Install `@tiptap-pro/extension-preserved-content` and add the extension:

```ts
import { PreservedContent } from '@tiptap-pro/extension-preserved-content'
import StarterKit from '@tiptap/starter-kit'

const extensions = [StarterKit, PreservedContent]
```
