Tiptap Conversion lets the users of your editor open a Word file and save their work as one. Two extensions add the commands, and the Conversion service does the conversion, in Tiptap Cloud or on your own server. To set it up, start with [Install Tiptap Conversion](/conversion/v3/getting-started/install).

## What you get

Each part has its own page:

- [Export DOCX](/conversion/v3/export/docx/editor-extension): the `exportDocx` command saves the document as a `.docx` file, formatted the way your editor shows it.
- [Import DOCX](/conversion/v3/import/docx/editor-extension): the `importDocx` command opens a `.docx` file in the editor.
- Page Layout: with [Page Layout](/features/page-layout/getting-started/overview) in the editor, sections, page size, margins, headers, footers and footnotes go into the `.docx` file on [export](/conversion/v3/export/docx/editor-extension#with-page-layout) and come back on [import](/conversion/v3/import/docx/page-layout).
- [Export styles and fonts](/conversion/v3/export/docx/styles): Word styles that match your editor, and fonts embedded in the file.
- [Render custom nodes](/conversion/v3/export/docx/custom-nodes): rules that turn the custom nodes you defined in Tiptap into Word paragraphs, text and tables.
- [What converts](/conversion/v3/content-reference/overview): for each kind of Word content, such as tables, comments or footnotes, what import gives the editor, what export writes, and which extension the editor needs for it.
- [Export warnings and errors](/conversion/v3/export/docx/warnings-and-errors) and [import warnings and errors](/conversion/v3/import/docx/warnings-and-errors): what a conversion left out, and why one failed.
- [REST API](/conversion/v3/rest-api/overview): the same conversions from your server, without an editor.
- [Migrate export from 0.x](/conversion/v3/getting-started/migrate-export-from-0x) and [Migrate import from 0.x](/conversion/v3/getting-started/migrate-import-from-0x): the changes for an editor that uses the 0.x packages.

## Quick start

The two packages come from Tiptap's private registry. Once your project can reach it, as [Install Tiptap Conversion](/conversion/v3/getting-started/install) shows, install them:

```bash
npm install @tiptap-pro/extension-export-docx @tiptap-pro/extension-import-docx
```

Then add both extensions to your editor with a Conversion token, which is a JWT that lets the editor call the Conversion service. Your UI then calls `exportDocx()` to save the document and `importDocx()` to open a file, for example from a button and a file input. In this example, `CONVERSION_TOKEN` stands for a token your server signed and the page fetched at runtime, as the install page shows, and `download` for your own function that saves the file:

```ts
import { Editor } from '@tiptap/core'
import StarterKit from '@tiptap/starter-kit'
import { ExportDocx } from '@tiptap-pro/extension-export-docx'
import { ImportDocx } from '@tiptap-pro/extension-import-docx'

const editor = new Editor({
  element: document.querySelector('#editor'),
  extensions: [
    StarterKit,
    ExportDocx.configure({
      token: CONVERSION_TOKEN,
      onCompleteExport: (blob) => download(blob),
    }),
    ImportDocx.configure({ token: CONVERSION_TOKEN }),
  ],
})

function saveAsWord() {
  editor.commands.exportDocx()
}

function openWordFile(file: File) {
  editor.commands.importDocx({ file })
}
```

`exportDocx()` hands the finished file to `onCompleteExport`, as a `Blob` unless you set another `exportType`. `importDocx()` replaces the editor's content with the content of the file. [Install Tiptap Conversion](/conversion/v3/getting-started/install) says where the token comes from and builds the complete editor, with a file input and a download button.

## What stays the same, and what changes

The document you save stays the JSON that `getJSON()` returns. Export reads it and import replaces it, so your extensions, commands and saving work as they did without Tiptap Conversion.

Both commands need a network connection, because the Conversion service builds and reads the `.docx` file. So `exportDocx()` and `importDocx()` return `true` right away, and the result arrives later in a callback: the file in `onCompleteExport`, and a failure in `onError`.

Export also reads the CSS your editor renders, so the Word file has the fonts, sizes and spacing the user sees. [Export styles and fonts](/conversion/v3/export/docx/styles) explains how to change them.

The editor shows what its extensions define. An import keeps everything else as preserved content. So a Word table in an editor without the table extension keeps its text, and it shows as a table once you add the extension and load the stored document again. [What converts](/conversion/v3/content-reference/overview) lists which extension each kind of content needs.

The table names the call for each task and the page that explains it. A call with `()` is a command and runs on `editor.commands`. An export option can be set in `ExportDocx.configure()` or passed to `exportDocx()`:

| Task                                         | Call                                                             | Page                                                                                               |
| -------------------------------------------- | ---------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| Save the document as a `.docx` file          | `exportDocx()`, with `onCompleteExport`                          | [Export DOCX](/conversion/v3/export/docx/editor-extension)                                         |
| Get the file as bytes or Base64              | `exportDocx({ exportType: 'buffer' })`, or `'base64'`            | [Save the file](/conversion/v3/export/docx/editor-extension#save-the-file)                         |
| Open a `.docx` file in the editor            | `importDocx({ file })`                                           | [Import DOCX](/conversion/v3/import/docx/editor-extension)                                         |
| Change the content before the editor gets it | `importDocx({ file, onImport })`                                 | [Import DOCX](/conversion/v3/import/docx/editor-extension)                                         |
| Keep headers, footers and page setup         | Page Layout in the editor                                        | [Export with Page Layout](/conversion/v3/export/docx/editor-extension#with-page-layout)            |
| Set the page size without Page Layout        | the `pageSize` and `pageMargins` options                         | [Page size and margins](/conversion/v3/export/docx/editor-extension#page-size-and-margins)         |
| Change a Word style, such as Heading 1       | the `styleOverrides` option                                      | [Export styles and fonts](/conversion/v3/export/docx/styles)                                       |
| Embed a font in the file                     | the `fonts` option, or `embedFonts: true`                        | [Embed fonts](/conversion/v3/export/docx/styles#embed-fonts)                                       |
| Write a node type of your own to Word        | the `customNodeDsl` option                                       | [Render custom nodes](/conversion/v3/export/docx/custom-nodes)                                     |
| Keep footnotes and endnotes                  | `@tiptap-pro/extension-footnotes` with Page Layout               | [Footnotes and endnotes](/conversion/v3/content-reference/structures-and-media/footnotes-endnotes) |
| Keep comments                                | `@tiptap-pro/extension-comments`                                 | [Comments](/conversion/v3/content-reference/structures-and-media/comments)                         |
| See what a conversion left out               | the `onWarning` option                                           | [Export warnings and errors](/conversion/v3/export/docx/warnings-and-errors)                       |
| Find out why a conversion failed             | the `onError` option of either extension                         | [Export warnings and errors](/conversion/v3/export/docx/warnings-and-errors)                       |
| Use the US region or your own server         | the `region` or `endpoint` option                                | [Region and endpoint](/conversion/v3/getting-started/install#region-and-endpoint)                  |

## Words these pages use

The pages explain these words where they use them. This list is the place to look one up:

| Word               | What it means                                                                                                                                |
| ------------------ | -------------------------------------------------------------------------------------------------------------------------------------------- |
| Conversion service | The server that turns Tiptap JSON into a `.docx` file and back. It runs in Tiptap Cloud, or on your own server.                              |
| Conversion token   | A JWT you sign that lets the editor, or your server, call the Conversion service for export, import or both.                                 |
| Tiptap JSON        | The document as `getJSON()` returns it. Import produces it, and export reads it.                                                             |
| Measured CSS       | The fonts, sizes, colors and spacing that export reads from the editor as the browser shows it, so the Word file looks the same.             |
| Word style         | A named set of formatting in the `.docx` file, such as Normal or Heading 1. Export builds them from the measured CSS.                        |
| Section            | A part of a Word document with its own page size, margins, columns, headers and footers. With Page Layout, it maps to a Page Layout section. |
| Section columns    | Word's text columns, which belong to a section. Page Layout keeps them in the section's page setup.                                          |
| Preserved content  | Imported content the editor has no extension for. It keeps its text, and it turns back into the real node once you add the extension.        |
| Warning            | Content a conversion left out or changed. The conversion goes on, and `onWarning` receives the warning.                                      |
| Error              | A reason a conversion failed, such as a missing token. `onError` receives it, and no file arrives.                                           |
| Custom node rule   | A description of how export writes a node type of yours to Word, set in the `customNodeDsl` option. DSL stands for domain-specific language. |
