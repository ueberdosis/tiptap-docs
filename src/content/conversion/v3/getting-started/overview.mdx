## What you get

Each part has its own page:

- [Export DOCX](/conversion/v3/docx/export): the `exportDocx` command saves the document as a `.docx` file, formatted the way your editor shows it.
- [Import DOCX](/conversion/v3/docx/import): the `importDocx` command opens a `.docx` file in the editor.
- [Word files with Page Layout](/conversion/v3/docx/page-layout): sections, page size, margins, headers, footers and footnotes go into the `.docx` file on export and come back on import. This needs [Page Layout](/features/page-layout/getting-started/overview), the extension that shows the editor as pages.
- [Export styles and fonts](/conversion/v3/docx/export-styles): Word styles that match your editor, and fonts embedded in the file.
- [Custom nodes in Word files](/conversion/v3/docx/custom-nodes): rules that turn the custom nodes you defined in Tiptap into Word paragraphs, text and tables.
- [What Word elements become](/conversion/v3/docx/elements): for each kind of Word content, such as tables, lists or footnotes, what import gives the editor, what export writes, and which extension the editor needs for it.
- [Tracked changes and comments](/conversion/v3/docx/tracked-changes-and-comments): Word's suggestions and comment threads on import and export.
- [Content the editor cannot show](/conversion/v3/docx/preserved-content): how an import keeps content the editor has no extension for, and how it turns back once you add the extension.
- [Import options](/conversion/v3/docx/import-options) and [Export options](/conversion/v3/docx/export-options): every option of the two extensions and their commands.
- [Warnings and errors](/conversion/v3/reference/warnings-and-errors): what a conversion left out, and why one failed.
- [REST API](/conversion/v3/rest-api/overview): the same conversions from your server, without an editor.
- [Migrate from Conversion v2](/conversion/v3/getting-started/migrate-from-v2): the changes for an editor that uses the 0.x packages.

## Quick start

The two packages come from Tiptap's private registry. Once your project can reach it, as [Install Tiptap Conversion](/conversion/v3/getting-started/install) shows, install them:

```bash
npm install @tiptap-pro/extension-export-docx @tiptap-pro/extension-import-docx
```

Then add both extensions to your editor. Both need a Conversion token, a JWT that lets the editor call the Conversion service. Import DOCX takes it in `configure()`, and `exportDocx()` can take it with each call, so each export uses a fresh one. Your UI then calls `exportDocx()` to save the document and `importDocx()` to open a file, for example from a button and a file input.

In this example, `CONVERSION_TOKEN` stands for a token your server signed, which the page fetched at runtime. `download` stands for your own function that saves a `Blob`:

```ts
import { Editor } from '@tiptap/core'
import StarterKit from '@tiptap/starter-kit'
import { ExportDocx } from '@tiptap-pro/extension-export-docx'
import { ImportDocx } from '@tiptap-pro/extension-import-docx'

const editor = new Editor({
  element: document.querySelector('#editor'),
  extensions: [
    StarterKit,
    ExportDocx.configure({
      onCompleteExport: (result) => {
        if (result instanceof Blob) download(result)
      },
    }),
    ImportDocx.configure({ token: CONVERSION_TOKEN }),
  ],
})

function saveAsWord() {
  editor.commands.exportDocx({ token: CONVERSION_TOKEN })
}

function openWordFile(file: File) {
  editor.commands.importDocx({ file })
}
```

`exportDocx()` hands the finished file to `onCompleteExport`, as a `Blob` unless you set another `exportType`. `importDocx()` replaces the editor's content with the content of the file. [Install Tiptap Conversion](/conversion/v3/getting-started/install) shows how your server signs the token and how the page fetches it, and builds the complete editor, with a file input and a download button.

## What stays the same, and what changes

Compared to an editor without Tiptap Conversion, the document you save stays the same: the JSON that `getJSON()` returns, Tiptap's document format. Export reads it and import replaces it, so your extensions, commands and saving work as before.

Both commands need a network connection, because the Conversion service builds and reads the `.docx` file. So `exportDocx()` and `importDocx()` return `true` right away, and the result arrives later in a callback: the file in `onCompleteExport`, and a failure in `onError`.

Export also reads the CSS your editor renders, so the Word file has the fonts, sizes and spacing the user sees. [Export styles and fonts](/conversion/v3/docx/export-styles) explains how to change them.

The editor shows what its extensions define. An import keeps everything else as preserved content, which holds it in the document until you add the extension. So a Word table in an editor without the table extension shows its cells' text as editable paragraphs, and export writes it to Word as a table.

The table shows as a table once you add the extension and load the stored document again, or run `editor.commands.restorePreservedContent()`. [What Word elements become](/conversion/v3/docx/elements) lists which extension each kind of content needs.

## Common tasks

The table names the call for each task and the page that explains it. A call with `()` is a command and runs on `editor.commands`. An export option can be set in `ExportDocx.configure()` or passed to `exportDocx()`:

| Task                                         | Call                                                             | Page                                                                                    |
| -------------------------------------------- | ---------------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| Save the document as a `.docx` file          | `exportDocx()`, with `onCompleteExport`                          | [Export DOCX](/conversion/v3/docx/export)                                               |
| Get the file as bytes or Base64              | `exportDocx({ exportType: 'buffer' })`, or `'base64'`            | [Save the file](/conversion/v3/docx/export#save-the-file)                               |
| Open a `.docx` file in the editor            | `importDocx({ file })`                                           | [Import DOCX](/conversion/v3/docx/import)                                               |
| Change the content before the editor gets it | `importDocx({ file, onImport })`                                 | [Import DOCX](/conversion/v3/docx/import#change-the-document-before-the-editor-gets-it) |
| Keep headers, footers and page setup         | Page Layout in the editor                                        | [Word files with Page Layout](/conversion/v3/docx/page-layout)                          |
| Set the page size without Page Layout        | the `pageSize` and `pageMargins` options                         | [Page size and margins](/conversion/v3/docx/export#page-size-and-margins)               |
| Change a Word style, such as Heading 1       | the `styleOverrides` option                                      | [Export styles and fonts](/conversion/v3/docx/export-styles)                            |
| Embed a font in the file                     | the `fonts` option, or `embedFonts: true`                        | [Embed fonts](/conversion/v3/docx/export-styles#embed-fonts)                            |
| Write a node type of your own to Word        | the `customNodeDsl` option                                       | [Custom nodes in Word files](/conversion/v3/docx/custom-nodes)                          |
| Keep footnotes and endnotes                  | the Footnotes extension                                          | [Footnotes and endnotes](/conversion/v3/docx/elements/footnotes)                        |
| Keep comments                                | the Comments extension                                           | [Tracked changes and comments](/conversion/v3/docx/tracked-changes-and-comments)        |
| Show content kept for a missing extension    | `restorePreservedContent()`, after you add the extension         | [Content the editor cannot show](/conversion/v3/docx/preserved-content)                 |
| See what a conversion left out               | the `onWarning` option                                           | [Warnings and errors](/conversion/v3/reference/warnings-and-errors)                     |
| Find out why a conversion failed             | the `onError` option of either extension                         | [Warnings and errors](/conversion/v3/reference/warnings-and-errors)                     |
| Use the US region or your own server         | the `region` or `endpoint` option                                | [Region and endpoint](/conversion/v3/getting-started/install#region-and-endpoint)       |

## Words these pages use

The pages explain these words where they use them. This list is the place to look one up:

| Word               | What it means                                                                                                                                |
| ------------------ | -------------------------------------------------------------------------------------------------------------------------------------------- |
| Conversion service | The server that turns Tiptap JSON into a `.docx` file and back. It runs in Tiptap Cloud, or on your own server.                              |
| Conversion token   | A JWT you sign that lets the editor, or your server, call the Conversion service for export, import or both.                                 |
| Tiptap JSON        | The document as `getJSON()` returns it. Import produces it, and export reads it.                                                             |
| Measured CSS       | The fonts, sizes, colors and spacing that export reads from the editor as the browser shows it, so the Word file looks the same.             |
| Word style         | A named set of formatting in the `.docx` file, such as Normal or Heading 1. Export builds them from the measured CSS.                        |
| Section            | A part of a Word document with its own page size, margins, columns, headers and footers. With Page Layout, it maps to a Page Layout section. |
| Section columns    | Word's text columns, which belong to a section. Page Layout keeps them in the section's page setup.                                          |
| Preserved content  | Imported content the editor has no extension for. It keeps its text, and it turns back into the real node once you add the extension.        |
| Warning            | Content a conversion left out or changed. The conversion goes on, and `onWarning` receives the warning.                                      |
| Error              | A reason a conversion failed, such as a missing token. `onError` receives it, and no file arrives.                                           |
| Custom node rule   | A description of how export writes a node type of yours to Word, set in the `customNodeDsl` option. DSL stands for domain-specific language. |
