The Import DOCX 0.x packages call the v2 API of Tiptap Conversion, and the 1.0 packages call v3, the version these pages describe. So moving to v3 means updating the package to 1.0.

In 1.0 the `importDocx` command writes into Page Layout when the editor has it. Several 0.x options are gone, and warnings and errors have their own callbacks.

Each step shows the 0.x code and its 1.0 replacement.

## 1. Check that you pass a `token`

`token` is required. The import now fails before it sends a request when `token` is missing, so make sure every `ImportDocx.configure` call sets one. Add `appId`, and `region` or `endpoint`, as you did for export. See [Install Tiptap Conversion](/conversion/v3/getting-started/install#connection-options).

```ts
ImportDocx.configure({
  token: 'CONVERT_TOKEN',
  appId: 'APP_ID',
})
```

An `endpoint` that ends in `/v2` still works. One base serves both the import and the export extension.

## 2. Replace `imageUploadCallbackUrl`

`imageUploadCallbackUrl` is gone. Pass `imageUploadConfig` with the upload URL instead.

```ts
// 0.x
ImportDocx.configure({
  imageUploadCallbackUrl: 'https://example.com/upload',
})

// 1.0
ImportDocx.configure({
  imageUploadConfig: { url: 'https://example.com/upload' },
})
```

`imageUploadConfig` also takes `headers`, `method` and `queryParams`.

## 3. Replace `verbose` with `onWarning`

`verbose` is gone. `onWarning` receives everything the import had to leave out. A warning never stops the import.

```ts
// 0.x
ImportDocx.configure({ verbose: 1 })

// 1.0
ImportDocx.configure({
  onWarning: (warning) => console.warn(warning.code, warning.message),
})
```

A warning has a `code`:

- `unsupported`: the schema has no extension for a node or mark.
- A code from Convert, such as `bookmarks-dropped` or `image-skipped`, for something it left out or changed while it read the file.

The service logs stay in `context.logs` and don't become warnings. Without `onWarning`, warnings go to the console. See [warnings and errors](/conversion/v3/import/docx/warnings-and-errors).

## 4. Remove placeholders

The `placeholders` option is gone from the command, and the `placeholders` setting of the Pages 1 extension no longer feeds the import. Word page fields such as `PAGE` and `NUMPAGES` now arrive as `pageNumber` nodes for Page Layout.

```ts
// 0.x
editor
  .chain()
  .importDocx({ file, placeholders: { total: 'pages' } })
  .run()

// 1.0
editor.chain().importDocx({ file }).run()
```

## 5. Read headers, footers and page setup from `content`

The import returns one Page Layout document. Sections, page setup, headers, footers, page numbers, breaks and notes are all inside `context.content`. The separate header, footer, `footnotes` and `endnotes` fields are gone from the `onImport` context, as are `pageLayout` and `numberingFormats`.

```ts
// 0.x
const { content, header, footer, pageLayout } = context

// 1.0
const { content } = context
```

With Page Layout, `setEditorContent` writes all of it in one step. See the [`onImport` context](/conversion/v3/import/docx/api#importcontext). The Pages 1 extension is no longer supported. To keep using it, stay on 0.x.

## 6. Write into Page Layout

When the Page Layout engine is on the editor, `setEditorContent` replaces the source document with the sections, headers, footers and notes. Without Page Layout, the body goes into the editor with `setContent`, and the nodes only Page Layout can hold are left out. See [import without Page Layout](/conversion/v3/import/docx/without-page-layout).

```ts
editor.commands.importDocx({
  file,
  onImport: (context) => {
    if (context.error) return
    context.setEditorContent()
  },
})
```

The import fails when the editor has Page Layout registered but no engine yet, which is the case before the editor mounts. Import after it has mounted. See [Page Layout](/features/page-layout/getting-started/overview) and [footnotes](/features/footnotes).

## 7. Handle errors with `onError`

Errors go to `onError`. Set it on the command or on `ImportDocx.configure`. The command's callback wins.

Without `onError`, the error reaches `onImport` as `{ content: null, error }`. Without `onImport` too, the import rethrows the error as an unhandled rejection.

```ts
ImportDocx.configure({
  token: 'CONVERT_TOKEN',
  onError: (error) => console.error(error),
})
```

A refused request or a network failure gives an `ImportDocxRequestError`. It has a `code` and, when the server responded, a `status`. See [warnings and errors](/conversion/v3/import/docx/warnings-and-errors#errors) for every error.

## 8. Expect a newer import to win

When you start a second import before the first response arrives, the first one writes nothing. It reports an `ImportDocxSupersededError`. Calling `setEditorContent` from an older import throws the same error.

```ts
import { ImportDocxSupersededError } from '@tiptap-pro/extension-import-docx'

ImportDocx.configure({
  token: 'CONVERT_TOKEN',
  onError(error) {
    if (error instanceof ImportDocxSupersededError) return
    console.error(error)
  },
})
```
