Update the package to 1.0 first, as [Update the packages](/conversion/v3/getting-started/migrate-from-v2#update-the-packages) shows. Afterward, your editor exports with 1.0 and warns about anything left from 0.x.

In the examples, `CONVERSION_TOKEN` is your token, `save` is your function that stores the file, and `editor` is an editor with the `ExportDocx` extension.

## 1. Add a Conversion token

Every 1.0 export calls the Conversion service, so it needs a `token`: a JWT, a signed token from your server, that allows the `Convert:Export:Docx` action. [Get a Conversion token](/conversion/v3/getting-started/install#3-get-a-conversion-token) shows how to sign one and get it into the browser.

Add the token to `ExportDocx.configure()`:

```ts
import { ExportDocx } from '@tiptap-pro/extension-export-docx'

// 0.x
ExportDocx.configure({
  onCompleteExport: (result) => save(result),
})

// 1.0
ExportDocx.configure({
  token: CONVERSION_TOKEN,
  onCompleteExport: (result) => save(result),
})
```

The export then reaches the Conversion service in Tiptap Cloud's EU region. A token in `configure()` stops working when it expires, so a long session passes a fresh one per call, as `exportDocx({ token })`.

Add more options for these setups:

- **US region.** Add `region: 'us'`.
- **Your own server.** Set `endpoint` to its base URL. A v2 base URL, ending in `/v2`, works unchanged, as [Region and endpoint](/conversion/v3/getting-started/install#region-and-endpoint) explains.
- **A token from [Legacy authentication](/authentication/legacy)**, with an App ID. Add `appId`.

## 2. Replace the standalone `exportDocx` function

1.0 removed the 0.x function that turned a JSON document into a file without an editor. Both replacements run on a server:

- **The [Export DOCX REST API](/conversion/v3/rest-api/export-docx).** Your backend sends the JSON to the Conversion service and gets the file back. It suits a backend not written in JavaScript, or one without Tiptap packages. Your code first turns preserved content from an import back into its original nodes, as the REST page shows.
- **An editor that isn't mounted.** The command runs as in the browser, with the options of `ExportDocx.configure()`, and turns preserved content back on its own. It suits a backend that shares its configuration with your browser editor.

The editor needs no DOM, only `fetch`, `Blob` and `FormData`, so it runs in Node.js 18 or later. This example loads the JSON with `element: null`, exports it and destroys the editor:

```ts
// 0.x
import { exportDocx } from '@tiptap-pro/extension-export-docx'

const file = await exportDocx({
  document: json,
  exportType: 'buffer',
  customNodes: [],
  styleOverrides: {},
})

// 1.0
import { Editor } from '@tiptap/core'
import StarterKit from '@tiptap/starter-kit'
import { ExportDocx } from '@tiptap-pro/extension-export-docx'

const editor = new Editor({
  element: null,
  content: json,
  extensions: [
    StarterKit,
    ExportDocx.configure({ token: CONVERSION_TOKEN, exportType: 'buffer', styleOverrides: {} }),
  ],
})

const file = await new Promise<Uint8Array>((resolve, reject) => {
  editor.commands.exportDocx({
    onCompleteExport: (result) => resolve(result as Uint8Array),
    onError: reject,
  })
}).finally(() => editor.destroy())
```

`json` is your Tiptap document. The 0.x call's other options move to `ExportDocx.configure()`, and `customNodes` becomes `customNodeDsl` in [step 4](#4-move-custom-nodes-to-customnodedsl).

Next to `StarterKit`, add an extension for each node type in your documents, such as tables and images. For documents from an import, also install `@tiptap-pro/extension-preserved-content` and add its `PreservedContent` extension, or the editor loads them as an empty document.

An editor that isn't mounted has no CSS for export to read. So the file gets the Conversion service's default styles, changed by `styleOverrides` and `cssStyles`, as [Export styles and fonts](/conversion/v3/docx/export/styles-and-fonts) shows.

## 3. Read buffers as `Uint8Array` and drop stream output

`exportType: 'buffer'` gives a `Uint8Array` in 1.0, not a Node.js `Buffer`. Code that only passes the file on, such as to `writeFile`, keeps working. A check such as `Buffer.isBuffer(file)` becomes `file instanceof Uint8Array`.

`exportType: 'stream'` is gone and fails the export, so use `'buffer'` or `'blob'` instead.

## 4. Move custom nodes to `customNodeDsl`

The Conversion service can't run the JavaScript renderers of `customNodes`, so 1.0 removed them. Describe each node type of your own with a rule in `customNodeDsl` instead, built with the helpers from `@tiptap-pro/extension-export-docx/dsl`:

```ts
// 0.x
import { Docx, ExportDocx } from '@tiptap-pro/extension-export-docx'

ExportDocx.configure({
  customNodes: [
    {
      type: 'notice',
      render: (node) => new Docx.Paragraph(String(node.attrs?.message ?? '')),
    },
  ],
})

// 1.0
import { ExportDocx } from '@tiptap-pro/extension-export-docx'
import { docxNode, paragraph, ref, textOp } from '@tiptap-pro/extension-export-docx/dsl'

ExportDocx.configure({
  token: CONVERSION_TOKEN,
  customNodeDsl: {
    dslVersion: '1.0',
    nodes: [
      docxNode('notice')
        .block()
        .emit(paragraph().children(textOp(ref('node.attrs.message', { default: '' }))))
        .toJSON(),
    ],
  },
})
```

The `notice` node then exports as a paragraph with its message:

- `docxNode('notice')` starts the rule, and `.block()` makes it a block node.
- `emit()` says what export writes: a paragraph with one text run, `textOp()`, whose text `ref()` reads from the `message` attribute.
- `.toJSON()` turns the rule into the plain object that `customNodeDsl` takes.

[Custom nodes in Word files](/conversion/v3/docx/custom-nodes) explains the rules, and [Custom node DSL](/conversion/v3/docx/custom-nodes/dsl) lists the helpers. Remove `customNodeDslLimits` if you set it, because the Conversion service applies its own limits.

## 5. Turn function overrides into plain objects

In 1.0, the override options take only plain objects, because a function can't be sent to the Conversion service. The command leaves a function out with an `unsupported` warning.

The override options are `paragraphOverrides`, `textRunOverrides`, `tableOverrides`, `tableRowOverrides`, `tableCellOverrides`, `imageOverrides` and each field of `headerFooterOverrides`:

```ts
import { ExportDocx } from '@tiptap-pro/extension-export-docx'

// 0.x
ExportDocx.configure({
  paragraphOverrides: (node, context) => (context.table ? {} : { spacing: { after: 120 } }),
})

// 1.0
ExportDocx.configure({
  token: CONVERSION_TOKEN,
  paragraphOverrides: { spacing: { after: 120 } },
})
```

The plain object applies to every paragraph, including those in tables. No 1.0 option formats only the paragraphs in tables, and a `customNodeDsl` rule formats only node types of your own, not `paragraph`.

## 6. Remove headers, footers and placeholders

1.0 writes headers and footers only from Page Layout, the Tiptap Pro extension that shows the editor as pages and replaces `@tiptap-pro/extension-pages`.

So the options that built them in code are gone: `headers`, `footers`, `placeholders`, `Docx.Header`, `Docx.Footer`, `convertHeader` and `convertFooter`. Remove `@tiptap-pro/extension-export-docx-header-footer` and its `ExportDocxHeaderFooter` extension too, because 1.0 ignores them. The command then takes no header or footer content:

```ts
// 0.x
import { Docx } from '@tiptap-pro/extension-export-docx'

editor.commands.exportDocx({
  headers: { default: new Docx.Header({ children: [new Docx.Paragraph('Example report')] }) },
  footers: { default: new Docx.Footer({ children: [new Docx.Paragraph('Confidential')] }) },
})

// 1.0
editor.commands.exportDocx()
```

To keep headers and footers in the file, add [Page Layout](/features/page-layout/getting-started/overview) to the editor, as [Header and footer](/features/page-layout/header-and-footer) shows. The file then has the headers and footers the user sees, and `headerFooterOverrides` still formats them. [Page numbers](/features/page-layout/page-numbers) shows the footer page number that `placeholders` filled in.

1.0 reads no page size from `@tiptap-pro/extension-pages`. Without Page Layout, pass the size and margins in the `pageSize` and `pageMargins` options, as [Page size and margins](/conversion/v3/docx/export/page-size-and-margins) shows.

Each extension's notes export differently:

- **Notes of the [Footnotes](/features/footnotes) extension** are nodes in the document, so they export without Page Layout. A document without such nodes can pass its notes in the `footnotes` and `endnotes` options, as [Footnotes and endnotes](/conversion/v3/docx/elements/footnotes) shows.
- **Notes of the legacy Pages extension**, `@tiptap-pro/extension-pages`, are in its storage, not in the document. Pass them in these options:

```ts
editor.commands.exportDocx({
  footnotes: editor.storage.pages.footnotesJSON,
  endnotes: editor.storage.pages.endnotesJSON,
})
```

## 7. Replace removed exports

1.0 no longer exports the `docx` library or its own converters, because the Conversion service builds the file. Replace each import your code still has:

| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| `Docx`                                                                                                                                                                                                              | None. Use plain objects in overrides, and `customNodeDsl` for output of your own.                                                           |
| `CharacterSet`                                                                                                                                                                                                      | The character set string, such as `'00'` for ANSI.                                                                                          |
| `LevelFormat`                                                                                                                                                                                                       | The format string, such as `'decimal'` or `'lowerRoman'`.                                                                                   |
| `IRunOptions`, `PositiveUniversalMeasure`                                                                                                                                                                           | The types `TextRunOverrides` and `PageMeasure` of this package.                                                                             |
| `convertNode`, `convertParagraph`, `convertTable`, `convertTextNode` and the other `convert*` helpers                                                                                                               | None. The Conversion service renders the nodes.                                                                                             |
| `processCssStyles`, `createExportStyles`, `exportStylesFromCss`, `ExportStyles`, `ExportStylesOptions`                                                                                                              | The `cssStyles` option, or `documentStyles: true`, the default. See [Export styles and fonts](/conversion/v3/docx/export/styles-and-fonts). |
| `compileCustomNodeDsl`, `DEFAULT_LIMITS`, `DslCompileError`, `DslRuntimeError`, `DslErrorCode`, `DslErrorPayload`                                                                                                   | None. ## 8. Replace the unit helpers

1.0 no longer exports the 0.x helpers that convert pixels and points to Word's units. Each one is a single multiplication, so write it in your code:

| 0.x helper                 | 1.0 code       |
| -------------------------- | -------------- |
| `pixelsToPoints(px)`       | `px * 0.75`    |
| `pixelsToHalfPoints(px)`   | `px * 1.5`     |
| `pointsToTwips(pt)`        | `pt * 20`      |
| `pointsToHalfPoints(pt)`   | `pt * 2`       |
| `lineHeightToDocx(height)` | `height * 240` |

## 9. Check images and fonts

The Conversion service needs every image and font of the document. The command uploads an image from the browser when it is:

- an image on the page's own origin,
- a `blob:` URL,
- a `data:` URL over 64 KB.

In Node.js, the editor has no page, so the command uploads only `blob:` and large `data:` URLs.

The service downloads every other image, so an image on another origin that needs a login is left out with a warning. To keep it, serve it from the page's own origin, such as through a route of your app, or make it public.

The `fonts` option, which embeds font files you pass, keeps its shape and also takes WOFF2 files next to TTF and OTF. `embedFonts: true`, which 0.x didn't have, uploads the page's `@font-face` files for you. [Embed fonts](/conversion/v3/docx/export/styles-and-fonts#embed-fonts) shows both.

One export uploads at most 64 files, fonts first and then images. A file over the limit is left out with a warning. [Limitations](/conversion/v3/reference/limitations#size-limits-of-an-export) lists the other limits.

## 10. Handle export warnings

Export reports what it leaves out to `onWarning`, including leftover 0.x options. Add a handler, so you see them instead of losing them without notice:

```ts
import { ExportDocx } from '@tiptap-pro/extension-export-docx'

ExportDocx.configure({
  token: CONVERSION_TOKEN,
  onWarning(warning) {
    if (warning.code === 'unsupported') console.warn(warning.attribute, warning.message)
  },
  onCompleteExport: (result) => save(result),
})
```

A removed option, such as `headers` or `customNodes`, isn't sent and arrives as an `unsupported` warning with its name in `attribute`. In TypeScript, a removed option in `configure()` is also a type error. [Warnings](/conversion/v3/reference/warnings) lists every warning code.

## Check that it worked

Run an export with the `onWarning` handler from [Handle export warnings](#10-handle-export-warnings). The migration is done when `onCompleteExport` receives the file and the console shows no `unsupported` warning.
