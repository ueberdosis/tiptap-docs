Update the package to 1.0 first, as [Update the packages](/conversion/v3/getting-started/migrate-from-v2#update-the-packages) shows. Each step shows the 0.x code and its 1.0 replacement.

In the examples, `CONVERSION_TOKEN` is your token, `editor` is an editor with the `ImportDocx` extension, and `file` is a `.docx` file the user picked.

## 1. Check that you pass a `token`

`token` is required in 1.0, and without it the import fails before it sends a request. So set one in every `ImportDocx.configure()` call. The token allows the `Convert:Import:Docx` action, as [Get a Conversion token](/conversion/v3/getting-started/install#3-get-a-conversion-token) shows:

```ts
import { ImportDocx } from '@tiptap-pro/extension-import-docx'

ImportDocx.configure({
  token: CONVERSION_TOKEN,
})
```

Add `appId`, and `region` or `endpoint`, as for export in [Add a Conversion token](/conversion/v3/getting-started/migrate-from-v2/export#1-add-a-conversion-token). An `endpoint` ending in `/v2` or `/v2/convert` still works, because the import calls `/v3` or `/v3/convert` on the same server. So one base serves both extensions, as [Connection options](/conversion/v3/getting-started/install#connection-options) explains.

## 2. Replace `imageUploadCallbackUrl`

`imageUploadCallbackUrl` is gone. Pass `imageUploadConfig` with the upload URL instead:

```ts
// 0.x
ImportDocx.configure({
  imageUploadCallbackUrl: 'https://example.com/upload',
})

// 1.0
ImportDocx.configure({
  token: CONVERSION_TOKEN,
  imageUploadConfig: { url: 'https://example.com/upload' },
})
```

`imageUploadConfig` also takes `headers`, `method` and `queryParams`, as [Images in imported files](/conversion/v3/docx/import/images) shows.

## 3. Replace `verbose` with `onWarning`

`verbose` is gone. `onWarning` receives everything the import left out or changed, and a warning doesn't stop the import:

```ts
// 0.x
ImportDocx.configure({ verbose: 1 })

// 1.0
ImportDocx.configure({
  token: CONVERSION_TOKEN,
  onWarning: (warning) => console.warn(warning.code, warning.message),
})
```

A warning's `code` is one of these:

- `preserved`: the editor has no extension for a node or mark, so the import kept it as preserved content. It comes back when you add the extension, as [Content the editor cannot show](/conversion/v3/docx/preserved-content) explains.
- `restructured` or `mark-excluded`: the import changed the shape of some content to fit the editor, and kept its text.
- A code from the Conversion service, such as `bookmarks-dropped` or `image-skipped`, for something it left out or changed while it read the file.

The service logs stay in `context.logs` and don't become warnings. Without `onWarning`, warnings go to the console. [Warnings](/conversion/v3/reference/warnings) lists every code.

## 4. Remove placeholders

The `placeholders` option is gone from the command, and the `placeholders` setting of the legacy Pages extension no longer feeds the import. Word page fields such as `PAGE` and `NUMPAGES` arrive as `pageNumber` nodes for Page Layout, and an editor without Page Layout keeps them as preserved content:

```ts
// 0.x
editor
  .chain()
  .importDocx({ file, placeholders: { total: 'pages' } })
  .run()

// 1.0
editor.chain().importDocx({ file }).run()
```

## 5. Read headers, footers and page setup from `content`

The import returns one Page Layout document in `context.content`, with its sections, page setup, headers, footers, page numbers, breaks and notes. The `onImport` context no longer has the separate `header`, `footer`, `footnotes`, `endnotes`, `pageLayout` and `numberingFormats` fields:

```ts
// 0.x
const { content, header, footer, pageLayout } = context

// 1.0
const { content } = context
```

Each section's headers and footers are `pageFurniture` nodes inside its `sectionBreak` node, as [Headers and footers](/conversion/v3/docx/elements/headers-and-footers#import) shows. With Page Layout, `setEditorContent` writes all of it in one step, as [The onImport context](/conversion/v3/docx/import/review#the-onimport-context) shows.

1.0 doesn't support the legacy Pages extension, `@tiptap-pro/extension-pages`. To keep using it, stay on 0.x from the `maintenance` tag.

## 6. Write into Page Layout

Your `onImport` code stays as it is: the same `setEditorContent()` call writes into Page Layout when the editor has it. It replaces the whole document, with the sections, headers, footers and notes, and one undo takes the import back:

```ts
editor.commands.importDocx({
  file,
  onImport: (context) => {
    if (context.error) return
    context.setEditorContent()
  },
})
```

A Page Layout editor that has not mounted, such as a headless one in Node.js, gets the import too, as [Where the document goes](/conversion/v3/docx/import#where-the-document-goes) explains.

Without Page Layout, the body goes into the editor with `setContent`. The parts only Page Layout shows, such as sections, headers and footers, stay preserved content until you add [Page Layout](/features/page-layout/getting-started/overview), as [Without Page Layout](/conversion/v3/docx/preserved-content#without-page-layout) explains. Notes need the [Footnotes](/features/footnotes) extension.

## 7. Handle errors with `onError`

Errors go to `onError`. Set it on the command or on `ImportDocx.configure()`, and the command's callback wins:

```ts
ImportDocx.configure({
  token: CONVERSION_TOKEN,
  onError: (error) => console.error(error),
})
```

Without `onError`, the error reaches `onImport` as `{ content: null, error }`, if the import hadn't handed over the document yet. Without either, the import logs the error with `console.error`.

A refused request or a network failure gives an `ImportDocxRequestError`. It has a `code` and, when the server responded, a `status`. [Errors](/conversion/v3/reference/errors) lists every error.

## 8. Expect a newer import to win

When you start a second import before the first response arrives, the first one writes nothing and reports an `ImportDocxSupersededError`. `setEditorContent` from an older import throws the same error:

```ts
import { ImportDocx, ImportDocxSupersededError } from '@tiptap-pro/extension-import-docx'

ImportDocx.configure({
  token: CONVERSION_TOKEN,
  onError(error) {
    if (error instanceof ImportDocxSupersededError) return
    console.error(error)
  },
})
```

## Check that it worked

Run an import with `onWarning` and `onError`. The migration is done when the imported file shows in the editor, `onError` receives nothing, and the console shows no `unsupported` warning.
