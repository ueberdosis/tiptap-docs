A Word hyperlink imports as a `link` mark with an `href`, and exports back as a Word hyperlink. A link to a Word bookmark, a named place in the same document, has the bookmark's name as its `href`, such as `#intro`.

Links convert in both directions. Bookmarks don't import, and export writes them only from a node you define.

## What you need

The `Link` mark from `StarterKit` holds links. Its `target` and `rel` attributes aren't set on import or written on export.

Export writes a Word bookmark only for an inline node named `bookmark` with an `id` attribute. No Tiptap extension defines that node. [Bookmarks](/features/bookmark) (`@tiptap-pro/extension-bookmark`) has a `bookmark` mark and a `bookmarkPoint` node instead, and export writes neither of them.

To export Word bookmarks, define the node in your own extension. This one also renders the `id` as an HTML `id`, so a link to `#intro` jumps to it in the browser too:

```ts
import { Node } from '@tiptap/core'

const WordBookmark = Node.create({
  name: 'bookmark',
  group: 'inline',
  inline: true,
  atom: true,
  addAttributes() {
    return { id: { default: null } }
  },
  parseHTML() {
    return [{ tag: 'span[data-bookmark]' }]
  },
  renderHTML({ HTMLAttributes }) {
    return ['span', { 'data-bookmark': '', ...HTMLAttributes }]
  },
})
```

Insert the bookmark at the cursor, where a link should lead. Then select the text of the link and set its `href` to the bookmark's `id` with a `#`. Here `editor` is an editor with `WordBookmark` and Export DOCX:

```ts
// With the cursor where the link should lead
editor.commands.insertContent({ type: 'bookmark', attrs: { id: 'intro' } })

// With the text of the link selected
editor.commands.setLink({ href: '#intro' })
```

The node has the same name as the mark of the Bookmarks extension, and an editor can't have both, so use one or the other.

## Import

Import turns a hyperlink into a `link` mark on its text:

```json
{
  "type": "text",
  "text": "Visit the Tiptap website",
  "marks": [{ "type": "link", "attrs": { "href": "https://tiptap.dev" } }]
}
```

Import reads every form Word stores a link in, including a `HYPERLINK` field. A link to a bookmark becomes an `href` such as `#intro`. A link with both a web address and a bookmark joins them, such as `https://example.com#intro`. Formatting inside the link stays.

Import keeps links that start with `http`, `https`, `mailto`, `tel` or `ftp`, and links without a scheme. A link with another scheme, such as `javascript`, imports as plain text.

Import leaves bookmarks out, with one `bookmarks-dropped` warning. A link to a bookmark keeps its `#name` `href`. A cross-reference, a Word field that repeats text from a bookmarked place, imports as the text Word last showed, as [Word fields](/features/cross-references/docx) describes.

## Export

A link to a web address, `mailto:` included, exports as a Word hyperlink with the Hyperlink style. `https://example.com#intro` stays external. An `href` such as `#intro` exports as an internal link to the bookmark with that name.

A `bookmark` node with an `id`, as in [What you need](#what-you-need), exports as an empty Word bookmark where the node sits, so it marks a point and wraps no text. A node without an `id` is left out.

Export drops the `bookmark` mark of the Bookmarks extension without a warning. It drops the extension's `bookmarkPoint` node with an `unsupported` warning. Links to either have no target in Word.

The `crossReference` node of the Cross-references extension (`@tiptap-pro/extension-cross-references`) is dropped with an `unsupported` warning too.

## Limits

- Import leaves bookmarks out, so a link to one has no target in the editor.
- Export drops the marks and points of the Bookmarks extension.
- Export doesn't write `target` and `rel`.
- Cross-references don't round-trip: import keeps their text, and export drops the `crossReference` node.
