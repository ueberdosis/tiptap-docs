Footnotes and endnotes convert in both directions. With Page Layout, import writes the notes into the document and export reads them from it. Without it, notes travel in separate objects that you handle.

## Set up the editor

Page Layout is the supported route. It holds the body and the notes in one document. Add `@tiptap-pro/extension-footnotes` for the note nodes. See [footnotes](/pages/v2/extensions/footnotes).

Without Page Layout, the editor needs nodes named `footnoteReference` and `endnoteReference` to keep the references in the text. Without them, import reports an `unsupported` warning for each missing type.

## Import

Each reference in the text carries a note id. The note bodies are separate Tiptap JSON documents, one for each id.

### With Page Layout

`setEditorContent` writes the body and the notes into the source document. It rebuilds the notes as the footnotes extension holds them.

- Each reference becomes a `footnoteReference` node with a `footnoteId`.
- Each note becomes a `footnote` node inside a `footnoteCollection` at the end of the document, with a `placement` of `footnote` or `endnote`.
- When an endnote id is also a footnote id, the endnote gets the suffix `-endnote`.

The import leaves out a note without a reference, and a reference without a note. `onWarning` receives an `unsupported` warning that names the note id.

### Without Page Layout

`setEditorContent` writes the body only. The references stay in the text as `footnoteReference` and `endnoteReference` nodes with a `noteId` attribute.

The note bodies come back in the [`onImport` context](/conversion/v3/import/docx/api#importcontext).

```ts
editor.commands.importDocx({
  file,
  onImport: (context) => {
    if (context.error) return
    context.setEditorContent()
    // context.footnotes and context.endnotes are keyed by note id
  },
})
```

Both are objects, empty when the document has no notes.

## Export

With Page Layout, export reads the notes from the document. Footnotes and endnotes follow the `placement` of each note. Export ignores the [`footnotes` and `endnotes` options](/conversion/v3/export/docx/usage#keep-notes-and-comments), and `onWarning` receives a warning for each one you pass. Export leaves out a note that no reference points at and reports an `unsupported` warning that names the note id.

Without Page Layout, pass the notes yourself. Each option maps a note id to a Tiptap JSON document, and the body needs a matching reference node with that id in `noteId`.

```ts
editor.commands.exportDocx({
  footnotes: {
    1: {
      type: 'doc',
      content: [{ type: 'paragraph', content: [{ type: 'text', text: 'Source: annual report.' }] }],
    },
  },
})
```

Export doesn't write a reference without a note body.

## Limitations

- Without Page Layout, import doesn't put the notes in the editor. You place them yourself.
- Import and export drop a note without a matching reference or body.
