A Word table imports as a `table` node with rows and cells, and exports back as a Word table. Merged cells, column widths, borders and cell styling travel with it. Header rows don't survive export.

## Set up the editor

Install the table extensions from `@tiptap/extension-table`. `TableKit` registers `Table`, `TableRow`, `TableCell` and `TableHeader`. `StarterKit` doesn't include them.

```ts
import { TableKit } from '@tiptap/extension-table'

const extensions = [StarterKit, TableKit]
```

Without these extensions, the table doesn't arrive as a table. `onWarning` receives an `unsupported` warning for each missing node type.

The stock cells define `colspan`, `rowspan` and `colwidth`. Import returns more attributes than that, and the editor drops each one it doesn't define, without a warning.

| Node                          | Attributes import adds                                                                     |
| ----------------------------- | ------------------------------------------------------------------------------------------ |
| `table`                       | `width`, `indent`, `border*` for each side and for the inside grid, `cellMargin*` per side |
| `tableRow`                    | `height` and `heightRule`                                                                  |
| `tableCell` and `tableHeader` | `background`, `verticalAlign`, `border*` for each side, `cellMargin*` per side             |

Export reads the same attributes back from the editor. A value the editor never stored can't reach the Word file.

## Import

Import returns `tableCell` nodes, and `tableHeader` nodes for header rows. The cells carry these values.

- `colspan` and `rowspan` come from merged cells. Import reads the whole table first, so a cell merged across rows gets the right `rowspan`.
- `colwidth` is an array of pixel widths, one for each column the cell covers.
- `background` is the cell shading as a hex color.
- `verticalAlign` is `top`, `middle` or `bottom`.

A table that Word sets to a percentage width imports without a `width`, so it stays fluid. A fixed width imports as pixels in `width`.

A row is a header row only when Word marks it to repeat at the top of each page. A first row that is only bold or shaded imports as ordinary cells. To make it a header, change the cell `type` from `tableCell` to `tableHeader` in `onImport` before you call `setEditorContent`.

A page break inside a cell is dropped.

## Export

A table with a `width` exports at that fixed width. A table without one exports full width, so it follows the page. Column widths come from each cell's `colwidth`. When none is set, the columns share the width evenly.

Export writes these from the node attributes.

- Merged cells.
- The table's own borders and cell margins.
- Cell backgrounds, per-side cell borders and vertical alignment.
- Row height. `heightRule: 'exact'` writes an exact height. Any other value writes a minimum.

A table without border attributes exports with no borders. A table without cell margins uses Word's default margins.

Export measures the CSS of your mounted editor too. See [Word styles](/conversion/v3/content-reference/structures-and-media/word-styles#export).

To set a default for every table, pass `tableOverrides`, `tableRowOverrides` or `tableCellOverrides` to the export command. Each one takes a plain object.

```ts
editor.commands.exportDocx({
  tableCellOverrides: { margins: { top: 80, bottom: 80 } },
})
```

The values use twips. A function is dropped with an `unsupported` warning.

## Limits

- Export writes a header cell as an ordinary cell. The header row property is lost.
- The editor keeps cell and table styling only with an extension that defines the attributes.
