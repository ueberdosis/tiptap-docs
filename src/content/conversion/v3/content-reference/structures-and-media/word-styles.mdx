Import reads Word styles to decide the node type and to find the formatting of each paragraph and run. It doesn't keep the style names. Export writes a fixed set of Word styles and fills them from your editor's CSS.

## Set up the editor

The editor has no concept of a Word style. Each style turns into a node type, marks and attributes, so you need the extensions for those. See [headings](/conversion/v3/content-reference/text-and-formatting/headings), [paragraphs](/conversion/v3/content-reference/text-and-formatting/paragraphs) and [block elements](/conversion/v3/content-reference/structures-and-media/block-elements).

## Import

### Paragraph styles

Import decides the node type from the style name of the paragraph. It matches the name without regard to case.

| Word style             | Node         |
| ---------------------- | ------------ |
| `Heading` and a number | `heading`    |
| `Quote`                | `blockquote` |
| Any other style        | `paragraph`  |

A paragraph without a style counts as Normal. A custom style based on Heading 2 imports as a `paragraph`, because only the style's own name counts. See [headings](/conversion/v3/content-reference/text-and-formatting/headings#title-subtitle-and-custom-styles).

### Formatting from styles

A style can be based on another style. Import walks that chain and merges the formatting of each parent, then the document defaults. The font, size, bold, italic and color of a style reach the text as marks. Spacing and indentation reach the paragraph as attributes.

A run's character style works the same way. A run in the Strong style gets a `bold` mark when the style resolves to bold. Import drops the name Strong. Formatting without a matching mark isn't kept.

### Styles as CSS

The experimental `cssStyles` option extracts the style catalog as CSS rules. Turn it on with `enabled`. Set `autoInject` to add the rules to the page as a `<style>` tag, scoped by `selector`, which is `.tiptap` by default. Without `autoInject`, the rules come back in the `cssStyles` object of `onImport`.

```ts
ImportDocx.configure({
  token: 'CONVERT_TOKEN',
  cssStyles: { enabled: true, autoInject: true },
})
```

The object covers `p`, `h1` to `h6`, `blockquote`, `a`, `code`, `ul li`, `ol li`, `strong`, `em`, `u` and `s`. Each selector holds a few typography properties, such as `fontFamily`, `fontSize`, `color` and `lineHeight`.

## Export

Each node type writes a fixed Word style.

| Node                        | Word style                |
| --------------------------- | ------------------------- |
| `paragraph`                 | Normal                    |
| `heading`, levels 1 to 6    | Heading 1 to Heading 6    |
| Paragraph in a `blockquote` | Quote                     |
| List item paragraph         | List Paragraph            |
| `code` mark                 | Code character style      |
| `link` mark                 | Hyperlink character style |

A style from the imported file isn't written back. A paragraph imported from a Legal Disclaimer style exports as Normal.

### What the styles look like

By default, export measures the CSS of your mounted editor and writes it into these styles. The Word styles then match what your editor shows. A headless or unmounted editor has nothing to measure. Set `documentStyles: false` to skip the measurement.

Without a measurement, export uses its own defaults. Normal is Arial 11pt with 10pt after each paragraph and a line height of 1.15. Heading 1 to Heading 5 are bold, blue and Arial, from 16pt down to 11pt.

To set a style yourself, pass `styleOverrides` as a plain object. It is merged into the defaults. A style with the same `id` merges, and a new `id` is added.

```ts
editor.commands.exportDocx({
  styleOverrides: {
    paragraphStyles: [
      {
        id: 'Normal',
        name: 'Normal',
        run: { font: 'Calibri', size: 24 },
        paragraph: { spacing: { after: 200 } },
      },
    ],
  },
})
```

Sizes are in half-points, so `24` is 12pt. Spacing is in twips, so `200` is 10pt.

The experimental `cssStyles` export option describes styles as CSS properties for a fixed set of selectors. `styleOverrides` applies after it.

## Limits

- Import doesn't keep style names. Custom styles export as Normal.
- Only a style named `Heading` and a number, or `Quote`, changes the node type.
- Export writes headings 1 to 6. Levels 7 to 9 export as paragraphs.
