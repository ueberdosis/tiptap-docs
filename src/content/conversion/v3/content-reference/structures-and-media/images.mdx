Import uploads each image in the `.docx` file to your server and returns an `image` node with the URL you give back. Export downloads each image and embeds it in the `.docx` file.

## Set up the editor

`@tiptap/extension-image` isn't part of `StarterKit`. Import puts images inside paragraphs, so set `inline` to `true`.

```ts
import Image from '@tiptap/extension-image'

const extensions = [StarterKit, Image.configure({ inline: true })]
```

Import sets `src`, `alt`, `title`, `width` and `height`, which `Image` defines. It also sets `cropTop`, `cropBottom`, `cropLeft` and `cropRight` when Word crops the image. The editor drops those four without an extension that defines them.

Without `Image`, import leaves the images out and `onWarning` receives an `unsupported` warning.

## Import

Word stores images inside the file. Convert can't give you a URL for them, so it sends each image to an upload endpoint you provide. Set it with [`imageUploadConfig`](/conversion/v3/import/docx/image-handling).

```ts
ImportDocx.configure({
  token: 'CONVERT_TOKEN',
  imageUploadConfig: {
    url: 'https://example.com/upload',
    headers: { Authorization: 'Bearer UPLOAD_TOKEN' },
  },
})
```

Convert sends each image to `url` with a `POST` request, or the `method` you set. The request has a `Content-Type` header and a `File-Name` header. The endpoint responds with JSON that has an absolute `http` or `https` address in `url`.

```json
{ "url": "https://example.com/images/photo.png" }
```

`url` must be an `http` or `https` address. `headers` must be a plain object of strings. You can also set `queryParams`. An invalid setting fails the import with an error.

Import skips an image, and `onWarning` receives a `server-warning`, in these cases.

- You didn't set `imageUploadConfig`.
- The endpoint failed or took too long to respond.
- The endpoint didn't return a usable `url`.

Import also skips images that sit behind the text, such as watermarks. It adds a floating image inline and loses its position and text wrapping.

`width` and `height` are in pixels. `alt` comes from the image's description in Word, and `title` from its title.

## Export

Export takes `src` from each `image` node and downloads it. Convert fetches public URLs. The browser uploads the images Convert can't reach: `blob:` URLs, `data:` URLs longer than 64 KB and images on your own origin.

Supported formats are PNG, JPEG, GIF, BMP and SVG. `width` and `height` set the size in pixels. Without them, export uses the size of the file. The `alt` attribute becomes the alt text in Word.

Export writes every image inline. Cropping isn't written, so a cropped image exports whole.

Export leaves out an image it can't use and reports it to `onWarning`. If it was the only content of its paragraph, the paragraph goes too. Common causes are a failed download, a format Word can't hold such as EMF, and a missing `src`. Pass `onWarning` to see which images export skipped. Set `onImageError: 'throw'` to fail the export instead. See [handle images](/conversion/v3/export/docx/usage#handle-images).

```ts
editor.commands.exportDocx({
  onImageError: 'throw',
  onWarning: (warning) => console.warn(warning.code, warning.src),
})
```

One export uploads at most 64 files, fonts and images together. An uploaded image can be at most 20 MB. See [limits](/conversion/v3/rest-api/export-docx#limitations).

## Limitations

- Import needs `imageUploadConfig`. Without it, no image arrives.
- Floating images lose their position. Export writes every image inline.
- Cropping imports as attributes and isn't written on export.
- Import skips images behind the text.
