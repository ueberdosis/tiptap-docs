Import turns Word comments into threads, with their replies and resolved state. Export writes the threads of your comments extension back as Word comments.

## Set up the editor

Add the Tiptap comments extension. Import marks the commented text with an `inlineThread` mark, or wraps commented blocks in a `blockThread` node. Both carry the thread id in `data-thread-id`.

Without those types, the text arrives without the comment anchors and `onWarning` receives an `unsupported` warning. The threads still come back in `onImport`.

Export reads threads from the provider of the comments extension, which must be named `comments`.

## Import

`onImport` receives `commentThreads`. Each thread has an `id`, a `resolved` flag and `messages` in order, the root comment first and the replies after it by date. Each message has a `body` as Tiptap JSON and `data` with the `author`, the `initials` and the dates.

```ts
editor.commands.importDocx({
  file,
  onImport: ({ commentThreads, setEditorContent }) => {
    setEditorContent()
    console.log(commentThreads.length)
  },
})
```

`commentThreads` is empty when the file has no comments.

### Live threads

Import can create the threads on the Document Server for you. It does that when all of these are true.

- The editor has a collaboration provider with a document name, on the comments extension or on a collaboration caret extension.
- The token grants write access to that document.
- The file has comments.

Import then returns the ids the Document Server gave the threads, and the same ids sit in the content. Otherwise the threads carry ids made from the file, and nothing is created. Either way the import succeeds.

### Importing again

Each created comment records the Word id it came from. When you import a file again onto the same document, import compares the file with the threads that came from a Word import.

- A comment that is already there isn't created twice.
- A changed comment updates the thread.
- A new comment becomes a new thread.
- A comment that is gone from the file is removed, when it came from a Word import.

Import never removes a comment you wrote in the editor. Keep one document for each Word file, so a new import is only compared with its own comments.

## Export

Export reads the unarchived threads from the comments provider. Each thread becomes a Word comment anchored to the same text, with its replies in order and the resolved state. The author, initials and date go with it.

The body of a comment goes through the normal conversion, so basic formatting stays. Keep comments to discussion text.

To send your own threads, pass `comments`. Pass an empty list to export no comments.

```ts
editor.commands.exportDocx({ comments: { threads: [] } })
```

## Limits

- A comment is tied to the text it marks. When that text goes, so does the anchor.
- Live threads need a collaboration provider and write access to the document.
- Comment bodies are meant for discussion text. Complex blocks in a comment may be simplified.
