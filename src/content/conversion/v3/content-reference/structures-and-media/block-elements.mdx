Blockquotes, horizontal rules and hard breaks convert in both directions. Code blocks don't convert at all. Page breaks have [their own page](/conversion/v3/content-reference/page-layout/page-breaks).

## Set up the editor

`StarterKit` has `Blockquote`, `HorizontalRule`, `HardBreak` and `CodeBlock`. No other extension or option is needed.

| Element         | Import | Export |
| --------------- | ------ | ------ |
| Blockquote      | Yes    | Yes    |
| Horizontal rule | Yes    | Yes    |
| Hard break      | Yes    | Yes    |
| Code block      | No     | No     |

## Blockquote

A paragraph with Word's Quote style imports as a `blockquote` that holds one `paragraph`. The match ignores case. Inline formatting inside the quote stays.

Export writes each paragraph inside a `blockquote` with the Quote style. Export expects paragraphs inside a blockquote. Other blocks in it, such as lists or tables, aren't written.

## Horizontal rule

Word draws a horizontal rule as a line shape. Import turns these into a `horizontalRule` node.

- The standard rule from Word's horizontal line command.
- A simple line shape, or a rectangle shape without text.

A shape that holds text isn't read as a rule.

Export writes a rule as a gray horizontal line shape that spans the text width.

## Hard break

A line break inside a paragraph imports as a `hardBreak` node. A break that ends a page or a column isn't a hard break. See [page breaks](/conversion/v3/content-reference/page-layout/page-breaks).

Export writes a `hardBreak` as a line break inside the paragraph.

## Code block

Import has no Word style that turns into a `codeBlock`. Export has no rule for the node, so a `codeBlock` and its text are left out of the file.

Inline code works. Export writes the `code` mark with Word's Code character style, and import reads it back.

## Limits

- A `codeBlock` and its text are lost on export. A [custom node rule](/conversion/v3/export/docx/custom-nodes) can render it.
