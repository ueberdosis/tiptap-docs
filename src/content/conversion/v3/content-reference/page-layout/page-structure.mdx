With Page Layout, Word's sections convert in both directions. Each Word section becomes a Page Layout section with its own page setup: paper size, orientation, margins, section columns and page numbering. Export writes each section back as a Word section.

Section columns are Word's Layout > Columns, which flow a section's text through several columns.

## What you need

[Page Layout](/features/page-layout/getting-started/overview) (`@tiptap-pro/extension-page-layout`), the extension that shows the document on pages, holds a page setup for each section, as [Sections](/features/page-layout/sections), [Page format](/features/page-layout/page-format) and [Section columns](/features/page-layout/section-columns) describe. A `sectionBreak` node starts each section and holds its setup.

Without Page Layout, import keeps the section breaks and their setup as [preserved content](/conversion/v3/content-reference/overview#what-the-editor-keeps), with a `preserved` warning. When you add Page Layout and load the saved document, it opens with its pages.

Without Page Layout, export writes one section from the `pageSize` and `pageMargins` options: A4 with 2.54cm top and bottom and 3.17cm side margins by default. [Page size and margins](/conversion/v3/export/docx/editor-extension#page-size-and-margins) shows the options.

## Import

Import puts a `sectionBreak` node in front of each section, the first at the very start of the document. Each holds its section's setup in these attributes, with lengths in pixels:

| Setting              | Attributes                                                                                   |
| -------------------- | -------------------------------------------------------------------------------------------- |
| Paper size           | `formatId`, `pageWidth`, `pageHeight`                                                        |
| Orientation          | `orientation`                                                                                |
| Margins              | `marginTop`, `marginRight`, `marginBottom`, `marginLeft`                                     |
| Section break kind   | `kind`: `nextPage` or `continuous`                                                           |
| Section columns      | `columnCount`, `columnGaps`, `columnWidths`, `columnRule` for the line between columns       |
| Page numbering       | `pageNumbering`, an object with `format`, `start` and `chapter`                              |
| Different first page | `differentFirstPage`                                                                         |
| Note settings        | `notePlacement`, `footnoteNumbering`, `endnoteNumbering`: where notes go, format and restart |
| Page color           | `themePage`, a hex color such as `#fff8e8`, on the first section only                        |
| Header and footer    | See [Headers and footers](/conversion/v3/content-reference/page-layout/headers-footers)      |

`columnGaps` holds the space after each column but the last, in pixels. `columnWidths` holds one share of the text width for each column, such as `[0.6, 0.4]`, so the widths follow the paper size.

`pageNumbering.format` is the number format, such as `decimal` or `lowerRoman`, and `start` is the first page number, or `null` to continue from the section before.

`chapter` is Word's "Include chapter number": `null`, or an object with the heading `level` that starts a chapter and the `separator` between the chapter and page numbers, such as `hyphen` for `2-5`.

A body without a section setup imports as one US Letter section with 1-inch margins. An "at least" top or bottom margin imports as a fixed margin of the same size.

A section's columns are settings on its section break. Its blocks aren't wrapped in column nodes, and Page Layout flows them through the columns, as [Section columns](/features/page-layout/section-columns) explains.

The document's page color goes on the first section when Word stores a hex color. A page color of `auto`, or a theme color without a hex value, gives none.

Two settings change to ones Page Layout has, each with a warning:

- A section that starts on an even or odd page starts on the next page, with `section-start-even-odd`.
- The binding gutter of the margins is left out, with `gutter-dropped`.

Import ignores a section break inside a table, with `section-in-table-cell`, because Word doesn't end a section there.

Two more settings change without a warning, which is a known limit that is being fixed:

- A section that starts in the next column starts on the next page.
- A custom Word number format, such as `001`, imports as the default for its kind: decimal for pages and footnotes, lowercase Roman for endnotes.

## Export

Export starts a Word section at each `sectionBreak`. It writes the settings in the [Import](#import) table back, with two exceptions. The note settings don't export, and the page color follows the rules in [Page color](#page-color).

The paper size comes from the format's width and height, and the chapter number keeps its `separator`.

[Headers and footers](/conversion/v3/content-reference/page-layout/headers-footers) describes how a section's headers and footers export.

A `nextPage` section starts a new page. A `continuous` one stays on the sheet and takes the paper of the section before it, because paper can't change halfway down a sheet.

Page numbers use the section's number format, such as `decimal` or `lowerRoman`. A format without an exact Word match is written as the closest one, with an `unsupported` warning.

An imported document starts with a `sectionBreak`. A document written in the editor may not, and its content before the first `sectionBreak` uses the editor's page setup, which [Page format](/features/page-layout/page-format) sets.

The `pageSetup` option of `exportDocx()` replaces the editor's page setup for one export, so it changes only the content before the first `sectionBreak`, as [Export DOCX API](/conversion/v3/export/docx/api) lists. With Page Layout, `pageSize` and `pageMargins` have no effect.

### Page color

Word has one page color for the whole document. Export writes the `themePage` of the first section, such as one from an import. To set it yourself, pass `pageColor` to the command of an editor set up as in [Export DOCX](/conversion/v3/export/docx/editor-extension). `pageColor` wins over `themePage`:

```ts
editor.commands.exportDocx({ pageColor: '#fff8e8' })
```

Export drops a different page color on a later section, with an `unsupported` warning. It also drops the text and accent colors Page Layout can give a section, `themeText` and `themeAccent`, with one `unsupported` warning for each kind. Word prints the page color only with its print background setting on.

## Limits

- Word has one page color per document and no section text or accent colors, so export drops them.
- Import leaves out the binding gutter, and starts an even or odd page section on the next page.
- Without a warning, import starts a next-column section on the next page, and reads a custom number format as the default.
- Export doesn't write a section's note settings.
