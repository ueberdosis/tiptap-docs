A manual page break imports as a `pageBreak` node and exports back as a Word page break. Page breaks that Word worked out by itself aren't in the file, so they don't import.

## Set up the editor

Page Layout has a `pageBreak` node and the `insertPageBreak` command. See [breaks](/pages/v2/core-concepts/breaks). Page Layout stores the break inside a paragraph, where the author inserted it.

Without Page Layout, use `@tiptap-pro/extension-pagebreak`, which defines a `pageBreak` block node.

Without a `pageBreak` node, import leaves the breaks out and `onWarning` receives an `unsupported` warning.

## Import

Import turns a page break in Word into a `pageBreak` node.

- A paragraph that holds only a page break becomes a single `pageBreak` node.
- A paragraph with text and a page break becomes the paragraph, followed by a `pageBreak` node. A break in the middle of the paragraph moves to the end of it.

```json
{ "type": "pageBreak" }
```

Import returns the node as its own block between paragraphs. Page Layout holds its break inside a paragraph.

Import doesn't read these.

- The soft breaks Word saves as layout hints.
- The paragraph setting that starts a paragraph on a new page.
- Column breaks.
- A page break inside a table cell, which is dropped.

For section breaks, see [page structure](/conversion/v3/content-reference/page-layout/page-structure).

## Export

Export writes a `pageBreak` node as a Word page break. A `pageBreak` between blocks becomes a paragraph with the break in it. A `pageBreak` inside a paragraph writes the break at that place.

A `columnBreak` node inside a paragraph exports as a Word column break.

## Limits

- With Page Layout, a page break in the file can make the import fail. The imported break is a block, and the break of Page Layout sits inside a paragraph.
- Soft page breaks and the "page break before" paragraph setting don't import.
- Column breaks export, but they don't import.
