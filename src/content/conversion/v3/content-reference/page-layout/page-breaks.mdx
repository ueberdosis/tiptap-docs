A manual page break imports as a `pageBreak` node and exports back as a Word page break. Page breaks that Word worked out by itself aren't in the file, so they don't import.

## Set up the editor

Page Layout has a `pageBreak` node and the `insertPageBreak` command. See [breaks](/pages/v2/core-concepts/breaks). Page Layout stores the break inside a paragraph, where the user inserted it.

To export without Page Layout, use `@tiptap-pro/extension-pagebreak`, which defines a `pageBreak` block node.

Without Page Layout, import leaves page and column breaks out and `onWarning` receives an `unsupported` warning for each type. This happens even when the editor has a `pageBreak` node.

## Import

Import keeps a page break inside the paragraph, where Word has it, as a `pageBreak` node. A column break becomes a `columnBreak` node the same way.

```json
{
  "type": "paragraph",
  "content": [{ "type": "text", "text": "End of part one" }, { "type": "pageBreak" }]
}
```

A paragraph set to start on a new page gets a `pageBreak` node at its start.

Import doesn't read the soft breaks Word saves as layout hints.

For section breaks, see [page structure](/conversion/v3/content-reference/page-layout/page-structure).

## Export

Export writes a `pageBreak` node as a Word page break. A `pageBreak` between blocks becomes a paragraph with the break in it. A `pageBreak` inside a paragraph writes the break at that place.

A `columnBreak` node inside a paragraph exports as a Word column break.

## Limitations

- Soft page breaks don't import.
- Without Page Layout, page and column breaks don't import.
