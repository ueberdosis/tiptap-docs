A page break the user inserted in Word imports as a `pageBreak` node and exports back as a Word page break. A column break converts the same way, as a `columnBreak` node. The breaks Word works out while laying out pages aren't content, so they don't import.

## What you need

[Page Layout](/features/page-layout/breaks) has inline `pageBreak` and `columnBreak` nodes and the `insertPageBreak` command. It keeps a break inside its paragraph.

Without Page Layout, `@tiptap-pro/extension-pagebreak` has a block `pageBreak` node, which import and export both use. A page break inside a paragraph then splits it, with the `pageBreak` between the halves.

An editor with no `pageBreak` or `columnBreak` node keeps each break in the text as [preserved content](/conversion/v3/content-reference/overview#what-the-editor-keeps), with a `preserved` warning. The break is visible only with the CSS that page gives for preserved content. `editor.getText()` returns a space for it, so the words around it stay apart.

## Import

Import keeps a page break inside its paragraph, where Word has it:

```json
{
  "type": "paragraph",
  "content": [{ "type": "text", "text": "End of part one" }, { "type": "pageBreak" }]
}
```

A column break becomes a `columnBreak` node the same way. A paragraph set to start on a new page, directly or by its style, gets a `pageBreak` at its start. A page break in a table cell stays in the cell's paragraph.

Import doesn't read the soft page breaks Word saves from its last layout. Section breaks are on [Page structure](/conversion/v3/content-reference/page-layout/page-structure).

## Export

A `pageBreak` between blocks, such as the block of `@tiptap-pro/extension-pagebreak`, exports as a paragraph with a Word page break. A `pageBreak` inside a paragraph writes the break at that place. A `columnBreak` exports as a Word column break.

## Limits

- Soft page breaks don't import, because they are Word's layout, not content.
