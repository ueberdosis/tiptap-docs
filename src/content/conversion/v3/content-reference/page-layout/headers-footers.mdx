Export writes the headers and footers of [Page Layout](/features/page-layout/header-and-footer). Import brings the headers and footers of a `.docx` file into Page Layout, one set for each section.

## Set up the editor

Page Layout holds headers and footers in the document, one set for each section. Without Page Layout, export writes no headers or footers. Export ignores the removed `headers` and `footers` options and reports an `unsupported` warning.

See [Get started with Page Layout](/features/page-layout/getting-started/overview) to add it.

## Import

Import puts the headers and footers of each section into the section's `sectionBreak` node, as `pageFurniture` nodes. With Page Layout, `setEditorContent` writes them with the rest of the document.

- Each section keeps its default, first page and even page versions of the header and of the footer.
- When Word shows different odd and even pages, the default version is the one for odd pages.
- The section break also carries different first page, different odd and even pages, and the distance of the header and footer from the page edge.

Word's page fields, `PAGE`, `NUMPAGES` and `SECTIONPAGES`, become `pageNumber` nodes with the `kind` `page`, `pages` or `sectionPages`, so they keep counting. Other fields, such as dates and authors, come back as the text Word last showed. They no longer update.

Without Page Layout, import leaves the headers and footers out. See [import without Page Layout](/conversion/v3/import/docx/without-page-layout).

## Export

Export reads the headers and footers from the sections of the Page Layout document.

- Each section can have a default, a first page and an even page version of the header and of the footer.
- A section without its own header uses the previous section's header, as in Word's link to previous.
- Each section sets its own different first page and different odd and even pages. Word has one odd and even switch for the whole file, so export turns it on when any section needs it.
- The distance from the page edge comes from each section. The default is 1.25cm.

Headers and footers hold rich content, such as paragraphs, tables and images. Export converts them like the body.

To format them differently from the body, pass [`headerFooterOverrides`](/conversion/v3/export/docx/usage#headers-footers-and-page-layout). It takes the same six override fields as the body. A field you leave out uses the body value.

```ts
editor.commands.exportDocx({
  headerFooterOverrides: { paragraphOverrides: { spacing: { after: 0 } } },
})
```

### Page numbers

A `pageNumber` node in a header or footer exports as a live field, so Word counts the pages itself. Its `kind` picks the field.

| `kind`         | Word field                         |
| -------------- | ---------------------------------- |
| `page`         | The page number                    |
| `pages`        | The number of pages                |
| `sectionPages` | The number of pages in the section |

See [page numbers](/features/page-layout/page-numbers#a-page-number-in-a-header-or-footer) for how to add one.

## Limitations

- Without Page Layout, import leaves headers and footers out.
- Fields other than page numbers import as plain text and no longer update.
- Without Page Layout, export writes no headers or footers.
