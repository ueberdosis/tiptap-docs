With Page Layout, Word's headers and footers convert in both directions, one set for each section. A section is a part of the document with its own page setup, as in Word. Page number fields stay live fields.

## What you need

[Page Layout](/features/page-layout/getting-started/overview) (`@tiptap-pro/extension-page-layout`), the extension that shows the document on pages, holds headers and footers in the document. [Header and footer](/features/page-layout/header-and-footer) shows how to set it up.

The `sectionBreak` node that starts a section holds its headers and footers as `pageFurniture` nodes, Page Layout's node for one header or footer. A page number in them is a `pageNumber` node.

Without Page Layout, import keeps each section's headers and footers as [preserved content](/conversion/v3/content-reference/overview#what-the-editor-keeps) at the start of the section, with a `preserved` warning. When you add Page Layout and load the saved document, it opens with its pages, headers and footers.

An editor without Page Layout has no headers or footers to export.

## Import

Import puts each section's headers and footers into its `sectionBreak`, as `pageFurniture` nodes with a `zone` of `header` or `footer` and one of these `slot` values:

| `slot`    | Shows on                                                       |
| --------- | -------------------------------------------------------------- |
| `default` | Every page, or the odd pages when odd and even pages differ    |
| `first`   | The first page of the section, when `differentFirstPage` is on |
| `even`    | The even pages, when `differentOddEven` is on                  |

The section break also carries `differentFirstPage`, `differentOddEven`, and the header and footer distance from the page edge as `headerOffset` and `footerOffset`, in pixels.

A header or footer that several sections share is converted once. A Word section set to "Link to Previous" gets no header or footer of its own, and shows the one of the section before it.

Word's page number fields, `PAGE`, `NUMPAGES` and `SECTIONPAGES`, become `pageNumber` nodes, so they keep counting, in headers, footers and the body. [Export](#export) lists their `kind` values. Other fields, such as dates, import as the text Word last showed and no longer update.

## Export

Export reads the headers and footers from the `pageFurniture` nodes of each section's `sectionBreak`:

- A section can have a `default`, `first` and `even` version of its header and of its footer.
- A section without its own version uses the previous section's. A section can name another section's version instead, with an `id` in its `headerDefaultLink`, `headerFirstLink`, `headerEvenLink` or matching `footer` attribute.
- Each section sets its own different first page.
- Word has one odd and even switch for the whole file. Export turns it on when any section has `differentOddEven`. A section without it then gets its `default` version on the even pages too.
- The header and footer distance comes from each section, 1.25cm by default.

Headers and footers hold rich content, such as tables and images, and convert like the body.

A `pageFurniture` node can set a distance of its own in `offset`. When the versions a section shows have different distances, export uses the section's distance, with an `unsupported` warning, because Word keeps one per section.

`headerFooterOverrides` formats headers and footers differently from the body, with the same override fields, such as `paragraphOverrides`. A field you leave out uses the body's value. [Export styles and fonts](/conversion/v3/export/docx/styles#header-and-footer-formatting) lists the fields. The example runs on an editor set up as in [Export DOCX](/conversion/v3/export/docx/editor-extension):

```ts
editor.commands.exportDocx({
  headerFooterOverrides: { paragraphOverrides: { spacing: { after: 0 } } },
})
```

A `pageNumber` node exports as a live Word field, which its `kind` picks:

| `kind`         | Word field                         |
| -------------- | ---------------------------------- |
| `page`         | The page number                    |
| `pages`        | The number of pages                |
| `sectionPages` | The number of pages in the section |

[Page numbers](/features/page-layout/page-numbers#a-page-number-in-a-header-or-footer) shows how to add one.

## Limits

- Fields other than page numbers import as plain text.
- Word keeps one header and footer distance per section, and one odd and even switch per file.
