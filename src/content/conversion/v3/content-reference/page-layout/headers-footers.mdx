Export writes the headers and footers of [Page Layout](/pages/v2/core-concepts/header-and-footer). Import returns the headers and footers of a Word file to you, and doesn't put them in the editor.

## Set up the editor

Page Layout holds headers and footers in the document, one set for each section. Without Page Layout, export writes no headers or footers. The `headers` and `footers` export options are dropped with an `unsupported` warning.

See [Get started with Page Layout](/pages/v2/getting-started/overview) to add it.

## Import

[`onImport`](/conversion/v3/import/docx/api#importcontext) receives each header and footer as Tiptap JSON, or `null` when the file doesn't have it.

| Field                                   | Holds                          |
| --------------------------------------- | ------------------------------ |
| `header` and `footer`                   | The default version            |
| `headerFirstPage` and `footerFirstPage` | The version for the first page |
| `headerEven` and `footerEven`           | The version for even pages     |
| `headerOdd` and `footerOdd`             | Always `null`                  |

When Word shows different odd and even pages, the default version is the one for odd pages. Read `header` for odd pages, not `headerOdd`.

```ts
editor.commands.importDocx({
  file,
  onImport: ({ header, footer, setEditorContent }) => {
    setEditorContent()
    console.log(header, footer)
  },
})
```

Import returns one set for the whole document. It takes the set from the last section. If that section has none, it takes the first section that has one. A file with different headers in each section doesn't get a set for each.

`setEditorContent` writes the body and the notes into the document. It doesn't write headers or footers. To show an imported header in Page Layout, write it into the document yourself. Page Layout keeps each header inside the section break of its section.

Page number fields come back as the number Word last showed, as plain text. Other fields, such as dates and authors, do the same. They no longer update.

## Export

Export reads the headers and footers from the sections of the Page Layout document.

- Each section can have a default, a first page and an even page version of the header and of the footer.
- A section without a header of its own shows the one of the section above, as in Word's link to previous.
- Different first page and different odd and even pages are set for each section. Word has one odd and even switch for the whole file, so export turns it on when any section needs it.
- The distance from the page edge comes from each section. The default is 1.25 cm.

Headers and footers hold rich content, such as paragraphs, tables and images. Export converts them like the body.

To format them differently from the body, pass [`headerFooterOverrides`](/conversion/v3/export/docx/usage#headers-footers-and-page-layout). It takes the same six override fields as the body. A field you leave out uses the body value.

```ts
editor.commands.exportDocx({
  headerFooterOverrides: { paragraphOverrides: { spacing: { after: 0 } } },
})
```

### Page numbers

A `pageNumber` node in a header or footer exports as a live field, so Word counts the pages itself. Its `kind` picks the field.

| `kind`         | Word field                         |
| -------------- | ---------------------------------- |
| `page`         | The page number                    |
| `pages`        | The number of pages                |
| `sectionPages` | The number of pages in the section |

See [page numbers](/pages/v2/core-concepts/page-numbers#a-page-number-in-a-header-or-footer) for how to add one.

## Limits

- Import returns one set of headers and footers, and doesn't write them into the editor.
- Page number fields import as plain text and no longer update.
- Without Page Layout, export writes no headers or footers.
