Font family and font size are attributes of the `textStyle` mark. Import sets them from Word and export writes them back, converting sizes between Word's points and the editor's pixels.

## What you need

Add `TextStyle` with `FontFamily` and `FontSize`, all three from `@tiptap/extension-text-style`:

```ts
import StarterKit from '@tiptap/starter-kit'
import { FontFamily, FontSize, TextStyle } from '@tiptap/extension-text-style'

const extensions = [StarterKit, TextStyle, FontFamily, FontSize]
```

`TextStyleKit` from the same package adds these three together with `Color`, `BackgroundColor` and `LineHeight`. Without the `textStyle` mark, import keeps it as preserved content, with a [`preserved` warning](/conversion/v3/import/docx/warnings-and-errors), and the text shows in the editor's font until you add the extensions. [What converts](/conversion/v3/content-reference/overview#what-the-editor-keeps) explains preserved content.

Letter spacing arrives as the `letterSpacing` attribute of `textStyle`, which no extension defines, so the editor doesn't show it. Import keeps it in the mark's `preservedAttrs` attribute, from `@tiptap-pro/extension-preserved-content`, which the ImportDocx extension adds on its own.

To show it, define `letterSpacing` on `textStyle` in an extension of your own, as [Show spacing and indents](/conversion/v3/content-reference/text-and-formatting/paragraphs#show-spacing-and-indents) does for paragraph spacing.

## Import

Import reads the font and size of each Word run, a stretch of text with the same formatting:

- The font family is the run's font for Latin text (Word's ASCII font), or else its high ANSI font. Import stores the name as written, such as `Courier New`.
- The font size is in half-points in Word. Import converts it to whole pixels and stores a string such as `16px`.
- Letter spacing becomes `letterSpacing` in pixels, such as `0.67px`. Import leaves it out when it is 0.

When a run doesn't set its font or size, the paragraph's style and the document defaults fill them in.

| Word size | Import |
| --------- | ------ |
| 12pt      | `16px` |
| 14pt      | `19px` |
| 18pt      | `24px` |

## Export

Export reads `fontFamily` and `fontSize` from the `textStyle` mark:

- The font family keeps the first name of a comma-separated list, without quotes. Word has no fallback fonts, so `"Arial, Helvetica, sans-serif"` exports as `Arial`.
- A size without a unit, or in `px`, is pixels. `pt` is points. `rem` and `em` use a 16px base.
- Export leaves out a size it can't read.

Text without a font or size mark gets the font and size your editor renders, because export measures your editor's CSS, as [Paragraphs](/conversion/v3/content-reference/text-and-formatting/paragraphs#export) explains. Export doesn't read `letterSpacing` from the mark either. It writes the letter spacing it measures in the CSS.

To embed a font Word may not have, use the `fonts` or `embedFonts` option, as [Embed fonts](/conversion/v3/export/docx/styles#embed-fonts) shows.

## Limits

Import rounds sizes to whole pixels. A size such as 14pt, which is 18.66px, comes in a little larger, so a round trip can change a size by a fraction of a point.

Import doesn't read a font set through the document's theme, which is how Word's default template sets the body font. Those runs get no `fontFamily`, without a warning. This is a known limit that is being fixed.

A symbol inserted with Word's Insert Symbol (`w:sym`), such as a Wingdings arrow, imports as its character with the symbol's font as the `fontFamily` of a `textStyle` mark. Symbol fonts put their characters at `U+F000` to `U+F0FF`, so the symbol shows correctly only where that font is installed.
