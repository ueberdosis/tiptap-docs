Font family and font size are attributes on the `textStyle` mark. Import sets them from Word, and export writes them back. Sizes convert between Word's points and the editor's pixels.

## Set up the editor

Add `TextStyle` with `FontFamily` and `FontSize`. All three come from `@tiptap/extension-text-style`.

```ts
import StarterKit from '@tiptap/starter-kit'
import { FontFamily, FontSize, TextStyle } from '@tiptap/extension-text-style'

const extensions = [StarterKit, TextStyle, FontFamily, FontSize]
```

`TextStyleKit` from the same package adds these and `Color`, `BackgroundColor` and `LineHeight` together. See [text color and highlight](/conversion/v3/content-reference/text-and-formatting/text-color-highlight).

Without a `textStyle` mark, the font and size of every run are left out of the import, and `onWarning` receives an `unsupported` warning.

## Import

Import reads the font and size of each run.

- The font family is the run's ASCII font. If there is none, it is the high ANSI font. The name is stored as written, for example `Courier New`.
- The font size is in half-points in Word. Import converts it to whole pixels and stores a string such as `16px`.
- Letter spacing becomes `letterSpacing` in pixels, such as `0.67px`.

The font and size of the paragraph's style and the document defaults fill in what a run doesn't set. Most runs therefore carry both.

| Word size | Import |
| --------- | ------ |
| 12pt      | `16px` |
| 14pt      | `19px` |
| 18pt      | `24px` |

Import rounds to whole pixels. A size such as 14pt, which is 18.66px, comes back a little larger.

None of these extensions defines `letterSpacing`, so the editor drops it.

## Export

Export reads `fontFamily` and `fontSize` from the `textStyle` mark.

- The font family keeps the first name of a comma-separated list, without quotes. Word has no fallback lists, so `"Arial, Helvetica, sans-serif"` exports as `Arial`.
- A size with no unit, or in `px`, is pixels. `pt` is points. `rem` and `em` resolve against a 16px base.
- A size it can't read is ignored, and a warning appears in the console.

Text without a font or size mark takes the editor's rendered font and size, because export measures your editor's CSS. See [paragraphs](/conversion/v3/content-reference/text-and-formatting/paragraphs#paragraph-styles).

Export doesn't read `letterSpacing` from the mark. It measures letter spacing from the editor's CSS and writes that.

For fonts that Word doesn't have, set `embedFonts` or `fonts` on the export command.

## Limits

- Pixel rounding on import can change a size by a fraction of a point after a round trip.
- The editor drops `letterSpacing` unless you define it on `textStyle`.
