A Word checkbox list imports as `taskList` and `taskItem` nodes, with the ticked state kept. Export writes a task item as a Word checkbox that stays clickable in Word.

## Set up the editor

Add `TaskList` and `TaskItem` from `@tiptap/extension-list`. Turn on `nested` so imported sublists are valid.

```ts
import StarterKit from '@tiptap/starter-kit'
import { TaskItem, TaskList } from '@tiptap/extension-list'

const extensions = [StarterKit, TaskList, TaskItem.configure({ nested: true })]
```

Without both nodes, `'auto'` leaves checkbox lists as bullet or numbered lists and loses the ticked state.

## Import

The [`taskLists`](/conversion/v3/import/docx/task-lists) option decides what happens to checkbox lists. Set it on `ImportDocx.configure` or on the `importDocx` command.

| Value      | Result                                                             |
| ---------- | ------------------------------------------------------------------ |
| `'auto'`   | Task lists when the editor has `taskList` and `taskItem`. Default. |
| `'import'` | Always task lists.                                                 |
| `'ignore'` | Bullet or numbered lists, as Word draws the markers.               |

### Which checkboxes convert

Word writes a checkbox in three ways.

- A box character as the list marker. These are Wingdings box characters, and the Unicode ballot boxes `U+2610` for unticked, and `U+2611` and `U+2612` for ticked. The ticked state comes from the character.
- A checkbox content control, which modern Word inserts. The ticked state comes from the control.
- A legacy form-field checkbox. The state comes from the field, or from its default when it has no current value.

A content control or form field converts when it is the only checkbox in the paragraph and comes before the text. A paragraph without list numbering also needs a hanging indent. A row such as `Yes ☐ No ☐`, or a box after a sentence, imports as it is.

Checkmark characters such as Wingdings `✔` don't convert. In Word they're decoration.

A numbered list item that starts with a single checkbox control becomes a task item, and import drops its number. Import with `taskLists: 'ignore'` to keep the numbers.

## Export

A task item exports as a Word checkbox followed by its text. Readers can tick and untick it in Word, and the state you exported is what they see.

Items use Word's List Paragraph style with a hanging indent. Nested task lists get a deeper indent. When an item holds several blocks, the checkbox goes on the first block and the rest line up under the text.

Export always writes a checkbox control. A document that arrived with box-character markers leaves with controls. Both import again as task lists.

## Style the list

`TaskItem` renders each item as `<li data-type="taskItem" data-checked="true">`, with the checkbox in a `<label>` and the content in a `<div>`. Style those parts.

```css
.tiptap ul[data-type='taskList'] li[data-checked='true'] > div > p {
  color: #6b7280;
  text-decoration: line-through;
}

.tiptap ul[data-type='taskList'] li > label input {
  accent-color: #7c3aed;
}
```

## Limitations

- A checkbox outside a list isn't converted.
- Export writes control checkboxes only, never box characters.
