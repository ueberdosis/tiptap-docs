A Word checkbox list imports as `taskList` and `taskItem` nodes, with the ticked state kept. On export, a task item becomes a Word checkbox the user can tick in Word.

## What you need

Add `TaskList` and `TaskItem` from `@tiptap/extension-list`, and set `nested: true` on `TaskItem`, so a task item can hold a nested checkbox list:

```ts
import StarterKit from '@tiptap/starter-kit'
import { TaskItem, TaskList } from '@tiptap/extension-list'

const extensions = [StarterKit, TaskList, TaskItem.configure({ nested: true })]
```

With the default `nested: false`, a task item holds only paragraphs. Import then puts the items of a nested checkbox list into their parent item as plain paragraphs, without checkboxes, with a `restructured` warning. `onWarning`, an option of `ImportDocx.configure()`, receives it, as [Warnings and errors](/conversion/v3/import/docx/warnings-and-errors) shows.

## Import

The `taskLists` option decides what a checkbox list becomes. Set it on `ImportDocx.configure()`, or on one `importDocx` call, which wins. In this example, `CONVERSION_TOKEN` stands for your Conversion token, `editor` for your editor and `file` for the `.docx` file the user picked:

```ts
import { ImportDocx } from '@tiptap-pro/extension-import-docx'

const importExtension = ImportDocx.configure({
  token: CONVERSION_TOKEN,
  taskLists: 'import',
})

editor.commands.importDocx({ file, taskLists: 'ignore' })
```

The option takes these values:

| Value      | Result                                                 |
| ---------- | ------------------------------------------------------ |
| `'auto'`   | The default. Task lists, the same as `'import'`.       |
| `'import'` | Task lists, also in an editor without the two nodes.   |
| `'ignore'` | Bullet or numbered lists, with the markers Word draws. |

In an editor without `taskList` and `taskItem`, `'auto'` and `'import'` keep the task lists as preserved content, ticked states included, with a `preserved` warning that names the `nodeType`. They become task lists once you add the extensions, as [What converts](/conversion/v3/content-reference/overview#what-the-editor-keeps) explains.

### Which checkboxes convert

Word writes a checkbox in three ways, and import reads all of them:

- **A box character as the list marker.** These are the Wingdings boxes and the Unicode ballot boxes `U+2610` for unticked, and `U+2611` and `U+2612` for ticked. The ticked state comes from the character.
- **A checkbox content control**, which current versions of Word insert. The ticked state comes from the control.
- **A legacy form-field checkbox.** The ticked state comes from the field, or from its default when it has no current value.

A content control or form field converts only when it is the only checkbox in the paragraph and comes before the text. So a row such as `Yes ☐ No ☐`, or a box after a sentence, imports as text.

A checkbox in a paragraph without list numbering also imports as text, unless the paragraph has a hanging indent.

Checkmark characters, such as the Wingdings `✔`, don't convert, because Word uses them as decoration.

A numbered list item that starts with a single checkbox becomes a task item, and loses its number. To keep the numbers, import with `taskLists: 'ignore'`.

## Export

A task item exports as a Word checkbox control followed by its text. The user can tick and untick it in Word, and it shows the state you exported.

The items use Word's List Paragraph style with a hanging indent, and a nested task list gets a deeper indent. When an item holds several blocks, the checkbox goes on the first block, and the other blocks line up under its text.

Export writes every checkbox as a control, so a file that arrived with box-character markers leaves with controls. Both kinds import again as task lists.
