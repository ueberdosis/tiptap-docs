Text color imports as the `color` attribute of the `textStyle` mark, and Word's highlight and character shading import as the `highlight` mark. Export writes both back as Word run formatting.

## What you need

Text color needs `TextStyle` and `Color`. Highlight needs `Highlight` with `multicolor: true`:

```ts
import StarterKit from '@tiptap/starter-kit'
import Highlight from '@tiptap/extension-highlight'
import { Color, TextStyle } from '@tiptap/extension-text-style'

const extensions = [StarterKit, TextStyle, Color, Highlight.configure({ multicolor: true })]
```

Without `multicolor`, `Highlight` has no `color` attribute, so every highlight shows in its default color. Without `Color`, text shows in the editor's text color.

In both cases, import keeps the `color` in the mark's `preservedAttrs` attribute, as [What converts](/conversion/v3/content-reference/overview#what-the-editor-keeps) explains. The color comes back when you add `Color` or turn on `multicolor`, and export still writes it.

Without the `textStyle` or `highlight` mark, import keeps that mark as preserved content, with a [`preserved` warning](/conversion/v3/import/docx/warnings-and-errors), and the text shows without the color until you add the extension. [What converts](/conversion/v3/content-reference/overview#what-the-editor-keeps) explains preserved content.

`TextStyleKit` from `@tiptap/extension-text-style` adds `TextStyle`, `Color`, `BackgroundColor`, `FontFamily`, `FontSize` and `LineHeight` in one step.

## Import

Import turns these Word settings into marks:

| Word setting               | Result                                   |
| -------------------------- | ---------------------------------------- |
| Font color `FF0000`        | `textStyle` mark with `color: "#FF0000"` |
| Highlight `yellow`         | `highlight` mark with `color: "yellow"`  |
| Shading with fill `00FFFF` | `highlight` mark with `color: "#00FFFF"` |

When a run, a stretch of text with the same formatting, doesn't set a color or shading, the paragraph's style and the document defaults fill it in. Import skips the font color `auto`, and shading with a fill of `auto` or white.

A highlight Word switches off (`w:highlight="none"`) gives no `highlight` mark.

## Export

Export turns a color into six hex digits, and reads these forms:

- Hex, such as `#FF0000`, `#F00` or `#FF0000AA`
- `rgb()` and `rgba()`
- One of these 20 color names: `black`, `blue`, `brown`, `cyan`, `gray`, `green`, `indigo`, `lime`, `magenta`, `maroon`, `navy`, `olive`, `orange`, `pink`, `purple`, `red`, `teal`, `violet`, `white` and `yellow`

Export skips a fully transparent color, and leaves out a color it can't read.

A `highlight` mark exports by its color:

- A color that is a Word highlight name, such as `yellow` or `cyan`, becomes that highlight.
- Any other readable color becomes character shading with that fill.
- A mark without a color, or with a color export can't read, becomes a yellow highlight.

The `backgroundColor` attribute of `textStyle`, from `BackgroundColor`, also exports as character shading. When a highlight becomes shading and the same text has a `backgroundColor`, the highlight's shading wins.

## Limits

A highlight in a color that isn't a Word highlight name, such as `#FFC0CB`, is shading in Word. It imports again as a `highlight` mark with the hex color. A `backgroundColor` is shading in Word too, so it also imports again as a `highlight` mark, not as `backgroundColor`.

Import has these known limits, which give no warning and are being fixed:

- A font color set only as a theme color, without a hex value, is skipped.
- The color and shading of a Word character style, such as a style for emphasis, don't apply.
