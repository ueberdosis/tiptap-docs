A Word tab imports as four spaces, and a tab character in the editor exports as a Word tab.

## What you need

Tabs need no extension, because a tab imports as plain text in the paragraph.

## Import

Each tab in a Word run becomes four spaces in the text, at the start of a paragraph and in the middle of one.

The editor shows those spaces because Tiptap's default editor styles set `white-space: break-spaces`, which keeps runs of spaces. If your CSS sets `white-space: normal` on paragraphs, the spaces collapse, and an indent made with a tab looks like it vanished.

## Export

Export writes a tab character in the text as a Word tab.

The `defaultTabStop` option sets the distance between Word's default tab stops, in twips, so `720` is half an inch. In this example, `editor` is an editor with `ExportDocx`, as [Export DOCX](/conversion/v3/export/docx/editor-extension) sets it up:

```ts
editor.commands.exportDocx({ defaultTabStop: 720 })
```

Without `defaultTabStop`, export uses the `tab-size` your editor's CSS renders.

## Limits

A tab doesn't round-trip, because it imports as four spaces and exports as four spaces.

Import doesn't read tab stops, so left, center, right, decimal and bar stops are lost. Export writes no tab stop positions from the document. The `paragraphOverrides` option can set `tabStops` for every paragraph, as [Export styles and fonts](/conversion/v3/export/docx/styles) shows.

Import drops a positional tab (Word's `w:ptab`) without a warning, so the text on both sides runs together. This is a known limit that is being fixed.
