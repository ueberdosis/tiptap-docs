A Word heading is a paragraph with a heading style. It imports as a `heading` node with a `level`, and exports back as the matching Word heading.

## Set up the editor

`StarterKit` has the `Heading` node, with levels 1 to 6. Add `TextAlign` for alignment, and the extensions for the text formatting you want to keep. See [text alignment](/conversion/v3/content-reference/text-and-formatting/text-alignment) and [font family and size](/conversion/v3/content-reference/text-and-formatting/font-family-size).

Spacing and indentation arrive as the same attributes as on a paragraph. The editor keeps them only when an extension defines them. See [paragraphs](/conversion/v3/content-reference/text-and-formatting/paragraphs#set-up-the-editor).

## Import

A paragraph becomes a heading when its style name is `Heading` followed by a number, such as `Heading 2`. The match ignores case and the space, so `heading2` works too.

```json
{
  "type": "heading",
  "attrs": { "level": 2, "textAlign": "center" },
  "content": [
    {
      "type": "text",
      "text": "My heading",
      "marks": [{ "type": "bold" }]
    }
  ]
}
```

The heading style's font, size, color and bold arrive as marks on the text. Without a `textStyle` mark in the editor, the font, size and color are left out with an `unsupported` warning.

The experimental [`cssStyles`](/conversion/v3/import/docx/css-styles) import option also returns the style catalog as CSS. Use it when you want `h1` to look like Word's Heading 1.

### Title, Subtitle and custom styles

Import decides by the style name only. A paragraph with the style Title, Subtitle or any other name imports as a `paragraph`. That includes a custom style based on Heading 1.

The formatting of those styles still arrives as marks and attributes, so the paragraph can look like a heading. The style name isn't kept. To get a heading, rename the style to `Heading 1` or `Heading 2` in Word before you import.

### Levels 7 to 9

Import keeps the number as `level`, so Heading 7 is `level` 7. The `Heading` node from `StarterKit` allows levels 1 to 6, and it draws any other level as `<h1>`.

## Export

Export reads `level` and writes a paragraph in the Word style Heading 1 to Heading 6. Alignment and inline formatting come along.

A heading with `level` 7 to 9 exports as a normal paragraph. Keep headings within 1 to 6 if the Word styles matter.

### Heading styles

Export measures the CSS your mounted editor renders for `h1` to `h6` and writes it into the Word heading styles. So the exported headings follow your editor's look, and not the style the file had when you imported it.

A headless or unmounted editor has nothing to measure. Heading 1 then starts as bold blue Arial at 16pt. To set your own, pass [`styleOverrides`](/conversion/v3/export/docx/usage#match-your-editors-formatting) as a plain object.

```ts
editor.commands.exportDocx({
  styleOverrides: {
    default: {
      heading1: {
        run: { font: 'Arial', size: 32, bold: true, color: '000000' },
        paragraph: { spacing: { before: 240, after: 120 } },
      },
    },
  },
})
```

`size` is in half-points, so `32` is 16pt. `before` and `after` are in twips, so `240` is 12pt.

## Limits

- A custom heading style doesn't keep its name through the editor.
- Levels 7 to 9 don't export as headings.
