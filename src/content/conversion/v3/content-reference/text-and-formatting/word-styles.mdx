A Word style is a named set of formatting, such as Normal or Heading 1. Import reads the styles to choose each paragraph's node type and formatting, and keeps no style names. Export writes a fixed set of Word styles and fills them from your editor's CSS.

## What you need

The editor has no node or mark for a Word style. Each style becomes a node type, marks and attributes, so the editor needs the extensions for those, which [Headings](/conversion/v3/content-reference/text-and-formatting/headings), [Paragraphs](/conversion/v3/content-reference/text-and-formatting/paragraphs) and [Block elements](/conversion/v3/content-reference/document-structure/block-elements) name.

## Import

Import chooses the node type from the name of a paragraph's style, in any case:

| Word style             | Node         |
| ---------------------- | ------------ |
| `Heading` and a number | `heading`    |
| `Quote`                | `blockquote` |
| Any other style        | `paragraph`  |

A style you map with `prosemirrorNodes` comes first, as [Custom node mapping](/conversion/v3/import/docx/custom-node-mapping#map-a-word-style-to-a-node) shows. A paragraph without a style counts as Normal. Only the style's own name counts, so a custom style based on Heading 2 imports as a `paragraph`, as [Headings](/conversion/v3/content-reference/text-and-formatting/headings) describes.

A style can be based on another style. Import follows that chain and merges the formatting of each style in it, then the document defaults. The font, size, bold, italic and color of a style reach the text as marks. Spacing and indentation reach the paragraph as attributes.

A run of text can also have a character style, such as Strong. The formatting of a character style doesn't reach the text, and import gives no warning for it. This is a known limit that is being fixed.

To give the runs of a character style a mark, map the style name to the mark with `prosemirrorMarks`, such as `{ Strong: 'bold' }`.

The experimental `cssStyles` option also returns the document's styles as CSS. Set `enabled: true` to get the rules in `context.cssStyles` of `onImport`, as property maps for each selector, such as `fontFamily`, `fontSize`, `color` and `lineHeight`. Without `enabled`, `context.cssStyles` is `null`.

Set `autoInject: true` to add the rules to the page as a `<style>` element when `setEditorContent()` runs, scoped by `selector`, which defaults to `.tiptap`. In this example, `CONVERSION_TOKEN` stands for your Conversion token:

```ts
import { ImportDocx } from '@tiptap-pro/extension-import-docx'

ImportDocx.configure({
  token: CONVERSION_TOKEN,
  cssStyles: { enabled: true, autoInject: true },
})
```

The rules cover `p`, `h1` to `h6`, `blockquote`, `a`, `code`, `ul li`, `ol li`, `strong`, `em`, `u` and `s`. [CSS styles](/conversion/v3/import/docx/css-styles) has the details.

## Export

Each node type and mark writes a fixed Word style:

| In the editor               | Word style                |
| --------------------------- | ------------------------- |
| `paragraph`                 | Normal                    |
| `heading`, levels 1 to 6    | Heading 1 to Heading 6    |
| Paragraph in a `blockquote` | Quote                     |
| List item paragraph         | List Paragraph            |
| `codeBlock`                 | Code Block                |
| `horizontalRule`            | Horizontal Rule           |
| `code` mark                 | Code character style      |
| `link` mark                 | Hyperlink character style |

Export doesn't write back a style from the imported file. A paragraph imported from a Legal Disclaimer style exports as Normal.

Export measures the CSS of your mounted editor and writes it into these styles, so the Word styles match what the user sees. A headless or unmounted editor has nothing to measure, and export then uses its own defaults. Set `documentStyles: false` to skip the measurement.

[Export styles and fonts](/conversion/v3/export/docx/styles) lists the defaults and shows how to change a style with `styleOverrides` or the export's `cssStyles` option.

## Limits

- Import keeps no style names, so a custom style exports as Normal.
- A character style's formatting doesn't import, unless you map the style to a mark.
- Only a style named `Heading` and a number, or `Quote`, changes the node type, unless you map a style with `prosemirrorNodes`.
- Export writes headings 1 to 6. Levels 7 to 9 export as paragraphs.
