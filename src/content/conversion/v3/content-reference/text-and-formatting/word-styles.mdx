A Word style is a named set of formatting, such as Normal or Heading 1. Import reads the styles to choose each paragraph's node type and formatting, and keeps no style names. Export writes a fixed set of Word styles and fills them from your editor's CSS.

## What you need

The editor has no node or mark for a Word style. Each style becomes a node type, marks and attributes, so the editor needs the extensions for those.

[Headings](/conversion/v3/content-reference/text-and-formatting/headings), [Paragraphs](/conversion/v3/content-reference/text-and-formatting/paragraphs) and [Block elements](/conversion/v3/content-reference/document-structure/block-elements) name the nodes. The marks for font, size and color are on [Font family and size](/conversion/v3/content-reference/text-and-formatting/font-family-size) and [Text color and highlight](/conversion/v3/content-reference/text-and-formatting/text-color-highlight).

## Import

Import chooses the node type from the name of a paragraph's style, in any case:

| Word style             | Node         |
| ---------------------- | ------------ |
| `Heading` and a number | `heading`    |
| `Quote`                | `blockquote` |
| Any other style        | `paragraph`  |

A style you map with `prosemirrorNodes` comes first, as [Custom node mapping](/conversion/v3/import/docx/custom-node-mapping#map-a-word-style-to-a-node) shows. A paragraph without a style counts as Normal. Only the style's own name counts, so a custom style based on Heading 2 imports as a `paragraph`, as [Headings](/conversion/v3/content-reference/text-and-formatting/headings) describes.

A style can be based on another style. Import follows that chain and merges the formatting of each style in it, then the document defaults. The font, size, bold, italic and color of a style reach the text as marks. Spacing and indentation reach the paragraph as attributes.

A run of text can also have a character style, such as Strong. The formatting of a character style doesn't reach the text, and import gives no warning for it. This is a known limit that is being fixed.

Word's Code character style is the exception: it imports as the `code` mark.

To give the runs of another character style a mark, map the style's id to the mark with the `prosemirrorMarks` option of `ImportDocx.configure()`, such as `{ Strong: 'bold' }`.

Word shows a style's name, and the file stores an id for it. For Word's built-in styles, the id is the English name without spaces, such as `Strong` or `IntenseEmphasis`.

The experimental `cssStyles` option of `ImportDocx.configure()` also returns the document's styles as CSS. Set `enabled: true` to get them in `context.cssStyles` of `onImport`.

`context.cssStyles` is an object that maps each selector, such as `h1`, to its CSS properties in camelCase, such as `fontFamily`, `fontSize`, `color` and `lineHeight`. Without `enabled`, `context.cssStyles` is `null`.

Set `autoInject: true` to add the rules to the page as a `<style>` element when `setEditorContent()` runs. The rules are scoped by the `selector` key of `cssStyles`, which defaults to `.tiptap`. In this example, `CONVERSION_TOKEN` stands for your Conversion token:

```ts
import { ImportDocx } from '@tiptap-pro/extension-import-docx'

ImportDocx.configure({
  token: CONVERSION_TOKEN,
  cssStyles: { enabled: true, autoInject: true },
})
```

The rules cover `p`, `h1` to `h6`, `blockquote`, `a`, `code`, `ul li`, `ol li`, `strong`, `em`, `u` and `s`. [CSS styles](/conversion/v3/import/docx/css-styles) has the details.

## Export

Each node type and mark writes a fixed Word style:

| In the editor               | Word style                |
| --------------------------- | ------------------------- |
| `paragraph`                 | Normal                    |
| `heading`, levels 1 to 6    | Heading 1 to Heading 6    |
| Paragraph in a `blockquote` | Quote                     |
| List item paragraph         | List Paragraph            |
| `codeBlock`                 | Code Block                |
| `horizontalRule`            | Horizontal Rule           |
| `code` mark                 | Code character style      |
| `link` mark                 | Hyperlink character style |

Export doesn't write back a style from the imported file. A paragraph imported from a Legal Disclaimer style exports as Normal.

Export reads the styles the browser computes for your mounted editor and writes them into these Word styles, so they match what the user sees.

A headless or unmounted editor has nothing to read, and export then uses its own defaults. To skip the reading, set the `documentStyles` option of `ExportDocx.configure()` or `exportDocx()` to `false`.

So the file's look survives a round trip when the import uses `autoInject: true`. The file's styles then apply to the mounted editor, and export writes them back into these Word styles. The style names of the file are still lost.

[Export styles and fonts](/conversion/v3/export/docx/styles) lists the defaults and shows how to change a style with `styleOverrides`. Export also has a `cssStyles` option, which sets Word styles from CSS properties you write and is a different option from the import's `cssStyles`.

## Limits

- Import keeps no style names, so a custom style exports as Normal.
- A character style's formatting doesn't import, unless you map the style to a mark. Word's Code style imports as the `code` mark.
- Only a style named `Heading` and a number, or `Quote`, changes the node type, unless you map a style with `prosemirrorNodes`.
- Export writes headings 1 to 6. Levels 7 to 9 export as paragraphs.
