Bullet lists and ordered lists convert in both directions, with nesting. Import also rebuilds the numbering format of each list, and export writes it back when the editor has stored it.

## Set up the editor

`StarterKit` has `BulletList`, `OrderedList`, `ListItem` and `ListKeymap`. That is enough for nesting and for the plain numbering of each list.

The editor keeps a numbering format, such as `A, B, C`, only with an extension that defines the `numberingFormat` attribute. See [numbering formats](#numbering-formats). For checkbox lists, see [task lists](/conversion/v3/content-reference/text-and-formatting/task-lists).

## Import

Word has no list element. A list is a run of paragraphs with the same numbering. Import groups them, and the level of each paragraph sets its nesting.

- A bullet, no marker or an empty marker format becomes a `bulletList`.
- Any other format, such as decimal, letters or Roman numerals, becomes an `orderedList`.

The outermost list gets these attributes.

| Attribute         | Value                                                                  |
| ----------------- | ---------------------------------------------------------------------- |
| `numberingFormat` | The id of the format import rebuilt from the file. On both list types. |
| `start`           | The first number of the first level. Left out when it is `1`.          |
| `type`            | `a`, `A`, `i` or `I` for letter and Roman formats.                     |

`OrderedList` already defines `start` and `type`, so those two render in the editor as they are.

Import also returns the formats in the `numberingFormats` field of the [`onImport` context](/conversion/v3/import/docx/api#importcontext).

## Export

Export writes each list as a Word list with the nesting you have. A list deeper than nine levels stays on the ninth. Each ordered list numbers on its own, so two lists in one document don't continue each other.

### Numbering formats

A format is a definition with an `id` and a list of levels. Export finds the format of a list through its `numberingFormat` attribute. It looks in the formats the editor has registered and in the [`numberingFormats`](/conversion/v3/export/docx/usage#keep-list-numbering) option of the export command.

Export doesn't read `start` or `type` by themselves. A list without a matching format exports with Word's default numbering.

Tiptap's `OrderedList` has no `numberingFormat` attribute, so the editor drops the format and shows default numbering. Export still accepts definitions through the `numberingFormats` option.

## Limitations

- Without a `numberingFormat` attribute, a list exports with default numbering. Letter and Roman lists lose their format.
- Word list levels are limited to nine.
