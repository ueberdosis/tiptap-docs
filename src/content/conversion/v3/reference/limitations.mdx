This page lists what Tiptap Conversion doesn't convert between a Word file and the editor, or converts only in part. Each entry says what happens, what you can do instead where there is a way, and links to the page with the details.

Where import leaves something out without a warning, it is a known limit that is being fixed.

## Text and formatting

### Character styles such as Strong or Emphasis

Import doesn't apply the formatting of a Word character style, so its bold, italic, color and shading are lost, without a warning. This is a known limit that is being fixed.

Until then, map the style to a mark with the `prosemirrorMarks` import option. A key that is the name of a character style gives every run with that style the mark you name, such as `prosemirrorMarks: { Strong: 'bold' }`. Word's Code style is the exception, and imports as the `code` mark. See [Text formatting](/conversion/v3/docx/elements/text-formatting).

### Double strikethrough

Import doesn't read double strikethrough.

On export, a `strike` mark is a single line. To get a double line in Word, draw struck text with a double line in your editor's CSS, because export reads the editor's CSS and writes it into the Word style. See [Text formatting](/conversion/v3/docx/elements/text-formatting).

### Exact font sizes

Import rounds font sizes to whole pixels. A size such as 14pt, which is 18.66px, comes in a little larger, so a round trip can change a size by a fraction of a point. See [Text formatting](/conversion/v3/docx/elements/text-formatting).

### Theme fonts and theme colors

Import doesn't read a font set through the document's theme, which is how Word's default template sets the body font. Those runs get no `fontFamily`, without a warning.

A font color set only as a theme color, without a hex value, is skipped. Both are known limits that are being fixed. See [Text formatting](/conversion/v3/docx/elements/text-formatting).

### Highlights in colors that aren't Word highlight names

Word has a fixed list of named highlight colors. On export, a highlight in another color, such as `#FFC0CB`, becomes shading in Word, and so does a `backgroundColor`. On import, shading becomes a `highlight` mark with the hex color, so after a round trip a `backgroundColor` comes back as a `highlight`. See [Text formatting](/conversion/v3/docx/elements/text-formatting).

### Symbols from a symbol font

A symbol inserted with Word's Insert Symbol, such as a Wingdings arrow, imports as its character with the symbol's font in a `textStyle` mark. Symbol fonts put their characters at `U+F000` to `U+F0FF`, so the symbol shows correctly only where that font is installed. See [Text formatting](/conversion/v3/docx/elements/text-formatting).

## Paragraphs and styles

### Right-to-left text

Import ignores the right-to-left setting of Word paragraphs and runs. It keeps the text inside Word's bidirectional embedding elements (`w:dir` and `w:bdo`), but not the text direction they set.

The text in custom XML tags, which mark parts of a file for other software, is kept too. See [Paragraphs and styles](/conversion/v3/docx/elements/paragraphs).

### Tabs and tab stops

A tab imports as four spaces and exports as four spaces, so it doesn't round-trip. A positional tab (`w:ptab`) imports as four spaces too, and its alignment is lost.

Import doesn't read tab stops, and export writes no tab stop positions from the document. To set tab stops for every paragraph, use `paragraphOverrides` with `tabStops`. See [Paragraphs and styles](/conversion/v3/docx/elements/paragraphs).

### Paragraph borders and shading

Import ignores paragraph borders and paragraph shading. Export writes paragraph borders only from the editor's CSS. See [Paragraphs and styles](/conversion/v3/docx/elements/paragraphs).

### Line spacing that round-trips

A line spacing of "at least" imports as a length, so it exports as an exact line height. A line spacing in multiples, such as 1.5, exports as an "at least" line height, so it doesn't come back from a round trip as a multiple. See [Paragraphs and styles](/conversion/v3/docx/elements/paragraphs).

### A pixel-exact copy of the editor

The exported file doesn't match the editor pixel for pixel, because Word and the browser measure fonts and lines differently. See [Paragraphs and styles](/conversion/v3/docx/elements/paragraphs).

### Hidden text

Import leaves out hidden text, without a warning. This is a known limit that is being fixed. See [Paragraphs and styles](/conversion/v3/docx/elements/paragraphs).

### Named Word styles

Import keeps no style names, so a custom style exports as Normal. Only a style named `Heading` and a number, or `Quote`, changes the node type, unless you map a style to a node type with the `prosemirrorNodes` import option, as [Map a Word style to a node](/conversion/v3/docx/custom-nodes#map-a-word-style-to-a-node) shows. See [Paragraphs and styles](/conversion/v3/docx/elements/paragraphs).

### Heading levels 7 to 9

The `Heading` node of `StarterKit` allows levels 1 to 6. It draws any other level, such as an imported `level: 7`, as `<h1>`, unless you lower `level` in `onImport` before you call `setEditorContent()`, as [Change the document before the editor gets it](/conversion/v3/docx/import#change-the-document-before-the-editor-gets-it) shows. A heading with `level` 7 to 9 exports as a normal paragraph. See [Paragraphs and styles](/conversion/v3/docx/elements/paragraphs).

### Numbered headings

A numbered heading, which is a heading style linked to Word's numbering, imports as a list item. When the list item has to start with a paragraph, as the `ListItem` of `StarterKit` does, the heading becomes that paragraph, with a `restructured` warning. Its text is kept. See [Paragraphs and styles](/conversion/v3/docx/elements/paragraphs).

### Style extraction as CSS

The `cssStyles` import option, which turns Word's named styles into CSS rules, extracts only the 16 selectors in [What is extracted](/conversion/v3/docx/import#what-is-extracted). It skips table, numbering and custom styles, and doesn't extract letter spacing. The rules describe the imported file, so when the user changes the document, the rules stay as they were.

Formatting set directly on a paragraph or run stays on the node, and the rules don't override it. See [Import DOCX](/conversion/v3/docx/import).

### Lists, tables and code in blockquotes and code blocks

A list or table inside a blockquote doesn't export. A `blockquote` with several paragraphs comes back from Word as one `blockquote` for each paragraph. A code block comes back from Word as a paragraph, without its `language`. See [Paragraphs and styles](/conversion/v3/docx/elements/paragraphs).

## Lists

### Custom list numbering formats

Import doesn't return the definitions of the file's numbering formats, so imported lists show default numbering, apart from `start` and `type`. There is no warning. This is a known limit that is being fixed. See [Lists and task lists](/conversion/v3/docx/elements/lists).

### Letter and Roman lists without a numbering format

Export doesn't read `type`, so a letter or Roman list without a numbering format exports with numbers. See [Lists and task lists](/conversion/v3/docx/elements/lists).

### Checkboxes outside a list

A checkbox outside a list isn't converted. A checkmark character such as `✔` isn't a checkbox, and stays as text. See [Import DOCX](/conversion/v3/docx/import).

## Tables

### Tables without border attributes

A table from a headless editor, one that isn't mounted on a web page, such as in Node.js, exports without borders when its nodes have no border attributes. See [Tables](/conversion/v3/docx/elements/tables).

### Page Layout's table settings

Neither import nor export reads the two table settings of Page Layout: a table's `repeatHeaderRow` and a row's `breakAcrossPages: false`. Neither gives a warning. This is a known limit that is being fixed. To keep a row on one page in Word, use the `break-inside: avoid` CSS that [Tables](/conversion/v3/docx/elements/tables) shows.

## Images and math

### Images the import skips

An image the import skips is left out of the document, with an `image-skipped` warning. Import skips images behind the text, such as a watermark, unless you set `behindTextImages: 'import'`. See [Images and math](/conversion/v3/docx/elements/images-and-math).

### Image uploads on import

The Conversion service doesn't resolve a relative URL that your upload endpoint returns, because it has no page to resolve it against. It doesn't retry a failed upload. See [Import DOCX](/conversion/v3/docx/import).

### Floating and cropped images

Floating images lose their position on import, and export writes every image inline. Export doesn't write cropping. See [Images and math](/conversion/v3/docx/elements/images-and-math).

### WebP and other image formats Word can't hold

A WebP image, or another format Word can't hold, fails the whole export when the browser uploads it, such as from a `blob:` URL. `onError` then receives an `ExportDocxRequestError` with `status` `400`, whatever `onImageError` says.

The same image at a public URL is left out with a warning. This is a known limit that is being fixed. See [Images and math](/conversion/v3/docx/elements/images-and-math).

### Equations

Equations don't import, and import gives no warning for them. Export builds no environment other than `matrix`, so `pmatrix` and the like don't convert. See [Images and math](/conversion/v3/docx/elements/images-and-math).

## Links, bookmarks and notes

### Bookmarks

Import leaves bookmarks out, with a `bookmarks-dropped` warning, so a link to one has no target in the editor. Export drops the marks and points of the Bookmarks extension. See [Links and bookmarks](/conversion/v3/docx/elements/links-and-bookmarks).

### Link targets

Export doesn't write a link's `target` and `rel`. See [Links and bookmarks](/conversion/v3/docx/elements/links-and-bookmarks).

### Cross-references

Import keeps the text Word shows for a cross-reference, and export drops the `crossReference` node. See [Links and bookmarks](/conversion/v3/docx/elements/links-and-bookmarks).

### Notes without a reference

A note without a reference, and a reference without a note, are left out, on import and on export. Import reports them with `notes-dropped`. Export reports only the note without a reference. See [Footnotes and endnotes](/conversion/v3/docx/elements/footnotes).

### Note settings of a section

Export doesn't write a section's note settings, such as the number format or restart. See [Footnotes and endnotes](/conversion/v3/docx/elements/footnotes).

## Pages

These limits concern [Page Layout](/features/page-layout/getting-started/overview), the extension that shows the document on pages.

### Page color per section

Word has one page color per document, so export drops a different page color on a later section, with an `unsupported` warning. Word has no text or accent colors for a section either, so export drops the `themeText` and `themeAccent` that Page Layout can give a section, with one `unsupported` warning for each. See [Page color](/conversion/v3/docx/page-layout#page-color).

### Sections that start on an even, odd or next-column page

Import starts an even or odd page section on the next page, with a `section-start-even-odd` warning. It starts a next-column section on the next page too, without a warning. See [Word files with Page Layout](/conversion/v3/docx/page-layout).

### The binding gutter

Import leaves out the binding gutter of the page margins, with a `gutter-dropped` warning. See [Word files with Page Layout](/conversion/v3/docx/page-layout).

### Custom page number formats

Import reads a custom Word number format, such as `001`, as the default for its kind, without a warning. See [Word files with Page Layout](/conversion/v3/docx/page-layout).

### Fields other than page numbers

Fields other than page numbers, such as dates, import as plain text and no longer update. See [Word files with Page Layout](/conversion/v3/docx/page-layout#headers-and-footers).

### Header and footer distances

Word keeps one header distance and one footer distance for each section, but a header or footer in Page Layout can set a distance of its own in `offset`. When the versions of one section differ, such as a first-page header and the header of the other pages, export writes the section's distance for all of them, with an `unsupported` warning.

To control the distance in Word, set it on the section, in its `headerOffset` and `footerOffset`.

Word also has one switch for different odd and even pages in the whole file. Export turns it on when any section has `differentOddEven`, and a section without it then shows its `default` header and footer on the even pages too. See [Export headers and footers](/conversion/v3/docx/page-layout#export-headers-and-footers).

### Soft page breaks

Soft page breaks don't import, because they are Word's layout, not content. See [Word files with Page Layout](/conversion/v3/docx/page-layout#page-breaks-and-column-breaks).

### Pageless documents

A pageless document, which Page Layout shows as one continuous column, has no paper of its own. So it exports with the `pageSize` and `pageMargins` options, which default to A4 with margins of 2.54cm at the top and bottom and 3.17cm at the sides. To export it on other paper, set those options or pass `pageSetup`. See [Word files with Page Layout](/conversion/v3/docx/page-layout).

### A page margin of zero

Without Page Layout, a number `0` in `pageMargins` means the default, without a warning. Write `'0cm'` for a margin of zero. This is a known limit that is being fixed. See [Page size and margins](/conversion/v3/docx/export#page-size-and-margins).

### Page measures in `pi`

A page measure in `pi`, another spelling of picas, passes the `PageMeasure` type, but fails the export with a 422 error. Write the same length in `pc`. This is a known limit that is being fixed. See [Page size and margins](/conversion/v3/docx/export#page-size-and-margins).

## Review

### Formatting changes, splits and joins

Formatting changes don't convert as tracked changes in either direction. A paragraph split or joined while Word tracked changes imports in its final form, without a suggestion. See [Tracked changes and comments](/conversion/v3/docx/tracked-changes-and-comments).

### Tracked moves

Import doesn't read Word's tracked moves, and gives no warning, so the moved text may be missing. Check a moved passage before you rely on it. This is a known limit that is being fixed. See [Tracked changes and comments](/conversion/v3/docx/tracked-changes-and-comments).

### Tracked changes in headers, footers, comments and notes

Changes in headers, footers, comments, footnotes and endnotes import as accepted. See [Tracked changes and comments](/conversion/v3/docx/tracked-changes-and-comments#import-tracked-changes).

### Pending node type changes

A pending node type change from the Tracked Changes extension fails the export. Accept or reject it first, as [A pending node type change fails the export](/conversion/v3/reference/warnings-and-errors#a-pending-node-type-change-fails-the-export) shows.

### Comments

A comment is tied to the text it marks, so deleting that text removes the mark. A table in a comment body doesn't export.

Import shows the comments as threads of the Comments extension only with live threads. These are threads the import creates on the Document Server, the Tiptap server that stores collaborative documents, and they need a collaboration provider and a token that may write the document. See [Tracked changes and comments](/conversion/v3/docx/tracked-changes-and-comments).

## Other Word content

These Word features convert only in part, or not at all:

| Feature                                       | What happens                                                                                                                                       |
| --------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| Table of contents                             | Import keeps the entries as plain paragraphs, with a `toc-flattened` warning. Export drops a `tableOfContents` node with an `unsupported` warning. |
| Text boxes                                    | Import leaves them out with their text, without a warning.                                                                                         |
| Shapes, SmartArt, WordArt                     | Import leaves them out, without a warning.                                                                                                         |
| Content controls and form fields              | Import keeps the text and drops the control.                                                                                                       |
| Document properties, such as author and title | Import doesn't read them, and export doesn't write them.                                                                                           |

[What Word elements become](/conversion/v3/docx/elements) lists what converts.

## Size limits of an export

These limits apply to each export from the editor:

| What                                                      | Limit                      | Over the limit                                              |
| --------------------------------------------------------- | -------------------------- | ----------------------------------------------------------- |
| Files the browser uploads, fonts first, then images       | 64                         | Left out with `font-fetch-failed` or `image-fetch-failed`   |
| Size of an uploaded image                                 | 20 MB                      | Left out with `image-fetch-failed`                          |
| Format of an uploaded image                               | PNG, JPEG, GIF, BMP or SVG | 400 `INVALID_EXPORT_OPTIONS`                                |
| Size of an uploaded font                                  | 25 MB                      | Left out with `font-fetch-failed`                           |
| Size of the request                                       | 100 MB                     | 413 `REQUEST_BODY_TOO_LARGE`                                |
| Images the Conversion service downloads                   | 200                        | `image-request-failed`, or 422 with `onImageError: 'throw'` |
| Total size of the images the Conversion service downloads | 100 MB                     | `image-request-failed`, or 422 with `onImageError: 'throw'` |
| Time to download one image on the Conversion service      | 15 s                       | `image-request-failed`, or 422 with `onImageError: 'throw'` |
| Font families the Conversion service looks up             | 20                         | Not embedded, without a warning                             |

The extension keeps its limits of 64 files, 20 MB and 25 MB even when a Conversion service on your own server allows more. The limits on custom node rules are in [Custom nodes in Word files](/conversion/v3/docx/custom-nodes#validation-and-limits). [Warnings and errors](/conversion/v3/reference/warnings-and-errors) explains each code.
