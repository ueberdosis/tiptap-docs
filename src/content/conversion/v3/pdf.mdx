## Choose a way

The two ways differ in where you call them and what the PDF looks like:

|                                | [Export from the editor](#export-from-the-editor)                          | [Print the pages](#print-the-pages)                    |
| ------------------------------ | -------------------------------------------------------------------------- | ------------------------------------------------------ |
| Where you call it              | In the editor, as a command                                                | In your code, as a REST request                        |
| How the PDF is made            | LibreOffice, an office suite, converts the Word file Export DOCX builds    | Chromium, a browser on the server, prints the pages    |
| What the PDF looks like        | The Word file                                                              | The editor's pages, styled by the stylesheets you send |
| Custom nodes                   | Written by your [custom node rules](/conversion/v3/docx/custom-nodes)      | Left out                                               |
| Page setup without Page Layout | The `pageSize` and `pageMargins` options                                   | A4 portrait                                            |
| Token permissions              | `Convert:Export:Docx` and `Convert:Export:Pdf`                             | `Convert:Export:Pdf`                                   |
| On your own server             | A `/v2` base in `endpoint`, as [Region and endpoint](#region-and-endpoint) | The Conversion service 2.50.0 or later                 |

For an export button in the editor, where your server only signs the token, export from the editor. For a PDF that looks like the editor's pages, or to export stored documents on your server, print the pages.

## Export from the editor

The `exportPdf()` command of the `ExportPdf` extension saves the editor's document as a PDF. It builds a Word file with [Export DOCX](/conversion/v3/docx/export) first, so keep `ExportDocx` in the editor.

Install both packages from Tiptap's private registry, which [Set up the registry](/conversion/v3/getting-started/install#1-set-up-the-registry) connects your project to:

```bash
npm install @tiptap-pro/extension-export-pdf @tiptap-pro/extension-export-docx
```

Add `ExportPdf` with a Conversion token. Here, `CONVERSION_TOKEN` stands for a token your server signed and the page fetched, and `download` for your function that saves a `Blob`:

```ts
import { Editor } from '@tiptap/core'
import StarterKit from '@tiptap/starter-kit'
import { ExportDocx } from '@tiptap-pro/extension-export-docx'
import { ExportPdf } from '@tiptap-pro/extension-export-pdf'

const editor = new Editor({
  element: document.querySelector('#editor'),
  extensions: [
    StarterKit,
    ExportDocx,
    ExportPdf.configure({
      token: CONVERSION_TOKEN,
      onCompleteExport: (blob) => download(blob),
      onExportError: (error) => console.error(error),
    }),
  ],
})

editor.commands.exportPdf()
```

The command returns `true` right away, and `onCompleteExport` receives the PDF as a `Blob` when the Conversion service answers.

The export calls the service twice, so the token needs both `Convert:Export:Docx` and `Convert:Export:Pdf`. [Install Tiptap Conversion](/conversion/v3/getting-started/install) shows how to sign it. `ExportDocx` needs no options here, because `exportPdf()` hands it its own token and callbacks.

### How the export runs

With `ExportDocx` in the editor, `exportPdf()` builds the Word file with `exportDocx()`. So the PDF has what the Word file has, such as Page Layout's page setup, headers and footers, footnotes and your custom nodes.

The Word step takes options from:

- **`ExportPdf`**: `styleOverrides`, `pageSize`, `pageMargins`, `pageColor`, `token`, `appId`, `endpoint` and `region`.
- **`ExportDocx.configure()`**: every other option, such as `customNodeDsl` or `fonts`.

Warnings of the Word step go to the `onWarning` callback of `ExportDocx`. `customFonts` goes to the conversion either way.

Without `ExportDocx`, `exportPdf()` sends the editor's JSON with `styleOverrides`, `pageSize` and `pageMargins`, and the Conversion service builds the Word file itself. That PDF has no headers, footers, custom nodes or page color.

### Options

`exportPdf()` takes the same options as `ExportPdf.configure()`. A value passed to the command wins for that call, unless it is `undefined`.

A measure in `pageSize` and `pageMargins` is a string of a number and a unit, such as `'21cm'`. The units are `mm`, `cm`, `in`, `pt`, and `pc` or `pi` for picas. [Page size and margins](/conversion/v3/docx/export/page-size-and-margins) explains the margins, also negative ones.

#### token

`string` · Default `''`

The Conversion token. It also goes to the Word step, so the `token` of `ExportDocx` doesn't apply.

#### appId

`string` · Default `''`

Your app ID, only for a token from [Legacy authentication](/authentication/legacy). Sent in the `X-App-Id` header.

#### region

`'eu' | 'us'` · Default none

The Tiptap Cloud region, the EU when not set. See [Region and endpoint](#region-and-endpoint).

#### endpoint

`string` · Default none

The base URL of your own Conversion service. It wins over `region`, and an empty string counts as not set.

#### onCompleteExport

`(result: Blob) => void` · Default: throws an error

Receives the PDF. Set it, because the default throws when the PDF arrives.

#### onExportError

`(error: Error) => void` · Default none

Receives the error when the export fails. Without it, the extension logs the error to the console.

#### styleOverrides

`IStylesOptions` from `docx` · Default none

Word styles. When not set, the Word step uses the `styleOverrides` of `ExportDocx`. See [Set Word styles](/conversion/v3/docx/export/styles-and-fonts#set-word-styles).

#### pageSize

`PageSize` · Default none

`{ width?, height? }`. When not set, the Word step uses the value of `ExportDocx`.

#### pageMargins

`PageMargins` · Default none

`{ top?, bottom?, left?, right?, header?, footer? }`. When not set, the Word step uses the value of `ExportDocx`.

#### pageColor

`string` · Default none

The page background, as hex, `rgb()` or a color name. When not set, the Word step uses the value of `ExportDocx`. Needs `ExportDocx`.

#### customFonts

`CustomFont[]` · Default none

Font files for the conversion, each `{ url, fontFamily }`. Only on your own server.

`customFonts` gives the Conversion service fonts to convert with. Each `url` is an HTTPS URL of a `.ttf` or `.woff2` file, and `fontFamily` is the font name the document uses. Tiptap Cloud refuses a request with `customFonts` with `403`, which reaches `onExportError`.

### Region and endpoint

Set `endpoint` or `region` on `ExportPdf`, not only on `ExportDocx`. When `ExportPdf` has neither, the Word step uses the value of `ExportDocx`, but the PDF step uses the EU region.

`exportPdf()` sends the file to `<base>/export/pdf`, on the Conversion service's v2 endpoints. Without `endpoint`, the base depends on `region`:

| `region` | Base                                   |
| -------- | -------------------------------------- |
| `'eu'`   | `https://api.tiptap.dev/v2/convert`    |
| `'us'`   | `https://api-us.tiptap.dev/v2/convert` |

On your own server, set `endpoint` to the service's `/v2` base, such as `https://convert.example.com/v2`, also when Export DOCX uses `/v3`. Bases work like this:

- **A `/v2` or `/v2/convert` base**: the Word step changes it to its `/v3` form, so it calls `/v3/export/docx`.
- **A `/v3` base** doesn't work here, because the PDF step would then send the Word file to the page print, which refuses it with `400`.
- **A base without a version**, such as a path on a proxy, is used as it is for both steps, and the Word step logs a console warning.

### Errors

A failed export calls `onExportError` with an `Error`. When the Conversion service answers with an error status, the message is the response's status text, such as `Forbidden`. A failure of the Word step, such as a missing token, reaches `onExportError` with the error of `exportDocx()`.

A started export can't be canceled.

## Print the pages

The page print lays the document out with Page Layout in Chromium, a browser on the server, and prints the pages. It takes Tiptap JSON and your editor's CSS instead of a Word file, so the PDF looks like the editor's pages.

The editor doesn't need Page Layout:

- **With Page Layout** in the editor, send its page setup to get the same pages.
- **Without Page Layout**, the page print uses A4 portrait, and [Page setup](/conversion/v3/rest-api/export-pdf#page-setup) shows how to ask for US Letter or landscape.

No command calls the page print, so send `POST /v3/convert/export/pdf` from your code. This browser code sends the editor's document, the Page Layout setup, the URL of your editor's stylesheet and the URLs of the document's images.

`CONVERSION_TOKEN` stands for a token with `Convert:Export:Pdf`, and `download` for your function that saves a `Blob`:

```ts
const doc = editor.getJSON()
const images = []
const collectImages = (node) => {
  if (node.type === 'image' && /^https?:/.test(node.attrs?.src ?? '')) {
    images.push({ id: `image-${images.length}`, src: node.attrs.src })
  }
  node.content?.forEach(collectImages)
}
collectImages(doc)

const options = {
  document: doc,
  pageSetup: editor.storage.pageLayout?.engine?.getSetup(),
  stylesheets: [{ url: 'https://app.example.com/assets/editor.css' }],
  assets: { images },
}

const form = new FormData()
form.append('options', JSON.stringify(options))

const response = await fetch('https://api.tiptap.dev/v3/convert/export/pdf', {
  method: 'POST',
  headers: { Authorization: `Bearer ${CONVERSION_TOKEN}` },
  body: form,
})

if (response.ok) download(await response.blob())
```

The service fetches the stylesheet and the images itself, so their URLs must be public. In development, when your CSS is on `localhost`, send its text instead, as [Stylesheets](/conversion/v3/rest-api/export-pdf#stylesheets) shows.

Without stylesheets, the PDF uses the service's default CSS, which sets Times New Roman at 16 pixels. The [Export PDF REST API](/conversion/v3/rest-api/export-pdf) describes every field, font and image uploads, the warnings and the errors.

### What the page print renders

The page print renders the node and mark types of these extensions. Their options are fixed, so a request can't change how they render:

| Extension                                                     | Package                                                        | Fixed setting                |
| ------------------------------------------------------------- | -------------------------------------------------------------- | ---------------------------- |
| StarterKit                                                    | `@tiptap/starter-kit`                                          |                              |
| TableKit                                                      | `@tiptap/extension-table`                                      |                              |
| Image                                                         | `@tiptap/extension-image`                                      |                              |
| TaskList, TaskItem                                            | `@tiptap/extension-list`                                       | `nested: true`               |
| Highlight                                                     | `@tiptap/extension-highlight`                                  | `multicolor: true`           |
| Subscript, Superscript                                        | `@tiptap/extension-subscript`, `@tiptap/extension-superscript` |                              |
| TextAlign                                                     | `@tiptap/extension-text-align`                                 | Headings and paragraphs      |
| TextStyleKit                                                  | `@tiptap/extension-text-style`                                 |                              |
| [Page Layout](/features/page-layout/getting-started/overview) | `@tiptap-pro/extension-page-layout`                            |                              |
| [Footnotes](/features/footnotes)                              | `@tiptap-pro/extension-footnotes`                              |                              |
| [Bookmark](/features/bookmark)                                | `@tiptap-pro/extension-bookmark`                               |                              |
| Columns, which places containers side by side                 | `@tiptap-pro/extension-columns`                                |                              |
| Whole Blocks                                                  | `@tiptap-pro/extension-whole-blocks`                           |                              |
| Number Formats                                                | `@tiptap-pro/extension-number-formats`                         |                              |
| Document Styles                                               | `@tiptap-pro/extension-document-styles`                        |                              |
| [Outline Numbering](/features/outline-numbering)              | `@tiptap-pro/extension-outline-numbering`                      | The decimal numbering preset |
| Cross References                                              | `@tiptap-pro/extension-cross-references`                       | Headings as the only targets |

So a document's sections with their page setup, headers, footers, page numbers, breaks, footnotes and endnotes print as Page Layout lays them out.

### What the page print leaves out

The page print removes a node type outside the list together with its content. It removes a mark type outside the list too, but the mark's text still prints. Among others, the page print leaves out:

- Node types of your own, because the page print has no [custom node rules](/conversion/v3/docx/custom-nodes).
- Preserved content, the placeholder nodes and marks an import keeps for content the importing editor had no extension for.
- Comments and tracked changes, which are marks. Their text prints as ordinary text, so a suggested deletion prints too.
- The nodes and marks of other extensions, such as Mention or Mathematics.

Each removal adds an `unsupported` warning with the type and its place in the document.

To print preserved content, send `unpreservedContent(doc)` from `@tiptap-pro/extension-preserved-content` as the document. It returns a copy with each preserved node and mark turned back into its original type, so a preserved table prints as a table.

An image prints when the request lists its `src` in `assets.images`, as the example in [Print the pages](#print-the-pages) does. An image whose `src` is a `data:` URL prints too. Any other image prints empty, with a warning. [Fonts and images](/conversion/v3/rest-api/export-pdf#fonts-and-images) shows how to upload an image instead.
