Call the endpoint from your backend, such as when a job reads uploaded Word files. The [Import DOCX](/conversion/v3/docx/import) extension calls the same endpoint from the editor. The [REST API overview](/conversion/v3/rest-api/overview) explains the base URLs, the token and the errors every call shares.

## Send a file

The request is a `multipart/form-data` form with the file in the `file` field. `CONVERSION_TOKEN` is an environment variable with a token that allows `Convert:Import:Docx`, as [Get a token](/conversion/v3/rest-api/overview#get-a-token) explains:

```bash
curl -X POST https://api.tiptap.dev/v3/convert/import/docx \
  -H "Authorization: Bearer $CONVERSION_TOKEN" \
  -F 'file=@report.docx' \
  -o report.json
```

This import leaves out the file's images, because the service needs a place to put them. Add an `imageUploadConfig` field with the URL of an upload endpoint of yours, such as `-F 'imageUploadConfig={"url":"https://example.com/upload"}'`. [Images in imported files](/conversion/v3/docx/import/images) describes the request your endpoint receives and the response it returns.

Let `curl` set the `Content-Type` header, because it adds the form's boundary. The request takes these headers:

| Header          | Value                                                                                                     |
| --------------- | --------------------------------------------------------------------------------------------------------- |
| `Authorization` | `Bearer <token>`.                                                                                         |
| `Content-Type`  | `multipart/form-data`, with its boundary. Any other type fails with `415` and `UNSUPPORTED_CONTENT_TYPE`. |
| `X-App-Id`      | Your app ID, only with a legacy token.                                                                    |

## Form fields

Every field is optional except `file`. Send each field once, or the request fails with `400` and `INVALID_IMPORT_OPTIONS`. An empty field counts as not sent, and a field the endpoint doesn't know is ignored.

| Field               | Type                             | Description                                                                                                                                                                                 |
| ------------------- | -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `file`              | File                             | Required. The `.docx` file.                                                                                                                                                                 |
| `imageUploadConfig` | JSON text                        | Where the service uploads the file's images: `url`, and optional `method` such as `"PUT"` (default `POST`), `headers` and `queryParams` as objects of strings.                              |
| `prosemirrorNodes`  | JSON text                        | Renames node types in the result, such as `{ "blockquote": "quote" }`.                                                                                                                      |
| `prosemirrorMarks`  | JSON text                        | Renames mark types in the result, such as `{ "bold": "strong" }`.                                                                                                                           |
| `trackedChanges`    | `preserve`, `accept` or `reject` | What happens to tracked changes. Defaults to `accept`. `preserve` keeps them as suggestions, as [Tracked changes and comments](/conversion/v3/docx/tracked-changes-and-comments) describes. |
| `taskLists`         | `import` or `ignore`             | `import` turns checkbox lists into task lists. `ignore`, the default, imports them as ordinary lists.                                                                                       |
| `behindTextImages`  | `import` or `ignore`             | Whether images behind the text, such as watermarks, come in. Defaults to `ignore`.                                                                                                          |
| `extractCssStyles`  | `true` or `false`                | `true` returns the file's Word styles as CSS in `data.cssStyles`.                                                                                                                           |
| `documentName`      | `string`                         | The name of the Tiptap Collaboration document that the comments belong to.                                                                                                                  |

`documentName` writes the file's comments into the threads of that Tiptap Collaboration document, and the response then holds the IDs of those threads. The import changes the threads like this:

- It creates a thread for each new comment, and updates the threads that match a comment of the file.
- It deletes the threads that an earlier import added and the file no longer has. Threads that users added in Collaboration stay.

The service does this only when:

- the token has `aud: "Convert"`,
- the token also allows `Documents:Write`, the Tiptap Collaboration action, in its `permissions`, and
- your environment includes Tiptap Collaboration.

Otherwise, the comments keep the IDs from the file, and `logs.warn` says why.

`prosemirrorNodes` can't rename the node types the document's structure is built from: `doc`, `paragraph`, `sectionBreak`, `pageFurniture`, `pageBreak`, `columnBreak`, `pageNumber`, `footnoteReference`, `endnoteReference`, `footnote`, `footnoteCollection`, `bookmark`, `bookmarkPoint` and `crossReference`. Renaming one fails with `400` and `UNSUPPORTED_NODE_OVERRIDE`. [Custom nodes on import](/conversion/v3/docx/custom-nodes/import) explains renaming.

### Removed fields

`imageUploadCallbackUrl` and `placeholders` belonged to the v2 REST API. Each one fails with `400` and `REMOVED_IMPORT_OPTION`, and `path` names the field. Use `imageUploadConfig` instead of `imageUploadCallbackUrl`. `placeholders` has no replacement, because Word's page number fields come in as `pageNumber` nodes.

## Response

A successful import returns `200` with JSON:

```json
{
  "data": {
    "content": { "type": "doc", "content": [] },
    "cssStyles": null,
    "commentThreads": []
  },
  "warnings": [
    {
      "code": "image-skipped",
      "message": "Some images were left out of the import. The import logs name each one and why."
    }
  ],
  "logs": { "info": [], "warn": [], "error": [] }
}
```

The response has these fields:

| Field                 | Description                                                                                                                                                                                                                                               |
| --------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `data.content`        | The document as Tiptap JSON. It starts with a `sectionBreak` node, and [Word files with Page Layout](/conversion/v3/docx/page-layout) describes its nodes.                                                                                                |
| `data.cssStyles`      | The file's styles as CSS rules keyed by selector, or `null` without `extractCssStyles=true`. See [Word styles as CSS](/conversion/v3/docx/import/word-styles).                                                                                            |
| `data.commentThreads` | The file's comment threads, each with an `id`, a `resolved` flag and its `messages`. Each message has its `body` as Tiptap JSON and `data` with `author` and dates. See [Tracked changes and comments](/conversion/v3/docx/tracked-changes-and-comments). |
| `warnings`            | What the import left out or changed. Each warning has a `code` and a `message`.                                                                                                                                                                           |
| `logs`                | The service's log entries, in `info`, `warn` and `error`. `warn` names each image and each table the import left out, and why.                                                                                                                            |

The commented text carries an `inlineThread` mark with the thread's `id` in its `data-thread-id` attribute.

The [Export DOCX REST API](/conversion/v3/rest-api/export-docx#notes-and-comments) takes threads in another shape. To export the comments again, give a resolved thread a `resolvedAt` date. Then turn `messages` into `comments`, each with an `id` of your choice, its `body` as `content`, and its `data`.

The Import DOCX extension changes the result to fit the editor's extensions, and keeps what the editor can't show as preserved content. The REST API returns the result as it is.

So an editor that loads `data.content` needs [Page Layout](/features/page-layout/getting-started/overview) for the sections, headers, footers and breaks, and [Footnotes](/features/footnotes) for the notes. By default, an editor without them replaces the whole document with an empty one, and logs `Invalid content` to the console.

### Warnings

A warning says what an import left out or changed, while the import still succeeds. Each code comes at most once per import:

- `section-in-table-cell`
- `bookmarks-dropped`
- `toc-flattened`
- `section-start-even-odd`
- `gutter-dropped`
- `notes-dropped`
- `image-skipped`
- `table-skipped`

[Warning codes](/conversion/v3/reference/warnings#warning-codes) explains each code. A later version of the Conversion service may send codes that this list lacks, so handle an unknown code.

## Errors

A failed import returns the error shapes of the [REST API overview](/conversion/v3/rest-api/overview#errors). A failure after the service accepted the file, which is a `422` or `500`, also has `logs`. These codes come from the import itself:

| Status | `code`                                  | When                                                                                            |
| ------ | --------------------------------------- | ----------------------------------------------------------------------------------------------- |
| 400    | `INVALID_IMPORT_OPTIONS`                | The body can't be read as a form, a field comes twice, or a JSON field is malformed or invalid. |
| 400    | `NO_FILE_PROVIDED`                      | The `file` field is missing or isn't a file.                                                    |
| 400    | `REMOVED_IMPORT_OPTION`                 | The body has a [removed field](#removed-fields).                                                |
| 400    | `UNSUPPORTED_NODE_OVERRIDE`             | `prosemirrorNodes` renames a node type the document's structure is built from.                  |
| 415    | `UNSUPPORTED_CONTENT_TYPE`              | The body isn't `multipart/form-data`.                                                           |
| 422    | `INVALID_DOCX_FILE`                     | The file is corrupt, or isn't a `.docx` file.                                                   |
| 422    | `DOCX_TOO_LARGE`                        | A part of the file is over 256 MB, or the file unpacks to more than 1,024 MB.                   |
| 422    | `FAILED_TO_PARSE_DOCX_FILE`             | The service couldn't read the file.                                                             |
| 500    | `FAILED_TO_CONVERT_DOCX_TO_TIPTAP_JSON` | The service read the file but couldn't convert it.                                              |

On your own server, `MAX_DOCX_PART_MB` and `MAX_DOCX_UNZIPPED_MB` change the limits of `DOCX_TOO_LARGE`. Authentication, size and rate limit errors are in the [REST API overview](/conversion/v3/rest-api/overview#errors).
