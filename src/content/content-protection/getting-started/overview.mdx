Content Protection controls which parts of a Tiptap document a user can edit or see. Keep template wording fixed, preserve table columns, protect attributes, or let an editor change a citation's words while retaining its source.

Your application supplies a policy. The extension checks document changes against it and explains refused edits. It works with your existing Nodes and Marks, including [Slots](/composable-documents/getting-started/overview).

## Install

```bash
npm install @tiptap-pro/extension-content-protection
```

Add the extension alongside your document extensions:

```ts
import { ContentProtection } from '@tiptap-pro/extension-content-protection'

const editor = new Editor({
  extensions: [
    StarterKit,
    ContentProtection.configure({
      policy: {
        version: 1,
        rules: [
          {
            selector: { target: 'node', node: { types: ['heading'] } },
            permissions: { edit: false },
            reason: 'Keep the template headings in place.',
          },
        ],
      },
    }),
  ],
})
```

This preserves headings while allowing their text to change. Use `target: 'content'` to protect their wording too.

## Client-side scope

Protection governs the local editor. Hidden content remains in its document and in `getJSON()` and `getHTML()`. Use `getReadableContent()` for a readable export. This beta does not provide server authorization, JWT integration or collaboration permission enforcement.

See the [API reference](/content-protection/api-reference/extension) and [policy language](/content-protection/api-reference/policy).
