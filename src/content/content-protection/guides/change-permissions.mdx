---
title: Change permissions
meta:
  description: Replace runtime policies and explain refused edits in your application.
---

Your application maps roles to policies. Replace the policy when the active role changes:

```ts
editor.commands.setContentProtectionPolicy({
  policy: policies[selectedRole],
})
```

Call this separately from content commands. Policies are runtime configuration and do not enter undo history. Invalid replacements return `false` and leave the previous policy active.

Show a useful reason when an edit is refused:

```ts
editor.on('contentProtectionRejected', ({ violations }) => {
  showMessage(violations.flatMap((item) => item.reasons).join(' '))
})
```

Add plain-text `reason` values to rules. Keep them free of hidden content because they may be displayed for concealed regions.

For toolbar state, call `getProtection({ editor })`. For a specific proposed write, use `checkProtectedTransaction({ editor, transaction })`. A preflight does not dispatch or emit events.
