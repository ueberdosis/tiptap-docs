`createSources<T>(inputs)` takes an array of `SourceInput<T>` records. Each record needs a unique, nonempty string `id`, a nonempty string `label`, and `data`. Use `createSources<unknown>(inputs)` for mixed data shapes. See [revision strategies](/citations/guides/sources#choose-a-revision-strategy) for `revision` and `getRevision`.

| Method | Result or effect |
| --- | --- |
| `add(input)` | Adds a source. Duplicate IDs throw. |
| `update(id, patch)` | Replaces the supplied `label`, `data`, or `revision` and keeps omitted fields. Unknown IDs throw. A label change preserves the revision. |
| `remove(id)` | Removes a source. Unknown IDs throw. |
| `get(id)` | Returns a frozen `SourceSnapshot<T>` or `undefined`. |
| `getAll()` | Returns a frozen snapshot array in insertion order. |
| `subscribe(listener)` | Returns an unsubscribe function. The listener receives `SourceChange` with a read-only `sourceIds` array. |
| `batch(callback)` | Combines changes into one notification at the end of the outermost synchronous batch. |

A source snapshot contains `id`, `label`, `revision`, and a frozen copy of `data`.

Source notifications are synchronous. Changes inside a listener queue another notification. The collection finishes delivery before rethrowing the first listener error. If a batch throws, it still keeps and reports successful changes.
