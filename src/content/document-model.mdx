## One document, several ways in

The same document serves people, applications, and agents. Each works with it through its own interface.

| Interface | Used by | What it does |
| --- | --- | --- |
| [Editor](/editor/getting-started/overview) | People | Renders the document and lets people write, format, and review it. |
| [Tiptap JSON](/editor/core-concepts/persistence) and the [REST API](/collaboration/documents/rest-api) | Your application and backend | Reads, stores, exports, and changes the content. |
| [AI Toolkit](/ai/ai-toolkit/overview) | AI agents | Gives agents tools that read and edit the document's structure instead of raw text or HTML. |
| [Collaboration](/collaboration/getting-started/overview) | Everyone editing at once | Keeps every copy of the document in sync, also offline. |

All interfaces share one [schema](/editor/core-concepts/schema). It defines which nodes and marks a document may contain.

## Two forms of the same content

A Tiptap document appears in two forms. They hold the same content and serve different jobs.

### Tiptap JSON

Tiptap JSON is a snapshot of the document tree: its nodes, marks, attributes, and text.

```json
{
  "type": "doc",
  "content": [
    {
      "type": "paragraph",
      "content": [{ "type": "text", "text": "Hello world" }]
    }
  ]
}
```

- It answers one question: what is in the document right now?
- It suits APIs, your own database, backups, exports, rendering, and agents.
- `editor.getJSON()` returns it, and `editor.commands.setContent()` loads it.

### Yjs

[Yjs](https://github.com/yjs/yjs) holds the document as a shared, conflict-free data type (a CRDT).

- It answers a different question: how do many people edit the same document at once?
- Changes travel as small updates, not as whole documents.
- Edits made offline merge without conflicts once the client reconnects.
- The [Collaboration extension](/editor/extensions/functionality/collaboration) keeps the editor and the Yjs document in step. The editor content lives in a Yjs XML fragment.

### How the two relate

| Question | Answer |
| --- | --- |
| Is the content the same? | Yes. Both follow the same schema. |
| Is a Yjs document just JSON in a wrapper? | No. Yjs stores its own data structure and its history of updates. |
| Can you read a collaborative document as JSON? | Yes, with `editor.getJSON()` or the [REST API](/collaboration/documents/rest-api). |
| Can JSON start a collaborative document? | Yes. The REST API creates documents from JSON with `format=json`. |
| Should you store a collaborative document as JSON only? | No. Store the Yjs updates. Rebuilding a Yjs document from JSON on every connection duplicates content. See [persistence in Hocuspocus](/hocuspocus/guides/persistence). |

## Without collaboration

The editor holds the document, and your application stores it as JSON.

```text
Editor  ↔  Tiptap JSON  ↔  your API and database
```

[Persistence](/editor/core-concepts/persistence) shows how to save and restore the JSON.

## With collaboration

Each editor binds to a shared Yjs document. A server syncs that document between everyone who has it open.

```text
Editor  ↔  Collaboration extension  ↔  Yjs document  ↔  Hocuspocus or the Document Server
                                                          └─ JSON for APIs, exports, and backups
```

- **Hocuspocus** is the open source WebSocket server that syncs Yjs documents. You run it and add storage and authentication.
- **The Document Server** is Tiptap's managed backend, in the cloud or on your own servers. It runs the same sync and adds storage, the REST API, webhooks, snapshots, and comments.

[Hosting](/hosting) compares Tiptap Cloud, on-premises, and Hocuspocus.
