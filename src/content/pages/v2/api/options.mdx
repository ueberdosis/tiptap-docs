Pass these to `PageLayout.configure`. Every option is optional.

```js
PageLayout.configure({
  setup: pageSetup('A4'),
  scrollMargin: { top: 64 },
})
```

The options of `createPageLayoutEditor` itself, such as `element` and `content`, are listed on the [install page](/pages/v2/getting-started/install#options-of-createpagelayouteditor).

Always build the whole `setup` with `pageSetup()`. Every field of a `PageSetup` is required, and `pageSetup()` fills them in.

## Page

| Option            | Type                                  | Default                        | Description                                                                                                                                                          |
| ----------------- | ------------------------------------- | ------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `setup`           | `PageSetup \| null`                   | `null`                         | The paper, margins and colors a document starts on. `null` gives an editor without pages. A page setup stored in the document overrules it.                          |
| `sections`        | `PageSection[]`                       | none                           | Section breaks written into the document when the editor is created, if `setup` is not `null`. Each entry has a `startBlockIndex`, a `setup` and an optional `kind`. |
| `chapterNumberOf` | `ChapterNumberOf`                     | `chapterNumbersFromHeadings()` | Returns the chapter a page number is written with, as in 2-1 and 2-2.                                                                                                |
| `blockBreaksOf`   | `(block, doc) => BlockBreaks \| null` | none                           | Sets how a top-level block meets a page boundary, as a paragraph style does in Word. `null` leaves it to the node type.                                              |

`chapterNumberOf` is a function that receives `{ doc, from, to, level }` and returns a string or `null`. `BlockBreaks` has the optional booleans `keepWithNext`, `keepTogether` and `pageBreakBefore`. See [custom nodes](/pages/v2/guides/custom-nodes#per-block-from-a-style). For `setup`, see [page format](/pages/v2/core-concepts/page-format).

Without a way to number chapters, `setPageNumbering` refuses a `chapter`. The default rule counts the headings of your schema. Pass `chapterNumbersFromHeadings({ label })` to write the number yourself. See [page numbers](/pages/v2/core-concepts/page-numbers).

## Features

Each of these is on by default. Pass `false` to turn it off. That also takes its node out of the schema.

| Option              | Type    | Default | Turns off                                                    |
| ------------------- | ------- | ------- | ------------------------------------------------------------ |
| `pageBreak`         | `false` | on      | Manual page breaks.                                          |
| `columnBreak`       | `false` | on      | Manual column breaks.                                        |
| `sectionBreak`      | `false` | on      | Section breaks.                                              |
| `pageFurniture`     | `false` | on      | Headers and footers. Also turns off `furnitureClicks`.       |
| `pageNumber`        | `false` | on      | The page number a header or footer can hold.                 |
| `tablePagination`   | `false` | on      | `breakAcrossPages` and `repeatHeaderRow` on tables and rows. |
| `columnsPagination` | `false` | on      | `keepTogether` on a column layout.                           |
| `listPagination`    | `false` | on      | `keepTogether` on a bullet or ordered list.                  |

A document that already holds a node you turned off can't load. `setContent` fails with `Unknown node type: pageBreak`, for example. Turn a feature off only for documents that never had it, or remove those nodes from the content first.

The commands for a page break, column break, section break, header, footer or page number return `false` while their feature is off, also under `editor.can()`.

## Drawing

| Option               | Type                   | Default                   | Description                                                                                                           |
| -------------------- | ---------------------- | ------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| `sheetAppearance`    | `'paper' \| 'none'`    | `'paper'`                 | `'paper'` draws white sheets with a shadow. `'none'` draws only the geometry, so your CSS styles the paper.           |
| `breaksWithoutPages` | `'lines' \| 'none'`    | `'lines'`                 | Draws page, column and section breaks as labeled lines in an editor without pages. `'none'` draws nothing.            |
| `breakLabels`        | `Partial<BreakLabels>` | English names             | The text of those lines, for another language. Keys: `page`, `region`, `section` and `sectionColumns`.                |
| `scrollMargin`       | `{ top?, bottom? }`    | `{ top: 48, bottom: 48 }` | Pixels left free at the edges of the viewport whenever the editor scrolls something into view.                        |
| `virtualization`     | `boolean`              | `true`                    | Fills only the sheets near the user's view. Every sheet keeps its size, so the scrollbar and page numbers stay right. |
| `layoutHint`         | `LayoutHintStore`      | none                      | Where Page Layout keeps what it measured, so a long document opens on its pages. See below.                           |

Defaults of `breakLabels` are `Page break`, `Column break`, `Section break` and `Section break · {count} columns`. Name only the labels you change. `{count}` stands for the number of columns and can sit anywhere in the string.

Set `scrollMargin.top` higher when a toolbar covers the top of the viewport. Page Layout can't see it. See [styling](/pages/v2/core-concepts/styling) for `sheetAppearance` and `scrollMargin`.

`virtualization: false` draws every sheet all the time. Printing draws every sheet either way. See [long documents](/pages/v2/guides/long-documents).

### layoutHint

A `LayoutHintStore` has two methods:

- `load(key: string): Promise<LayoutHint | null>` returns the hint saved under the key, or `null`.
- `save(key: string, hint: LayoutHint): void` keeps a hint.

Without a store, a long document opens on estimates and its pages move while the text is measured. With one, Page Layout asks for the hint when the document opens. It saves a new one after measuring, once the document has been still for a second.

A hint is a first guess. Every block is still measured, and a hint for another document, paper or font is ignored. The document never holds it.

## Clicks

| Option            | Type    | Default | Description                                                                                                                                  |
| ----------------- | ------- | ------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| `furnitureClicks` | `false` | on      | Double-click a header or footer to edit it. Double-click the text or press Escape to go back. `false` leaves the way in to your own buttons. |

`openFurniture` and `closeFurniture` work with or without it.

## Document

| Option                    | Type                               | Default                | Description                                                                                                  |
| ------------------------- | ---------------------------------- | ---------------------- | ------------------------------------------------------------------------------------------------------------ |
| `source`                  | `SourceDocumentOptions`            | local history          | The source document's plugins, history and presence. Collaboration replaces the history through this option. |
| `onCommandOnPages`        | `(report: CommandOnPages) => void` | warns once per command | Runs when a command wrote something to the pages that could not be carried back to the document.             |
| `experimentalSourceState` | `boolean`                          | `false`                | Experimental. `editor.state` holds the document instead of the pages.                                        |

`SourceDocumentOptions` takes `plugins`, `undo` and `redo`. It also takes `keepsLocalSelection`, `bookmarkSelection` and `carets`, which collaboration sets for you.

`CommandOnPages` has `command`, `extension`, `reason` and `refused`. `refused` is `true` when nothing was written and `false` when the edit was recomputed. Pass a function that does nothing to silence the console warning. See [custom nodes](/pages/v2/guides/custom-nodes#commands-of-your-own-extension) and [collaboration](/pages/v2/guides/collaboration#set-it-up).

With `experimentalSourceState`, positions you pass to Tiptap commands are positions in the document. `editor.view.state` still holds the pages. A position read from `editor.state` and passed to `coordsAtPos` or `domAtPos` is wrong.
