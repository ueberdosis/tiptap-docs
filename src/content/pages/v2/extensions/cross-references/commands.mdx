These are Tiptap commands, so they chain and work with `can()`:

```js
editor.commands.insertCrossReference({ target: 'scope-of-work', show: 'title' })
editor.can().resetCrossReference()
```

A command that can't do anything returns `false` and changes nothing. A toolbar uses that to disable a button.

The commands that act on one reference take its position. Without one, they act on the reference at the cursor, which is the one the cursor is in or the one that is selected.

## insertCrossReference(options)

Inserts a reference at the selection and replaces what is selected.

```js
editor.commands.insertCrossReference({
  target: pos, // the position the target starts at, or its id
  show: 'relativeNumber',
  hyperlink: true,
  aboveBelow: false,
  numberSeparator: null,
})

editor.commands.insertCrossReference({ targets: ['payment', 'term'], show: 'number' })
```

- `target` is one target, by the position it starts at or by its id.
- `targets` is several, shown as `3, 5 and 7`. It works only with `multiple: true`.
- `show`, `hyperlink`, `aboveBelow` and `numberSeparator` are described under [references](/pages/v2/extensions/cross-references#references).
- `join` is the rule that joins several targets: `'list'`, `'commas'`, `'range'` or one of yours. The default is `null`, the configured one. See [several targets](/pages/v2/extensions/cross-references/joins).

A target that has no id yet gets one in the same step. In `'manual'` mode the reference holds the text its targets say from the start, and the cursor goes after it.

The command returns `false` in these cases:

- A target isn't a registered one.
- A target has no id and `defineIdAttribute` is `false`.
- Several targets are named without `multiple`.
- The selection isn't in text.

## setCrossReferenceOptions(options, pos?)

Changes how a reference reads its targets. The options are `show`, `hyperlink`, `aboveBelow`, `numberSeparator`, `join`, and `targetIds` for which targets it names. A choice you leave out stays as it is.

```js
editor.commands.setCrossReferenceOptions({ show: 'page', aboveBelow: true })
```

The reference keeps the text it holds. Call `resetCrossReference()` afterwards to give it what the new choices read. The command returns `false` when there is no reference, or nothing changes.

## setCrossReferenceShow(pos, show)

Sets what the reference at `pos` shows. It is `setCrossReferenceOptions({ show }, pos)` on its own.

## resetCrossReference(pos?)

Gives a reference back to its targets. In `'live'` mode the command removes the text written into it, and it follows its targets again. In `'manual'` mode it gets what its targets say now. It returns `false` where the reference already reads that.

## updateCrossReferences()

Does what F9 does. Every reference holding text gets what its targets say now. In `'live'` mode those are the references somebody wrote into. In `'manual'` mode it is all of them. The command skips locked references, and returns `false` when no reference changes.

## setCrossReferenceLocked(locked, pos?)

Sets whether `updateCrossReferences()` leaves the reference alone. You can still edit, reset and remove a locked reference. The command returns `false` where it is already locked or unlocked.

## convertCrossReferenceToText(pos?)

Replaces a reference with the words it reads, as plain text with the reference's marks. That is its own text where it holds some, and what its targets say where it doesn't. The command returns `false` where there is no reference, or where an empty one has nothing to read because its target is gone.

## convertCrossReferencesToText()

Does the same for every reference in the document, locked ones included. References to a target that is gone stay. The command returns `false` when there is nothing to convert.

## removeCrossReference(pos?)

Takes a reference out of the text, with whatever it holds. It returns `false` where there is no reference.

## goToCrossReferenceTarget(targetId)

Puts the cursor at the start of a target's text and scrolls to it. This is where following a reference leads. Name the target by the id a reference stores. The command returns `false` for an id no target in the document carries, and for a target a [source](/pages/v2/extensions/cross-references/sources) resolves from outside the document.

```js
editor.view.focus()
editor.commands.goToCrossReferenceTarget('payment')
```

## refreshCrossReferences()

Reads every reference again, and asks every [source](/pages/v2/extensions/cross-references/sources) outside the document for its targets again. Call it when the data behind those targets changed, because the editor can't see that by itself. Nothing in the document changes, so it isn't part of the undo history and doesn't reach collaborators. It always returns `true`.

## setCrossReferenceUpdate(update)

Sets `'live'` or `'manual'` while the editor runs. It is the [`update`](/pages/v2/extensions/cross-references#update-references) option. It changes no reference. One that is empty when the mode becomes `'manual'` reads its targets until you reset or update it.

The command returns `false` when the mode is already that, and for `'manual'` with [`holdsText: false`](/pages/v2/extensions/cross-references#references-that-hold-no-text).

## With `holdsText: false`

`setCrossReferenceUpdate('manual')`, `updateCrossReferences()`, `convertCrossReferenceToText()` and `convertCrossReferencesToText()` return `false`, and `insertCrossReference` stores no text. See [references that hold no text](/pages/v2/extensions/cross-references#references-that-hold-no-text).

The commands never update or convert a reference to a [withheld target](/pages/v2/extensions/cross-references#withheld-targets).

## Write with transactions

The same writes exist as functions that return the transaction instead of dispatching it. They return `null` where the command would return `false`. `writing` is `editor.storage.crossReferences`:

| Command                        | Function                                                        |
| ------------------------------ | --------------------------------------------------------------- |
| `insertCrossReference`         | `insertCrossReferenceTransaction(state, writing, options)`      |
| `setCrossReferenceOptions`     | `setCrossReferenceOptionsTransaction(state, pos, options)`      |
| `setCrossReferenceShow`        | `setCrossReferenceShowTransaction(state, pos, show)`            |
| `resetCrossReference`          | `resetCrossReferenceTransaction(state, writing, pos)`           |
| `updateCrossReferences`        | `updateCrossReferencesTransaction(state, writing)`              |
| `setCrossReferenceLocked`      | `setCrossReferenceLockedTransaction(state, pos, locked)`        |
| `convertCrossReferenceToText`  | `convertCrossReferenceToTextTransaction(state, writing, pos)`   |
| `convertCrossReferencesToText` | `convertCrossReferencesToTextTransaction(state, writing)`       |
| `removeCrossReference`         | `removeCrossReferenceTransaction(state, pos)`                   |
| `goToCrossReferenceTarget`     | `goToCrossReferenceTargetTransaction(state, writing, targetId)` |

In a paginated editor, the commands write the source document, not the pages. See [commands on pages](/pages/v2/extensions/cross-references#commands-on-pages).
