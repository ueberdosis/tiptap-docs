A block selected from its first character to its last is deleted, cut and copied as a block. Nothing empty stays behind, such as an empty heading or an outline number left standing on a line with no text. Word calls this smart paragraph selection.

`@tiptap-pro/extension-whole-blocks` works in any editor, with or without pages. A block here is any textblock, such as a paragraph, a heading or a code block.

## Install

```bash
npm install @tiptap-pro/extension-whole-blocks
```

The package comes from Tiptap's private registry. See [set up the registry](/pages/v2/getting-started/install#set-up-the-registry) if you haven't yet.

## Add it to an editor

```js
import { Editor } from '@tiptap/core'
import StarterKit from '@tiptap/starter-kit'
import { WholeBlocks } from '@tiptap-pro/extension-whole-blocks'

const editor = new Editor({
  extensions: [StarterKit, WholeBlocks],
})
```

## What changes

- Backspace or Delete over a selection that covers whole blocks removes them. The caret lands at the start of the block that followed.
- Cut does the same. Copy, cut and drag put whole blocks on the clipboard. A paste then inserts them as blocks of their own instead of pouring their text into the block at the cursor.
- A selection from the first character of a block into a later one removes the blocks it covers. What is left of the last block keeps that block's type.
- Typing over such a selection replaces the text and keeps the block.

A selection that starts after the first character behaves as in any Tiptap editor. The text goes, and the block stays.

A block that is the only content of a list item takes the list item along. A block that is the only content of a table cell, or of anything else `isolating`, leaves the cell with an empty paragraph. So does the only block of the document.

## Options

```js
WholeBlocks.configure({ ignore: (node) => node.attrs.isCopy === true })
```

`ignore` is a function of a node, and `null` by default. A textblock it returns `true` or `'descend'` for is a piece of a block drawn somewhere else. A selection that starts in one, or ends where one carries on, is left to the default.

A container it returns `'descend'` for holds whole blocks. That is the rest of a list drawn somewhere else, for example. A block that ends right before such a container is whole.

## Switch it off

Leave it out of the extensions. No option turns it off while it is registered.

## Write with transactions

```js
import {
  blockCoverOf,
  deleteWholeBlocksTransaction,
  wholeBlockSlice,
} from '@tiptap-pro/extension-whole-blocks'

blockCoverOf(editor.state, null) // what the selection covers, or null
deleteWholeBlocksTransaction(editor.state, null) // the deletion, or null
wholeBlockSlice(editor.state, null) // what a copy puts on the clipboard, or null
```

The second argument is `ignore`. A `null` result from any of them means the selection doesn't cover whole blocks, and the default applies.

## On pages

With pages, pass `ignoreLayoutArtifacts` so a block that carries on over a page is recognized as one:

```js
import {
  createPageLayoutEditor,
  ignoreLayoutArtifacts,
  PageLayout,
  pageSetup,
} from '@tiptap-pro/extension-page-layout'
import { WholeBlocks } from '@tiptap-pro/extension-whole-blocks'

createPageLayoutEditor({
  element,
  content,
  extensions: [
    StarterKit,
    WholeBlocks.configure({ ignore: ignoreLayoutArtifacts }),
    PageLayout.configure({ setup: pageSetup('A4') }),
  ],
})
```

`ignoreLayoutArtifacts` is described in [extensions on pages](/pages/v2/extensions/overview#packages-that-work-without-pages).

A selection that ends at the foot of a page, in a block that carries on at the top of the next, covers part of a block. The default handles it. The last item of a list cut between two items is whole, and the extension deletes it as one.
