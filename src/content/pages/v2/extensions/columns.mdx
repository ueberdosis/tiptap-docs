A column layout puts containers side by side, each with content of its own. Think of a picture beside its caption, two versions of a clause next to each other, or a row of three short notes. You edit, select and move every column on its own, and its content stays in it.

The text in one column doesn't flow into the next. For text that fills the bottom of the first column and continues at the top of the second, use [section columns](/pages/v2/core-concepts/section-columns).

## Install

```bash
npm install @tiptap-pro/extension-columns
```

The package comes from Tiptap's private registry. See [set up the registry](/pages/v2/getting-started/install#set-up-the-registry) if you haven't yet.

## Add it to an editor

`@tiptap-pro/extension-columns` works in any Tiptap editor, with or without pages. A layout grows with its content.

```js
import { Editor } from '@tiptap/core'
import StarterKit from '@tiptap/starter-kit'
import { Columns } from '@tiptap-pro/extension-columns'

const editor = new Editor({
  extensions: [StarterKit, Columns],
})

editor.commands.insertColumns({ count: 2 })
```

## What the document holds

`Columns` registers two node types together:

| Type           | What it is                                                                 |
| -------------- | -------------------------------------------------------------------------- |
| `columnLayout` | The row. It holds two to six `column` nodes.                               |
| `column`       | One column. It holds any blocks, such as paragraphs, headings and a table. |

```json
{
  "type": "columnLayout",
  "attrs": { "gap": "32px", "widthMode": "custom", "widths": ["1fr", "2fr"] },
  "content": [
    { "type": "column", "content": [{ "type": "paragraph" }] },
    { "type": "column", "content": [{ "type": "paragraph" }] }
  ]
}
```

| Attribute   | What it holds                                                                                            |
| ----------- | -------------------------------------------------------------------------------------------------------- |
| `gap`       | The space between columns, as a CSS length. A layout with `null` is drawn with a gap of `24px`.          |
| `widthMode` | `'equal'` or `'custom'`.                                                                                 |
| `widths`    | One CSS track size per column, such as `'1fr'` or `'240px'`. It is read while `widthMode` is `'custom'`. |

The layout is drawn with equal columns until `widths` has one entry per column. Adding, removing or setting the number of columns on a layout with custom widths makes the columns equal again.

A layout is a top-level block. A layout inside a column is valid content, for example from a paste, but no command creates one.

## Options

```js
Columns.configure({
  minColumns: 2,
  maxColumns: 6,
  defaultGap: '24px',
  defaultWidthMode: 'equal',
})
```

| Option             | What it does                                               |
| ------------------ | ---------------------------------------------------------- |
| `minColumns`       | The fewest columns a layout can have. Default `2`.         |
| `maxColumns`       | The most columns a layout can have. Default `6`.           |
| `defaultGap`       | The `gap` of a layout you insert. Default `'24px'`.        |
| `defaultWidthMode` | The `widthMode` of a layout you insert. Default `'equal'`. |

`minColumns` and `maxColumns` are part of the schema. Content with more or fewer columns doesn't load, so every editor on one shared document needs the same numbers.

## Commands

Every command except `insertColumns` works on the layout the cursor is in, or on a layout selected as a node. It returns `false` outside one.

| Command                    | What it does                                                                                                                                                                                                                                                                    |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `insertColumns(options?)`  | Inserts a layout of empty columns after the top-level block at the cursor and puts the caret in the first column. An empty paragraph or heading at the cursor is replaced. `options` takes `count`, `gap` and `widthMode`. `count` is clamped to `minColumns` and `maxColumns`. |
| `setColumnCount(count)`    | Adds or removes columns at the end. The content of a removed column moves into its neighbor.                                                                                                                                                                                    |
| `setColumnGap(gap)`        | Sets the space between the columns, as a CSS length.                                                                                                                                                                                                                            |
| `setColumnWidthMode(mode)` | Sets `'equal'` or `'custom'`. `'equal'` also clears `widths`.                                                                                                                                                                                                                   |
| `setColumnWidths(widths)`  | Sets one track size per column and switches `widthMode` to `'custom'`. `null` makes the columns equal. A list of the wrong length does nothing and returns `false`.                                                                                                             |
| `addColumn(options?)`      | Adds an empty column after the one the cursor is in, or before it with `{ position: 'before' }`. It does nothing at `maxColumns`.                                                                                                                                               |
| `removeColumn()`           | Removes the column the cursor is in. Its content moves into the next column, or into the previous one for the last column. It does nothing at `minColumns`.                                                                                                                     |
| `moveColumn(direction)`    | Moves the column the cursor is in to the `'left'` or `'right'`, and the caret with it.                                                                                                                                                                                          |
| `deleteColumns()`          | Removes the whole layout, with its columns and content.                                                                                                                                                                                                                         |
| `exitColumns(options?)`    | Puts the caret in the block after the layout, or before it with `{ direction: 'before' }`. It creates an empty block where there is none.                                                                                                                                       |

```js
editor.commands.setColumnWidths(['1fr', '2fr'])
editor.can().addColumn() // false at maxColumns, or outside a layout
```

`addColumn`, `removeColumn` and `moveColumn` need the cursor inside a column. They return `false` for a layout selected as a whole.

## Keys

| Key                                               | What it does                                                                                                 |
| ------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| `Mod-Enter`                                       | Leaves the layout with `exitColumns()`.                                                                      |
| `ArrowLeft`, `Backspace` at the start of a column | Moves the caret to the end of the previous column. Backspace deletes nothing there.                          |
| `ArrowRight` at the end of a column               | Moves the caret to the start of the next column.                                                             |
| `ArrowDown`, `ArrowUp`                            | Leave the layout at its end when it is the last block of the document, or at its start when it is the first. |

Everywhere else the keys do what they do in any block. With Page Layout, the page break shortcut wins over `Mod-Enter`, so a page break asked for inside a column is still a page break.

## Styling

The extension puts the grid rules into the page itself, first in `head`, so a stylesheet of yours wins over them. The rules draw the row. They keep every column to its share, even with a long word or a wide image in it. Columns of different length keep their own height.

| Selector                        | What it matches                                              |
| ------------------------------- | ------------------------------------------------------------ |
| `.tiptap-columns-layout`        | The layout, also `[data-tt-column-layout]`.                  |
| `.tiptap-columns-column`        | A column, also `[data-tt-column]`.                           |
| `.tiptap-columns-column-active` | The column the cursor is in. The extension gives it no look. |

| Custom property      | What it holds                                |
| -------------------- | -------------------------------------------- |
| `--tt-column-gap`    | The gap of the layout, set on its element.   |
| `--tt-column-widths` | The track list, while the widths are custom. |

Nothing has a border or a background. An outline on the active column is one rule:

```css
.tiptap .tiptap-columns-column-active {
  outline: 1px dashed rgba(0, 0, 0, 0.2);
}
```

The rules go into the page when the editor is created, as a `style` element that carries the editor's `injectNonce`. With `injectCSS: false` they are left out, and without them the columns stack. `columnStyleRules()` returns the rules as a string for a stylesheet of your own. `mountColumnStyles(document, { nonce })` puts them into a document once.

## Write with transactions

Every command has a transaction function of the same name. It takes positions instead of reading the selection, so you can write several changes in one step:

```js
import { columnLayoutAt, setColumnGapTransaction } from '@tiptap-pro/extension-columns'

const at = columnLayoutAt(editor.state.doc, editor.state.selection.from)

if (at) {
  editor.view.dispatch(setColumnGapTransaction(editor.state.tr, at.pos, '48px'))
}
```

`columnLayoutAt(doc, pos)` returns `{ node, pos, columnIndex }` for the innermost layout around a position, or `null` outside one. `columnIndex` is `-1` between columns. `columnBounds(layout, layoutPos, index)` returns where one column sits as `{ node, pos, start, end }`.

The other functions are `insertColumnsTransaction`, `setColumnCountTransaction`, `setColumnWidthModeTransaction`, `setColumnWidthsTransaction`, `addColumnTransaction`, `removeColumnTransaction`, `moveColumnTransaction`, `deleteColumnsTransaction` and `exitColumnsTransaction`.

## On pages

Register `Columns` next to Page Layout. It needs no other setup.

A column layout is cut at one height through all of its columns at once. Each column carries on at the top of the next page, and a column that ended above the cut is empty there.

An author can keep a layout on one page:

```js
editor.commands.setColumnLayoutKeepTogether(true)

editor.storage.pageLayout.engine.getColumnLayoutContext()
// { layout, layoutPosition, keepTogether }, or null outside a layout
```

The layout then moves to the next page whole. It stores the setting as `keepTogether`. Like every keep-together setting, it is a [preference](/pages/v2/extensions/overview#keep-together-is-a-preference): a layout taller than a page is cut anyway.

`PageLayout.configure({ columnsPagination: false })` takes the setting away.
