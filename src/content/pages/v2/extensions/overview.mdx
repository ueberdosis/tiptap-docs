Every block in the document meets the bottom of a page one way or another, and the type decides what happens. A paragraph is cut between two of its lines. A list moves an item to the next page whole. A horizontal rule is never cut.

This page covers the standard types and the settings an author can make about a list. Each Pro extension that behaves differently on pages has its own page. Every one of them also works without pages and is described completely in its own documentation.

## What the standard types do

| Type                        | At the bottom of a page                                                                                  |
| --------------------------- | -------------------------------------------------------------------------------------------------------- |
| `paragraph`                 | Cut between two lines.                                                                                   |
| `heading`                   | Cut between two lines.                                                                                   |
| `codeBlock`                 | Cut between two lines. The continuation stays a code block.                                              |
| `blockquote`                | Cut between two of its blocks. A paragraph inside it is then cut between lines.                          |
| `horizontalRule`            | Never cut. It moves to the next page.                                                                    |
| `hardBreak`                 | Ends a line, so a page can be cut right after it.                                                        |
| `bulletList`, `orderedList` | Cut between two items. The item the boundary landed in moves on whole.                                   |
| `table`                     | Cut between rows, and through a row where that is not enough. See [tables](/pages/v2/extensions/tables). |
| `columnLayout`              | Cut at one height through all of its columns. See [column layout](/pages/v2/extensions/columns).         |

A continuation is not a second node in the document. The document keeps one paragraph, one list and one table. The two halves on screen are two views of it. An ordered list that carries on over a page keeps counting across the boundary, and a cut block has the same attributes and marks on both sides.

## Keep a list on one page

Two settings sit on the list, and both match Word:

```js
// Word's "Keep lines together": the list moves to the next page whole.
editor.commands.setListKeepTogether(true)

// Word's "Allow row to break across pages", for a list: an item may be cut between two lines.
editor.commands.setListBreakItems(true)
```

The list stores them as `keepTogether` and `breakItemsAcrossPages`, and both are `false` by default. Out of the box, a list breaks between its items and never inside one. Both commands return `false` when the cursor is not in a list. See [commands](/pages/v2/api/commands#tables-columns-and-lists).

A caret in a nested item answers with the outermost list. That is the block the page boundary meets, and holding a sub-list together does nothing while the list around it can break anywhere.

`PageLayout.configure({ listPagination: false })` takes both settings away.

### Read the state

```js
const context = editor.storage.pageLayout.engine.getListContext()
```

`getListContext()` returns `null` when the cursor is not in a list. Otherwise it returns:

| Field                   | What it holds                                                                                        |
| ----------------------- | ---------------------------------------------------------------------------------------------------- |
| `list`, `listPosition`  | The list node and where it starts.                                                                   |
| `keepTogether`          | Whether the list stays on one page.                                                                  |
| `breakItemsAcrossPages` | Whether an item may be cut.                                                                          |
| `itemCount`             | How many items the list has. A one-item list makes both settings pointless, so a toolbar can say so. |

## Keep together is a preference

A block that is taller than a page is cut anyway. The alternative is a block hanging off the bottom of the sheet, so the engine gives up on the setting and keeps the page. The block keeps the setting the author gave it, and only that boundary ignores it.

A toolbar can find out and say so:

```js
const engine = editor.storage.pageLayout.engine
const context = engine.getListContext()

if (context?.keepTogether) {
  const cut = engine.isDividedInView(
    context.listPosition,
    context.listPosition + context.list.nodeSize,
  )

  if (cut) {
    // The list is taller than a page. Tell the author instead of leaving the switch looking broken.
  }
}
```

`isDividedInView(from, to)` takes positions in the document. It returns `true` when the content between them is drawn in more than one piece, on two pages or in two columns. It works for a table row, a list, a column layout or a paragraph.

A manual page break inside such a block always counts. An author who put a break in the middle of a list said where it ends, so the two settings don't compete with it.

## Packages that work without pages

These packages work in any editor and don't depend on Page Layout. On pages, a block cut across two pages is drawn as two nodes, and the header or footer being edited is a node too. Each package takes the reader Page Layout exports, `ignoreLayoutArtifacts`, as its `ignore` option to leave those out.

`ignoreLayoutArtifacts(node)` returns:

- `true` for a header or footer, and for the rest of a paragraph or heading that continues from the page before. Neither the node nor anything in it belongs to the document.
- `'descend'` for the rest of a list, quote or other container that continues from the page before. The container is not a block of its own, but the items in it are. A list cut between its third and fourth item has its fourth item on the next page.
- `false` for everything else.

`isLayoutArtifact(node)` gives the same answer as a boolean. It returns `true` wherever the other function doesn't return `false`. Use it in your own code that only asks whether a node stands for itself.

## Limitations

Page Layout has no widow and orphan control and no keep-with-next rule for headings. [Limitations](/pages/v2/core-concepts/limitations#pagination) lists both, with the ways to keep a block on one page.
