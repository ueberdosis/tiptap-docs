Add footnotes and endnotes to a Tiptap editor. A footnote appears at the foot of its page and an endnote at the end of the document. Both are the same node, and one attribute switches between them.

`@tiptap-pro/extension-footnotes` works in any editor, with or without pages. It brings the nodes, the commands and the numbering.

## Install

```bash
npm install @tiptap-pro/extension-footnotes
```

The package comes from Tiptap's private registry. See [set up the registry](/pages/v2/getting-started/install#set-up-the-registry) if you haven't yet.

## Add it to an editor

```js
import { Editor } from '@tiptap/core'
import StarterKit from '@tiptap/starter-kit'
import { Footnotes } from '@tiptap-pro/extension-footnotes'

const editor = new Editor({
  extensions: [StarterKit, Footnotes],
})

editor.commands.insertFootnote()
```

Without pages, the editor shows every note at the end of the document, with footnotes in one run and endnotes in another. With Page Layout, a footnote appears at the foot of the page that refers to it. See [on pages](#on-pages).

## What the document holds

A `footnoteReference` sits at the place in the text. The note's text sits in a `footnoteCollection` at the end of the document. There is one collection per placement, so footnotes and endnotes stay apart, and one per numbering scope.

A footnote is one reference and one note. Copying text with a reference in it copies the note as well:

- Copy and paste gives the pasted reference a note of its own, with the same text, under a new `footnoteId`. The original keeps its identity.
- Cut and paste, and dragging text, keep the `footnoteId` and the note.
- Pasting into another document brings the note along.
- A second reference to the same note, from a source that didn't carry the note or from a script, gets its own copy of the note. The first reference in the text keeps the original.

To refer to a note a second time, write "see note 3" as text. A note has one reference.

The collections come after the last block that has content. Empty paragraphs at the end of the document stay after them, and that includes `StarterKit`'s trailing paragraph. Once you type into one, the collections move after it.

## Commands

```js
editor.commands.insertFootnote()
editor.commands.insertFootnote({ placement: 'endnote' })
```

Both put a reference at the cursor, add a note for it and move the cursor into the note.

| Command                                                     | What it does                                                                   |
| ----------------------------------------------------------- | ------------------------------------------------------------------------------ |
| `insertFootnote(options?)`                                  | Inserts a note. `options.placement` defaults to the `defaultPlacement` option. |
| `deleteFootnote(footnoteId)`                                | Removes the note and every reference to it in one step.                        |
| `setFootnotePlacement(footnoteId, 'footnote' \| 'endnote')` | Turns a footnote into an endnote and back. It is the same note.                |
| `focusFootnote(footnoteId)`                                 | Puts the cursor in the note's text, wherever the editor shows it.              |
| `focusFootnoteReference(footnoteId)`                        | Moves from a note back to the place in the text it annotates.                  |
| `insertNoteNumberingBreak(options?)`                        | Inserts a boundary after which both kinds count from the start again.          |

Every note has a `footnoteId`, and the commands and click handlers take it. A position wouldn't work, because the editor can show a note somewhere other than where the document keeps it.

`defaultPlacement` is `'endnote'` unless you set it. To make `insertFootnote()` insert footnotes, pass `defaultPlacement: 'footnote'` to `Footnotes.configure`.

`footnoteAtSelection(selection)` returns the note a selection is on, and whether it is in the reference or the note. Use it when a toolbar decides whether to offer going to the note or back to the reference:

```js
import { footnoteAtSelection } from '@tiptap-pro/extension-footnotes'

footnoteAtSelection(editor.state.selection)
// { footnoteId: 'fn3', in: 'note' }, { footnoteId: 'fn3', in: 'reference' } or null
```

## Click a reference or a mark

Both handlers are off by default, because a click on a reference selects it by default. Turn them on to get the pair a user expects. The reference leads to the note, and the mark at the head of the note leads back to the sentence:

```js
Footnotes.configure({
  onReferenceClick: ({ footnoteId }) => editor.commands.focusFootnote(footnoteId),
  onNoteMarkClick: ({ footnoteId }) => editor.commands.focusFootnoteReference(footnoteId),
})
```

Both handlers return a boolean. Return `true` when you handled the click. A paginated editor sets both when you leave them out. See [on pages](#on-pages).

## Numbering

Footnotes and endnotes count independently, so the mark tells the reader which of the two to look for. Footnotes read 1, 2, 3 and endnotes read i, ii, iii:

```js
Footnotes.configure({
  footnoteNumbers: { format: 'decimal', start: 1 },
  endnoteNumbers: { format: 'lowerRoman', start: 1 },
})
```

Those two values are the defaults. `format` is one of the [number formats](/pages/v2/extensions/number-formats), and `start` is the first number of the sequence. Name only the one you change, and the other keeps its default.

`insertNoteNumberingBreak()` puts a boundary at the cursor. After it, both kinds start again. A collapsed cursor in the middle of a paragraph splits the paragraph, and each scope keeps its own runs of notes.

The document never holds a number. The editor draws the mark, so a note inserted above renumbers every note after it without an edit.

| Option             | What it does                                                                                                |
| ------------------ | ----------------------------------------------------------------------------------------------------------- |
| `defaultPlacement` | `'footnote'` or `'endnote'`. What `insertFootnote` makes when you don't say. Default `'endnote'`.           |
| `numbering`        | `false` draws no marks, for an integration that draws its own. Default `true`.                              |
| `counter`          | A function that says which mark each note gets, for an integration that counts differently. Default `null`. |
| `scopes`           | A function that says where a numbering scope ends, instead of the numbering breaks. Default `null`.         |

Set `counter` and `scopes` together or neither. With only one of them, the marks count one way and the runs of notes split another.

## Titles above a run of notes

By default a run of notes has no title, which is what a printed document does. To get a heading instead:

```js
Footnotes.configure({
  titleNode: 'heading',
  footnoteTitle: 'Notes',
  endnoteTitle: 'Endnotes',
})
```

`titleNode` is the name of a node type from your own schema. What a heading is, whether it belongs in the outline and what it looks like, is yours to decide. The extension writes the two words once, when the run of notes comes into being. After that the heading is content, and the user can rename it. `footnoteTitle` defaults to `'Footnotes'` and `endnoteTitle` to `'Endnotes'`.

## Keep notes and references in agreement

A pass in the editor keeps every note tied to a reference and in the order of the references. Deleting a reference deletes its note. A second reference to the same note gets a copy of its own.

| Option          | What it does                                                                                                                    |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| `repair`        | `false` turns the pass off. Default `true`.                                                                                     |
| `notesDocument` | A function of the editor that returns the document a copy takes notes from. Default `null`, which is the editor's own document. |

An editor with pages runs the pass on the document instead of on what it draws, and sets `notesDocument` itself. See [on pages](#on-pages).

## Paste from Word

Footnotes and endnotes copied in Word paste as notes. The reference lands where Word's mark was, and the note's text goes into the run of notes. A footnote stays a footnote and an endnote stays an endnote. Each note gets a new identity, and the editor numbers it with the others.

A mark whose note wasn't copied stays as the anchor Word wrote. That happens when you copy text without the end of the document, where Word keeps its notes.

`Footnotes` adds this itself. The package exports both steps for an editor that handles pastes some other way. `wordNotesToHtml(html)` returns the HTML with references in place of Word's marks, and the text of each note by identity. `sliceCarryingWordNotes(slice, notes, schema, parse)` gives each pasted reference its note.

## On pages

Page Layout adds the part that needs paper. It pulls a note to the foot of the page that refers to it, and it restarts the count on every sheet or in every section.

### Set it up

Register the extension next to Page Layout, configured as it would be without pages:

```js
import StarterKit from '@tiptap/starter-kit'
import { Footnotes } from '@tiptap-pro/extension-footnotes'
import { createPageLayoutEditor, PageLayout, pageSetup } from '@tiptap-pro/extension-page-layout'

createPageLayoutEditor({
  element,
  content,
  extensions: [StarterKit, Footnotes, PageLayout.configure({ setup: pageSetup('A4') })],
})
```

Page Layout sets three of the extension's options itself, and replaces any value you pass for them:

- `counter` counts the marks over the pages. With restart on each page, the same note is note 1 on one sheet and note 4 counted through the document. Only the side that knows where the pages fall can say which. The extension still draws the mark, in the format the section asks for.
- `scopes` ends a run of notes where a section starts a new count. Page Layout doesn't read the extension's numbering breaks. A section whose `noteNumbering` restarts either kind of note, with `restart` set to `'section'` or `'page'`, takes their place.
- `notesDocument` makes a copy take each note whole and once, wherever the pages draw it, including when a page boundary splits it.

The `repair` pass runs on the source document, not on the pages. Page Layout can draw a long run of notes as two runs, and a pass that read the pages would write that back. Turning `repair` off turns it off on the source document as well.

A click on a reference leads to its note, and a click on the mark at the head of a note leads back to the sentence. You don't need `onReferenceClick` or `onNoteMarkClick` for that. Page Layout runs `focusFootnote` and `focusFootnoteReference`, and draws the note's page if it isn't drawn yet. A handler of your own replaces either one.

### Commands on pages

Every command of the extension works on a paginated editor and writes the source document, not the pages. `insertFootnote()` puts the note at the end of the document and the cursor into it, wherever Page Layout draws it. `can()` also checks the source document, so a toolbar can disable a button with it.

```js
editor.chain().insertFootnote({ placement: 'footnote' }).focus().run()
editor.commands.focusFootnoteReference(id)
```

Read what the cursor is on from the source state:

```js
import { footnoteAtSelection } from '@tiptap-pro/extension-footnotes'

const atCursor = footnoteAtSelection(editor.storage.pageLayout.engine.getSourceState().selection)
// { footnoteId: 'fn3', in: 'note' }, { footnoteId: 'fn3', in: 'reference' } or null
```

To list the notes with the marks the pages show, pass `noteMarks` as the counter:

```js
import { noteNumbers } from '@tiptap-pro/extension-footnotes'
import { noteMarks } from '@tiptap-pro/extension-page-layout'

const numbers = noteNumbers(editor.storage.pageLayout.engine.getSourceDocument(), {
  counter: noteMarks,
})
```

### Edit a note where it is drawn

A note at the foot of a page is still one note in the source document, which keeps it at the end. The user edits it where the page shows it, and the edit lands in that note.

### Where notes are drawn

Each [section](/pages/v2/core-concepts/sections) sets it in its page setup:

```js
pageSetup('A4', { notePlacement: 'bottomOfPage' })
```

| `notePlacement`  | What it does                                                                         |
| ---------------- | ------------------------------------------------------------------------------------ |
| `'bottomOfPage'` | Draws the notes at the foot of the text area, above the footer. This is the default. |
| `'belowText'`    | Draws the notes directly under the last line of text, wherever that ends.            |

Endnotes aren't affected. The reader finds them in the collection at the end.

### Numbering on pages

With pages, each section sets the numbering in its page setup, and it replaces the extension's `footnoteNumbers` and `endnoteNumbers`:

```js
pageSetup('A4', {
  noteNumbering: {
    footnote: { format: 'decimal', start: 1, restart: 'page' },
    endnote: { format: 'lowerRoman', start: 1, restart: 'never' },
  },
})
```

| Field     | What it holds                                                                                                                         |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| `format`  | One of the [number formats](/pages/v2/extensions/number-formats), such as `'decimal'`, `'lowerAlpha'`, `'upperRoman'` or `'symbols'`. |
| `start`   | The first number of the sequence.                                                                                                     |
| `restart` | `'never'`, `'section'` or `'page'`.                                                                                                   |

`'never'` is the default and counts through the document. `'section'` starts over at each section break. `'page'` starts over on every sheet, which is Word's restart each page.

The document never holds any of the three as a number. The setting is content and the mark stays derived, so the same file opened at another paper size renumbers instead of showing a wrong number. For the section settings, see [page format](/pages/v2/core-concepts/page-format#what-a-setup-holds).

### At a page boundary

A run of notes breaks between two notes, and a note that is longer than that breaks between its blocks. A list follows the same rules, and an endnote needs nothing more.

A footnote at the foot of a page splits more finely. Page Layout splits it at a line, in the middle of a paragraph if the sheet ran out there. The note area has only the room the text left. The next page draws the rest of the note at its foot without a number in front of it. Word shows a continued note the same way.

Page Layout reserves the room the notes take before it fits the text on the page. A page whose text refers to five long notes holds fewer lines of text.

## Limitations

- The note area has no columns of its own. Page Layout draws the notes in one box across the text area. On a page with one column, this is the same thing.
- A note that continues across a change of paper size reserves more room than it needs. A note stays in the section its reference is in, so this only happens when a break right after the reference puts the next piece on a page of another width.
- A single note can't have a custom mark, for example a symbol that stays out of the count. The format is a per-section setting.
