A definition says what a style is called, what it is for and what it sets:

```js
editor.commands.setStyleDefinition({
  id: 'heading-1',
  name: 'Heading 1',
  kind: 'paragraph',
  basedOn: 'body',
  targets: [{ kind: 'node', types: ['heading', 'paragraph'] }],
  node: { type: 'heading', attrs: { level: 1 } },
  props: { fontSize: 32, fontWeight: 700, marginTop: 24 },
})
```

| Field                           | What it holds                                                                                                                                                                                                              |
| ------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `id`                            | What content refers to it by. It stays when the style is renamed.                                                                                                                                                          |
| `name`                          | What a reader sees in a style picker.                                                                                                                                                                                      |
| `kind`                          | `'paragraph'`, `'character'`, `'list'`, `'object'`, `'table'`, `'cell'` or `'custom'`. It says what the style is for, and a picker groups by it.                                                                           |
| `basedOn`                       | The style this one inherits every value from that it doesn't set itself.                                                                                                                                                   |
| `nextStyle`                     | The style the paragraph after this one gets when Enter is pressed at its end. See [the next paragraph](#the-next-paragraph).                                                                                               |
| `outlineLevel`                  | `1` to `9`, where a paragraph of this style sits in the document's outline, or `null` for body text. See [outline levels](#outline-levels).                                                                                |
| `defaultFor`                    | Blocks without a style that are drawn in this one. It takes node types such as `['paragraph']`, or a type with attributes such as `{ type: 'heading', attrs: { level: 2 } }`. See [the default style](#the-default-style). |
| `builtIn`                       | The one of Word's built-in styles this one is, such as `'heading 1'`. See [Word's built-in styles](#words-built-in-styles).                                                                                                |
| `priority`, `hidden`, `gallery` | Where a style list puts it, whether it waits until something uses it, and whether a gallery offers it. See [the style list](#the-style-list).                                                                              |
| `autoUpdate`                    | Whether formatting set on a paragraph of this style changes the style. See [update automatically](#update-automatically).                                                                                                  |
| `language`                      | The language of its text, such as `'de-CH'`, or `null` for none. See [language](#language).                                                                                                                                |
| `tableConditions`               | For a table style, what it formats in the header row, the total row, the first and last column and the bands. See [table styles](/pages/v2/extensions/document-styles/tables).                                             |
| `pagination`                    | `{ keepWithNext, keepLinesTogether, pageBreakBefore }`, how a paragraph of this style meets the end of a page. See [line and page breaks](#line-and-page-breaks).                                                          |
| `targets`                       | Where it can go: `{ kind: 'node', types }` and `{ kind: 'mark', types }`. Without targets, a `character` style goes on text and any other style on the block.                                                              |
| `node`                          | The node type and attributes the block becomes where `applyStyle` transforms it. It can also be the type the blocks are put in, where the type holds blocks, such as `blockquote`.                                         |
| `props`                         | The values it sets, by CSS property in camel case. A font or color can be the theme's, such as `'theme:accent1'`. See [themes](/pages/v2/extensions/document-styles/themes).                                               |
| `meta`                          | Anything of yours, such as the design token a value came from. It is kept and never read.                                                                                                                                  |
| `version`                       | Yours to count with.                                                                                                                                                                                                       |
| `status`                        | `'draft'`, `'published'` or `'deprecated'`.                                                                                                                                                                                |
| `replacementStyleId`            | Where a deprecated style points its users.                                                                                                                                                                                 |

`setStyleDefinition` replaces the document's own definition of the same id. It returns `false` for something without an `id`, a `name` and a `kind`, and for an id a [library](/pages/v2/extensions/document-styles/libraries) defines.

## What a style can set

`props` takes any CSS property in camel case, with the value CSS writes for it. A number is a length in pixels, except for `fontWeight`, `lineHeight` and the other properties CSS reads as a factor. These are the ones a style for text usually sets:

| What                  | Properties                                                                                                         | Values, for example                                             |
| --------------------- | ------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------- |
| Font                  | `fontFamily`, `fontSize`, `fontWeight`, `fontStyle`                                                                | `'theme:minor'`, `16`, `700`, `'italic'`                        |
| Spacing               | `letterSpacing`, `lineHeight`, `marginTop`, `marginBottom`, `textIndent`                                           | `'0.02em'`, `1.15`, `12`, `0`, `24`                             |
| Alignment             | `textAlign`                                                                                                        | `'left'`, `'center'`, `'right'`, `'justify'`                    |
| Case                  | `textTransform`, `fontVariantCaps`                                                                                 | `'uppercase'`, `'small-caps'`, `'all-small-caps'`               |
| Lines                 | `textDecorationLine`, `textDecorationStyle`, `textDecorationColor`, `textDecorationSkipInk`, `textUnderlineOffset` | `'underline'`, `'wavy'`, `'theme:accent2'`, `'none'`, `'0.2em'` |
| Ligatures and numbers | `fontVariantLigatures`, `fontVariantNumeric`                                                                       | `'discretionary-ligatures'`, `'oldstyle-nums tabular-nums'`     |
| Any OpenType feature  | `fontFeatureSettings`                                                                                              | `'"ss01" 1, "swsh" 1'`                                          |
| Trimming a line       | `textBoxTrim`, `textBoxEdge`                                                                                       | `'trim-both'`, `'cap alphabetic'`                               |
| Color                 | `color`, `backgroundColor`                                                                                         | `'#1f2937'`, `'theme:accent1/+40'`                              |

A value containing `;`, `{`, `}`, `<`, `>`, `\` or `/*` isn't written. Neither is a name that isn't a property in camel case. A property the browser doesn't know is written and ignored by it. For example, `textBoxTrim` trims a line only in browsers that draw `text-box-trim`.

## Where a value comes from

A value is looked up in this order, and the first place that sets it wins:

1. `styleOverrides` on the paragraph.
2. The style's own `props`.
3. The style it is `basedOn`, and then what that one is based on.
4. Your CSS for the element.

```js
import { resolveStyle } from '@tiptap-pro/extension-document-styles'

const styles = editor.storage.documentStyles.stylesOf(editor.state.doc)
const result = resolveStyle(styles, 'heading-1', { color: 'navy' })

if (result.ok) {
  result.style.props // body's values, heading-1's over them, then color: navy
}
```

`resolveStyle` returns an answer and doesn't throw. `result.error.code` is `'missing-style'` for an id nothing defines. It is `'circular-inheritance'` for styles based on each other, with the `chain` that loops. A style that can't be resolved has no rule in the stylesheet, and what refers to it is drawn as if it had no style.

## The default style

A style with `defaultFor: ['paragraph']` is what every paragraph without a style of its own is drawn in, as Word's Normal is:

```js
editor.commands.setStyleDefinition({
  id: 'normal',
  name: 'Normal',
  kind: 'paragraph',
  defaultFor: ['paragraph'],
  props: { fontSize: 15, lineHeight: 1.5 },
})
```

The paragraphs keep `styleId: null`. `getJSON()` and `getHTML()` are the same as without a default, and changing the default restyles them all at once. In the editor, such a block carries the default's `data-tt-style-id` and `data-tt-style-default`, so CSS can tell it from a block that has the style itself.

With `stylesheet: false`, nothing is drawn and the defaults are yours to read:

```js
import { styleIdOrDefaultOf } from '@tiptap-pro/extension-document-styles'

const defaults = editor.storage.documentStyles.defaultStylesOf(editor.state.doc)

defaults.of(node) // 'normal' for a paragraph, whatever its own style
styleIdOrDefaultOf(defaults, node) // the node's own style, or its default
defaults.entries // [{ type: 'paragraph', attrs: {}, styleId: 'normal' }]
```

A default can be for blocks of a type that have certain attributes. That is how each heading level gets its own, as Word's Heading 1 to Heading 9 do:

```js
editor.commands.setStyleDefinition({
  id: 'heading-2',
  name: 'Heading 2',
  kind: 'paragraph',
  defaultFor: [{ type: 'heading', attrs: { level: 2 } }],
  props: { fontSize: 21 },
})
```

An attribute matches where the node's value is the same. A block that changes level is drawn in the default of its new one.

A default that names more attributes wins over one that names fewer, so a style with `defaultFor: ['heading']` draws only the levels nothing names. Between two defaults that are equally particular, the first one wins. That is the document's own before a library's, unless `precedence` is `'libraries'`.

A type has to be in `types` to have a default. A default style and the styles it is based on are never reported as unused, and `removeUnusedStyles` keeps them. A block drawn in its default keeps the outline level of its node type.

## The next paragraph

Enter at the end of a paragraph whose style has a `nextStyle` gives the new paragraph that style. After a Heading 1 comes Body Text. The new paragraph starts without the overrides of the one before it. With `transformNodeOnApply`, it also becomes the next style's `node` type, so the paragraph after a heading is a paragraph again.

Enter in the middle of a paragraph keeps the style on both halves. So does Enter at the end of a paragraph whose style has no `nextStyle`. Undo takes back the Enter and the style in one step. `followNextStyle: false` turns this off.

## Outline levels

`outlineLevel` is inherited through `basedOn` like a value in `props`. `null` stops it, so a style based on a heading can be body text. A level outside `1` to `9` is read as the nearest one.

A paragraph's level comes from its style, whatever node type it is:

```js
import { styleOutlineLevelOf } from '@tiptap-pro/extension-document-styles'

const levels = editor.storage.documentStyles.outlineLevelsOf(editor.state.doc)

styleOutlineLevelOf(levels, node) // 2 for a paragraph styled Heading 2
```

It returns `null` for a node whose style is body text. It returns `undefined` for one without a style, or with a style nothing defines.

`outlineLevelsOf` returns the same object until a definition changes, so you can compare it or use it as a cache key. `styleOutlineLevels(doc, libraries, precedence)` reads the same in code that holds no editor.

[Outline numbering](/pages/v2/extensions/outline-numbering#number-by-style) numbers paragraphs by these levels.

## Line and page breaks

This is Word's "Line and Page Breaks" of a paragraph style:

```js
editor.commands.setStyleDefinition({
  id: 'heading-1',
  name: 'Heading 1',
  kind: 'paragraph',
  pagination: { keepWithNext: true, keepLinesTogether: true },
})
```

| Key                 | What it does                                               |
| ------------------- | ---------------------------------------------------------- |
| `keepWithNext`      | The paragraph stays on the page of the paragraph after it. |
| `keepLinesTogether` | The paragraph isn't divided between two pages.             |
| `pageBreakBefore`   | The paragraph starts a page.                               |

Each key is inherited through `basedOn` on its own, and `false` stops one a base sets. `resolveStyle` returns them as `result.style.pagination`.

Nothing about them is drawn. An editor without pages has no end of a page, so they are read where the document is laid out on pages.

```js
import { styleBlockBreaks } from '@tiptap-pro/extension-document-styles'

const breaksOf = styleBlockBreaks({ types: ['paragraph', 'heading'], libraries: [house] })

breaksOf(node, doc) // { keepWithNext: true, keepTogether: true, pageBreakBefore: false }, or null
```

It reads a block's own style or its type's default. It returns `null` for a block whose style says nothing about pages. On pages, pass it to `PageLayout` as `blockBreaksOf`. See [document styles on pages](/pages/v2/extensions/document-styles#line-and-page-breaks).

## Word's built-in styles

`builtIn` names the one of Word's built-in styles a style is. It uses the name a `.docx` gives it in `w:name`. Examples are `'Normal'`, `'heading 1'` to `'heading 9'`, `'Title'`, `'Subtitle'`, `'Quote'`, `'caption'`, `'toc 1'`, `'Emphasis'`, `'Strong'`, `'Table Grid'` and the others in `WORD_BUILT_IN_STYLES`. That name is the same in every language Word runs in. The one Word shows, such as "Überschrift 1" in German, isn't.

```js
editor.commands.setStyleDefinition({
  id: 'chapter',
  name: 'Chapter',
  kind: 'paragraph',
  builtIn: 'heading 1',
})
```

Nothing is drawn differently by it. A converter of yours reads it in both directions:

```js
const builtIns = editor.storage.documentStyles.wordBuiltInStylesOf(editor.state.doc)

builtIns.builtInOf('chapter') // 'heading 1': write the style under Word's name
builtIns.styleIdOf('Heading 1') // 'chapter': the style for a paragraph read from a .docx
builtIns.styleIdOf('Title') // null: no style stands for it
```

Word lists a paragraph of such a style in its navigation pane and its table of contents, as it would a paragraph in its own Heading 1. A style without `builtIn` is written as a style of its own.

`styleIdOf` takes a name in any case. `wordBuiltInStyleOf(name)` spells it the way Word does, or returns `null` for a name Word doesn't build in.

`builtIn` isn't inherited through `basedOn`. Where two styles name the same built-in style, the first one has it. That is the document's own before a library's, unless `precedence` is `'libraries'`. The other is a style of its own. A definition with a name Word doesn't build in is kept and stands for nothing.

## The style list

`priority` orders a style list, the lower number first, as Word's "Recommended" order does. Styles with the same priority, and every style without one after them, are in the order of their names.

`hidden: true` keeps a style out of the list until a block or a run of text in the document has it, or it is the default of some blocks. This is Word's "Hide until used". `gallery: true` puts a style into the short row a toolbar offers, Word's "Quick Styles".

```js
const list = editor.storage.documentStyles.catalogOf(editor.state.doc)
const gallery = editor.storage.documentStyles.catalogOf(editor.state.doc, { gallery: true })
const everything = editor.storage.documentStyles.catalogOf(editor.state.doc, { hidden: true })
```

`catalogOf` returns definitions in that order. `styleCatalog(doc, lookup, options)` does the same without an editor. None of the three fields is inherited, and none changes how anything is drawn. You can apply a hidden style like any other.

To find out whether a hidden style is used, the editor reads the document until each one has turned up. In a long document, a hidden style nothing uses costs a reading of all of it.

## Update automatically

With `autoUpdate: true`, `setStyleOverride` on a paragraph of the style writes the value into the style instead of onto the paragraph. Every paragraph of the style changes with it. This is Word's "Automatically update".

```js
editor.commands.setStyleDefinition({
  id: 'quote',
  name: 'Quote',
  kind: 'paragraph',
  autoUpdate: true,
})
editor.commands.setStyleOverride('color', 'teal') // every quote is teal now
```

Where the paragraph already overrode that value, the override is taken off, since the style now says the same. This holds for paragraph styles the document defines and for paragraphs that have the style themselves.

A style from a library is read only. A paragraph drawn in a style only because it is a default gets an override as before. `unsetStyleOverride` and `clearStyleOverrides` always act on the paragraph.

## Language

`language` gives the text of a style a language, as a BCP 47 tag such as `'en-GB'` or `'de-CH'`. A block of the style, and a run of text in a character style, are drawn with a `lang` attribute of it. The browser's spell checker and hyphenation read it, and so does a screen reader.

```js
editor.commands.setStyleDefinition({
  id: 'citation-fr',
  name: 'French quote',
  kind: 'paragraph',
  basedOn: 'quote',
  language: 'fr',
})
```

The language is inherited through `basedOn`, and `language: null` stops a style inheriting one. A value that isn't a language tag is ignored.

Nothing is written into the content. The attribute follows the style, so a style that changes its language changes it for every block of it. `styleLanguages(doc, libraries, precedence)` returns the language of each style that has one, by id.

## Change a style

Every change is one step of the history, together with whatever else the command changed.

| Command                                                          | What it does                                                                                                                                                    |
| ---------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `renameStyle(styleId, name)`                                     | Gives the style a new name. The id and everything referring to it stay.                                                                                         |
| `duplicateStyle(styleId, newStyleId, name?)`                     | Copies the style under a new id, as a `draft`. Its name is the original's with `Copy` unless you give one.                                                      |
| `deprecateStyle(styleId, replacementStyleId?)`                   | Marks the style `deprecated`, pointing to a replacement that has to exist.                                                                                      |
| `updateStyleFromSelection(styleId, { removeMatchingOverrides })` | Writes what the selection overrides into the style. With `removeMatchingOverrides`, the selection's overrides are taken off, since its style now says the same. |
| `createStyleFromSelection({ id, name, kind })`                   | Makes a new style of what the selection overrides, and the selection gets it. A `character` style goes on the selected text.                                    |

Each returns `false` where it would change nothing. That covers the same name, an id that is taken, and a style that isn't the document's own. `editor.can()` tells a toolbar which of them apply:

```js
editor.can().renameStyle('heading-1', 'Title')
```

## In code that holds no editor

You can read and write the definitions on any document of the schema:

```js
import {
  setStyleDefinitionTransaction,
  removeStyleDefinitionTransaction,
  styleDefinitionsOf,
} from '@tiptap-pro/extension-document-styles'

const transaction = setStyleDefinitionTransaction(state.tr, definition)
styleDefinitionsOf(transaction.doc)
```

`setStyleDefinitionTransaction` throws for something that isn't a definition. It changes only the `styleDefinition` node of that style. A document left without any definition and without a theme loses the `styleDefinitions` node.
