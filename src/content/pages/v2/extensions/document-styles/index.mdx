Named styles work as they do in Word: "Heading 1", "Body Text", "Quote", "Emphasis". A paragraph refers to its style by id, and the style says how it looks. Change the style and every paragraph that refers to it changes with it.

`@tiptap-pro/extension-document-styles` works in any editor, with or without pages.

## Install

```bash
npm install @tiptap-pro/extension-document-styles
```

The package comes from Tiptap's private registry. See [set up the registry](/pages/v2/getting-started/install#set-up-the-registry) if you haven't yet.

## Add it to an editor

```js
import { Editor } from '@tiptap/core'
import StarterKit from '@tiptap/starter-kit'
import { TextStyle } from '@tiptap/extension-text-style'
import { DocumentStyles } from '@tiptap-pro/extension-document-styles'

const editor = new Editor({
  extensions: [StarterKit, TextStyle, DocumentStyles],
})

editor.commands.applyStyle('heading-1')
```

`TextStyle` is what character styles go on.

Word's built-in styles come with it: Normal, No Spacing, Title, Subtitle, Heading 1 to 3, Quote, Intense Quote and four character styles. See [Word's built-in styles](/pages/v2/extensions/document-styles/libraries#words-built-in-styles). A paragraph nobody styled gets Normal. A heading gets the Heading style of its level.

Styles go on the `paragraph`, `heading`, `blockquote` and `table` types and on the `textStyle` mark, wherever the schema has them.

A style of your own is a definition stored in the document:

```js
editor.commands.setStyleDefinition({
  id: 'body',
  name: 'Body Text',
  kind: 'paragraph',
  props: { fontFamily: 'Georgia, serif', fontSize: 16, lineHeight: 1.6 },
})

editor.commands.applyStyle('body')
```

To choose the types yourself, list them. `types` is the node types a paragraph style can go on. `markTypes` is the mark types a character style can go on. The extension skips a type the schema doesn't have. `wordStyles: false` leaves Word's styles out.

## What is stored

Each node and mark type listed in `types` and `markTypes` gets two attributes:

- `styleId` is the id of its style, or `null`.
- `styleOverrides` holds the values this one node or mark sets apart from its style, such as `{ color: 'red' }`, or `null`.

The document stores the definitions in a hidden `styleDefinitions` node at its end. `DocumentStyles` adds that node to the schema. The definitions save with the document, undo with the history, and reach every collaborator through Tiptap Collaboration. Nothing about them shows on the page.

```json
{
  "type": "doc",
  "content": [
    { "type": "paragraph", "attrs": { "styleId": "body", "styleOverrides": null }, "content": [] },
    {
      "type": "styleDefinitions",
      "content": [
        {
          "type": "styleDefinition",
          "attrs": { "definition": { "id": "body", "name": "Body Text", "kind": "paragraph" } }
        }
      ]
    }
  ]
}
```

Each definition is a `styleDefinition` node of its own, so two people changing two different styles at the same time both keep their change. `styleDefinitionsContent(definitions, theme)` builds that JSON for content you put together yourself, such as a document's first content.

## How it is drawn

`DocumentStyles` writes a stylesheet for the editor with one rule per style. The `data-tt-style-id` attribute on the content selects the rule. The extension rewrites the stylesheet whenever a definition changes. It writes an override inline on its element, where it wins over the rule.

```html
<p data-tt-style-id="body" data-tt-style-overrides='{"color":"red"}' style="color: red">...</p>
```

The rules are scoped to the editor's own element, which carries `data-tt-document-styles`. Two editors on one page with different styles don't draw each other's. Set `stylesheet: false` to write the CSS yourself, for example from `documentStylesStylesheet`.

A block without a style gets its type's [default style](/pages/v2/extensions/document-styles/definitions#the-default-style) where there is one. In the editor it carries `data-tt-style-default` beside the default's id.

Each value becomes the CSS property it names. `fontSize` becomes `font-size` and `marginTop` becomes `margin-top`. A number is in pixels where the property takes a length, and stays as it is for `fontWeight`, `lineHeight` and `opacity`.

The extension leaves out a value that isn't a plain CSS value, because the definitions come with the document. That covers a value containing `;`, `{`, `}`, `<`, `>` or a comment. A value such as `'theme:accent1'` is the theme's, written as a custom property. See [themes](/pages/v2/extensions/document-styles/themes).

A character style alone gets an empty `style` attribute, as in `<span data-tt-style-id="marker" style="">`. `TextStyle` reads a `<span>` back only where it has one.

## Paste from Word

Text pasted from Word keeps its styles where the document has a style of the same kind. Word writes a paragraph's style as a class, such as `class=MsoTitle` or `class=Fazit`, and a heading as `<h1>` to `<h6>`. Each becomes a reference to:

1. The style whose [`builtIn`](/pages/v2/extensions/document-styles/definitions#words-built-in-styles) is that style of Word's, such as `'Title'` or `'heading 1'`.
2. Otherwise, the style whose `name` is the one Word gives it, in any case. This is how a style the user made in Word comes back.

A paragraph in Word's Normal gets no reference where Normal is the default for paragraphs, since it gets Normal anyway. The paste doesn't create a style the document has nothing for. The text arrives with whatever formatting the rest of the HTML carries. Text styles come back on the first mark type in `markTypes`.

The first pasted paragraph goes into the paragraph at the cursor and keeps that paragraph's style. The ones after it keep their own.

`wordStylesToHtml(html, styleIdOf)` is the same rewrite on a string. `styleIdOfWordNameIn(doc, libraries, precedence)` is the lookup it uses.

## Options

| `markTypes`            | `[]`                   | Mark types a character style can go on. The first is the one `applyStyle` uses for a style that names none. Left empty, it is `textStyle`, if the schema has it.                            |

| `wordStyles`           | `true`                 | Word's built-in styles under the libraries. `{ defaults: false }` offers them without drawing unstyled blocks in Normal.                                                                    |

| `repeatedRowSelector`  | `null`                 | The selector of a row drawn as a copy of a table's header row, formatted as the header row.                                                                                                 |

## Read the styles

```js
const styles = editor.storage.documentStyles.stylesOf(editor.state.doc)

styles.getStyles() // every style the document can use, its own and its libraries'
styles.getStyle('body') // one, or null
styles.originOf('body') // 'document', 'library' or null
```

## On pages

Changing a style moves text from page to page. With Page Layout, pass the source document to the read functions, and tell `PageLayout` where a style breaks a page.

### Set it up

```js
import StarterKit from '@tiptap/starter-kit'
import { TextStyle } from '@tiptap/extension-text-style'
import { DocumentStyles, styleBlockBreaks } from '@tiptap-pro/extension-document-styles'
import { createPageLayoutEditor, PageLayout, pageSetup } from '@tiptap-pro/extension-page-layout'

const types = ['paragraph', 'heading']

createPageLayoutEditor({
  element,
  content,
  extensions: [
    StarterKit,
    TextStyle,
    DocumentStyles.configure({ types }),
    PageLayout.configure({
      setup: pageSetup('A4'),
      blockBreaksOf: styleBlockBreaks({ types }),
    }),
  ],
})
```

Pass `styleBlockBreaks` the same `types` and `libraries` you give `DocumentStyles`. Without it, the pages don't read a style's `pagination`.

### Text moves with a style

Make the body style larger and every paragraph using it gets taller. Page Layout lays out the whole document again, as for a change of paper width. A paragraph that fitted at the bottom of page 4 starts page 5.

The definitions block has no height and sits on no page. The same block keeps the [theme](/pages/v2/extensions/document-styles/themes), so `setDocumentTheme` lays the pages out again as a changed style does. A theme with a wider heading font moves the text after every heading.

### Read the source document

In a paginated editor, `editor.state` holds the pages. A paragraph split by a page boundary is two pieces there. Pass the source document to the read functions:

```js
import { analyzeStyleUsage, discoverStyles } from '@tiptap-pro/extension-document-styles'

const doc = editor.storage.pageLayout.engine.getSourceDocument()
const styles = editor.storage.documentStyles.stylesOf(doc)

analyzeStyleUsage(doc, styles)
discoverStyles(doc)
```

A candidate found this way is what `createStyleFromCandidate` takes. The commands need nothing extra. They act on the source document, and a style applied to a paragraph split by a page boundary applies to both pieces.

### A library change is not a document change

Replacing a library's styles redraws them. Page Layout lays out the pages again once you ask the engine to measure:

```js
house.setStyles(next)
editor.storage.pageLayout.engine.refresh()
```

To write the definitions without the commands, apply a transaction through the engine:

```js
import { setStyleDefinitionTransaction } from '@tiptap-pro/extension-document-styles'

const engine = editor.storage.pageLayout.engine
const transaction = setStyleDefinitionTransaction(engine.getSourceState().tr, definition)

engine.applySourceTransaction(transaction, { addToHistory: true })
```

### Line and page breaks

Page Layout reads a style's `pagination` only when you pass `styleBlockBreaks` to `PageLayout`, as in the setup above. Then:

- A paragraph in a style with `keepWithNext` moves to the next page with the first line of the paragraph after it.
- A paragraph in a style with `keepLinesTogether` doesn't split between pages.
- A paragraph in a style with `pageBreakBefore` starts a page.

A paragraph without a style of its own follows its type's default style. See [line and page breaks](/pages/v2/extensions/document-styles/definitions#line-and-page-breaks) for the field. Changing a style's `pagination` lays out the pages again, like any change to a definition.

### Tables

A table style counts a table split between pages as one:

- The bands of the rows on the next page go on from where the page before stopped.
- Only the last page holds the total row.
- The header row a table repeats on every page gets the style's header row format.
- A row split between two pages is one row in its band in both pieces.

You don't need to configure anything for this. `PageLayout` sets `continuesNode` and `repeatedRowSelector` in the paginated editor. A change to a table's look, or to a table style, lays out the pages again, since a bold header row can be taller. See [table styles](/pages/v2/extensions/document-styles/tables).
