Delete or replace styles, fix references to missing ones, and turn repeated formatting into a style.

## deleteStyle(styleId, options)

When you delete a style, you say what becomes of everything that refers to it:

```js
editor.commands.deleteStyle('subtitle', { strategy: 'replace', replacementStyleId: 'body' })
```

| `strategy`             | What happens to the references                                    |
| ---------------------- | ----------------------------------------------------------------- |
| `'replace'`            | They point to `replacementStyleId`. Overrides stay.               |
| `'freeze-inline'`      | The style's values become overrides, so the text looks as it did. |
| `'remove-reference'`   | The command takes them off. Overrides stay.                       |
| `'preserve-reference'` | They stay, and are missing.                                       |

With every strategy, the command removes the definition. The selection and the rest of the text stay as they were, and the deletion is one step of the history. When `'remove-reference'` leaves a mark with no attribute at all, the command removes the mark.

`deleteStyle` returns `false` for a style that isn't the document's own. With `'replace'`, it also returns `false` for a replacement nothing defines or the style itself.

## replaceStyle(styleId, replacementStyleId)

This points everything that uses one style at another and keeps both definitions, as Word's "Select all instances" followed by another style does:

```js
editor.commands.replaceStyle('subtitle', 'heading-2')
```

Each reference keeps its overrides. A reference the new style doesn't fit stays as it is:

- A paragraph style replaces block references and not character styles on text.
- A table style goes only on a table.
- A style whose `node` target lists types replaces only references of those types.

With `transformNodeOnApply`, each block also becomes the style's `node` type, such as a heading. A style whose `node` holds blocks, such as a blockquote, sets the reference without wrapping anything.

`replaceStyle` returns `false` for a replacement nothing defines or that doesn't resolve, for the style itself, and where nothing it fits uses the style.

## Missing styles

The editor keeps a reference to an id nothing defines, and draws it as if it had no style. Once something defines the id, the editor draws it in that style.

| Command                                    | What it does                                           |
| ------------------------------------------ | ------------------------------------------------------ |
| `replaceMissingStyles(replacementStyleId)` | Points every such reference to a style that exists.    |
| `removeMissingStyleReferences()`           | Takes every such reference off, keeping its overrides. |

## removeUnusedStyles()

This removes the document's own styles nothing refers to. A style that another style in use is based on counts as used. The command never removes a library's styles.

## How styles are used

```js
import { analyzeStyleUsage } from '@tiptap-pro/extension-document-styles'

const doc = editor.state.doc
const report = analyzeStyleUsage(doc, editor.storage.documentStyles.stylesOf(doc))

report.usedStyles // per style: its references, how many are nodes and marks, what they override
report.missingStyles // references to an id nothing defines
report.deprecatedStyles // styles in use that are deprecated
report.unusedStyles // styles nothing refers to
report.overrideReferences
```

A styled run of text counts once, however many other marks run through it. `missingStyleReferences(doc, lookup)` and `unusedStyles(doc, lookup)` each return one of these lists.

## Formatting that should be a style

The same overrides, set again and again, are a style nobody defined yet. `discoverStyles` finds them, most frequent first. It counts what [Tiptap's own formatting](/pages/v2/extensions/document-styles/values#tiptaps-own-formatting) set with them, such as eleven paragraphs colored with `setColor`. It compares values in one written form, so `#1F2937` and `#1f2937` are the same formatting:

```js
import { discoverStyles } from '@tiptap-pro/extension-document-styles'

const [candidate] = discoverStyles(editor.state.doc, { minOccurrences: 3 })

candidate.props // { fontSize: '18px', fontWeight: 700 }
candidate.references // every place it was found

editor.commands.createStyleFromCandidate(candidate, {
  id: 'lead',
  name: 'Lead',
  applyToMatches: true,
})
```

Two sets of overrides match when their values do, whatever order they were set in. `discoverStyles` skips content that already has a style unless you pass `includeStyledNodes: true`.

`createStyleFromCandidate` with `applyToMatches` gives the new style to every place the candidate was found that still has that formatting, and takes the overrides off there.

To use a style the document already has instead, give it to the candidate:

```js
editor.commands.applyStyleToCandidate(candidate, 'heading-2')
```

It returns `false` for a style that doesn't resolve. It leaves alone a place that was restyled since the candidate was found.

## Blocks without a style

A document from somewhere else often has no styles at all. Its headings are headings and its paragraphs are paragraphs. `unstyledBlocks` groups the blocks that have neither a style nor overrides, by node type and level:

```js
const groups = discoverStyles(doc, { unstyledBlocks: true, minOccurrences: 1 }).filter(
  (candidate) => candidate.node,
)

groups[0].node // { type: 'heading', attrs: { level: 2 } }
groups[0].references.length // 11

editor.commands.applyStyleToCandidate(groups[0], 'heading-2')
```

`blockAttributes` names the attributes that tell two blocks of a type apart. The default is `['level']`. `skipUnstyled` leaves blocks out, such as those already drawn in their [default style](/pages/v2/extensions/document-styles/definitions#the-default-style):

```js
const defaults = editor.storage.documentStyles.defaultStylesOf(doc)

discoverStyles(doc, { unstyledBlocks: true, skipUnstyled: (node) => defaults.of(node) !== null })
```

A style made of such a group with `createStyleFromCandidate` sets nothing, so the blocks look as before. Its `node` is the group's type and attributes, so applying it to another block turns that block into, for example, a level 2 heading.

## applyDefaultStyles(styleId?, options?)

A block drawn in its [default style](/pages/v2/extensions/document-styles/definitions#the-default-style) names no style, so it changes when the default does. That happens when a library loaded later has another default for paragraphs, or when a style stops being one. `applyDefaultStyles` writes the default onto those blocks, which keeps them in it:

```js
editor.storage.documentStyles.defaultStyledBlocksOf(editor.state.doc)
// [{ styleId: 'body', positions: [0, 42, 97] }]

editor.commands.applyDefaultStyles() // every default
editor.commands.applyDefaultStyles('body') // only the blocks drawn in Body Text
```

Nothing changes for the user. Each block keeps the same style, now by its own reference, and keeps what it overrides. The command only writes blocks of `types`. The command returns `false` where no block is drawn in a default, or in the one named.

`applyDefaultStylesTransaction(tr, defaults, types, styleId)` and `defaultStyledBlocks(doc, defaults, types)` do the same without an editor.

With `libraries`, the command writes the defaults those libraries say rather than the ones the editor draws. An editor that offers Word's styles without making them the default can give every paragraph Normal and every heading its level that way:

```js
import { wordStyleLibrary } from '@tiptap-pro/extension-document-styles'

editor.commands.applyDefaultStyles(null, { libraries: [wordStyleLibrary()] })
```

Here the blocks change for the user, since they had no style before. The command skips a default the document can't draw. That is a default whose id none of its own styles or libraries defines. `defaultStylesWhere(defaults, keep)` filters defaults the same way for `applyDefaultStylesTransaction`.

## Write with transactions

```js
import {
  replaceStyleReferencesTransaction,
  freezeStyleReferencesTransaction,
  removeStyleReferencesTransaction,
  mapStyleReferencesTransaction,
} from '@tiptap-pro/extension-document-styles'

replaceStyleReferencesTransaction(tr, 'old', 'new')
mapStyleReferencesTransaction(tr, (reference) =>
  reference.styleId === 'old' ? { styleId: 'new', overrides: null } : null,
)
```
