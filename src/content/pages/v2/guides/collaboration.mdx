Two people edit the same document and each sees their own pages. The content travels between them. The sheets it is laid out on are worked out on each screen and never sent.

So a colleague on Letter paper, or with a font your machine doesn't have, can see eleven pages of the text you see on twelve. Neither document is wrong.

## Set it up

The shared document goes through `PageLayout`, not into the extension list of the editor:

```js
import {
  createPageLayoutEditor,
  PageLayout,
  createSourceCollaboration,
  pageSetup,
} from '@tiptap-pro/extension-page-layout'

const collaboration = createSourceCollaboration({
  document: yDoc, // the shared document from your provider
  awareness: provider.awareness, // optional, for remote cursors
  user: { name: 'Ada', color: '#e11d48' },
})

const editor = createPageLayoutEditor({
  element: document.querySelector('#editor'),
  content: { type: 'doc', content: [{ type: 'paragraph' }] },
  extensions: [StarterKit, PageLayout.configure({ setup: pageSetup('A4'), source: collaboration })],
})
```

`createSourceCollaboration` takes these fields:

| Field       | What it does                                                                                                      |
| ----------- | ----------------------------------------------------------------------------------------------------------------- |
| `document`  | The shared document that your provider connects.                                                                  |
| `field`     | Which field in it holds the content. Defaults to `default`.                                                       |
| `awareness` | The awareness of your provider, for remote cursors. Without it the content still syncs, but there are no cursors. |
| `user`      | The name and color shown beside the caret of this client.                                                         |

The provider is yours: Hocuspocus, Tiptap Collaboration or anything else that connects a shared document. `yjs` and `y-prosemirror` are optional peer dependencies of Page Layout, and this path needs both.

`content` is a placeholder. The real content arrives from the shared document once it is bound. Pass an empty paragraph, and don't seed the same JSON on every client. One client writing the initial content is one update. Two clients writing it are two copies of the document.

## Don't add the collaboration extensions

`createPageLayoutEditor` throws if the extension list holds `collaboration`, `collaborationCaret` or `collaborationCursor`. Bind collaboration through `createSourceCollaboration` only.

The content of the editor itself is the paged view, with its pages and its blocks cut in half by a page boundary. A shared document bound to it would share the page layout of one client, and every peer would receive sheets planned for a screen they aren't looking at.

Leave `StarterKit` as it is. Page Layout removes its history from the paged view for you.

## What is shared

| Shared                                                     | Local to each client                                                                    |
| ---------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| The text, and every node you persist                       | The page count and where each page breaks                                               |
| Manual page, column and section breaks                     | Measurements, and the plan built from them                                              |
| Paper, margins and columns, once the document carries them | `PageLayout.configure({ setup })`, until a section break in the document names a format |
| Headers, footers and note text                             | Where a note is drawn, and which page a header appears on                               |
| Page colors                                                | Pageless mode, the zoom, and how many sheets are shown per row                          |

Anything an author decided is shared. Anything a screen decided is not. A format chosen in the UI has to be written to the document to reach a colleague, which `setSectionSetup` does. The `setup` that you pass to `PageLayout.configure` is only the fallback of this client for a document that has never had a format chosen. See [sections](/pages/v2/core-concepts/sections#the-documents-own-format).

To check that nothing about the layout leaked into the shared content:

```js
import { isPureSourceDocument } from '@tiptap-pro/extension-page-layout'

const engine = editor.storage.pageLayout.engine

isPureSourceDocument(engine.getSourceDocument(), engine.getSourceState().schema) // true
```

## Undo and redo

Both are commands of Page Layout. Under collaboration they act on the history of the shared document:

```js
editor.commands.undo()
editor.commands.redo()
```

Each client undoes its own edits. A change that arrived from a colleague isn't on your stack. Cmd/Ctrl+Z is bound for you.

Don't add any of these, because each ends up as a second history that competes with this one:

- an undo extension on the editor
- a history plugin of your own on the shared document
- a second undo manager over the same field

## Remote cursors

With `awareness` passed, each peer's caret and selection are drawn where that position lands in your pagination. You see a line in the text, the name of the peer above it, and their selected text tinted, each in the color that peer sent. You style none of that to see it.

Three attributes change how they look:

```css
[data-tt-remote-caret] {
  /* the caret itself */
}
[data-tt-remote-caret-label] {
  /* the name beside it, with the name of the peer as its text */
}
[data-tt-remote-selection] {
  /* the selected text of a peer */
}
```

On the first line of a page, where the name would be cut off above the text, it hangs below the line instead. The label then carries `data-tt-remote-caret-label-below`. A label you style yourself should place itself by that attribute too.

All three carry `--tt-remote-caret-color`, so one declaration covers everybody. `--tt-remote-caret-width` sets the thickness of the caret:

```css
.my-editor {
  --tt-remote-caret-width: 3px;
}
```

Use that property and not a `border-width` of your own. A caret takes no horizontal space, and the room it gives back is derived from that width. A marker that took room would push the words behind it, break the line earlier and repaginate your document whenever a colleague moves. That part belongs to the engine and holds even with `sheetAppearance: 'none'`.

A selection that spans a page boundary is drawn once per page it covers. A peer who selects across a break gets a highlight on both sheets, not one running through the gap.

To rename this client later, call `setUser` on the channel:

```js
collaboration.carets?.setUser({ name: 'Ada Lovelace', color: '#0ea5e9' })
```

`carets` is there only when you passed `awareness`.

## Limitations

- A peer's caret isn't scrolled to.
- Two peers at the same position draw on top of each other.
- A caret at the very start of a line that continues on the next page is drawn at the end of the previous one. It is one line out, in the one place where a single position in the document has two places on paper.
