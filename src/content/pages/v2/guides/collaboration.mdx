Two people edit the same document and each sees their own pages. The content travels between them. The sheets it is laid out on are worked out on each screen and never sent.

So a collaborator on Letter paper, or with a font your machine doesn't have, can see eleven pages where you see twelve. Neither layout is wrong.

## Set it up

The shared document goes through `PageLayout`, not into the editor's extension list:

```js
import {
  createPageLayoutEditor,
  PageLayout,
  createSourceCollaboration,
  pageSetup,
} from '@tiptap-pro/extension-page-layout'

const collaboration = createSourceCollaboration({
  document: yDoc, // the shared document from your provider
  awareness: provider.awareness, // optional, for remote cursors
  user: { name: 'Ada', color: '#e11d48' },
})

const editor = createPageLayoutEditor({
  element: document.querySelector('#editor'),
  content: { type: 'doc', content: [{ type: 'paragraph' }] },
  extensions: [StarterKit, PageLayout.configure({ setup: pageSetup('A4'), source: collaboration })],
})
```

`createSourceCollaboration` takes these fields:

| Field       | What it does                                                                                                       |
| ----------- | ------------------------------------------------------------------------------------------------------------------ |
| `document`  | The shared document that your provider connects.                                                                   |
| `field`     | Which field in it holds the content. Defaults to `default`.                                                        |
| `awareness` | Your provider's awareness, for collaborators' carets. Without it the content still syncs, but there are no carets. |
| `user`      | The name and color collaborators see beside this user's caret.                                                     |

The provider is yours: Hocuspocus, Tiptap Collaboration or anything else that connects a shared document. `yjs` and `y-prosemirror` are optional peer dependencies of Page Layout, and this path needs both.

`content` is a placeholder. The real content arrives from the shared document once it is bound. Pass an empty paragraph, and don't seed the same JSON on every client. One client writing the initial content is one update. Two clients writing it are two copies of the document.

## Don't add the collaboration extensions

`createPageLayoutEditor` throws if the extension list holds `collaboration`, `collaborationCaret` or `collaborationCursor`. Bind collaboration through `createSourceCollaboration` only.

`editor.state` holds the pages, with blocks split by a page boundary. A shared document bound to it would share one client's page layout, and every collaborator would receive sheets planned for a screen they aren't looking at.

Leave `StarterKit` as it is. Page Layout removes its history from the pages for you.

## What is shared

| Shared                                                     | Local to each client                                                                        |
| ---------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| The text, and every node you persist                       | The page count and where each page breaks                                                   |
| Manual page, column and section breaks                     | Measurements, and the plan built from them                                                  |
| Paper, margins and columns, once the document carries them | `PageLayout.configure({ setup })`, until a section break in the document names a page setup |
| Headers, footers and note text                             | Where a note is drawn, and which page a header appears on                                   |
| Page colors                                                | Pageless mode, the zoom, and how many sheets are shown per row                              |

Anything a user decided is shared. Anything a screen decided is not. A page setup chosen in the UI has to be written to the document to reach a collaborator, which `setSectionSetup` does. The `setup` that you pass to `PageLayout.configure` is only this client's fallback for a document that has never had a page setup chosen. See [sections](/pages/v2/core-concepts/sections#the-documents-own-page-setup).

To check that nothing about the layout leaked into the shared content:

```js
import { isPureSourceDocument } from '@tiptap-pro/extension-page-layout'

const engine = editor.storage.pageLayout.engine

isPureSourceDocument(engine.getSourceDocument(), engine.getSourceState().schema) // true
```

## Undo and redo

Both are Page Layout commands. Under collaboration they act on the shared document's history:

```js
editor.commands.undo()
editor.commands.redo()
```

Each user undoes their own edits. A change that arrived from a collaborator isn't on their stack. Page Layout binds `Mod-z` to undo, and `Shift-Mod-z` and `Mod-y` to redo.

Don't add any of these, because each ends up as a second history that competes with this one:

- An undo extension on the editor.
- Your own history plugin on the shared document.
- A second undo manager over the same field.

## Collaborator carets

With `awareness` passed, Page Layout draws each collaborator's caret and selection where that position lands in your pagination. You see a line in the text, the collaborator's name above it, and their selected text tinted, each in the color that collaborator sent. You don't need any CSS for that.

Three attributes change how they look:

```css
[data-tt-remote-caret] {
  /* the caret itself */
}
[data-tt-remote-caret-label] {
  /* the name beside it, with the collaborator's name as its text */
}
[data-tt-remote-selection] {
  /* a collaborator's selected text */
}
```

On the first line of a page, where the name would be clipped above the text, it hangs below the line instead. The label then carries `data-tt-remote-caret-label-below`. A label you style yourself should place itself by that attribute too.

All three carry `--tt-remote-caret-color`, so one declaration covers everybody. `--tt-remote-caret-width` sets the thickness of the caret:

```css
.my-editor {
  --tt-remote-caret-width: 3px;
}
```

Use that property and not your own `border-width`. A caret takes no horizontal space, and Page Layout derives the room it gives back from that width. A marker that took room would push the words behind it, break the line earlier and repaginate your document whenever a collaborator moves. Page Layout keeps that part even with `sheetAppearance: 'none'`.

Page Layout draws a selection that spans a page boundary once per page it covers. A collaborator who selects across a break gets a highlight on both sheets, not one running through the gap.

To rename this user later, call `setUser` on the channel:

```js
collaboration.carets?.setUser({ name: 'Ada Lovelace', color: '#0ea5e9' })
```

`carets` is there only when you passed `awareness`.

## Limitations

- Page Layout doesn't scroll to a collaborator's caret.
- The carets of two collaborators at the same position draw on top of each other.
- A caret at the very start of a line that continues on the next page is drawn at the end of the previous one. It is one line out, in the one place where a single position in the document has two places on paper.
