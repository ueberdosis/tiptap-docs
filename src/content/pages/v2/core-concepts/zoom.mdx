Scaling the pages takes one call and needs no markup of yours:

```js
const engine = editor.storage.pageLayout.engine

engine.setZoom(0.75) // three quarters
engine.setZoom('fit') // the largest size that fits the width
engine.setZoom(1) // back to full size
```

You decide which levels to offer and where the control sits.

Zoom is an engine method and not a command. It changes nothing in the document. It isn't an edit, there is nothing to undo, and a collaborator sees none of it. It is also not a stylesheet's job. A transform the engine doesn't know about counts in every height, and the document paginates at the scaled size.

## Fit the width

```js
engine.setZoom('fit')
engine.setZoom('fit', 2) // two sheets side by side
```

`'fit'` isn't a factor that Page Layout calculates once. The engine watches the element it is mounted in and fits again when the width changes. A reader who drags the window edge keeps a page that fits. The fit never goes above full size.

It fits the widest sheet the document has, not the format it opens with. Without that, a landscape section in the middle of the document would hang off the side.

The second argument is how many sheets go across. The gap between them counts, so `setZoom('fit', 2)` leaves room for one `--tt-page-sheet-gap` between the two.

## Read the zoom

```js
engine.getZoom() // what you set: a factor, or 'fit'
engine.getScale() // the factor in force
```

There are two methods because `'fit'` is an intention and not a number. A toolbar that shows the selected level asks `getZoom()`. A ruler or an overlay that has to line up with the pages asks `getScale()`.

## What Page Layout takes care of

Each of these goes wrong when you scale pages by hand, and none shows in a screenshot.

- The pagination doesn't change. Page Layout measures at full size however far the pages are scaled, so a page breaks in the same place at 75% as at 100%.
- The scroll range matches what the reader sees. A scaled subtree is still laid out at its own size, so the scroller would offer the unscaled height. A document of nine pages would scroll as if it had twelve.
- Printing is at full size. See [printing and PDF](/pages/v2/guides/printing-and-pdf). A reader who prints from the browser gets sheets at their paper size. The scaled element carries `data-tt-page-zoom`, and the print rules of Page Layout take the transform off through that attribute, so no zoom reset is needed.

## The room around the pages

The desk the sheets lie on is a scroller of yours, and styling it is up to you. See [styling the pages](/pages/v2/core-concepts/styling). `--tt-page-sheet-gap` is the space between two sheets. A fit reads it back when you ask for a spread, so a wider gap makes the fit slightly smaller instead of pushing the second sheet past the edge.
