A page arrives finished. It has the size of its paper and the text box its margins leave. It has white paper with a shadow and a gap to the next sheet. Where a section asks for one, it has a line between columns. A selection stays visible even where a page boundary runs through a table row. You write no CSS to get any of that.

Your stylesheet decides how the editor looks. That includes the desk the sheets lie on and the typography of the document. It also includes any of the values below that you want to set differently. Change a value with a declaration. Every value Page Layout draws is a custom property with a fallback, so you never have to out-specify a stylesheet you can't see.

## Change how it looks

```css
.my-editor {
  /* the paper */
  --tt-page-paper: #fdfdfb;
  --tt-page-sheet-shadow: 0 1px 2px rgba(0, 0, 0, 0.1);
  --tt-page-sheet-gap: 40px;

  /* a selection drawn across a boundary */
  --tt-page-selection-fill: #b4d5fe;

  /* the line between columns */
  --tt-page-column-rule-color: #d4d4d8;
  --tt-page-column-rule-width: 1px;

  /* a collaborator's caret */
  --tt-remote-caret-width: 2px;

  /* the labeled line that stands in for a break without pages */
  --tt-page-break-line-color: rgba(15, 23, 42, 0.28);
  --tt-page-break-label-color: rgba(15, 23, 42, 0.45);
  --tt-page-break-label-size: 8px;
  --tt-page-break-line-space: 1.75rem;

  /* how far past the text an outline or a handle stays visible */
  --tt-page-clip-margin: 8px;
}
```

The default sheet gap is `24px`. The text area of a page clips what doesn't fit, so nothing paints over a footer. `--tt-page-clip-margin` is how far outside that edge content still paints. The default of `8px` is enough for the outline of a selected image as wide as the text, and for the handles beside it. Content that is too wide or too tall is still cut off there. A browser without `overflow-clip-margin` clips at the edge itself.

Three of these do more than set a color, and Page Layout keeps that part:

- The selection is drawn over the words, because a sheet is opaque and a layer beneath it wouldn't show. It multiplies, so the letters stay as dark as they were. Your color is used, and the blending isn't yours to change. To fill behind the text, draw the selection yourself.
- The line between columns is painted, not laid out. A border would take width from the column that every block was measured at, and the page count would change when an author switches the line on.
- A caret takes no horizontal room. Page Layout derives the room it gives back from `--tt-remote-caret-width`, so the width is a property and not a `border-left` of yours. A marker that pushed the words behind it would repaginate the document whenever a collaborator moves.

Colors that a document carries, paper and text per section, win over `--tt-page-paper`, because they are content. See [page colors](/pages/v2/core-concepts/page-colors).

## Turn the paper off

```js
PageLayout.configure({ sheetAppearance: 'none' })
```

Page Layout then draws nothing visible: no paper, no shadow, no gap, no selection fill, no column rule and no collaborator's caret color. Every element still carries the attributes below. Use this for an interface with its own design, before you override rule after rule.

Two things stay, because they aren't appearance: the geometry of a sheet, and a collaborator's caret taking no room. A page whose content box is a few pixels out measures every block at a width the paper was never divided into. A caret that took horizontal space would push words along. The document would repaginate whenever a collaborator moves.

## What Page Layout sets either way

These boxes aren't yours to set:

- The sheet: its width and height from the paper, the padding from the margins, a fixed height so it can't grow with its content, and clipping.
- Where each header and footer sits, and how tall it is.
- The note area at the foot of the sheet or under the text.
- Where the pieces of a drawn selection sit, and that the mouse goes through them.
- Print: one sheet per page at its planned size, no sheet split in two, no margin around a page and no shadow.

A page is exactly as tall as its paper. Content that doesn't fit is clipped, and the page says so with `data-tt-overflow`. That is where a warning in your interface can hang.

The rules the pagination depends on use `!important`, so your selector can't override them by accident, however specific it is. A `height: auto` on a page or a `column-count` of your own has no effect. Pagination is measured against these boxes. A page 40 pixels taller than its paper breaks in places nothing on screen explains. Appearance goes through the properties above, which need no specificity.

## A Content Security Policy

Page Layout adds its rules to the page as a `style` element, as Tiptap does for its own, and follows the same two editor options:

```js
createPageLayoutEditor({ element, extensions, content, injectNonce: nonce })
```

`injectNonce` puts the nonce on the element, which is what a policy without `'unsafe-inline'` allows. `injectCSS: false` leaves the element out, for a policy that allows none. You then load the rules from a file:

```js
import { layoutStyleRules } from '@tiptap-pro/extension-page-layout'

const css = layoutStyleRules({ sheetAppearance: 'paper' }) // the options you configured
```

Pass the same `breaksWithoutPages` and `sheetAppearance` that you gave `PageLayout`. Without these rules, sheets don't get their size and the breaks land in the wrong places.

## What Page Layout publishes

Every measurement is a custom property on the element that owns it. Your stylesheet never computes geometry, and a panel, a ruler or an overlay of yours can read the same numbers.

On `[data-tt-page]`:

| Property                                                                                             | What it holds                                                                   |
| ---------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| `--tt-page-width`, `--tt-page-height`                                                                | The sheet.                                                                      |
| `--tt-page-margin-top`, `--tt-page-margin-right`, `--tt-page-margin-bottom`, `--tt-page-margin-left` | The margins.                                                                    |
| `--tt-page-content-top`, `--tt-page-content-bottom`                                                  | Where the text begins and ends once a header or footer has outgrown its margin. |
| `--tt-page-header-offset`, `--tt-page-footer-offset`                                                 | How far a band sits from the edge.                                              |
| `--tt-page-background`, `--tt-page-text`, `--tt-page-accent`                                         | The colors of the document, where it carries any.                               |

On `[data-tt-page-tier]`, one section's slice of a sheet:

| Property                                               | What it holds                                                               |
| ------------------------------------------------------ | --------------------------------------------------------------------------- |
| `--tt-page-columns`                                    | How many columns this section has.                                          |
| `--tt-page-column-tracks`                              | The grid tracks, columns and gaps together.                                 |
| `--tt-page-column-rule-1` to `--tt-page-column-rule-5` | Where a line between columns goes, measured from the left of the text area. |

On `[data-tt-page-notes]`: `--tt-page-notes-height`, and `--tt-page-notes-top` where the notes sit directly below the text instead of at the foot of the sheet.

## Attributes to style with

Style through these attributes and not through class names. Both exist, but a `data-` selector can't collide with a class of yours.

| Attribute                                                             | On                   | Means                                                                    |
| --------------------------------------------------------------------- | -------------------- | ------------------------------------------------------------------------ |
| `data-tt-page`                                                        | The sheet            | This is a page.                                                          |
| `data-tt-overflow`                                                    | The sheet            | Content taller than the sheet had to run past it.                        |
| `data-tt-page-parity`                                                 | The sheet            | `odd` or `even`, by the number the page shows and not its position.      |
| `data-tt-page-tier`, `data-tt-section-index`                          | A tier               | One section's slice of the sheet, and which section it is.               |
| `data-tt-column-rule`                                                 | A tier               | This section asked for a line between its columns.                       |
| `data-tt-page-region`, `data-tt-column-track`                         | A region             | The text box, and which column it fills.                                 |
| `data-tt-locked`                                                      | A region             | The body isn't editable right now, because a header or footer is.        |
| `data-tt-page-band`, `data-tt-slot`                                   | A header or footer   | `header` or `footer`, and which mask: `default`, `first` or `even`.      |
| `data-tt-live`                                                        | A header or footer   | This is the band being edited.                                           |
| `data-tt-page-notes`, `data-tt-note-placement`                        | The note area        | `bottomOfPage` or `belowText`.                                           |
| `data-tt-furniture-editing`, `data-tt-furniture-slot`                 | The editor root      | Which band the reader is in. A style that dims the body text hangs here. |
| `data-tt-page-break`, `data-tt-column-break`, `data-tt-section-break` | A marker in the text | A break the author inserted.                                             |
| `data-tt-split-continuation`                                          | A block              | The lower half of something a page boundary ran through.                 |

Where a paragraph splits across a page boundary, the lower half starts flush at the top of the next page. `[data-tt-split-continuation]` is that half. Use it for something that shouldn't repeat at a seam, such as a first-line indent.

## The room around the pages

The desk the sheets lie on is yours. The element you pass as `element` holds the pages. What surrounds it is up to your stylesheet: its background, its padding and how far the sheets sit from the edge. `--tt-page-sheet-gap` is the space between two sheets.

You need no particular markup. Nothing is required around that element, and the window scrolls the document if nothing closer does. Give the element a scrolling ancestor when the sheets should scroll inside a pane instead of with the page. A fit is measured against that box too:

```css
.my-desk {
  background: #f3f4f6;
  overflow: auto;
  padding: 40px;
}
```

### A toolbar over the pages

Page Layout scrolls things into view, such as the caret, a header the reader just opened and the note area the caret moved into. It can't see that a toolbar of yours covers the top of the scroller. Tell it how much room to leave:

```js
PageLayout.configure({ scrollMargin: { top: 96, bottom: 24 } })
```

Both edges are optional and in pixels. An edge you leave out keeps its default of 48, about three lines of body text. Set `top` to the height of anything drawn over the pages. Otherwise the caret can scroll to exactly where your toolbar is, and it reads as the editor scrolling to the wrong place.

To scale the sheets, use [zoom](/pages/v2/core-concepts/zoom). A transform of your own counts in every height, and the document paginates at the scaled size.
