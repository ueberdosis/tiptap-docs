Section columns work as they do in a word processor. One run of text fills the first column to the bottom of the page, then carries on at the top of the second. Newsletters, two-column articles and a narrow notes column beside a wide body all use them.

Containers side by side, each with content of their own, are a different feature. That is a [column layout](/pages/v2/extensions/columns), not section columns.

The text stays one sequence in the document. Only its picture is divided. Selecting across a column boundary selects the text between the two points, the clipboard gets a continuous passage, and search finds a phrase that breaks across two columns.

Columns belong to a [section](/pages/v2/core-concepts/sections), because a column count decides where a line breaks. It can't change halfway down a page. Giving a passage columns therefore divides the document into sections around it. The command below does that for you. A section holds at most six columns.

## Set columns

```js
editor.commands.setSectionColumns({ count: 2, gaps: null, rule: false, widths: null })
```

The columns apply to the blocks the selection covers. Select three paragraphs and ask for two columns, and exactly those three paragraphs flow in two columns. Page Layout adds the section breaks it needs around them. They are continuous breaks, so nothing starts a new sheet. With only a cursor, the command applies to the section at the cursor.

### The four fields

| Field    | What it holds                                                                                                                                          |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `count`  | How many columns the text flows through. At least one. `1` is an undivided page.                                                                       |
| `gaps`   | The space after each column but the last, in pixels. One entry fewer than there are columns, or `null` while every gap is the default of half an inch. |
| `rule`   | A vertical line drawn in each gap.                                                                                                                     |
| `widths` | A share of the text area for each column, or `null` for equal columns.                                                                                 |

`gaps` is a measure and `widths` are shares, on purpose. A gap is a typographic constant, so it stays the same on A5 as on A4. A width is a proportion, so the same section in landscape or with wider margins keeps the split the author chose. `gaps` is a list because three columns can have two different spacings.

`rule` takes no width from the columns. Page Layout draws the line inside the gap, so switching it on doesn't reflow the text.

### Widths without the arithmetic

Two presets and the way back to one column:

```js
import {
  NARROW_COLUMN_FIRST,
  NARROW_COLUMN_LAST,
  SINGLE_COLUMN,
} from '@tiptap-pro/extension-page-layout'

editor.commands.setSectionColumns({ count: 2, gaps: null, rule: true, widths: NARROW_COLUMN_FIRST })
editor.commands.setSectionColumns(SINGLE_COLUMN)
```

`NARROW_COLUMN_FIRST` is 1:2 and `NARROW_COLUMN_LAST` is 2:1. Each is named after where the narrow column sits. `SINGLE_COLUMN` is a complete `PageColumns` value.

For widths typed in any unit, convert them to shares:

```js
import { columnSharesFromWidths } from '@tiptap-pro/extension-page-layout'

// Two fields in centimeters, from a dialog
const widths = columnSharesFromWidths([4.5, 11.5])
```

The function divides each number by the total. It returns `null` when the numbers can't describe a division, such as an empty list or a number that isn't positive. Equal columns are the answer to that case.

## Start the next column

```js
editor.commands.insertColumnBreak()
```

This ends the column at the cursor and continues at the top of the next one. In a section with one column, the column is the page, so the same command ends the page. That is why it is worth offering even where no section has columns yet.

A column break is a marker in the document, like a manual page break. It stays where the author put it.

## Read what is in force

A dialog has to show which preset a section uses and what its gaps are. You can't read either from the setup directly. `widths` is `null` for equal columns, `gaps` is `null` while they are the default, and either can hold a list left over from a different count. These functions return what is in force:

```js
import { columnGaps, columnShares, hasEqualGaps } from '@tiptap-pro/extension-page-layout'

const engine = editor.storage.pageLayout.engine
const section = engine.getSections()[engine.getActiveSectionIndex()]
const { columns } = section.setup

columnShares(columns) // [0.333, 0.666] with one entry per column
columnGaps(columns) // [48] with one entry fewer than there are columns
hasEqualGaps(columns) // true when one field is enough to show the gaps
```

`hasEqualColumns(columns)` is `true` while every column has the same width.

`columnWidths(setup)` returns the width of each column in pixels. Use it when you draw your own rules or measure anything yourself. In a section with columns, the text is laid out in a fraction of the text area, not the whole of it.

## What columns do to the pages

A column fills to the bottom of the page before the next one begins. A paragraph too tall for what is left of a column continues at the top of the next column on the same sheet. A page break ends the page, not the column. Footnotes are drawn at the foot of the sheet, not the foot of the column.

The count belongs to the section. A two-column page whose text ran out halfway shows one filled column and one empty one.

## Limitations

- Balancing is exact for equal columns only. Page Layout balances the columns of a section that ends in the middle of a page. When a section divides its area unequally, the result can be a line or two off the shortest arrangement. The content is all there.
- The footnote area has no columns of its own. Notes are drawn in one box across the width of the text area.
- You can't drag a column edge. Set widths through `setSectionColumns`.
