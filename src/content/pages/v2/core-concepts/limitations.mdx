This page lists what Page Layout doesn't do. Each entry names the feature it belongs to.

## The editor

- You have to build the editor with `createPageLayoutEditor`. `PageLayout` in an editor built with `new Editor` draws no pages, and its commands return `false`. `createPageLayoutEditor` doesn't accept `editorProps`. See [install](/pages/v2/getting-started/install#build-a-first-editor).
- `editor.state` holds the pages, not the document. Save what `getJSON()` returns, and read positions through the engine. See [positions and events](/pages/v2/core-concepts/positions-and-events#positions).
- Collaboration binds through the `source` option of `PageLayout`, not through an extension. `createPageLayoutEditor` throws if the extension list holds `collaboration`, `collaborationCaret` or `collaborationCursor`, because they would share the pages along with the content.

## Pagination

- A block that can't be cut and is taller than a page runs past the bottom of its sheet. The sheet gets `data-tt-overflow`. See [styling](/pages/v2/core-concepts/styling#what-page-layout-sets-either-way).
- A list or column layout set to stay together is cut anyway when it is taller than a page. A block that can't fit on a page of its own would otherwise hang off the sheet.
- The setting stays as the author left it. Only that boundary ignores it.
- There is no widow and orphan control. A paragraph is cut wherever the page runs out, including after its first line. No setting keeps at least two lines on either side of a boundary.
- A heading has no keep-with-next rule of its own, so a heading can end up as the last line on a page. To tie a block to the next one, return `keepWithNext` from the `blockBreaksOf` option, or set a `keepWithNext` rule for a node type with `defineNodeLayout`. See [options](/pages/v2/api/options#the-page).
- A table inside a table cell isn't supported at a page boundary. See [tables](/pages/v2/extensions/tables#limitations).

You can keep a block on one page with `setListKeepTogether` and `setColumnLayoutKeepTogether`, and for a type of your own with `defineNodeLayout`.

## Section columns

- Balancing is exact for equal columns only.
- You can't drag a column edge on the page.

See [section columns](/pages/v2/core-concepts/section-columns#limitations).

## Footnotes

- The footnote area has no columns of its own. Page Layout draws the notes in one box across the text area.
- A note continued across a change of paper size reserves more room than it needs.
- A single note can't have a mark of its own. The format is a per-section setting.

See [footnotes](/pages/v2/extensions/footnotes#limitations).

## Long documents

- The browser's find and a screen reader reach the drawn sheets only. With `virtualization` on, only the sheets near the reader carry their text in the DOM. A search of yours over the document JSON isn't affected. See [options](/pages/v2/api/options#drawing).

## Printing

- Safari prints every sheet on the paper of the first page. A page in another format is fitted onto that paper.

## Pasting from Word

- A pasted section break starts its section in the format in force where you paste it. The paper, margins and columns of the section in Word aren't taken.
