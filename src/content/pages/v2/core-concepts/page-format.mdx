The page format is the paper a document is laid out on. It has a size, an orientation and margins. Twenty-one formats are built in. For any other size, you give a width and a height.

The format belongs to a [section](/pages/v2/core-concepts/sections). A document is one section until something about the paper has to change halfway through. Until then, the format of the first section is the format of the document.

## Set the paper

```js
import { PageLayout, pageSetup } from '@tiptap-pro/extension-page-layout'

PageLayout.configure({
  setup: pageSetup('A4', {
    orientation: 'landscape',
    margins: { top: 96, right: 96, bottom: 96, left: 96 },
  }),
})
```

`pageSetup(format, options)` builds a complete `PageSetup`. `format` is a built-in id or a `PageFormat`. Without options, the page is portrait. Its margins are the ones the format carries, or 1 inch on every side if it has none. The built-in formats have none.

`margins` takes all four sides. `theme`, `columns`, `noteNumbering` and `pageNumbering` take a partial object, and the missing fields come from their defaults.

At runtime, set the format for the whole document or for one section:

```js
import { pageSetup } from '@tiptap-pro/extension-page-layout'

editor.commands.setPageSetup(pageSetup('Letter'))

const engine = editor.storage.pageLayout.engine
const index = engine.getActiveSectionIndex()

editor.commands.setSectionSetup(index, {
  ...engine.getSections()[index].setup,
  orientation: 'landscape',
})
```

`setPageSetup` sets the format this editor shows when the document names none. It is not saved with the document. `setSectionSetup` sets any section by index and is saved. Section `0` is the document's own format. Both commands are described in the [commands reference](/pages/v2/api/commands#setpagesetupsetup).

## Built-in formats

The ids are `A3`, `A4`, `A5`, `A6`, `Letter`, `Legal`, `Tabloid`, `Executive`, `Folio`, `Oficio`, `B5ISO`, `B5JIS`, `Book184x260`, `Book195x270`, `EnvelopeC5`, `EnvelopeDL`, `EnvelopeMonarch`, `EnvelopeNo10`, `Postcard`, `PostcardDouble` and `ROC16K`.

`PAGE_FORMATS` holds them by id. `PAGE_FORMAT_ORDER` lists the ids in the order a picker usually offers them, starting with `A4` and `Letter`.

## Define your own size

```js
import { pageFormat, pageSetup } from '@tiptap-pro/extension-page-layout'

const square = pageFormat({ id: 'square', label: 'Square', width: 20, height: 20, unit: 'cm' })

PageLayout.configure({ setup: pageSetup(square) })
```

`unit` is `'px'` (default), `'mm'`, `'cm'`, `'in'` or `'pt'`. `id` and `label` are optional. The document stores a format with its width and height. A document on your paper opens on the same paper in an editor that doesn't know the format.

Sizes are in CSS pixels wherever the engine takes a number. `toPixels` and `fromPixels` convert between a unit and pixels, and `cmToPixels`, `inchToPixels`, `pixelsToCm` and `pixelsToInch` cover centimeters and inches. A panel can show centimeters while the document holds pixels.

## Margins

`MARGIN_PRESETS` holds three labeled margin sets: Normal, Narrow and Wide. Offer them in a dropdown:

```js
import { MARGIN_PRESETS } from '@tiptap-pro/extension-page-layout'

const engine = editor.storage.pageLayout.engine
const narrow = MARGIN_PRESETS.find((preset) => preset.label === 'Narrow')

editor.commands.setSectionSetup(0, {
  ...engine.getSections()[0].setup,
  margins: narrow.margins,
})
```

A header or footer taller than its margin pushes the text down instead of overlapping it. See [distance from the edge](/pages/v2/core-concepts/header-and-footer#distance-from-the-edge).

## What a setup holds

| Field           | What it holds                                                                                                                            |
| --------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| `format`        | The paper, as a `PageFormat`.                                                                                                            |
| `orientation`   | `'portrait'` or `'landscape'`.                                                                                                           |
| `margins`       | `top`, `right`, `bottom` and `left`, in pixels.                                                                                          |
| `theme`         | Page, text and accent color. See [page colors](/pages/v2/core-concepts/page-colors).                                                     |
| `columns`       | How the text area is divided. See [section columns](/pages/v2/core-concepts/section-columns).                                            |
| `notePlacement` | `'bottomOfPage'` or `'belowText'`, for the notes of this section. See [footnotes](/pages/v2/extensions/footnotes#where-notes-are-drawn). |
| `noteNumbering` | How the notes of this section are counted and marked. See [footnotes](/pages/v2/extensions/footnotes#numbering-on-pages).                |
| `pageNumbering` | How the pages of this section are numbered. See [page numbers](/pages/v2/core-concepts/page-numbers#number-the-pages).                   |

## The document names its own paper

The document stores its format in a section break in front of its first block. A server, an export or a second client can read the JSON and know the paper without an editor.

```js
import { documentPageSetup, sectionsDeclaredBy } from '@tiptap-pro/extension-page-layout'

const setup = documentPageSetup(doc) // the document's own setup, or null
const sections = sectionsDeclaredBy(doc) // every section it declares, or null
```

Both return `null` when the document names no format. A format stored in the document overrules the `setup` option when the document loads. The option is what a document with no format of its own is shown in.

## Pageless

```js
editor.commands.setPageSetup(null)
```

`null` shows one continuous column with no page boundaries, at a fixed width of 816 pixels. The document doesn't change. It is the same text without paper around it. Pass a setup again to switch back.

Manual breaks stay visible in a pageless editor. See [breaks without pages](/pages/v2/core-concepts/breaks#breaks-without-pages).
