A section is a run of blocks with its own page setup. [Format, orientation and margins](/pages/v2/core-concepts/page-format), [columns](/pages/v2/core-concepts/section-columns), [page colors](/pages/v2/core-concepts/page-colors), [page numbering](/pages/v2/core-concepts/page-numbers#number-the-pages), [headers and footers](/pages/v2/core-concepts/header-and-footer) and note settings belong to a section, not to a single sheet. A document is one section by default. It gets another wherever something about the paper has to change.

A report with a landscape table in the middle has three sections:

```
Section 1  A4 portrait     The introduction, up to the table
Section 2  A4 landscape    The wide table
Section 3  A4 portrait     Everything after it
```

Each section after the first starts at a section break. It is a node in the document that sits between two blocks. It moves with the text. Insert a paragraph above it and the break stays in front of the same content. [Breaks](/pages/v2/core-concepts/breaks) explains how to insert one, and the difference between a break on new paper and a continuous one.

## The document's own format

The document stores the setup of the first section as a section break in front of the first block. A document without one is shown in the setup that `PageLayout` is configured with. Two editors can show the same document on different paper.

That changes when the document gets a second section. The break that starts the second section takes the format of the first section with it, in the same transaction. From then on, every client shows the document on the same paper. An undo takes both back together.

If you build a document yourself, start it with that break when it has more than one section.

## Change one section

```js
const engine = editor.storage.pageLayout.engine
const index = engine.getActiveSectionIndex()
const current = engine.getSections()[index].setup

editor.commands.setSectionSetup(index, { ...current, orientation: 'landscape' })
```

Spread the current setup. A fresh one resets margins, colors, columns and note settings along with the field you meant to change.

A new section starts with the setup of the section it was cut from. Inserting a break changes nothing about the layout until you change the new section.

Some settings apply to the blocks the selection covers instead of a section index, and add section breaks around them where needed. [`setSectionColumns`](/pages/v2/api/commands#setsectioncolumnscolumns) is one. Select three paragraphs, ask for two columns, and you get a section with exactly those paragraphs.

## Read the sections

```js
const engine = editor.storage.pageLayout.engine

engine.getSetup() // the setup of the first section, or null without pages
engine.getSections() // every section, each with startBlockIndex, setup and kind
engine.getActiveSectionIndex() // the section at the cursor, or the one whose header or footer is open
engine.getPageCount()
```

A toolbar that shows "Section 2 of 3, A4 landscape" reads these. They are up to date after every change.

Without an editor, `sectionsDeclaredBy(doc)` reads the same sections from the JSON of a document. It returns `null` when the document names no format. See [the document names its own paper](/pages/v2/core-concepts/page-format#the-document-names-its-own-paper).

## Replace all sections

```js
editor.commands.setPageSections([
  { startBlockIndex: 0, setup: pageSetup('A4') },
  { startBlockIndex: 12, setup: pageSetup('A4', { orientation: 'landscape' }) },
])
```

A single entry for block `0` removes every other break. That is a "reset to one format" button. [`removeSection`](/pages/v2/api/commands#removesectionsectionindex) removes one section.

## Write sections without an editor

In a server or a migration, the section commands answer `false`, because no paginating editor holds the document. Use the transaction functions instead. They write what the command of the same name writes, including the format of the first section.

```js
import {
  insertSectionBreakTransaction,
  removeSectionTransaction,
  setSectionSetupTransaction,
} from '@tiptap-pro/extension-page-layout'

const tr = insertSectionBreakTransaction({
  tr: editor.state.tr,
  documentSetup: pageSetup('A4'),
  position: 120,
  kind: 'continuous',
})
```

`documentSetup` is the format a document that names none is shown in. `setSectionSetupTransaction` takes `sectionIndex` and `setup`, and `removeSectionTransaction` takes `sectionIndex`. A function that refuses the change returns `tr` unchanged. Check `tr.docChanged` to tell.

The full list of section commands is in the [commands reference](/pages/v2/api/commands#page-format-and-sections).
