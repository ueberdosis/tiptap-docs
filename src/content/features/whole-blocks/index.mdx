Word calls this smart paragraph selection. A block here is any textblock, a node that holds text
directly: a paragraph, a heading, a code block.

## Install

Install the package:

```bash
npm install @tiptap-pro/extension-whole-blocks
```

- **The Pro registry.** The package comes from Tiptap's private registry. See the
  [private registry guide](https://tiptap.dev/docs/guides/pro-extensions) to set it up.
- **Peer dependencies.** `@tiptap/core` and `@tiptap/pm`.
- **Without pages.** The package works in any Tiptap editor, with or without Page Layout.

## Quick start

Add `WholeBlocks` to an editor:

```js
import { Editor } from '@tiptap/core'
import StarterKit from '@tiptap/starter-kit'
import { WholeBlocks } from '@tiptap-pro/extension-whole-blocks'

const editor = new Editor({
  element: document.querySelector('#editor'),
  extensions: [StarterKit, WholeBlocks],
})
```

Select a heading from its first character to its last and press Backspace. The heading is gone,
and the caret is at the start of the block that followed it.

## What changes

With `WholeBlocks` in the editor, a selection that starts at the first character of a block
and ends at the last character of a block covers whole blocks. These actions treat such a
selection differently:

- **Backspace or Delete** removes the blocks. The caret lands at the start of the block that
  followed.
- **Cut** removes them the same way.
- **Copy, cut and drag** carry whole blocks. When the user pastes or drops them in a Tiptap
  editor, they arrive as blocks of their own. Without the extension, their text would be merged
  into the block at the cursor.

A selection can also start at the first character of a block and end inside a later block.
Backspace, Delete and cut then remove every block before the last one whole, and the start of
the last one.

The rest of the last block keeps its own type. A selection from the start of a heading into the
middle of a paragraph leaves the rest as a paragraph.

A selection that starts after the first character of a block is handled as in any Tiptap
editor: the text goes, and the block stays.

## Where an emptied block goes

When the selection covers a block that is the only content of its parent, the parent decides
what is left. No option changes these results:

- **The only content of a list item or a blockquote.** The block takes the list item or the
  blockquote along. A list whose only item goes is removed too.
- **The only content of a table cell**, or of another node whose type sets `isolating: true`.
  `isolating` is a setting of a node type that keeps editing inside the node, and the table
  cells of `@tiptap/extension-table` set it. The cell keeps the block, empty, because deleting
  the text of a cell does not delete the cell.
- **The only block of the document.** The block stays, empty, because a document needs one.

## Options

Most editors leave `ignore` at `null`. In a Page Layout editor, set it as
[With Page Layout](/features/whole-blocks#with-page-layout) shows.

| Option   | Type                 | Default | Description                                    |
| -------- | -------------------- | ------- | ---------------------------------------------- |
| `ignore` | `IgnoreNode \| null` | `null`  | Names the nodes that hold only part of a block |

`ignore` is for an editor whose document shows one block as several nodes. Page Layout does
this where a page ends inside a paragraph.

The paragraph's first lines are then one node on the first page, and the rest is a second
node, a piece, on the next page. Without `ignore`, Whole blocks would take the first node for
the whole paragraph.

`IgnoreNode` is a function `(node) => boolean | 'descend'` that the extension calls with nodes
of the editor's document:

- **`true` for a textblock** marks it as a piece of a block, not a block of its own. A
  selection that starts in a piece is left to the default. So is a selection that ends at the
  end of a node whose block goes on in a piece. `'descend'` has the same effect on a textblock.
- **`'descend'` for a container**, such as a list, marks it as the rest of a container that a
  page boundary cut, which holds whole blocks. The list item that ends right before it is whole,
  although the list goes on after it.
- **`false`** is any other node.

This example treats every textblock with the attribute `isCopy`, an attribute of your own
schema, as a piece:

```js
WholeBlocks.configure({ ignore: node => node.attrs.isCopy === true })
```

## Switching it off

Leave it out of the extensions. No option turns it off while it is registered.

## Writing with transactions

The functions that decide what the extension does are exported, so a key handler or a toolbar
button of your own can do the same. Each takes the editor's state, `editor.state`. This example
deletes the selected whole blocks:

```js
import {
  blockCoverOf,
  deleteWholeBlocksTransaction,
  wholeBlockSlice,
} from '@tiptap-pro/extension-whole-blocks'

const ignore = () => false

blockCoverOf(editor.state, ignore) // what the selection covers, or null

const transaction = deleteWholeBlocksTransaction(editor.state, ignore)

if (transaction) {
  editor.view.dispatch(transaction)
}
```

Each function takes the editor's state and an `ignore` function like the option's:

| Function                       | Arguments         | Returns                                                                  |
| ------------------------------ | ----------------- | ------------------------------------------------------------------------ |
| `blockCoverOf`                 | `state`, `ignore` | A `BlockCover`, or `null`                                                |
| `deleteWholeBlocksTransaction` | `state`, `ignore` | The deletion as a transaction, or `null`                                 |
| `wholeBlockSlice`              | `state`, `ignore` | The `Slice` a copy puts on the clipboard, or `null`                      |
| `wholeBlocksPlugin`            | `ignore`          | The ProseMirror plugin `WholeBlocks` registers, for an editor without it |

- **`ignore` is a function.** Pass `() => false` where nothing is to be ignored.
- **`null` from any of them** means the selection does not cover whole blocks, and the default
  applies.
- **A `BlockCover`** is `{ kind: 'whole', from }` for blocks covered to their end, or
  `{ kind: 'into', from, last }` for a selection that ends inside `last`. `from` is the document
  position where the selection starts, and `last` is the node the selection ends in.
- **`wholeBlockSlice`** returns the copied content, a `Slice` from `@tiptap/pm/model`, for a copy
  action of your own. It returns `null` unless the whole blocks share one parent node.
- **`wholeBlocksPlugin`** is for a ProseMirror `EditorState` you create yourself, outside an
  editor's extensions. In a Tiptap editor, add `WholeBlocks` instead.
- **`WholeBlocksOptions`** is the type of the options.

## Limitations

The extension leaves these cases to Tiptap's default handling, or does not cover them:

- **Text selections only.** A node selection, or everything selected with `Mod-a` (Cmd+A or
  Ctrl+A), is left to the default.
- **Typing over whole blocks.** The typed text replaces the selection, and the first block stays
  with its type, as without the extension. Word removes the first block too, and the typed text
  joins the block after it.
- **Nothing shows that the block goes whole.** The highlight ends at the last character. Word
  also highlights the paragraph mark, the end-of-paragraph symbol, to show that it goes too.
- **No commands.** The extension changes keys, cut, copy and drag. It adds nothing to
  `editor.commands`.

## With Page Layout

In a Page Layout editor, a page boundary can cut a block in two pieces. Set `ignore` to
`ignoreLayoutArtifacts`, the `IgnoreNode` function Page Layout exports, so a block that goes on
over a page counts as one:

```js
import { ignoreLayoutArtifacts } from '@tiptap-pro/extension-page-layout'
import { WholeBlocks } from '@tiptap-pro/extension-whole-blocks'

WholeBlocks.configure({ ignore: ignoreLayoutArtifacts })
```

What changes on pages is described in
[Extension behavior](/features/page-layout/extension-behavior#whole-blocks), in
the Page Layout docs.
