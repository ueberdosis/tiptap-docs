A block here is any textblock, a node that holds text directly, such as a paragraph, a heading
or a code block. Word calls this behavior smart paragraph selection.

## Install

To add Whole blocks to an editor:

1. Set up Tiptap's private registry, as the
   [private registry guide](https://tiptap.dev/docs/guides/pro-extensions) explains.
2. Install the package:

   ```bash
   npm install @tiptap-pro/extension-whole-blocks
   ```

3. Add `WholeBlocks` to the editor's extensions:

   ```js
   import { Editor } from '@tiptap/core'
   import StarterKit from '@tiptap/starter-kit'
   import { WholeBlocks } from '@tiptap-pro/extension-whole-blocks'

   const editor = new Editor({
     element: document.querySelector('#editor'),
     extensions: [StarterKit, WholeBlocks],
   })
   ```

To check that it works, select a heading from its first character to its last and press
Backspace. The heading is gone, and the caret is at the start of the block that followed it.

Whole blocks works in any Tiptap editor, with or without Page Layout. Its peer dependencies are
`@tiptap/core` and `@tiptap/pm`.

## Deleting and cutting whole blocks

When a selection starts at the first character of a block and ends at the last character of a
block, it covers whole blocks. Backspace, Delete and cut then remove those blocks, and the caret
lands at the start of the block that followed.

A selection that starts after the first character of a block is handled as in any Tiptap
editor: the text goes, and the block stays.

## Copying and pasting whole blocks

When the user copies, cuts or drags whole blocks, the clipboard carries them as blocks. A paste
or a drop in a Tiptap editor then inserts them as blocks of their own. Without the extension,
their text would be merged into the block at the cursor.

This works when the blocks share one parent node. Blocks from two list items, or from a list and
the paragraph after it, are copied as without the extension.

## A selection that ends inside a block

A selection can also start at the first character of a block and end inside a later block.
Backspace, Delete and cut then remove every block before the last one whole, and the start of
the last one.

The rest of the last block keeps its own type. A selection from the start of a heading into the
middle of a paragraph leaves the rest as a paragraph.

When the last block's type cannot hold the
text that is left, the rest joins the first block, and that block keeps its own type. A code
block is such a type for bold text, because it allows no formatting.

## When a block is the only content of its parent

When the selected block is the only content of its parent, the parent decides what is left. No
option changes it:

- **A list item or a blockquote.** The block takes the list item or the blockquote along. A list
  whose only item goes is removed too.
- **A table cell.** The block stays in the cell, empty, because deleting the text of a cell does
  not delete the cell. The same holds for any node whose type sets `isolating: true`, a setting
  that keeps editing inside the node. The table cells of `@tiptap/extension-table` set it.
- **The document.** The block stays, empty, because a document needs one block.

## With Page Layout

Page Layout, a separate Pro extension, shows a document on pages. Where a page ends inside a
paragraph, the editor shows the paragraph as two nodes, one on each page, while the document you
save keeps one.

Set the [ignore](/features/whole-blocks#ignore) option to `ignoreLayoutArtifacts`, the function Page
Layout exports for this, so the paragraph still counts as one block. Use the configured
extension in place of `WholeBlocks`:

```js
import { ignoreLayoutArtifacts } from '@tiptap-pro/extension-page-layout'
import { WholeBlocks } from '@tiptap-pro/extension-whole-blocks'

const wholeBlocks = WholeBlocks.configure({ ignore: ignoreLayoutArtifacts })
```

What else changes on pages is on
[Extension behavior](/features/page-layout/extension-behavior#whole-blocks), in
the Page Layout docs.

## Options

`WholeBlocks` has one option, and most editors leave it at its default:

| Option   | Type                 | Default | Description                                                     |
| -------- | -------------------- | ------- | --------------------------------------------------------------- |
| `ignore` | `IgnoreNode \| null` | `null`  | The nodes that hold only part of a block. See [ignore](/features/whole-blocks#ignore) |

No option turns the extension off. To turn it off, leave `WholeBlocks` out of the editor's
extensions.

### ignore

Defaults to `null`. `ignore` is for an editor that shows one block as several nodes, as Page
Layout does at a page boundary. The first node holds the start of the block. Every node after it
that holds the rest is a piece.

`IgnoreNode` is a function `(node) => boolean | 'descend'`. The extension calls it with nodes of
the editor's document, and it answers for each node:

- **`true` for a textblock that is a piece.** The block before it is then not whole at its
  last character, because it goes on in the piece. A selection that starts in a piece is left
  to the default too. `'descend'` has the same effect on a textblock.
- **`'descend'` for a container that is a piece**, such as the second part of a list that a page
  boundary cut between two items. The items in it are whole blocks. The last item before the
  cut is whole as well, because it ends where the list is cut.
- **`false` for any other node.**

In this example, the nodes that hold the rest of a block carry `isCopy`, an attribute of your
own schema:

```js
WholeBlocks.configure({ ignore: node => node.attrs.isCopy === true })
```

## Functions for your own handlers

The functions that decide what the extension does are exported, so a key handler or a toolbar
button of your own can do the same. This example deletes the selected whole blocks:

```js
import { deleteWholeBlocksTransaction } from '@tiptap-pro/extension-whole-blocks'

// The ignore function of an editor without pieces, see the ignore option
const noPieces = () => false
const transaction = deleteWholeBlocksTransaction(editor.state, noPieces)

if (transaction) {
  editor.view.dispatch(transaction)
}
```

Each function takes the editor's state, `editor.state`, and an `ignore` function. Pass
`() => false` when the editor has no pieces. A function returns `null` when the selection does
not cover whole blocks:

| Function                       | Arguments         | Returns                                                                |
| ------------------------------ | ----------------- | ---------------------------------------------------------------------- |
| `blockCoverOf`                 | `state`, `ignore` | What the selection covers, as a `BlockCover`, or `null`                |
| `deleteWholeBlocksTransaction` | `state`, `ignore` | The deletion as a transaction you dispatch yourself, or `null`         |
| `wholeBlockSlice`              | `state`, `ignore` | The content a copy puts on the clipboard, as a `Slice`, or `null`      |
| `wholeBlocksPlugin`            | `ignore`          | The ProseMirror plugin of the extension, for a state outside an editor |

- **A `BlockCover`** is `{ kind: 'whole', from }` for a selection that ends at the end of a
  block. For one that ends inside the block `last`, it is `{ kind: 'into', from, last }`. `from`
  is the document position where the selection starts, and `last` is the node of that block.
- **`wholeBlockSlice`** returns a `Slice` from `@tiptap/pm/model`, for a copy action of your own.
  It returns `null` unless the whole blocks share one parent node.
- **`wholeBlocksPlugin`** is for a ProseMirror `EditorState` you create yourself. In a Tiptap
  editor, add `WholeBlocks` instead.

A copy button of your own can put whole blocks on the clipboard the way Ctrl+C does. When the
selection does not cover whole blocks, it falls back to the selected content. Call it from a
click handler, because the browser allows `navigator.clipboard.write` only for a focused page:

```js
import { wholeBlockSlice } from '@tiptap-pro/extension-whole-blocks'

async function copyAsBlocks(editor) {
  const slice = wholeBlockSlice(editor.state, () => false) ?? editor.state.selection.content()
  const { dom, text } = editor.view.serializeForClipboard(slice)

  await navigator.clipboard.write([
    new ClipboardItem({
      'text/html': new Blob([dom.innerHTML], { type: 'text/html' }),
      'text/plain': new Blob([text], { type: 'text/plain' }),
    }),
  ])
}
```

The package also exports the types `WholeBlocksOptions`, `IgnoreNode` and `BlockCover`.

## Limitations

What Whole blocks leaves as it is in a Tiptap editor without it:

### Typing over whole blocks

Typing over a selection of whole blocks works as without the extension: the typed text replaces
the selection, and the first block stays with its type. Word removes the first block too, and
the typed text joins the block after it.

### Select all and node selections

Whole blocks handles text selections only. A document selected with `Mod-a` (Cmd+A or Ctrl+A),
or a node selected as a whole, is handled as in any Tiptap editor.

### A visible paragraph mark

The highlight of a selection ends at the last character, so nothing shows the user that the
block will go whole. Word shows this by also highlighting the paragraph mark, the symbol at the
end of a paragraph.

### Commands

Whole blocks adds no commands to `editor.commands`. It changes what Backspace, Delete, cut, copy
and drag do.

## With other extensions

`WholeBlocks` has the priority 1010. Its Backspace and Delete handling runs before extensions
with a lower priority, such as the Tiptap default of 100. An extension of yours that has to
handle these keys first needs a higher priority.

Cut and copy go through the editor's own clipboard handling, so other extensions that change
what is copied still apply.
