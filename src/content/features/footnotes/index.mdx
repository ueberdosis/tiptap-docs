A footnote and an endnote are the same note. One attribute, its placement, says which it is.
Footnotes and endnotes count separately: 1, 2, 3 and i, ii, iii. This number is the note's
mark, shown at the reference and at the head of the note.

In an editor without pages, both kinds stand at the end of the document, each in a list of its
own, so they differ only in their numbers. With [Page Layout](/features/page-layout/getting-started/overview), which shows the editor as
pages, a footnote is drawn at the foot of the page that refers to it.

## Install

```bash
npm install @tiptap-pro/extension-footnotes
```

The package comes from the Tiptap Pro registry. See
[the Pro registry](/features/page-layout/getting-started/install#the-pro-registry)
if you have not set it up yet.

- **Peer dependencies:** `@tiptap/core` and `@tiptap/pm`.
- **Dependency:** `@tiptap-pro/extension-number-formats`, which writes the marks as 1, i, a or
  another format. It is installed with the package.

## Quick start

Add `Footnotes` to the editor, and put its stylesheet in the page once:

```js
import { Editor } from '@tiptap/core'
import StarterKit from '@tiptap/starter-kit'
import { Footnotes, mountFootnoteStyles } from '@tiptap-pro/extension-footnotes'

mountFootnoteStyles(document)

const editor = new Editor({
  element: document.querySelector('#editor'),
  extensions: [StarterKit, Footnotes.configure({ defaultPlacement: 'footnote' })],
})

editor.commands.insertFootnote()
```

- **The stylesheet draws the numbers.** Without it, references and notes show no numbers.
  `footnoteStyleRules()` returns the same rules as a CSS string, for a stylesheet of your own.
- **`insertFootnote()` makes an endnote** unless you set `defaultPlacement: 'footnote'`, as the
  code does. With Page Layout it makes a footnote unless you set `'endnote'`.
- **`insertFootnote()` moves the caret into the new note,** so the user types its text next. Call
  it from a toolbar button, as `editor.chain().focus().insertFootnote().run()`.
- **Every note is shown at the end of the document.** Footnotes stand in one run of notes and
  endnotes in another, after the last block with content. A run of notes is a numbered list,
  `footnoteCollection` in the document.

## What the document holds

| Node                     | Where it stands                       | HTML element and class                |
| ------------------------ | ------------------------------------- | ------------------------------------- |
| `footnoteReference`      | Inline, where the note is referred to | `sup.tiptap-footnote-reference`       |
| `footnote`               | The note's text, inside a collection  | `li.tiptap-footnote`                  |
| `footnoteCollection`     | A block at the end, one run of notes  | `ol.tiptap-footnotes`                 |
| `footnoteNumberingBreak` | A block where the count starts again  | `div.tiptap-footnote-numbering-break` |

- **The notes are saved with the document.** `editor.getJSON()` and `editor.getHTML()` hold the
  references and the collections, and setting that content again restores them.
- **`footnoteId`** pairs a reference with its note. The Commands and the click handlers take it.
  To get the `footnoteId` of the note at the caret, use
  [`footnoteAtSelection`](/features/footnotes#reading-the-notes).
- **`placement`** on a note and on a collection is `'footnote'` or `'endnote'`. The default is
  `'endnote'`.
- **One collection per placement and numbering scope.** Footnotes and endnotes stay apart, the
  footnotes first. A numbering scope is the part of the document between two
  [numbering breaks](/features/footnotes#numbering-breaks). Without breaks, the whole document is one scope.
- **No number is stored.** The editor draws each mark, so a note inserted above renumbers every
  note after it without an edit. `getHTML()` has no numbers either. To show saved content with
  its numbers outside the editor, read them with [`noteNumbers`](/features/footnotes#reading-the-notes).
- **Empty paragraphs at the end stay after the collections.** StarterKit's trailing paragraph
  goes there. Once you type in one, the collections move after it.

The HTML attributes are listed under [Names](/features/footnotes#names).

### Copying a note

A note has one reference. Copying text with a reference in it copies the note as well:

- **Copy and paste** gives the pasted reference a note of its own, with the same text and a new
  `footnoteId`. The original keeps its identity.
- **Cut and paste**, and dragging text, keep the `footnoteId` and the note.
- **Pasting into another document** brings the note along.
- **A second reference to the same note** gets its own copy of the note. It comes from HTML
  that holds the reference but not its note, or from a script. The first reference in the text
  keeps the original.
- **The new identity is derived** from the old one, such as `fn3-1` and `fn3-2`. Every client of
  a shared document arrives at the same one.

## Clicking a reference or a mark

Both clicks are off by default, so a click on a reference selects it. Turn them on to lead from
the reference to its note, and from the mark at the head of the note back to the text:

```js
Footnotes.configure({
  onReferenceClick: ({ footnoteId }) => editor.commands.focusFootnote(footnoteId),
  onNoteMarkClick: ({ footnoteId }) => editor.commands.focusFootnoteReference(footnoteId),
})
```

| Handler            | Receives                             | Called for                                                     |
| ------------------ | ------------------------------------ | -------------------------------------------------------------- |
| `onReferenceClick` | `{ footnoteId, pos, event }`         | A click on the reference                                       |
| `onNoteMarkClick`  | `{ footnoteId, noteElement, event }` | A left-button press on the first line, before its first letter |

- **Return `true`** when you handled the click. Return `false` to let the editor handle it as
  usual: it selects the reference, or puts the caret at the start of the note. The commands in
  the example return `true` when they move the caret.
- **The handlers run after the editor exists,** so they can use the `editor` that
  `new Editor()` returns.
- **The editor gets a class while a handler is set:** `tiptap-footnote-references-clickable` or
  `tiptap-footnote-marks-clickable`. The stylesheet shows a pointer under it.
- **With Page Layout,** both clicks work without a handler. See
  [What Page Layout sets](/features/page-layout/extension-behavior/footnotes#what-page-layout-sets).

## Numbering

Footnotes count 1, 2, 3 and endnotes i, ii, iii, so the mark tells a reader where to look. Change
either sequence:

```js
Footnotes.configure({
  footnoteNumbers: { format: 'decimal', start: 1 },
  endnoteNumbers: { format: 'lowerRoman', start: 1 },
})
```

| Field    | Type           | Description                                                                |
| -------- | -------------- | -------------------------------------------------------------------------- |
| `format` | `NumberFormat` | One of the [number formats](/features/number-formats) |
| `start`  | `number`       | The number of the first note of that kind                                  |

Name only the sequence you change. The other keeps its default.

### Numbering breaks

A numbering break lets each chapter, or a preface and the body, number its notes from 1.
`insertNoteNumberingBreak()` puts a break at the caret. After it, footnotes and endnotes both
count from the start again.

```js
editor.commands.insertNoteNumberingBreak({
  footnoteNumbering: { format: 'lowerAlpha', start: 1 },
})
```

- **The break replaces the Selection.** Selected text is deleted. With nothing selected, a caret
  in the middle of a paragraph splits the paragraph.
- **Each scope keeps its own runs of notes.** Its collections stand at the end of the scope,
  before the break. So with breaks, notes also stand inside the document, not only at its end.
- **A break can change the marks.** `footnoteNumbering` and `endnoteNumbering` on the break set
  the sequence from there on. `null` keeps the format and start used before the break.
- **The break is drawn as a dashed rule** with no label.

## Titles above a run of notes

A run of notes has no title by default, as in a printed document. To head each run, name a Node
type of your schema:

```js
Footnotes.configure({
  titleNode: 'heading',
  footnoteTitle: 'Notes',
  endnoteTitle: 'Endnotes',
})
```

- **The title is written once,** when the run of notes is created. After that it is content, and
  the user can rename it. A run that existed before you set `titleNode` gets no title.
- **The title Node gets its default attributes.** With StarterKit, a `heading` title is a level 1
  heading.
- **`titleNode` is read when the schema is built.** To turn titles on or off, create a new
  editor.
- **The words default** to `'Footnotes'` and `'Endnotes'`.

## Keeping notes and references agreeing

After every change, the editor checks the notes and fixes them in the same step. This pass keeps
each note with its reference and in the order of the references:

- **A deleted reference** takes its note with it.
- **A second reference to the same note** gets a copy of its own. See
  [Copying a note](/features/footnotes#copying-a-note).
- **A note out of order** moves to where its reference is read.
- **A note whose placement changed** moves into the other run.

Leave the pass on. Set `repair: false` only in an editor that shows something other than the
document you save. Page Layout sets it, because its editor shows pages: the pass then runs on
the document and not on the pages. See [What Page Layout sets](/features/page-layout/extension-behavior/footnotes#what-page-layout-sets).

## Styling

`mountFootnoteStyles(document, options)` adds a `style` element to the page once. A second call
with the same `id` does nothing.

| Option  | Type     | Default                    | Description                                  |
| ------- | -------- | -------------------------- | -------------------------------------------- |
| `id`    | `string` | `'tiptap-footnote-styles'` | The id of the `style` element                |
| `nonce` | `string` | None                       | The nonce a Content Security Policy asks for |

Under a Content Security Policy, pass `nonce`: the same value you give the editor's
`injectNonce` option.

These custom properties change the look. Set them on `.tiptap` or on any element around it:

```css
.tiptap {
  --tt-footnotes-rule: none;
  --tt-footnote-size: 0.8em;
}
```

| Property                                | Default                   | Changes                               |
| --------------------------------------- | ------------------------- | ------------------------------------- |
| `--tt-footnote-reference-raise`         | `-0.45em`                 | How far a reference is raised         |
| `--tt-footnote-reference-color`         | `inherit`                 | The color of a reference              |
| `--tt-footnote-reference-cursor`        | `pointer`                 | The cursor over a clickable reference |
| `--tt-footnote-reference-target`        | `-0.7em -0.35em -0.5em`   | The click area, as a CSS `inset`      |
| `--tt-footnotes-space`                  | `2rem`                    | The space above a run of notes        |
| `--tt-footnotes-rule`                   | `1px solid currentColor`  | The rule above a run of notes         |
| `--tt-footnote-size`                    | `0.875em`                 | The text size of a note               |
| `--tt-footnote-layout`                  | `block`                   | `grid` for a hanging indent           |
| `--tt-footnote-number-float`            | `left`                    | `none` for a hanging indent           |
| `--tt-footnote-number-width`            | `1.5em`                   | The number column of a hanging indent |
| `--tt-footnote-number-color`            | `inherit`                 | The color of a note's number          |
| `--tt-footnote-number-size`             | `0.85em`                  | The size of a note's number           |
| `--tt-footnote-number-cursor`           | `pointer`                 | The cursor over a clickable mark      |
| `--tt-footnote-gap`                     | `0.4em`                   | The space after a note's number       |
| `--tt-footnote-numbering-break-space`   | `0.6em`                   | The space above a numbering break     |
| `--tt-footnote-numbering-break-rule`    | `1px dashed currentColor` | The rule of a numbering break         |
| `--tt-footnote-numbering-break-opacity` | `0.5`                     | The opacity of a numbering break      |

By default, a note's number stands at the head of its first line, and the text runs on past it.
Set `--tt-footnote-layout: grid` and `--tt-footnote-number-float: none` to put the number in a
column of its own.

## Pasting from Word

Footnotes and endnotes copied in Word paste as notes. `Footnotes` adds this itself.

- **A reference** goes where Word's mark was, and the note's text into the run of notes.
- **A footnote stays a footnote,** and an endnote stays an endnote.
- **Each note gets a new identity,** and is numbered with the others.
- **A mark whose note was not copied keeps Word's anchor,** a link around the number. Word keeps
  its notes at the end of the document, so text copied without the end has none.

`Footnotes` includes the `WordFootnotePaste` Extension, so do not add it a second time. For an
editor that handles pastes its own way, the steps are exported:

| Export                   | Arguments                     | What it does                                                                                  |
| ------------------------ | ----------------------------- | --------------------------------------------------------------------------------------------- |
| `wordNotesToHtml`        | `html, createId?`             | Returns `{ html, notes }`: references in place of Word's marks, and each note by `footnoteId` |
| `sliceCarryingWordNotes` | `slice, notes, schema, parse` | Returns the Slice with each pasted reference carrying its note                                |
| `parseWordNoteInBrowser` | None, pass it as `parse`      | The `parse` the editor uses: reads a note's HTML with the schema's parser                     |
| `WordFootnotePaste`      | None, an Extension            | The Extension that runs both on a paste, for an editor without `Footnotes`                    |

## Options

| Option             | Type                                    | Default                              | Description                                                                                               |
| ------------------ | --------------------------------------- | ------------------------------------ | --------------------------------------------------------------------------------------------------------- |
| `defaultPlacement` | `'footnote' \| 'endnote' \| null`       | `null`                               | What `insertFootnote` makes when it is not told. `null` makes an endnote, and a footnote with Page Layout |
| `footnoteNumbers`  | `NoteSequence`                          | `{ format: 'decimal', start: 1 }`    | How footnotes count. See [Numbering](/features/footnotes#numbering)                                                          |
| `endnoteNumbers`   | `NoteSequence`                          | `{ format: 'lowerRoman', start: 1 }` | How endnotes count                                                                                        |
| `numbering`        | `boolean`                               | `true`                               | `false` draws no marks, for an integration that draws its own                                             |
| `counter`          | `NoteCounter \| null`                   | `null`                               | `(doc) => Map` from `footnoteId` to `{ ordinal, format }`: the number and format of each mark             |
| `scopes`           | `NoteScopeReader \| null`               | `null`                               | `(doc) => number[]`: the positions where a scope ends                                                     |
| `titleNode`        | `string \| null`                        | `null`                               | The Node type that heads a run. See [Titles](/features/footnotes#titles-above-a-run-of-notes)                                |
| `footnoteTitle`    | `string`                                | `'Footnotes'`                        | The words of a new footnote title                                                                         |
| `endnoteTitle`     | `string`                                | `'Endnotes'`                         | The words of a new endnote title                                                                          |
| `repair`           | `boolean`                               | `true`                               | Whether [the pass](/features/footnotes#keeping-notes-and-references-agreeing) runs in this editor                            |
| `notesDocument`    | `((editor) => Node \| null) \| null`    | `null`                               | The document a copy takes notes from. `null` is the editor's own                                          |
| `onReferenceClick` | `FootnoteReferenceClickHandler \| null` | `null`                               | See [Clicking a reference or a mark](/features/footnotes#clicking-a-reference-or-a-mark)                                     |
| `onNoteMarkClick`  | `NoteMarkClickHandler \| null`          | `null`                               | See [Clicking a reference or a mark](/features/footnotes#clicking-a-reference-or-a-mark)                                     |

- **`counter`, `scopes` and `notesDocument` are for an integration that shows the document as
  something else, such as pages.** Page Layout sets all three. Leave them `null` in an editor
  that shows the document as it is.
- **Set `counter` and `scopes` together, or neither.** With only one, the marks count one way and
  the runs of notes split another.
- **`scopes` replaces the numbering breaks.** Without it, the breaks in the text end the scopes.

## Commands

Each command returns `false` when it has nothing to do, so `editor.can()` tells a toolbar
whether to enable its button.

### insertFootnote

Inserts a reference at the caret and a note for it, and moves the caret into the note.

```js
editor.commands.insertFootnote()
editor.commands.insertFootnote({ placement: 'footnote' })
```

| Option      | Type                      | Description                                                                            |
| ----------- | ------------------------- | -------------------------------------------------------------------------------------- |
| `placement` | `'footnote' \| 'endnote'` | The kind of note. Default the `defaultPlacement` option                                |
| `at`        | `number`                  | Where the reference goes. Default the head of the Selection                            |
| `createId`  | `() => string`            | Makes the new `footnoteId`. Default `createFootnoteId`                                 |
| `titles`    | `StrandTitles`            | `{ node, footnote, endnote }` for a run this insert creates. Default the title options |
| `scopes`    | `NoteScopeReader \| null` | Where the scopes end. Default the `scopes` option                                      |

Returns `false` where the position takes no text, inside a note, and when the schema has no
`footnote` or `footnoteCollection`.

### deleteFootnote

Deletes a note and every reference to it, in one step.

```js
editor.commands.deleteFootnote('fn3')
```

| Argument     | Type     | Description        |
| ------------ | -------- | ------------------ |
| `footnoteId` | `string` | The note to delete |

Returns `false` when neither a note nor a reference has that `footnoteId`.

### setFootnotePlacement

Turns a footnote into an endnote, or back. It stays the same note.

```js
editor.commands.setFootnotePlacement('fn3', 'endnote')
```

| Argument     | Type                      | Description       |
| ------------ | ------------------------- | ----------------- |
| `footnoteId` | `string`                  | The note          |
| `placement`  | `'footnote' \| 'endnote'` | Its new placement |

Returns `false` when no note has that `footnoteId`, and when the note has that placement
already.

### focusFootnote

Puts the caret at the start of a note's text.

```js
editor.commands.focusFootnote('fn3')
```

| Argument     | Type     | Description       |
| ------------ | -------- | ----------------- |
| `footnoteId` | `string` | The note to go to |

Returns `false` when no note has that `footnoteId`.

### focusFootnoteReference

Puts the caret at a note's reference in the text.

```js
editor.commands.focusFootnoteReference('fn3')
```

| Argument     | Type     | Description                       |
| ------------ | -------- | --------------------------------- |
| `footnoteId` | `string` | The note whose reference to go to |

Returns `false` when no reference has that `footnoteId`.

### insertNoteNumberingBreak

Inserts a [numbering break](/features/footnotes#numbering-breaks) in place of the Selection.

```js
editor.commands.insertNoteNumberingBreak()
```

| Option              | Type                   | Description                                                    |
| ------------------- | ---------------------- | -------------------------------------------------------------- |
| `at`                | `number`               | Where the break goes. Default the head of the Selection        |
| `footnoteNumbering` | `NoteSequence \| null` | How footnotes count after the break. Default `null`, as before |
| `endnoteNumbering`  | `NoteSequence \| null` | How endnotes count after the break. Default `null`, as before  |

Returns `false` inside a note, and when the schema has no `footnoteNumberingBreak`.

## Reading the notes

`footnoteAtSelection` says which note a Selection is on, and whether it is in the note or at its
reference. A toolbar reads it to offer the way to the note or back:

```js
import { footnoteAtSelection } from '@tiptap-pro/extension-footnotes'

footnoteAtSelection(editor.state.selection)
// { footnoteId: 'fn3', in: 'note' }, { footnoteId: 'fn3', in: 'reference' } or null
```

`noteNumbers` returns the mark of every note, as the editor draws it:

```js
import { noteNumbers } from '@tiptap-pro/extension-footnotes'

noteNumbers(editor.state.doc).get('fn3') // 'iv'
```

Each of these reads a document, without an editor:

| Function                    | Arguments         | Returns                                                                                                       |
| --------------------------- | ----------------- | ------------------------------------------------------------------------------------------------------------- |
| `footnoteReferences`        | `doc`             | `{ footnoteId, pos }` of every reference in the text, in reading order                                        |
| `footnoteAt`                | `doc, footnoteId` | `{ node, pos }` of the note, or `null`                                                                        |
| `footnoteCollectionsIn`     | `doc`             | `{ node, pos }` of every collection                                                                           |
| `footnoteCollectionFor`     | `doc, placement`  | The first collection of that placement, or `null`                                                             |
| `numberingBreaksIn`         | `doc`             | `{ node, pos }` of every numbering break                                                                      |
| `noteNumbers`               | `doc, options?`   | A `Map` from `footnoteId` to its mark. `options` takes `sequences`, as `{ footnote, endnote }`, and `counter` |
| `footnoteNumberDecorations` | `doc, options?`   | The marks as a DecorationSet                                                                                  |
| `scopeBoundaries`           | `doc, reader?`    | The positions where a scope ends, from `reader` or from the breaks                                            |
| `scopeOfPosition`           | `boundaries, pos` | The index of the scope a position is in, from the top                                                         |
| `schemaHasFootnotes`        | `doc`             | Whether the schema has `footnote` and `footnoteCollection`                                                    |

These read one Node:

- **`isFootnoteReference`, `isFootnote`, `isFootnoteCollection`, `isFootnoteNumberingBreak`** say
  whether a Node is of that type.
- **`footnoteIdOf(node)`** returns the `footnoteId` of a reference or a note, or `null`.
- **`placementOf(node)`** returns the placement of a note or a collection.
- **`noteStrandTitle(collection)`** returns the title of a collection, or `null`.
- **`numberingBreakSequence(node, kind)`** returns the sequence a break sets for `'footnote'` or
  `'endnote'`, or `null`.

## Writing without a command

Each Command that writes has a function that returns the Transaction instead of dispatching it,
or `null` where the Command returns `false`:

| Command                    | Function                                                        |
| -------------------------- | --------------------------------------------------------------- |
| `insertFootnote`           | `insertFootnoteTransaction(state, options?)`                    |
| `deleteFootnote`           | `deleteFootnoteTransaction(state, footnoteId)`                  |
| `setFootnotePlacement`     | `setFootnotePlacementTransaction(state, footnoteId, placement)` |
| `insertNoteNumberingBreak` | `insertNoteNumberingBreakTransaction(state, options?)`          |

`insertFootnoteTransaction` makes an endnote unless `placement` says otherwise, and no title
unless `titles` names one.

For an editor state without the `Footnotes` Extension, its parts are exported too:

- **The Nodes:** `FootnoteReference`, `Footnote`, `FootnoteCollection` and
  `FootnoteNumberingBreak`.
- **The plugins:** `footnotesRepairPlugin(options)`, `footnoteReferenceClickPlugin(handler)` and
  `noteMarkClickPlugin(handler)`.
- **The pass as one write:** `repairTransaction(tr, doc, options)`. It returns `null` when the
  document needs no repair.
- **The mark area:** `markZoneOf(noteElement)` measures it, and `isOnNoteMark(zone, x, y)` says
  whether a point is in it.
- **Ids:** `createFootnoteId()`.

## Limitations

- **A note has one reference.** To refer to a note a second time, write "see note 3" as text, or
  use a [cross-reference](/features/cross-references#footnotes-as-targets).
- **A note cannot hold a reference** or a numbering break.
- **Pasting plain text loses the note.** Plain text has no reference to carry it.
- **An empty note has no mark to click.** `onNoteMarkClick` finds the mark from the note's first
  line.
- **A single note cannot have a mark of its own,** such as a symbol outside the count.
- **A .docx file needs Page Layout for its notes.** With Page Layout, Tiptap Conversion v3
  imports Word's footnotes and endnotes as these notes, and exports these notes to Word. Without
  Page Layout, the notes travel as separate objects that you handle yourself. See
  [Footnotes and endnotes](https://tiptap.dev/docs/conversion/v3/content-reference/structures-and-media/footnotes-endnotes)
  in the Conversion docs.

With [Page Layout](/features/page-layout/getting-started/overview), a footnote is drawn at the foot
of the page that refers to it. See
[Footnotes in Page Layout](/features/page-layout/extension-behavior/footnotes).
