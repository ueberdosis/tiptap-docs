A reference is the number in the text that points to a note. A
[numbering break](/features/footnotes/numbering#number-again-from-1-in-each-chapter) is a point after which notes
are numbered from 1 again, and a collection is the numbered list of notes it ends.

## Two references to one note

A note has one reference, so a second reference to it, for example from a paste, gets a copy of the
note. To refer to a note again, write "see note 3" as text, or use a
[cross-reference](/features/cross-references/targets#footnotes-as-targets), which
prints the note's number.

## A reference or a numbering break inside a note

`insertFootnote()` and `insertNoteNumberingBreak()` return `false` inside a note, but a paste can
still put a reference or a numbering break there:

- **A reference inside a note** gets no number and no note. Its `carriedNote` attribute keeps the
  JSON of the note it was copied with, also in the saved document.
- **A numbering break inside a note** starts the numbers again, but the notes before and after it
  stay in one collection.

To fix it, the user deletes the reference or the break from the note and inserts it again in the
text.

## A numbering break inside a blockquote, a list or a table

`insertNoteNumberingBreak()` also works inside a blockquote, a list item or a table cell, and the
numbers start again there. But such a break does not start a new collection, so one collection of
notes shows the number 1 twice.

Only a break between two blocks of the document itself, outside
any blockquote, list or table, starts a new collection.

Insert numbering breaks between paragraphs or headings of the document, not inside other blocks.

## Pasting as plain text

A reference carries its note on the clipboard only in HTML, so pasting as plain text loses the note.

## Clicking the number of an empty note

`onNoteMarkClick`, whose name calls the number a mark, finds the number from the note's first line,
so an empty note has none to click.

## Giving one note a number of its own

Every number comes from the count, so a single note cannot read \* while the others read 1, 2, 3.
Only `counter`, which replaces the whole count, can do it. See
[Numbering](/features/footnotes/numbering#numbers-in-an-integration-that-draws-pages).

## Searching the page for a note's number

The stylesheet draws each number as CSS content, so the browser's find in page does not find it.

## Endnotes with a screen reader

Screen readers read an endnote's number with a footnote's label: "Footnote reference i" at the
reference and "Footnote i" at the note.

## Exporting notes to a .docx file

Tiptap Conversion v3 imports Word's footnotes and endnotes as these notes with or without Page
Layout, but the export writes them to Word only with Page Layout. See
[Notes in .docx files](/features/footnotes/word#notes-in-docx-files).

## Footnotes at the foot of the page

Without pages, notes stand at the end of their numbering scope.
[Footnotes in Page Layout](/features/page-layout/extension-behavior/footnotes)
draws each footnote at the foot of the page that refers to it.
