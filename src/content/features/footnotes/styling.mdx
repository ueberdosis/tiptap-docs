## The stylesheet

`mountFootnoteStyles(document)` adds the extension's stylesheet to the web page. Without it,
references and notes show no numbers, because the document stores none. The extension writes each
number into the `data-tt-footnote-number` attribute in the editor, and the stylesheet shows it.

```js
import { mountFootnoteStyles } from '@tiptap-pro/extension-footnotes'

mountFootnoteStyles(document, { nonce: 'your-nonce' })
```

`'your-nonce'` stands for the nonce your server sends with the web page. A Content Security Policy
that does not allow inline styles asks for it, and it is the same value you give the editor's
`injectNonce` option. Leave `nonce` out otherwise.

The call appends one `style` element to the `head`. Its options:

| Option  | Type     | Default                    | Description                                                            |
| ------- | -------- | -------------------------- | ---------------------------------------------------------------------- |
| `id`    | `string` | `'tiptap-footnote-styles'` | The id of the `style` element. A call does nothing while the id exists |
| `nonce` | `string` | None                       | The nonce of the `style` element. An empty string adds none            |

`footnoteStyleRules()` returns the same rules as one CSS string, for a stylesheet of your own. The
rules select the classes without `.tiptap` in front, so they also style `getHTML()` output shown
elsewhere on the web page. That HTML has no numbers.

## Custom properties

Custom properties change the look without replacing the rules. Set them on `.tiptap` or on any
element around the editor:

```css
.tiptap {
  --tt-footnotes-rule: none;
  --tt-footnote-size: 0.8em;
}
```

These are all the properties, with their defaults:

| Property                                | Default                   | Changes                                                             |
| --------------------------------------- | ------------------------- | ------------------------------------------------------------------- |
| `--tt-footnote-reference-raise`         | `-0.45em`                 | How far a reference is raised                                       |
| `--tt-footnote-reference-color`         | `inherit`                 | The color of a reference                                            |
| `--tt-footnote-reference-cursor`        | `pointer`                 | The cursor over a reference, while `onReferenceClick` is set        |
| `--tt-footnote-reference-target`        | `-0.7em -0.35em -0.5em`   | The click area around a reference, as a CSS `inset`. `0` removes it |
| `--tt-footnotes-space`                  | `2rem`                    | The space above a list of notes                                     |
| `--tt-footnotes-rule`                   | `1px solid currentColor`  | The line above a list of notes                                      |
| `--tt-footnote-size`                    | `0.875em`                 | The font size of a note                                             |
| `--tt-footnote-layout`                  | `block`                   | `grid` for a hanging indent                                         |
| `--tt-footnote-number-float`            | `left`                    | `none` for a hanging indent                                         |
| `--tt-footnote-number-width`            | `1.5em`                   | The number column of a hanging indent                               |
| `--tt-footnote-number-color`            | `inherit`                 | The color of a note's number                                        |
| `--tt-footnote-number-size`             | `0.85em`                  | The font size of a note's number                                    |
| `--tt-footnote-number-cursor`           | `pointer`                 | The cursor over a note's number, while `onNoteMarkClick` is set     |
| `--tt-footnote-gap`                     | `0.4em`                   | The space after a note's number                                     |
| `--tt-footnote-numbering-break-space`   | `0.6em`                   | The padding above a numbering break                                 |
| `--tt-footnote-numbering-break-rule`    | `1px dashed currentColor` | The line that shows a numbering break                               |
| `--tt-footnote-numbering-break-opacity` | `0.5`                     | The opacity of a numbering break                                    |

A reference is a `sup` element in the browser's smaller font size, which no property changes. The
stylesheet raises it without `vertical-align`, so inserting one does not make its line taller. A
list of notes shows no list markers, because the drawn numbers take their place.

The click area takes no room, but a click inside it selects the reference instead of placing the
cursor. [Insert and edit notes](/features/footnotes/notes#clicks-on-a-reference-and-on-a-notes-number) has the
click handlers.

## A hanging indent

By default, a note's number stands at the start of its first line, and the lines after it start
under the number. A hanging indent puts the number in a column of its own:

```css
.tiptap {
  --tt-footnote-layout: grid;
  --tt-footnote-number-float: none;
}
```

## A title above the notes

A list of notes has no title by default. To head each one, set `titleNode` to a node type of your
schema, such as StarterKit's `heading`. With StarterKit, the title is a level 1 heading:

```js
Footnotes.configure({ titleNode: 'heading', footnoteTitle: 'Notes' })
```

`footnoteTitle` and `endnoteTitle` are the words, `'Footnotes'` and `'Endnotes'` by default.

The extension writes a title only when it creates a list of notes. After that, the title is text the
user can rename or delete. So a list from before `titleNode` was set gets no title, and a list
created again after its last note was deleted gets a new one.

The extension reads `titleNode` when it builds the schema, so turning titles on or off needs a new
editor. A type the schema does not have throws when the editor is created, such as
`No node type or group 'x' found (in content expression 'x? footnote+')`.

## Classes and data attributes

A stylesheet of your own can select these elements, in the editor and in `getHTML()`:

| Node                     | Element and class                     | Data attributes                                                            |
| ------------------------ | ------------------------------------- | -------------------------------------------------------------------------- |
| `footnoteReference`      | `sup.tiptap-footnote-reference`       | `data-tt-footnote-reference`, the `footnoteId` that pairs it with its note |
| `footnote`               | `li.tiptap-footnote`                  | `data-tt-footnote`, the `footnoteId`, and `data-tt-footnote-placement`     |
| `footnoteCollection`     | `ol.tiptap-footnotes`                 | `data-tt-footnote-collection="true"` and `data-tt-footnote-placement`      |
| `footnoteNumberingBreak` | `div.tiptap-footnote-numbering-break` | `data-tt-footnote-numbering-break="true"`, `aria-hidden="true"`            |

A numbering break that sets a format also has `data-tt-footnote-sequence` or
`data-tt-endnote-sequence`, as JSON.

Only in the editor, a reference and a note have
`data-tt-footnote-number`, and the editor's element has `tiptap-footnote-references-clickable` or
`tiptap-footnote-marks-clickable` while a click handler is set.

With
[Page Layout](/features/page-layout/getting-started/overview), the part of a note carried on to the
next page has `data-tt-footnote-continued` and no number.
[Functions and names](/features/footnotes/api-reference/functions#constants) has the constants for these names.
