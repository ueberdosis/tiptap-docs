## The default numbers

Each note takes its number from its reference, the number in the text that points to the note. The
extension counts the references in reading order, footnotes and endnotes separately, so a note
inserted early in the text moves every later note up by one.

The number shows at the reference and at the start of the note. It is not stored, and the
stylesheet draws it, so without [`mountFootnoteStyles(document)`](/features/footnotes/styling#the-stylesheet) no
numbers show. A reference whose note is missing gets no number, and neither does one inside a note,
as [Limitations](/features/footnotes/limitations#a-reference-or-a-numbering-break-inside-a-note) explains.

## Change the format and the start

`footnoteNumbers` sets how footnotes count, and `endnoteNumbers` how endnotes count. Set only the one
you change, because the other keeps its default:

```js
import { Footnotes } from '@tiptap-pro/extension-footnotes'

Footnotes.configure({
  footnoteNumbers: { format: 'lowerAlpha', start: 1 },
  endnoteNumbers: { format: 'upperRoman', start: 1 },
})
```

Both take a `NoteSequence`, which has these fields:

| Field    | Type           | Description                                                                                  |
| -------- | -------------- | -------------------------------------------------------------------------------------------- |
| `format` | `NumberFormat` | The name of a number format. A name the editor does not know draws decimal, without an error |
| `start`  | `number`       | The number of the first note. Each next note counts one more. Below 1, it is drawn as 1      |

| Option            | Default                              | Reads      |
| ----------------- | ------------------------------------ | ---------- |
| `footnoteNumbers` | `{ format: 'decimal', start: 1 }`    | 1, 2, 3    |
| `endnoteNumbers`  | `{ format: 'lowerRoman', start: 1 }` | i, ii, iii |

[Install Footnotes](/features/footnotes/install) has the complete editor these options go into.

### Formats

The formats come from [Number formats](/features/number-formats). These are the
ones notes use most:

| Format         | Reads                                    |
| -------------- | ---------------------------------------- |
| `'decimal'`    | 1, 2, 3                                  |
| `'lowerRoman'` | i, ii, iii                               |
| `'upperRoman'` | I, II, III                               |
| `'lowerAlpha'` | a, b, c, then aa                         |
| `'upperAlpha'` | A, B, C, then AA                         |
| `'symbols'`    | \*, †, ‡, §, then \*\*, ††, as Word does |

[The built-in formats](/features/number-formats#the-built-in-formats) lists
all 29 and where each one falls back to decimal. A format defined with `defineNumberFormat` or
stored in the document works too, and spelled formats use the document's language. See
[Formats stored in the document](/features/number-formats#formats-stored-in-the-document).

## Number again from 1 in each chapter

A numbering break is a point in the document after which notes are numbered from the start again,
such as before each chapter of a book. `insertNoteNumberingBreak()` inserts one at the cursor:

```js
editor.chain().focus().insertNoteNumberingBreak().run()
```

After the break, footnotes and endnotes both count again from their `start`. The part between two
breaks is a numbering scope, and each scope keeps its notes in its own collections, the numbered
lists of notes, in front of the next break.
[Notes in the document](/features/footnotes/document#where-the-collections-stand) says where they stand.

The break changes no text. A cursor inside a paragraph splits it, and a selection keeps its text,
with the break at its head.

### Change the format after a break

`footnoteNumbering` and `endnoteNumbering` set how the notes after a break count. This break numbers
an appendix's footnotes a, b, c, and its endnotes from i again:

```js
editor.commands.insertNoteNumberingBreak({
  footnoteNumbering: { format: 'lowerAlpha', start: 1 },
})
```

`null`, the default, keeps the format and start in force, and so does a sequence that is not valid.
A sequence a break sets holds until another break sets one.

No command changes the sequence of a break already in the document. To change it, find the break
with `numberingBreaksIn` and set its attribute in a transaction. This numbers the footnotes after
the first break I, II, III:

```js
import { numberingBreaksIn } from '@tiptap-pro/extension-footnotes'

const [firstBreak] = numberingBreaksIn(editor.state.doc)

editor.commands.command(({ tr }) => {
  tr.setNodeAttribute(firstBreak.pos, 'footnoteNumbering', { format: 'upperRoman', start: 1 })
  return true
})
```

### Remove a numbering break

A break is a dashed line with no label. The user clicks it to select it and presses Delete or
Backspace. The two scopes then count on as one, and their collections merge.

### insertNoteNumberingBreak()

Inserts a numbering break at the cursor, after which notes count from the start again.

```js
editor.commands.insertNoteNumberingBreak({
  endnoteNumbering: { format: 'decimal', start: 1 },
})
```

It takes an optional `InsertNumberingBreakOptions` object:

| Option              | Type                   | Default                   | Description                         |
| ------------------- | ---------------------- | ------------------------- | ----------------------------------- |
| `at`                | `number`               | The head of the selection | The position the break goes to      |
| `footnoteNumbering` | `NoteSequence \| null` | `null`                    | How footnotes count after the break |
| `endnoteNumbering`  | `NoteSequence \| null` | `null`                    | How endnotes count after the break  |

Returns `false` inside a note, a collection or its title, and when the schema has no
`footnoteNumberingBreak` node.

## Show the numbers outside the editor

`noteNumbers` returns the number of every note without an editor. `savedJson` stands for the JSON you stored from `getJSON()`:

```js
import { getSchema } from '@tiptap/core'
import { Node } from '@tiptap/pm/model'
import StarterKit from '@tiptap/starter-kit'
import { Footnotes, noteNumbers } from '@tiptap-pro/extension-footnotes'

const doc = Node.fromJSON(getSchema([Footnotes, StarterKit]), savedJson)

const numbers = noteNumbers(doc, {
  sequences: {
    footnote: { format: 'lowerAlpha', start: 1 },
    endnote: { format: 'lowerRoman', start: 1 },
  },
})

numbers.get('fn3') // 'c'
```

The result maps each `footnoteId`, the id that pairs a reference with its note, to its number.
`noteNumbers` does not read the editor's options, so pass the editor's sequences.

The stylesheet draws a number from the `data-tt-footnote-number` attribute, also outside the
editor. [Functions and names](/features/footnotes/api-reference/functions) has the details.

## Numbers in an integration that draws pages

Three options let an integration that shows the document as printed pages take over the numbering.
[Page Layout](/features/page-layout/extension-behavior/footnotes#numbering-on-pages)
sets them, and other editors leave them at their defaults:

| Option      | Default | What it does                                                                                    |
| ----------- | ------- | ----------------------------------------------------------------------------------------------- |
| `counter`   | `null`  | Returns `{ ordinal, format }` per `footnoteId`, in place of the count, sequences and breaks     |
| `scopes`    | `null`  | Returns where numbering scopes end. It places the collections, but breaks still restart numbers |
| `numbering` | `true`  | `false` draws no numbers, so the sequences and `counter` do nothing                             |

Set `counter` and `scopes` together, or neither. [Options](/features/footnotes/api-reference/options) has the types.
