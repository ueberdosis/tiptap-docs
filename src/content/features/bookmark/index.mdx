## Install

1. Set up Tiptap's private registry, as the
   [private registry guide](https://tiptap.dev/docs/guides/pro-extensions) shows. The package
   comes from there, not from npm's registry.
2. Install the extension with its peer dependencies and StarterKit, which the example uses:

```bash
npm install @tiptap-pro/extension-bookmark @tiptap/core @tiptap/pm @tiptap/starter-kit
```

This example builds an editor, puts a bookmark on the first three words, and goes to it by its
name:

```js
import { Editor } from '@tiptap/core'
import StarterKit from '@tiptap/starter-kit'
import { Bookmarks, bookmarkByName, mountBookmarkStyles } from '@tiptap-pro/extension-bookmark'

mountBookmarkStyles(document)

const editor = new Editor({
  element: document.querySelector('#editor'),
  extensions: [StarterKit, Bookmarks.configure({ showBookmarks: true })],
  content: '<p>Invoices are due within 30 days.</p>',
})

// Select "Invoices are due": positions count from 1 at the start of the paragraph
editor.chain().setTextSelection({ from: 1, to: 17 }).addBookmark({ name: 'Payment_terms' }).run()

// Go to it by its name
const bookmark = bookmarkByName(editor.state.doc, 'Payment_terms')
editor.commands.goToBookmark(bookmark.id)
```

When it works, "Invoices are due" has a dashed gray underline and is selected. The underline
comes from `mountBookmarkStyles` and `showBookmarks: true`. Without them, a bookmark is invisible.
The other examples on this page build on this editor.

The package brings no buttons, dialogs or lists. Build them from the
[commands](/features/bookmark#commands) and from the functions in [List the bookmarks](/features/bookmark#list-the-bookmarks), as
the demo does.

## Add a bookmark

`addBookmark` puts a bookmark on the selected text. With nothing selected, it puts a bookmark on
no text, a point at the cursor, which marks a place between two characters.

```js
editor.commands.addBookmark({ name: 'Price' })
```

- **A new name** gives a new bookmark, with a random `id`. Store the `id` to find the bookmark again
  after it is renamed.
- **A name the document already has** moves that bookmark to the selection, as Word does. Its name
  and `id` stay, so links and references to it still find it.
- **No `name`** names the bookmark after the selected words, such as `the_agreed_price`. With no
  words selected, the name is `Bookmark`.

`addBookmark` returns `false` and adds nothing for a name that is not valid. It also returns
`false` where nothing in the selection can hold a bookmark, such as text in a code block. The
[addBookmark() reference](/features/bookmark#addbookmark) lists its options, such as `from` and `to` for another
range.

A bookmark on text may run across several paragraphs, and bookmarks may overlap and nest. Typing
at the end of a bookmark does not make it longer.

### Bookmark names

A bookmark name follows Word's rules, so it survives a round trip through a .docx file. It starts
with a letter, holds only letters, digits and `_`, and has at most 40 characters. Names are
compared without regard to case, so `Terms` and `terms` name the same bookmark.

These functions check and make names, for example for a name field in a bookmark dialog:

```js
import { bookmarkNameFromText, isValidBookmarkName } from '@tiptap-pro/extension-bookmark'

isValidBookmarkName('4th clause') // false, it starts with a digit
bookmarkNameFromText('the agreed price') // 'the_agreed_price'
bookmarkNameFromText('Price', ['price']) // 'Price_2', because 'price' is taken
```

A name that starts with `_` is a hidden name, which Word gives the bookmarks it makes for itself,
such as `_Ref…` behind a cross-reference and `_Toc…` behind a table of contents. Hidden bookmarks
are kept but never shown, and `bookmarksIn` lists them only with `hidden: true`.

`addBookmark` refuses a hidden name unless you pass `hidden: true`, so a name the user types
cannot start with `_`. These functions check and compare names:

| Function               | Arguments                  | Returns                                                                                                 |
| ---------------------- | -------------------------- | ------------------------------------------------------------------------------------------------------- |
| `isValidBookmarkName`  | `name, { hidden }?`        | Whether the name follows the rules. With `hidden: true`, a name may start with `_`                      |
| `bookmarkNameFromText` | `text, taken?`             | A valid name of the words, joined by `_` and numbered when `taken` has it. See the note after the table |
| `isHiddenBookmarkName` | `name`                     | Whether the name starts with `_`                                                                        |
| `sameBookmarkName`     | `a, b`                     | Whether two names are the same without regard to case                                                   |
| `isBookmarkNameFree`   | `state, name, { except }?` | Whether no bookmark has the name. `except` is the `id` of a bookmark that may keep its own              |
| `BOOKMARK_NAME_LIMIT`  |                            | `40`, the longest name                                                                                  |

`bookmarkNameFromText` puts `Bookmark_` in front of words that do not start with a letter, and
returns `Bookmark` for no words.

## Rename or remove a bookmark

`renameBookmark` gives the bookmark at the cursor another name, and `removeBookmark` takes the
bookmark away and leaves its text. Without an `id`, both commands take the smallest bookmark
around the selection, the innermost one where bookmarks nest:

```js
editor.commands.renameBookmark('Cost')
editor.commands.removeBookmark()

// Another bookmark, by its id
editor.commands.renameBookmark('Cost', id)
editor.commands.removeBookmark(id)
```

Renaming keeps the bookmark's `id`, so references by `id` still find it. Links go by name, so a
link to the old name no longer finds the bookmark. A name another bookmark has is refused, but a
change of case only, such as `Price` to `price`, is allowed.

## Go to a bookmark

`goToBookmark` selects a bookmark and scrolls it into view. It takes the bookmark's `id`, which
`bookmarkByName` finds from a name:

```js
const { id } = bookmarkByName(editor.state.doc, 'Payment_terms')
editor.commands.goToBookmark(id)
```

Most editors need nothing more. An editor that scrolls to a position its own way, for example
because it renders only part of a long document, passes `reveal`. `goToBookmark` and a followed
link then call `reveal` instead, and select nothing themselves.

`reveal` gets the bookmark as [List the bookmarks](/features/bookmark#list-the-bookmarks) describes it, and returns
whether it went there:

```js
Bookmarks.configure({
  reveal: bookmark => myScrollTo(bookmark.from),
})
```

`myScrollTo` stands for your own function that shows a document position.

## Link to a bookmark

A link whose `href` is `#` and a bookmark name points at that bookmark, and a click on it goes
there. `bookmarkHref` makes the `href`. Insert the link with the `setLink` command of Tiptap's
Link extension, which StarterKit includes:

```js
import { bookmarkHref } from '@tiptap-pro/extension-bookmark'

editor
  .chain()
  .setLink({ href: bookmarkHref('Payment_terms') }) // href '#Payment_terms'
  .run()
```

A click on such a link goes to the bookmark in an editable editor too. The name in the `href` is
compared without regard to case.

- **A link to a name no bookmark has,** and every other link, is left to the Link extension and
  any other click handler.
- **`followLinks: false`** leaves all links alone, so a click on `#name` does not go anywhere.
- **`bookmarkNameOfHref(href)`** reads the name back out of an `href`, or returns `null` when the
  `href` is not `#` and a name.

## Show bookmarks

Shown bookmarks are Word's _Show bookmarks_: the text of each bookmark gets a dashed underline,
and a thin bar marks a bookmark on no text. Hidden bookmarks stay hidden. The underline and the
bar need the package's styles, which `mountBookmarkStyles` adds to the page once:

```js
import { mountBookmarkStyles } from '@tiptap-pro/extension-bookmark'

mountBookmarkStyles(document)

Bookmarks.configure({ showBookmarks: true }) // shown from the start
editor.commands.toggleBookmarkVisibility() // switch
editor.commands.toggleBookmarkVisibility(false) // hide
```

Showing bookmarks writes nothing to the document, and no line wraps differently while they are
shown. `areBookmarksShown(editor.state)` says whether they are shown.

These custom properties change the look:

| Property              | Default   | Changes                                    |
| --------------------- | --------- | ------------------------------------------ |
| `--tt-bookmark-color` | `#8a8a8a` | The color of the underline and the bar     |
| `--tt-bookmark-line`  | `dashed`  | The underline, any `text-decoration-style` |

The underlined text has the class `tiptap-bookmark-shown` and the bookmark's name as its `title`.
The bar is `tiptap-bookmark-point-marker`.

### Styles under a Content Security Policy

`mountBookmarkStyles` adds a `style` element to the head of the web page, and does nothing when
an element with its `id` is there already. Under a Content Security Policy, pass it the same nonce
as Tiptap's `injectNonce` editor option:

```js
mountBookmarkStyles(document, { nonce })
```

| Option  | Type     | Default                    | Description                                    |
| ------- | -------- | -------------------------- | ---------------------------------------------- |
| `id`    | `string` | `'tiptap-bookmark-styles'` | The id of the `style` element                  |
| `nonce` | `string` | None                       | The nonce the Content Security Policy asks for |

When the policy allows no `style` element at all, `bookmarkStyleRules()` returns the same rules
as a string. Save them in a stylesheet of your own and load it instead.

## List the bookmarks

`bookmarksIn` returns the bookmarks of a document, for example to fill a bookmark panel or the
list of a "go to" dialog. The other functions find one bookmark:

```js
import {
  bookmarkAround,
  bookmarkById,
  bookmarkByName,
  bookmarksIn,
} from '@tiptap-pro/extension-bookmark'

bookmarksIn(editor.state.doc) // in the order they begin
bookmarksIn(editor.state.doc, { sort: 'name' }) // by name, as Word's dialog sorts them
bookmarksIn(editor.state.doc, { hidden: true }) // with the hidden ones
bookmarkByName(editor.state.doc, 'price') // without regard to case
bookmarkById(editor.state.doc, id)
bookmarkAround(editor.state.doc, from, to) // the smallest one around a range
```

`bookmarkById`, `bookmarkByName` and `bookmarkAround` return `null` when no bookmark matches.
`bookmarkAround` with an empty range, such as a cursor, also finds a bookmark on no text right
beside it. Each bookmark they return has these fields:

| Field    | Type      | Description                                   |
| -------- | --------- | --------------------------------------------- |
| `id`     | `string`  | The bookmark's id                             |
| `name`   | `string`  | Its name                                      |
| `hidden` | `boolean` | Whether the name starts with `_`              |
| `from`   | `number`  | The document position where it begins         |
| `to`     | `number`  | Where it ends. The same as `from` for a point |
| `point`  | `boolean` | Whether it is a bookmark on no text           |

A bookmark across several paragraphs is one entry, from the first position it covers to the last.

`bookmarksInBlock(block, blockPos)` returns the bookmarks that begin in one top-level block, a
direct child of the document, at
their positions in the document. It is for code that reads the document block by block, such as a
[cross-reference source](/features/bookmark#refer-to-a-bookmark).

## Copy and paste

A bookmark name belongs to one bookmark, so a paste never adds a second bookmark of a name:

- **Pasting text whose bookmark the document already has,** by `id` or by name, pastes the text
  without the bookmark. The bookmark in the document stays where it is.
- **Cutting and pasting text** moves its bookmark, and so does dragging the text to another place.
- **Text copied in Word** keeps its bookmarks under their names, hidden ones included. Each
  arrives as a bookmark on no text where it began, because Word's clipboard does not say where a
  bookmark ends.
- **A paste as plain text** has no bookmarks.

## Refer to a bookmark

A cross-reference is text such as "see Payment terms" that points at a place in the document and
stays right when the document changes. The
[cross-references extension](/features/cross-references) adds them, and
reads bookmarks through a source, a function you register.
[Sources](/features/cross-references/sources#inside-the-document) shows the source
for bookmarks. Neither package depends on the other.

## Word documents

A .docx file holds a bookmark as a name between a `w:bookmarkStart` and a `w:bookmarkEnd`
element. Tiptap's own .docx import and export do not carry this package's bookmarks yet, as
[Limitations](/features/bookmark#limitations) says. If you convert .docx files with code of your own, two functions
read and write that shape:

```js
import { addImportedBookmarksTransaction, bookmarkRangesIn } from '@tiptap-pro/extension-bookmark'

// Export: every bookmark, hidden ones included, as { name, from, to }
const ranges = bookmarkRangesIn(editor.state.doc)

// Import: ranges your converter read out of a file, at positions of the editor's document
const transaction = addImportedBookmarksTransaction(editor.state, rangesFromTheFile)
if (transaction) editor.view.dispatch(transaction)
```

`rangesFromTheFile` stands for the `{ name, from, to }` ranges your converter found.
`addImportedBookmarksTransaction` keeps Word's hidden names, and an empty range becomes a
bookmark on no text. It returns `null` when it could add none. It skips:

- a name the document already has,
- a name that does not follow the [name rules](/features/bookmark#bookmark-names),
- a range in which nothing can hold a bookmark, such as one in a code block,
- the second of two ranges with the same name.

## Leave copied content out

Most editors do not need this. It is for an editor that holds copies of content that stands
elsewhere in the document, such as a table header row repeated on every page. A bookmark in such
a copy is not a bookmark of its own, so the copy has to be left out.

The `ignore` option is a function that gets a node and returns one of these:

- **`true`** skips the node with everything in it.
- **`'descend'`** reads only what is inside the node.
- **`false`** reads the node as usual.

Pass `ignore` once to the extension, and the commands and the shown bookmarks use it. In this
example, the copies are nodes with an `isCopy` attribute:

```js
Bookmarks.configure({ ignore: node => node.attrs.isCopy === true })
```

Every function in [List the bookmarks](/features/bookmark#list-the-bookmarks) takes the same `ignore` in its
options.

With [Page Layout](/features/page-layout/getting-started/overview), pass `ignoreLayoutArtifacts` from
`@tiptap-pro/extension-page-layout` as `ignore`.
[Bookmarks in Page Layout](/features/page-layout/extension-behavior#bookmarks)
says what else changes on pages.

## What is stored

`Bookmarks` adds a mark and a node to the schema. A mark is a property of a run of text, like
bold, and a node is an element of its own in the document. The bookmark node is an inline atom
node: it sits in a line of text, has no content, and is moved and deleted as one piece.

| Type            | Kind             | For                   | HTML                                                                                                     |
| --------------- | ---------------- | --------------------- | -------------------------------------------------------------------------------------------------------- |
| `bookmark`      | Mark             | A bookmark on text    | `<span class="tiptap-bookmark" data-tt-bookmark="id" data-tt-bookmark-name="name">` around the text      |
| `bookmarkPoint` | Inline atom node | A bookmark on no text | An empty `<span class="tiptap-bookmark-point" data-tt-bookmark-point="id" data-tt-bookmark-name="name">` |

The mark and the node store an `id`, which stays the same when the bookmark is renamed or moved,
and a `name`, which the user sees and a .docx file stores.

A bookmark across several paragraphs is the `bookmark` mark with the same `id` on each run of
text. In the JSON of `editor.getJSON()`, the mark and the node look like this:

```json
[
  {
    "type": "text",
    "text": "Invoices are due",
    "marks": [{ "type": "bookmark", "attrs": { "id": "bm4k2x9q1z", "name": "Payment_terms" } }]
  },
  { "type": "bookmarkPoint", "attrs": { "id": "bm7c0d3e5f", "name": "Signature" } }
]
```

A bookmark adds no text: `editor.getText()` and a copy as plain text are the same with or without
one. Whether bookmarks are shown is a setting of the editor and is not stored.

`Bookmark` and `BookmarkPoint` are the mark and the node on their own, for a schema that needs them
without the commands. `BOOKMARK_MARK_NAME` and `BOOKMARK_POINT_NODE_NAME` are their names.

## Options

`Bookmarks.configure()` takes these options:

| Option          | Type                                       | Default | Description                                                                      |
| --------------- | ------------------------------------------ | ------- | -------------------------------------------------------------------------------- |
| `showBookmarks` | `boolean`                                  | `false` | Whether bookmarks are [shown](/features/bookmark#show-bookmarks) from the start                    |
| `followLinks`   | `boolean`                                  | `true`  | Whether a click on a [link to `#name`](/features/bookmark#link-to-a-bookmark) goes to the bookmark |
| `ignore`        | `((node) => boolean \| 'descend') \| null` | `null`  | Which nodes to [leave out](/features/bookmark#leave-copied-content-out)                            |
| `reveal`        | `((bookmark) => boolean) \| null`          | `null`  | How to [go to a bookmark](/features/bookmark#go-to-a-bookmark) your own way                        |

## Commands

Every command except `toggleBookmarkVisibility` returns `false` and changes nothing when it cannot
act, so `editor.can()` tells a toolbar when to disable a button:

```js
const canRemove = editor.can().removeBookmark()
```

### addBookmark()

Adds a bookmark on the selection, or a bookmark on no text where the selection is empty. See
[Add a bookmark](/features/bookmark#add-a-bookmark). Its options:

| Option   | Type      | Default                    | Description                                                  |
| -------- | --------- | -------------------------- | ------------------------------------------------------------ |
| `name`   | `string`  | The selected words         | A [name](/features/bookmark#bookmark-names). A name in use moves that bookmark |
| `hidden` | `boolean` | `false`                    | Whether the name may start with `_`                          |
| `from`   | `number`  | The start of the selection | Where the bookmark begins                                    |
| `to`     | `number`  | The end of the selection   | Where it ends. The same as `from` for a bookmark on no text  |

Returns `false` for a name that is not valid, and where nothing in the range can hold a bookmark,
such as text in a code block or a horizontal rule.

### removeBookmark()

Removes a bookmark and leaves its text. See [Rename or remove](/features/bookmark#rename-or-remove-a-bookmark).

Takes an optional `id`. Without it, the command removes the smallest bookmark around the selection.

Returns `false` where there is no such bookmark.

### renameBookmark()

Gives a bookmark another name and keeps its `id`. See
[Rename or remove](/features/bookmark#rename-or-remove-a-bookmark). Its arguments:

| Argument | Type     | Description                                                 |
| -------- | -------- | ----------------------------------------------------------- |
| `name`   | `string` | The new name                                                |
| `id`     | `string` | The bookmark. Default the smallest one around the selection |

Returns `false` where there is no such bookmark, for a name that is not valid, for exactly the
current name, and for a name another bookmark has.

### goToBookmark()

Selects a bookmark and scrolls it into view, or calls `reveal` where the extension has one. See
[Go to a bookmark](/features/bookmark#go-to-a-bookmark).

Takes the bookmark's `id`.

Returns `false` where no bookmark has that `id`, and where `reveal` returns `false`.

### toggleBookmarkVisibility()

Shows or hides the bookmarks, and writes nothing to the document. See
[Show bookmarks](/features/bookmark#show-bookmarks).

Takes an optional `visible`, `true` to show and `false` to hide. Without it, the command switches.

Always returns `true`.

## Write without a command

Each command except `toggleBookmarkVisibility` has a function that returns the transaction
instead of dispatching it, or `null` where the command returns `false`. Use it to change an
editor state that no editor shows, or to add steps of your own to the same transaction before you
dispatch it:

```js
import { addBookmarkTransaction } from '@tiptap-pro/extension-bookmark'

const transaction = addBookmarkTransaction(editor.state, { name: 'Price' })
if (transaction) {
  transaction.insertText(' (see the price list)', transaction.selection.to)
  editor.view.dispatch(transaction)
}
```

| Command          | Function                    | Arguments                   |
| ---------------- | --------------------------- | --------------------------- |
| `addBookmark`    | `addBookmarkTransaction`    | `state, options?`           |
| `removeBookmark` | `removeBookmarkTransaction` | `state, id, options?`       |
| `renameBookmark` | `renameBookmarkTransaction` | `state, id, name, options?` |
| `goToBookmark`   | `goToBookmarkTransaction`   | `state, id, options?`       |

Every `options` takes [`ignore`](/features/bookmark#leave-copied-content-out). `addBookmarkTransaction` also takes
the options of [addBookmark()](/features/bookmark#addbookmark), and `renameBookmarkTransaction` takes `hidden` for a
hidden name. The functions need an `id`, which `bookmarkAround` finds for the selection.
`goToBookmarkTransaction` sets the selection and scrolls, and does not call `reveal`.

## Limitations

Bookmarks do not yet survive Tiptap's own .docx conversion, and a paste keeps less than the
original.

### Tiptap's .docx import and export keep only where a bookmark begins

Tiptap's .docx import and export use a `bookmark` node of their own, from
`@tiptap-pro/extension-convert-kit`, not this package's bookmarks. An import puts that node where
a bookmark of the file begins. The text stays, but which text the bookmark covered is lost. To
keep bookmarks with your own converter, see [Word documents](/features/bookmark#word-documents).

### ConvertKit and Bookmarks in one editor

`ConvertKit` brings a node named `bookmark`, the name of this package's mark, and a schema cannot
have a node and a mark of one name. In an editor with `Bookmarks`, turn off ConvertKit's node:

```js
import { Bookmarks } from '@tiptap-pro/extension-bookmark'
import { ConvertKit } from '@tiptap-pro/extension-convert-kit'

const extensions = [ConvertKit.configure({ bookmark: false }), Bookmarks]
```

### A paste from Word keeps only where a bookmark begins

Each bookmark pasted from Word arrives as a bookmark on no text where it began. See
[Copy and paste](/features/bookmark#copy-and-paste).
