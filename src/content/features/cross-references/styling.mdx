A reference is the inline node `crossReference`, which reads the number, title or page of its
targets, such as headings. Attributes on its element say what it shows and what is wrong with it.

## The stylesheet

`mountCrossReferenceStyles` adds the stylesheet to `document.head`. A second call does nothing,
so each editor you create may call it:

```js
import { mountCrossReferenceStyles } from '@tiptap-pro/extension-cross-references'

mountCrossReferenceStyles(document)
```

[Install Cross-references](/features/cross-references/install#a-first-editor) has the complete editor around it. The
function takes these options as its second argument:

| Option  | Type     | Default                            | Description                                                            |
| ------- | -------- | ---------------------------------- | ---------------------------------------------------------------------- |
| `id`    | `string` | `'tiptap-cross-references-styles'` | The `id` of the `style` element, which keeps it from being added twice |
| `nonce` | `string` | None                               | The `nonce` of the `style` element, for a Content Security Policy      |

Under a Content Security Policy, pass the same nonce you give the editor's `injectNonce` option.

The stylesheet is optional. Without it, references still work and look like the text around
them, and a reference with nothing to show still reads `?`.

To load the rules from a stylesheet of your own instead, `crossReferenceStyleRules()` returns
them as a CSS string. The rules select references by their attributes, not under `.tiptap`. So
they also apply to HTML you rendered from `getHTML()` outside the editor.

Besides the colors, the stylesheet sets `[data-tt-cross-reference-format="superscript"]` in
superscript, for the `formattedNumber` display.

## Custom properties

These custom properties change the colors of the stylesheet:

| Property                                | Default   | Colors                                  |
| --------------------------------------- | --------- | --------------------------------------- |
| `--tt-cross-reference-color`            | `inherit` | Every reference                         |
| `--tt-cross-reference-unresolved-color` | `#b42318` | A reference with nothing to show        |
| `--tt-cross-reference-stale-color`      | `#b54708` | The wavy underline of a stale reference |

This makes every reference blue:

```css
.tiptap {
  --tt-cross-reference-color: #175cd3;
}
```

## The element of a reference

A reference is a `span` with the class `tiptap-cross-reference`, also in the HTML of `getHTML()`.
When HTML is parsed, any `span` with `data-tt-cross-reference` becomes a reference.

An empty reference shows text the editor draws, in a `span` with `data-tt-cross-reference-text`.
That `span` is not editable and not part of the document. A reference that shows text of its own
has none.

These attributes are part of the document, so they are written to HTML and read back from it:

| Attribute                  | When it is set                                                     | What it holds                             |
| -------------------------- | ------------------------------------------------------------------ | ----------------------------------------- |
| `data-tt-cross-reference`  | Always                                                             | The target ids, separated by spaces       |
| `data-tt-show`             | Always                                                             | What the reference shows, such as `title` |
| `data-tt-hyperlink`        | The reference is not followed on a click                           | `false`                                   |
| `data-tt-above-below`      | `above` or `below` follows the text                                | `true`                                    |
| `data-tt-number-separator` | The reference has a number separator                               | The separator, such as `-`                |
| `data-tt-join`             | The reference has its own rule for several targets                 | The rule, such as `range`                 |
| `data-tt-locked`           | The reference is locked                                            | `true`                                    |
| `data-tt-field-switches`   | It came from a Word field with switches the extension does not use | The switches, see [Word fields](/features/cross-references/docx)  |

The editor adds these attributes while it shows the document, and they are not written to HTML:

| Attribute                             | When it is set                               | What it holds                                                                      |
| ------------------------------------- | -------------------------------------------- | ---------------------------------------------------------------------------------- |
| `data-tt-cross-reference-label`       | Always                                       | What the targets say, such as `4.2`, also when the reference shows text of its own |
| `data-tt-cross-reference-fixed`       | The reference shows text of its own          | `true`                                                                             |
| `data-tt-cross-reference-stale`       | Its own text is not what its targets say     | `true`                                                                             |
| `data-tt-cross-reference-hidden-text` | Its own text is hidden                       | `true`                                                                             |
| `data-tt-cross-reference-unresolved`  | It has nothing to show                       | Why, see [Unresolved references](/features/cross-references/styling#unresolved-references)                           |
| `data-tt-cross-reference-format`      | The display prints the text in a special way | `superscript`, or the `format` of your own display                                 |
| `title`                               | It is unresolved or stale                    | The tooltip, see [Tooltips](/features/cross-references/styling#tooltips)                                             |

Own text is hidden with the `holdsText: false` option and on a reference to a withheld target.
Such a reference has no `data-tt-cross-reference-fixed`.

## Unresolved references

An unresolved reference has nothing to show, and it reads `?`. The stylesheet colors it by its
`data-tt-cross-reference-unresolved` attribute, whose value says what is missing:

| Value      | What is missing                                                                                                    |
| ---------- | ------------------------------------------------------------------------------------------------------------------ |
| `target`   | No target has the id, such as a deleted target. An undo that brings the target back makes the reference read again |
| `number`   | The target has no number, or `show` names a display nobody registered                                              |
| `page`     | Nothing answers which page the target is on                                                                        |
| `withheld` | The target is withheld. The reference reads `[withheld]`                                                           |

A reference that shows text of its own is not marked unresolved when its target is gone. It is
marked stale instead.

## Stale references

A stale reference holds text of its own that is no longer what its targets say. The user may
have typed into it, or it stored its text before the target was renumbered.

The stylesheet draws `data-tt-cross-reference-stale="true"` as a wavy underline.
[Updating references](/features/cross-references/references#updating-references) says how to give the reference back to
its targets.

## Tooltips

An unresolved or stale reference gets a tooltip, its `title` attribute, so the user learns what
is wrong. The texts come from the `phrases` option, see [Phrases](/features/cross-references/displays#phrases).

## While references can be followed

While the `reveal` option or a source's own `reveal` is set, a click can take the user to a
reference's target, see [Going to the target](/features/cross-references/references#going-to-the-target). The editor
element then has the class `tiptap-cross-references-clickable`, which can show that references
are clickable:

```css
.tiptap.tiptap-cross-references-clickable [data-tt-cross-reference] {
  cursor: pointer;
}
```
