A target is the place a reference points at: a node of a type you register, such as a heading, or a
target of a [source](/features/cross-references/sources).

## Inserting a reference

`insertCrossReference()` inserts a reference at the selection. It takes the target by its id, or by
the position where the target node starts. In this example, `pos` is the position of a heading:

```js
editor.commands.insertCrossReference({ target: pos, show: 'fullNumber' })

editor.commands.insertCrossReference({ target: 'scope-of-work', show: 'page', aboveBelow: true })
```

The first call reads the heading's full number, such as `3(a)`. The second reads the page of the
target `scope-of-work`, such as `7 below`. The editor is the one of
[Install Cross-references](/features/cross-references/install#a-first-editor).

`show` picks the display, which is what the reference reads of its target, see
[What a reference shows](/features/cross-references/displays).

A target named by position that has no id gets one in the
same step, see [How a target gets its id](/features/cross-references/targets#how-a-target-gets-its-id). With
`multiple: true`, a reference may name several targets, see
[Several targets in one reference](/features/cross-references/joins).

## What a reference stores

A reference is the inline node `crossReference`, with these attributes:

| Attribute         | Type             | Default        | Description                                                                     |
| ----------------- | ---------------- | -------------- | ------------------------------------------------------------------------------- |
| `targetIds`       | `string[]`       | `[]`           | The ids of its targets, in order                                                |
| `show`            | `string`         | `'fullNumber'` | What it reads of its targets                                                    |
| `hyperlink`       | `boolean`        | `true`         | Whether a click can lead to the target                                          |
| `aboveBelow`      | `boolean`        | `false`        | Whether `above` or `below` follows, as in `4.2 below`                           |
| `numberSeparator` | `string \| null` | `null`         | Replaces the punctuation in a number, so `-` reads `3(b)(ii)` as `3-b-ii`       |
| `join`            | `string \| null` | `null`         | How it reads several targets. `null` or an unknown rule means the `join` option |
| `locked`          | `boolean`        | `false`        | Whether an update leaves it alone                                               |
| `fieldSwitches`   | `string \| null` | `null`         | Switches of a Word field, kept for the export. See [Word fields](/features/cross-references/docx)       |

Its HTML is on [The element of a reference](/features/cross-references/styling#the-element-of-a-reference). JSON with the
older single `targetId` attribute still opens.

`setCrossReferenceOptions()` changes these choices on the reference at the cursor. A choice you
leave out stays as it is. Text the reference holds is kept until it is
[reset](/features/cross-references/references#resetting-a-reference):

```js
editor.commands.setCrossReferenceOptions({ show: 'title' })
```

## Editing a reference

An empty reference reads its targets. Once the user writes into it, it shows that text instead. So
the user can turn `4.2` into `clause 4.2`, and the reference still points at its target.

### Moving the caret

The caret moves through a reference like through a field in a word processor. Left, Right, Home and
End stop at its inner start and end, and Up and Down move between its lines. A click on its edge
puts the caret at the nearer inner edge.

Where the browser draws no caret, such as inside an empty reference, the extension draws a `div` with
`data-tt-cross-reference-caret` while the editor has focus.

### Typing and deleting

Keys that change text keep a reference in one piece:

- **Typing in an empty reference** stores the text it shows, with the new character at the caret.
  Typing right beside a reference writes beside it.
- **Backspace right after a reference, or Delete right in front of one,** selects it. A second press
  removes it.
- **Backspace or Delete at its inner edge** does nothing, so the reference is not joined with the
  text beside it.

A reference cannot be dragged, so it stays in its sentence. A paste over its text stays inside it.
[`removeCrossReference()`](/features/cross-references/commands#removecrossreference) takes the reference at the cursor out.

### Stale references

A reference whose own text is no longer what its targets say is stale, also when its target is
deleted. It gets a wavy underline, see [Styling](/features/cross-references/styling#stale-references), until it is
[reset](/features/cross-references/references#resetting-a-reference).

## References that hold no text

Set `holdsText: false` when a reference should hold no text the user wrote:

```js
CrossReferences.configure({ targets: { heading: {} }, holdsText: false })
```

Typing, deleting, pasting and dropping inside a reference then do nothing. Because nothing stores
what a reference reads, `update: 'manual'` behaves as `'live'`. `setCrossReferenceUpdate('manual')`,
`updateCrossReferences()` and both commands that convert to text return `false`.

A reference that already holds text, from older content, reads its targets anyway. Its text stays in
the document, hidden, until `resetCrossReference()` removes it.

## Updating references

The `update` option says when a reference follows its targets:

| `update`           | What a reference does                                                                                                   |
| ------------------ | ----------------------------------------------------------------------------------------------------------------------- |
| `'live'` (default) | An empty reference follows its targets, so a new heading renumbers every reference after it                             |
| `'manual'`         | A reference stores what its targets say when it is inserted, and keeps it until an update, as Word's fields do until F9 |

```js
CrossReferences.configure({ targets: { heading: {} }, update: 'manual' })
```

An update writes what the targets say now into the references, keeping their marks. F9 runs it, and
so does `updateCrossReferences()`. In `'live'` mode it writes into references the user wrote into,
in `'manual'` mode into every reference. Where a target is gone, it writes `?`.

The `updateKey` option changes the key, and `null` sets none.

An update skips locked references and references to a
[withheld target](/features/cross-references/targets#withheld-targets), one a reference may point at without saying anything
about it. Nothing else writes into a reference, so two people editing one document do not overwrite
each other's references.

### Switching the mode while the editor runs

`setCrossReferenceUpdate()` switches between `'live'` and `'manual'`:

```js
editor.commands.setCrossReferenceUpdate('manual')
```

The mode belongs to the editor, in `editor.storage.crossReferences.update`. It is not undone, not
sent to other users, and an editor created again starts with the configured `update`.

The switch writes into no reference. So a reference that is empty at the switch to `'manual'` reads
its targets until it is reset or updated.

### Resetting a reference

`resetCrossReference()` gives the reference at the cursor back to its targets, also when it is
locked. In `'live'` mode, it removes the reference's own text. In `'manual'` mode, it writes what the
targets say now, keeping the marks.

```js
editor.commands.resetCrossReference()
```

### Locking a reference

`setCrossReferenceLocked(true)` locks the reference at the cursor, so an update leaves it alone. The
lock does nothing else: a locked reference is still edited, reset, removed and converted to text.

```js
editor.commands.setCrossReferenceLocked(true)
```

## Converting a reference to text

`convertCrossReferenceToText()` replaces the reference at the cursor by the words it reads, as plain
text that follows nothing. `convertCrossReferencesToText()` converts every reference:

```js
editor.commands.convertCrossReferencesToText()
```

What a reference becomes depends on what it holds:

- **Text of its own** becomes that text with its marks, also when the target is gone.
- **An empty reference** becomes what its targets say, with the reference's marks.
- **An empty reference that cannot read its target,** because the target, a number or a page is
  missing, stays a reference, so nothing turns into a `?`.
- **A reference to a withheld target** stays a reference.

Locked references are converted like any other.

## Going to the target

The `reveal` option makes a Cmd/Ctrl+click on a reference lead to its first target.
`goToCrossReferenceTarget()` puts the caret at the start of the target's text and scrolls to it:

```js
CrossReferences.configure({
  targets: { heading: {} },
  reveal: ({ targetId }) => {
    editor.view.focus()
    return editor.commands.goToCrossReferenceTarget(targetId)
  },
})
```

The command does not focus the editor, so the example does, and the user sees the caret. `reveal`
returns `true` to stop the click, or `false` to let the editor place the caret. It receives one
object:

| Field      | Type             | Description                                                             |
| ---------- | ---------------- | ----------------------------------------------------------------------- |
| `targetId` | `string`         | The id as the reference stores it, `source:id` for a target of a source |
| `source`   | `string \| null` | The source of the target, or `null` for a node target                   |
| `id`       | `string`         | The id within that source, or `targetId` for a node target              |
| `pos`      | `number`         | The position of the clicked reference                                   |
| `event`    | `MouseEvent`     | The click                                                               |

A plain click places the caret, so the user can still edit.

With `follow: 'click'`, any click
follows, for an editor where nobody edits. A reference with `hyperlink: false`, a withheld target or
no target is not followed. A source with a `reveal` of its own is asked first, see
[Following a reference](/features/cross-references/sources#following-a-reference).

`goToCrossReferenceTarget()` also goes to a source's target inside the document, such as a bookmark,
and returns `false` for one outside it. It does not check whether a target is withheld.

With [Page Layout](/features/page-layout/getting-started/overview), a reference is followed without
`reveal`, see
[Going to a target on another page](/features/page-layout/extension-behavior/cross-references#going-to-a-target-on-another-page).

## Copy and paste

A reference pasted into another program is its text, such as `see 1.2`. Pasted into an editor with
`CrossReferences`, it is a reference again.

A reference that was empty reads whatever its target
says there, and one with text of its own keeps that text. A cross-reference pasted from Word is plain
text, see [Limitations](/features/cross-references/limitations).
