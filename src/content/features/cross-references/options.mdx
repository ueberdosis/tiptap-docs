A target is a node a reference points at, such as a heading.
A reference is the inline node that points at it and reads its number, title or page.

You pass the options to `CrossReferences.configure()`. Most editors set only `targets`. This
editor of [Install Cross-references](/features/cross-references/install#a-first-editor) also allows several targets per
reference, updates references by hand and makes a Cmd/Ctrl+click lead to the target:

```js
CrossReferences.configure({
  targets: { heading: {} },
  multiple: true,
  update: 'manual',
  reveal: ({ targetId }) => {
    editor.view.focus()
    return editor.commands.goToCrossReferenceTarget(targetId)
  },
})
```

## All options

The options fall into four groups, one table each.

### Targets

| Option              | Type                           | Default              | Description                                                                                                                             |
| ------------------- | ------------------------------ | -------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| `targets`           | `CrossReferenceTargets`        | `{}`                 | The node types that are targets, by name. See [Registering targets](/features/cross-references/targets#registering-targets)                                     |
| `sources`           | `CrossReferenceSources`        | `{}`                 | Targets that are not node types, such as bookmarks. See [Sources](/features/cross-references/sources)                                                           |
| `idAttribute`       | `string`                       | `'crossReferenceId'` | The attribute a target's id is kept in. See [Using an id another extension defines](/features/cross-references/targets#using-an-id-another-extension-defines)   |
| `defineIdAttribute` | `boolean`                      | `true`               | Whether the extension adds `idAttribute` to the target types. See [defineIdAttribute](/features/cross-references/options#defineidattribute)                               |
| `repair`            | `boolean`                      | `true`               | Whether this editor gives a copied target a new id, so each id names one target. See [One id, one target](/features/cross-references/targets#one-id-one-target) |
| `ignore`            | `CrossReferenceIgnore \| null` | `null`               | A function that leaves nodes out of the targets. See [Leaving nodes out](/features/cross-references/targets#leaving-nodes-out)                                  |

### What a reference reads

| Option     | Type                             | Default  | Description                                                                                                                                     |
| ---------- | -------------------------------- | -------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| `displays` | `CrossReferenceDisplays`         | `{}`     | Values of `show` of your own. See [Displays of your own](/features/cross-references/displays#displays-of-your-own)                                                      |
| `phrases`  | `Partial<CrossReferencePhrases>` | `{}`     | The words a reference reads that do not come from its target, such as `above` and `?`. See [Phrases](/features/cross-references/displays#phrases)                       |
| `pageOf`   | `CrossReferencePageOf \| null`   | `null`   | The page a target is on, where there are pages. See [pageOf](/features/cross-references/options#pageof)                                                                           |
| `multiple` | `boolean`                        | `false`  | Whether a reference may name several targets. See [Letting a reference name several targets](/features/cross-references/joins#letting-a-reference-name-several-targets) |
| `joins`    | `CrossReferenceJoins`            | `{}`     | Rules of your own for reading several targets. See [A rule of your own](/features/cross-references/joins#a-rule-of-your-own)                                            |
| `join`     | `string`                         | `'list'` | The rule a reference without one of its own reads several targets by. See [Choosing the rule](/features/cross-references/joins#choosing-the-rule)                       |

### Editing and updating

| Option      | Type                 | Default  | Description                                                                                                                      |
| ----------- | -------------------- | -------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `update`    | `'live' \| 'manual'` | `'live'` | When a reference follows its targets. See [Updating references](/features/cross-references/references#updating-references)                               |
| `updateKey` | `string \| null`     | `'F9'`   | The key that updates every reference, or `null` for none. See [updateKey](/features/cross-references/options#updatekey)                                            |
| `holdsText` | `boolean`            | `true`   | Whether a reference may hold text the user wrote. See [References that hold no text](/features/cross-references/references#references-that-hold-no-text) |

### Following a reference

| Option   | Type                                  | Default      | Description                                                                                                                 |
| -------- | ------------------------------------- | ------------ | --------------------------------------------------------------------------------------------------------------------------- |
| `reveal` | `CrossReferenceRevealHandler \| null` | `null`       | Called when the user follows a reference. See [Going to the target](/features/cross-references/references#going-to-the-target)                      |
| `follow` | `'modifier' \| 'click'`               | `'modifier'` | Which click follows a reference: Cmd/Ctrl+click, or any click. See [Going to the target](/features/cross-references/references#going-to-the-target) |

## defineIdAttribute

Set it to `false` when another extension already defines the id attribute on the target types, such
as a table of contents that puts an `id` on headings. That extension then decides how the id is
written to HTML and when a target gets one.

With `false`, no target gets an id when it is first referred to, and the check that keeps each id
on one target does not run, whatever `repair` says. With `true`, the attribute is added only to
registered types without an `idAttribute` of their own.

## pageOf

A function `({ node, pos, doc }) => string | null` that returns the page a target is on, as the page
shows it. `node` is `null` for a range of a source. Without it, `show: 'page'` reads `?`.
[Page Layout](/features/page-layout/getting-started/overview) passes one, and
[The page of a target](/features/cross-references/displays#the-page-of-a-target) explains what a reference reads with it.

## updateKey

A Tiptap keyboard shortcut that runs `updateCrossReferences()`, so it takes any key name a shortcut
takes. The default `'F9'` is the key Word updates its fields with.

## The registration in the editor's storage

`editor.storage.crossReferences` holds the options as the registration, which the functions that
read the document take, see [The registration](/features/cross-references/reading#the-registration).

When the editor is created, it warns in the console about a registered type the schema does not
have, and about one without its id attribute. Neither can be referred to.
