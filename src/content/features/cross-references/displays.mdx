## Choosing a display

A reference, the inline node `crossReference`, keeps the id of its display in its `show`
attribute, Word's "Insert reference to". You set `show` on insert and change it with
`setCrossReferenceOptions`. Here `'late-payment'` is the id of a heading that is a target:

```js
editor.commands.insertCrossReference({ target: 'late-payment', show: 'title' })

// Changes the reference at the cursor
editor.commands.setCrossReferenceOptions({ show: 'page' })
```

A reference without `show`, or with an empty `show` in HTML, reads `fullNumber`. The examples on
this page build on the editor of [Install Cross-references](/features/cross-references/install#a-first-editor).

## The built-in displays

Each display has an id, which `show` stores, and a title for a [picker](/features/cross-references/picker), the menu
you build to insert a reference. The examples are for item `(b)` of clause 3, "Late payment",
on page 7:

| `show`            | Picker title          | Reads                                                            | Example         |
| ----------------- | --------------------- | ---------------------------------------------------------------- | --------------- |
| `relativeNumber`  | Number                | The number, with the context it needs where the reference stands | `(b)` or `3(b)` |
| `number`          | Number (no context)   | The number as the target shows it                                | `(b)`           |
| `fullNumber`      | Number (full context) | The number with all of its context. The default                  | `3(b)`          |
| `title`           | Text                  | The target's title                                               | `Late payment`  |
| `page`            | Page number           | The target's page, from [`pageOf`](/features/cross-references/displays#the-page-of-a-target)        | `7`             |
| `aboveBelow`      | Above/below           | The `above` or `below` phrase, by where the target stands        | `below`         |
| `formattedNumber` | Number (formatted)    | The number, raised like a footnote's mark                        | `²`             |

A reference with nothing to show reads `?`. These pages call it unresolved, and
[Styling](/features/cross-references/styling#unresolved-references) lists the attribute that says why. A `show` that
names no registered display leaves the reference unresolved too.

`formattedNumber` carries `data-tt-cross-reference-format="superscript"`, which the package's
[stylesheet](/features/cross-references/styling) prints raised.

## Where the numbers come from

The number displays read the target's label: what the `label` function you register for its
node type in the `targets` option returns, see [Numbering targets](/features/cross-references/targets#numbering-targets).
A target without a label has no number, so a reference to one of its numbers is unresolved.

### How relativeNumber shortens a number

`relativeNumber` writes `(b)` inside clause 3 and `3(b)` elsewhere, as Word's relative context
does. It writes `number` when the last target of the same type in front of the reference has
`counts` that start with the target's parent counts, and `fullNumber` otherwise.

For `(b)`, with `counts` `[3, 2]`, a reference after clause 3 or `3(a)` reads `(b)`, and one after clause
4 reads `3(b)`. It also writes the whole number when:

- The target's label has no `counts`, or fewer than two levels.
- No target of the same type stands in front, or that target has no `counts`.
- The target is [outside the document](/features/cross-references/displays#targets-outside-the-document).

## Separating the parts of a number

`numberSeparator` on a reference joins the runs of letters and digits of a number with the
separator, as Word's "Separate numbers with" does. With `-`, `3(b)` reads `3-b`, and `(b)`
reads `b`:

```js
editor.commands.insertCrossReference({ target: 'late-payment', numberSeparator: '-' })
```

It applies to `relativeNumber`, `number` and `fullNumber`, the displays with `numbered: true`.

## Adding above or below

`aboveBelow: true` on a reference adds a space and the `above` or `below` phrase to what its
display reads, as Word's "Include above/below" does. With `fullNumber` it reads `3(b) below`.
With `page` it reads `7 above`, because `page` reads only what `pageOf` returns:

```js
editor.commands.insertCrossReference({ target: 'late-payment', show: 'page', aboveBelow: true })
```

It adds nothing to an unresolved reference, to `show: 'aboveBelow'`, or when the first target
is outside the document. A reference with [several targets](/features/cross-references/joins) says it once, after the
joined text, of its first target.

## The page of a target

`show: 'page'` asks the `pageOf` option, which gets `{ node, pos, doc }` of a target and returns
the page as text, or `null`. `pageNumberAt` stands for your own function:

```js
CrossReferences.configure({
  targets: { heading: {} },
  pageOf: ({ pos }) => pageNumberAt(pos),
})
```

`pageOf` is `null` by default, so the page is unresolved, because the package knows nothing of
pages.
[Cross-references in Page Layout](/features/page-layout/extension-behavior/cross-references)
shows the `pageOf` for [Page Layout](/features/page-layout/getting-started/overview). `node` is
`null` for a bookmark or another range a [source](/features/cross-references/sources) gives.

## Targets outside the document

A [source](/features/cross-references/sources) can name targets outside the document, such as a statute. Such a target
has no page and no side, so `page` and `aboveBelow` leave the reference unresolved,
`relativeNumber` reads the full number, and `aboveBelow: true` adds nothing.

## Reference types

Each registered target has a reference type, Word's "Reference type", such as Heading or
Footnote. A picker lists the types first, then their targets. The type is the node type's
name, unless `type` gives a string, or a function of the node where one node type is two kinds.

`displays` on a registration lists what a picker offers for the type, in order. An entry is an
id, or `{ id, title }` to retitle the display for this type. Here a `footnote` is an Endnote or
a Footnote by its `placement` attribute, and `label` stands for its `label` function:

```js
CrossReferences.configure({
  targets: {
    footnote: {
      type: node => (node.attrs.placement === 'endnote' ? 'Endnote' : 'Footnote'),
      displays: ['number', 'formattedNumber', { id: 'page', title: 'Page of the note' }],
      label,
    },
  },
})
```

Without `displays`, a type offers a default list, by whether its registration has a `label`
function:

| Registration | Displays offered, in this order                                         |
| ------------ | ----------------------------------------------------------------------- |
| With `label` | `relativeNumber`, `number`, `fullNumber`, `title`, `page`, `aboveBelow` |
| Without      | `title`, `page`, `aboveBelow`                                           |

`formattedNumber` is not in the default list, so list it where a type needs it. `displays`
only shapes the picker. A reference reads any registered display its `show` names.

## Phrases

The phrases are the words a reference reads that are not its target's, such as "above", the `?`
of an unresolved reference, and the tooltips. The `phrases` option sets them, and each phrase
you leave out keeps its default from `DEFAULT_CROSS_REFERENCE_PHRASES`:

```js
CrossReferences.configure({
  targets: { heading: {} },
  phrases: { above: 'oben', below: 'unten', unresolved: '??' },
})
```

These are the phrases and their defaults:

| Phrase           | Default                                         | Where                                               |
| ---------------- | ----------------------------------------------- | --------------------------------------------------- |
| `above`          | `'above'`                                       | After a target before the reference                 |
| `below`          | `'below'`                                       | After a target after the reference                  |
| `unresolved`     | `'?'`                                           | A reference with nothing to show                    |
| `withheld`       | `'[withheld]'`                                  | A reference to a withheld target                    |
| `listSeparator`  | `', '`                                          | Between [several targets](/features/cross-references/joins)                 |
| `lastSeparator`  | `' and '`                                       | Before the last of several targets                  |
| `rangeSeparator` | `'–'`, an en dash                               | Inside a range, such as `3–5`                       |
| `targetMissing`  | `'The target of this reference is gone'`        | Tooltip: the target is gone                         |
| `numberMissing`  | `'The target of this reference has no number'`  | Tooltip: no number                                  |
| `pageMissing`    | `'The page of the target is not known'`         | Tooltip: no page                                    |
| `withheldTarget` | `'The target of this reference is withheld'`    | Tooltip: withheld target                            |
| `staleText`      | `'This text is no longer what the target says'` | Tooltip: the reference's own text no longer matches |

The separators hold their own spaces, because nothing else adds one. A reference that reads as
it should has no tooltip.

## Displays of your own

The `displays` option registers a display by id, and a type lists it like a built-in one. A
display with a built-in id replaces it, title included. A house style, such as a law firm's
citation rules, is a set of such displays.

This display reads `Figure 2`, and `null` leaves a figure without a number unresolved:

```js
CrossReferences.configure({
  displays: {
    captionLabel: {
      title: 'Only label and number',
      numbered: true,
      text: ({ target }) => target.label && `Figure ${target.label.number}`,
    },
  },
  targets: {
    figure: { type: 'Figure', displays: ['captionLabel', 'title', 'page'], label },
  },
})
```

A display has these fields:

| Field      | Type                          | Default    | Description                                                                           |
| ---------- | ----------------------------- | ---------- | ------------------------------------------------------------------------------------- |
| `title`    | `string`                      | Required   | What a picker lists it as                                                             |
| `text`     | `(context) => string \| null` | Required   | What a reference reads of one target. `null` leaves it unresolved                     |
| `missing`  | `'number' \| 'page'`          | `'number'` | What an unresolved reference says is missing                                          |
| `numbered` | `boolean`                     | `false`    | Whether `numberSeparator` applies and [ranges](/features/cross-references/joins#ranges) may form              |
| `format`   | `string`                      | None       | Written to `data-tt-cross-reference-format`. The stylesheet styles only `superscript` |

`text` runs once per target. For a `numbered` display, `numberSeparator` then works on the whole
text, so with `-`, `Figure 2` reads `Figure-2`. `text` gets a context with these fields:

| Field       | Description                                                                         |
| ----------- | ----------------------------------------------------------------------------------- |
| `target`    | The target, as [`crossReferenceTargetsIn`](/features/cross-references/reading#reading-the-targets) lists it |
| `reference` | The reference, as [`crossReferencesIn`](/features/cross-references/reading#reading-the-references) lists it |
| `doc`       | The document                                                                        |
| `context`   | The last target of the same type in front of the reference, or `null`               |
| `phrases`   | All configured phrases, although its type names only `above` and `below`            |
| `pageOf`    | The `pageOf` option, or `null`                                                      |

A target outside the document has `pos` and `node` `null`, and it is not a `context`.

## Helpers

The package exports what its built-in displays use, so your own can read numbers the same way:

| Name               | Arguments             | Description                                                                 |
| ------------------ | --------------------- | --------------------------------------------------------------------------- |
| `relativeNumberOf` | `target`, `context`   | The number as `relativeNumber` reads it, or `null` without a label          |
| `separatedNumber`  | `number`, `separator` | The number as `numberSeparator` writes it. Unchanged for a `null` separator |

The constants, such as `DEFAULT_CROSS_REFERENCE_DISPLAYS`, are listed under
[Names](/features/cross-references/reading#names). For TypeScript, the package exports `BuiltInCrossReferenceShow`, `CrossReferenceShow`,
`CrossReferenceDisplay`, `CrossReferenceDisplayContext` and `CrossReferenceDisplays`.
