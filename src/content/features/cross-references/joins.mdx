## Letting a reference name several targets

Set `multiple: true` to let a reference name several targets, and pass them as `targets`. Here
`label` stands for the function that numbers each heading, see
[Numbering targets](/features/cross-references/targets#numbering-targets), and `'payment'`, `'term'` and `'fees'` are
heading ids:

```js
CrossReferences.configure({
  targets: { heading: { label } },
  multiple: true,
})

editor.commands.insertCrossReference({ targets: ['payment', 'term', 'fees'], show: 'number' })
```

The reference reads `3, 5 and 7`, in the editor of
[Install Cross-references](/features/cross-references/install#a-first-editor). Without `multiple`, the default,
`insertCrossReference` with more than one target returns `false`.
[Inserting a reference](/features/cross-references/references#inserting-a-reference) has the other arguments.

When one of the targets cannot be read, such as one that was deleted, it reads `?` in its place
and the others read as usual. A withheld target reads `[withheld]` in its place. The reference
is then marked as unresolved, see [Styling](/features/cross-references/styling).

## The three rules

Each rule has an id, which a reference stores, and a title for a picker:

| Rule     | Picker title and result | How                                                                               |
| -------- | ----------------------- | --------------------------------------------------------------------------------- |
| `list`   | `3, 5 and 7`            | `listSeparator` between the targets, `lastSeparator` before the last. The default |
| `commas` | `3, 5, 7`               | `listSeparator` between all of them                                               |
| `range`  | `3–5 and 7`             | Numbers that follow each other form a [range](/features/cross-references/joins#ranges). The rest is listed        |

## Choosing the rule

The `join` option is the rule for every reference that names none, `list` by default. A
reference's `join` attribute is a rule id, or `null` for the configured rule:

```js
CrossReferences.configure({
  targets: { heading: { label } },
  multiple: true,
  join: 'range',
})

editor.commands.insertCrossReference({ targets: ['three', 'five'], join: 'commas' })

// The reference at the cursor goes back to the configured rule
editor.commands.setCrossReferenceOptions({ join: null })
```

A reference whose rule nobody registered reads by the configured rule.

## The words between the targets

The words between the targets are the phrases `listSeparator`, `lastSeparator` and
`rangeSeparator` of the `phrases` option. Write the spaces into the phrase, because nothing adds
them. With the `range` rule, these phrases make clauses 3, 4, 5 and 7 read `3 bis 5 und 7`:

```js
CrossReferences.configure({
  targets: { heading: { label } },
  multiple: true,
  join: 'range',
  phrases: { lastSeparator: ' und ', rangeSeparator: ' bis ' },
})
```

[Phrases](/features/cross-references/displays#phrases) lists the defaults.

## Ranges

The `range` rule writes three or more numbers that follow each other as one range, such as
`3–5`, and two as `3 and 4`. Numbers follow each other when they share level and parent and the
second is one more, so `3.2` follows `3.1`, but `4.1` does not follow `3.9`.

The rule reads this from the `counts` of each target's label, such as `[3, 2]` for `3.2`, so a
target without `counts` is in no range. The targets are not sorted, so `5, 4, 3` is no range.

Only a display with `numbered: true` makes ranges, so a reference showing the title has none. A
target that is gone, withheld or has no answer for the display is in no range either.

## A rule of your own

The `joins` option registers a rule by id, and one under a built-in id replaces it. This rule
reads `3, 5 or 7`:

```js
CrossReferences.configure({
  targets: { heading: { label } },
  multiple: true,
  joins: {
    alternatives: {
      title: '3, 5 or 7',
      pieces: ({ parts, phrases }) =>
        parts.flatMap((_part, index) =>
          index === 0
            ? [index]
            : [index === parts.length - 1 ? ' or ' : phrases.listSeparator, index],
        ),
    },
  },
})
```

A rule has a `title` for a picker and a `pieces` function. `pieces` returns what the reference
reads, in order: a number is the part at that index, and a string is text between parts. It
gets these fields:

| Field      | Description                                                 |
| ---------- | ----------------------------------------------------------- |
| `parts`    | One `{ text, target }` per target, in the reference's order |
| `phrases`  | All configured phrases                                      |
| `numbered` | Whether the display is `numbered`, which ranges need        |

A part's `text` is what the reference reads of that target. Its `target` is the target as
`crossReferenceTargetsIn` lists it. It is `null` when the target is gone, withheld or has no
answer, and `text` is then the `unresolved` or `withheld` phrase.

Each part is read once, at its first index, and an index that is not a part is left out. A part
the rule leaves out, as the `4` of `3–5`, is not read. A reference with one target does not call
the rule.

### Offering the rules in a picker

`crossReferenceJoinChoices(editor.storage.crossReferences.joins)` lists the rules as
`{ id, title }`, the built-in ones first. [Build a reference picker](/features/cross-references/picker#3-offer-the-join-rules)
shows it in a menu. For TypeScript, the package exports
`BuiltInCrossReferenceJoin`, `CrossReferenceJoin`, `CrossReferenceJoinContext`,
`CrossReferenceJoinPart`, `CrossReferenceJoinPiece` and `CrossReferenceJoins`.

## In Word

A rule returns pieces, not a string, because a .docx file writes each part as a field and the
text between parts as plain text, see [Word fields](/features/cross-references/docx#export). There `pieces` gets parts
with an empty `text`, so a rule that reads `part.text` can give other pieces than in the editor.
