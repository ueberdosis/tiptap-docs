The examples on this page build on the complete editor of [Install](/features/document-styles/install).

## Define a style

`setStyleDefinition` stores a style in the document. A definition needs an `id`, a `name` and a
`kind`, and its `props` hold the values it sets:

```js
editor.commands.setStyleDefinition({
  id: 'chapter',
  name: 'Chapter',
  kind: 'paragraph',
  basedOn: 'normal',
  props: { fontSize: 28, fontWeight: 700, marginTop: 24 },
})

editor.commands.applyStyle('chapter')
```

Numbers are pixels, except in unitless properties such as `fontWeight`. `applyStyle` puts the
style on the paragraph at the cursor, as [Applying styles](/features/document-styles/applying#apply-a-style) describes.

With `basedOn: 'normal'`, Chapter inherits every value it does not set from Normal, one of Word's
built-in styles. The extension brings them as a [library](/features/document-styles/libraries), a read-only set of styles
from outside the document.

The `kind` says what a style is for, such as `'paragraph'`, `'character'` for a piece of text, or
`'table'`. By default, a `'character'` style goes on text and any other kind on the block.
[Definition fields](/features/document-styles/definitions#definition-fields) lists every field.

## Change a style

To change a style, read its definition, change the values, and set the whole definition again.
`setStyleDefinition` replaces the stored definition and merges nothing, so a field you leave out
is gone:

```js
const styles = editor.storage.documentStyles.stylesOf(editor.state.doc)
const chapter = styles.getStyle('chapter')

editor.commands.setStyleDefinition({
  ...chapter,
  props: { ...chapter.props, fontSize: 32 },
})
```

Every paragraph in Chapter changes at once. `stylesOf(doc)` holds every style the document can
use, its own and its libraries'. `getStyle(id)` returns the definition that wins for the id, or
`null`, as [Which definition wins](/features/document-styles/libraries#which-definition-wins) explains.

When the stored definition is already the same, `setStyleDefinition` returns `false`. To change
only the name, use [`renameStyle`](/features/document-styles/definitions#renamestyle). To take the values set on the selection, use
[`updateStyleFromSelection`](/features/document-styles/definitions#updatestylefromselection) or
[Updating automatically](/features/document-styles/definitions#updating-automatically).

## Word's styles are read only

With the default options, the extension brings Word's built-in styles as a library, and a library
is read only. So `setStyleDefinition` returns `false` for their ids, such as `normal` and
`heading-1`, which [Word's built-in styles](/features/document-styles/libraries#words-built-in-styles) lists. To change
one, copy it with `duplicateStyle` and change the copy:

```js
editor.commands.duplicateStyle('heading-1', 'chapter-heading', 'Chapter heading')
```

The copy is the document's own style, with `status: 'draft'`. It keeps every field except `scope`
and `replacementStyleId`, Heading 1's [`defaultFor`](/features/document-styles/definitions#the-default-style) and
[`builtIn`](/features/document-styles/definitions#words-built-in-name) included. So level-one headings without a style of their own
are drawn in the copy instead of Heading 1, and the copy stands for Word's Heading 1.

A document that stores its own definition of such an id, such as one converted from a .docx file,
can change it, because the document's own definition wins over Word's. The `precedence` option
can turn that around, as [Read only](/features/document-styles/libraries#read-only) describes.

Word's library has headings for levels 1 to 3 only. With `wordStyles: false`, it is left out and
takes no id.

## What a style can set

`props` takes any CSS property in camel case, and the stylesheet writes it in kebab case, so
`fontSize` becomes `font-size`. These are the properties a style for text usually sets:

| What                  | Properties                                                                                                         | Values, for example                                             |
| --------------------- | ------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------- |
| Font                  | `fontFamily`, `fontSize`, `fontWeight`, `fontStyle`                                                                | `'theme:minor'`, `16`, `700`, `'italic'`                        |
| Spacing               | `letterSpacing`, `lineHeight`, `marginTop`, `marginBottom`, `textIndent`                                           | `'0.02em'`, `1.15`, `12`, `0`, `24`                             |
| Alignment             | `textAlign`                                                                                                        | `'left'`, `'center'`, `'right'`, `'justify'`                    |
| Case                  | `textTransform`, `fontVariantCaps`                                                                                 | `'uppercase'`, `'small-caps'`, `'all-small-caps'`               |
| Lines                 | `textDecorationLine`, `textDecorationStyle`, `textDecorationColor`, `textDecorationSkipInk`, `textUnderlineOffset` | `'underline'`, `'wavy'`, `'theme:accent2'`, `'none'`, `'0.2em'` |
| Ligatures and numbers | `fontVariantLigatures`, `fontVariantNumeric`                                                                       | `'discretionary-ligatures'`, `'oldstyle-nums tabular-nums'`     |
| Any OpenType feature  | `fontFeatureSettings`                                                                                              | `'"ss01" 1, "swsh" 1'`                                          |
| Trimming a line       | `textBoxTrim`, `textBoxEdge`                                                                                       | `'trim-both'`, `'cap alphabetic'`                               |
| Color                 | `color`, `backgroundColor`                                                                                         | `'#1f2937'`, `'theme:accent1/+40'`                              |

How a value is written depends on its type:

- **A number** is pixels. Only `fontWeight`, `lineHeight`, `opacity`, `orphans`, `widows`,
  `zIndex`, `flexGrow`, `flexShrink` and `order` take it as it is. So write a plain number for any
  other property as a string, such as `columnCount: '2'`.
- **A string** is written trimmed, and an empty one not at all.
- **A string that starts with `theme:`** refers to a font or color of the document's
  [theme](/features/document-styles/themes#referring-to-the-theme). `'theme:accent1/+40'` is that color 40% lighter.
- **`null`** takes away the value the base style sets.
- **`true` and `false`** are not written.

An unknown property is written, and the browser ignores it. `textBoxTrim` works only where the
browser supports `text-box-trim`. The stylesheet leaves out a value or name that could break its
rule, as [How a value becomes CSS](/features/document-styles/how-it-works#how-a-value-becomes-css) lists.

With a `colorScheme` other than `'light'`, the option for [dark mode](/features/document-styles/themes#dark-mode), each
color gets a dark counterpart.

## Where a value comes from

A block's value for a property is looked up in this order, and the first place that sets it wins:

1. The block's [overrides](/features/document-styles/applying#overrides), the values set on this one block.
2. The style's own `props`.
3. The style it is `basedOn`, then that style's base, and so on.

A block without a style of its own starts at its [default style](/features/document-styles/definitions#the-default-style). A style can
be based on a library's style, as Chapter is based on Normal. Your own CSS competes with the
stylesheet's rule by CSS specificity, as [Your own CSS](/features/document-styles/how-it-works#your-own-css) explains.

To get a style's final values, such as for a preview in a style picker or for an export, use
`resolveStyle`:

```js
import { resolveStyle } from '@tiptap-pro/extension-document-styles'

const styles = editor.storage.documentStyles.stylesOf(editor.state.doc)
const result = resolveStyle(styles, 'chapter', { color: 'navy' })

if (result.ok) {
  result.style.props // Normal's values, Chapter's over them, then color: navy
}
```

The third argument is optional overrides, laid over `props` only. `result.style` holds the `id`,
`name`, `kind` and the stored `definition`, with the inherited `props`, `outlineLevel`,
`pagination`, `tableConditions`, `tableBands` and `language`.

`resolveStyle` returns an error instead of throwing, because content can refer to a style that is
gone. `result.error.code` is one of these:

- **`'missing-style'`**: nothing defines the id, or a base up the chain. `result.error.styleId`
  is the missing one.
- **`'circular-inheritance'`**: styles are based on each other, or one on itself.
  `result.error.chain` is the loop, such as `['a', 'b', 'a']`.

What refers to a style that does not resolve is drawn as if it had no style. Such a style is also
no block's default and has no outline level, pagination or language.

## The default style

A style with `defaultFor: ['paragraph']` is what every paragraph without a style of its own is
drawn in, as Word's Normal is:

```js
editor.commands.setStyleDefinition({
  id: 'body',
  name: 'Body Text',
  kind: 'paragraph',
  defaultFor: ['paragraph'],
  props: { fontSize: 15, lineHeight: 1.5 },
})
```

The paragraphs keep `styleId: null`, so `getJSON()` and `getHTML()` do not change. When you change
the default, all of them change at once.

With the default options, Word's `normal` is the default for paragraphs, and `heading-1` to
`heading-3` for headings of levels 1 to 3. Body Text wins over Normal, because of two defaults for
the same blocks, the document's own wins over a library's. With `precedence: 'libraries'`, the
library's wins instead.

A default can be for blocks with certain attributes. That is how each heading level gets its own,
and Section heading wins over Word's Heading 2 the same way:

```js
editor.commands.setStyleDefinition({
  id: 'section',
  name: 'Section heading',
  kind: 'paragraph',
  defaultFor: [{ type: 'heading', attrs: { level: 2 } }],
  props: { fontSize: 21 },
})
```

An attribute matches when the node's value is strictly equal, so a heading that changes level gets
the default of its new level. A default that names more attributes wins, so
`defaultFor: ['heading']` draws only the levels nothing else names.

Only blocks whose type is one of the `types`, the node types the extension styles, are drawn in a
default. Such a block keeps the outline level of its node type.

To show a block's style in a toolbar, read the defaults with `defaultStylesOf`:

```js
import { styleIdOrDefaultOf } from '@tiptap-pro/extension-document-styles'

const defaults = editor.storage.documentStyles.defaultStylesOf(editor.state.doc)

styleIdOrDefaultOf(defaults, node) // its own style, even one nothing defines, or else its default
defaults.of(node) // the default of its type and attributes, or null, for any node type
defaults.entries // [{ type: 'heading', attrs: { level: 2 }, styleId: 'section' }, ...]
```

`entries` lists the more specific first. In the editor, a default is a decoration and is not
stored, as [The stylesheet](/features/document-styles/how-it-works#the-stylesheet) describes.

## The next paragraph

`nextStyle` names the style of the paragraph that follows. When the user presses Enter at the end
of a paragraph in Lead, the new paragraph is in Normal:

```js
editor.commands.setStyleDefinition({
  id: 'lead',
  name: 'Lead',
  kind: 'paragraph',
  basedOn: 'normal',
  nextStyle: 'normal',
  props: { fontSize: 19 },
})
```

Word's `title`, `subtitle` and headings already have `nextStyle: 'normal'`. A style without
`nextStyle`, or with its own id or `''`, keeps itself. Enter in the middle of a paragraph keeps the
style on both halves.

The new paragraph starts without the overrides of the one before, and one undo takes back the
Enter and the style. The option `followNextStyle: false` turns `nextStyle` off.

Apart from Enter, any transaction that splits a textblock at its very end with a cursor sets the
next style. A paragraph drawn in a default style gets none, and neither does a block whose type,
or the new block's, is not in `types`. A change from a collaborator sets none either.

`nextStyle` is read off the paragraph's own definition, not inherited. One that nothing defines is
still set, as a [style nothing defines](/features/document-styles/applying#a-style-nothing-defines). With the option
`transformNodeOnApply`, the new paragraph also becomes the next style's `node` type, where it is a
textblock the schema allows there.

## Outline levels

`outlineLevel` puts a style's paragraphs in the document's outline, the headings that a table of
contents or heading numbers read, whatever node type they are.
[Outline numbering](/features/outline-numbering/what-is-numbered#numbering-by-style)
numbers paragraphs by these levels:

```js
editor.commands.setStyleDefinition({
  id: 'part',
  name: 'Part',
  kind: 'paragraph',
  basedOn: 'normal',
  outlineLevel: 1,
  props: { fontSize: 24 },
})
```

Levels go from `1`, the outermost, to `9`, and `null` is body text. The level is inherited through
`basedOn`, and `null` stops it, so a style based on a heading can be body text. Word's `title` is
body text, and its headings have levels 1 to 3.

A level outside `1` to `9` is read as the nearest one, and a fraction is rounded. A value that is
not a number, such as `'2'`, is read as `null`.

To read the levels, use `outlineLevelsOf`, a `Map` of style id to level. Here `node` is a block of
the document:

```js
import { styleOutlineLevelOf } from '@tiptap-pro/extension-document-styles'

const levels = editor.storage.documentStyles.outlineLevelsOf(editor.state.doc)

styleOutlineLevelOf(levels, node) // 1 for a paragraph in Part
```

`styleOutlineLevelOf` returns `null` for a node whose style is body text. It returns `undefined`
for a node without a style that resolves, whose own level then counts, such as a heading's.

## Line and page breaks

`pagination` says how a style's paragraphs meet the end of a page, as Word's Line and Page Breaks
do. Only an editor that shows pages reads it, such as Page Layout, the extension that shows a
document on pages. In an editor without pages, `pagination` is stored with the style and changes
nothing you see, so you can skip this section.

```js
editor.commands.setStyleDefinition({
  id: 'appendix',
  name: 'Appendix',
  kind: 'paragraph',
  basedOn: 'heading-1',
  pagination: { pageBreakBefore: true },
})
```

Each key of `pagination` is optional:

| Key                 | Type      | Description                                               |
| ------------------- | --------- | --------------------------------------------------------- |
| `keepWithNext`      | `boolean` | The paragraph stays on the page of the paragraph after it |
| `keepLinesTogether` | `boolean` | The paragraph is not divided between two pages            |
| `pageBreakBefore`   | `boolean` | The paragraph starts a page                               |

Each key is inherited through `basedOn` on its own, and `false` stops one a base sets. Word's
headings set `keepWithNext` and `keepLinesTogether`, so Appendix has both. A value that is not a
boolean, and any other key, is not read.

With Page Layout, pass `styleBlockBreaks()` as its `blockBreaksOf` option, with the same `types`
and `libraries` as `DocumentStyles`. Add `wordStyleLibrary()` to those libraries, so that Page
Layout also reads Word's headings:

```js
import { styleBlockBreaks, wordStyleLibrary } from '@tiptap-pro/extension-document-styles'

PageLayout.configure({
  blockBreaksOf: styleBlockBreaks({ types, libraries: [...libraries, wordStyleLibrary()] }),
})
```

`types` and `libraries` stand for the arrays you give `DocumentStyles`. The complete setup is in
[Document styles in Page Layout](/features/page-layout/extension-behavior/document-styles#line-and-page-breaks).

`resolveStyle` returns the keys as `result.style.pagination`, and `stylePaginations` returns them
for every style that sets any. The function `styleBlockBreaks` returns reads a block's own style,
or else its type's default, and names `keepLinesTogether` `keepTogether`, the word Page Layout
uses. [API reference](/features/document-styles/api#functions-without-an-editor) lists what it returns.

## Language

`language` gives the text of a style a language, as a BCP 47 tag such as `'en-GB'` or `'de-CH'`:

```js
editor.commands.setStyleDefinition({
  id: 'citation-fr',
  name: 'French quote',
  kind: 'paragraph',
  basedOn: 'quote',
  language: 'fr',
})
```

A block in the style, and a run of text in a character style, get a `lang` attribute, which the
browser's spell checking, hyphenation and screen readers use. A block drawn in its default gets the
default's language. `lang` is drawn only on blocks of `types` and marks of `markTypes`.

Word's `quote` is there when `blockquote` is one of the `types`, as with StarterKit. Without it,
French quote does not resolve and gets no `lang`.

The language is inherited through `basedOn`, and `language: null` stops it. Nothing is written into
the content, so `getHTML()` has no `lang`, and changing the style's language changes every block of
it. `styleLanguages` returns the language of every style that has one, inherited included.

## Updating automatically

With `autoUpdate: true`, formatting the user sets on a paragraph changes its style instead, as
Word's Automatically update does. Every paragraph of the style changes with it:

```js
editor.commands.setStyleDefinition({
  id: 'note',
  name: 'Note',
  kind: 'paragraph',
  autoUpdate: true,
})
editor.commands.applyStyle('note')
editor.commands.setStyleOverride('color', 'teal') // every note is teal
```

`setStyleOverride` takes the paragraph's override of that property off, since the style now sets
it. Other paragraphs keep their own overrides. `unsetStyleOverride` and `clearStyleOverrides` act
on the paragraph and leave the style as it is.

`autoUpdate` is read off the style's own definition, not inherited. It works for the document's
own paragraph styles, on paragraphs that have the style themselves.

A paragraph in a library's
style, which is read only, gets an override as usual. So does a paragraph drawn in the style only
because it is its default.

## Word's built-in name

`builtIn` says which of Word's built-in styles a style is, for code that converts a document to or
from a .docx file. This package converts nothing itself. A converter writes the style as Word's
own, so Word lists its paragraphs in the navigation pane and the table of contents:

```js
editor.commands.setStyleDefinition({
  id: 'chapter-title',
  name: 'Chapter title',
  kind: 'paragraph',
  builtIn: 'heading 1',
})
```

The value is the style's name in the .docx file's `w:name` attribute. It is the same in every
language Word runs in, unlike the name Word shows, such as Überschrift 1. Examples are `'Normal'`,
`'heading 1'` to `'heading 9'`, `'Title'`, `'Quote'`, `'caption'`, `'toc 1'`, `'Strong'` and
`'Table Grid'`. `WORD_BUILT_IN_STYLES` lists all 45.

`builtIn` draws nothing and is not inherited. A style without it is written as a style of its own,
and a name Word does not build in is kept and stands for nothing.

A converter asks `wordBuiltInStylesOf` which style stands for which name:

```js
const builtIns = editor.storage.documentStyles.wordBuiltInStylesOf(editor.state.doc)

builtIns.builtInOf('chapter-title') // 'heading 1', or null for a style of its own
builtIns.styleIdOf('Heading 1') // 'chapter-title': the style for a paragraph read from a .docx
builtIns.styleIdOf('caption') // null: no style stands for it
```

`styleIdOf` takes a name in any case, trimmed. It finds Chapter title and not Word's `heading-1`,
which has the same `builtIn`, because of two such styles the document's own has the name. With
`precedence: 'libraries'`, the library's has it. The other counts as a style of its own.

Without a style of the document's own, `styleIdOf('Normal')` is `'normal'`.
`wordBuiltInStyleOf(name)` spells a name the way Word does, or returns `null`.

## Without an editor

On a server or in a migration script, you can write the definitions into a saved document without
an editor. The schema needs `DocumentStyles`, and `json` stands for the saved document:

```js
import { getSchema } from '@tiptap/core'
import { Node } from '@tiptap/pm/model'
import { EditorState } from '@tiptap/pm/state'
import StarterKit from '@tiptap/starter-kit'
import { TextStyle } from '@tiptap/extension-text-style'
import {
  DocumentStyles,
  setStyleDefinitionTransaction,
} from '@tiptap-pro/extension-document-styles'

const schema = getSchema([StarterKit, TextStyle, DocumentStyles])
const state = EditorState.create({ doc: Node.fromJSON(schema, json) })
const lead = { id: 'lead', name: 'Lead', kind: 'paragraph', props: { fontSize: 19 } }

const saved = setStyleDefinitionTransaction(state.tr, lead).doc.toJSON()
```

`setStyleDefinitionTransaction(tr, definition)` returns the transaction it was handed, with the
steps added. The document keeps each definition as a node in one hidden `styleDefinitions` node,
as [The definitions node](/features/document-styles/how-it-works#the-definitions-node) describes.

The function replaces the node of that id, or appends one, and adds the `styleDefinitions` node at
the end where there is none. It also removes later nodes of the same id, which collaborators can
leave behind.

It stores a JSON copy, so a field set to `undefined` is dropped. It adds no step when the stored
definition is the same. It does not check libraries, so it can store an id of Word's, such as
`normal`, which then wins over Word's under `precedence: 'document'`.

It throws for something that is not a definition, with a message ending in "it needs an id, a
name and a kind". It also throws when the schema has no `styleDefinitions` node, as the
[list of transactions](/features/document-styles/api#transactions) says, or no container at the end of the document can
take one.

`removeStyleDefinitionTransaction(tr, styleId)` removes the document's own definition of the id,
and does nothing when there is none. What refers to the style stays. A document left without
definitions and without a theme loses the `styleDefinitions` node.

To read the styles without an editor, use the
[functions without an editor](/features/document-styles/api#functions-without-an-editor).

## Definition fields

A definition needs `id`, `name` and `kind`. Every other field is optional:

| Field                | Type                                     | Description                                                                                                                            |
| -------------------- | ---------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| `id`                 | `string`                                 | What content refers to. It stays when the style is renamed                                                                             |
| `name`               | `string`                                 | What a style picker shows the user                                                                                                     |
| `kind`               | `StyleKind`                              | `'paragraph'`, `'character'`, `'list'`, `'object'`, `'table'`, `'cell'` or `'custom'`                                                  |
| `scope`              | `StyleScope`                             | `'document'`, `'workspace'`, `'organization'` or `'system'`                                                                            |
| `basedOn`            | `string`                                 | The style this one inherits every value from that it does not set itself                                                               |
| `nextStyle`          | `string`                                 | The style of the next paragraph. See [The next paragraph](/features/document-styles/definitions#the-next-paragraph)                                                         |
| `outlineLevel`       | `number \| null`                         | `1` to `9`, or `null` for body text. See [Outline levels](/features/document-styles/definitions#outline-levels)                                                             |
| `defaultFor`         | `StyleDefaultFor[]`                      | Node types, or `{ type, attrs }`, it is the default of. See [The default style](/features/document-styles/definitions#the-default-style)                                    |
| `builtIn`            | `WordBuiltInStyle`                       | The Word style it is, such as `'heading 1'`. See [Word's built-in name](/features/document-styles/definitions#words-built-in-name)                                          |
| `pagination`         | `StylePagination`                        | How its paragraphs meet a page end. See [Line and page breaks](/features/document-styles/definitions#line-and-page-breaks)                                                  |
| `language`           | `string \| null`                         | The language of its text, such as `'de-CH'`. See [Language](/features/document-styles/definitions#language)                                                                 |
| `priority`           | `number`                                 | Its place in a style list, the lower first. See [A style picker](/features/document-styles/applying#a-style-picker)                                           |
| `hidden`             | `boolean`                                | Out of a style list until something uses it. See [A style picker](/features/document-styles/applying#a-style-picker)                                          |
| `gallery`            | `boolean`                                | In the short row of styles a toolbar offers. See [A style picker](/features/document-styles/applying#a-style-picker)                                          |
| `autoUpdate`         | `boolean`                                | Formatting on a paragraph changes the style. See [Updating automatically](/features/document-styles/definitions#updating-automatically)                                     |
| `tableConditions`    | `TableConditions`                        | A table style's header row, total row, columns and bands. See [Table styles](/features/document-styles/tables#conditional-formats)                            |
| `tableBands`         | `Partial<TableBands>`                    | Rows and columns per band. See [Bands of more than one row](/features/document-styles/tables#bands-of-more-than-one-row)                                      |
| `targets`            | `StyleTarget[]`                          | Where it can go, each `{ kind: 'node' \| 'mark', types }`                                                                              |
| `node`               | `StyleNodeTransform`                     | `{ type?, attrs? }`, what a block becomes or is put in. See [A style that wraps its blocks](/features/document-styles/applying#a-style-that-wraps-its-blocks) |
| `props`              | `StyleProps`                             | The values it sets. See [What a style can set](/features/document-styles/definitions#what-a-style-can-set)                                                                  |
| `meta`               | `Record<string, unknown>`                | Anything of yours, such as the design token a value came from. Not read                                                                |
| `version`            | `number`                                 | Yours to count with. Not read                                                                                                          |
| `status`             | `'draft' \| 'published' \| 'deprecated'` | Read only by the [usage report](/features/document-styles/cleanup#how-styles-are-used), which counts none as `'published'`                                    |
| `replacementStyleId` | `string`                                 | Where a deprecated style points. See [Replacing a style](/features/document-styles/cleanup#replacing-a-style)                                                 |

These fields need more than a cell:

- **`kind`** draws nothing, but commands read it. A `'table'` style goes on the table node types
  and a `'character'` style on a mark. `autoUpdate` works only for a `'paragraph'` style.
  `replaceStyle` puts only a `'paragraph'` style on blocks and a `'table'` style on tables.
- **`scope`** is a label. A library's style without one gets the library's scope, and the
  document's own get `'document'`.
- **`targets`** overrides where the kind puts a style. Only the first entry of each kind is read,
  and `targets: []` counts as none.
- **`status`** and **`replacementStyleId`** move nothing. A deprecated style can still be
  applied, and `replaceStyle` moves its users.

When a document is read, a stored definition that fails `isStyleDefinition` is skipped, and of two
with one id the first counts. `isStyleDefinition` does not check `kind` against the list, and
accepts an empty `name`.

## Commands

Each command is one step of the history, with whatever else it changed. A command returns `false`
when it would change nothing or cannot act, so a toolbar can ask `editor.can()` first.

A command that would change a library's style returns `false`, as
[Read only](/features/document-styles/libraries#read-only) describes, with what changes under `precedence: 'libraries'`.

### setStyleDefinition()

Stores a definition in place of the document's own definition of the same id.
[Define a style](/features/document-styles/definitions#define-a-style) and [Change a style](/features/document-styles/definitions#change-a-style) show it.

It takes one argument, `definition`, the whole `StyleDefinition`.

Returns `false`, without throwing, for something without an `id`, a `name` and a `kind`. Also
returns `false` for an id whose definition comes from a [library](/features/document-styles/definitions#words-styles-are-read-only),
and when the document already has the same definition.

### renameStyle()

Gives one of the document's styles a new name. Its id, and what refers to it, stay:

```js
editor.commands.renameStyle('chapter', 'Part opener')
```

| Argument  | Type     | Description                     |
| --------- | -------- | ------------------------------- |
| `styleId` | `string` | The style                       |
| `name`    | `string` | The new name, trimmed of spaces |

Returns `false` for a style that is not the document's own, and for a name that is empty or the
same after trimming.

### duplicateStyle()

Copies a style, the document's own or a library's, into a new style of the document's own with
`status: 'draft'`. [Word's styles are read only](/features/document-styles/definitions#words-styles-are-read-only) shows it and what the
copy keeps.

| Argument     | Type     | Description                                                                       |
| ------------ | -------- | --------------------------------------------------------------------------------- |
| `styleId`    | `string` | The style to copy                                                                 |
| `newStyleId` | `string` | The id of the copy, trimmed                                                       |
| `name`       | `string` | Optional. Empty or left out, the original's name and ` Copy`, as `Heading 1 Copy` |

Returns `false` for a style nothing defines, and for a new id that is empty or taken, Word's ids
included.

### deprecateStyle()

Marks one of the document's styles `'deprecated'` and points it to a replacement. What refers to it
stays:

```js
editor.commands.deprecateStyle('section', 'chapter')
```

| Argument             | Type     | Description                                                          |
| -------------------- | -------- | -------------------------------------------------------------------- |
| `styleId`            | `string` | The style                                                            |
| `replacementStyleId` | `string` | Optional. A style that exists. Left out, the style's own one is kept |

Returns `false` for a style that is not the document's own, for a replacement nothing defines, and
when the style is already deprecated that way.

### updateStyleFromSelection()

Writes the values the selection overrides into one of the document's styles, over its `props`:

```js
editor.commands.updateStyleFromSelection('lead', { removeMatchingOverrides: true })
```

| Argument                          | Type      | Default | Description                                                        |
| --------------------------------- | --------- | ------- | ------------------------------------------------------------------ |
| `styleId`                         | `string`  |         | The style to update                                                |
| `options.removeMatchingOverrides` | `boolean` | `false` | Also takes the overrides off the selection, where it has the style |

When part of a block is selected, the overrides are those of the selected text, which its mark
holds, as [Overrides](/features/document-styles/applying#overrides) describes. Otherwise they are the block's. They go
into `styleId` whatever style the selection has.

Returns `false` for a style that is not the document's own, and when the selection overrides
nothing. Also returns `false` when the style already sets the same values, though with
`removeMatchingOverrides` the overrides still come off.

### createStyleFromSelection()

Makes a new style of the values the selection overrides, and gives the selection that style:

```js
editor.commands.createStyleFromSelection({ id: 'callout', name: 'Callout', kind: 'paragraph' })
```

| Argument     | Type        | Description                                                             |
| ------------ | ----------- | ----------------------------------------------------------------------- |
| `input.id`   | `string`    | The new id                                                              |
| `input.name` | `string`    | The new name                                                            |
| `input.kind` | `StyleKind` | A `'character'` style goes on the selected text, any other on the block |

The overrides become the new style's `props` and come off the selection. A `'character'` style gets
`targets` with the mark the selection's style is on, or else the first of the `markTypes` option,
the mark types a character style can go on.

Returns `false` for an empty or taken id, Word's ids included, and for a `'character'` style when
there is no mark type.
