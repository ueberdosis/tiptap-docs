## A house style

To offer the same styles in every document, make a library with `styleLibrary()` and pass it in
the `libraries` option of `DocumentStyles`. Each entry is a style definition, which names a style
and says what it sets, as [Defining styles](/features/document-styles/definitions) describes. The code builds on the
editor of [Install](/features/document-styles/install):

```js
import { DocumentStyles, styleLibrary } from '@tiptap-pro/extension-document-styles'

const house = styleLibrary(
  [{ id: 'body', name: 'House Body', kind: 'paragraph', props: { fontFamily: 'Inter' } }],
  { scope: 'organization' },
)

DocumentStyles.configure({ libraries: [house] })
```

A library's style is applied like any other, here to the paragraph at the cursor:

```js
editor.commands.applyStyle('body')
```

The paragraph stores only the style's id, `'body'`, and the editor draws it, that is renders it
with a stylesheet of its own, in the library's values.

Nothing of the library is stored in the document. So a document opened without the library still refers to `'body'`, and is drawn in
whatever else defines that id, or as a [missing style](/features/document-styles/cleanup#missing-styles).

To publish new styles, replace the library's definitions with `setStyles()`. Each editor that uses
the library draws them again, and the content does not change, so there is nothing to undo. Here
`fetchHouseStyles` stands for your own function that loads them:

```js
house.setStyles(await fetchHouseStyles())
```

`styleLibrary(definitions, options)` returns a `WritableStyleLibrary`. Its `options` can be left
out:

| Option  | Type                                                      | Default | Description                                                                               |
| ------- | --------------------------------------------------------- | ------- | ----------------------------------------------------------------------------------------- |
| `scope` | `'document' \| 'workspace' \| 'organization' \| 'system'` | None    | The scope of each definition that names none itself                                       |
| `theme` | `DocumentTheme \| null`                                   | `null`  | The theme its styles are meant to be drawn in. See [A library's theme](/features/document-styles/libraries#a-librarys-theme) |

A scope, a `StyleScope`, labels where a definition comes from. Your interface can read it, for
example to show it next to a style, and the extension draws nothing differently by it.

A `WritableStyleLibrary` has these methods:

| Method                         | Description                                                                    |
| ------------------------------ | ------------------------------------------------------------------------------ |
| `house.getStyles()`            | Returns its definitions                                                        |
| `house.setStyles(definitions)` | Replaces them, and each editor that uses the library draws them again          |
| `house.getTheme()`             | Returns its theme, or `null`                                                   |
| `house.setTheme(theme)`        | Replaces its theme, and each editor draws again. `setTheme(null)` takes it off |
| `house.subscribe(listener)`    | Calls `listener` on each change. Returns the function that unsubscribes        |

## Word's built-in styles

An editor has the styles a new Word document starts with, unless its `wordStyles` option is
`false`. A document with no styles of its own is drawn in them: a paragraph in Normal, and a
heading of the second level in Heading 2.

That is because Normal and the headings are [default styles](/features/document-styles/definitions#the-default-style),
the styles a block without a style of its own is drawn in.

To bring none of Word's styles, set `wordStyles` to `false`. To offer them to apply, but leave
content without a style as it looked, turn off only their defaults:

```js
DocumentStyles.configure({ wordStyles: false })

DocumentStyles.configure({ wordStyles: { defaults: false } })
```

With `defaults: false`, Normal and the headings are no type's default. To give every block its
default style later, use [`applyDefaultStyles`](/features/document-styles/cleanup#writing-the-defaults-onto-the-blocks).

The extension adds Word's styles as a library after every library in `libraries`. So a library of
yours that defines the same id, such as `normal`, wins over Word's.

A paragraph style goes on a block, and a character style on text only, as a mark. A linked style
goes on the block, or on the selected text when only part of a paragraph is selected, as
[A style on a block or on text](/features/document-styles/applying#a-style-on-a-block-or-on-text) explains.

Word's styles, with the `priority` a [style picker](/features/document-styles/applying#a-style-picker) sorts them by:

| Id                                                          | Name                                                | Kind              | Priority | What it does                                                                |
| ----------------------------------------------------------- | --------------------------------------------------- | ----------------- | -------- | --------------------------------------------------------------------------- |
| `normal`                                                    | Normal                                              | Paragraph         | 1        | The default of every paragraph                                              |
| `no-spacing`                                                | No Spacing                                          | Paragraph         | 2        | Normal with `lineHeight: 1` and `marginBottom: 0`                           |
| `heading-1` to `heading-3`                                  | Heading 1 to Heading 3                              | Paragraph, linked | 9        | Made for a heading of its level, and the default of headings of that level  |
| `title`, `subtitle`                                         | Title, Subtitle                                     | Paragraph, linked | 11, 12   | A title and a subtitle                                                      |
| `subtle-emphasis`, `emphasis`, `intense-emphasis`, `strong` | Subtle Emphasis, Emphasis, Intense Emphasis, Strong | Character         | 19 to 22 | Go on a piece of text                                                       |
| `quote`, `intense-quote`                                    | Quote, Intense Quote                                | Paragraph         | 29, 30   | Put their paragraphs in a blockquote, and go on the blockquote, not on text |

Styles that need a type the editor does not style are left out, as
[wordStyles](/features/document-styles/options#wordstyles) lists. The paragraph styles go on `paragraph`, and the
character and linked styles on the first of `markTypes`. With `markTypes` empty, the linked styles
go on the block only.

A document's own definition of a Word id, such as `normal`, is drawn instead of Word's, as
[Which definition wins](/features/document-styles/libraries#which-definition-wins) describes. It replaces all of Word's definition, so
a document's own `normal` without `defaultFor`, the field that makes a style a default, leaves
paragraphs with no default style.

Word's values are those of Word's Office theme, converted to pixels, so Word's 12pt is `16`. Their
fonts and colors refer to the document's [theme](/features/document-styles/themes), such as `'theme:minor'`,
`'theme:major'`, `'theme:accent1/-25'`, `'theme:dark1/+25'` and `'theme:dark1/+35'`. So a document
with another theme draws them in its own.

Normal sets `fontFamily: 'theme:minor'`, `fontSize: 16`, `lineHeight: 1.15`, `marginTop: 0` and
`marginBottom: 11`. Every other style inherits from Normal through `basedOn`, except Heading 2
from Heading 1, Heading 3 from Heading 2, and Intense Quote from Quote.

Word's styles also set these fields:

| Field                                               | Set on                                                                                  |
| --------------------------------------------------- | --------------------------------------------------------------------------------------- |
| [`nextStyle`](/features/document-styles/definitions#the-next-paragraph)    | `'normal'` on Title, Subtitle and the headings                                          |
| [`outlineLevel`](/features/document-styles/definitions#outline-levels)     | `1` to `3` on Heading 1 to Heading 3, and `null`, body text, on Title                   |
| [`pagination`](/features/document-styles/definitions#line-and-page-breaks) | `{ keepWithNext: true, keepLinesTogether: true }` on the headings                       |
| [`builtIn`](/features/document-styles/definitions#words-built-in-name)     | The name a .docx file knows the style by, such as `'Normal'` and `'heading 1'`, on each |
| `gallery`, `scope`                                  | `true` and `'system'` on each                                                           |

### Word's styles as a library of your own

`wordStyleLibrary(options)` returns Word's styles as a library of your own, for an editor whose
types have other names, or to put Word's styles somewhere other than last in `libraries`.

Set `wordStyles: false` with it, or Word's styles are there twice, and the built-in copy goes last.
Here `house` is the library of [A house style](/features/document-styles/libraries#a-house-style):

```js
import { DocumentStyles, wordStyleLibrary } from '@tiptap-pro/extension-document-styles'

DocumentStyles.configure({
  wordStyles: false,
  // First, so Word's styles win over the house style of the same id
  libraries: [wordStyleLibrary({ quoteType: null }), house],
})
```

The library is a `WritableStyleLibrary` with `scope: 'system'`. Its `options`, a
`WordStylesOptions`, can be left out:

| Option          | Type             | Default        | Description                                                                      |
| --------------- | ---------------- | -------------- | -------------------------------------------------------------------------------- |
| `paragraphType` | `string`         | `'paragraph'`  | The type Normal is the default of                                                |
| `headingType`   | `string \| null` | `'heading'`    | The heading type, with a `level` attribute. `null` leaves the headings out       |
| `quoteType`     | `string \| null` | `'blockquote'` | The type the quotes put their paragraphs in. `null` leaves the quotes out        |
| `markType`      | `string \| null` | `'textStyle'`  | The mark for character and linked styles. `null` leaves the character styles out |
| `defaults`      | `boolean`        | `true`         | Whether Normal and the headings are default styles, as with `wordStyles`         |

With `headingType`, `quoteType` and `markType` all `null`, only Normal, No Spacing, Title and
Subtitle remain.

`wordStyles(options)` returns the same definitions as an array, to store in a document or to start
a library of your own from. `WORD_STYLES` is that array, frozen, for `paragraph`, `heading`,
`blockquote` and `textStyle`.

## Which definition wins

The same id can be defined by the document and by a library. The `precedence` option of
`DocumentStyles`, a `StylePrecedence`, decides which definition is used:

- **`'document'`, the default.** The document's own definition wins, and a library's is used
  where the document has none. A style changed in one document stays as it was changed when the
  library is updated later.
- **`'libraries'`.** A library's definition wins, and the document's own is used where no library
  has one. So the house style wins over a document's own style of the same id.

```js
DocumentStyles.configure({ libraries: [house], precedence: 'libraries' })
```

Among libraries, the first one in `libraries` that defines the id wins.

To find out which definition the editor uses, ask its style lookup, the object that answers a
definition by id. `editor.storage.documentStyles.stylesOf(doc)` returns the lookup of a document,
with its own styles, its libraries and Word's styles:

```js
const styles = editor.storage.documentStyles.stylesOf(editor.state.doc)

styles.getStyle('body') // the definition that wins, or null
styles.originOf('body') // 'document', 'library', or null where nothing defines it
styles.getStyle('body')?.scope // 'organization'
```

A `StyleLookup` has these methods:

| Method                | Returns                                                                                       |
| --------------------- | --------------------------------------------------------------------------------------------- |
| `styles.getStyle(id)` | The definition that wins, or `null`                                                           |
| `styles.originOf(id)` | `'document'` or `'library'` for the definition that wins, or `null` for an id nothing defines |
| `styles.getStyles()`  | Each id once, the document's own first unless the libraries win                               |

A definition the lookup returns keeps the scope it names itself. One that names none is labeled
`'document'` when it is the document's own, or with its library's `scope`.

## Read only

A library's style is applied, and other styles are based on it, like any other style. To change
one for a single document, copy it with [`duplicateStyle`](/features/document-styles/definitions#duplicatestyle), and
change the copy. The arguments are the style to copy, the new id and the new name:

```js
editor.commands.duplicateStyle('body', 'my-body', 'Body, adjusted')
```

A command that would change a library's style returns `false`: `setStyleDefinition` with the
style's id, `renameStyle`, `deprecateStyle`, `updateStyleFromSelection` and `deleteStyle`.
[Word's styles are read only](/features/document-styles/definitions#words-styles-are-read-only) says what a copy keeps,
and what that means for Word's styles.

With `precedence: 'libraries'`, these commands differ for an id that the document and a library
both define. `setStyleDefinition` returns `false`, because the library's definition wins. The
other four look at the document's own definitions only. So they change the document's copy, which
stays hidden behind the library's.

## A library's theme

A library can bring the [theme](/features/document-styles/themes) its styles are meant to be drawn in, the fonts and
colors that `theme:` values refer to. Pass it as `theme`, and publish a new one with `setTheme()`,
the same way as new styles. Here `houseStyles` stands for your array of definitions:

```js
const house = styleLibrary(houseStyles, {
  scope: 'organization',
  theme: { name: 'House', colors: { accent1: '#536dfe' } },
})

house.setTheme({ name: 'House 2026', colors: { accent1: '#0f766e' } })
```

A library's theme fills in each font and color the document's own theme leaves blank, and the
`theme` option of `DocumentStyles` fills in what both leave blank. Among libraries, the first one's
theme wins.

A theme's `dark` colors, used in dark mode, and its `named` colors, colors under names of your
own, are filled in the same way, key by key.

A library theme that is not a valid `DocumentTheme` is ignored.
[Which theme a document is drawn in](/features/document-styles/themes#which-theme-a-document-is-drawn-in) lists the
fields of a `DocumentTheme`, and has the whole order.

## A library of your own

Anything with a `getStyles()` method is a `StyleLibrary`, so styles kept in your own store can be
a library without `styleLibrary()`. Here `cache` stands for your own store, which emits `'change'`:

```js
const library = {
  scope: 'workspace',
  getStyles: () => cache.styles,
  getTheme: () => cache.theme,
  subscribe: listener => cache.on('change', listener),
}
```

A `StyleLibrary` has these members:

| Member                        | Required | Description                                                                                          |
| ----------------------------- | -------- | ---------------------------------------------------------------------------------------------------- |
| `library.getStyles()`         | Yes      | Its definitions                                                                                      |
| `library.scope`               | No       | The scope its definitions are labeled with                                                           |
| `library.getTheme()`          | No       | Its theme, or `null`                                                                                 |
| `library.subscribe(listener)` | No       | How the editor learns of a change to the styles or the theme. Returns the function that unsubscribes |

After a change, `getStyles()` has to return a new array. The editor compares a library's styles by
array identity to know when to read its defaults, outline levels and Word's built-in names again.

The editor subscribes as its view is made, and unsubscribes as it is destroyed. A library without
`subscribe` is drawn again only once the document's own styles or theme next change. With the
`stylesheet` option off, the editor does not subscribe at all.

When a library calls its listener, the editor draws the styles again. The document does not
change, but the editor dispatches a transaction with no steps and the meta `STYLE_LIBRARY_CHANGED`
set to `true`. Code that lays out the content can check
`transaction.getMeta(STYLE_LIBRARY_CHANGED)` and lay it out again.

Outside an editor, `styleLookupOf(doc, libraries, precedence)` returns a `StyleLookup` for a
document of the editor's schema. Unlike the editor's `stylesOf`, it has Word's styles only when you
pass `wordStyleLibrary()`:

```js
import { styleLookupOf, wordStyleLibrary } from '@tiptap-pro/extension-document-styles'

styleLookupOf(doc, [house, wordStyleLibrary()]).getStyles()
```
