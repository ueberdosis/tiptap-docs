## Quick start

Add the table extension, define a style of kind `'table'` with `tableConditions`, and apply it
with the cursor in a cell. The code shows what differs from the complete editor on
[Install](/features/document-styles/install), which imports `Editor`, `StarterKit`, `TextStyle` and `DocumentStyles`.
Install the table extension first with `npm install @tiptap/extension-table`:

```js
import { TableKit } from '@tiptap/extension-table'

const editor = new Editor({
  element: document.querySelector('#editor'),
  extensions: [StarterKit, TextStyle, TableKit, DocumentStyles],
})

editor.commands.setStyleDefinition({
  id: 'grid-table',
  name: 'Grid Table',
  kind: 'table',
  props: { borderCollapse: 'collapse' },
  tableConditions: {
    firstRow: { backgroundColor: '#536dfe', color: '#ffffff', fontWeight: 700 },
    lastRow: { borderTop: '2px solid #536dfe', fontWeight: 700 },
    oddRows: { backgroundColor: '#eef1ff' },
  },
})

editor.commands.applyStyle('grid-table') // the table around the cursor
```

A new table shows no total row, so `lastRow` shows nothing until
`editor.commands.setTableLook({ lastRow: true })`, as
[Which parts a table shows](/features/document-styles/tables#which-parts-a-table-shows) describes. Applying the style takes off
the table's [overrides](/features/document-styles/applying#overrides), the values set on the table itself.

The example needs no options, because `types` and `tableTypes`, the table types whose parts a
table style formats, include `table` by default, as [Options](/features/document-styles/options) lists. A style of kind
`'table'` needs no `targets`: without a `node` target, it goes on a type of `tableTypes`.

A table type also needs `tableRole: 'table'` in its node type's spec, or its parts are not drawn.
The table extension sets it, so TableKit's `table` has it.

## Which parts a table shows

A table keeps which parts of its style it shows in its `styleLook` attribute, as Word's Table
Style Options do. `setTableLook()` changes it for the table around the cursor:

```js
editor.commands.setTableLook({ lastRow: true, bandedRows: false })
```

The keys of a `TableLook`, all `boolean`, default to what a new table in Word shows:

| Key             | Default | What it shows                                 |
| --------------- | ------- | --------------------------------------------- |
| `firstRow`      | `true`  | The header row, the `firstRow` condition      |
| `lastRow`       | `false` | The total row, the `lastRow` condition        |
| `firstColumn`   | `true`  | The `firstColumn` condition                   |
| `lastColumn`    | `false` | The `lastColumn` condition                    |
| `bandedRows`    | `true`  | The `oddRows` and `evenRows` conditions       |
| `bandedColumns` | `false` | The `oddColumns` and `evenColumns` conditions |

The table stores only what differs from the defaults, and `null` once nothing does. `getHTML()`
writes it as JSON in `data-tt-style-look` and reads it back, so a copy and paste keeps it.
`tableLookOf(value)` reads a stored look, with `DEFAULT_TABLE_LOOK` filling in a key that is
missing or not a boolean.

## Conditional formats

A table style's `props` format the table element itself. Its `tableConditions` format the cells
of each part, where the table's look shows that part:

| Condition                           | The cells                               |
| ----------------------------------- | --------------------------------------- |
| `firstRow`                          | Of the header row                       |
| `lastRow`                           | Of the total row                        |
| `firstColumn`, `lastColumn`         | Of the first and the last column        |
| `oddRows`, `evenRows`               | Of the row bands, the first band odd    |
| `oddColumns`, `evenColumns`         | Of the column bands, the first band odd |
| `topLeftCell`, `topRightCell`       | The corners of the header row           |
| `bottomLeftCell`, `bottomRightCell` | The corners of the total row            |

The row bands count the rows between the header row and the total row, so the first row under the
header is odd. Without a header row, the table's first row is the first odd band. Column bands
skip the first and last column where the look shows them, and count the same way.

Where parts set the same property for one cell, the later part in this order wins: column bands,
row bands, first and last column, header and total row, corners. `TABLE_CONDITIONS` lists them in
that order.

So in a band row, a first-column cell gets the column's background where the column sets one, and
the band's where it does not.

Some cells are in a part you might not expect:

| Cell                                              | Is in                              |
| ------------------------------------------------- | ---------------------------------- |
| A cell that spans the last row or the last column | That row or column                 |
| The row of a table of one row                     | The header row, not the total row  |
| The column of a table of one column               | The first column, not the last     |
| A corner cell whose row or column the look hides  | The part that shows, and no corner |

Conditions are inherited through `basedOn` condition by condition, value by value, and `null`
removes an inherited value. `resolveStyle` answers them as `result.style.tableConditions`.

A condition name not in `TABLE_CONDITIONS` is ignored. A condition that is not a set of style
values makes the definition invalid, and `setStyleDefinition` returns `false`.

The formats are drawn on the cell, so they reach its text only by inheritance. A property the
paragraph's own or default style sets wins in the text. Word's Normal sets `fontFamily`,
`fontSize` and `lineHeight`, so a `fontSize` in `firstRow` does not show over it.

[Tables in the editor](/features/document-styles/how-it-works#tables-in-the-editor) lists the attributes the editor
marks each cell with, and how to draw the formats yourself.

## Bands of more than one row

`tableBands` says how many rows and how many columns make one band:

```js
editor.commands.setStyleDefinition({
  id: 'ledger',
  name: 'Ledger',
  kind: 'table',
  basedOn: 'grid-table',
  tableBands: { rows: 2 }, // two rows shaded, two rows not
})
```

The keys of `TableBands`:

| Key       | Type     | Default | Description                     |
| --------- | -------- | ------- | ------------------------------- |
| `rows`    | `number` | `1`     | How many rows one band spans    |
| `columns` | `number` | `1`     | How many columns one band spans |

Bands are inherited through `basedOn` count by count. A number of one or more that is not whole
is rounded down, so `2.5` is `2`. A value that is not a number, not finite or below `1` is
ignored. `resolveStyle` answers the bands as `result.style.tableBands`.

## The cursor in a cell

With the cursor in a cell, the selection is in the paragraph there, not in the table. So a
command acts on the table or the paragraph depending on what it is for:

- **A table style** applied from a cell goes on the table around it, the innermost one in nested
  tables.
- **A paragraph style** applied in a cell goes on the paragraph.
- **`removeStyle`, `setStyleOverride`, `unsetStyleOverride`, `clearStyleOverrides` and
  [`detachStyle`](/features/document-styles/applying#detachstyle)** act on that paragraph. They leave the table's style
  alone, even where the paragraph has none.
- **`removeTableStyle()`** takes the table's style off.

`tableStyleAt(selection, tableTypes)` reads the style of the innermost table around the
selection's start. It is `null` where the table has none, or the selection is in no table:

```js
import { tableStyleAt } from '@tiptap-pro/extension-document-styles'

tableStyleAt(editor.state.selection, ['table']) // 'grid-table'
```

## A table split across pages

Page Layout, the extension that shows a document on pages, sets these two options for you, as
[Table styles across pages](/features/page-layout/extension-behavior/document-styles#table-styles-across-pages)
describes. Set them yourself only for a view of your own that splits a table into pieces, such as
one per page:

| Option                | Type                          | Default | Description                                                                                                                     |
| --------------------- | ----------------------------- | ------- | ------------------------------------------------------------------------------------------------------------------------------- |
| `continuesNode`       | `((node) => boolean) \| null` | `null`  | Answers `true` for a piece that continues the one before: a table, or the first row of one for a row divided between two pieces |
| `repeatedRowSelector` | `string \| null`              | `null`  | The CSS selector of a row drawn as a copy of the header row at the top of a piece                                               |

With `continuesNode`, the pieces count as one table:

- **The bands** go on counting from the piece before. A row divided between two pieces counts once.
- **The header row** is the first piece's first row only.
- **The total row** is in the last piece only.
- **The style and look** of the first piece apply to every piece.

The row `repeatedRowSelector` matches gets the header row's format. Its first cell also gets
`topLeftCell` where the look shows a first column, and its last cell `topRightCell` where it shows
a last column.

The row must be a grandchild of the table element (`table > * > row > cell`), and the table must
carry the `data-tt-table-look` the editor adds.

## Limitations

The rules of a table style win over a style put on a cell itself, where Word lets the cell's
formatting win.

## Commands

These commands act on the innermost table of `tableTypes` around the selection. `applyStyle()`
puts a table style on it, as [Applying styles](/features/document-styles/applying#applystyle) describes.

### removeTableStyle()

Takes the style and every override off the table around the selection. The table keeps its look.

```js
editor.commands.removeTableStyle()
```

Takes no arguments. Returns `false` outside a table of `tableTypes`, and where the table has
neither a style nor an override.

### setTableLook()

Changes which parts of its style the table around the selection shows, and keeps the rest of its
look. See [Which parts a table shows](/features/document-styles/tables#which-parts-a-table-shows).

```js
editor.commands.setTableLook({ lastRow: true, bandedRows: false })
```

Takes one argument, `look`, a `Partial<TableLook>` with the keys to change. It also works on a
table without a style: the look is stored, and nothing is drawn. Returns `false` outside a table
of `tableTypes`, and where the look is already as asked.
