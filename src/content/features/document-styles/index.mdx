## What you get

The extension gives the users of your editor the styles of a word processor, and gives you the
commands to build a style menu on them:

- Word's built-in styles, such as Normal, Title and Heading 1 to 3, ready to apply.
- Paragraph styles for whole blocks, and character styles for a piece of text:
  [Applying styles](/features/document-styles/applying).
- Styles of your own, stored in the document, which inherit from each other and can be the
  default for every paragraph: [Defining styles](/features/document-styles/definitions).
- Table styles with a header row, a total row and banded rows: [Table styles](/features/document-styles/tables).
- A theme of two fonts and twelve colors that styles refer to, and dark mode:
  [Themes](/features/document-styles/themes).
- Every color and font of a document in one list, and one replaced by another everywhere:
  [Colors and fonts](/features/document-styles/values).
- Styles shared from outside the document, such as a house style: [Libraries](/features/document-styles/libraries).
- Clean-up for unused and missing styles, and for formatting that should be a style:
  [Cleaning up](/features/document-styles/cleanup).

## A first look

Install the extension, add it to an editor, and apply one of Word's styles to the paragraph at
the cursor:

```bash
npm install @tiptap-pro/extension-document-styles @tiptap/extension-text-style
```

```js
editor.commands.applyStyle('heading-1')
```

[Install](/features/document-styles/install) has the complete editor, and the setup of Tiptap's private registry that
the package comes from.

## What changes in your editor

Each paragraph, heading, blockquote and table gets two attributes: `styleId`, the id of its
style, and `styleOverrides`, the values that one block sets differently from its style.

The definitions of the document's own styles are stored in the document too, in a hidden node.
So `getJSON()` and `getHTML()` carry the styles, undo takes back a change to a style, and
collaborators share them.

`DocumentStyles` adds that node type to your schema itself, and the editor does not show the
node.

The extension draws the styles with a stylesheet it adds to the web page, so you write no CSS,
and the rules match only elements inside the editor. [How styles are stored and drawn](/features/document-styles/how-it-works)
explains the details.

## Words these pages use

| Word                   | What it means                                                                                         |
| ---------------------- | ----------------------------------------------------------------------------------------------------- |
| Style                  | A named set of values, such as a font and a size, that blocks or text refer to by id                  |
| Definition             | The object that says what a style is called and what it sets, `{ id, name, kind, props }`             |
| Paragraph style        | A style for a whole block, such as a paragraph or a heading                                           |
| Character style        | A style for a piece of text inside a paragraph                                                        |
| Linked style           | A style that can go on a whole block or on a piece of text, such as Word's Title and headings         |
| Table style            | A style for a table, with formats for its header row, total row, columns and bands                    |
| Override               | A value that one block or piece of text sets differently from its style                               |
| Default style          | The style a block without a style of its own is drawn in, such as Normal for paragraphs               |
| Library                | A set of styles from outside the document, read only, such as a house style or Word's built-in styles |
| Theme                  | Two fonts and twelve colors that styles refer to, such as `'theme:accent1'`                           |
| Word's built-in styles | The styles a new Word document starts with, which the extension brings unless you turn them off       |

## Common tasks

The functions and constants in the table, such as `styleLibrary`, `COLOR_PROPS` and
`discoverStyles`, are named exports of `@tiptap-pro/extension-document-styles`:

| Task                                         | How                                                                                                                                                                                                      |
| -------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Apply a style to the paragraph at the cursor | `editor.commands.applyStyle('heading-1')`. See [Applying styles](/features/document-styles/applying)                                                                                                                            |
| Show the style of the selection in a picker  | `editor.getAttributes('paragraph').styleId`. See [A style picker](/features/document-styles/applying#a-style-picker)                                                                                                            |
| List the styles a picker offers              | `editor.storage.documentStyles.catalogOf(editor.state.doc)`. See [A style picker](/features/document-styles/applying#a-style-picker)                                                                                            |
| Set one value of one paragraph               | `editor.commands.setStyleOverride('color', '#c00')`. See [Overrides](/features/document-styles/applying#overrides)                                                                                                              |
| Define a style of your own                   | `editor.commands.setStyleDefinition({ id, name, kind, props })`. See [Defining styles](/features/document-styles/definitions)                                                                                                   |
| Change a style                               | `setStyleDefinition` again, with the values changed. See [Defining styles](/features/document-styles/definitions#change-a-style)                                                                                                |
| Make a style the default for paragraphs      | `defaultFor: ['paragraph']` in its definition. See [The default style](/features/document-styles/definitions#the-default-style)                                                                                                 |
| Change one of Word's styles                  | Word's styles are read only, so copy one with `editor.commands.duplicateStyle('heading-1', 'chapter')` and change the copy. See [Word's styles are read only](/features/document-styles/definitions#words-styles-are-read-only) |
| Style a table                                | A style of kind `'table'` with `tableConditions`. See [Table styles](/features/document-styles/tables)                                                                                                                          |
| Change the theme's colors and fonts          | `editor.commands.setDocumentTheme({ colors: { accent1: '#0f766e' } })`. See [Themes](/features/document-styles/themes)                                                                                                          |
| Draw the document in dark mode               | `DocumentStyles.configure({ colorScheme: 'auto-dark' })`. See [Dark mode](/features/document-styles/themes#dark-mode)                                                                                                           |
| Replace one color everywhere                 | `editor.commands.replaceStyleValue(COLOR_PROPS, '#1e293b', '#1f2937')`. See [Colors and fonts](/features/document-styles/values)                                                                                                |
| Share a house style across documents         | `DocumentStyles.configure({ libraries: [styleLibrary(styles)] })`. See [Libraries](/features/document-styles/libraries)                                                                                                         |
| Use no Word styles                           | `DocumentStyles.configure({ wordStyles: false })`. See [Libraries](/features/document-styles/libraries#words-built-in-styles)                                                                                                   |
| Delete a style and keep how the text looks   | `editor.commands.deleteStyle('lead', { strategy: 'freeze-inline' })` writes its values onto the text as overrides. See [Cleaning up](/features/document-styles/cleanup)                                                         |
| Delete the styles nothing uses               | `editor.commands.removeUnusedStyles()`. See [Cleaning up](/features/document-styles/cleanup#unused-styles)                                                                                                                      |
| Turn formatting set by hand into a style     | `discoverStyles(editor.state.doc)`. See [Cleaning up](/features/document-styles/cleanup#formatting-that-should-be-a-style)                                                                                                      |

Every option is on [Options](/features/document-styles/options), and every command, reader and function on
[API reference](/features/document-styles/api).

## With Page Layout

The extension works in any Tiptap editor. With Page Layout, the extension that shows a document
on pages, a style can also keep a heading on the same page as the paragraph after it.
[Document styles in Page Layout](/features/page-layout/extension-behavior/document-styles)
describes what changes on pages.
