Most editors set the libraries, the use of Word's styles and the color scheme:

```js
import { DocumentStyles, styleLibrary } from '@tiptap-pro/extension-document-styles'

const houseStyle = styleLibrary([
  {
    id: 'body',
    name: 'Body Text',
    kind: 'paragraph',
    defaultFor: ['paragraph'],
    props: { fontSize: 16, lineHeight: 1.6 },
  },
])

DocumentStyles.configure({
  libraries: [houseStyle],
  wordStyles: { defaults: false },
  colorScheme: 'auto-dark',
})
```

`styleLibrary` makes a [library](/features/document-styles/libraries), a read-only set of styles from outside the
document. Body Text is a style for whole blocks, `kind: 'paragraph'`, and `props` holds its
values. [Definition fields](/features/document-styles/definitions#definition-fields) lists every field.

`defaultFor` makes Body Text the style of a paragraph without one. Word's styles can still be
applied, and colors turn dark when the user's system is dark. [Install](/features/document-styles/install) has the
complete editor.

## wordStyles

Defaults to `true`. Word's built-in styles, such as Normal, Title and Heading 1 to 3, come with the
editor as a library, so the user has styles to apply before you define any.
[Word's built-in styles](/features/document-styles/libraries#words-built-in-styles) lists them.

| Value                 | What the editor gets                                         |
| --------------------- | ------------------------------------------------------------ |
| `true`                | Word's styles, and Normal and the headings as default styles |
| `{ defaults: false }` | Word's styles to apply, but no default styles from them      |
| `false`               | None of Word's styles                                        |

With `true`, a paragraph without a style is drawn in Normal, and a heading in Heading 1, 2 or 3 by
its level. Word's library has Heading 1 to 3 only, so a heading of level 4 to 6 is drawn in no
style.

Use `{ defaults: false }` for content that was laid out without Word's styles.

Word's library comes after the `libraries` you configure, so a library that defines `normal` or
`heading-1` wins over it. Word's Normal, No Spacing, Title and Subtitle go on the `paragraph`
type.

Some of Word's styles need a type the editor may not style:

- The quotes are left out if `types` has no `blockquote`.
- The headings are left out if `types` has no `heading`.
- The character styles are left out if `markTypes` is empty.

## partialSelection

Defaults to `'apply-as-mark'`. This option decides where `applyStyle` puts a linked style when the
user selects part of a paragraph's text. A linked style, such as Word's Title or Heading 1, can go
on a whole block or on a piece of text:

| Value              | What `editor.commands.applyStyle()` does |
| ------------------ | ---------------------------------------- |
| `'apply-as-mark'`  | Puts the style on the selected text      |
| `'apply-to-block'` | Puts the style on the whole paragraph    |
| `'reject'`         | Changes nothing and returns `false`      |

At the caret, or with whole blocks selected, a linked style goes on the block. One call chooses for
itself with `applyStyle(styleId, { target: 'node' })` or `{ target: 'mark' }`, whatever this
option says. [A style on a block or on text](/features/document-styles/applying#a-style-on-a-block-or-on-text) explains
linked styles.

## onMissingStyle

Defaults to `'preserve-reference'`. This option decides what `applyStyle` does with an id that
neither the document nor a library defines:

| Value                  | What `applyStyle` does                                                                  |
| ---------------------- | --------------------------------------------------------------------------------------- |
| `'preserve-reference'` | Puts the id on the block, which is drawn without a style until something defines the id |
| `'fallback'`           | Applies the style `fallbackStyleId` names instead                                       |
| `'remove'`             | Takes the style and the overrides off what is selected                                  |

With `'fallback'`, `applyStyle` returns `false` when `fallbackStyleId` is `null` or names a style
nothing defines:

```js
DocumentStyles.configure({ onMissingStyle: 'fallback', fallbackStyleId: 'body' })
```

[A style nothing defines](/features/document-styles/applying#a-style-nothing-defines) explains how a document comes to
refer to one.

## transformNodeOnApply

Defaults to `false`, so a style changes how a block looks but not its node type.
`applyStyle('heading-1')` on a paragraph keeps it a `paragraph` and only sets its `styleId`.

Set it to `true` when the node type should follow the style. Applying a style then also turns the
block into the node type the style's `node` field names, so Heading 1 makes the paragraph a
`heading` of level 1:

```js
DocumentStyles.configure({ transformNodeOnApply: true })
```

With `true`, a style's `nextStyle`, the style Enter gives the next paragraph, sets that
paragraph's node type too. And `removeStyle` takes blocks out of a wrapper that a style put them
in, such as a blockquote.

One call chooses for itself with `applyStyle('heading-1', { transformNode: true })`.
[A style that wraps its blocks](/features/document-styles/applying#a-style-that-wraps-its-blocks) explains wrappers.

## colorScheme

Defaults to `'light'`. With a dark color scheme, every color of the document gets a dark
counterpart, so the document can be drawn in dark mode:

| Value                       | Colors are drawn                                                             |
| --------------------------- | ---------------------------------------------------------------------------- |
| `'light'`                   | As they are set                                                              |
| `'auto-dark'`               | Dark when the user's system is dark                                          |
| `{ darkSelector: '.dark' }` | Dark where the selector matches the editor's element or an element around it |

[Dark mode](/features/document-styles/themes#dark-mode) explains where the dark colors come from. A `darkSelector` that
is empty, or contains `{`, `}`, `;`, `<`, `>` or `/*`, is ignored, and the editor follows the
system as with `'auto-dark'`.

`printColorScheme` decides what print and a PDF made in the browser get with a dark color scheme.
Its default `'light'` adds a `@media print` rule with `color-scheme: light !important`, since paper
is white. `'screen'` prints what the screen shows:

```js
DocumentStyles.configure({ colorScheme: { darkSelector: '.dark' }, printColorScheme: 'screen' })
```

## directFormatting

Defaults to `DIRECT_FORMATTING`, the rules for Tiptap's own formatting extensions. A rule says how
an extension stores one style value: Color as the `color` attribute of the `textStyle` mark, Bold
as a mark of its own that stands for `fontWeight: 700`.

To add a rule for a formatting extension of your own, spread `DIRECT_FORMATTING` into the list,
which replaces the default one. Here `smallCaps` is a mark your editor has:

```js
import { DIRECT_FORMATTING, DocumentStyles } from '@tiptap-pro/extension-document-styles'

DocumentStyles.configure({
  directFormatting: [
    ...DIRECT_FORMATTING,
    { prop: 'fontVariant', mark: 'smallCaps', value: 'small-caps' },
  ],
})
```

[Tiptap's own formatting](/features/document-styles/values#tiptaps-own-formatting) lists the fields of a rule, with an
example for a mark attribute and a block attribute, and what reads the rules.

## continuesNode

Defaults to `null`, which fits an editor that shows each table whole. Page Layout, the extension
that shows a document on pages, sets this option and `repeatedRowSelector` for you, as
[Document styles in Page Layout](/features/page-layout/extension-behavior/document-styles)
describes.

An editor that splits a table into pieces, such as one per page, sets a function of the node. It
returns `true` for a piece that continues the one before it: a table, or the first row of a table
when a row is divided between two pieces.

A table style then formats the pieces as one table, as
[A table split across pages](/features/document-styles/tables#a-table-split-across-pages) explains.

## repeatedRowSelector

Defaults to `null`. Page Layout sets it for you, as [continuesNode](/features/document-styles/options#continuesnode) describes.

An editor that repeats a table's header row at the top of each piece sets the CSS selector of the
repeated row. A table style then formats that row as its header row. A selector that is empty, or
contains `{`, `}`, `;`, `<`, `>` or `/*`, is ignored.
