A theme can also name colors of your own, and say what its colors become in dark mode.

## Quick start

A style is a named set of values, such as a font and a color, and it refers to the theme with a
value such as `'theme:accent1'`. Define a style in the theme's heading font and first accent
color, put it on the selected paragraphs, then store a theme:

```js
editor.commands.setStyleDefinition({
  id: 'chapter',
  name: 'Chapter',
  kind: 'paragraph',
  props: { fontFamily: 'theme:major', color: 'theme:accent1', fontSize: 28 },
})

editor.commands.applyStyle('chapter')

editor.commands.setDocumentTheme({
  name: 'Ocean',
  fonts: { major: 'Georgia, serif' },
  colors: { accent1: '#0f766e' },
})
```

`kind: 'paragraph'` makes a style for whole blocks, and [`applyStyle`](/features/document-styles/applying#apply-a-style)
puts it on them. `editor` is the editor of the complete example on [Install](/features/document-styles/install). The
Chapter paragraphs are drawn in Georgia and teal.

Word's built-in styles refer to the theme too, Normal to `theme:minor` and the headings to
`theme:major`, so a new theme restyles them as well. The extension writes the CSS for the theme,
so you add none. [Themes in CSS](/features/document-styles/how-it-works#themes-in-css) has the details.

## Dark mode

Set the `colorScheme` option, and every color of the document gets a dark counterpart. The
browser shows it when the editor's element is dark by its CSS `color-scheme`:

```js
DocumentStyles.configure({
  colorScheme: 'auto-dark', // color-scheme: light dark, so it follows the user's system
  // colorScheme: { darkSelector: '.dark' }, // dark where .dark is on the editor or around it
})
```

The default, `'light'`, draws every color as it is set and writes no `color-scheme`.
[colorScheme](/features/document-styles/options#colorscheme) has every value.

You do not have to pick the dark colors. Each color is turned dark for you: its lightness is
inverted and its hue stays, so an accent stays the accent and black text becomes light text.

A [tint or shade](/features/document-styles/themes#tints-and-shades) turns the other way, so `theme:accent1/+80`, a pale accent
behind a heading, becomes a deep one rather than a glaring one.

To pick the dark colors of the theme yourself, give the theme a `dark` field, color by color. The
colors it leaves out are derived:

```js
editor.commands.setDocumentTheme({
  name: 'Ocean',
  colors: { accent1: '#0f766e', light2: '#e6f4f1' },
  dark: { accent1: '#5eead4', light2: '#12302c' },
})
```

Some colors stay as they are set:

- **A CSS color name or keyword**, such as `red`, `transparent` or `currentColor`. Only hex values
  and `rgb()`, `hsl()`, `hwb()`, `lab()`, `lch()`, `oklab()`, `oklch()` and `color()` are derived.
- **A shorthand.** Only a property whose CSS name ends in `color` gets a counterpart, so
  `background` and `border` stay.
- **The editor's background.** It is yours to set. `light-dark()` in your CSS reads the same
  `color-scheme`, so `background: light-dark(white, #16181d)` on `.tiptap` follows along.
- **The document.** Its JSON and `data-tt-style-overrides` keep each color as set. Only an
  override's inline CSS carries `light-dark()`.

A color set with Tiptap's Color, BackgroundColor or Highlight extension gets its counterpart too.
The editor draws it over the text without storing it, so `getHTML()` has none of it. Where the
text's override sets the same property, the override's counterpart is drawn instead.

Print, and a PDF made in a browser, stay light, since paper is white. The `printColorScheme`
option changes that, as [colorScheme](/features/document-styles/options#colorscheme) shows.

For code that writes CSS of its own:

- **`darkColorCss(color)`** returns the derived CSS, such as
  `oklch(from #156082 calc(0.95 - 0.75 * l) c h)`. The lightness in OKLCH, a CSS color space,
  turns round: black becomes 0.95, white 0.2 and the middle 0.575. Hue and chroma stay.
- **Each theme color** is kept in `--tt-document-styles-theme-accent1-light` and `-dark`, and
  `--tt-document-styles-theme-accent1` is `light-dark()` of both. A named color is kept the same
  way, as `--tt-document-styles-named-brandRed`. Fonts are written once.
- **`styleDeclarations(props, { dark: true })`** writes a style's values with `light-dark()`
  counterparts. See [Your own CSS](/features/document-styles/how-it-works#your-own-css).

Dark mode needs a browser that supports `light-dark()` and CSS relative colors.

## Referring to the theme

A value of the form `theme:<name>` refers to the theme wherever a font or a color goes. That is a
style's `props`, a table style's [conditional formats](/features/document-styles/tables#conditional-formats) for parts
such as the header row, and an [override](/features/document-styles/applying#overrides).

An override is a value one block or piece of text sets apart from its style. These are the names:

| Value                                                        | What it refers to                                                                                                 |
| ------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------- |
| `theme:major`, `theme:minor`                                 | The font for headings and the font for body text                                                                  |
| `theme:dark1`, `theme:light1`, `theme:dark2`, `theme:light2` | Text and background colors, in two strengths. `text1`, `background1`, `text2` and `background2` are the same four |
| `theme:accent1` to `theme:accent6`                           | The six accent colors                                                                                             |
| `theme:hyperlink`, `theme:followedHyperlink`                 | The colors of a link and of one that was followed                                                                 |

The names are the ones a .docx file uses. For a picker, `THEME_COLORS` lists the twelve color
names in the order of Word's color picker, without the aliases, and `THEME_FONTS` is
`['major', 'minor']`. The types `ThemeColor` and `ThemeFont` are the union of those names.

- **A name no theme has**, such as `theme:accent9`, writes no CSS, so the property is drawn as if
  the style did not set it.
- **A shorthand such as a border.** A reference has to be the whole value, so
  `'4px solid theme:accent1'` is not one. Write the color on its own property:

```js
props: { borderLeft: '4px solid', borderLeftColor: 'theme:accent1' }
```

## Tints and shades

A theme color can be lighter or darker by a share, as every row of Word's color picker after the
first is. `theme:accent1/+40` is _Lighter 40%_, and `theme:accent1/-25` is _Darker 25%_.

Here a table style's header row is in the accent, and every other row in a pale tint of it:

```js
tableConditions: {
  firstRow: { backgroundColor: 'theme:accent1', color: 'theme:light1' },
  oddRows: { backgroundColor: 'theme:accent1/+80' },
}
```

The share is a whole number from 1 to 99, with its sign. So `theme:accent1/40`, `/+0`, `/+100`
and a font's `theme:major/+40` are no references, and write no CSS.

A tint keeps the hue and saturation and changes the lightness, as Word does. _Lighter N%_ is the
lightness times (100 - N)/100, plus N, and _Darker N%_ the lightness times (100 - N)/100.

The browser computes it from the theme color, as
`hsl(from var(--tt-document-styles-theme-accent1) h s calc(l * 0.6 + 40))`, so a tint follows the
theme. It needs a browser that supports CSS relative colors.

To build or read such a value in code, such as for a color picker:

```js
import { themeColorValue, themeReferenceOf } from '@tiptap-pro/extension-document-styles'

themeColorValue('accent1', { lighter: 40 }) // 'theme:accent1/+40'
themeColorValue('accent1', { darker: 25 }) // 'theme:accent1/-25'
themeReferenceOf('theme:text1/-25') // { kind: 'color', name: 'dark1', darker: 25 }
```

- **`themeColorValue(name, { lighter, darker })`** gives the plain `'theme:<name>'` for a share
  that is missing, not whole or outside 1 to 99. Given both, it writes `lighter`.
- **`themeReferenceOf(value)`** returns a `ThemeReference`, `{ kind: 'font', name }` or
  `{ kind: 'color', name, lighter?, darker? }`. An alias reads as the name it stands for. Any other
  value, a `named:` value or a number included, gives `null`.

## Which theme a document is drawn in

The `theme` option is your integration's theme, a `DocumentTheme`, and `null` by default:

```js
import { DocumentStyles } from '@tiptap-pro/extension-document-styles'

DocumentStyles.configure({
  theme: { name: 'House', fonts: { major: 'Inter, sans-serif' }, colors: { accent1: '#536dfe' } },
})
```

A document is drawn in four layers, font by font and color by color, and the first that sets one
wins:

1. The document's own theme, which [`setDocumentTheme()`](/features/document-styles/themes#setdocumenttheme) stores.
2. The theme of a [library](/features/document-styles/libraries#a-librarys-theme), a read-only set of styles you pass
   in the `libraries` option. The first library's wins over later ones'.
3. The `theme` option.
4. Word's _Office_ theme, `OFFICE_THEME`, a frozen `ResolvedTheme`. [Constants](/features/document-styles/api#constants)
   lists its values.

With the `precedence: 'libraries'` option, the libraries' themes and the `theme` option win over
the document's own. See [Which definition wins](/features/document-styles/libraries#which-definition-wins).

A layer's blank font or color is ignored, and the layer under it shows through. So is a color
under a name no theme has, such as `colors: { accent9 }`, while the rest of that theme is used.

The `name` is the one of the highest layer that has one, else `'Office'`.

The `theme` option is read once, when the editor is created, so changing it needs a new editor. A
library's `setTheme(theme)` redraws the editor at once.

The editor's storage answers which theme a document is drawn in:

```js
const theme = editor.storage.documentStyles.themeOf(editor.state.doc)

theme.name // 'Ocean'
theme.colors.accent1 // '#0f766e'
theme.fonts.minor // 'Aptos, Calibri, Arial, sans-serif', from Office
```

It returns a `ResolvedTheme`: a `name`, both `fonts`, all twelve `colors`, the `dark` colors a
layer names, and the `named` colors of every layer. Without an editor,
`resolveTheme(doc, theme, precedence, libraries)` does the same, and `documentThemeOf(doc)` returns
only what the document stores, or `null`.

A `DocumentTheme`, what you store or configure, has these fields, all optional:

| Field    | Type                                  | Description                                                       |
| -------- | ------------------------------------- | ----------------------------------------------------------------- |
| `name`   | `string`                              | What a picker shows                                               |
| `fonts`  | `Partial<Record<ThemeFont, string>>`  | `major` and `minor`                                               |
| `colors` | `Partial<Record<ThemeColor, string>>` | The twelve colors                                                 |
| `dark`   | `Partial<Record<ThemeColor, string>>` | The colors in [dark mode](/features/document-styles/themes#dark-mode), used only there            |
| `named`  | `NamedColors`                         | Colors under names of your own. See [Named colors](/features/document-styles/themes#named-colors) |

`isDocumentTheme(value)` checks that `name` is a string, that `fonts`, `colors` and `dark` are
records of strings, and that `named` is a record. A stored value that fails it reads as `null`.

## Tying a color to the theme

To tie a fixed color to the theme, as Word does, make it one of the twelve theme colors. Then
replace it with a reference to that theme color everywhere. `COLOR_PROPS` is the list of
properties a color is set in:

```js
import { COLOR_PROPS, documentThemeOf } from '@tiptap-pro/extension-document-styles'

const own = documentThemeOf(editor.state.doc) ?? {}
editor
  .chain()
  .setDocumentTheme({ ...own, colors: { ...own.colors, accent3: '#0f766e' } })
  .replaceStyleValue(COLOR_PROPS, '#0f766e', 'theme:accent3')
  .run()
```

`setDocumentTheme` replaces the whole stored theme, so the example spreads the document's own
theme to keep the rest. [`replaceStyleValue`](/features/document-styles/values#replacing-a-value) does the replacing.

The twelve theme colors cannot be renamed, and whatever referred to `accent3` before is drawn in
the new color too. For a color under a name of its own, use a [named color](/features/document-styles/themes#named-colors).

## Named colors

A theme can name colors beyond its twelve, as many as it needs, such as _Brand Red_. A style or an
override refers to one as `named:<key>`, so changing the color changes everything that refers to
it:

```js
import { COLOR_PROPS, namedColorValue } from '@tiptap-pro/extension-document-styles'

editor.commands.setNamedColor('brandRed', { name: 'Brand Red', color: '#c00000' })

editor.commands.setStyleDefinition({
  id: 'alert',
  name: 'Alert',
  kind: 'character',
  props: { color: 'named:brandRed' },
})

// Every #c00000 the document uses, as a reference to it
editor.commands.replaceStyleValue(COLOR_PROPS, '#c00000', namedColorValue('brandRed'))
```

A `NamedColor` has these fields:

| Field   | Type     | Description                                                                        |
| ------- | -------- | ---------------------------------------------------------------------------------- |
| `name`  | `string` | What a picker shows, `Brand Red`                                                   |
| `color` | `string` | The color, `#c00000`. Not blank                                                    |
| `dark`  | `string` | Optional. The color in [dark mode](/features/document-styles/themes#dark-mode). Derived from `color` when left out |

The key is the id the references use. It is letters, digits and inner hyphens, starting with a
letter: `brandRed`, `brand-red-2`. A named color takes tints and shades as a theme color does,
`named:brandRed/+40`.

Every layer of the theme can name colors in its `named` field, a `NamedColors` record by key. They
are layered key by key, in the same order as the fonts and colors, and a higher layer replaces
the whole entry of a key.

So a [library's theme](/features/document-styles/libraries#a-librarys-theme) brings the organization's colors to every
document, as `styleLibrary(houseStyles, { theme: { named: { brandRed } } })`, and a document adds
its own.

The document's named colors are kept apart from the rest of its theme. `setDocumentTheme`, even
with `null`, keeps them, and a theme that names colors lays them over the document's and removes
none.

Named colors survive `getHTML()` and a reload, and a stored entry with an invalid key or value is
left out when read.

A reference that cannot be drawn leaves the CSS property unset, so a text color is inherited from
around it and a background is transparent. That happens for a key no layer has.

It also happens for a `color` that cannot be written: a `theme:` or `named:` value, or a string
that [the stylesheet leaves out](/features/document-styles/how-it-works#how-a-value-becomes-css), such as one with `;`.
A `dark` that cannot be written is derived from `color` instead.

For a picker, these functions read and write named colors. [Themes and colors](/features/document-styles/api#themes-and-colors)
has their signatures:

- **`namedColorValue(key, { lighter, darker })`** writes a reference, `'named:brandRed/+40'`. It
  does not check the key, and gives the plain reference for a share outside 1 to 99.
- **`namedColorReferenceOf(value)`** reads one as a `NamedColorReference`,
  `{ key, lighter?, darker? }`, or `null` for an invalid key and a share of 0.
- **`namedColorsOf(doc)`** returns the document's own named colors, and `themeOf(doc).named`
  those of every layer.
- **`themeValueOf(theme, 'named:brandRed')`** returns the color it is drawn in, tint applied, or
  the value unchanged where no layer has the key.
- **`setNamedColorTransaction(tr, key, color)`** writes a color into a transaction, or takes it
  off with `null` and leaves the references. It throws for an invalid key or color.

## Standard colors

`WORD_STANDARD_COLORS` is the row of ten fixed colors under the theme colors in Word's color
picker, from Dark Red to Purple. Each entry is a `WordStandardColor`, `{ name, value }`, and
[Constants](/features/document-styles/api#constants) lists them all:

```js
import { WORD_STANDARD_COLORS } from '@tiptap-pro/extension-document-styles'

WORD_STANDARD_COLORS[0] // { name: 'Dark Red', value: '#c00000' }
```

They do not change with the theme and have no tints or shades, since Word offers none. A picker
writes the hex value.

## Commands

These commands change the theme the document stores, so the change is saved, undone and shared
with the document.

### setDocumentTheme()

Stores a theme in the document in place of the one it had, or takes it off with `null`, so the
configured theme draws again.

```js
editor.commands.setDocumentTheme({ colors: { accent1: '#aa0000' } })
editor.commands.setDocumentTheme(null)
```

It takes the theme:

| Argument | Type                    | Description                                       |
| -------- | ----------------------- | ------------------------------------------------- |
| `theme`  | `DocumentTheme \| null` | The theme, or `null` for the configured one again |

The document's [named colors](/features/document-styles/themes#named-colors) stay unless the new theme names the key. The theme
is stored with the style definitions, as [What is stored](/features/document-styles/how-it-works#what-is-stored) and
[Saving, undo and collaboration](/features/document-styles/how-it-works#saving-undo-and-collaboration) describe.

Returns `false` for a value that is not a theme, and where the document already has that theme.
`setDocumentThemeTransaction(tr, theme)` writes the same into a transaction of your own. It throws
for a value that is not a theme, and does not check for the same theme.

### setNamedColor()

Stores a named color in the document's own theme, in place of the one under that key. The rest of
the theme stays.

```js
editor.commands.setNamedColor('brandRed', { name: 'Brand Red', color: '#c00000', dark: '#ff8080' })
```

It takes the key and the color:

| Argument | Type         | Description                              |
| -------- | ------------ | ---------------------------------------- |
| `key`    | `string`     | What a value refers to, as `named:<key>` |
| `color`  | `NamedColor` | See [Named colors](/features/document-styles/themes#named-colors)        |

Returns `false` for an invalid key, a value that is not a named color, and the same color already
under the key.

### removeNamedColor()

Takes a named color off the document's own theme.

```js
editor.commands.removeNamedColor('brandRed')
```

It takes the key:

| Argument | Type     | Description     |
| -------- | -------- | --------------- |
| `key`    | `string` | The color's key |

What happens to the references depends on the other layers:

- **A library or the `theme` option names the key.** References stay, drawn in that layer's color.
- **No layer names it.** Each reference becomes the color it was drawn in, tints included, so
  `named:brandRed/+40` becomes `#ff4040`. That happens in `COLOR_PROPS` of the document's own
  styles, in overrides, and in [Tiptap's own formatting](/features/document-styles/values#tiptaps-own-formatting), such
  as a color set with `setColor`.
- **References in a library's styles, or in other properties**, stay as they are, and draw no
  color until a layer names the key again.

Returns `false` where the document's own theme has no color under the key.
