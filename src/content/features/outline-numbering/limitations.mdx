## Two people setting the scheme at once

The stored scheme is one attribute on one node, so the last write wins whole. When one person
changes level 2 and another changes level 3 at the same moment, only one of the changes stays.

## A second scheme node

When two documents with a stored scheme each are combined, the document holds two scheme nodes.
The first one counts. The second is ignored, and nothing removes it.

## Typing over a heading and the next block

Typing over a selection from a heading's first character into the next block keeps the heading,
while Word deletes it. Backspace, Delete and Cut delete the heading whole, as
[Deleting a numbered heading](/features/outline-numbering/display#deleting-a-numbered-heading) says.

## A cut as plain text

A cut from a heading's first character into the next block can put plain text without the
heading's number on the clipboard. With [Whole blocks](/features/whole-blocks)
registered, the number is in the text.

## The copy attribute in the JSON

Each node of a registered type carries `copiedOutlineLabel: null` in its JSON, because the copy
marks a heading with a schema attribute. See [Copy and paste](/features/outline-numbering/display#copy-and-paste).

## Copied HTML loaded as content

HTML copied out of an editor and loaded with `setContent` or `insertContent` keeps the number in
the heading's text, and keeps `copiedOutlineLabel` set. Only a paste takes the number out.

## setOutlineLevel on a scheme with a broken level

When the stored scheme has a level that is not a template, such as one written by hand,
`setOutlineLevel` throws an error instead of returning `false`. Replace the whole scheme with
[setOutlineLevels()](/features/outline-numbering/scheme#setoutlinelevels) to repair it.
