## The stylesheet

The extension does not add its CSS to the page, so without it the numbers are counted but not
drawn. `mountOutlineStyles` adds the rules once, at the end of the page's `head`:

```js
import { mountOutlineStyles } from '@tiptap-pro/extension-outline-numbering'

mountOutlineStyles(document)
```

When your page has a Content Security Policy, pass the nonce it requires on style elements. That is
the nonce you give the editor as its `injectNonce` option:

```js
mountOutlineStyles(document, { nonce })
```

`nonce` stands for your own nonce value. The second argument takes these options:

| Option  | Type     | Default                             | Description                                                         |
| ------- | -------- | ----------------------------------- | ------------------------------------------------------------------- |
| `nonce` | `string` | none                                | The nonce your Content Security Policy asks of a style element      |
| `id`    | `string` | `'tiptap-outline-numbering-styles'` | The style element's id. A second call with the same id adds nothing |

`outlineStyleRules()` takes no arguments and returns the same rules as a string. Use it instead
of `mountOutlineStyles` to put the rules into a stylesheet of your own or a build step.

The rules print the number with the `::before` pseudo-element of the numbered node. A heading's
number stands in front of its text, followed by a gap. The number of a
[clause](/features/outline-numbering/clauses), a numbered list item, stands in the margin before it, the same gap away.

## Custom properties

Set these on the editor to change how the numbers look:

```css
.tiptap {
  --tt-outline-number-color: #6b7280;
  --tt-outline-number-gap: 0.75em;
}
```

| Custom property                    | Default         | Description                                      |
| ---------------------------------- | --------------- | ------------------------------------------------ |
| `--tt-outline-number-gap`          | `0.5em`         | The gap between the number and the text          |
| `--tt-outline-number-color`        | `inherit`       | The number's color                               |
| `--tt-outline-list-indent`         | `2.5em`         | The indent of a [list of clauses](/features/outline-numbering/clauses)    |
| `--tt-outline-selected-background` | `Highlight`     | The background of a numbered node selected whole |
| `--tt-outline-selected-color`      | `HighlightText` | Its text color                                   |

A numbered node selected as a whole, such as after a click on its number, gets the editor's
`ProseMirror-selectednode` class. `--tt-outline-selected-background` and
`--tt-outline-selected-color` color it.

## Attributes

A numbered node gets these attributes in the editor. `getHTML()` and `getJSON()` do not contain
them, because they are not in the document:

| Attribute                | Constant                   | Value                                        |
| ------------------------ | -------------------------- | -------------------------------------------- |
| `data-tt-outline-number` | `OUTLINE_NUMBER_ATTRIBUTE` | The label, such as `1.2`                     |
| `data-tt-outline-level`  | `OUTLINE_LEVEL_ATTRIBUTE`  | The level, such as `2`                       |
| `data-tt-outline-marker` | `OUTLINE_MARKER_ATTRIBUTE` | `gutter`, for a type with `marker: 'gutter'` |

`marker` is set per node type in the `types` option, as
[Choose what is numbered](/features/outline-numbering/what-is-numbered#where-the-number-is-drawn) shows. A level whose
[template](/features/outline-numbering/levels#templates) is `''` gets none of the attributes. CSS of your own can use the attributes, such as
to make the numbers of level 1 bold:

```css
.tiptap [data-tt-outline-level='1']::before {
  font-weight: 700;
}
```

## Deleting a numbered heading

The number cannot be selected on its own, since it is not text. `OutlineNumbering` makes deleting
work the way Word deletes a numbered paragraph, with nothing else to register:

- **A click on the number**, or a triple click in the heading, selects the whole heading. Cut or
  delete it, and the heading is gone, number and all.
- **A selection from the heading's first character into a block after it** deletes the heading
  whole with Backspace, Delete or Cut. The rest of that block keeps its own type, rather than
  becoming a numbered heading.
- **A selection inside the heading's text** deletes the text, and keeps the heading and its
  number.
- **Typing over a selection**, also one from the heading's first character into the next block,
  replaces it the usual way and keeps the heading.

## Copy and paste

A copied heading takes its number along as text, so a heading pasted into an email or another
program reads `1.2 Scope`:

- **A heading counts as copied** when the selection holds it from its first character. When the
  selection begins inside the heading's text, the heading is copied without its number.
- **A clause** takes its number along in front of the text of its first paragraph, such as
  `(a) charge interest`. A clause that does not start with a paragraph is copied without its
  number.
- **Pasted into an editor that has `OutlineNumbering`**, the number is taken out of the text
  again, and the heading is numbered where it lands.
- **A heading whose text really begins with its number** keeps it, because only the number the
  copy added is taken out.

The copied HTML marks each heading with `data-tt-outline-label="1.2"`. To carry that mark, each
node type you register in `types` gets a `copiedOutlineLabel` attribute. It is `null` by default
and a paste sets it back to `null`, so your stored JSON holds `copiedOutlineLabel: null` on these
nodes. That is expected, and you can leave it. `COPIED_LABEL_ATTRIBUTE` is
`'copiedOutlineLabel'`.
