## Registering node types

Each entry of `types` is keyed by a node type's name. StarterKit's heading reads its level from
its own `level` attribute:

```js
import { OutlineNumbering } from '@tiptap-pro/extension-outline-numbering'

OutlineNumbering.configure({
  types: {
    heading: { level: node => node.attrs.level },
  },
})
```

| Field    | Type                                         | Default    | Description                                                 |
| -------- | -------------------------------------------- | ---------- | ----------------------------------------------------------- |
| `level`  | `number \| 'nested' \| (node, context) => …` | `1`        | How deep the node sits. See [Levels](/features/outline-numbering/what-is-numbered#levels)               |
| `marker` | `'inline' \| 'gutter'`                       | `'inline'` | See [Where the number is drawn](/features/outline-numbering/what-is-numbered#where-the-number-is-drawn) |

A type your schema does not have is reported with a console warning when the editor is created.
`OutlineType` is the type of one entry, and `OutlineTypes` the type of the whole option.

## Levels

`level` says how deep a node sits, `1` being the outermost. It is a number, a function or
`'nested'`:

- **A number** puts the nodes of the type at that level. A number that is not a whole number
  from 1, such as `2.4` or `0`, is rounded, and anything below 1 is read as 1.
- **A function** gets the node and a context, `{ ancestors, lookup }`, and returns a number,
  `'nested'` or `null`. `null` leaves that node unnumbered.
- **`'nested'`** numbers the node one level below the last numbered node before it whose level
  is a number. Each `'nested'` node that contains it adds one more level.
  [Lists as clauses](/features/outline-numbering/clauses) are numbered this way.

In the context, `ancestors` are the nodes that contain the node, its top-level block first and its
parent last. `lookup` is what the `lookupOf` option returns, as
[Numbering by style](/features/outline-numbering/what-is-numbered#numbering-by-style) shows. `OutlineTypeContext` is the type of the context,
and `OutlineLevelAnswer` the type of what the function returns.

## Where the number is drawn

`marker` says where the number stands:

- **`'inline'`** draws it in front of the node's text, as for a heading.
- **`'gutter'`** draws it in the margin before the node, outside its text, as for a clause.

`OutlineMarker` is the type of `marker`.

## Numbering by style

A level can come from somewhere other than the node itself, such as a paragraph style that says
where its paragraphs sit in the outline. The `lookupOf` option is a function of the document that
returns an object, and each `level` function gets that object as `lookup`.

[Document styles](/features/document-styles/definitions#outline-levels) gives styles
an outline level and reads it like this:

```js
import { styleOutlineLevelOf, styleOutlineLevels } from '@tiptap-pro/extension-document-styles'
import { OutlineNumbering } from '@tiptap-pro/extension-outline-numbering'

OutlineNumbering.configure({
  lookupOf: doc => styleOutlineLevels(doc, [houseStyle]),
  types: {
    heading: {
      level: (node, { lookup }) => {
        const level = styleOutlineLevelOf(lookup, node)
        return level === undefined ? node.attrs.level : level
      },
    },
    paragraph: { level: (node, { lookup }) => styleOutlineLevelOf(lookup, node) ?? null },
  },
})
```

`houseStyle` stands for your own style library, which `styleLibrary()` of Document styles makes.
See [Libraries](/features/document-styles/libraries).

- **A heading whose style is body text** is left unnumbered, because `styleOutlineLevelOf`
  returns `null` for it.
- **A heading without a style** is numbered by its own level, because `styleOutlineLevelOf`
  returns `undefined` for it.
- **Numbers are counted again** when `lookupOf` returns another object. Return the same object
  for as long as what it holds is the same, as `styleOutlineLevels` does.
- **Without `lookupOf`**, `lookup` is `null`.

## Leaving nodes out

The `ignore` option leaves nodes out of the numbering, such as headings quoted in a blockquote.
It is a function of type `OutlineIgnore` that gets each node and returns what to do with it:

- **`true`** leaves the node unnumbered, and nothing inside it is numbered either.
- **`'descend'`** leaves the node unnumbered, and what is inside it is counted as usual.
- **`false`** counts the node.

```js
OutlineNumbering.configure({
  types: { heading: { level: node => node.attrs.level } },
  ignore: node => node.type.name === 'blockquote',
})
```

Headings inside a blockquote then show no number and do not count, so the next heading after the
quote goes on from the one before it.

`'descend'` is for a node that is the rest of another one, such as the part of a clause that
[Page Layout](/features/page-layout/extension-behavior/outline-numbering)
continues on the next page.

A clause left out with `'descend'` shows no number and no list marker. The clauses nested in it
are still numbered a level below it.
