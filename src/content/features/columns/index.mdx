The text in one column does not flow into the next. For one run of text that fills the first
column to the bottom and carries on at the top of the second, use
[section columns](/features/page-layout/section-columns) in Page Layout,
Tiptap's extension that shows a document on pages.

## Install

Columns is one extension, `Columns`, that you add to the extensions of any Tiptap editor. It
does not need Page Layout.

1. Set up access to Tiptap's private registry, which the package comes from. The
   [private registry guide](https://tiptap.dev/docs/guides/pro-extensions) explains how.
2. Install the package. Its peer dependencies, `@tiptap/core` and `@tiptap/pm`, come with any
   Tiptap editor. The example also uses StarterKit, for the paragraphs and headings in the
   columns:

   ```bash
   npm install @tiptap-pro/extension-columns @tiptap/starter-kit
   ```

3. Add `Columns` to the editor and insert a layout of two columns:

```js
import { Editor } from '@tiptap/core'
import StarterKit from '@tiptap/starter-kit'
import { Columns } from '@tiptap-pro/extension-columns'

const editor = new Editor({
  element: document.querySelector('#editor'),
  extensions: [StarterKit, Columns],
  content: '<p>Notes before the columns.</p>',
})

editor.chain().focus().insertColumns({ count: 2 }).run()
```

The editor shows the paragraph and, below it, two empty columns side by side with the caret in
the first one. The columns have no border, so you see them once there is text in them, or once
you add the outline from [Styling](/features/columns#styling).

## Common tasks

Each call works on the editor from [Install](/features/columns#install). A call that changes a layout acts on the
layout the cursor is in. From a button, chain the call after `focus()`, as in
`editor.chain().focus().addColumn().run()`, so the editor keeps the focus.

| Task                                              | Call                                                                |
| ------------------------------------------------- | ------------------------------------------------------------------- |
| Insert a layout of three columns                  | `editor.commands.insertColumns({ count: 3 })`                       |
| Add a column after the cursor's column            | `editor.commands.addColumn()`                                       |
| Remove the cursor's column and keep its content   | `editor.commands.removeColumn()`                                    |
| Move the cursor's column one place to the right   | `editor.commands.moveColumn('right')`                               |
| Give the layout four columns                      | `editor.commands.setColumnCount(4)`                                 |
| Give two columns the widths one third, two thirds | `editor.commands.setColumnWidths(['1fr', '2fr'])`                   |
| Make the columns equal again                      | `editor.commands.setColumnWidths(null)`                             |
| Change the space between the columns              | `editor.commands.setColumnGap('48px')`                              |
| Put the caret after the layout                    | `editor.commands.exitColumns()`                                     |
| Delete the layout and its content                 | `editor.commands.deleteColumns()`                                   |
| Disable a toolbar button that would do nothing    | `editor.can().addColumn()`, see [Build a toolbar](/features/columns#build-a-toolbar) |
| Outline the column the cursor is in               | The class `tiptap-columns-column-active`, see [Styling](/features/columns#styling)   |
| Allow more than six columns                       | `Columns.configure({ maxColumns: 8 })`, see [Options](/features/columns#options)     |
| Change a layout from your own code                | The transaction functions on [Columns API](/features/columns/api)                  |

## Insert a layout

`insertColumns()` inserts a layout of empty columns after the block the cursor is in, and puts
the caret in the first column. Pass `count` for the number of columns, which defaults to two:

```js
editor.chain().focus().insertColumns({ count: 3 }).run()
```

Where the layout goes depends on the cursor:

- **In an empty paragraph or heading at the top level.** The layout replaces it, so no empty
  line stays above the layout.
- **In a block with content.** The layout goes after the block, at the top level of the
  document. A cursor in a list item puts the layout after the whole list.
- **In a column.** The new layout goes after the layout the cursor is in, not into the column.

Each new column holds one empty block of the schema's default type, which is a paragraph with
StarterKit. A layout is a block, so the user can paste one into a column, and the commands then
act on the inner layout when the cursor is in it. No command puts a layout inside a column.

## Build a toolbar

Each command that changes a layout works on the layout the cursor is in. `editor.can()` asks
whether a command would do anything without running it, so a toolbar can disable the buttons
that would not:

```js
const addButton = document.querySelector('#add-column')

addButton.addEventListener('click', () => editor.chain().focus().addColumn().run())

const updateButton = () => {
  addButton.disabled = !editor.can().addColumn()
}

updateButton()
editor.on('transaction', updateButton)
```

`addColumn()`, `removeColumn()` and `moveColumn()` need the cursor inside a column, because
they act on that column. The other commands, except `insertColumns()`, also work on a layout
selected as a whole, such as one your toolbar selects with Tiptap's `setNodeSelection()`. Each
command returns `false` when it cannot act, and [Commands](/features/columns#commands) lists when that is.

## Widths and the gap

The columns of a layout share its width equally until you give them widths of their own.
`setColumnWidths()` takes one CSS grid track size per column, the kind of value
`grid-template-columns` takes, such as `'1fr'` for one share of the free space or `'240px'`:

```js
editor.commands.setColumnWidths(['1fr', '2fr'])
```

The list needs one width per column, so the command returns `false` for a list of another
length. Adding or removing a column clears the widths, because the old list no longer fits:
`widthMode` becomes `'equal'` and `widths` becomes `null`. `setColumnWidths(null)` makes the
columns equal again yourself.

Moving a column keeps the widths in their places, so the moved column takes the width of its
new place.

The gap is the space between the columns, as a CSS length:

```js
editor.commands.setColumnGap('48px')
```

A new layout gets the `defaultGap` option, `'24px'` unless you set it. A layout stored without
a gap is drawn with `24px`, whatever `defaultGap` says, because the option applies only when a
layout is inserted. To give such a layout another gap, call `setColumnGap()` on it.

`setColumnGap()` takes only a length, so `setColumnGap('24px')` is the way back to the default.

To insert a layout with widths of its own, call `setColumnWidths()` after `insertColumns()`. A
new layout stores no widths, so `widthMode: 'custom'` on its own draws equal columns.

## Keys

The arrow keys and Backspace move the caret from one column into the next, and a shortcut
leaves the layout. `Mod` is `Cmd` on macOS and `Ctrl` elsewhere:

| Key                                                 | What it does                                                                         |
| --------------------------------------------------- | ------------------------------------------------------------------------------------ |
| `Mod-Enter` in a layout                             | Puts the caret after the layout, like `exitColumns()`                                |
| `ArrowLeft` or `Backspace` at the start of a column | Moves the caret to the end of the column before. Backspace deletes nothing there     |
| `ArrowRight` at the end of a column                 | Moves the caret to the start of the next column                                      |
| `ArrowDown` at the end of a column                  | Puts the caret after the layout, when the layout is the last block of the document   |
| `ArrowUp` at the start of a column                  | Puts the caret before the layout, when the layout is the first block of the document |

Backspace never joins two columns into one. Inside a column, every key does what it does
anywhere else in the editor.

## Styling

The extension draws only the grid: the columns side by side, the gap between them, and their
widths. The columns have no border and no background, so their look is yours. This rule
outlines the column the cursor is in:

```css
.tiptap .tiptap-columns-column-active {
  outline: 1px dashed rgba(0, 0, 0, 0.2);
}
```

The elements of a layout carry these classes:

| Selector                        | Element                                                                        |
| ------------------------------- | ------------------------------------------------------------------------------ |
| `.tiptap-columns-layout`        | The layout, also `[data-tt-column-layout]`                                     |
| `.tiptap-columns-column`        | A column, also `[data-tt-column]`                                              |
| `.tiptap-columns-column-active` | The column the cursor is in. The extension sets the class and no styles for it |

The grid comes from CSS rules that the extension adds to the start of the page's `head` when
the editor is created. They use the attribute selectors `[data-tt-column-layout]` and
`[data-tt-column]`, so a rule of yours with a class selector or a stronger one wins over them.

The rules keep each column at its width even with a long word or a wide image in it. Columns of
different length keep their own height.

The layout's element also carries the custom properties `--tt-column-gap` and, while it has
widths of its own, `--tt-column-widths`. They are set in the element's `style` attribute, which
wins over your stylesheet. So use them in your own rules, such as `var(--tt-column-gap)`, and
change the gap and the widths with the commands.

### The grid CSS and a Content Security Policy

The extension adds its rules as a `style` element with the nonce from the editor option
`injectNonce`, so a Content Security Policy that requires a nonce on styles lets them through.
With the editor option `injectCSS: false`, the extension adds no rules, as Tiptap adds none of
its own, and the columns show one below the other. Then add the rules yourself, before or after
creating the editor:

```js
import { mountColumnStyles } from '@tiptap-pro/extension-columns'

mountColumnStyles(document, { nonce: 'your-nonce' })
```

`mountColumnStyles()` adds the rules to the DOM document you pass, such as the document of an
iframe, and does nothing when they are already there. The `nonce` is optional. For a
stylesheet you build yourself, `columnStyleRules()` from the same package returns the rules as
a string.

## What a layout stores

A layout is a `columnLayout` node that holds `column` nodes, two to six by default. A column
holds blocks of any kind, such as paragraphs, headings, a list, a table or an image. This is a
layout of two columns with custom widths in the editor's JSON:

```json
{
  "type": "columnLayout",
  "attrs": { "gap": "32px", "widthMode": "custom", "widths": ["1fr", "2fr"] },
  "content": [
    { "type": "column", "content": [{ "type": "paragraph" }] },
    { "type": "column", "content": [{ "type": "paragraph" }] }
  ]
}
```

The layout keeps its gap and widths in these attributes:

| Attribute   | Type                  | Default   | Description                                                               |
| ----------- | --------------------- | --------- | ------------------------------------------------------------------------- |
| `gap`       | `string \| null`      | `null`    | The space between the columns, as a CSS length. `null` is drawn as `24px` |
| `widthMode` | `'equal' \| 'custom'` | `'equal'` | Equal columns, or the widths in `widths`                                  |
| `widths`    | `string[] \| null`    | `null`    | One grid track size per column, used only while `widthMode` is `'custom'` |

Widths that do not match the number of columns, such as in content you wrote by hand, are drawn
as equal columns.

In HTML, `getHTML()` writes the attributes as data attributes, and the editor reads them
back from the same form, for example when the user pastes it:

```html
<div
  class="tiptap-columns-layout"
  data-tt-column-layout="true"
  data-tt-column-gap="32px"
  data-tt-column-width-mode="custom"
  data-tt-column-widths="1fr,2fr"
>
  <div class="tiptap-columns-column" data-tt-column="true"><p>Left</p></div>
  <div class="tiptap-columns-column" data-tt-column="true"><p>Right</p></div>
</div>
```

`getHTML()` also writes the `style` attribute with the custom properties from
[Styling](/features/columns#styling). The editor does not read it back, because the data attributes hold the
same values.

## Options

Pass the options to `Columns.configure()`. These are the defaults:

```js
Columns.configure({
  minColumns: 2,
  maxColumns: 6,
  defaultGap: '24px',
  defaultWidthMode: 'equal',
})
```

| Option             | Type                  | Default   | Description                          |
| ------------------ | --------------------- | --------- | ------------------------------------ |
| `minColumns`       | `number`              | `2`       | The fewest columns a layout may have |
| `maxColumns`       | `number`              | `6`       | The most columns a layout may have   |
| `defaultGap`       | `string`              | `'24px'`  | The `gap` of a new layout            |
| `defaultWidthMode` | `'equal' \| 'custom'` | `'equal'` | The `widthMode` of a new layout      |

`minColumns` and `maxColumns` are part of the schema, the rules for what a document may hold.
So the commands stay within them, and a layout with fewer or more columns is invalid content.
Editors that edit one document together through Tiptap Collaboration need the same values.

Tiptap loads invalid content as it is, without a check, unless you set the editor option
`enableContentCheck`, which then reports it to `onContentError`. So lowering `maxColumns` does
not change layouts that are already stored.

A new layout stores no widths, so `defaultWidthMode: 'custom'` draws equal columns until
`setColumnWidths()` gives it widths.

## Commands

Each command of `Columns` except `insertColumns()` works on the layout the cursor is in.
`addColumn()`, `removeColumn()` and `moveColumn()` need the cursor in a column, and the others
also work on a layout selected as a whole.

Each command returns `false` and changes nothing when it cannot act, and `editor.can()` asks
the same without running it. Each command has a transaction function for your own code, on
[Columns API](/features/columns/api).

### insertColumns()

Inserts a layout of empty columns after the block at the cursor, and puts the caret in the
first column. [Insert a layout](/features/columns#insert-a-layout) says where it goes.

```js
editor.commands.insertColumns({ count: 3, gap: '32px' })
```

| Option      | Type                  | Default            | Description                                       |
| ----------- | --------------------- | ------------------ | ------------------------------------------------- |
| `count`     | `number`              | `minColumns`       | How many columns. Clamped to the bounds           |
| `gap`       | `string \| null`      | `defaultGap`       | The space between the columns                     |
| `widthMode` | `'equal' \| 'custom'` | `defaultWidthMode` | The width mode. `'custom'` needs widths set after |

Returns `false` only when the schema has no block to put into a column.

### setColumnCount()

Adds columns at the end of the layout, or removes columns from its end.

```js
editor.commands.setColumnCount(3)
```

Takes the number of columns, clamped to `minColumns` and `maxColumns`. The command removes the
last columns, so the content of each removed column moves into the column before it, as with
`removeColumn()` in the last column.

Returns `false` outside a layout, and when the layout already has that many columns.

### setColumnGap()

Sets the space between the columns to a CSS length, such as `'48px'`. See
[Widths and the gap](/features/columns#widths-and-the-gap).

Returns `false` outside a layout.

### setColumnWidths()

Gives each column a width of its own, such as `['1fr', '2fr']`, and sets `widthMode` to
`'custom'`. See [Widths and the gap](/features/columns#widths-and-the-gap).

Takes one grid track size per column. With `null`, it makes the columns equal: `widthMode`
becomes `'equal'` and `widths` becomes `null`.

Returns `false` outside a layout, and for a list whose length is not the number of columns.

### setColumnWidthMode()

Sets `widthMode` alone. `'equal'` makes the columns equal and removes the stored widths, as
`setColumnWidths(null)` does.

```js
editor.commands.setColumnWidthMode('equal')
```

Takes `'equal'` or `'custom'`. `'custom'` draws the widths the layout stores, so it changes
the look only of a layout that stores widths with `widthMode: 'equal'`, such as one loaded from
your own content. To give a layout widths, use `setColumnWidths()`.

Returns `false` outside a layout.

### addColumn()

Adds an empty column beside the column the cursor is in.

```js
editor.commands.addColumn({ position: 'before' })
```

| Option     | Type                  | Default   | Description                       |
| ---------- | --------------------- | --------- | --------------------------------- |
| `position` | `'before' \| 'after'` | `'after'` | Which side of the cursor's column |

Returns `false` outside a column, for a layout selected as a whole, and when the layout has
`maxColumns` columns.

### removeColumn()

Removes the column the cursor is in, and keeps its content.

```js
editor.commands.removeColumn()
```

Takes no arguments. The content moves into the next column, after the content already there.
When the cursor is in the last column, the content moves to the end of the column before. An empty column is removed with nothing moved. The user
undoes the whole removal in one step.

Returns `false` outside a column, for a layout selected as a whole, and when the layout has
`minColumns` columns.

### moveColumn()

Moves the column the cursor is in one place to the left or right, and the caret with it.

```js
editor.commands.moveColumn('right')
```

Takes `'left'` or `'right'`. Returns `false` outside a column, for a layout selected as a
whole, and for the first column moved left or the last column moved right.

### deleteColumns()

Deletes the whole layout, with its columns and their content.

```js
editor.commands.deleteColumns()
```

Takes no arguments. Returns `false` outside a layout.

### exitColumns()

Puts the caret in an empty block after the layout, or before it.

```js
editor.commands.exitColumns({ direction: 'before' })
```

| Option      | Type                  | Default   | Description              |
| ----------- | --------------------- | --------- | ------------------------ |
| `direction` | `'before' \| 'after'` | `'after'` | Which side of the layout |

An empty paragraph or heading on that side gets the caret. Otherwise the command inserts an
empty block of the type the document allows there, a paragraph with StarterKit.

Returns `false` outside a layout.

## Limitations

What Columns does not do, and what to do instead.

### Turning a layout back into paragraphs

No command takes the content out of a layout and keeps it. `removeColumn()` stops at
`minColumns` columns, and `deleteColumns()` deletes the layout with all of its content. To
unwrap a layout, write a transaction of your own that replaces the layout with the content of
its columns. `columnBounds()` on [Columns API](/features/columns/api) finds where each column's content is.

### Resizing columns by dragging

The extension has no resize handle. Set widths with `setColumnWidths()`, for example from a
menu of your own.

### Changing the keys

No option turns the keys in [Keys](/features/columns#keys) off or binds them to other keys. To use a key
differently, add an extension of your own with a `priority` above 100, the default of
`Columns`. Its shortcut for the same key runs first, and when it returns `true`, the key of
`Columns` does not run.

To bind the same moves to other keys, [Columns API](/features/columns/api) has the functions the keys use.

## Columns on pages

With Page Layout, a page boundary cuts a layout through all of its columns. A layout set to keep
together moves to the next page whole instead. [Columns in Page Layout](/features/page-layout/extension-behavior/columns)
describes it.
