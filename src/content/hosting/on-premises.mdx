## What you get

- **The [Document Server](/collaboration/getting-started/overview)**, with the same real-time sync, storage, [REST API](/collaboration/documents/rest-api), [webhooks](/collaboration/core-concepts/webhooks), [snapshots](/collaboration/documents/snapshot), and [comments](/comments/getting-started/overview) as in Tiptap Cloud.
- **Docker images** to deploy into your own stack.
- **The [AI Toolkit](/ai/ai-toolkit/install) and [Conversion](/conversion/getting-started/install) services**, running on your servers as well.
- **A high-availability cluster** for large numbers of users.
- **Dedicated support** from Tiptap's team for custom development and integration.

## Requirements

| What | Why |
| --- | --- |
| A container runtime, such as Docker or Kubernetes | Runs the Document Server images |
| S3-compatible object storage | Stores documents and snapshots |
| A domain with TLS | Serves the WebSocket connection and the REST API |
| Redis | Coordinates the servers in a high-availability cluster |

## Get the images

After your agreement, Tiptap gives you access to the Document Server images and a license key. Pull the images into your own registry, so deployments don't depend on Tiptap's.

## Deploy

A minimal deployment runs one Document Server container next to your storage:

```yaml
services:
  document-server:
    image: <document server image from your onboarding>
    ports:
      - '8080:8080'
    environment:
      LICENSE_KEY: <your license key>
      S3_BUCKET: <bucket for documents>
      S3_ENDPOINT: <your S3 endpoint>
```

Put a reverse proxy with TLS in front of it, and allow WebSocket connections through it.

## Connect the editor

Pass your server's URL as `baseUrl` instead of `appId` to the [`TiptapCollabProvider`](/collaboration/provider/integration):

```js
import { TiptapCollabProvider } from '@tiptap-pro/provider'

const provider = new TiptapCollabProvider({
  name: 'document-name', // The document to open
  baseUrl: 'YOUR_DOCUMENT_SERVER_URL', // Where your Document Server runs
  token: 'YOUR_JWT',
  document: doc, // The Y.Doc the Collaboration extension uses
})
```

## Secure it

- **Users:** Sign a JWT for each user, as described in [Authentication](/authentication). The server accepts the same tokens as Tiptap Cloud. Create the key pair you sign them with in the [Tiptap Cloud dashboard](https://cloud.tiptap.dev), which you sign in to with an on-premises plan as well. [Authenticate](/collaboration/getting-started/authenticate) shows how to limit access per document.
- **REST API:** Your backend sends a token carrying `Documents:Api:All`, as for the [REST API](/collaboration/documents/rest-api#authentication) in Tiptap Cloud. Keep that token server-side.
- **Legacy secrets:** The server also creates a JWT `secret` and an `api_secret` on first launch. They keep existing integrations working, see [Legacy authentication](/authentication/legacy). Read and replace them through the [runtime configuration API](/collaboration/operations/configure). Use the new tokens for anything new.
- **Origins:** Set `allowed_origins` to the domains your editor runs on.

## Configure it

Change settings at runtime through the [runtime configuration API](/collaboration/operations/configure), without a restart:

| Setting | What it does |
| --- | --- |
| `webhook_url` | Where the server sends [webhooks](/collaboration/core-concepts/webhooks) |
| `default_auto_versioning` | Turns automatic [snapshots](/collaboration/documents/snapshot) on |
| `jwt_explicit_access` | Denies access when a JWT names no documents |
| `skip_s3_health_check` | Skips the S3 health check, for storage that doesn't support it |

## Scale it

Run several Document Servers as a high-availability cluster. Set the provider's [`shardKey`](/collaboration/provider/integration), usually to the document name or a team ID, so all clients of a document reach the same server.

## Monitor it

The [metrics API](/collaboration/operations/metrics) reports server statistics, document statistics, and server health. Connect it to your monitoring system.

## Update and back up

- **Updates:** Tiptap publishes new images with release notes. Update one server at a time in a cluster, so editing continues.
- **Backups:** Back up the object storage. The REST API can also export documents as JSON for a second copy.

## Move from Hocuspocus or Tiptap Cloud

- **From Hocuspocus:** Replace the `HocuspocusProvider` with the `TiptapCollabProvider`, and import your documents with the [batch import endpoint](/collaboration/documents/rest-api#batch-import-documents).
- **From Tiptap Cloud:** Replace `appId` with `baseUrl`. Your documents move with their versions: [export and import a document](/collaboration/documents/rest-api#export-and-import-a-document).
