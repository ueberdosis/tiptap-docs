The Mermaid extension shows [Mermaid](https://mermaid.js.org/) diagrams in your editor. People write a diagram as text in a code block and see the picture while they type.

Diagrams are code blocks with the language `mermaid`, so editors without the extension keep them as code. The extension comes without UI: build menus and buttons with its [commands](#commands).

<Callout title="Beta" variant="info">
  The Mermaid extension is in beta. Its API may still change before a stable release.
</Callout>

## Install

Install the extension from Tiptap's [private registry](/guides/pro-extensions), and Mermaid 11:

```bash
npm install @tiptap-pro/extension-mermaid mermaid@11
```

## Usage

```js
import { Editor } from '@tiptap/core'
import StarterKit from '@tiptap/starter-kit'
import { Mermaid } from '@tiptap-pro/extension-mermaid'

const editor = new Editor({
  extensions: [
    StarterKit,
    Mermaid.configure({
      mermaidUrl: new URL('mermaid/dist/mermaid.min.js', import.meta.url).href,
    }),
  ],
})
```

The extension doesn't include Mermaid. `mermaidUrl` is where your app serves Mermaid's file: `new URL(…, import.meta.url)` makes your bundler copy the file into your build and gives its URL. This works with Vite, Next.js with Turbopack or webpack, and Rspack. In Next.js, create the URL in the client component that creates the editor. With other bundlers, [serve Mermaid from your public folder](#serve-mermaid-from-your-public-folder).

The editor needs a code block extension, like StarterKit's [CodeBlock](/editor/extensions/nodes/code-block). People create diagrams when they type ` ```mermaid ` and a space, or paste a Mermaid code fence.

## How it works

Mermaid draws each diagram in a sandboxed iframe, and the editor shows the picture as an image. Mermaid's strict mode alone isn't enough: it runs in your page, and Mermaid had bugs that let a diagram run script in that mode as recently as 2025. In a shared document, such a diagram would run for everyone who opens it. In the iframe, it can't reach your page, its cookies, or the editor.

Good to know:

- Diagrams render only in the browser. `getHTML()`, Markdown, and server-side rendering give the text.
- Pictures are images: links in diagrams don't work, and their text can't be selected.
- Mermaid 11 needs Chrome 98, Firefox 94, or Safari 16.4 or later.
- A page with a Content Security Policy needs a few changes. See [Content Security Policy](#content-security-policy).

## Settings

### mermaidUrl

Required. The URL of Mermaid's single-file build, `mermaid/dist/mermaid.min.js`: Mermaid 11.16.1 or a later 11.x version. Without it, diagrams show their text and the `unavailable` label, and the console says how to set it.

Default: `null`

```js
Mermaid.configure({
  mermaidUrl: '/mermaid.min.js',
})
```

### defaultDisplay

How diagrams show until someone picks a mode: `'code'` shows the text, `'split'` the text and the picture, `'preview'` the picture.

Default: `'split'`

```js
Mermaid.configure({
  defaultDisplay: 'preview',
})
```

### theme

How diagrams look: one of [Mermaid's themes](https://mermaid.js.org/config/theming.html), or `{ name, look, variables }`. Pictures are images, so your page's CSS can't style them. For your own colors, start from the `base` theme and set Mermaid's [theme variables](https://mermaid.js.org/config/theming.html#theme-variables).

A theme `name` is one of `default`, `dark`, `neutral`, `forest`, `base`, `neo`, `neo-dark`, `redux`, `redux-dark`, `redux-color`, and `redux-dark-color`. `look` is `classic` or `neo`. To change the theme later, for example for dark mode, use [`setMermaidTheme()`](#setmermaidtheme).

Default: `'default'`

```js
Mermaid.configure({
  theme: {
    name: 'base',
    look: 'neo',
    variables: { primaryColor: '#f4eeff', lineColor: '#2e2b29' },
  },
})
```

### maxTextSize

The longest diagram text Mermaid draws. Longer diagrams show Mermaid's size message.

Default: `50000`

```js
Mermaid.configure({
  maxTextSize: 100000,
})
```

### labels

The texts the extension shows, for example for translations. The example shows the defaults.

```js
Mermaid.configure({
  labels: {
    // The alt text, when the diagram has no accTitle or accDescr
    diagram: 'Mermaid diagram',
    // When Mermaid can't start, for example when its file didn't load
    unavailable: "This diagram can't be shown.",
    // When a diagram takes more than 10 seconds to render
    timeout: 'This diagram took too long to render.',
    // When a diagram has images from URLs, which can't load
    externalImages: "Images in this diagram can't be shown.",
  },
})
```

### HTMLAttributes

Custom HTML attributes for each diagram's root element.

```js
Mermaid.configure({
  HTMLAttributes: {
    class: 'my-custom-class',
  },
})
```

### scriptNonce

The nonce for the iframe's scripts and Mermaid's styles, if your page has a [Content Security Policy](#content-security-policy) with nonces. Without it, the extension uses the editor's [`injectNonce`](/editor/api/editor#injectnonce).

Default: `null`

```js
Mermaid.configure({
  scriptNonce: 'your-nonce',
})
```

### rendererUrl

The URL of the extension's renderer script, served as a file. Most apps don't need it: it's only for pages whose [Content Security Policy](#content-security-policy) allows scripts by URL only. Without it, the iframe runs the script inline.

Default: `null`

```js
Mermaid.configure({
  rendererUrl: '/mermaid-renderer.js',
})
```

## Commands

### insertMermaid()

Inserts a diagram and selects its text, so typing replaces it. `source` is the Mermaid text, a small flowchart by default. `display` is the mode.

```js
editor.commands.insertMermaid()
editor.commands.insertMermaid({
  source: 'flowchart LR\n  A --> B',
  display: 'preview',
})
```

To turn the selected code block into a diagram, set its language:

```js
editor.commands.updateAttributes('codeBlock', { language: 'mermaid' })
```

### setMermaidDisplay()

Shows the selected diagram as `'code'`, `'split'`, or `'preview'`. In Preview, a click selects the whole diagram, like an image. The mode is saved in the document, so everyone sees the same mode.

```js
editor.commands.setMermaidDisplay('preview')
```

### setMermaidSize()

Sets the selected diagram's width, as a share of the column from 0.1 to 1, so diagrams fit any page width. `null` goes back to the natural size, scaled down to fit.

```js
editor.commands.setMermaidSize({ width: 0.5 })
editor.commands.setMermaidSize(null)
```

### setMermaidAlign()

Aligns the selected diagram when it's narrower than the column: `'left'`, `'center'`, or `'right'`.

```js
editor.commands.setMermaidAlign('left')
```

### setMermaidTheme()

Sets the theme for this editor, for example for dark mode, and draws every diagram again. It takes the same values as the [`theme`](#theme) setting. The document and the undo history don't change.

```js
const darkMode = window.matchMedia('(prefers-color-scheme: dark)')

darkMode.addEventListener('change', () => {
  editor.commands.setMermaidTheme(darkMode.matches ? 'dark' : 'default')
})
```

`insertMermaid()` returns `false` without a code block extension. The other commands return `false` when no diagram is selected.

## Keyboard shortcuts

In a diagram's text, keys work like in a code block, except these:

| Key                                           | Action                                                                                      |
| --------------------------------------------- | ------------------------------------------------------------------------------------------- |
| <kbd>Shift</kbd> + <kbd>Enter</kbd>           | Adds a line                                                                                 |
| <kbd>Tab</kbd>                                | Adds two spaces, or indents the selected lines                                              |
| <kbd>Shift</kbd> + <kbd>Tab</kbd>             | Outdents the selected lines                                                                 |
| <kbd>Cmd</kbd>/<kbd>Ctrl</kbd> + <kbd>A</kbd> | Selects the diagram's text. Press again to select the document.                             |
| <kbd>Escape</kbd>                             | Selects the whole diagram. <kbd>Tab</kbd> then moves the focus on.                          |
| <kbd>Backspace</kbd>, <kbd>Delete</kbd>       | Keep the diagram whole at the start and end of its text. Next to a diagram, they select it. |
| Arrow keys                                    | Next to a diagram in Preview, select it, like an image                                      |

## Styling

The extension adds no CSS, and works without it. Style diagrams with this DOM:

```html
<div class="tiptap-mermaid" data-display="split" data-state="ready">
  <pre class="tiptap-mermaid__source"><code>flowchart LR …</code></pre>
  <div class="tiptap-mermaid__preview" contenteditable="false">
    <div class="tiptap-mermaid__message"></div>
    <img class="tiptap-mermaid__image" />
    <div class="tiptap-mermaid__status" role="status"></div>
  </div>
</div>
```

`data-state` is `idle` before the first render and in Code, `empty` without text, `loading` while Mermaid draws, `ready`, or `error`. While loading and after an error, the last good picture stays.

```css
.tiptap-mermaid[data-state='error'] .tiptap-mermaid__message {
  color: #dc2626;
}
```

`setMermaidSize()` sets the image's inline `width`, and `setMermaidAlign()` the inline `text-align` of `.tiptap-mermaid__preview`. A picture's alt text is the diagram's `accTitle` and `accDescr`. The hidden status element reads the first line of a new error to screen readers while someone types.

## Render a diagram as SVG

For a zoom view or a download, `editor.storage.mermaid.render(node)` returns the diagram's `svg`, its `width` and `height`, and its `title` and `description`. Show the SVG in an `<img>`, never as HTML in your page: it holds text from your users.

```js
// The selected diagram: the whole block in Preview, or the block with the caret
const { selection } = editor.state
const node = selection.node ?? selection.$from.parent

const { svg, title } = await editor.storage.mermaid.render(node)
const image = new Image()

image.src = `data:image/svg+xml;charset=utf-8,${encodeURIComponent(svg)}`
image.alt = title || 'Diagram'
```

For a download, save `svg` as an `.svg` file. When a diagram can't render, `render()` rejects with a `MermaidRenderError`. Its `reason` is `setup`, `version`, `syntax`, `timeout`, or `image`.

## Advanced setup

Most apps don't need this section. It's for bundlers without `new URL(…, import.meta.url)`, and pages with a Content Security Policy.

### Serve Mermaid from your public folder

Copy `node_modules/mermaid/dist/mermaid.min.js` into your public folder, and pass its path, like `mermaidUrl: '/mermaid.min.js'`. Copy it again when you update Mermaid.

This works with every bundler. Use it when yours doesn't support `new URL(…, import.meta.url)`, like esbuild or Parcel. It also helps in Vite's dev server: there, the first diagram can take a few seconds, because Vite adds Mermaid's 13 MB source map to the file.

### Content Security Policy

Mermaid runs in a sandboxed iframe. It can't reach your page or its cookies, it can't fetch anything, and it runs only its own scripts. Pictures show as images, which run no code.

If your page has a Content Security Policy, it needs:

- `img-src data:`, because pictures are `data:` images.
- `style-src 'unsafe-inline'`, or a nonce through the editor's [`injectNonce`](/editor/api/editor#injectnonce). Tiptap's own styles need this too.
- Mermaid's file in `script-src`, like `'self'`, unless you use a nonce. Some older Safari versions need your app's origin itself, like `script-src 'self' https://app.example.com`.

The iframe also runs the extension's renderer script, inline. What to do depends on your `script-src`:

| Your `script-src`               | What to do                                                                                        |
| ------------------------------- | ------------------------------------------------------------------------------------------------- |
| Allows `'unsafe-inline'`        | Nothing                                                                                           |
| Uses a nonce                    | Pass the nonce to the editor's `injectNonce`, or to the extension's [`scriptNonce`](#scriptnonce) |
| Allows only URLs, like `'self'` | Serve the renderer script as a file, and set [`rendererUrl`](#rendererurl)                        |

To serve the renderer script with Vite 6.2.1 or later, import its URL. `no-inline` keeps Vite from turning the small file into a `data:` URL, which your policy would block:

```js
import rendererUrl from '@tiptap-pro/extension-mermaid/renderer?url&no-inline'

Mermaid.configure({ rendererUrl })
```

Without Vite, copy the file into your public folder:

```bash
cp node_modules/@tiptap-pro/extension-mermaid/dist/mermaid/rendererScript.js public/mermaid-renderer.js
```

Then pass its path: `Mermaid.configure({ rendererUrl: '/mermaid-renderer.js' })`. Copy the file again when you update the extension.

Add `frame-src` to stop the iframe from navigating to other sites. Diagrams still render.

When the policy or a wrong URL stops Mermaid, diagrams show their text and the `unavailable` label. The browser console shows the cause, starting with `[Mermaid]`.

## Use with other extensions

- **Collaboration:** Changes to a diagram's text merge like any text. For the mode, size, and alignment, the last change wins. Add the extension to every editor of a shared document. An editor without it shows diagrams as code.
- **Tracked Changes:** Enable [code block tracking](/tracked-changes/guides/editor-setup#enable-code-block-tracking). Without it, typing in a code block fails while tracking is on. The picture shows the text as if every suggestion were accepted.
- **Pages:** Pictures are scaled down to fit one page.
- **Markdown:** Diagrams read and write as `mermaid` code fences. The mode, size, and alignment aren't kept.
- **AI Toolkit:** Agents can write and change diagrams as `mermaid` code blocks. To describe diagrams to an agent, change the code block's entry in the [editor context](/ai/ai-toolkit/api-reference/editor-context).
- **DOCX export:** Code blocks [aren't exported to Word](/conversion/content-types/structures-and-media/block-elements) yet, so diagrams aren't either.

## Stored content

A code block is a diagram when its language's first word is `mermaid`. The extension adds two attributes to every code block:

- `mermaidDisplay`: `'code'`, `'split'`, or `'preview'`, or `null` for the [`defaultDisplay`](#defaultdisplay). In HTML, `data-mermaid-display`.
- `mermaidSettings`: `null`, or an object with `size` and `align`. In HTML, `data-mermaid-settings`.

```json
{
  "type": "codeBlock",
  "attrs": {
    "language": "mermaid",
    "mermaidDisplay": "preview",
    "mermaidSettings": { "size": { "width": 0.5 }, "align": "left" }
  },
  "content": [{ "type": "text", "text": "flowchart LR\n  A --> B" }]
}
```

## Known limitations

- Diagrams render only in the browser, as images. See [How it works](#how-it-works).
- Mermaid 12 isn't supported yet.
- Some browsers run the iframe on the page's thread, so a very big diagram can freeze the page while it renders.
- Only `data:` images load in diagrams.
- A code block with its own node view keeps it, and shows no pictures.
- The sandbox protects your page, not the diagrams. If a Mermaid bug let a diagram run script, the script could read the other diagrams on the page, and send them out through WebRTC, which no policy blocks in Chromium and Safari.
