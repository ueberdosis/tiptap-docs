The Diagram extension shows [Mermaid](https://mermaid.js.org/) diagrams in your editor. People write a diagram as text in a code block, and see the picture while they type.

Diagrams are code blocks with the language `mermaid`, so editors without the extension keep them as code. Mermaid draws them in a sandboxed iframe. The extension comes without UI: you build menus and buttons with its commands.

<Callout title="Alpha" variant="warning">
  The Diagram extension is in alpha, and its API may change before a stable release. Pin the version
  you install.
</Callout>

## Install

Set up access to Tiptap's private registry with the [private registry guide](/guides/pro-extensions). Then install the extension and Mermaid 11:

```bash
npm install @tiptap-pro/extension-diagram mermaid@11
```

The extension works with Mermaid 11.16.1 and later 11.x versions. Mermaid 12 isn't supported yet.

## Usage

Mermaid runs in an iframe, so your app serves two files as they are:

- Mermaid's single-file build, `mermaid/dist/mermaid.min.js`
- the extension's renderer script, `@tiptap-pro/extension-diagram/mermaid-renderer`

With Vite, import their URLs with `?url`, and pass them to `createMermaidRenderer()`:

```ts
import { Editor } from '@tiptap/core'
import StarterKit from '@tiptap/starter-kit'
import { createMermaidRenderer, Diagram } from '@tiptap-pro/extension-diagram'
import rendererUrl from '@tiptap-pro/extension-diagram/mermaid-renderer?url&no-inline'
import mermaidUrl from 'mermaid/dist/mermaid.min.js?url'

const editor = new Editor({
  extensions: [
    StarterKit,
    Diagram.configure({
      renderers: [createMermaidRenderer({ mermaidUrl, rendererUrl })],
    }),
  ],
})
```

`no-inline` keeps Vite from turning the small renderer script into a `data:` URL, which the iframe can't load. It needs Vite 6 or later.

The editor needs a code block extension, like StarterKit's [CodeBlock](/editor/extensions/nodes/code-block).

### Serve the files from the public folder

Without Vite, or with Vite 5 or older, copy both files into your public folder:

```bash
mkdir -p public/diagram
cp node_modules/mermaid/dist/mermaid.min.js public/diagram/mermaid.min.js
cp node_modules/@tiptap-pro/extension-diagram/dist/mermaid/rendererScript.js public/diagram/mermaid-renderer.js
```

Then pass their paths:

```ts
const renderers = [
  createMermaidRenderer({
    mermaidUrl: '/diagram/mermaid.min.js',
    rendererUrl: '/diagram/mermaid-renderer.js',
  }),
]
```

Copy the files again when you update Mermaid or the extension, for example in a `postinstall` script. A renderer script from another version of the extension may not work.

In Vite's dev server, this also avoids a slow first load: Vite adds Mermaid's 13 MB source map to the file.

  Mermaid is MIT licensed, and its single-file build doesn't include the license notice. When you
  serve the file, serve Mermaid's license with it, for example `node_modules/mermaid/LICENSE`.
</Callout>

### Create a diagram

Every code block with the language `mermaid` is a diagram, also in documents written before you added the extension. People create one when they:

- type ` ```mermaid ` and a space
- paste a Mermaid code fence as plain text, for example from a Markdown file
- paste HTML, or load Markdown, with a `mermaid` code block

To insert a diagram from your UI, use `insertDiagram()`. It selects the diagram's text, so typing replaces it:

```ts
editor.commands.insertDiagram()

editor.commands.insertDiagram({
  source: 'flowchart LR\n  A --> B',
  display: 'preview',
})
```

To turn the selected code block into a diagram, set its language:

```ts
editor.commands.updateAttributes('codeBlock', { language: 'mermaid' })
```

## Display modes

A diagram shows in one of three modes:

| Mode      | Shows                                                          |
| --------- | -------------------------------------------------------------- |
| `code`    | The text. The diagram isn't drawn.                             |
| `split`   | The text, and the picture below it                             |
| `preview` | The picture. A click selects the whole diagram, like an image. |

Until someone picks a mode, a diagram shows the renderer's default, Split. To use another default, set the renderer's `display` option:

```ts
createMermaidRenderer({ mermaidUrl, rendererUrl, display: 'preview' })
```

To change the mode of the selected diagram, use `setDiagramDisplay()`:

```ts
editor.commands.setDiagramDisplay('preview')
```

The mode is saved in the document, so everyone sees the same mode, and undo works.

## Size and alignment

A picture has its natural size, scaled down to fit. To set its width, use a share of the column, from 0.1 to 1. A picture narrower than the column is centered, unless you align it:

```ts
editor.commands.setDiagramSize({ width: 0.5 })
editor.commands.setDiagramAlign('left') // 'left', 'center', or 'right'

// Back to the natural size
editor.commands.setDiagramSize(null)
```

Both commands change the selected diagram and keep the selection. Use them for resize handles and alignment menus. A width is never in pixels, so diagrams fit any page width.

## Themes

Pictures are images, so your page's CSS can't style them. Set `theme` to one of [Mermaid's themes](https://mermaid.js.org/config/theming.html) instead, like `'neutral'`. For your own colors, start from a theme and set Mermaid's [theme variables](https://mermaid.js.org/config/theming.html#theme-variables). Mermaid documents them for the `base` theme:

```ts
Diagram.configure({
  renderers,
  theme: {
    name: 'base',
    look: 'neo',
    variables: {
      primaryColor: '#f4eeff',
      lineColor: '#2e2b29',
    },
  },
})
```

To change the theme later, for example for dark mode, use `setDiagramTheme()`. It draws every diagram in the editor again, and doesn't change the document:

```ts
const darkMode = window.matchMedia('(prefers-color-scheme: dark)')
const getTheme = () => (darkMode.matches ? 'dark' : 'default')

const editor = new Editor({
  extensions: [StarterKit, Diagram.configure({ renderers, theme: getTheme() })],
})

darkMode.addEventListener('change', () => editor.commands.setDiagramTheme(getTheme()))
```

## Build your own UI

Build menus and buttons with the API:

| Feature                  | Use                                           |
| ------------------------ | --------------------------------------------- |
| Display menu             | `setDiagramDisplay()`                         |
| Resize handles           | `setDiagramSize()`                            |
| Alignment menu           | `setDiagramAlign()`                           |
| Language menu            | `updateAttributes('codeBlock', { language })` |
| Zoom view or download    | `editor.storage.diagram.render()`             |
| Copy button              | The diagram node's `textContent`              |
| Loading and error styles | CSS on `data-state`                           |

### Display menu

This React menu shows the mode of the selected diagram. A saved `null` means the renderer's default:

```tsx
import type { Editor } from '@tiptap/core'
import { useEditorState } from '@tiptap/react'
import type { DiagramDisplay } from '@tiptap-pro/extension-diagram'

const modes: DiagramDisplay[] = ['code', 'split', 'preview']

function DisplayMenu({ editor }: { editor: Editor }) {
  const display = useEditorState({
    editor,
    selector: ({ editor: currentEditor }) =>
      currentEditor.isActive('codeBlock', { language: 'mermaid' })
        ? (currentEditor.getAttributes('codeBlock').diagramDisplay ?? 'split')
        : null,
  })

  return modes.map((mode) => (
    <button
      key={mode}
      disabled={!display}
      className={display === mode ? 'is-active' : ''}
      onClick={() => editor.chain().focus().setDiagramDisplay(mode).run()}
    >
      {mode}
    </button>
  ))
}
```

### Zoom view

`editor.storage.diagram.render(node)` returns a diagram as SVG. It uses the same iframe and cache as the editor. Show the SVG in an `<img>`, never as HTML in your page: diagrams can hold links, which do nothing in an image.

```ts
import { NodeSelection } from '@tiptap/pm/state'

async function showZoomView(dialog: HTMLDialogElement) {
  const { selection } = editor.state
  // In Preview, the whole diagram is selected. Otherwise, the caret is in its text.
  const node = selection instanceof NodeSelection ? selection.node : selection.$from.parent
  const { svg, title, description } = await editor.storage.diagram.render(node)
  const image = new Image()

  image.src = `data:image/svg+xml;charset=utf-8,${encodeURIComponent(svg)}`
  image.alt = [title, description].filter(Boolean).join(': ') || 'Diagram'
  dialog.replaceChildren(image)
  dialog.showModal()
}
```

For a download, save the same `svg` as an `.svg` file. When a diagram can't render, `render()` rejects with a [`DiagramRenderError`](#diagramrendererror).

### Styles

The extension adds no CSS. It hides the text in Preview and the picture in Code with the `hidden` attribute, so diagrams work without a stylesheet. Style them with this DOM:

```html
<div class="tiptap-diagram" data-language="mermaid" data-display="split" data-state="ready">
  <pre class="tiptap-diagram__source"><code>flowchart LR …</code></pre>
  <div class="tiptap-diagram__preview" contenteditable="false">
    <div class="tiptap-diagram__message"></div>
    <img class="tiptap-diagram__image" />
    <div class="tiptap-diagram__status" role="status"></div>
  </div>
</div>
```

`data-state` is one of:

- `idle`: before the first render, and in Code
- `empty`: the diagram has no text
- `loading`: Mermaid is drawing. The last picture stays.
- `ready`: the picture is shown
- `error`: the message shows Mermaid's error. The last good picture stays.

```css
.tiptap-diagram[data-state='error'] .tiptap-diagram__message {
  color: #dc2626;
}

.tiptap-diagram[data-state='loading'] .tiptap-diagram__image {
  opacity: 0.5;
}
```

A width from `setDiagramSize()` is the image's inline `width`, and the alignment is the inline `text-align` of `.tiptap-diagram__preview`. The status element is for screen readers, and hides itself.

## Security and Content Security Policy

Mermaid runs in a sandboxed iframe, with no access to your page, its cookies, or the network. Pictures come back as SVG and show as images, which run no code and load nothing. Diagrams can't change Mermaid's security settings.

If your page has a Content Security Policy:

- Allow `data:` images with `img-src data:`. Pictures are `data:` images.
- Allow inline styles with `style-src 'unsafe-inline'`, or set a nonce with the editor's [`injectNonce`](/editor/api/editor#injectnonce) option. Tiptap's own styles need this too. Without it, labels in diagrams are out of place.
- `script-src 'self'` works in Chrome, Firefox, and newer Safari versions. Some older Safari versions also need your app's origin, like `script-src 'self' https://app.example.com`, or a nonce.
- With a nonce, the extension adds `injectNonce` to the iframe's scripts and Mermaid's styles. To use another nonce, set the `scriptNonce` option.
- `frame-src` and `child-src` don't apply: the iframe's page is inline, in `srcdoc`, and isn't loaded from a URL.

When the policy or a wrong URL stops Mermaid, diagrams show their text and the `unavailable` label. The browser console shows the cause once, starting with `[Diagram]`.

## Use with other extensions

- **Collaboration:** Changes to a diagram's text merge like any text. For the mode, size, and alignment, the last change wins. Add the extension to every editor of a shared document: an editor without it shows diagrams as code, and when it edits one, the diagram goes back to its default mode. The text stays.
- **Tracked Changes:** Diagrams are code blocks, so their text is tracked only with [code block tracking](/tracked-changes/guides/editor-setup#enable-code-block-tracking). In Preview, the text and its suggestions are hidden.
- **Pages:** Pictures are scaled down to fit one page.
- **Markdown:** Diagrams read and write as `mermaid` code fences. The mode, size, and alignment aren't kept.
- **AI Toolkit:** Agents can write and change diagrams as `mermaid` code blocks. To describe diagrams to an agent, change the code block's entry in the [editor context](/ai/ai-toolkit/api-reference/editor-context) or the [schema awareness](/ai/ai-toolkit/client/agents/schema-awareness).
- **DOCX export:** Code blocks [aren't exported to Word](/conversion/content-types/structures-and-media/block-elements) yet, so diagrams aren't either.

## Keyboard shortcuts

In a diagram's text, keys work like in a code block, except these:

| Key                                           | Action                                                                                      |
| --------------------------------------------- | ------------------------------------------------------------------------------------------- |
| <kbd>Shift</kbd> + <kbd>Enter</kbd>           | Adds a line                                                                                 |
| <kbd>Tab</kbd>                                | Adds two spaces, or indents the selected lines                                              |
| <kbd>Shift</kbd> + <kbd>Tab</kbd>             | Outdents the selected lines                                                                 |
| <kbd>Cmd</kbd>/<kbd>Ctrl</kbd> + <kbd>A</kbd> | Selects the diagram's text. Press again to select the document.                             |
| <kbd>Escape</kbd>                             | Selects the whole diagram. <kbd>Tab</kbd> then moves the focus on.                          |
| <kbd>Backspace</kbd>, <kbd>Delete</kbd>       | Keep the diagram whole at the start and end of its text. Next to a diagram, they select it. |

## Accessibility

- A picture's alt text is the diagram's `accTitle` and `accDescr`, or the `diagram` label.
- The picture area has `aria-busy` while a diagram renders.
- While someone types in a diagram, screen readers read the first line of a new error, like "Parse error on line 4:".

## Known limitations

- Mermaid 12 isn't supported yet.
- Mermaid 11 needs Chrome 98, Firefox 94, or Safari 16.4 or later.
- Some browsers run the iframe on the page's thread. There, a very big diagram freezes the page while it renders. A flowchart with 450 connections took about 0.4 seconds.
- Only `data:` images load in diagrams. A diagram with an image from a URL shows the `externalImages` label.
- Links in diagrams don't work, because pictures are images.
- Pictures need a browser. `getHTML()`, Markdown, and server-side rendering give the text, not the picture.
- A code block with its own node view keeps it, and shows no pictures.

## API reference

### Options

| Option           | Type                      | Default       | Description                                                                           |
| ---------------- | ------------------------- | ------------- | ------------------------------------------------------------------------------------- |
| `renderers`      | `DiagramRenderer[]`       | `[]`          | The renderers that draw diagrams. Code blocks in other languages stay code.           |
| `theme`          | `MermaidTheme`            | `'default'`   | Mermaid's theme: a theme name, or `{ name, look, variables }`                         |
| `scriptNonce`    | `string \| null`          | `null`        | The nonce for the iframe's scripts and Mermaid's styles. Falls back to `injectNonce`. |
| `maxTextSize`    | `number`                  | `50000`       | The longest text Mermaid renders. Longer texts show Mermaid's size message.           |
| `labels`         | `Partial<DiagramLabels>`  | English texts | The texts the extension shows, for example for translations                           |
| `HTMLAttributes` | `Record<string, unknown>` | `{}`          | HTML attributes for each diagram's root element                                       |

A theme `name` is one of `default`, `dark`, `neutral`, `forest`, `base`, `neo`, `neo-dark`, `redux`, `redux-dark`, `redux-color`, and `redux-dark-color`. `look` is `classic`, the default, or `neo`.

Without a code block extension or a renderer, the extension logs how to fix it, and does nothing.

### Labels

| Label            | Default                                  | Shown                                                           |
| ---------------- | ---------------------------------------- | --------------------------------------------------------------- |
| `diagram`        | `Mermaid diagram`                        | As alt text, when the diagram has no `accTitle` or `accDescr`   |
| `unavailable`    | `This diagram can't be shown.`           | When Mermaid can't start, for example when its file didn't load |
| `timeout`        | `This diagram took too long to render.`  | When a diagram takes more than 10 seconds                       |
| `externalImages` | `Images in this diagram can't be shown.` | When a diagram has images from URLs                             |

### createMermaidRenderer(options)

Returns the renderer for code blocks with the language `mermaid`.

| Option        | Type                             | Default   | Description                                                 |
| ------------- | -------------------------------- | --------- | ----------------------------------------------------------- |
| `mermaidUrl`  | `string`                         |           | The URL of `mermaid/dist/mermaid.min.js`                    |
| `rendererUrl` | `string`                         |           | The URL of `@tiptap-pro/extension-diagram/mermaid-renderer` |
| `display`     | `'code' \| 'split' \| 'preview'` | `'split'` | The mode of diagrams until someone picks one                |

### Commands

| Command                      | Description                                                                                                                                |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| `insertDiagram(options?)`    | Inserts a diagram and selects its text. `options.source` is the Mermaid text, a small flowchart by default. `options.display` is the mode. |
| `setDiagramDisplay(display)` | Sets the selected diagram's mode: `'code'`, `'split'`, or `'preview'`                                                                      |
| `setDiagramSize(size)`       | Sets the selected diagram's width: `{ width }`, from 0.1 to 1, or `null` for the natural size                                              |
| `setDiagramAlign(align)`     | Sets the selected diagram's alignment: `'left'`, `'center'`, or `'right'`                                                                  |
| `setDiagramTheme(theme)`     | Sets the Mermaid theme for this editor. The document and the undo history don't change.                                                    |

`insertDiagram()` returns `false` without a code block extension or a `mermaid` renderer. The commands for the selected diagram return `false` when no diagram is selected.

### Storage

`editor.storage.diagram.render(node)` draws a diagram node, and returns a `Promise<DiagramRenderResult>`:

| Property            | Type      | Description                                                |
| ------------------- | --------- | ---------------------------------------------------------- |
| `svg`               | `string`  | The diagram as SVG. Show it in an `<img>`, never as HTML.  |
| `width`             | `number`  | The SVG's width in pixels                                  |
| `height`            | `number`  | The SVG's height in pixels                                 |
| `title`             | `string`  | The diagram's `accTitle`, or an empty string               |
| `description`       | `string`  | The diagram's `accDescr`, or an empty string               |
| `hasExternalImages` | `boolean` | Whether the diagram has images from URLs, which can't load |

### DiagramRenderError

`render()` rejects with a `DiagramRenderError`. Its `reason` is one of:

- `setup`: Mermaid can't start, for example because of a missing URL or the page's Content Security Policy
- `version`: the Mermaid version isn't supported, or the renderer script is from another version of the extension
- `syntax`: Mermaid can't read the text
- `timeout`: the render took more than 10 seconds
- `image`: an image in the diagram didn't load. Only `data:` images load in the iframe.

### Attributes

The extension adds two attributes to every code block:

| Attribute         | HTML                    | Description                                                            |
| ----------------- | ----------------------- | ---------------------------------------------------------------------- |
| `diagramDisplay`  | `data-diagram-display`  | `'code'`, `'split'`, or `'preview'`. `null` for the renderer's default |
| `diagramSettings` | `data-diagram-settings` | `null`, or an object with `size` and `align`                           |

```json
{
  "type": "codeBlock",
  "attrs": {
    "language": "mermaid",
    "diagramDisplay": "preview",
    "diagramSettings": { "size": { "width": 0.5 }, "align": "left" }
  },
  "content": [{ "type": "text", "text": "flowchart LR\n  A --> B" }]
}
```

`insertDiagram()` and `setDiagramDisplay()` save a mode only when it differs from the renderer's default. Settings the extension doesn't know are kept.
