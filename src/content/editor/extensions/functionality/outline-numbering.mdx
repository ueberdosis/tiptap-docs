## Install

```bash
npm install @tiptap-pro/extension-outline-numbering
```

- **The Pro registry.** The package comes from Tiptap's private registry. See
  [The Pro registry](/page-layout/getting-started/install#the-pro-registry)
  to set it up.
- **Peer dependencies.** `@tiptap/core` and `@tiptap/pm`.
- **[Number formats](/editor/extensions/functionality/number-formats)** is a dependency, and is
  installed with it.
- **Without pages.** The package works in any Tiptap editor, with or without Page Layout.

## Quick start

Register the Node types that carry a number, and put the rules that draw the numbers into the
page:

```js
import { Editor } from '@tiptap/core'
import StarterKit from '@tiptap/starter-kit'
import { mountOutlineStyles, OutlineNumbering } from '@tiptap-pro/extension-outline-numbering'

mountOutlineStyles(document)

const editor = new Editor({
  element: document.querySelector('#editor'),
  extensions: [
    StarterKit,
    OutlineNumbering.configure({
      types: {
        heading: { level: (node) => node.attrs.level },
      },
    }),
  ],
})
```

Headings are numbered `1`, `1.1`, `1.1.1`. Without `mountOutlineStyles` the numbers are counted
but not drawn. See [How a number is shown](/editor/extensions/functionality/outline-numbering#how-a-number-is-shown).

## Options

| Option         | Type                                    | Default  | Description                                                                                                                                             |
| -------------- | --------------------------------------- | -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `types`        | `OutlineTypes`                          | `{}`     | The Node types that carry a number. See [Registering what is numbered](/editor/extensions/functionality/outline-numbering#registering-what-is-numbered) |
| `levels`       | `OutlineLevel[]`                        | `[]`     | A template per level. See [How a level reads](/editor/extensions/functionality/outline-numbering#how-a-level-reads)                                     |
| `skippedLevel` | `'zero' \| 'zeroEverywhere' \| 'first'` | `'zero'` | What a skipped level counts as. See [Counting](/editor/extensions/functionality/outline-numbering#counting)                                             |
| `lists`        | `string[]`                              | `[]`     | The list types that can belong to the outline. See [Lists as clauses](/editor/extensions/functionality/outline-numbering#lists-as-clauses)              |
| `ignore`       | `OutlineIgnore \| null`                 | `null`   | Nodes that are not numbered. See [Leaving Nodes out](/editor/extensions/functionality/outline-numbering#leaving-nodes-out)                              |
| `lookupOf`     | `((doc) => object \| null) \| null`     | `null`   | Where a level comes from besides the Node. See [Numbering by style](/editor/extensions/functionality/outline-numbering#numbering-by-style)              |

`OutlineNumberingOptions` is their type, and `OutlineSkippedLevel` the type of `skippedLevel`.

## Registering what is numbered

Which of your Node types carry a number is yours to say, because the schema is yours. Register
them by name in `types`, with how deep each one sits:

| Field    | Type                                         | Default    | Description                                                            |
| -------- | -------------------------------------------- | ---------- | ---------------------------------------------------------------------- |
| `level`  | `number \| 'nested' \| (node, context) => …` | `1`        | How deep the Node sits. `1` is the outermost                           |
| `marker` | `'inline' \| 'gutter'`                       | `'inline'` | Draw the number in front of the text, or in the margin before the Node |

- **A function** answers a number, `'nested'` or `null`. It gets the Node and
  `{ ancestors, lookup }`.
- **`ancestors`** are the Nodes around it, the outermost first.
- **`null`** leaves that Node unnumbered.
- **A number that is not a whole number from one** is read as the nearest level there is.
- **`'nested'`** is one level below the last Node before it that has a number level of its own,
  and one more for each `'nested'` Node it stands in. A [list of clauses](/editor/extensions/functionality/outline-numbering#lists-as-clauses) is
  numbered that way.
- **A type your schema does not have** is reported with a console warning when the editor is
  created.

`OutlineType` is the type of one entry, `OutlineTypes` of the record, `OutlineTypeContext` of
the second argument, `OutlineLevelAnswer` of the answer and `OutlineMarker` of `marker`.

### Numbering by style

A level can come from somewhere other than the Node itself, such as a paragraph style that says
where its paragraphs sit in the outline. `lookupOf` is a function of the document that answers an
object, and every `level` function gets that object as `lookup`:

```js
import { styleOutlineLevelOf, styleOutlineLevels } from '@tiptap-pro/extension-document-styles'

OutlineNumbering.configure({
  lookupOf: (doc) => styleOutlineLevels(doc, [houseStyle]),
  types: {
    heading: {
      level: (node, { lookup }) => {
        const level = styleOutlineLevelOf(lookup, node)
        return level === undefined ? node.attrs.level : level
      },
    },
    paragraph: { level: (node, { lookup }) => styleOutlineLevelOf(lookup, node) ?? null },
  },
})
```

`houseStyle` stands for your own style library.

- **A heading whose style is body text** is left unnumbered that way.
- **A heading without a style** is numbered by its own level.
- **Numbers are counted again** when `lookupOf` answers with another object. Answer with the
  same one for as long as what it holds is the same.
  [Document Styles](/editor/extensions/functionality/document-styles/definitions#outline-levels) does.
- **Without `lookupOf`**, `lookup` is `null`.

## How a level reads

Each level has a template. `{n}` is the count at level `n`, and a format after a colon writes it
differently:

| Placeholder       | Reads                                                                                                      |
| ----------------- | ---------------------------------------------------------------------------------------------------------- |
| `{2}` or `{2:1}`  | `1`, `2`, `3`                                                                                              |
| `{2:01}`          | `01`, `02`, … `10`                                                                                         |
| `{2:a}` / `{2:A}` | `a`, `b`, … `z`, `aa` / `A`, `B`, …                                                                        |
| `{2:i}` / `{2:I}` | `i`, `ii`, `iii` / `I`, `II`, `III`                                                                        |
| `{2:*}`           | `*`, `†`, `‡`, `§`, `**`, …                                                                                |
| `{2:lowerGreek}`  | Any [number format](/editor/extensions/functionality/number-formats) by its name, one you defined included |

```js
OutlineNumbering.configure({
  types: { heading: { level: (node) => node.attrs.level } },
  levels: [
    'Article {1:I}',
    'Section {1}.{2:01}',
    { label: '({3:a})', full: '{1}.{2:01}({3:a})' },
    { label: '({4:i})', full: '{1}.{2:01}({3:a})({4:i})' },
  ],
})
```

- **Everything else in a template** is text.
- **A level is a string**, or an object with a `label` and a `full` form. `OutlineLevel` is its
  type.
- **`label`** is what the heading shows.
- **`full`** names it from anywhere else in the document, as a cross-reference does. It is the
  label when you leave it out.
- **A level you leave out** reads `{1}.{2}…` down to its own. With no `levels` at all, headings
  are numbered `1`, `1.1`, `1.1.1`.
- **A level whose template is `''`** is not numbered. Its headings show nothing, and they still
  count.
- **A placeholder naming a format** that neither your code nor the document defines is written
  as it stands, such as `{2:clause}`, until one does.

### Word's numbering gallery

`OUTLINE_PRESETS` has the schemes of Word's _Outline Numbered_ gallery, nine levels each, ready
to pass as `levels`:

```js
import { OUTLINE_PRESETS, OutlineNumbering } from '@tiptap-pro/extension-outline-numbering'

OutlineNumbering.configure({
  types: { heading: { level: (node) => node.attrs.level } },
  levels: OUTLINE_PRESETS.legal,
})
```

| Preset          | Levels read                                                   |
| --------------- | ------------------------------------------------------------- |
| `parenthesized` | `1)`, `a)`, `i)`, then `(1)`, `(a)`, `(i)`, `1.`, `a.`, `i.`  |
| `decimal`       | `1.`, `1.1.`, `1.1.1.`                                        |
| `bullets`       | `❖`, `➢`, `▪`, then `●`, `◆`, `■`                             |
| `legal`         | `Article I.`, `Section 1.01`, `(a)`, then `(i)`, `(A)`, `(1)` |
| `headings`      | `1`, `1.1`, `1.1.1`: the same as no `levels`                  |
| `outline`       | `I.`, `A.`, `1.`, then `a)`, `(1)`, `(a)`, `(i)`              |
| `chapter`       | `Chapter 1`, and no number below it                           |

- **`legal`** names a level-3 clause `1.01(a)` from elsewhere in the document.
- **A preset is an array** like any other, so a scheme of your own can start from one:
  `[...OUTLINE_PRESETS.decimal.slice(0, 2), '{1}.{2}.{3:a}']`.
- **`OutlinePreset`** is the type of a preset's name.

### Counting

- **A level counts from one again** under every new heading above it.
- **Headings nested in other blocks**, a blockquote or a list, are counted where they stand.

A level skipped on the way down, such as a level-3 heading directly under a level 1, is not
counted. `skippedLevel` says what it reads:

| `skippedLevel`     | A skipped level                                               | A document that starts at level 2 |
| ------------------ | ------------------------------------------------------------- | --------------------------------- |
| `'zero'`           | Reads `0`: in `1`, `1.0.1`, the next level-2 heading is `1.1` | `1.1`, `1.2`, then `2`            |
| `'zeroEverywhere'` | Reads `0`, before the first number too. Word draws it so      | `0.1`, `0.2`, then `1`            |
| `'first'`          | Counts as its first: `1`, `1.1.1`, `1.2`                      | `1.1`, `1.2`, then `2`            |

- **Cutting a heading and leaving its clauses** produces a skipped level. The next heading of its
  level moves up.
- **In the digits of a format** the `0` is padded like the other numbers, as in `1.00(a)`.
- **A format of letters or Roman numerals** writes `0` as well.

## A scheme stored in the document

`levels` is the scheme every document gets. A document can carry its own instead. It then keeps
its numbering wherever it goes: to another editor, to everyone editing it with you, into a file.
Register `OutlineScheme` for that:

```js
import {
  OUTLINE_PRESETS,
  OutlineNumbering,
  OutlineScheme,
} from '@tiptap-pro/extension-outline-numbering'

const editor = new Editor({
  element: document.querySelector('#editor'),
  extensions: [
    StarterKit,
    OutlineNumbering.configure({ types: { heading: { level: (node) => node.attrs.level } } }),
    OutlineScheme,
  ],
})

editor.commands.setOutlineLevels(OUTLINE_PRESETS.legal)
```

- **One hidden block** at the end of the document holds the scheme. It is an `outlineScheme`
  Node (`OUTLINE_SCHEME_NODE`) with a template per level in its `levels` attribute.
- **In HTML** it is `<div data-tt-outline-scheme="true" hidden data-tt-levels="[…]">`.
  `OUTLINE_SCHEME_ATTRIBUTE` is `data-tt-outline-scheme`.
- **A stored level that is not a template**, written by hand or by an older version, is read as
  `levels` has that level.
- **Two documents with a scheme each, combined:** the first scheme counts.

### Writing the scheme with Transactions

| Function                      | Arguments                            | Description                                                                                           |
| ----------------------------- | ------------------------------------ | ----------------------------------------------------------------------------------------------------- |
| `setOutlineLevelsTransaction` | `tr`, `levels`                       | `setOutlineLevels` as a Transaction                                                                   |
| `setOutlineLevelTransaction`  | `tr`, `level`, `template`, `current` | `setOutlineLevel` as a Transaction. `current` is the scheme to start from where the document has none |
| `outlineLevelsOf`             | `doc`, `levels`                      | The scheme a document is numbered by, with `levels` where it stores none                              |
| `outlineSchemeAt`             | `doc`                                | The block and its position, `{ node, pos }` (`OutlineSchemeAt`), or `null`                            |
| `outlineLabelFor`             | `scheme`, `counts`, `context?`       | What a heading with these counts reads in a scheme: `{ label, fullLabel }`                            |

- **The two Transactions throw** for a template that is not a string or `{ label, full? }`, and
  when the schema has no `outlineScheme` Node.
- **`outlineLabelFor`** is the preview a dialog shows beside each level.
  `outlineLabelFor(OUTLINE_PRESETS.legal, [1, 1, 1])` is `(a)` and `1.01(a)`.

## Lists as clauses

A numbered list can belong to the outline, as a list linked to a heading style does in Word. Its
items are numbered a level below the heading before them, and an item indented under one is a
level below that. Under `Section 1.01` they read `(a)`, `(b)`, and `(i)` under `(b)`.

```js
import { OutlineNumbering, outlineListItem } from '@tiptap-pro/extension-outline-numbering'

OutlineNumbering.configure({
  types: {
    heading: { level: (node) => node.attrs.level },
    listItem: outlineListItem,
  },
  lists: ['orderedList'],
})
```

Then `editor.commands.setOutlineList(true)` makes the list around the cursor a list of clauses.
See [setOutlineList](/editor/extensions/functionality/outline-numbering#setoutlinelist).

- **`lists`** are the list types that can belong to the outline. Each gets a boolean
  `outlineList` attribute (`OUTLINE_LIST_ATTRIBUTE`), `data-tt-outline-list` in HTML.
- **`outlineListItem`** is the registration for a list item: `'nested'` inside a list that has
  `outlineList`, `null` anywhere else, drawn in the gutter.
- **The setting is on the outermost list.** The lists inside it count as part of it, so an item
  indented with Tab is a clause too.
- **Under an `Article` heading** the same list reads one level higher.

### How clauses count

- **Clauses count together with the headings.** `(a)` starts again under every heading above it.
- **A second list under the same heading** goes on with `(c)` where the first stopped at `(b)`.

### How a clause is drawn

- **In the margin.** A clause's number stands in the margin before the item, and the list's own
  marker is not drawn.
- **No line moves.** The number is no part of a line, so a label growing from `(ix)` to `(x)`
  moves no text.
- **The list is indented** by `--tt-outline-list-indent` (`2.5em`) to make room. A stylesheet of
  yours that sets the list's `padding-inline-start` more specifically wins.
- **An item `ignore` answers `'descend'` for** has no number of its own and draws no list marker
  either. It gets `data-tt-outline-marker="gutter"` without a `data-tt-outline-number`.

### Reading the list

- **`outlineListAt(doc, pos)`** returns the outermost list of a `lists` type around a position,
  as `{ pos, node, linked }` (`OutlineListAt`), or `null`.
- **`setOutlineListTransaction(state, linked)`** is `setOutlineList` as a Transaction, or `null`
  outside such a list.

## How a number is shown

A numbered Node gets attributes in the editor, never in the document:

| Attribute                | Constant                   | Value                                        |
| ------------------------ | -------------------------- | -------------------------------------------- |
| `data-tt-outline-number` | `OUTLINE_NUMBER_ATTRIBUTE` | The label                                    |
| `data-tt-outline-level`  | `OUTLINE_LEVEL_ATTRIBUTE`  | The level                                    |
| `data-tt-outline-marker` | `OUTLINE_MARKER_ATTRIBUTE` | `gutter`, for a type with `marker: 'gutter'` |

What prints the label is CSS, which you put into the page:

```js
import { mountOutlineStyles } from '@tiptap-pro/extension-outline-numbering'

mountOutlineStyles(document, { nonce })
```

- **`mountOutlineStyles(document, options?)`** adds the rules once, at the end of `head`.
  `options` takes `nonce`, the one you give the editor as `injectNonce`, and `id`, the style element's id,
  `'tiptap-outline-numbering-styles'` by default.
- **`outlineStyleRules()`** returns the rules as a string, for a stylesheet of your own.
- **The rules print the label** in front of the text, followed by a gap. For `gutter` they print
  it in the margin before the Node, the same gap away.
- **`getHTML()` and `getJSON()`** do not contain the number, because it is not in the document.

| Custom property                    | Default         | Description                                      |
| ---------------------------------- | --------------- | ------------------------------------------------ |
| `--tt-outline-number-gap`          | `0.5em`         | The gap between the number and the text          |
| `--tt-outline-number-color`        | `inherit`       | The number's color                               |
| `--tt-outline-list-indent`         | `2.5em`         | The indent of a list of clauses                  |
| `--tt-outline-selected-background` | `Highlight`     | The background of a numbered Node selected whole |
| `--tt-outline-selected-color`      | `HighlightText` | Its text color                                   |

A heading selected as a whole gets the editor's `ProseMirror-selectednode` class, which the last
two tint.

### When a number changes without an edit

Numbers are counted again whenever the document changes. If your `level` or `ignore` function
answers differently for another reason, run
[refreshOutlineNumbers](/editor/extensions/functionality/outline-numbering#refreshoutlinenumbers). The same is the Transaction meta
`tr.setMeta(outlineLabelsKey, 'refresh')`, where `outlineLabelsKey` is a `PluginKey`.

## Deleting a numbered heading

The number cannot be selected on its own, since it is not text. Deleting works the way Word
deletes a numbered paragraph:

- **A click on the number**, or a triple click in the heading, selects the whole heading. Cut or
  delete it, and the heading is gone, number and all.
- **A selection from the heading's first character into the next block** deletes the heading
  whole with Backspace, Delete or Cut. The rest of the next block keeps its own type, rather than
  becoming a numbered heading.
- **A selection inside the heading's text** deletes the text, and keeps the heading and its
  number.
- **Typing over a selection** replaces it the usual way, and keeps the heading.

## Copy and paste

- **A copy writes each heading's label in front of its text**, so a heading copied into a mail
  or another program reads `1.2 Scope`.
- **A heading counts as copied** when the selection holds it from its first character. One the
  selection begins inside of is copied without its label.
- **The copied HTML marks the heading** with `data-tt-outline-label="1.2"`.
- **Pasted into an editor that has `OutlineNumbering`**, the label is taken out of the text
  again, and the heading is numbered where it lands.
- **A heading whose text really begins with its number** keeps it, because only the marked label
  is taken out.
- **A clause takes its label along** in front of the text of the item's first paragraph, so a
  copied clause reads `(a) charge interest…`. An item whose first child is not a textblock is
  copied without it.
- **Each registered type has a `copiedOutlineLabel` attribute** (`COPIED_LABEL_ATTRIBUTE`) for
  that mark. It is `null` in every document, and appears in `getJSON()` as `null`.

## Leaving Nodes out

`ignore` is a function of a Node (`OutlineIgnore`):

- **`true`** leaves the Node unnumbered, and nothing inside it is numbered either.
- **`'descend'`** leaves the Node unnumbered, and what is inside it is counted as usual.
- **`false`** counts the Node.
- **A Node answered `'descend'` still counts for depth.** A `'nested'` item inside it is a level
  below, as it would be inside the Node it stands for.

## Reading the numbers

```js
import { outlineNumberAt, outlineNumbersIn } from '@tiptap-pro/extension-outline-numbering'

const registry = editor.storage.outlineNumbering

for (const { pos, level, counts, label, fullLabel } of outlineNumbersIn(
  editor.state.doc,
  registry,
)) {
  // counts is [1, 1, 2] for 1.1.2, the outermost first
}
```

| Function           | Arguments                   | Returns                                                            |
| ------------------ | --------------------------- | ------------------------------------------------------------------ |
| `outlineNumbersIn` | `doc`, `registry`           | Every number in the document, in order, as `OutlineNumber`s        |
| `outlineNumberAt`  | `doc`, `registry`, `pos`    | The number of the Node starting at `pos`, or `null`                |
| `outlineLevelOf`   | `types`, `node`, `context?` | What a Node's registration answers: a level, `'nested'`, or `null` |

| Field of `OutlineNumber` | Type                   | Description                                    |
| ------------------------ | ---------------------- | ---------------------------------------------- |
| `node`                   | `Node`                 | The numbered Node                              |
| `pos`                    | `number`               | Where it starts                                |
| `level`                  | `number`               | Its level                                      |
| `counts`                 | `number[]`             | The count at every level down to its own       |
| `label`                  | `string`               | What its own template writes, such as `(a)`    |
| `fullLabel`              | `string`               | What names it from anywhere, such as `1.01(a)` |
| `marker`                 | `'inline' \| 'gutter'` | Where its type draws the number                |

- **`registry`** is `editor.storage.outlineNumbering`: the options `types`, `levels`, `ignore`,
  `lookupOf` and `skippedLevel`. `OutlineNumberingStorage` and `OutlineRegistry` are its types.
- **Both read the document you pass.** A document is counted once for each editor, however often
  you ask.
- **`outlineLevelOf`** answers `null` for a type that is not registered, and for a Node that is
  not numbered. Pass `{ ancestors }` as `context`.

## Commands

### setOutlineLevels

Stores a scheme in the document, or removes it with `null` so that `levels` counts again.

```js
editor.commands.setOutlineLevels(OUTLINE_PRESETS.legal)
editor.commands.setOutlineLevels(null)
```

| Argument | Type                     | Description                                  |
| -------- | ------------------------ | -------------------------------------------- |
| `levels` | `OutlineLevel[] \| null` | A template per level, or `null` for `levels` |

Needs `OutlineScheme`. Returns `false` for a template that is not a string or
`{ label, full? }`, when the document already stores this scheme, and for `null` when it stores
none.

### setOutlineLevel

Stores one level of the document's scheme.

```js
editor.commands.setOutlineLevel(2, 'Section {1}.{2:01}')
```

| Argument   | Type           | Description                  |
| ---------- | -------------- | ---------------------------- |
| `level`    | `number`       | The level, the first being 1 |
| `template` | `OutlineLevel` | Its template                 |

- **The other levels** stay as the document has them, or as `levels` has them where it has
  none yet.
- **Levels before it that neither has** are filled in as `{1}.{2}…`.

Needs `OutlineScheme`. Returns `false` for a level that is not a whole number from 1, for a
template that is not a string or `{ label, full? }`, and when the scheme the document stores
already has that template at that level.

### refreshOutlineNumbers

Counts the numbers again with the document unchanged.

```js
editor.commands.refreshOutlineNumbers()
```

Never returns `false`.

### setOutlineList

Makes the list around the selection a list of clauses, or a plain list again.

```js
editor.commands.setOutlineList(true)
editor.commands.setOutlineList(false)
```

| Argument | Type      | Description                             |
| -------- | --------- | --------------------------------------- |
| `linked` | `boolean` | Whether the list belongs to the outline |

It sets the attribute on the outermost list of one of the `lists` types around the selection,
and clears it on the lists inside.

Returns `false` outside a list of one of the `lists` types, so `editor.can().setOutlineList(true)`
tells a toolbar whether to offer it.

## Limitations

- **Two people setting the scheme at the same moment:** the last write wins whole. One person's
  change to level 2 and another's to level 3 keep only one of them.
- **A second scheme Node**, from two documents combined, is ignored, and nothing removes it.
- **Typing over a selection** from a heading's first character into the next block keeps the
  heading. Word deletes it.
- **A cut from a heading's first character into the next block** can put plain text without the
  heading's number on the clipboard. With
  [Whole blocks](/editor/extensions/functionality/whole-blocks) registered, the number is in the
  text.
- **A schema attribute for the copy.** Every numbered Node carries `copiedOutlineLabel: null` in
  its JSON.
- **The numbers need `mountOutlineStyles`** or `outlineStyleRules()`. The extension does not put
  its rules into the page.

What changes on pages: see
[Outline numbering in Page Layout](/page-layout/paginating-extensions/outline-numbering).
