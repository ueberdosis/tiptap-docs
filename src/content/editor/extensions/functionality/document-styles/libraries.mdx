```js
import { DocumentStyles, styleLibrary } from '@tiptap-pro/extension-document-styles'

const house = styleLibrary(
  [{ id: 'body', name: 'House Body', kind: 'paragraph', props: { fontFamily: 'Inter' } }],
  { scope: 'organization' },
)

DocumentStyles.configure({
  types: ['paragraph', 'heading'],
  libraries: [house],
})
```

Replace a library's styles, and every editor using it draws them again:

```js
house.setStyles(await fetchHouseStyles())
```

- **Nothing of a library is stored in the document.**
- **A document opened without it** keeps its references. It draws them by whatever else defines
  those ids, or as [missing](/editor/extensions/functionality/document-styles/cleanup#missing-styles).
- **Switching libraries** changes how content looks, never the content.

## Making a library

`styleLibrary(definitions, options)` returns a `WritableStyleLibrary`:

| Option  | Type                    | Description                                                                                                                                         |
| ------- | ----------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| `scope` | `StyleScope`            | The scope its definitions are labeled with where they say none themselves                                                                           |
| `theme` | `DocumentTheme \| null` | The theme its styles are meant to be drawn in. See [A library's theme](/editor/extensions/functionality/document-styles/libraries#a-librarys-theme) |

| Method      | Arguments     | Description                                                          |
| ----------- | ------------- | -------------------------------------------------------------------- |
| `getStyles` | —             | Its definitions                                                      |
| `setStyles` | `definitions` | Replaces them, and every editor using it draws them again            |
| `getTheme`  | —             | Its theme, or `null`                                                 |
| `setTheme`  | `theme`       | Replaces its theme                                                   |
| `subscribe` | `listener`    | Calls `listener` on a change. Returns the function that unsubscribes |

## Word's built-in styles

An editor has the styles a new Word document starts with, unless `wordStyles` is `false`. They
are under every library you configure. A library of yours, or the document's own style, that
defines the same id is the one drawn.

| id                                                          | Name                 | Kind              | On                                                             |
| ----------------------------------------------------------- | -------------------- | ----------------- | -------------------------------------------------------------- |
| `normal`                                                    | Normal               | paragraph         | the default of every paragraph                                 |
| `no-spacing`                                                | No Spacing           | paragraph         |                                                                |
| `title`, `subtitle`                                         | Title, Subtitle      | paragraph, linked |                                                                |
| `heading-1` to `heading-3`                                  | Heading 1 to 3       | paragraph, linked | a heading of that level; the default of headings of that level |
| `quote`, `intense-quote`                                    | Quote, Intense Quote | paragraph         | puts the paragraphs in a blockquote                            |
| `subtle-emphasis`, `emphasis`, `intense-emphasis`, `strong` |                      | character         |                                                                |

- **A document with no styles of its own** is drawn in them: a paragraph in Normal, a heading of
  the second level in Heading 2.
- **Their fonts and colors** refer to the [theme](/editor/extensions/functionality/document-styles/themes).
- **Each has the `builtIn` name** a .docx knows it by.
- **A style for a type the editor does not style** is left out: the quotes without `blockquote`
  in `types`, the character styles without a Mark.

```js
DocumentStyles.configure({
  libraries: [house], // house wins; Word's styles fill in what it does not define
})

DocumentStyles.configure({
  wordStyles: false, // none of Word's styles
})

DocumentStyles.configure({
  wordStyles: { defaults: false }, // to apply, but a paragraph nobody styled stays as it was
})
```

With `defaults: false`, Normal and the headings are no type's default. Content that has no styles
keeps the look it had, and Word's styles are there to apply. To give every block its default
later, see [applyDefaultStyles](/editor/extensions/functionality/document-styles/cleanup#applydefaultstyles).

### Word's styles as a library of your own

`wordStyleLibrary(options)` is the same styles as a library of your own, for types named
differently or to put them somewhere other than last. Use it with `wordStyles: false`:

```js
wordStyleLibrary({
  paragraphType: 'paragraph',
  headingType: 'heading',
  quoteType: null,
  markType: 'textStyle',
})
```

| Option          | Type             | Default        | Description                                                                      |
| --------------- | ---------------- | -------------- | -------------------------------------------------------------------------------- |
| `paragraphType` | `string`         | `'paragraph'`  | The type Normal is the default of                                                |
| `headingType`   | `string \| null` | `'heading'`    | The heading type, with a `level` attribute. `null` leaves the headings out       |
| `quoteType`     | `string \| null` | `'blockquote'` | The type the quotes put their paragraphs in. `null` leaves them out              |
| `markType`      | `string \| null` | `'textStyle'`  | The Mark for character and linked styles. `null` leaves the character styles out |
| `defaults`      | `boolean`        | `true`         | Whether Normal and the headings are what an unstyled block is drawn in           |

- **`wordStyleLibrary({ defaults: false })`** is `wordStyles: { defaults: false }` as a library.
- **`wordStyles(options)`** gives the same definitions as an array, to store in a document or to
  start a library of your own from.
- **`WORD_STYLES`** is that array for the default types.

## A library's theme

A library can bring the [theme](/editor/extensions/functionality/document-styles/themes) its styles are meant to be drawn in, and publish a new
one the same way as new styles:

```js
const house = styleLibrary(houseStyles, {
  scope: 'organization',
  theme: { name: 'House', colors: { accent1: '#536dfe' } },
})

house.setTheme({ name: 'House 2026', colors: { accent1: '#0f766e' } })
```

- **Where it sits.** Under the document's own theme and over the `theme` option, font by font and
  color by color.
- **With `precedence: 'libraries'`** it wins over the document's.
- **Among libraries**, the first one's wins.

## Which definition wins

The same id can be defined by the document and by a library:

```mermaid
flowchart TB
  id["styleId: body"] --> precedence{"precedence"}
  precedence -->|"'document' (default)"| own{"Does the document define it?"}
  own -->|yes| docWins["The document's"]
  own -->|no| firstLib["The first library that defines it"]
  precedence -->|"'libraries'"| lib{"Does a library define it?"}
  lib -->|yes| firstLib
  lib -->|no| docWins
```

- **`'document'`, the default.** A style changed in one document stays as it was changed when the
  library is updated later.
- **`'libraries'`.** The house style wins over a document's own of the same id.

```js
const styles = editor.storage.documentStyles.stylesOf(editor.state.doc)

styles.getStyle('body')?.scope // 'document', or the library's scope
styles.originOf('body') // 'document' or 'library'
```

## Read only

A Command that would change a library's style returns `false`: `setStyleDefinition` with its id,
`renameStyle`, `deprecateStyle`, `updateStyleFromSelection`, `deleteStyle`.

- **Applied and inherited from** like any other style.
- **`duplicateStyle`** gives the document a copy of its own to change:

```js
editor.commands.duplicateStyle('body', 'my-body', 'Body, adjusted')
```

## A library of your own

Anything with `getStyles()` is a `StyleLibrary`:

```js
const library = {
  scope: 'workspace',
  getStyles: () => cache.styles,
  getTheme: () => cache.theme,
  subscribe: (listener) => cache.on('change', listener),
}
```

| Member      | Arguments  | Required | Description                                                                         |
| ----------- | ---------- | -------- | ----------------------------------------------------------------------------------- |
| `getStyles` | —          | Yes      | Its definitions                                                                     |
| `scope`     | —          | No       | The scope its definitions are labeled with                                          |
| `getTheme`  | —          | No       | Its theme, or `null`                                                                |
| `subscribe` | `listener` | No       | How the editor learns of a change to either. Returns the function that unsubscribes |

A change to a library is not a change to the document. With `stylesheet` on, the editor draws
the styles again. It dispatches a Transaction with the meta `STYLE_LIBRARY_CHANGED`, so whatever
lays the content out can do it again.

Outside an editor, `styleLookupOf(doc, libraries, precedence)` gives the same lookup for any
document of the schema:

```js
import { styleLookupOf } from '@tiptap-pro/extension-document-styles'

styleLookupOf(state.doc, [house]).getStyles()
```
