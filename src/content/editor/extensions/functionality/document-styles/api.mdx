## Setup

```js
DocumentStyles.configure({
  types: ['paragraph', 'heading', 'blockquote'],
  markTypes: ['textStyle', 'code', 'highlight'],
  libraries: [houseStyle],
  precedence: 'document',
})
```

- **Every option can be left out.** `DocumentStyles` alone styles the `paragraph`, `heading`,
  `blockquote` and `table` types and the `textStyle` Mark the schema has. It brings Word's
  built-in styles under the libraries (`wordStyles: true`).
- **Every option**, with its type and default, is in [Options](/editor/extensions/functionality/document-styles#options).
- **`DocumentStylesOptions`** is the type of the options, and `DocumentStylesStorage` the type of
  `editor.storage.documentStyles`.

## Shared styles

The definitions are kept in the document, in the hidden `styleDefinitions` Node. They are saved
with it, undone with the history, and shared with every collaborator through Tiptap
Collaboration. There is nothing to synchronize besides the document.

- **One Node per definition.** Each definition is a `styleDefinition` Node inside it. Two
  collaborators changing two styles at once both keep their change.
- **The same style at once.** Two collaborators changing the same style at once end with one of
  the two, the same for both.
- **The same new id at once.** Two collaborators adding a style with the same id at once leave two
  `styleDefinition` Nodes of it. The first is read, and the next change to that style removes the
  other one.
- **The first style at once.** Two collaborators writing the first style or the theme of a
  document at once each add a `styleDefinitions` Node.
- **Repair.** With `repair` on, the default, the editor moves the definitions of the second Node
  into the first: those of an id the first does not have, and its theme where the first has none.
  It removes the second. This is not added to the history.
- **Without an editor**, `repairStyleDefinitionsTransaction(transaction)` does the same.

| Export                                                      | Arguments            | What it is                                                                       |
| ----------------------------------------------------------- | -------------------- | -------------------------------------------------------------------------------- |
| `styleDefinitionsOf`                                        | `doc`                | The document's own definitions                                                   |
| `styleDefinitionsAt`                                        | `doc`                | The `styleDefinitions` Node and its position, or `null`                          |
| `styleDefinitionsContent`                                   | `definitions, theme` | The `styleDefinitions` Node as JSON, for content put together rather than edited |
| `StyleDefinitions`, `StyleDefinitionEntry`                  | —                    | The two Nodes, which `DocumentStyles` adds itself                                |
| `STYLE_DEFINITIONS_NODE`, `STYLE_DEFINITION_NODE`           | —                    | Their names, `'styleDefinitions'` and `'styleDefinition'`                        |
| `STYLE_DEFINITIONS_ATTRIBUTE`, `STYLE_DEFINITION_ATTRIBUTE` | —                    | Their DOM attributes, `data-tt-style-definitions` and `data-tt-style-definition` |

## Rendering

- **A stylesheet of the editor's own**, one rule per style, selected by `data-tt-style-id` and
  scoped to the editor's element by `data-tt-document-styles`.
- **An override** is written as `data-tt-style-overrides` and as inline CSS, which wins over the
  rule.
- **`stylesheet: false`** leaves the CSS to you. `documentStylesStylesheet(lookup, scope, options)` writes the rules, with `StylesheetOptions`. `styleDeclarations(props)` writes one
  declaration list.

| Constant                          | Value                     | On                            |
| --------------------------------- | ------------------------- | ----------------------------- |
| `STYLE_ID_ATTRIBUTE`              | `data-tt-style-id`        | A styled block or run         |
| `STYLE_OVERRIDES_ATTRIBUTE`       | `data-tt-style-overrides` | A block or run with overrides |
| `DEFAULT_STYLE_ATTRIBUTE`         | `data-tt-style-default`   | A block drawn in its default  |
| `DOCUMENT_STYLES_SCOPE_ATTRIBUTE` | `data-tt-document-styles` | The editor's element          |
| `TABLE_STYLE_ATTRIBUTE`           | `data-tt-table-style`     | A cell of a styled table      |
| `TABLE_CELL_ATTRIBUTE`            | `data-tt-table-cell`      | The conditions a cell is in   |
| `TABLE_LOOK_ATTRIBUTE`            | `data-tt-table-look`      | The parts a table shows       |

See [How it is drawn](/editor/extensions/functionality/document-styles#how-it-is-drawn).

## Marks

- **A character style** goes on the first type in `markTypes` unless its `targets` name another:
  `textStyle`, `highlight`, `code`, or any Mark of the schema.
- **The Mark keeps its own meaning** and carries the `styleId` beside it.
- **A linked style**, which goes on a paragraph and on text alike, lists a `node` and a `mark`
  target.

## Pasting from Word

`wordStylesToHtml(html, styleIdOf)` and `styleIdOfWordNameIn(doc, libraries, precedence)` do on
a string what a paste does. `styleIdOf` is a `StyleIdOfWordName`. See
[Pasting from Word](/editor/extensions/functionality/document-styles#pasting-from-word).

## Types of a definition

`StyleDefinition`, `StyleKind`, `StyleScope`, `StyleTarget`, `StyleNodeTransform`,
`StyleDefaultFor`, `StylePagination`, `StyleProps`, `StyleValue` and `StyleOverrides` are the
types of [a definition's fields](/editor/extensions/functionality/document-styles/definitions#what-a-definition-holds). `isStyleDefinition`
checks one. `ResolvedStyle`, `ResolveStyleResult` and `ResolveStyleError` are what `resolveStyle`
answers.
