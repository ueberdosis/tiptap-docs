## The built-in displays

| `show`            | Reads                                                                   | For `(b)` under clause 3                |
| ----------------- | ----------------------------------------------------------------------- | --------------------------------------- |
| `relativeNumber`  | The number, with as much context as it needs where the reference stands | `(b)` inside clause 3, `3(b)` elsewhere |
| `number`          | The number as the target shows it                                       | `(b)`                                   |
| `fullNumber`      | The number with all of its context. The default                         | `3(b)`                                  |
| `title`           | The target's title                                                      | `Late payment`                          |
| `page`            | The page the target is on, from `pageOf`                                | `7`                                     |
| `aboveBelow`      | `above` when the target comes first, `below` when it comes after        | `below`                                 |
| `formattedNumber` | The number, printed as a note's mark is                                 | `²`                                     |

`relativeNumber` needs to know which levels the number has. Give the target's `label` a `counts`
array, one count per level, such as `[3, 2]` for `3(b)`. A number without `counts` is written
whole.

```js
heading: {
  label: ({ doc, pos }) => {
    const found = outlineNumberAt(doc, outline, pos)
    return found && { number: found.label, fullNumber: found.fullLabel, counts: found.counts }
  },
},
```

- **`numberSeparator`** applies to the three numbers. It replaces every run of punctuation
  between the parts: `3-b` for `3(b)` with `-`.
- **`aboveBelow: true`** adds `above` or `below` to any display, as in `3(b) below` or
  `page 7 above`.
- **`formattedNumber`** carries `data-tt-cross-reference-format="superscript"`, which the
  package's styles raise.

A target outside the document, from a [source](/editor/extensions/functionality/cross-references/sources), has no page and no side:

- **`page` and `aboveBelow`** are unresolved, with `page` missing.
- **`relativeNumber`** reads the full number.
- **`aboveBelow: true`** adds nothing.

## Reference types

A registered target has a type, which a picker lists first. It is Word's "Reference type". The
type is the Node type's name by default. Give a string, or a function of the Node where one Node
type is two kinds of target:

```js
CrossReferences.configure({
  targets: {
    heading: { type: 'Heading', label: /* … */ },
    footnote: {
      type: node => (node.attrs.placement === 'endnote' ? 'Endnote' : 'Footnote'),
      displays: ['number', 'formattedNumber', 'page', 'aboveBelow'],
      label: /* … */,
    },
  },
})
```

`displays` lists which values of `show` a reference to this target may have, in the order a
picker lists them:

- **An entry** is an id, or `{ id, title }` to name it differently for this type.
- **Without `displays`,** a target with a `label` offers the three numbers, the title, the page
  and above/below.
- **A target without a `label`** offers the title, the page and above/below.

## Your own displays

A display the package does not have is registered by id. A type lists it like a built-in one:

```js
CrossReferences.configure({
  displays: {
    captionLabel: {
      title: 'Only label and number',
      numbered: true,
      text: ({ target }) => target.label && `Figure ${target.label.number}`,
    },
  },
  targets: {
    figure: { type: 'Figure', displays: ['captionLabel', 'title', 'page'], label: /* … */ },
  },
})
```

| Field      | Type                          | Default    | Description                                                       |
| ---------- | ----------------------------- | ---------- | ----------------------------------------------------------------- |
| `title`    | `string`                      | —          | What a picker lists it as                                         |
| `text`     | `(context) => string \| null` | —          | What a reference reads of one target. `null` leaves it unresolved |
| `missing`  | `'number' \| 'page'`          | `'number'` | What an unresolved reference says is missing                      |
| `numbered` | `boolean`                     | `false`    | Whether `numberSeparator` applies to the text                     |
| `format`   | `string`                      | —          | Written to `data-tt-cross-reference-format`, for a stylesheet     |

`text` gets a context with these fields:

| Field       | Description                                                           |
| ----------- | --------------------------------------------------------------------- |
| `target`    | The target, as `crossReferenceTargetsIn` lists it                     |
| `reference` | The reference                                                         |
| `doc`       | The document                                                          |
| `context`   | The last target of the same type in front of the reference, or `null` |
| `phrases`   | The phrases, with `above` and `below`                                 |
| `pageOf`    | The `pageOf` option                                                   |

- **A [source's](/editor/extensions/functionality/cross-references/sources) target** carries what the source gave along in `target.data`.
- **A target outside the document** has `target.pos` and `target.node` `null`, and is never the
  `context`.

### A house style

How a label reads is the display's, so a style guide is a display. This brief cites its own notes
as `note 4`, and its own parts as `Part II.B above`:

```js
CrossReferences.configure({
  displays: {
    noteCite: {
      title: 'note N',
      numbered: true,
      text: ({ target }) => target.label && `note ${target.label.number}`,
    },
    partCite: {
      title: 'Part N above/below',
      numbered: true,
      text: ({ target, reference, phrases }) =>
        target.label &&
        `Part ${target.label.fullNumber} ${target.pos < reference.pos ? phrases.above : phrases.below}`,
    },
  },
  targets: {
    footnote: { displays: ['noteCite', 'formattedNumber'], label: /* … */ },
    heading: { displays: ['partCite', 'fullNumber', 'title'], label: /* … */ },
  },
})
```

- **A display with the id of a built-in one** replaces it.
- **`relativeNumberOf(target, context)` and `separatedNumber(number, separator)`** are the
  helpers the built-in displays use.
- **`DEFAULT_CROSS_REFERENCE_DISPLAYS`** holds all built-in displays.

## Offering the choices

`crossReferenceTypesIn` returns what a dialog needs, in one call. It lists every type the
document has a target of, in reading order, with its targets and what a reference to one can
show:

```js
import { crossReferenceTypesIn } from '@tiptap-pro/extension-cross-references'

for (const { name, targets, displays } of crossReferenceTypesIn(
  editor.state.doc,
  editor.storage.crossReferences,
)) {
  // name: 'Heading'; targets: [{ pos, id, title, label, type }, …]; displays: [{ id, title }, …]
}
```
