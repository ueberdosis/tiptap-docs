The text in one column does not flow into the next. For one run of text that fills the bottom
of the first column and carries on at the top of the second, use
[section columns](/page-layout/features/section-columns).

## Install

```bash
npm install @tiptap-pro/extension-columns
```

- **The Pro registry.** The package comes from Tiptap's private registry. See
  [The Pro registry](/page-layout/getting-started/install#the-pro-registry)
  to set it up.
- **Peer dependencies.** `@tiptap/core` and `@tiptap/pm`.
- **Without pages.** The package works in any Tiptap editor, with or without Page Layout. A
  layout grows with its content.

## Quick start

Add `Columns` to an editor and insert a layout of two columns:

```js
import { Editor } from '@tiptap/core'
import StarterKit from '@tiptap/starter-kit'
import { Columns } from '@tiptap-pro/extension-columns'

const editor = new Editor({
  element: document.querySelector('#editor'),
  extensions: [StarterKit, Columns],
})

editor.commands.insertColumns({ count: 2 })
```

The caret is in the first column. Type into it, and press `Mod-Enter` to leave the layout.

## The document

`Columns` registers two Node types together:

| Type           | Description                                                                   |
| -------------- | ----------------------------------------------------------------------------- |
| `columnLayout` | The row. Holds `minColumns` to `maxColumns` `column`s, two to six by default  |
| `column`       | One column. Holds any blocks, such as paragraphs, headings, a table, an image |

```json
{
  "type": "columnLayout",
  "attrs": { "gap": "32px", "widthMode": "custom", "widths": ["1fr", "2fr"] },
  "content": [
    { "type": "column", "content": [{ "type": "paragraph" }] },
    { "type": "column", "content": [{ "type": "paragraph" }] }
  ]
}
```

| Attribute   | Type                  | Default   | Description                                                           |
| ----------- | --------------------- | --------- | --------------------------------------------------------------------- |
| `gap`       | `string \| null`      | `null`    | The space between columns, as a CSS length. `null` is drawn as `24px` |
| `widthMode` | `'equal' \| 'custom'` | `'equal'` | Equal columns, or the widths in `widths`                              |
| `widths`    | `string[] \| null`    | `null`    | One CSS track size per column, such as `'1fr'` or `'240px'`           |

- **`widths` is read** only while `widthMode` is `'custom'`.
- **Widths of the wrong length** are not used. The layout is drawn with equal columns until
  `widths` has one entry per column.
- **Adding or removing a column** makes custom widths equal again.
- **A layout is a top-level block.** A layout inside a column is valid content, from a paste
  for example, but no Command creates one.

## Options

```js
Columns.configure({
  minColumns: 2,
  maxColumns: 6,
  defaultGap: '24px',
  defaultWidthMode: 'equal',
})
```

| Option             | Type                  | Default   | Description                                   |
| ------------------ | --------------------- | --------- | --------------------------------------------- |
| `minColumns`       | `number`              | `2`       | The fewest columns a layout may have          |
| `maxColumns`       | `number`              | `6`       | The most columns a layout may have            |
| `defaultGap`       | `string`              | `'24px'`  | The `gap` a new layout is inserted with       |
| `defaultWidthMode` | `'equal' \| 'custom'` | `'equal'` | The `widthMode` a new layout is inserted with |

- **The bounds are part of the schema.** Content with more or fewer columns does not load.
- **Every editor on one shared document** needs the same `minColumns` and `maxColumns`.
- **`defaultGap` is written into a new layout.** A layout whose `gap` is `null` is drawn with
  `24px`, whatever `defaultGap` says.

## Keys

| Key                                               | Description                                                                        |
| ------------------------------------------------- | ---------------------------------------------------------------------------------- |
| `Mod-Enter`                                       | Leaves the layout: `exitColumns()`                                                 |
| `ArrowLeft`, `Backspace` at the start of a column | Moves the caret to the end of the previous column. Backspace deletes nothing there |
| `ArrowRight` at the end of a column               | Moves the caret to the start of the next column                                    |
| `ArrowDown` at the end of a column                | Leaves the layout when it is the last block of the document                        |
| `ArrowUp` at the start of a column                | Leaves the layout when it is the first block of the document                       |

Everywhere else the keys do what they do in any block.

## Styling

The extension draws the grid with rules it puts into the page itself, first in `head`, so a
stylesheet of yours wins over them.

- **The row.** The rules lay the columns out side by side.
- **A column keeps its share** even with a long word or a wide image in it.
- **Columns of different length** keep their own height.
- **Nothing has a border or a background.**

| Selector                        | Description                                                 |
| ------------------------------- | ----------------------------------------------------------- |
| `.tiptap-columns-layout`        | The layout, also `[data-tt-column-layout]`                  |
| `.tiptap-columns-column`        | A column, also `[data-tt-column]`                           |
| `.tiptap-columns-column-active` | The column the cursor is in. The extension gives it no look |

| Custom property      | Description                                 |
| -------------------- | ------------------------------------------- |
| `--tt-column-gap`    | The layout's gap, set on its element        |
| `--tt-column-widths` | Its track list, while the widths are custom |

An outline on the active column is one rule:

```css
.tiptap .tiptap-columns-column-active {
  outline: 1px dashed rgba(0, 0, 0, 0.2);
}
```

### The rules in a stylesheet of your own

- **When the rules go in.** They are added when the editor is created, as a `style` element
  that carries the editor's `injectNonce`.
- **`injectCSS: false`** leaves them out, as it leaves out Tiptap's own. Without them the
  columns stack.
- **`columnStyleRules()`** returns the rules as a string, for a stylesheet of your own.
- **`mountColumnStyles(document, { nonce })`** puts them into a document once.

## Commands

Every Command but `insertColumns` works on the layout the cursor is in, or on a layout selected
as a Node. `addColumn`, `removeColumn` and `moveColumn` also need the cursor inside a column.

`can()` answers whether a Command would do anything, so a toolbar can disable a button:

```js
editor.can().addColumn() // false at maxColumns, or outside a column
```

### insertColumns

Inserts a layout of empty columns after the top-level block at the cursor, and puts the caret in
the first column.

```js
editor.commands.insertColumns({ count: 3, gap: '32px' })
```

| Option      | Type                  | Default            | Description                             |
| ----------- | --------------------- | ------------------ | --------------------------------------- |
| `count`     | `number`              | `minColumns`       | How many columns. Clamped to the bounds |
| `gap`       | `string \| null`      | `defaultGap`       | The space between the columns           |
| `widthMode` | `'equal' \| 'custom'` | `defaultWidthMode` | The width mode of the layout            |

- **An empty paragraph or heading at the cursor** is replaced by the layout.
- **A cursor inside a layout** gets the new layout after it.

Returns `false` only when the schema has no block to fill a column with.

### setColumnCount

Adds or removes columns at the end of the layout.

```js
editor.commands.setColumnCount(3)
```

| Argument | Type     | Description                                  |
| -------- | -------- | -------------------------------------------- |
| `count`  | `number` | The number of columns. Clamped to the bounds |

A removed column's content moves into the column before it.

Returns `false` outside a layout, and when the layout already has that many columns.

### setColumnGap

Sets the space between the columns.

```js
editor.commands.setColumnGap('48px')
```

| Argument | Type     | Description  |
| -------- | -------- | ------------ |
| `gap`    | `string` | A CSS length |

Returns `false` outside a layout.

### setColumnWidthMode

Sets the width mode of the layout.

```js
editor.commands.setColumnWidthMode('equal')
```

| Argument | Type                  | Description                    |
| -------- | --------------------- | ------------------------------ |
| `mode`   | `'equal' \| 'custom'` | `'equal'` also clears `widths` |

Returns `false` outside a layout.

### setColumnWidths

Sets one track size per column, and sets `widthMode` to `'custom'`.

```js
editor.commands.setColumnWidths(['1fr', '2fr'])
```

| Argument | Type               | Description                                                |
| -------- | ------------------ | ---------------------------------------------------------- |
| `widths` | `string[] \| null` | One CSS track size per column, or `null` for equal columns |

Returns `false` outside a layout, and for a list whose length is not the number of columns.

### addColumn

Adds an empty column beside the one the cursor is in.

```js
editor.commands.addColumn({ position: 'before' })
```

| Option     | Type                  | Default   | Description                       |
| ---------- | --------------------- | --------- | --------------------------------- |
| `position` | `'before' \| 'after'` | `'after'` | Which side of the cursor's column |

Returns `false` outside a column, for a layout selected as a whole, and at `maxColumns`.

### removeColumn

Removes the column the cursor is in, and keeps what was written in it.

```js
editor.commands.removeColumn()
```

- **Its content moves** into the next column, or into the previous one for the last column.
- **An empty column** is removed with nothing moved.

Returns `false` outside a column, for a layout selected as a whole, and at `minColumns`.

### moveColumn

Moves the column the cursor is in one place, and the caret with it.

```js
editor.commands.moveColumn('right')
```

| Argument    | Type                | Description      |
| ----------- | ------------------- | ---------------- |
| `direction` | `'left' \| 'right'` | Where to move it |

Returns `false` outside a column, for a layout selected as a whole, and for the first column
moved left or the last moved right.

### deleteColumns

Removes the whole layout, with its columns and their content.

```js
editor.commands.deleteColumns()
```

Returns `false` outside a layout.

### exitColumns

Puts the caret in an empty block after the layout, or before it.

```js
editor.commands.exitColumns({ direction: 'before' })
```

| Option      | Type                  | Default   | Description              |
| ----------- | --------------------- | --------- | ------------------------ |
| `direction` | `'before' \| 'after'` | `'after'` | Which side of the layout |

- **An empty paragraph or heading** already on that side gets the caret.
- **Otherwise** a new empty block is inserted there.

Returns `false` outside a layout.

## Writing with Transactions

Every Command has a Transaction function of the same name. It takes positions instead of reading
the selection, so you can write several changes in one step:

```js
import { columnLayoutAt, setColumnGapTransaction } from '@tiptap-pro/extension-columns'

const at = columnLayoutAt(editor.state.doc, editor.state.selection.from)

if (at) {
  editor.view.dispatch(setColumnGapTransaction(editor.state.tr, at.pos, '48px'))
}
```

| Function                        | Arguments                                        |
| ------------------------------- | ------------------------------------------------ |
| `insertColumnsTransaction`      | `transaction`, `position`, `options`, `input?`   |
| `setColumnCountTransaction`     | `transaction`, `layoutPos`, `count`, `options`   |
| `setColumnGapTransaction`       | `transaction`, `layoutPos`, `gap`                |
| `setColumnWidthModeTransaction` | `transaction`, `layoutPos`, `mode`               |
| `setColumnWidthsTransaction`    | `transaction`, `layoutPos`, `widths`             |
| `addColumnTransaction`          | `transaction`, `layoutPos`, `index`, `options`   |
| `removeColumnTransaction`       | `transaction`, `layoutPos`, `index`, `options`   |
| `moveColumnTransaction`         | `transaction`, `layoutPos`, `index`, `direction` |
| `deleteColumnsTransaction`      | `transaction`, `layoutPos`                       |
| `exitColumnsTransaction`        | `transaction`, `layoutPos`, `direction?`         |

- **`options`** is a `ColumnLayoutOptions`, the options of `Columns`.
  `DEFAULT_COLUMN_LAYOUT_OPTIONS` holds the defaults.
- **`input`** is an `InsertColumnsOptions`: `count`, `gap` and `widthMode`.
- **Each returns the Transaction it was given.** One that does nothing adds no step.

## Reading a layout

| Function                     | Arguments                      | Returns                                                                                 |
| ---------------------------- | ------------------------------ | --------------------------------------------------------------------------------------- |
| `columnLayoutAt`             | `doc`, `pos`                   | `{ node, pos, columnIndex }` for the innermost layout around a position, or `null`      |
| `columnBounds`               | `layout`, `layoutPos`, `index` | `{ node, pos, start, end }`: where one column sits, or `null` for an index out of range |
| `gapOf`                      | `node`                         | The layout's gap, `'24px'` when it has none                                             |
| `widthsOf`                   | `node`                         | Its `widths`, or `null`                                                                 |
| `gridTemplateOf`             | `node`                         | Its track list as one `grid-template-columns` value, or `null` for equal columns        |
| `isColumnLayout`, `isColumn` | `node`                         | Whether a Node is a layout, or a column                                                 |
| `isEmptyColumn`              | `node`                         | Whether a column holds nothing but one empty textblock                                  |

`columnIndex` is `-1` between columns. `ColumnLayoutAt` and `ColumnBounds` are the types of the
two results.

## Limitations

- **No Command creates a layout inside a column.** Content can still hold one, from a paste for
  example.
- **No resize handle.** Set widths with `setColumnWidths`.

What changes on pages: see
[Columns in Page Layout](/page-layout/paginating-extensions/columns).
