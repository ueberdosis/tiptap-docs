A block here is any textblock: a paragraph, a heading, a code block.

## Install

```bash
npm install @tiptap-pro/extension-whole-blocks
```

- **The Pro registry.** The package comes from Tiptap's private registry. See
  [The Pro registry](/page-layout/getting-started/install#the-pro-registry)
  to set it up.
- **Peer dependencies.** `@tiptap/core` and `@tiptap/pm`.
- **Without pages.** The package works in any Tiptap editor, with or without Page Layout.

## Quick start

Add `WholeBlocks` to an editor:

```js
import { Editor } from '@tiptap/core'
import StarterKit from '@tiptap/starter-kit'
import { WholeBlocks } from '@tiptap-pro/extension-whole-blocks'

const editor = new Editor({
  element: document.querySelector('#editor'),
  extensions: [StarterKit, WholeBlocks],
})
```

Select a heading from its first character to its last and press Backspace. The heading is gone,
and the caret is at the start of the block that followed it.

## What changes

- **Backspace or Delete** over a selection that covers whole blocks removes them. The caret lands
  at the start of the block that followed.
- **Cut** removes them the same way.
- **Copy, cut and drag** put whole blocks on the clipboard. A paste inserts them as blocks of
  their own, instead of pouring their text into the block at the cursor.
- **A selection from the first character of a block into a later one** removes the blocks it
  covers. What is left of the last block keeps that block's type.
- **Typing** over such a selection replaces the text and keeps the block.
- **A selection that starts after the first character** is handled as in any Tiptap editor: the
  text goes, the block stays.

## Where an emptied block goes

- **The only content of a list item.** The block takes the list item along.
- **The only content of a table cell**, or of anything else `isolating`. The cell keeps an empty
  paragraph.
- **The only block of the document.** An empty paragraph stays.

## Options

```js
WholeBlocks.configure({ ignore: (node) => node.attrs.isCopy === true })
```

| Option   | Type                 | Default | Description                                            |
| -------- | -------------------- | ------- | ------------------------------------------------------ |
| `ignore` | `IgnoreNode \| null` | `null`  | Marks Nodes that are pieces of a block drawn elsewhere |

`IgnoreNode` is `(node) => boolean | 'descend'`. What it answers changes this:

- **A textblock it answers `true` or `'descend'` for** is a piece of a block drawn somewhere else.
- **A selection that starts in one**, or ends where one carries on, is left to the default.
- **A container it answers `'descend'` for** holds whole blocks, such as the rest of a list drawn
  somewhere else.
- **A block that ends right before such a container** is whole.

## Switching it off

Leave it out of the Extensions. No option turns it off while it is registered.

## Writing with Transactions

The extension's decisions are functions of an `EditorState`, for a key handler or a toolbar of
your own:

```js
import {
  blockCoverOf,
  deleteWholeBlocksTransaction,
  wholeBlockSlice,
} from '@tiptap-pro/extension-whole-blocks'

const ignore = () => false

blockCoverOf(editor.state, ignore) // what the selection covers, or null

const transaction = deleteWholeBlocksTransaction(editor.state, ignore)

if (transaction) {
  editor.view.dispatch(transaction)
}
```

| Function                       | Arguments         | Returns                                                                  |
| ------------------------------ | ----------------- | ------------------------------------------------------------------------ |
| `blockCoverOf`                 | `state`, `ignore` | A `BlockCover`, or `null`                                                |
| `deleteWholeBlocksTransaction` | `state`, `ignore` | The deletion as a Transaction, or `null`                                 |
| `wholeBlockSlice`              | `state`, `ignore` | The Slice a copy puts on the clipboard, or `null`                        |
| `wholeBlocksPlugin`            | `ignore`          | The ProseMirror plugin `WholeBlocks` registers, for an editor without it |

- **`ignore` is a function.** Pass `() => false` where nothing is to be ignored.
- **`null` from any of them** means the selection does not cover whole blocks, and the default
  applies.
- **A `BlockCover`** is `{ kind: 'whole', from }` for blocks covered to their end, or
  `{ kind: 'into', from, last }` for a selection that ends inside `last`.
- **`wholeBlockSlice`** answers only for whole blocks that sit side by side in one parent.
- **`WholeBlocksOptions`** is the type of the options.

## Limitations

- **Text selections only.** A Node selection, or everything selected with `Mod-a`, is left to
  the default.
- **Typing over a whole block keeps it.** Word replaces the paragraph mark too, and the text
  typed joins the block after.
- **No visible paragraph mark.** The highlight ends at the text, so nothing shows that the block
  will go whole.
- **No Commands.** The extension changes keys, cut, copy and drag. It adds nothing to
  `editor.commands`.
