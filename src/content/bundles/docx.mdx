## Choose how to start

{/* MOCK: the three starts are a proposal; the JavaScript editor and the React editor on Page Layout don't exist yet */}

| Start | What runs right away | What you build | Framework |
| --- | --- | --- | --- |
| [Kit in your editor](#kit-in-your-editor) | Every part, installed, licensed, and configured | The display of pages and the whole interface | Any |
| [JavaScript editor](#javascript-editor) | A running editor with pages, headers and footers, notes, and DOCX import and export, but no toolbar or menus | Buttons and menus | Any |
| [React editor](#react-editor) | The complete editor from UI Components: toolbar, comments, headers and footers, export | Only your changes | React |

All three use the same package and the same license, so you can start with one and move to another. React projects can use any of them; the React editor only saves you building the interface.

### Kit in your editor

{/* MOCK: package name and API shape */}

You have an editor already, and add one extension that registers every part, configured to work together. The interface is yours to build.

```bash
npm install @tiptap-pro/docx
```

```ts
import { DocxKit } from '@tiptap-pro/docx'
import StarterKit from '@tiptap/starter-kit'

const extensions = [StarterKit, DocxKit]
```

### JavaScript editor

A running editor in plain JavaScript that shows the document on pages, with nothing from React. It brings as little interface as it can: the pages, and the places to edit headers, footers, and notes, but no toolbar or menus. Mount it on an element in any framework, such as Vue, Angular, or Svelte, and add your own buttons:

```ts
import { createDocxEditor, DocxKit } from '@tiptap-pro/docx'
import StarterKit from '@tiptap/starter-kit'

const editor = createDocxEditor({
  element: document.querySelector('#editor'),
  page: 'A4',
  extensions: [StarterKit, DocxKit],
})
```

{/* MOCK: hook name */}

In React, `useDocxEditor` from the same package sets up the same editor in place of `useEditor`.

### React editor

The complete editor, built with [UI Components](/ui-components/getting-started/overview). The [DOCX Editor template](/ui-components/templates/docx-editor) adds it to your project as source files, so you can change every part of it:

```bash
npx @tiptap/cli@latest init docx
```

The template is built on [Pages](/pages/getting-started/overview) today and moves to the bundle once it ships.

## Configure the parts

- **Switch a part off.** Pass `false` for it, for example `DocxKit.configure({ crossReferences: false })`.
- **Configure a part.** Pass its options under its name, for example `footnotes: { defaultPlacement: 'endnote' }`. Each part's page lists its options.
- **Use your own extension.** Switch the part off and add yours. DOCX export then needs a [custom converter](/conversion/export/docx/custom-nodes-dsl).

## Plans and access

{/* MOCK: plan and services wait for pricing */}

The bundle is a plan of its own. It unlocks every paid part in one step, without add-ons, and the open source parts stay free. Import, export, and PDF rendering run on the [Conversion service](/conversion/getting-started/overview); comments and real-time collaboration use the [Document Server](/collaboration/getting-started/overview).

## Limits

- Page Layout and the document structure extensions aren't released yet.
- Some revision kinds don't carry over as tracked changes yet. See [tracked changes on import](/conversion/import/docx/tracked-changes).
- [Pages](/pages/getting-started/overview) can't be combined with Page Layout.
