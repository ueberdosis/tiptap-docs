## What you can do with it

- **Protect parts of a document.** Rules select Nodes, Marks, attributes, or content and allow or deny editing. [Policy language](/composable-docs/content-protection/api-reference/policy)
- **Start from examples.** Protect headings, fix heading levels, hide blockquotes, or protect table columns and headers. [Example policies](/composable-docs/content-protection/guides/example-policies)
- **Hide content.** Content a user may not read is replaced with a placeholder you can style. [Redacted content](/composable-docs/content-protection/api-reference/rendering)
- **Let users lock content.** Users select content and mark it as locked. [Lock selected content](/composable-docs/content-protection/guides/lock-selected-content)
- **Let users fill only fields.** Protect everything outside Slots. [Allow filling only](/composable-docs/slots/guides/fill-only)
- **Change the policy at runtime.** Replace it with a command and get events when edits are refused. [Commands](/composable-docs/content-protection/api-reference/commands), [Editor events](/composable-docs/content-protection/api-reference/extension#editor-events)
- **Check permissions in your code.** Validate a policy or check a change before applying it. [Utilities](/composable-docs/content-protection/api-reference/utilities)
- **Edit together.** Each collaborator can have their own policy. [Collaboration](#collaboration)

## Get started

1. [Contact our team](https://tiptap.dev/contact-sales?form=pilot-program) to join the Composable Documents pilot program.
2. Set up access to Tiptap's private npm registry with the [setup guide](/guides/pro-extensions).
3. Install the package:

```bash
npm install @tiptap/core @tiptap/starter-kit @tiptap/y-tiptap yjs @tiptap-pro/extension-content-protection
```

4. Add the extension with a [policy](/composable-docs/content-protection/api-reference/policy). This one makes headings read-only:

```ts
import { Editor } from '@tiptap/core'
import StarterKit from '@tiptap/starter-kit'
import {
  ContentProtection,
  type ContentProtectionPolicy,
} from '@tiptap-pro/extension-content-protection'

const policy: ContentProtectionPolicy = {
  version: 1,
  rules: [
    {
      selector: { target: 'node', node: { types: ['heading'] } },
      permissions: { edit: false },
    },
  ],
}

const editor = new Editor({
  extensions: [StarterKit, ContentProtection.configure({ policy })],
})
```

Update the rules while the editor runs:

```ts
editor.commands.setContentProtectionPolicy({ policy })
```

## Collaboration

Content Protection works with real-time collaboration through the [Collaboration extension](/editor/extensions/functionality/collaboration). Each collaborator can have a different local policy. Local edits are checked against that policy; updates from the collaboration binding are accepted so all editors stay synchronized with the shared document. This includes initial synchronization and collaborative undo/redo, even if the current local policy would reject the corresponding edit. Read permissions still control what each collaborator sees and copies.

```ts
import Collaboration from '@tiptap/extension-collaboration'

const editor = new Editor({
  extensions: [
    StarterKit.configure({ undoRedo: false }),
    Collaboration.configure({ document: ydoc }),
    ContentProtection.configure({ policy: localPolicy }),
  ],
})
```

Here, `ydoc` is the shared Y.Doc connected to your collaboration provider, and `localPolicy` is the policy your application assigns to this user. Install `@tiptap/extension-collaboration` to use this setup. Policies remain local and are not stored in the shared document. These client-side permissions do not authorize incoming collaboration updates; enforce access to the shared document in your application and on the server, for example with the Document Server's [document permissions](/collaboration/getting-started/authenticate).

## Part of Composable Documents

Content Protection is one of three parts of Composable Documents. With [Slots](/composable-docs/slots/getting-started/overview), it lets users fill fields while the rest stays fixed. [Variables](/composable-docs/variables/getting-started/overview) display values in the document.
