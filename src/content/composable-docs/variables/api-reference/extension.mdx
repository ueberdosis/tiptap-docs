## Configuration

```ts
Variable.configure({
  variables: {
    customer: 'Ada',
    greeting: ({ get }) => `Hello, ${get('customer')}!`,
  },
  slots: { customerField: 'customer', signatureField: 'customer' },
  onUpdate: ({ values }) => console.log(values),
  onError: ({ error }) => console.error(error),
})
```

| Option      | Default   | Description                                                                                     |
| ----------- | --------- | ----------------------------------------------------------------------------------------------- |
| `variables` | `{}`      | Variable names mapped to primitive values or synchronous resolvers.                             |
| `slots`     | `{}`      | Slot IDs mapped to variable names. Requires the `Slot` extension.                               |
| `onUpdate`  | No action | Receives `{ editor, values }` after an accepted value change. `values` is a read-only snapshot. |
| `onError`   | No action | Receives `{ editor, error }` when an update fails.                                              |

Invalid initial configuration or a failing initial resolver throws during editor creation. Later resolver errors preserve the previous runtime values and call `onError`.

## Commands

### insertVariable

Insert a non-editable inline reference at the selection. Returns `false` for an unknown variable.

```ts
editor.commands.insertVariable({ name: 'greeting' })
```

### setVariable

Set a primitive value and recalculate its dependents. Returns `false` when the name is unknown or the update fails.

```ts
editor.commands.setVariable({ name: 'customer', value: 'Grace' })
```

Setting a resolver-backed variable overrides its cached value until the resolver next runs, either through `refreshVariables` or a dependency update. The resolver itself is preserved.

### refreshVariables

Refresh the named variables and their dependents. Omit `names` to refresh all resolvers. An empty list reruns no resolvers and synchronizes bound slots with the current values.

```ts
editor.commands.refreshVariables({ names: ['customer'] })
editor.commands.refreshVariables()
```

Commands support `editor.chain()`. Capability checks with `editor.can()` do not execute resolvers; they check known variable names, so they cannot predict resolver failures.

## Read a value

```ts
import { getVariable } from '@tiptap-pro/extension-variable'

const greeting = getVariable({ editor, name: 'greeting' })
```

Returns the current primitive value, or `undefined` when the name is unknown or the extension is not installed. `null` is a valid configured value and displays as empty text.

## Types

The package exports `VariableValue`, `VariableResolver`, `VariableResolverContext`, `VariableOptions`, `SetVariableOptions`, `RefreshVariablesOptions`, `GetVariableOptions`, `VariableUpdateOptions`, and `VariableErrorOptions`.

```ts
import type { VariableResolver } from '@tiptap-pro/extension-variable'

const greeting: VariableResolver = ({ get }) => `Hello, ${get('customer')}!`
```
