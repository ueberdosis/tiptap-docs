Bind one or more [slots](/composable-docs/slots/getting-started/overview) to a variable so that their content syncs with the variable.

## Configure the bindings

Install both `@tiptap-pro/extension-slot` and `@tiptap-pro/extension-variable`.

First, define a document with two slots:

```ts
const content = {
  type: 'doc',
  content: [
    {
      type: 'paragraph',
      content: [
        {
          type: 'inlineSlot',
          attrs: { id: 'customerField' },
          content: [{ type: 'text', text: 'Ada' }],
        },
        { type: 'text', text: ' / ' },
        {
          type: 'inlineSlot',
          attrs: { id: 'signatureField' },
          content: [{ type: 'text', text: 'Ada' }],
        },
      ],
    },
  ],
}
```

Then, create the editor and map both slot IDs to the `customer` variable:

```ts
import { Editor } from '@tiptap/core'
import StarterKit from '@tiptap/starter-kit'
import { Slot } from '@tiptap-pro/extension-slot'
import { Variable } from '@tiptap-pro/extension-variable'

const editor = new Editor({
  extensions: [
    StarterKit,
    Slot,
    Variable.configure({
      variables: { customer: 'Ada' },
      slots: { customerField: 'customer', signatureField: 'customer' },
    }),
  ],
  content,
})
```

The value appears directly inside each slot. No extra variable node is needed.

## Update from either side

Edit either slot, or fill it with a command. The variable and the other slot update together:

```ts
editor.commands.fillSlot({
  id: 'customerField',
  content: [{ type: 'text', text: 'Grace' }],
})
```

Updating the variable also refills both slots:

```ts
editor.commands.setVariable({ name: 'customer', value: 'Lin' })
```

## Initial values and rich content

The first bound slot supplies the initial value. Without a bound slot, the configured value is used.

Plain text slots supply strings. Formatted slots supply Tiptap JSON, preserving marks, line breaks, and structure:

```ts
editor.commands.setVariable({
  name: 'customer',
  value: { type: 'text', text: 'Ada', marks: [{ type: 'bold' }] },
})
```

- Content must fit every bound slot. Use block slots for multiple paragraphs.
- Give each slot a unique ID. Bound slots cannot be nested.
- Other objects display as JSON text. `null` and `undefined` empty the slot.
- Editing a resolver-backed variable overrides its value until the resolver runs again.

## Saving and protection

Slot content is saved with the document. Undoing a slot edit also updates its variable.

With [Content Protection](/composable-docs/content-protection/getting-started/overview):

- Local edits require permission to update every bound slot.
- Unreadable slots conceal their variable and dependent values until access is restored.
- Incoming collaborative edits still apply. Additional local slot writes require edit permission.

Bindings run in the client-side editor. Provide the same extension configuration when loading a document.
