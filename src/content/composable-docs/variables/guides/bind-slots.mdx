Bind one or more [slots](/composable-docs/slots/getting-started/overview) to a variable so that their content syncs with the variable.

## Configure the bindings

Install both `@tiptap-pro/extension-slot` and `@tiptap-pro/extension-variable`.

First, give both slots a `variable` attribute with the same name:

```ts
const content = {
  type: 'doc',
  content: [
    {
      type: 'paragraph',
      content: [
        {
          type: 'inlineSlot',
          attrs: { id: 'customerField', variable: 'customer' },
          content: [{ type: 'text', text: 'Ada' }],
        },
        { type: 'text', text: ' / ' },
        {
          type: 'inlineSlot',
          attrs: { id: 'signatureField', variable: 'customer' },
          content: [{ type: 'text', text: 'Ada' }],
        },
      ],
    },
  ],
}
```

Then, create the editor with both extensions:

```ts
import { Editor } from '@tiptap/core'
import StarterKit from '@tiptap/starter-kit'
import { Slot } from '@tiptap-pro/extension-slot'
import { Variable } from '@tiptap-pro/extension-variable'

const editor = new Editor({
  extensions: [StarterKit, Slot, Variable],
  content,
})
```

The value appears directly inside each slot. No extra variable node is needed.

## Let slots supply the value

With no explicit value or resolver for `customer`, the first bound slot supplies its value. Edit either slot, or fill it with a command. The variable and the other slot update together:

```ts
editor.commands.fillSlot({
  id: 'customerField',
  content: [{ type: 'text', text: 'Grace' }],
})
```

## Let the variable control the slots

An explicit value or resolver takes precedence over slot content. Setting one refills both slots and makes them read-only:

```ts
editor.commands.setVariable({ name: 'customer', value: 'Lin' })
```

To use a resolver instead:

```ts
const currentCustomer = { name: 'Lin' }
editor.commands.setVariables({ variables: { customer: () => currentCustomer.name } })
```

Remove the explicit definition to make the slots editable again. Their current content becomes the variable's value:

```ts
editor.commands.removeVariables({ names: ['customer'] })
```

Explicit `null` and `undefined` values also make slots read-only; they display empty content.

## Change bindings

Bind an existing slot to a variable, or change its current binding:

```ts
editor.commands.bindSlotVariable({ id: 'customerField', name: 'customer' })
```

An unknown name creates a slot-driven variable. If the variable already has a bound slot, the newly bound slot takes its value.

Remove the binding while keeping the slot's content:

```ts
editor.commands.unbindSlotVariable({ id: 'customerField' })
```

## Rich content

Plain text slots supply strings. Formatted slots supply Tiptap JSON, preserving marks, line breaks, and structure:

```ts
editor.commands.setVariable({
  name: 'customer',
  value: { type: 'text', text: 'Ada', marks: [{ type: 'bold' }] },
})
```

- Content must fit every bound slot. Use block slots for multiple paragraphs.
- Give each slot a unique ID. Bound slots cannot be nested.
- Other objects display as JSON text. `null` and `undefined` empty the slot.

## Saving and protection

Slot content and bindings are saved with the document. Bindings support undo and redo. Runtime values and resolvers stay in the editor configuration.

With [Content Protection](/composable-docs/content-protection/getting-started/overview):

- Local edits require permission to update every bound slot.
- Unreadable source slots conceal their slot-driven variable and dependent values until access is restored.
- Incoming collaborative edits still apply. Additional local slot writes require edit permission.

Synchronization runs in the client-side editor. Provide explicit values and resolvers again when loading a document.
