**Variables** display dynamic values inside your editor. Define a value, or a function that calculates it, and insert a reference wherever you want to display it.

The value is not editable as normal text. Update it through a command, refresh its resolver after an application event, or [bind it to an editable slot](/composable-docs/slots/guides/bind-variables).

<Callout title="Client-side alpha" variant="info">
  Variables run inside each editor instance. This alpha does not provide a server API or synchronize
  runtime values between clients.
</Callout>

## Install

First, [contact our team](https://tiptap.dev/contact-sales?form=pilot-program) to join the Tiptap Composable Docs pilot program and follow the [private registry guide](/guides/pro-extensions).

```bash
npm install @tiptap/core @tiptap/starter-kit @tiptap-pro/extension-variable
```

## Define and display a variable

```ts
import { Editor } from '@tiptap/core'
import StarterKit from '@tiptap/starter-kit'
import { Variable } from '@tiptap-pro/extension-variable'

const editor = new Editor({
  extensions: [
    StarterKit,
    Variable.configure({
      variables: {
        customer: 'Ada',
        greeting: ({ get }) => `Hello, ${get('customer')}!`,
      },
    }),
  ],
  content: {
    type: 'doc',
    content: [
      {
        type: 'paragraph',
        content: [{ type: 'variable', attrs: { name: 'greeting' } }],
      },
    ],
  },
})

editor.commands.setVariable({ name: 'customer', value: 'Grace' })
// The editor now displays "Hello, Grace!".
```

You can also insert a reference at the current selection:

```ts
editor.commands.insertVariable({ name: 'customer' })
```

## Values and resolvers

A variable holds a string, finite number, boolean, or `null`. A resolver is a synchronous function that returns one of those values. Use `get(name)` inside the resolver to read another variable. Reads register dependencies automatically, including reads made only in one branch of a conditional.

When you set a variable or refresh a resolver, its dependents are recalculated synchronously. Unrelated resolvers keep their cached values. Circular dependencies, unknown variable reads, promises, and other unsupported return values are rejected.

## Refresh after an application event

Changing an external object does not automatically call a resolver. Refresh the affected variables from your application's event listener:

```ts
let customer = { name: 'Ada' }
const events = new EventTarget()

const variable = Variable.configure({
  variables: {
    customer: () => customer.name,
    greeting: ({ get }) => `Hello, ${get('customer')}!`,
  },
})

// Include variable in the editor's extensions.
const refresh = () => editor.commands.refreshVariables({ names: ['customer'] })
events.addEventListener('customer-change', refresh)

customer = { name: 'Grace' }
events.dispatchEvent(new Event('customer-change'))

// Remove application listeners when disposing this editor.
editor.on('destroy', () => events.removeEventListener('customer-change', refresh))
```

For asynchronous data, fetch it in your application and then call `setVariable`, or refresh a synchronous resolver that reads the fetched result.

## What is saved

An inline reference saves only its variable name. Its current value is absent from document JSON, exported HTML, plain text, and clipboard exports. Value changes do not add document history entries. A reference itself can still be selected, deleted, copied, and undone as a document node.

Each editor resolves its own values. Loading the same document in another editor uses that editor's configuration. An imported reference to an unknown name displays an empty value.

Bound slots behave differently: their filled text is normal document content, so it is saved, exported, and included in undo history. Read [Bind slots to variables](/composable-docs/slots/guides/bind-variables) for the details.
