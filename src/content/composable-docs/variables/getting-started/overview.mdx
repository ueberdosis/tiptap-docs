## What you can do with it

- **Show a value in the text.** The document stores a reference; your application supplies the value. [Define and display a variable](#define-and-display-a-variable)
- **Calculate values.** A resolver function derives a value from other variables. [Values and resolvers](#values-and-resolvers)
- **Add and remove variables at runtime.** You don't need to know every variable when you create the editor. [Add and manage variables at runtime](#add-and-manage-variables-at-runtime)
- **Use data from your application.** Refresh a resolver when your data changes. [Connect variable values to external sources](#connect-variable-values-to-external-sources)
- **Keep editable fields in sync.** Bind Variables to Slots, so a value and the fields that show it stay the same. [Bind slots to variables](/composable-docs/variables/guides/bind-slots)
- **Render references your way.** Style them or use your own NodeViews. [Styling](/composable-docs/variables/api-reference/rendering)

## Define and display a variable

First, import the editor and extensions:

```ts
import { Editor } from '@tiptap/core'
import StarterKit from '@tiptap/starter-kit'
import { Variable } from '@tiptap-pro/extension-variable'
```

Define a variable called `customer` and add the extension to your editor:

```ts
const editor = new Editor({
  extensions: [
    StarterKit,
    Variable.configure({
      variables: { customer: 'Ada' },
    }),
  ],
  content: '<p></p>',
})
```

Insert a reference at the current selection. It displays **Ada**:

```ts
editor.commands.insertVariable({ name: 'customer' })
```

Update the value. Every reference to `customer` now displays **Grace**:

```ts
editor.commands.setVariable({ name: 'customer', value: 'Grace' })
```

## Add and manage variables at runtime

You don't need to know every variable when you create the editor. Add a value or resolver later with `addVariable()`, then insert a reference:

```ts
editor.commands.addVariable({ name: 'company', value: 'Acme' })
editor.commands.insertVariable({ name: 'company' })

editor.commands.addVariable({
  name: 'customerLabel',
  value: ({ getText }) => `${getText('customer')} at ${getText('company')}`,
})
editor.commands.insertVariable({ name: 'customerLabel' })
```

`addVariable()` returns `false` if the name is empty or already registered. Use `setVariable()` to update an existing value, or `setVariables()` to replace a value or resolver:

```ts
editor.commands.setVariable({ name: 'company', value: 'Tiptap' })
editor.commands.setVariables({
  variables: { customerLabel: ({ getText }) => getText('customer').toUpperCase() },
})
```

Remove a variable with `removeVariable()`. Remove its dependent resolvers first, or remove them together with `removeVariables()`:

```ts
editor.commands.removeVariable({ name: 'customerLabel' })
editor.commands.removeVariable({ name: 'company' })
```

Existing references stay in the document and display an empty value after removal. Adding the same name again restores their display. Runtime definitions belong to this editor instance and are not saved in the document or reverted by document undo. For bound slots, removal [returns the variable to slot content](/composable-docs/variables/api-reference/extension#removevariable).

See the [command reference](/composable-docs/variables/api-reference/extension#commands) for bulk registration, removal, and failure behavior.

## Values and resolvers

Define values directly or calculate them with a function, called a **resolver**. Use `get()` to read another variable's raw value, or `getText()` to read it as a string. Replace `Variable.configure(...)` in your editor with:

```ts
Variable.configure({
  variables: {
    customer: 'Ada',
    quantity: 3,
    greeting: ({ getText }) => `Hello, ${getText('customer')}!`,
  },
})
```

With this configuration, changing `customer` also updates `greeting`:

```ts
editor.commands.setVariable({ name: 'customer', value: 'Grace' })
// greeting becomes "Hello, Grace!"
```

Values can also be objects or arrays. Objects that are not Tiptap content display as JSON:

```ts
editor.commands.setVariable({
  name: 'customer',
  value: { name: 'Ada', company: 'Acme' },
})
```

To display the name and company separately, define a resolver for each property using `get('customer')`, then insert references to those variables. Names such as `customer.name` do not look up object properties automatically.

Use Tiptap JSON to display formatted content:

```ts
editor.commands.setVariable({
  name: 'customer',
  value: { type: 'text', text: 'Ada', marks: [{ type: 'bold' }] },
})
```

## Connect variable values to external sources

A resolver can read data from your application. Create a customer object, a resolver that reads its name, and an editor that displays it:

```ts
let customer = { name: 'Ada' }

const refreshEditor = new Editor({
  extensions: [
    StarterKit,
    Variable.configure({
      variables: { customer: () => customer.name },
    }),
  ],
  content: '<p></p>',
})
refreshEditor.commands.insertVariable({ name: 'customer' })
```

Listen for an application event and refresh the resolver:

```ts
const events = new EventTarget()
const refresh = () => refreshEditor.commands.refreshVariables({ names: ['customer'] })
events.addEventListener('customer-change', refresh)
```

After changing the data, send the event. The editor now displays **Grace**:

```ts
customer = { name: 'Grace' }
events.dispatchEvent(new Event('customer-change'))
```

Remove the listener when the editor is destroyed:

```ts
refreshEditor.on('destroy', () => events.removeEventListener('customer-change', refresh))
```

## What is saved

The document saves the variable's name, not its value. Each editor supplies its own values.

Text inside a [bound slot](/composable-docs/variables/guides/bind-slots) is saved as normal document content.
