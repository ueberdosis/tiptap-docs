A doc frame is a shape that shows a rich text document, in an editor of its own. The board stores the frame and the id of its document. Your app keeps the documents, so the board stays free of any storage.

## Provide the documents

Tell the board where the documents live with the `docs` option of `WhiteboardKit`. Without it, doc frames show no document. This example keeps the documents in memory:

```ts
import { Editor, type JSONContent } from '@tiptap/core'
import { StarterKit } from '@tiptap/starter-kit'
import { WhiteboardKit } from '@tiptap-pro/extension-whiteboard'

const documents = new Map<string, JSONContent>()

const editor = new Editor({
  element: viewport,
  extensions: [
    WhiteboardKit.configure({
      docs: {
        createEditor: ({ element, docId }) =>
          new Editor({
            element,
            extensions: [StarterKit],
            content: documents.get(docId),
            onUpdate: ({ editor: docEditor }) => documents.set(docId, docEditor.getJSON()),
          }),
        copy: ({ fromDocId, toDocId }) => {
          const document = documents.get(fromDocId)

          if (document) {
            documents.set(toDocId, structuredClone(document))
          }
        },
      },
    }),
  ],
})
```

In React, create the configured kit once, outside the component or with `useMemo`. See [Set up a board in React](/whiteboard/getting-started/install#set-up-a-board-in-react).

The `docs` object has three members:

- `createEditor({ element, docId })` creates the editor of a document inside `element`, the element of the frame. The board destroys the editor with its frame. The editor can have any extensions, like `StarterKit`.
- `copy({ fromDocId, toDocId })` copies a document for the copy of its frame, when someone duplicates or pastes the frame. It runs before the copy shows.
- `start(docId)`, which is optional, starts the document of a frame that this editor adds. It runs before the frame shows. Frames that other editors add, like through Yjs, don't start a document here.

`start` also runs for a copy, after `copy`. So keep a document that `copy` gave the frame:

```ts
start: (docId) => {
  if (!documents.has(docId)) {
    documents.set(docId, { type: 'doc', content: [{ type: 'paragraph' }] })
  }
},
```

## Add a doc frame

The `doc` tool, key <kbd>W</kbd>, adds a frame with a new document and starts editing it. In code, add a frame like any other shape:

```ts
import { createShapeId } from '@tiptap-pro/extension-whiteboard'

editor.commands.insertShape({ type: 'docFrame', docId: createShapeId(), x: 0, y: 0, width: 420 })
```

The frame shows the document with the id in `docId`. A frame without a `docId` uses its own shape id, so it still gets a document of its own. `docIdOf` returns the id of a frame's document, from its node or the node's JSON.

## Edit a document

The board selects, moves and resizes a frame like other shapes. Its height follows its document. The editor of the document is read-only until editing starts: with a click on the selected frame, with <kbd>Enter</kbd>, or with `editShapeText`:

```ts
editor.commands.editShapeText({ id: 'frame' })
```

While the document is edited, presses and keys inside the frame belong to its editor. <kbd>Escape</kbd> stops editing and selects the frame again. A press on another shape stops editing, too, and so does [making the board read-only](/whiteboard/guides/shapes-and-tools#read-only-boards).

### Format the edited document

Your toolbar can work on the edited document and on the text of shapes alike. `getEditedDocEditor` returns the editor of the document that a frame edits, or `null` while none is edited:

```ts
import { getEditedDocEditor } from '@tiptap-pro/extension-whiteboard'

// A bold button that works in documents too
const textEditor = getEditedDocEditor(editor) ?? editor
textEditor.commands.toggleBold()
```

The board's editor emits `docChange` on every transaction of a document's editor, also one that only moves the caret, when its editing starts or stops, and when its editor comes or goes. Use it to update the toolbar, but not to save documents:

```ts
editor.on('docChange', ({ docId }) => {
  console.log(`The document ${docId} changed`)
})
```

## Read all documents

`getDocEditors` returns the editors of the documents that the frames on the board show:

```ts
import { getDocEditors } from '@tiptap-pro/extension-whiteboard'

const contents = getDocEditors(editor).map((docEditor) => docEditor.getJSON())
```

It returns no editors once the board's editor is destroyed.

## Documents that arrive later

A frame grows as tall as its document after each change in this editor. Other people's editors measure the changes that they make. When the document arrives after the frame, like when an AI adds a frame and writes its document later, keep the height that you gave the frame with `keepShapeHeights`:

```ts
import { keepShapeHeights } from '@tiptap-pro/extension-whiteboard'

const { tr } = editor.state
// … add a doc frame whose document arrives later
editor.view.dispatch(keepShapeHeights(tr))
```
