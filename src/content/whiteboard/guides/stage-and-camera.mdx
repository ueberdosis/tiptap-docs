A board lives in three elements. The **stage** is the element around the board. It takes presses and wheel turns, and clips everything outside it. Inside the stage, the **viewport** holds the editor. The **camera** moves and scales the viewport.

## The camera

The camera is state of your app:

```ts
type Camera = {
  x: number
  y: number
  zoom: number
}
```

`x` and `y` are in screen pixels, and a `zoom` of 1 is 100%. The camera helpers keep the zoom between `minZoom`, which is 10%, and `maxZoom`, which is 400%.

Show the board with the camera: move the viewport with `toCssTransform`, and set `--zoom` to the zoom. Handles and outlines read `--zoom` to keep their size at every zoom.

```ts
import { toCssTransform } from '@tiptap-pro/extension-whiteboard'

toCssTransform({ x: 100, y: 50, zoom: 2 }) // 'translate(100px, 50px) scale(2)'
```

The viewport needs `transform-origin: 0 0`. See the [install guide](/whiteboard/getting-started/install#add-the-stage-css) for the CSS of the stage and the viewport.

## Attach the stage

`attachStage` connects the board of an editor to its stage. It returns a function that detaches everything again:

```ts
import { attachStage } from '@tiptap-pro/extension-whiteboard'

const detach = attachStage({ stage, editor, updateCamera: setCamera })
```

`updateCamera` changes the camera through an update function, like a React state setter. In React, pass the setter of a `useState`. Without React, apply the update yourself, see [Without a framework](/whiteboard/getting-started/install#without-a-framework).

Once attached, people can work with the board in the stage. Its keys work while the focus is in the stage, so the rest of the page, and other boards on it, keep theirs:

- **Pan**: drag with space held, with the middle mouse button, or with the `hand` tool. Turning the wheel or scrolling on a trackpad pans too. A pan wins over drawing and selecting.
- **Zoom**: <kbd>Cmd/Ctrl</kbd> + wheel, or a pinch on a trackpad, zooms at the pointer.
- **Zoom shortcuts**: <kbd>Cmd/Ctrl</kbd> + <kbd>=</kbd> or <kbd>+</kbd> zooms in, <kbd>Cmd/Ctrl</kbd> + <kbd>-</kbd> zooms out, and <kbd>Cmd/Ctrl</kbd> + <kbd>0</kbd> goes back to 100%, around the middle of the stage, instead of zooming the page. Keys in a field are left to the field.
- **Fit**: <kbd>Shift</kbd> + <kbd>1</kbd> fits all shapes into view while the board has the keyboard.
- **Draw**: with a shape tool, a drag on the board adds a shape. A click adds a note, text, doc frame or geometric shape in its default size. The pen draws lines, and the eraser erases the pen lines it touches. Drawing also works over other shapes.
- **Select**: with the `select` tool, a drag on the empty board selects the shapes that its box touches. Hold <kbd>Shift</kbd> to add them to the selection. A click on the empty board clears the selection.

<kbd>Escape</kbd> cancels a drag while it runs, except a pan.

### Keep room for your controls

<kbd>Shift</kbd> + <kbd>1</kbd> keeps 64 screen pixels free at each edge of the stage. When panels
float over the stage, keep more room with `fitInsets`:

```ts
import { attachStage } from '@tiptap-pro/extension-whiteboard'

attachStage({
  stage,
  editor,
  updateCamera: setCamera,
  // Keeps shapes out from under the toolbar when Shift + 1 fits them into view
  fitInsets: () => ({ top: 80, right: 24, bottom: 24, left: 24 }),
})
```

### Show the tool and the pan in CSS

The stage shows the active tool as `data-tool`, and a pan as `data-pan`: `ready` while space is held, and `active` while the board pans. Use them for cursors:

```css
.stage:where([data-tool]:not([data-tool='select'], [data-tool='hand'])),
.stage:where([data-tool]:not([data-tool='select'], [data-tool='hand'])) * {
  cursor: crosshair;
}

.stage[data-tool='hand'],
.stage[data-tool='hand'] *,
.stage[data-pan='ready'],
.stage[data-pan='ready'] * {
  cursor: grab;
}

.stage[data-pan='active'],
.stage[data-pan='active'] * {
  cursor: grabbing;
}
```

While a drag runs, the stage holds a preview element: `data-selection-box`, `data-shape-preview`, `data-arrow-preview` or `data-pen-preview`. See [Styling](/whiteboard/api-reference/styling#stage).

## Zoom buttons

`zoomAtStageCenter` changes the zoom around the middle of the stage, so the board stays put there. `stepZoom` returns the next zoom step in a direction, from 10% to 400%:

```ts
import { stepZoom, zoomAtStageCenter } from '@tiptap-pro/extension-whiteboard'

// Zoom in one step
zoomAtStageCenter({
  stage,
  updateCamera: setCamera,
  nextZoom: (zoom) => stepZoom({ zoom, direction: 1 }),
})

// Back to 100%
zoomAtStageCenter({ stage, updateCamera: setCamera, nextZoom: () => 1 })
```

A zoom between two steps goes to the next step in that direction. For example, `stepZoom({ zoom: 0.8, direction: -1 })` returns `0.75`.

## Fit shapes into view

`zoomToFitShapes` moves and zooms the camera so every shape is in the stage. It never zooms in beyond 100%, and does nothing on an empty board:

```ts
import { zoomToFitShapes } from '@tiptap-pro/extension-whiteboard'

zoomToFitShapes({ stage, editor, updateCamera: setCamera })
```

`scrollShapesIntoView` moves the camera as little as it can, so the shapes with the given ids are in the stage. It zooms out only when they don't fit:

```ts
import { getSelectedShapeIds, scrollShapesIntoView } from '@tiptap-pro/extension-whiteboard'

scrollShapesIntoView({
  stage,
  editor,
  ids: getSelectedShapeIds(editor.state),
  updateCamera: setCamera,
})
```

Both keep 64 screen pixels free at each edge. Pass `insets` to keep a different room, one number for every edge or one for each.

To show a part of the board, like when the board opens, `fitCameraToRect` returns the camera that shows a rectangle in the middle of the stage:

```ts
import { fitCameraToRect } from '@tiptap-pro/extension-whiteboard'

const camera = fitCameraToRect({
  rect: { x: 0, y: 0, width: 1200, height: 800 },
  viewport: { width: stage.clientWidth, height: stage.clientHeight },
})
```

It zooms out until the rectangle fits, but by default never zooms in beyond 100%. Set `largestZoom` to allow more.

## Convert coordinates

Shapes use board units. `clientToBoard` converts a point in window coordinates, like the `clientX` and `clientY` of a pointer event, to board units. It returns `null` while the editor shows no board, like before it is mounted:

```ts
import { clientToBoard } from '@tiptap-pro/extension-whiteboard'

stage.addEventListener('pointermove', (event) => {
  const point = clientToBoard({ editor, point: { x: event.clientX, y: event.clientY } })

  if (point) {
    console.log(`The pointer is at ${point.x}, ${point.y} on the board`)
  }
})
```

`visibleBoardRect` returns the part of the board that the stage shows. Use it to add a shape where people look:

```ts
import { stickyNoteSize, visibleBoardRect } from '@tiptap-pro/extension-whiteboard'

const seen = visibleBoardRect({
  camera,
  viewport: { width: stage.clientWidth, height: stage.clientHeight },
})
const { width, height } = stickyNoteSize

// A new note in the middle of the stage
editor.commands.insertStickyNote({
  x: seen.x + (seen.width - width) / 2,
  y: seen.y + (seen.height - height) / 2,
})
```
