## Install

First, [contact our team](https://tiptap.dev/contact-sales?form=pilot-program) for access to the Whiteboard pilot program.

After gaining access, configure your package manager by following the [private registry guide](/guides/pro-extensions).

Then, install the package and its peer dependencies:

```bash
npm install @tiptap-pro/extension-whiteboard @tiptap/core @tiptap/pm
```

The setup on this page uses React, so also install `@tiptap/react`:

```bash
npm install @tiptap/react
```

### What the package includes

The package is headless. It needs `@tiptap/core` and `@tiptap/pm` from Tiptap 3, version 3.22.5 or later. The text extensions that shapes use, like paragraphs, bold, italic, links and lists, come with the package as dependencies.

If your app pins `@tiptap/core` to one version, install these extensions at that version too. Otherwise npm installs their latest version, which may need a newer `@tiptap/core`:

```bash
npm install @tiptap/extension-bold@3.22.5 @tiptap/extension-code@3.22.5 \
  @tiptap/extension-highlight@3.22.5 @tiptap/extension-italic@3.22.5 \
  @tiptap/extension-link@3.22.5 @tiptap/extension-list@3.22.5 \
  @tiptap/extension-paragraph@3.22.5 @tiptap/extension-strike@3.22.5 \
  @tiptap/extension-text@3.22.5 @tiptap/extensions@3.22.5
```

Replace `3.22.5` with the version of your `@tiptap/core`.

`WhiteboardKit` brings its own document node. Don't add `Document` or `StarterKit` to the editor of a board.

Collaboration is optional. It lives in its own entry, `@tiptap-pro/extension-whiteboard/collaboration`, and only that entry needs Yjs. See [Collaboration](/whiteboard/guides/collaboration).

## Set up a board in React

A board needs three elements: the stage, which takes presses and wheel turns, the viewport inside it, which the camera moves, and the editor inside the viewport. This setup follows the [example](/whiteboard/examples/simple):

```jsx
import { EditorContent, useEditor } from '@tiptap/react'
import {
  attachStage,
  boardContent,
  stickyNoteContent,
  toCssTransform,
  WhiteboardKit,
} from '@tiptap-pro/extension-whiteboard'
import { useEffect, useRef, useState } from 'react'

import { Toolbar } from './Toolbar'
import './whiteboard.css'

const content = boardContent([
  stickyNoteContent({ id: 'hello', x: 40, y: 40, text: 'Double-click to write here' }),
])

export default function Whiteboard() {
  const stageRef = useRef(null)
  const [camera, setCamera] = useState({ x: 0, y: 0, zoom: 1 })
  const editor = useEditor({ extensions: [WhiteboardKit], content, immediatelyRender: false })

  // Lets the user pan, zoom, draw and select in the stage
  useEffect(() => {
    if (!editor || !stageRef.current) {
      return undefined
    }

    return attachStage({ stage: stageRef.current, editor, updateCamera: setCamera })
  }, [editor])

  if (!editor) {
    return null
  }

  return (
    <div className="whiteboard">
      <Toolbar editor={editor} />
      <div className="stage" ref={stageRef}>
        <div
          className="viewport"
          style={{ transform: toCssTransform(camera), '--zoom': String(camera.zoom) }}
        >
          <EditorContent editor={editor} />
        </div>
      </div>
    </div>
  )
}
```

With `immediatelyRender: false`, `useEditor` creates the editor after the first render, so `editor` is `null` until then. Next.js needs this, because the server can't render the board. It also matters when the board loads lazily, like with `next/dynamic` or `React.lazy`: `useEditor` destroys an editor that it created during a render if React mounts it too late.

`attachStage` returns a function that detaches everything again, so the effect cleans up after itself. Its `updateCamera` option takes a function that turns the old camera into the new one, like a React state setter, so `setCamera` fits.

### Add tools

The board starts with the `select` tool. Your buttons choose another tool with `setTool`, and `getActiveTool` tells which tool is active. `toolKeys` holds the key that chooses each tool:

```jsx
import { useEditorState } from '@tiptap/react'
import { focusBoard, getActiveTool, toolKeys } from '@tiptap-pro/extension-whiteboard'

const tools = ['select', 'hand', 'note', 'text', 'rectangle', 'ellipse', 'arrow', 'pen', 'eraser']

export function Toolbar({ editor }) {
  const activeTool = useEditorState({
    editor,
    selector: ({ editor: currentEditor }) => getActiveTool(currentEditor.state),
  })

  return (
    <div role="group" aria-label="Tools">
      {tools.map((tool) => (
        <button
          key={tool}
          type="button"
          aria-pressed={activeTool === tool}
          title={`${tool} (${toolKeys[tool].toUpperCase()})`}
          onClick={() => {
            editor.commands.setTool(tool)
            // Gives the keyboard back to the board, so the tool keys keep working
            focusBoard(editor.view)
          }}
        >
          {tool}
        </button>
      ))}
    </div>
  )
}
```

The `doc` tool adds doc frames, which need the `docs` option. See [Doc frames](/whiteboard/guides/doc-frames).

### Add the stage CSS

The stage clips the board and keeps touches for itself. The viewport sits in the top left corner of the stage and scales from there:

```css
.stage {
  height: 32rem;
  overflow: clip;
  position: relative;
  touch-action: none;
}

.viewport {
  left: 0;
  position: absolute;
  top: 0;
  transform-origin: 0 0;
}

/* The board's origin sits in the corner of the viewport, so the editor keeps no margin */
.viewport .tiptap {
  margin: 0;
}
```

### Style the shapes

The board adds the CSS that it needs to work, like the size of the board and where handles sit. Colors, fonts and cursors are up to your app. A few rules give the shapes a look:

```css
[data-type='sticky-note'] {
  background: #fff59d;
  padding: 12px;
}

[data-shape-outline] path {
  fill: #fff;
  stroke: #1d1d1d;
  stroke-width: 2px;
  vector-effect: non-scaling-stroke;
}

/* Arrows and pen lines are drawn in the current color */
[data-type='arrow'],
[data-type='freehand'] {
  color: #1d1d1d;
}

/* Divided by the zoom, so outlines and handles keep their size */
[data-shape][data-selected],
[data-shape][data-editing] {
  outline: calc(2px / var(--zoom, 1)) solid #6a00f5;
}

[data-shape-handle='resize'],
[data-arrow-handle] {
  background: #fff;
  border: calc(1.5px / var(--zoom, 1)) solid #6a00f5;
}

[data-selection-box],
[data-shape-preview] {
  background: rgba(106, 0, 245, 0.1);
  border: 1px dashed #6a00f5;
}
```

Shapes store the name of their color in `data-color`, like `data-color="blue"`, so your CSS decides how each color looks. See [Styling](/whiteboard/api-reference/styling) for every attribute that the board sets.

## Without a framework

The same setup works with `Editor` from `@tiptap/core`. `stage` and `viewport` are the two elements from the CSS above:

```ts
import { Editor } from '@tiptap/core'
import { attachStage, toCssTransform, WhiteboardKit } from '@tiptap-pro/extension-whiteboard'

const editor = new Editor({ element: viewport, extensions: [WhiteboardKit] })
let camera = { x: 0, y: 0, zoom: 1 }

// Pan, zoom, draw and select in the stage, the element around the board
const detach = attachStage({
  stage,
  editor,
  updateCamera: (update) => {
    camera = update(camera)
    viewport.style.transform = toCssTransform(camera)
    viewport.style.setProperty('--zoom', String(camera.zoom))
  },
})
```
