## Extensions that change on pages

| Extension                                                            | On pages                                                                                       |
| -------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| [Tables](/page-layout/other-extensions/tables)                       | A row cut at the boundary, a header row repeated on every page, and what an author may forbid. |
| [Column layout](/page-layout/other-extensions/column-layout)         | Columns side by side, cut at one height, and kept on one page.                                 |
| [Footnotes](/page-layout/other-extensions/footnotes)                 | A note at the foot of the page it is referred from, and numbering per page or section.         |
| [Cross-references](/page-layout/other-extensions/cross-references)   | "See page 7", writing through the engine, and going to a target that is not drawn yet.         |
| [Outline numbering](/page-layout/other-extensions/outline-numbering) | A heading cut by a page numbered once, and clauses counting on over a page.                    |
| [Bookmarks](/page-layout/other-extensions/bookmarks)                 | Going to a bookmark on a page that is not drawn yet.                                           |
| [Document Styles](/page-layout/other-extensions/document-styles)     | Text moving with a style, and reading the styles of a document that has pages.                 |
| [Number formats](/page-layout/other-extensions/number-formats)       | Writing a document's formats and language.                                                     |
| [Whole blocks](/page-layout/other-extensions/whole-blocks)           | A block that carries on over a page, selected whole.                                           |

## What the standard types do

| Type                        | At the bottom of a page                                                                                           |
| --------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| `paragraph`                 | Cut between two lines.                                                                                            |
| `heading`                   | Cut between two lines.                                                                                            |
| `codeBlock`                 | Cut between two lines, and the continuation stays a code block.                                                   |
| `blockquote`                | Cut between two of its blocks. A paragraph inside it is then cut between lines.                                   |
| `horizontalRule`            | Never cut. Moves to the next page.                                                                                |
| `hardBreak`                 | Ends a line, so a page can be cut right after it.                                                                 |
| `bulletList`, `orderedList` | Cut between two items. The item the boundary landed in moves on whole.                                            |
| `table`                     | Cut between rows, and through a row where that is not enough. See [Tables](/page-layout/other-extensions/tables). |
| `columnLayout`              | Cut at one height through all of its columns. See [Column layout](/page-layout/other-extensions/column-layout).   |

A block cut by a page stays one Node in the document:

- **Two views of one Node.** The document keeps one paragraph, one list, one table. The two
  halves on screen are two views of it.
- **Lists keep counting.** An ordered list that carries on over a page goes on counting: item
  eight follows item seven across the boundary.
- **Attributes and marks** of a cut block are the same on both sides of the cut.

## Keeping a list on one page

Two settings on the list, both Word's:

```js
// Word's "Keep lines together": the list is never cut, and moves to the next page whole.
editor.commands.setListKeepTogether(true)

// Word's "Allow row to break across pages", for a list: an item may itself be cut
// between two of its lines, rather than moving on whole.
editor.commands.setListBreakItems(true)
```

| Attribute               | Default | In HTML                        |
| ----------------------- | ------- | ------------------------------ |
| `keepTogether`          | `false` | `data-tt-keep-together="true"` |
| `breakItemsAcrossPages` | `false` | `data-tt-break-items="true"`   |

- **Stored on the list Node**, on `bulletList` and `orderedList`. A copied list keeps them.
- **By default** a list breaks between its items and not inside one.
- **A caret in a nested item** answers with the outermost list. That is the block the page
  boundary meets: holding a sub-list together is no use while the list around it may break
  anywhere.
- **`PageLayout.configure({ listPagination: false })`** takes both settings away.

### The list at the cursor

```js
const context = editor.storage.pageLayout.engine.getListContext()
```

`null` when the cursor is not in a list, otherwise:

| Field                   | Type      | Description                                                       |
| ----------------------- | --------- | ----------------------------------------------------------------- |
| `list`                  | `Node`    | The outermost list around the cursor                              |
| `listPosition`          | `number`  | Where it starts                                                   |
| `keepTogether`          | `boolean` | Whether it is held on one page                                    |
| `breakItemsAcrossPages` | `boolean` | Whether an item may be cut                                        |
| `itemCount`             | `number`  | How many items it has. With one, both settings make no difference |

## Keep together is a preference

A block that does not fit on a page of its own is cut anyway, rather than hang off the bottom of
the sheet.

- **The setting stays** as the author left it. Only this one boundary ignores it.
- **An item taller than a page** is cut at its lines, whatever `breakItemsAcrossPages` says.
- **A manual page break inside such a block** is always honored. An author who put a break in
  the middle of a list has said where it ends.

A surface that offers the switch can find out and say so:

```js
const engine = editor.storage.pageLayout.engine
const context = engine.getListContext()

if (context?.keepTogether) {
  const cut = engine.isDividedInView(
    context.listPosition,
    context.listPosition + context.list.nodeSize,
  )

  if (cut) {
    // Taller than a page: tell the author, so the switch does not look broken.
  }
}
```

`isDividedInView(from, to)` is `true` when the content between two document positions is drawn
on more than one page. It works for a table row, a list, a layout or a paragraph.

## Packages that work without pages

These packages do not depend on Page Layout. On pages, a block cut across two pages is drawn as
two Nodes, and the header or footer being edited is a Node too. Cross-references, outline
numbering, bookmarks and whole blocks take `ignoreLayoutArtifacts` as `ignore` to leave those
out.

`ignoreLayoutArtifacts(node)` answers:

| Returns     | For                                                                                                        |
| ----------- | ---------------------------------------------------------------------------------------------------------- |
| `true`      | A header or footer, and the rest of a paragraph or heading from the page before. Left out with its content |
| `'descend'` | The rest of a list, quote or other container from the page before. Its items are the document's own        |
| `false`     | Everything else                                                                                            |

- **Why `'descend'`.** A list cut between its third and fourth item has its fourth item on the
  next page, in the rest of the list.
- **`isLayoutArtifact(node)`** is the same reading as a yes or no: `true` wherever
  `ignoreLayoutArtifacts` is not `false`. Use it in code of your own that only asks whether a
  Node stands for itself.

What each package needs besides that is on its page.

## What is not supported

- **Widow and orphan control.** No setting keeps at least two lines of a paragraph on either
  side of a boundary. A paragraph is cut wherever the page runs out, even after its first line.
- **Keep with next by default.** A heading is not tied to the paragraph after it, so it can end
  up as the last line on a page. Turn it on with
  [`defineNodeLayout`](/page-layout/other-extensions/your-own-extension/layout-rules#keeping-a-block-with-the-next), per block with
  the `blockBreaksOf` option, or per style with
  [Document Styles](/page-layout/other-extensions/document-styles#line-and-page-breaks).

Keeping a block on one page is available for lists, [table rows](/page-layout/other-extensions/tables) and
[column layouts](/page-layout/other-extensions/column-layout), and for a type of your own through
[`defineNodeLayout`](/page-layout/other-extensions/your-own-extension).

## Commands

### setListKeepTogether

Keeps the list at the cursor on one page, or lets it break again.

```js
editor.commands.setListKeepTogether(true)
```

| Argument | Type      | Description                                  |
| -------- | --------- | -------------------------------------------- |
| `kept`   | `boolean` | `true` moves the list to the next page whole |

Returns `false` when the cursor is not in a list.

### setListBreakItems

Lets a page cut through an item of the list at the cursor, or moves the item on whole again.

```js
editor.commands.setListBreakItems(true)
```

| Argument  | Type      | Description                                  |
| --------- | --------- | -------------------------------------------- |
| `allowed` | `boolean` | `true` cuts an item between two of its lines |

Returns `false` when the cursor is not in a list.
