`@tiptap-pro/extension-outline-numbering` works without pages.

## Registering what is numbered

Which of your Node types carry a number is yours to say, because the schema is yours. Register
them by name, with how deep each one sits:

```js
import { OutlineNumbering } from '@tiptap-pro/extension-outline-numbering'

new Editor({
  extensions: [
    StarterKit,
    OutlineNumbering.configure({
      types: {
        heading: { level: (node) => node.attrs.level },
      },
    }),
  ],
})
```

- **`level`** — a number, `'nested'`, or a function of the Node and `{ ancestors }` answering
  either or `null`, 1 being the outermost. `ancestors` are the Nodes around it, the outermost
  first. `null` leaves that Node unnumbered. A number that is not a whole number from one is
  read as the nearest level there is. `1` when you leave it out.
- **`'nested'`** — one level below the last Node before it that has a number level of its own,
  and one more for each `'nested'` Node it stands in. That is how a
  [list of clauses](/page-layout/extensions/outline-numbering#lists-as-clauses) is numbered.
- **`marker`** — `'inline'` draws the number in front of the text, `'gutter'` in the margin
  before the Node. `'inline'` when you leave it out.

A type your schema does not have is reported with a console warning when the editor is created.

### Numbering by style

A level read from somewhere other than the Node itself — a paragraph style that says where its
paragraphs sit in the outline — comes in through `lookupOf`. It is a function of the document
answering an object, and that object is handed to every `level` function as `lookup`:

```js
import { styleOutlineLevelOf, styleOutlineLevels } from '@tiptap-pro/extension-document-styles'

OutlineNumbering.configure({
  lookupOf: (doc) => styleOutlineLevels(doc, [houseStyle]),
  types: {
    heading: {
      level: (node, { lookup }) => {
        const level = styleOutlineLevelOf(lookup, node)
        return level === undefined ? node.attrs.level : level
      },
    },
    paragraph: { level: (node, { lookup }) => styleOutlineLevelOf(lookup, node) ?? null },
  },
})
```

A heading whose style is body text is left unnumbered that way, and one without a style is
numbered by its own level.

Numbers are counted again when `lookupOf` answers with another object, so it has to answer with
the same one for as long as what it holds is the same. With [Document Styles](/page-layout/extensions/document-styles/definitions#outline-levels)
that is the case. `null` by default, and `lookup` is `null` then.

## How a level reads

Each level has a template. `{n}` is the count at level `n`, and a format after a colon spells it
differently:

| Placeholder       | Reads                                                                                             |
| ----------------- | ------------------------------------------------------------------------------------------------- |
| `{2}` or `{2:1}`  | `1`, `2`, `3`                                                                                     |
| `{2:01}`          | `01`, `02`, … `10`                                                                                |
| `{2:a}` / `{2:A}` | `a`, `b`, … `z`, `aa` / `A`, `B`, …                                                               |
| `{2:i}` / `{2:I}` | `i`, `ii`, `iii` / `I`, `II`, `III`                                                               |
| `{2:*}`           | `*`, `†`, `‡`, `§`, `**`, …                                                                       |
| `{2:lowerGreek}`  | Any [number format](/page-layout/extensions/number-formats) by its name, one you defined included |

Everything else in a template is text. A level you leave out reads `{1}.{2}…` down to its own, so
with no `levels` at all headings are numbered `1`, `1.1`, `1.1.1`. A level whose template is `''`
is not numbered: its headings show nothing, and they still count. A placeholder naming a format
neither your code nor the document defines is written as it stands, `{2:clause}`, until one does.

```js
OutlineNumbering.configure({
  types: { heading: { level: (node) => node.attrs.level } },
  levels: [
    'Article {1:I}',
    'Section {1}.{2:01}',
    { label: '({3:a})', full: '{1}.{2:01}({3:a})' },
    { label: '({4:i})', full: '{1}.{2:01}({3:a})({4:i})' },
  ],
})
```

A level is a string, or an object with a `label` — what the heading shows — and a `full` form —
what names it from anywhere else in the document, as a cross-reference does. `full` is the label
when you leave it out.

A placeholder with a format that does not exist, like `{1:x}`, is printed as it is written.

### Word's numbering gallery

`OUTLINE_PRESETS` has the schemes of Word's _Outline Numbered_ gallery, nine levels each, ready
to pass as `levels`:

```js
import { OUTLINE_PRESETS, OutlineNumbering } from '@tiptap-pro/extension-outline-numbering'

OutlineNumbering.configure({
  types: { heading: { level: (node) => node.attrs.level } },
  levels: OUTLINE_PRESETS.legal,
})
```

| Preset          | Levels 1, 2, 3 read                                                                        |
| --------------- | ------------------------------------------------------------------------------------------ |
| `parenthesized` | `1)`, `a)`, `i)`, then `(1)`, `(a)`, `(i)`, `1.`, `a.`, `i.`                               |
| `decimal`       | `1.`, `1.1.`, `1.1.1.`                                                                     |
| `bullets`       | `❖`, `➢`, `▪`, then `●`, `◆`, `■`                                                          |
| `legal`         | `Article I.`, `Section 1.01`, `(a)`, then `(i)`, `(A)`, `(1)`; a reference names `1.01(a)` |
| `headings`      | `1`, `1.1`, `1.1.1` — the same as no `levels`                                              |
| `outline`       | `I.`, `A.`, `1.`, then `a)`, `(1)`, `(a)`, `(i)`                                           |
| `chapter`       | `Chapter 1`, and no number below it                                                        |

A preset is an array like any other, so a scheme of your own can start from one:
`[...OUTLINE_PRESETS.decimal.slice(0, 2), '{1}.{2}.{3:a}']`.

### A scheme stored in the document

`levels` is the scheme every document gets. A document can carry its own instead, so it keeps
its numbering wherever it goes — to another editor, to everyone editing it with you, into a
file — and so a reader can change it while editing. Register `OutlineScheme` for that:

```js
import { OutlineNumbering, OutlineScheme } from '@tiptap-pro/extension-outline-numbering'

new Editor({
  extensions: [
    StarterKit,
    OutlineNumbering.configure({ types: { heading: { level: (node) => node.attrs.level } } }),
    OutlineScheme,
  ],
})

editor.commands.setOutlineLevels(OUTLINE_PRESETS.legal) // the whole scheme
editor.commands.setOutlineLevel(2, 'Section {1}.{2:01}') // one level, the first being 1
editor.commands.setOutlineLevels(null) // back to `levels`
```

The scheme is kept in one hidden block at the end of the document, `outlineScheme`, which shows
nothing and holds a template per level in its `levels` attribute; in HTML it is
`<div data-tt-outline-scheme hidden data-tt-levels="[…]">`. `setOutlineLevel` keeps the other levels
as the document has them, or as `levels` has them where it has none yet. Both commands answer
`false` for a template that is not a string or `{ label, full? }`, so `editor.can()` tells a
toolbar whether a value is acceptable; `setOutlineLevels` also answers `false` when the scheme
is already the one given.

A level stored in the document that is not a template — written by hand, or by an older
version — is read as `levels` has that level. Where two documents with a scheme each are
combined, the first scheme counts.

For code that writes outside an editor command, the same writes are Transactions:
`setOutlineLevelsTransaction(tr, levels)` and `setOutlineLevelTransaction(tr, level, template, current)`, where `current` is the scheme to start from where the document has none.
`outlineLevelsOf(doc, levels)` is the scheme a document is numbered by, and `outlineSchemeAt(doc)`
the block and its position, or `null`.

`outlineLabelFor(scheme, counts, context?)` is what a heading with these counts reads in a
scheme, `{ label, fullLabel }` — the preview a dialog shows beside each level:
`outlineLabelFor(OUTLINE_PRESETS.legal, [1, 1, 1])` is `(a)` and `1.01(a)`.

### Counting

- A level counts from one again under every new heading above it.
- A level skipped on the way down — a level-3 heading directly under a level 1 — is not counted,
  and reads `0`: in `1`, `1.0.1`, the next level-2 heading is `1.1`. That is what cutting a
  heading and leaving its clauses produces: the next heading of its level moves up. In the digits
  of a format the `0` is padded like the other numbers, `1.00(a)`, and a format of letters or Roman
  numerals writes `0` as well.
- The levels a document skips before its first number count as their first: a document that
  starts at level 2 reads `1.1`, `1.2`, and a level-1 heading after them is `2`.
- `skippedLevel: 'zeroEverywhere'` leaves those uncounted as well: `0.1`, `0.2`, then `1`. That
  is what Word draws.
- `skippedLevel: 'first'` counts a skipped level as its first everywhere: `1`, `1.1.1`, `1.2`.
- Headings nested in other blocks, a blockquote or a list, are counted where they stand.

## Lists as clauses

A numbered list can belong to the outline, as a list linked to a heading style does in Word: its
items are numbered a level below the heading before them, and an item indented under one is a
level below that. Under `Section 1.01` they read `(a)`, `(b)`, and `(i)` under `(b)`; under an
`Article` heading the same list reads one level higher.

```js
import { OutlineNumbering, outlineListItem } from '@tiptap-pro/extension-outline-numbering'

OutlineNumbering.configure({
  types: {
    heading: { level: (node) => node.attrs.level },
    listItem: outlineListItem,
  },
  lists: ['orderedList'],
})

editor.commands.setOutlineList(true) // the list around the cursor becomes clauses
editor.commands.setOutlineList(false) // and a plain list again
```

- **`lists`** — the list types that can belong to the outline. Each gets a boolean `outlineList`
  attribute, `data-tt-outline-list` in HTML. `[]` by default.
- **`outlineListItem`** — the registration for a list item: `'nested'` inside a list that has
  `outlineList`, `null` anywhere else, drawn in the gutter.

The setting is on the outermost list, and the lists inside it count as part of it, so an item
indented with Tab is a clause too. `setOutlineList` sets it on the outermost list of one of the
`lists` types around the selection and clears it on the lists inside; it answers `false` outside
such a list, so `editor.can().setOutlineList(true)` tells a toolbar whether to offer it.
`outlineListAt(doc, pos)` is that list, `{ pos, node, linked }`, or `null`, and
`setOutlineListTransaction(state, linked)` the same write as a Transaction, `null` outside a
list.

Clauses count together with the headings: `(a)` starts again under every heading above it, and a
second list under the same heading goes on with `(c)` where the first stopped at `(b)`.

A clause's number stands in the margin before the item, and the list's own marker is not drawn.
The number is no part of a line, so a label growing from `(ix)` to `(x)` moves no text. The
stylesheet indents a linked list by `--tt-outline-list-indent` (`2.5em`) to make room for it; a
stylesheet of yours that sets the list's `padding-inline-start` more specifically wins over it.

Where `ignore` answers `'descend'` for an item — the rest of a clause continued on the next page —
the item has no number of its own and draws no list marker either: it gets
`data-tt-outline-marker="gutter"` without a `data-tt-outline-number`.

## How a number is shown

A numbered Node gets two attributes in the editor, never in the document: `data-tt-outline-number`
with its label and `data-tt-outline-level` with its level. What prints the label is CSS:

```js
import { mountOutlineStyles } from '@tiptap-pro/extension-outline-numbering'

mountOutlineStyles(document) // or put outlineStyleRules() in your own stylesheet
```

Under a Content Security Policy, pass the nonce you give the Editor as `injectNonce`:
`mountOutlineStyles(document, { nonce })`.

A Node registered with `marker: 'gutter'` also gets `data-tt-outline-marker="gutter"`.

The rule prints the label in front of the text, followed by a gap, or — for `gutter` — in the
margin before the Node, the same gap away from it. Two custom properties change
the look without replacing it: `--tt-outline-number-gap` (`0.5em`) and `--tt-outline-number-color`.

Because the number is not in the document, `getHTML()` and `getJSON()` do not contain it.

A heading selected as a whole gets the editor's `ProseMirror-selectednode` class, and the same
stylesheet tints it: `--tt-outline-selected-background` (`Highlight`) and `--tt-outline-selected-color`
(`HighlightText`).

### When a number changes without an edit

Numbers are counted again whenever the document changes. If your `level` or `ignore` function
answers differently for another reason, tell the editor:

```js
editor.commands.refreshOutlineNumbers()
```

The same is the Transaction meta `tr.setMeta(outlineLabelsKey, 'refresh')`.

## Deleting a numbered heading

The number cannot be selected on its own, since it is not text. Deleting works the way Word
deletes a numbered paragraph:

- A click on the number, or a triple click in the heading, selects the whole heading. Cut or
  delete it and the heading is gone, number and all.
- A selection from the heading's first character into the next block deletes the heading whole
  with Backspace, Delete or Cut: the rest of the next block keeps its own type, rather than
  becoming a numbered heading.
- A selection inside the heading's text deletes the text and keeps the heading and its number.
- Typing over a selection replaces it the usual way, and keeps the heading.

## Copy and paste

A copy writes each heading's label in front of its text, so a heading copied into a mail or
another program reads `1.2 Scope`. A heading counts as copied when the selection holds it from
its first character; one the selection begins inside of is copied without its label.

The copied HTML marks the heading with `data-tt-outline-label="1.2"`. Pasted into an editor that
has `OutlineNumbering`, the label is taken out of the text again, and the heading is numbered
where it lands. A heading whose text really begins with its number keeps it, because only the
marked label is taken out.

For that mark, each registered type has a `copiedOutlineLabel` attribute. It is `null` in every
document and appears in `getJSON()` as `null`.

A clause takes its label along the same way: it goes in front of the text of the item's first
paragraph, so a copied clause reads `(a) charge interest…`, and an item whose first child is not
a paragraph is copied without it.

## Leaving Nodes out

- **`ignore`** — a function of a Node. A Node it answers `true` for is not numbered, and nothing
  inside it is; a Node it answers `'descend'` for is not numbered, and what is inside it is
  counted as usual. `false` counts the Node. `null` by default.

A Node answered `'descend'` still counts for depth: a `'nested'` item inside it is a level
below, as it would be inside the Node it stands for.

With [Page Layout](/page-layout/getting-started/overview), pass its `ignoreLayoutArtifacts` here, and tell it where
a heading's number is drawn from; see
[Outline numbering on pages](/page-layout/extensions/outline-numbering/on-pages).

## Reading the numbers

```js
import { outlineNumbersIn, outlineNumberAt } from '@tiptap-pro/extension-outline-numbering'

const registry = editor.storage.outlineNumbering

for (const { pos, level, counts, label, fullLabel } of outlineNumbersIn(
  editor.state.doc,
  registry,
)) {
  // counts is [1, 1, 2] for 1.1.2, the outermost first
}

outlineNumberAt(editor.state.doc, registry, pos) // the number of the Node starting at pos, or null
```

Both read the document you pass. A document is counted once for each editor, however often you
ask.

Each number also has `marker`, `'inline'` or `'gutter'`, from its type's registration.

`outlineLevelOf(registry.types, node, { ancestors })` is what a Node's registration answers: a
level, `'nested'`, or `null` for a type that is not registered or a Node that is not numbered.

## Names

| Name                       | Value                           | What it is                                                                           |
| -------------------------- | ------------------------------- | ------------------------------------------------------------------------------------ |
| `OUTLINE_PRESETS`          | `{ parenthesized, decimal, … }` | Word's gallery of outline numberings, as `levels`.                                   |
| `OUTLINE_NUMBER_ATTRIBUTE` | `data-tt-outline-number`        | The label, on a numbered Node's element in the editor.                               |
| `OUTLINE_LEVEL_ATTRIBUTE`  | `data-tt-outline-level`         | The level, on the same element.                                                      |
| `OUTLINE_MARKER_ATTRIBUTE` | `data-tt-outline-marker`        | `gutter` on the same element, for a number drawn in the margin.                      |
| `OUTLINE_LIST_ATTRIBUTE`   | `outlineList`                   | The attribute of a list that belongs to the outline; `data-tt-outline-list` in HTML. |
| `COPIED_LABEL_ATTRIBUTE`   | `copiedOutlineLabel`            | The attribute a copied heading carries its label in, `null` in a document.           |
| `OUTLINE_SCHEME_NODE`      | `outlineScheme`                 | The type name of the block a document keeps its scheme in.                           |
| `OUTLINE_SCHEME_ATTRIBUTE` | `data-tt-outline-scheme`        | That block's element in HTML.                                                        |
| `outlineLabelsKey`         | a `PluginKey`                   | The key the `'refresh'` meta is set under.                                           |

## Commands

| Command                            | What it does                                                                                             |
| ---------------------------------- | -------------------------------------------------------------------------------------------------------- |
| `setOutlineLevels(levels)`         | The document's scheme, or `null` for `levels`. Needs `OutlineScheme`.                                    |
| `setOutlineLevel(level, template)` | One level of the document's scheme. Needs `OutlineScheme`.                                               |
| `refreshOutlineNumbers()`          | Counts again with the document unchanged.                                                                |
| `setOutlineList(linked)`           | Makes the list around the selection a list of clauses, or not. `false` outside one of the `lists` types. |
