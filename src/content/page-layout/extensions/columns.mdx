```js
import { Editor } from '@tiptap/core'
import { Columns } from '@tiptap-pro/extension-columns'
import StarterKit from '@tiptap/starter-kit'

const editor = new Editor({
  extensions: [StarterKit, Columns],
})

editor.commands.insertColumns({ count: 2 })
```

`@tiptap-pro/extension-columns` works in any editor, with or without pages. A layout grows with its content;
nothing about it needs pages.

The text in one column does not flow into the next. Columns that one run of text fills from the
bottom of the first to the top of the second belong to a page section; see
[Section columns](/page-layout/core-concepts/section-columns).

## The document

Two Node types, which `Columns` registers together:

| Type           |                                                                         |
| -------------- | ----------------------------------------------------------------------- |
| `columnLayout` | The row. Holds two to six `column`s.                                    |
| `column`       | One column. Holds any blocks — paragraphs, headings, a table, an image. |

```json
{
  "type": "columnLayout",
  "attrs": { "gap": "32px", "widthMode": "custom", "widths": ["1fr", "2fr"] },
  "content": [
    { "type": "column", "content": [{ "type": "paragraph" }] },
    { "type": "column", "content": [{ "type": "paragraph" }] }
  ]
}
```

| Attribute   |                                                                                                    |
| ----------- | -------------------------------------------------------------------------------------------------- |
| `gap`       | The space between columns, as a CSS length. `null` is the default gap.                             |
| `widthMode` | `'equal'` or `'custom'`.                                                                           |
| `widths`    | One CSS track size per column, such as `'1fr'` or `'240px'`, read while `widthMode` is `'custom'`. |

Widths that do not match the number of columns are not used: the layout is drawn with equal
columns until they do. Changing the number of columns makes them equal again.

A layout is a top-level block. A layout inside a column is valid content, from a paste for
example, but no command creates one.

## Options

```js
Columns.configure({
  minColumns: 2,
  maxColumns: 6,
  defaultGap: '24px',
  defaultWidthMode: 'equal',
})
```

- **`minColumns`**, **`maxColumns`** — how many columns a layout may have. They are part of the
  schema, so content with more or fewer does not load, and every editor on one shared document
  needs the same numbers.
- **`defaultGap`** — the gap of a new layout, and of one whose `gap` is `null`.
- **`defaultWidthMode`** — the width mode of a new layout.

## Commands

All of them but `insertColumns` work on the layout the cursor is in, or on a layout selected as
a Node, and answer `false` outside one.

| Command                    |                                                                                                                                                                                                                                                                                    |
| -------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `insertColumns(options?)`  | A layout of empty columns after the top-level block at the cursor, with the caret in the first one. An empty paragraph or heading at the cursor is replaced, and a cursor in a layout gets the new one after it. `options`: `count` (clamped into the bounds), `gap`, `widthMode`. |
| `setColumnCount(count)`    | Adds or removes columns at the end. A removed column's content moves into its neighbor.                                                                                                                                                                                            |
| `setColumnGap(gap)`        | The space between the columns, as a CSS length.                                                                                                                                                                                                                                    |
| `setColumnWidthMode(mode)` | `'equal'` or `'custom'`. `'equal'` also clears `widths`.                                                                                                                                                                                                                           |
| `setColumnWidths(widths)`  | One track size per column, which also sets `widthMode` to `'custom'`; `null` for equal columns. A list of the wrong length is refused.                                                                                                                                             |
| `addColumn(options?)`      | An empty column beside the one the cursor is in, after it unless `{ position: 'before' }`. Refused at `maxColumns`.                                                                                                                                                                |
| `removeColumn()`           | Removes the column the cursor is in. What was written in it moves into the next column, or the previous one for the last. Refused at `minColumns`.                                                                                                                                 |
| `moveColumn(direction)`    | Moves the column the cursor is in `'left'` or `'right'`, and the caret with it.                                                                                                                                                                                                    |
| `deleteColumns()`          | Removes the whole layout, columns and content.                                                                                                                                                                                                                                     |
| `exitColumns(options?)`    | Puts the caret in the block after the layout, or before it with `{ direction: 'before' }`, and makes an empty one where there is none.                                                                                                                                             |

```js
editor.commands.setColumnWidths(['1fr', '2fr'])
editor.can().addColumn() // false at maxColumns, or outside a layout
```

`addColumn`, `removeColumn` and `moveColumn` need the cursor inside a column, and answer `false`
for a layout selected as a whole.

## Keys

| Key                                               |                                                                                                                     |
| ------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| `Mod-Enter`                                       | Leaves the layout: `exitColumns()`.                                                                                 |
| `ArrowLeft`, `Backspace` at the start of a column | Moves the caret to the end of the previous column. Backspace deletes nothing there.                                 |
| `ArrowRight` at the end of a column               | Moves the caret to the start of the next column.                                                                    |
| `ArrowDown`, `ArrowUp`                            | At the end of a layout that is the last block of the document, or at the start of one that is the first, leaves it. |

Everywhere else the keys do what they do in any block.

## Styling

The grid is drawn by rules the extension puts into the page itself, first in `head`, so a
stylesheet of yours wins over them. They set the row, give every column at most its share even
with a long word or a wide image in it, and keep columns of different length at their own
height.

| Selector                        |                                                              |
| ------------------------------- | ------------------------------------------------------------ |
| `.tiptap-columns-layout`        | The layout, also `[data-tt-column-layout]`.                  |
| `.tiptap-columns-column`        | A column, also `[data-tt-column]`.                           |
| `.tiptap-columns-column-active` | The column the cursor is in. The extension gives it no look. |

| Custom property      |                                             |
| -------------------- | ------------------------------------------- |
| `--tt-column-gap`    | The layout's gap, set on its element.       |
| `--tt-column-widths` | Its track list while the widths are custom. |

Nothing has a border or a background. An outline on the active column is one rule:

```css
.tiptap .tiptap-columns-column-active {
  outline: 1px dashed rgba(0, 0, 0, 0.2);
}
```

The rules go into the page when the Editor is created, as a `style` element carrying the Editor's
`injectNonce`. With `injectCSS: false` they are left out, as Tiptap's own are, and
`columnStyleRules()` is the rules as a string for a stylesheet of your own. Without them the columns
stack. `mountColumnStyles(document, { nonce })` puts them into a document once.

## As Transactions

Every command has a Transaction of the same name that takes positions instead of reading the
selection, for writing several things in one step:

```js
import { columnLayoutAt, setColumnGapTransaction } from '@tiptap-pro/extension-columns'

const at = columnLayoutAt(editor.state.doc, editor.state.selection.from)

if (at) {
  editor.view.dispatch(setColumnGapTransaction(editor.state.tr, at.pos, '48px'))
}
```

`columnLayoutAt(doc, pos)` is `{ node, pos, columnIndex }` for the innermost layout around a
position, with `columnIndex` `-1` between columns, or `null` outside one.
`columnBounds(layout, layoutPos, index)` is where one column sits: `{ node, pos, start, end }`.
The others are `insertColumnsTransaction`, `setColumnCountTransaction`,
`setColumnWidthModeTransaction`, `setColumnWidthsTransaction`, `addColumnTransaction`,
`removeColumnTransaction`, `moveColumnTransaction`, `deleteColumnsTransaction` and
`exitColumnsTransaction`.

## With Page Layout

A layout cut by the bottom of a page carries on at the top of the next, and an author can keep
one on a page; see [Column layout on pages](/page-layout/extensions/overview#column-layout).
