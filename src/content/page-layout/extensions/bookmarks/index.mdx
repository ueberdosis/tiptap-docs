```js
import { Editor } from '@tiptap/core'
import StarterKit from '@tiptap/starter-kit'
import { Bookmarks } from '@tiptap-pro/extension-bookmark'

const editor = new Editor({
  extensions: [StarterKit, Bookmarks],
})

editor.commands.addBookmark({ name: 'Payment_terms' })
editor.commands.goToBookmark(id)
```

`Bookmarks` brings two types: the `bookmark` Mark, on text, and the `bookmarkPoint` Node, an
empty inline Node for a bookmark on no text. A bookmark is invisible unless bookmarks are
[shown](/page-layout/extensions/bookmarks#showing-bookmarks), and it adds nothing to the text: `editor.getText()` and a copy as
plain text are the same with or without one.

The [Commands](/page-layout/extensions/bookmarks/commands) are all on one page.

## What a bookmark is

Each bookmark has two attributes:

- **`id`** — what a reference or a link to it keeps. It does not change, also not when the
  bookmark is renamed or moved.
- **`name`** — what a reader sees and what a .docx stores.

A bookmark on text may run across several paragraphs, and every run of text carrying the same
`id` is one bookmark, from the first position any of them covers to the last. Bookmarks may
overlap and nest. Typing at the end of a bookmark does not widen it.

In HTML a bookmark is `<span class="tiptap-bookmark" data-tt-bookmark="id" data-tt-bookmark-name="name">`
around its text, and one on no text is an empty
`<span class="tiptap-bookmark-point" data-tt-bookmark-point="id" data-tt-bookmark-name="name">`.

## Names

A name is one Word accepts: a letter first, then letters, digits and `_`, at most forty
characters. Names are compared without regard to case, so `Terms` and `terms` are the same
bookmark.

A name starting with `_` is **hidden**, which is how Word names the bookmarks it makes for
itself — `_Ref…` behind a cross-reference, `_Toc…` behind a table of contents. Hidden bookmarks
are kept and left out of `bookmarksIn` unless you ask for them. A reader cannot add one under
such a name; an import can, with `hidden: true`.

```js
import { isValidBookmarkName, bookmarkNameFromText } from '@tiptap-pro/extension-bookmark'

isValidBookmarkName('4th clause') // false
bookmarkNameFromText('the agreed price') // 'the_agreed_price'
bookmarkNameFromText('Price', ['price']) // 'Price_2'
```

Without a `name`, `addBookmark` names the bookmark after the selected words this way.

## Adding, moving, renaming, removing

```js
editor.commands.addBookmark({ name: 'Price' }) // on the Selection
editor.commands.renameBookmark('Cost') // the bookmark around the cursor
editor.commands.removeBookmark() // the text stays
```

- With text selected, the bookmark is on that text. With nothing selected, it is a point at the
  cursor.
- **Adding under a name the document already has moves that bookmark** to the Selection, as Word
  does. Its `id` stays, so every reference to it follows.
- Renaming keeps the `id` too. A name another bookmark has is refused.
- Every Command answers `false` where it would do nothing — an invalid name, nothing that can
  carry a bookmark in the Selection, no bookmark around the cursor — which is what `can()` reads.

## Going to a bookmark

```js
editor.commands.goToBookmark(id)
```

Selects the bookmark and scrolls to it. An integration that reveals a position its own way —
because the place may not be drawn yet — passes `reveal`, which `goToBookmark` and a followed
link call instead:

```js
Bookmarks.configure({
  reveal: (bookmark) => myScrollTo(bookmark.from),
})
```

`reveal` is given the bookmark as `bookmarksIn` reads it and answers whether it went there.

## Links to a bookmark

A click on a link whose `href` is `#name` goes to the bookmark of that name, which is how a link
inside a document points at a place in it. A link to a name no bookmark has, and every other
link, is left to whatever else handles links — Tiptap's Link Extension included.

```js
import { bookmarkHref } from '@tiptap-pro/extension-bookmark'

editor
  .chain()
  .setLink({ href: bookmarkHref('Payment_terms') })
  .run()
```

`Bookmarks.configure({ followLinks: false })` leaves every link alone.

## Showing bookmarks

Word's _Show bookmarks_: the text of every bookmark underlined with a dashed line, across
paragraphs and pages, and a thin bar where one is on no text. Hidden bookmarks are not shown.

```js
Bookmarks.configure({ showBookmarks: true })
editor.commands.toggleBookmarkVisibility() // on, off
editor.commands.toggleBookmarkVisibility(false) // off
```

Neither takes room or covers a character: no line rewraps when they appear. The package brings
their stylesheet as a function, for a surface that has no build step for CSS:

```js
import { mountBookmarkStyles, bookmarkStyleRules } from '@tiptap-pro/extension-bookmark'

mountBookmarkStyles(document) // once; a second call does nothing
```

Under a Content Security Policy, pass the nonce you give the Editor as `injectNonce`:
`mountBookmarkStyles(document, { nonce })`. Where the policy admits no `style` element, load
`bookmarkStyleRules()` from a file instead.

The underlined text is `.tiptap-bookmark-shown`, with the bookmark's name as its `title`; the bar
is `.tiptap-bookmark-point-marker`. These custom properties change them:

| Property              | Default                               |
| --------------------- | ------------------------------------- |
| `--tt-bookmark-color` | `#8a8a8a`, the line and the bar       |
| `--tt-bookmark-line`  | `dashed`, any `text-decoration-style` |

## Copy and paste

A name is one bookmark. Pasting text whose bookmark the document already has — the same `id`,
or another bookmark of that name — pastes the text without it and leaves the bookmark where it
was. Pasting what was cut moves the bookmark, and so does dragging text to another place.

## Reading the bookmarks

```js
import {
  bookmarksIn,
  bookmarkById,
  bookmarkByName,
  bookmarkAround,
} from '@tiptap-pro/extension-bookmark'

bookmarksIn(editor.state.doc) // in the order they begin
bookmarksIn(editor.state.doc, { sort: 'name' }) // as Word's dialog sorts them
bookmarksIn(editor.state.doc, { hidden: true }) // Word's own as well
bookmarkByName(editor.state.doc, 'price') // without regard to case
bookmarkAround(editor.state.doc, from, to) // the smallest one around a range
```

Each bookmark is `{ id, name, hidden, from, to, point }`: `from` and `to` are where it begins and
ends, the same position for a bookmark on no text. `bookmarksInBlock(block, blockPos)` reads the
bookmarks beginning in one top-level block, at the positions of the document.

Every reader takes `ignore`, a function of a Node: what it returns `true` for is skipped with
everything in it, and what it returns `'descend'` for is read inside — a Node holding the
document's own content without being part of it. An editor drawing copies of content that
stands elsewhere passes it once to
the Extension, and every Command uses it:

```js
Bookmarks.configure({ ignore: (node) => node.attrs.isCopy === true })
```

## Referring to a bookmark

The cross-reference package reads bookmarks through a source; see
[Sources](/page-layout/extensions/cross-references/sources#inside-the-document). Neither package depends on the
other.

## Word

A .docx holds a bookmark as a name between a `w:bookmarkStart` and a `w:bookmarkEnd`. For a
converter, `bookmarkRangesIn` lists every bookmark that way, hidden ones included, and
`addImportedBookmarksTransaction` puts the ranges read out of a file onto the document:

```js
import { bookmarkRangesIn, addImportedBookmarksTransaction } from '@tiptap-pro/extension-bookmark'

const ranges = bookmarkRangesIn(editor.state.doc) // [{ name, from, to }]

const tr = addImportedBookmarksTransaction(editor.state, rangesFromTheFile)
if (tr) editor.view.dispatch(tr)
```

An import keeps Word's hidden names. It skips a name the document already has, a name Word would
not accept, a range with no text that can carry a bookmark, and the second of two ranges under
one name. An empty range is a bookmark on no text.

Text copied in Word and pasted keeps its bookmarks under their names, hidden ones included. Each
is pasted as a bookmark on no text where it begins, since the clipboard does not say where in the
text a bookmark ends. A name the document already has is dropped, as with any paste.
