`@tiptap-pro/extension-footnotes` brings the Nodes, the commands and the numbering, and works in
any editor:

```js
import { Editor } from '@tiptap/core'
import StarterKit from '@tiptap/starter-kit'
import { Footnotes } from '@tiptap-pro/extension-footnotes'

const editor = new Editor({
  extensions: [StarterKit, Footnotes],
})

editor.commands.insertFootnote()
```

The marks and the numbers in front of each note are drawn by a stylesheet that comes with the
package. Put it in the page once with `mountFootnoteStyles(document)`, or take its text from
`footnoteStyleRules()` into a stylesheet of your own. Without it, references and notes show no
numbers.

Without pages, every note is read at the end of the document, footnotes in one run and endnotes
in another. With [Page Layout](/page-layout/getting-started/overview), a footnote is drawn at the foot of the
page it is referred to on; see [Footnotes on pages](/page-layout/extensions/footnotes/on-pages).

## What the document holds

A `footnoteReference` at the place in the text, and the note's text in a `footnoteCollection` at
the end — one collection per placement, so footnotes and endnotes are kept apart, and one per
numbering scope.

A footnote is one reference and one note. Copying text with a reference in it copies the note
as well:

- **Copy and paste** gives the pasted reference a note of its own, with the same text, under a
  new `footnoteId`. The original keeps its identity.
- **Cut and paste**, and dragging text, keeps the `footnoteId` and the note it had.
- **Pasting into another document** brings the note along.
- **A second reference to the same note** that got there some other way — pasted from
  somewhere that did not carry the note, or written by a script — is given its own copy of the
  note; the first one in the text keeps the original. The new identity is derived from the old
  one (`…-1`, `…-2`), so every client of a shared document arrives at the same one.

To refer to a note a second time, write "see note 3" as text: a note has one reference.

The collections come after the last block with something in it. Empty paragraphs at the end of the
document or of a scope stay behind them, which is where StarterKit's trailing paragraph goes; once
one is typed in, the collections move behind it.

## Commands

```js
editor.commands.insertFootnote()
editor.commands.insertFootnote({ placement: 'endnote' })
```

A reference at the caret, a note for it, and the caret in that note.

| Command                                                     |                                                                      |
| ----------------------------------------------------------- | -------------------------------------------------------------------- |
| `insertFootnote(options?)`                                  | `{ placement }`, defaulting to the extension's `defaultPlacement`.   |
| `deleteFootnote(footnoteId)`                                | The note and every reference to it, in one step.                     |
| `setFootnotePlacement(footnoteId, 'footnote' \| 'endnote')` | Footnote to endnote and back. Same note, one attribute.              |
| `focusFootnote(footnoteId)`                                 | Puts the caret in the note's text, wherever it is being shown.       |
| `focusFootnoteReference(footnoteId)`                        | Back from a note to the place in the text it annotates.              |
| `insertNoteNumberingBreak(options?)`                        | A boundary behind which both kinds are counted from the start again. |

Every note has a `footnoteId`, which is what the commands and the click handlers take. A position
would not do: a note may be drawn somewhere other than where it is kept.

Which note a Selection is on, and in which half of it, is `footnoteAtSelection` — what a toolbar
asks before it offers to go to the note or back to the reference:

```js
import { footnoteAtSelection } from '@tiptap-pro/extension-footnotes'

footnoteAtSelection(editor.state.selection)
// { footnoteId: 'fn3', in: 'note' }, { footnoteId: 'fn3', in: 'reference' } or null
```

## Clicking a reference or a mark

Both are off by default, because selecting an atom is what a click on one does in an editor.
Turn them on to get the pair a reader expects — the reference leads to the note, the mark at the
head of the note leads back to the sentence:

```js
Footnotes.configure({
  onReferenceClick: ({ footnoteId }) => editor.commands.focusFootnote(footnoteId),
  onNoteMarkClick: ({ footnoteId }) => editor.commands.focusFootnoteReference(footnoteId),
})
```

What the handler returns says whether the editor should go on treating the click as a click. A
paginated editor sets both when they are left out; see
[Footnotes on pages](/page-layout/extensions/footnotes/on-pages).

## Numbering

Footnotes and endnotes count independently, so the mark says which of the two a reader is looking
for — 1, 2, 3 for footnotes and i, ii, iii for endnotes:

```js
Footnotes.configure({
  footnoteNumbers: { format: 'decimal', start: 1 },
  endnoteNumbers: { format: 'lowerRoman', start: 1 },
})
```

Those two are the defaults. `format` is one of the [number formats](/page-layout/extensions/number-formats),
`start` the first number of the sequence. Name only the one you change; the other keeps its
default.

`insertNoteNumberingBreak()` puts a boundary at the caret behind which both kinds start again. An
empty caret in the middle of a paragraph divides it, and each scope keeps its own runs of notes.

No number is ever written into the document. The mark is drawn, so a note inserted above
renumbers every note behind it without an edit.

| Option             |                                                                                                           |
| ------------------ | --------------------------------------------------------------------------------------------------------- |
| `defaultPlacement` | `'footnote'` or `'endnote'`, what `insertFootnote` makes when it is not told.                             |
| `numbering`        | `false` draws no marks, for a surface that draws its own. `true` by default.                              |
| `counter`          | A function that says which mark each note gets, for a surface that counts differently. `null` by default. |
| `scopes`           | A function that says where a numbering scope ends, instead of the numbering breaks. `null` by default.    |

Set `counter` and `scopes` together or neither. One of the two on its own gives a document whose
marks are counted one way and whose runs of notes are divided another.

## Titles above a run of notes

Nothing by default, which is what a printed document does. To have a heading instead:

```js
Footnotes.configure({
  titleNode: 'heading',
  footnoteTitle: 'Notes',
  endnoteTitle: 'Endnotes',
})
```

`titleNode` is the name of a Node type from your own schema, since what a heading is — whether it
belongs in the outline, what it looks like — is yours. The two words are written once, when the
run of notes comes into being; after that the heading is content, and a reader may rename it.

## Keeping notes and references agreeing

A pass in the editor keeps every note behind a reference and in the order of the references: a
note whose reference is deleted goes, and a second reference to the same note is given a copy of
its own.

| Option          |                                                                                                      |
| --------------- | ---------------------------------------------------------------------------------------------------- |
| `repair`        | `false` turns the pass off. `true` by default.                                                       |
| `notesDocument` | A function of the editor returning the document a copy takes notes from. `null` is the editor's own. |

An editor with pages runs the pass on the document rather than on what it renders, and sets
`notesDocument` itself; see [Footnotes on pages](/page-layout/extensions/footnotes/on-pages).

## Pasting from Word

Footnotes and endnotes copied in Word are pasted as notes: a reference where Word's mark was,
and the note's text in the run of notes, a footnote as a footnote and an endnote as an endnote.
Each is given a new identity and numbered with the others. A reference whose note was not
copied — text copied without the end of the document, where Word keeps its notes — is pasted as
the text of its mark.

`Footnotes` adds this itself. Its two halves are exported for an editor that handles pastes
some other way: `wordNotesToHtml(html)` returns the HTML with references in place of Word's
marks and the text of each note by identity, and `sliceCarryingWordNotes(slice, notes, schema, parse)` gives each pasted reference its note.
