## What a document is drawn in

```js
import { COLOR_PROPS, styleValuesOf } from '@tiptap-pro/extension-document-styles'

const { documentStyles } = editor.storage
const doc = editor.state.doc

const colors = styleValuesOf(
  doc,
  documentStyles.stylesOf(doc),
  COLOR_PROPS,
  documentStyles.themeOf(doc),
)

colors[0]
// {
//   value: '#1f2937',
//   props: ['color'],
//   styles: ['normal', 'note', 'grid'],
//   readOnlyStyles: [],
//   overrides: 3,
//   direct: 2,
//   themeColor: null,
// }
```

`styleValuesOf(doc, lookup, props, theme)` reads the given properties in every style the document
can use — its own and its libraries', table conditions included — in what its blocks and text
override by hand, and in what [Tiptap's own formatting](/page-layout/extensions/document-styles/values#tiptaps-own-formatting) sets. It answers
one entry per value, the most used first:

| Field            |                                                                                                                   |
| ---------------- | ----------------------------------------------------------------------------------------------------------------- |
| `value`          | The value, written one way: `#1F2937` and `#1f2937` are one color, `Georgia,serif` and `Georgia, serif` one font. |
| `props`          | The properties it is set in.                                                                                      |
| `styles`         | The ids of the styles that set it.                                                                                |
| `readOnlyStyles` | Of those, the ones a library defines. Replacing the value leaves them as they are.                                |
| `overrides`      | How many blocks and runs of text set it by hand.                                                                  |
| `direct`         | How many set it with Tiptap's own formatting, such as `setColor`.                                                 |
| `themeColor`     | The theme color it is drawn the same as, such as `'accent1'`, or `null`. Only with a `theme`.                     |

A reference to the theme, `'theme:accent1'`, is a value of its own and not the hex it is drawn in:
it follows the theme, and the hex does not.

`COLOR_PROPS` is `color`, `backgroundColor`, `textDecorationColor`, `outlineColor`,
`columnRuleColor` and the border colors. `FONT_PROPS` is `fontFamily`. Any list of properties in
camel case works.

`normalizeStyleValue(value)` writes a value the way `styleValuesOf` compares it.

## Where a value or a style is drawn

`editor.storage.documentStyles.valueLocationsOf(doc, props, value)` answers every place a value is
drawn in, in document order: each block, cell or run of text, and why it has the value.
`locationsOf(doc, styleId)` does the same for a style. Both read the extension's options — the
defaults, `tableTypes`, `continuesNode` and `directFormatting` — and a panel steps through what they
answer to show each place in turn.

```js
import { COLOR_PROPS } from '@tiptap-pro/extension-document-styles'

const doc = editor.state.doc
const storage = editor.storage.documentStyles

storage.valueLocationsOf(doc, COLOR_PROPS, '#c00000')
// [{ from: 0, to: 22, kind: 'node', via: 'default', styleId: 'body' },
//  { from: 48, to: 61, kind: 'mark', via: 'override', styleId: null }]

storage.locationsOf(doc, 'heading-1')

const [first] = storage.locationsOf(doc, 'quote')
editor
  .chain()
  .focus()
  .setTextSelection({ from: first.from + 1, to: first.to - 1 })
  .scrollIntoView()
  .run()
```

| `via`      | Why the place has it                                                                                                               |
| ---------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| `style`    | It refers to the style, or to a style that sets the value, through `basedOn` as well.                                              |
| `default`  | It has no style and is drawn in its type's [default style](/page-layout/extensions/document-styles/definitions#the-default-style). |
| `table`    | A cell, drawn in the value by a part of its table's style: the header row, a band, a corner. `styleId` is the table's style.       |
| `override` | It sets the value by hand.                                                                                                         |
| `direct`   | [Tiptap's own formatting](/page-layout/extensions/document-styles/values#tiptaps-own-formatting) sets it, a `setColor`.            |

What is found is what shows the value. A paragraph drawn red with one word set to blue is found as
the two runs of text around the word, each `kind: 'mark'`; a red word in a red paragraph is found
once, as the paragraph. A place whose override sets the same property is found by the override's
value, not by its style's. A cell's own style and overrides are drawn over its table's, so a cell
that sets the property itself is not found by the table's.

Values are compared the way `styleValuesOf` groups them, so `#C00000` finds `#c00000`, and a theme
reference finds only the same reference. A `kind: 'node'` place spans the whole block or cell, `from`
before it and `to` after it.

`styleValueLocationsOf(doc, styles, props, value, { defaults, tables, rules })` and
`styleLocationsOf(doc, styleId, { defaults })` are the same without an editor. Without `defaults`, a
block drawn in its default is not found, and without `tables: { types, continuesNode }`, a cell drawn
by a part of a table style is not.

## replaceStyleValue()

```js
import { COLOR_PROPS } from '@tiptap-pro/extension-document-styles'

// One color for another
editor.commands.replaceStyleValue(COLOR_PROPS, '#1f2937', '#111827')

// Two colors merged into one
editor.commands.replaceStyleValue(COLOR_PROPS, '#1e293b', '#1f2937')

// A fixed color tied to the theme
editor.commands.replaceStyleValue(COLOR_PROPS, '#156082', 'theme:accent1')

// A font
editor.commands.replaceStyleValue(['fontFamily'], 'Georgia, serif', 'theme:minor')
```

`replaceStyleValue(props, from, to)` replaces `from` by `to` in the given properties of the
document's own styles, their table conditions, every override, and Tiptap's own formatting. `from`
is compared written one way; `to` is written as given. A color `setColor` set and replaced by a
reference to the theme becomes an override with the reference, and the Mark's `color` is cleared.

A library's styles are read only and keep the value. To replace it there too, duplicate the style
into the document first; see [Libraries](/page-layout/extensions/document-styles/libraries).

It answers `false` where `to` is `from` written another way, where `to` is no value CSS can take
in one of the properties — such as one containing `;` — and where nothing uses `from`.

Without an editor, `replaceStyleValueTransaction(transaction, props, from, to)` writes the same
into a Transaction you pass and returns it.

## Tiptap's own formatting

Tiptap's formatting Extensions are read as formatting of the text, the same as an override: Color,
BackgroundColor, FontFamily, FontSize and LineHeight set an attribute of `textStyle`, Highlight one
of its own Mark, TextAlign one of the block, and Bold, Italic, Underline, Strike, Subscript and
Superscript are a Mark whose being there is the value. They stay where they are; nothing turns a
`setColor` into an override unless [`adoptDirectFormatting()`](/page-layout/extensions/document-styles/applying#adoptdirectformatting)
is asked to.

|                                                                                                           | What it does with them                                                                                                                                                  |
| --------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `styleValuesOf`                                                                                           | Counts them in `direct`.                                                                                                                                                |
| `replaceStyleValue`                                                                                       | Replaces an attribute's value; a theme reference becomes an override. A value a Mark stands for, Bold's 700, is not replaced.                                           |
| [`discoverStyles`](/page-layout/extensions/document-styles/cleanup)                                       | Groups them with the overrides: ten bold paragraphs are a candidate. A style made with `createStyleFromCandidate` or given with `applyStyleToCandidate` takes them off. |
| `clearInlineStyles`                                                                                       | Clears them on the selected text, and on the text typed next.                                                                                                           |
| `adoptDirectFormatting`                                                                                   | Turns them into overrides of the style, drawn the same.                                                                                                                 |
| [`expressAsDirectFormatting`](/page-layout/extensions/document-styles/applying#expressasdirectformatting) | Writes overrides back as them, where a rule says how.                                                                                                                   |
| [`colorScheme`](/page-layout/extensions/document-styles/themes#dark-mode)                                 | Draws a color of theirs with its dark counterpart.                                                                                                                      |

How each is written is a rule, and the rules are the `directFormatting` option, `DIRECT_FORMATTING`
by default. A rule applies only where the schema has its type. A formatting Extension of your own
is read by adding one:

```js
import { DIRECT_FORMATTING, DocumentStyles } from '@tiptap-pro/extension-document-styles'

DocumentStyles.configure({
  directFormatting: [
    ...DIRECT_FORMATTING,
    { prop: 'fontVariantCaps', mark: 'smallCaps', value: 'small-caps' }, // the Mark is the value
    { prop: 'letterSpacing', mark: 'textStyle', attribute: 'letterSpacing' }, // an attribute of a Mark
    { prop: 'textIndent', attribute: 'indent' }, // an attribute of the block
  ],
})
```

| Field       |                                                                             |
| ----------- | --------------------------------------------------------------------------- |
| `prop`      | The style property, in camel case.                                          |
| `mark`      | The Mark type; left out for an attribute of a block a style can go on.      |
| `attribute` | The attribute the value is in; left out where the Mark itself is the value. |
| `value`     | What the Mark stands for where there is no `attribute`.                     |

A value equal to the attribute's default is not read: an alignment an Extension writes on every
paragraph is not formatting. Underline and Strike together are `textDecorationLine: 'underline line-through'`. Where an override and Tiptap's formatting set the same property, the override is
the one read, and the one drawn.

`directFormattingOf(node, rules)` answers what a text Node or a block is formatted with that way,
or `null`.

## Pasted formatting

Pasted text keeps a color, a background, a weight, a slant, a decoration or sub- and superscript
that no Extension of the editor would hold, as an override: a red span pasted into an editor
without Color stays red, and a bold one without Bold stays bold. What an Extension holds is left
to it. The font, its size and the line height are not kept this way, since Word writes them on
nearly every run whether anybody set them or not.

`keepPastedFormatting: false` drops what nothing holds, as the editor does without Document Styles.
