A reference can point at more than a Node type: a bookmark around a few words, a place a plugin
works out, a statute, a clause in another document. Each of these comes from a **source**,
registered by name next to the Node types:

```js
CrossReferences.configure({
  targets: { heading: {} },
  sources: {
    bookmark: {
      inBlock: (block, blockPos) => bookmarksIn(block, blockPos),
      displays: ['title', 'page', 'aboveBelow'],
    },
    statute: {
      targets: () =>
        statutes.map((s) => ({ id: s.number, type: 'Statute', title: s.name, data: s })),
      resolve: (id) => lookUpStatute(id),
    },
  },
})
```

A source's targets are listed, inserted, read, followed and exported like a heading's. Every
display, `update: 'manual'`, several targets in one reference, the picker data from
`crossReferenceTypesIn` and `refreshCrossReferences` work the same for them.

## What a source returns

Each target is `{ id, type, title, label?, data?, withheld? }`:

- **`id`** — unique within the source.
- **`type`** — the reference type a picker lists it under, `Statute`.
- **`title`** — what `show: 'title'` reads.
- **`label`** — `{ number, fullNumber, counts? }`, as for a Node type, or `null`.
- **`data`** — anything your own displays read as `target.data`. The package does not look at it.
- **`withheld`** — whether this target is [withheld](/page-layout/extensions/cross-references#withheld-targets).

## Inside the document

**`inBlock(block, blockPos)`** returns the targets inside one top-level block, each with the
`pos` it starts at in the document. They are listed in reading order among the Node targets. Only
the block that changed is asked again, so the answer may depend on the block alone and not on
anything around it. A target two blocks both return — a bookmark across two paragraphs — is one
target, at the first of them.

The bookmarks of [`@tiptap-pro/extension-bookmark`](/page-layout/extensions/bookmarks), read out of a block:

```js
import { bookmarksInBlock } from '@tiptap-pro/extension-bookmark'

function bookmarksIn(block, blockPos) {
  return bookmarksInBlock(block, blockPos).map((bookmark) => ({
    id: bookmark.id,
    type: 'Bookmark',
    title: bookmark.name,
    pos: bookmark.from,
  }))
}
```

Such a target has a position, so `page`, `aboveBelow` and a number relative to the clause the
reference is in work as for a heading. It has no Node: a display reading `target.node` gets
`null`, and `pageOf` is given `{ pos, doc, node: null }`.

## Outside the document

**`targets()`** lists them, in the order a picker shows them, after the document's own targets.
It is asked once, and again on `refreshCrossReferences()` and whenever the editor reads every
target afresh — keep it quick, and fetch the data somewhere else.

**`resolve(id)`** answers for an id `targets()` does not list — one pasted from another document
or typed into a form — with `{ type, title, label?, data?, withheld? }`, or `null`. A reference
to an id nobody answers for is unresolved: it reads `?` and carries
`data-tt-cross-reference-unresolved="target"`.

A target outside the document has no position and no page:

- `page` and `aboveBelow` are unresolved, with `data-tt-cross-reference-unresolved="page"`.
- `relativeNumber` reads the full number.
- `aboveBelow: true` on a reference adds nothing.

A display of your own reads what the source gave along:

```js
CrossReferences.configure({
  displays: {
    paragraph: { title: 'Paragraph', text: ({ target }) => target.data?.paragraph ?? null },
  },
  sources: {
    statute: { targets, displays: ['paragraph', 'title'] },
  },
})
```

## Ids

A reference stores a source's target as `source:id` — `statute:433` — in the same `targetIds` a
heading's id goes in. A Node target keeps its id as it is. `sourceTargetId(source, id)` writes the
stored form and `parseTargetId(stored, sources)` reads it back as `{ source, id }`; a prefix that
is not the name of a registered source is part of a Node target's id, so a heading with the id
`a:b` stays that heading's.

```js
editor.commands.insertCrossReference({ target: 'statute:433', show: 'title' })
```

A source owns its ids. The package never gives a source's target an id and never changes one,
also not where two targets of a source share it — keeping them apart is the source's.
Two sources may use the same id, since the prefix keeps them apart.

## Following a reference

**`reveal(click)`** on a source is asked first when a reference to one of its targets is
followed; where it returns `false`, the editor's `reveal` is asked. The click carries
`{ targetId, source, id, pos, event }`: the stored id, the source's name, the id within it, the
reference's position and the mouse event. A Node target's click has `source: null` and `id`
equal to `targetId`.

## Word fields

A target inside the document is exported with a bookmark, under `bookmarkOf` of its stored id,
like a heading. For a bookmark of the bookmark package, pass a `bookmarkOf` that answers with the
bookmark's own name, so the `REF` field names the bookmark the export writes:

```js
import { bookmarkById } from '@tiptap-pro/extension-bookmark'
import {
  bookmarkNameFor,
  parseTargetId,
  crossReferenceToFields,
} from '@tiptap-pro/extension-cross-references'

const bookmarkOf = (targetId) => {
  const { source, id } = parseTargetId(targetId, sources)
  return (source === 'bookmark' && bookmarkById(doc, id)?.name) || bookmarkNameFor(targetId)
}

crossReferenceToFields(reference, text, { bookmarkOf, doc, reading })
```

For a target outside the document, **`field(target)`** on the source returns
`{ instruction }` — a `HYPERLINK` to where it is kept, say — or `null`; without `field`, or where
it returns `null`, the reference is written as its text alone. See [Word fields](/page-layout/extensions/cross-references/docx#export).

## When the data changes

The editor sees a change to the document, and nothing else. When what `targets()`, `resolve`, a
`label` or `withheld` would answer changes, call:

```js
editor.commands.refreshCrossReferences()
```

Every reference is read again. Nothing is written to the document.
