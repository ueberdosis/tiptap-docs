Tiptap commands, so they chain and they answer `can()`:

```js
editor.commands.insertCrossReference({ target: 'scope-of-work', show: 'title' })
editor.can().resetCrossReference()
```

A command that cannot do anything returns `false` and changes nothing, which is what a toolbar
needs to disable a button. The commands that act on one reference take its position, and the
reference at the cursor when it is left out — the one the caret is in, or the one that is
selected.

## insertCrossReference(options)

A reference at the selection, replacing what is selected.

```js
editor.commands.insertCrossReference({
  target: pos, // the position the target starts at, or its id
  show: 'relativeNumber',
  hyperlink: true,
  aboveBelow: false,
  numberSeparator: null,
})

editor.commands.insertCrossReference({ targets: ['payment', 'term'], show: 'number' })
```

- **`target`** — one target, by the position it starts at or by its id.
- **`targets`** — several, read as `3, 5 and 7`. Only with `multiple: true`.
- **`show`**, **`hyperlink`**, **`aboveBelow`**, **`numberSeparator`** — as described under
  [references](/page-layout/extensions/cross-references#references).
- **`join`** — the rule several targets are read by, `'list'`, `'commas'`, `'range'` or one of
  yours; `null` by default, the configured one. See [several targets](/page-layout/extensions/cross-references/joins).

A target that has no id yet gets one in the same step. In `'manual'` mode the reference holds
the text its targets say from the start, and the caret is placed after it.

`false` when a target is not a registered one, when it has no id and `defineIdAttribute` is
`false`, when several are named without `multiple`, or when the selection is not in text.

## setCrossReferenceOptions(options, pos?)

Changes how a reference reads its targets: `show`, `hyperlink`, `aboveBelow`,
`numberSeparator`, `join`, and `targetIds` for which targets it names. A choice left out stays as it is.

```js
editor.commands.setCrossReferenceOptions({ show: 'page', aboveBelow: true })
```

The text a reference holds is kept; `resetCrossReference()` afterwards gives it what the new
choices read. `false` when there is no reference, or nothing changes.

## setCrossReferenceShow(pos, show)

What the reference at `pos` shows — `setCrossReferenceOptions({ show }, pos)` on its own.

## resetCrossReference(pos?)

Gives a reference back to its targets. In `'live'` mode the text written into it is removed and
it follows its targets again; in `'manual'` mode it gets what its targets say now. `false` where
it already reads that.

## updateCrossReferences()

What F9 does: every reference holding text gets what its targets say now. In `'live'` mode those
are the references somebody wrote into, in `'manual'` mode all of them. A locked reference is
left as it is. `false` when no reference changes.

## setCrossReferenceLocked(locked, pos?)

Whether `updateCrossReferences()` leaves the reference alone. The reference is still edited,
reset and removed as usual. `false` where it is locked or unlocked already.

## convertCrossReferenceToText(pos?)

Replaces a reference by the words it reads, as plain text with the reference's Marks: its own
text where it holds some, what its targets say where it does not. `false` where there is no
reference, or where an empty one has nothing to read because its target is gone.

## convertCrossReferencesToText()

The same for every reference in the document, locked ones included. References to a target that
is gone stay. `false` when there is nothing to convert.

## removeCrossReference(pos?)

Takes a reference out of the text, with whatever it holds. `false` where there is no reference.

## goToCrossReferenceTarget(targetId)

The caret at the start of a target's text, scrolled to: where following a reference leads. The
target is named by the id a reference stores. `false` for an id no target in the document
carries, and for a target a [source](/page-layout/extensions/cross-references/sources) resolves from outside the document.

```js
editor.view.focus()
editor.commands.goToCrossReferenceTarget('payment')
```

## refreshCrossReferences()

Reads every reference again, and asks every [source](/page-layout/extensions/cross-references/sources) outside the document for its
targets again. Call it when the data behind those targets changed: the editor cannot see that
by itself. Nothing in the document changes, so it is not part of the undo history and is not
sent to other users. Always `true`.

## setCrossReferenceUpdate(update)

`'live'` or `'manual'`, while the editor runs — the [`update`](/page-layout/extensions/cross-references#updating-references)
option. It changes no reference: one that is empty when the mode becomes `'manual'` reads its
targets until it is reset or updated. `false` when the mode is that already, and for `'manual'`
with [`holdsText: false`](/page-layout/extensions/cross-references#references-that-hold-no-text).

With `holdsText: false`, `updateCrossReferences()`, `convertCrossReferenceToText()` and
`convertCrossReferencesToText()` return `false` as well, and `insertCrossReference` stores no
text. A reference to a [withheld target](/page-layout/extensions/cross-references#withheld-targets) is neither updated nor
converted.

## As Transactions

The same writes, each returning the Transaction instead of dispatching it, or `null` where the
command would return `false`. `writing` is `editor.storage.crossReferences`:

| Command                        | Function                                                        |
| ------------------------------ | --------------------------------------------------------------- |
| `insertCrossReference`         | `insertCrossReferenceTransaction(state, writing, options)`      |
| `setCrossReferenceOptions`     | `setCrossReferenceOptionsTransaction(state, pos, options)`      |
| `setCrossReferenceShow`        | `setCrossReferenceShowTransaction(state, pos, show)`            |
| `resetCrossReference`          | `resetCrossReferenceTransaction(state, writing, pos)`           |
| `updateCrossReferences`        | `updateCrossReferencesTransaction(state, writing)`              |
| `setCrossReferenceLocked`      | `setCrossReferenceLockedTransaction(state, pos, locked)`        |
| `convertCrossReferenceToText`  | `convertCrossReferenceToTextTransaction(state, writing, pos)`   |
| `convertCrossReferencesToText` | `convertCrossReferencesToTextTransaction(state, writing)`       |
| `removeCrossReference`         | `removeCrossReferenceTransaction(state, pos)`                   |
| `goToCrossReferenceTarget`     | `goToCrossReferenceTargetTransaction(state, writing, targetId)` |

In a paginated editor the commands themselves write the document, not the pages — see
[Cross-references on pages](/page-layout/extensions/cross-references/on-pages#commands).
