## Quick start

Page Layout ships its own print rules, so printing needs only the browser's print dialog:

```js
window.print()
```

## What comes out

Sections on different paper print on their own paper, and the print dialog offers the paper of the first page. A zoom comes off for printing.

The paper sizes come from a style element, `style[data-tt-page-layout-sheets]`, that Page Layout always writes, also with `injectCSS: false`. It carries the editor's `injectNonce`, so a Content Security Policy without `'unsafe-inline'` lets it through. See [A Content Security Policy](/page-layout/guides/styling#a-content-security-policy).

Headers, footers, footnotes and repeated table header rows print. Sheet shadows, break lines, the selection Page Layout draws, and other users' cursors and selections do not.

A [long document](/page-layout/guides/long-documents#printing) prints every page. The browser breaks a [pageless](/page-layout/features/page-format#pageless) document, one continuous column without pages, into pages itself.

## Printing in Safari

Safari prints every sheet on the paper of the first page, and Page Layout fits a page of another format onto it:

- **A landscape page on portrait paper** is turned, its top to the left edge.
- **A larger page** is scaled down.

Other pages keep their size, and every page holds the same text as on screen.

## Several editors on one page

A browser prints the whole web page, so `window.print()` prints the sheets of every editor on it, in the order they appear. Each sheet still gets its own paper size, even when the editors use different formats. Destroying an editor removes its formats from the print rules.

The print dialog offers the paper of the first sheet on the web page, the first page of the editor that comes first. Safari prints every sheet on that paper, as [Printing in Safari](/page-layout/features/printing#printing-in-safari) explains.

To print one editor alone, hide the others in a print stylesheet of yours, such as `@media print { #original { display: none; } }`. In Safari the paper still follows the first editor on the web page, hidden or not.

## One format per print job

A print job has one paper size, so a printer that takes one format at a time prints a mixed document once per format.

`printSheetName(size)` returns the name of the sheets of one size, `{ width, height }` in CSS pixels, rounded. Sections of one format share a name. Each sheet carries it in `data-tt-page-sheet`, for a print stylesheet to select:

```js
import { printSheetName } from '@tiptap-pro/extension-page-layout'

// 'pl-sheet-794x1123', selected by [data-tt-page-sheet='pl-sheet-794x1123']
const a4 = printSheetName({ width: 794, height: 1123 })
```

## A PDF from a server

A PDF of the pages made on a server comes from Tiptap's Conversion service, see [PDF export with the REST API](https://tiptap.dev/docs/conversion/export/pdf/rest-api).

## A PDF from your own headless browser

A PDF printed by your own headless browser, such as Puppeteer or Playwright, gets the same sheets at full size.

It fires no print event, so in a long document only the sheets near the part in view are drawn. Pass `virtualization: false` to `PageLayout.configure()`, or draw every sheet before printing, where `editor` is the editor in the printed page:

```js
const engine = editor.storage.pageLayout.engine

engine.setVisiblePageRange(0, engine.getPageCount() - 1)
```
