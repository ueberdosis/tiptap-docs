## Quick start

`insertPageNumbers()` puts a page number into the footer of every page of the section at the cursor, here including the first page:

```js
import { createPageLayoutEditor, PageLayout, pageSetup } from '@tiptap-pro/extension-page-layout'
import StarterKit from '@tiptap/starter-kit'

const editor = createPageLayoutEditor({
  element: document.querySelector('#editor'),
  content: { type: 'doc', content: [{ type: 'paragraph' }] },
  extensions: [StarterKit, PageLayout.configure({ setup: pageSetup('A4') })],
})

editor.commands.insertPageNumbers({ zone: 'footer', align: 'center', firstPage: true })
```

## Page numbers on every page

`insertPageNumbers()` puts a number into the headers or the footers of a section, without opening one for editing. `removePageNumbers()` takes the numbers out of both again:

```js
editor.commands.insertPageNumbers({ zone: 'footer', align: 'outside', firstPage: false })
editor.commands.removePageNumbers()
```

Both act on the section whose header or footer is open, or else on the section at the cursor. `align` says where the number stands:

- **`'left'`, `'center'` or `'right'`.** On that side of every page.
- **`'outside'`.** Right on odd pages, left on even pages.
- **`'inside'`.** Left on odd pages, right on even pages.

Odd and even follow the number the page shows, so a section that starts its count again at 1 opens on the right with `'outside'`.

`firstPage: false` leaves the section's first page without a number. It switches on the section's [different first page](/page-layout/features/header-and-footer#a-different-first-page-odd-and-even-pages), which gives that page a header and footer of their own, and keeps their other content.

`firstPage: true` leaves that switch as it is. So where the switch is on, the first page gets the number too.

At a side, the number sits beside the first line, so the pages do not move.

Text already on that line flows around it, 0.13 in away. When the number is on the left, the text runs on to its right. When the number is on the right, the text breaks before it.

When the first line no longer fits beside the number, it wraps and the header grows by that line. From the second line on, the text has the full width.

A centered number takes a line of its own above the text, as in Word, so a header with text grows by a line.

In an empty header the number is the only line, and the pages do not move. Enter at the end of the number opens a line below it.

Each header or footer that the section draws in the zone gets the number, a first-page or even-page one too. With `firstPage: false`, the first-page one gets none. A section that [shows the header of a section before it](/page-layout/features/header-and-footer#inheriting-from-the-section-before) gets the number in that section.

Calling `insertPageNumbers()` again moves the numbers rather than adding more, and one undo takes them back with the first-page switch they set.

The number stands in a frame, a paragraph of its own that holds ordinary text. So for `Page 3 of 9` on the right, call `insertPageNumbers({ zone: 'footer', align: 'right', firstPage: true })` and write the text into that frame.

The user opens the footer, puts the cursor in front of the number and types `Page `. After the number, they type `of`, and your toolbar runs [`insertPageNumber('pages')`](/page-layout/features/page-numbers#insertpagenumber).

A later call of `insertPageNumbers()` with another alignment keeps the frame and its text, and changes only where it stands. A number moved to the other zone, such as from the footer to the header, arrives as a bare number.

`removePageNumbers()` leaves numbers that `insertPageNumber()` wrote into a header's text. For a toggle button, the engine, `editor.storage.pageLayout.engine`, answers for the same section: `hasPageNumbers()` says whether there are numbers to remove, and `getPageNumbers()` returns the options that put them there, or `null`. With numbers in both zones, it returns the header's:

```js
const engine = editor.storage.pageLayout.engine

engine.getPageNumbers() // { zone: 'footer', align: 'outside', firstPage: false }
```

## A page number in a header or footer

While a header or footer is open for editing, `insertPageNumber()` puts a page number field at the caret, an inline node that Page Layout fills in on every page. This example writes "Page 1 of 12" into the footer of the first page:

```js
editor.commands.openFurniture({ zone: 'footer', slot: 'default', pageIndex: 0 })

editor
  .chain()
  .insertContent('Page ')
  .insertPageNumber('page')
  .insertContent(' of ')
  .insertPageNumber('pages')
  .run()

editor.commands.closeFurniture()
```

The argument is the kind of number. `'page'`, the default, shows the number printed on the page, in its section's format, such as `iv` or `12`. `'pages'` shows how many pages the document has, and `'sectionPages'` how many begin in the page's section, both in digits.

The document stores which number stands there, not the number, so each page shows its own and a page added later updates them all. The caret treats the field as one character, and Backspace removes it whole.

Only headers and footers fill the field in, so a field pasted into the text shows nothing. For the page a position in the text is on, use `pageNumberAt`, as [From a decoration](/page-layout/getting-started/document-and-pages/reading#from-a-decoration) shows.

A header is as tall on every page that draws it, because Page Layout measures it once. So when a number makes a line wrap on one page only, that page's header does not grow.

## Number formats and chapters

A section's number format, such as `iv` or `12`, and the number its count starts at are on [Numbering per section](/page-layout/features/page-numbers/numbering). The chapter number in front of a page number, as in `2-1`, is on [Chapter numbers](/page-layout/features/page-numbers/chapter-numbers).

## Your own value per page

A node of your own in a header can show a value of its page, such as `iv / 12`. The node is an ordinary inline Tiptap node.

Its layout rule, which tells Page Layout how to treat the node type, has a `pageText` function and a `labelAttribute`. On each page, Page Layout sets that attribute on the node's element to what `pageText` returns:

```js
import { Node } from '@tiptap/core'
import { defineNodeLayout } from '@tiptap-pro/extension-page-layout'

export const PageVariable = Node.create({
  name: 'pageVariable',
  group: 'inline',
  inline: true,
  atom: true,
  parseHTML: () => [{ tag: 'span.page-variable' }],
  renderHTML: () => ['span', { class: 'page-variable' }],
})

defineNodeLayout('pageVariable', {
  labelAttribute: 'page-variable-text',
  pageText: (node, page) => `${page.label} / ${page.pageCount}`,
})
```

Add `PageVariable` to the editor's `extensions`, and call `defineNodeLayout()` before the editor is created. The node needs no attribute of its own. A stylesheet draws the value from the attribute:

```css
.page-variable::after {
  content: attr(page-variable-text);
}
```

To put the node into the header of the page at the cursor, open the header, insert it, and close the header again:

```js
editor.commands.openFurniture({ zone: 'header' })
editor.commands.insertContent({ type: 'pageVariable' })
editor.commands.closeFurniture()
```

`pageText` gets the node and `page`, which has these fields:

| Field               | Description                                  |
| ------------------- | -------------------------------------------- |
| `value`             | The number printed on the page.              |
| `label`             | That number in its section's format.         |
| `pageIndex`         | The page's place in the document, from zero. |
| `pageCount`         | How many pages the document has.             |
| `sectionPageNumber` | Which page of its section this is, from one. |
| `sectionPageCount`  | How many pages begin in that section.        |
| `sectionIndex`      | The section the page begins in, from zero.   |

When `pageText` returns `null`, nothing is written, and a node without a `labelAttribute` gets nothing written. Only headers and footers are asked for `pageText`.

## Switching it off

`pageNumber: false` removes the page number field:

```js
import { PageLayout } from '@tiptap-pro/extension-page-layout'

PageLayout.configure({ pageNumber: false })
```

`insertPageNumber()`, `insertPageNumbers()` and `removePageNumbers()` then return `false`.

## Commands

The commands return `false` and change nothing when they cannot act, as [How commands behave](/page-layout/reference/commands#how-commands-behave) explains.

### insertPageNumbers()

Puts a page number into the headers or the footers of a section:

```js
editor.commands.insertPageNumbers({ zone: 'footer', align: 'outside', firstPage: false })
```

It takes these options:

| Option      | Type                                                     | Default  | Description                                               |
| ----------- | -------------------------------------------------------- | -------- | --------------------------------------------------------- |
| `zone`      | `'header' \| 'footer'`                                   | Required | Where the numbers go.                                     |
| `align`     | `'left' \| 'center' \| 'right' \| 'inside' \| 'outside'` | Required | Where on the line the number stands.                      |
| `firstPage` | `boolean`                                                | Required | `false` leaves the section's first page without a number. |

Returns `false` while [pageless](/page-layout/features/page-format#pageless), where the document is one continuous column without pages. It also returns `false` with `pageNumber: false` or with `pageFurniture: false`, which switches headers and footers off.

### removePageNumbers()

Takes out the numbers `insertPageNumbers()` put into the section's headers and footers:

```js
editor.can().removePageNumbers()
editor.commands.removePageNumbers()
```

It takes no arguments, and returns `false` where the section has no such numbers and with `pageNumber: false`.

### insertPageNumber()

Puts a page number at the caret in the open header or footer:

```js
editor.commands.insertPageNumber('page')
editor.can().insertPageNumber('page') // false while no header or footer is open
```

Takes `kind`: `'page'`, `'pages'` or `'sectionPages'`, with `'page'` as the default.

Returns `false`, under `can()` too, while no header or footer is open, in a block that cannot hold the field, such as a code block, and with `pageNumber: false`.
