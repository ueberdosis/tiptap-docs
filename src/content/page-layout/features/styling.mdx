What a page has without any CSS of yours:

- the size of its paper, and the text box its margins leave,
- white paper with a shadow, and a gap to the next sheet,
- a line between its columns where the section asked for one,
- a visible selection, even where a page boundary runs through a table row.

What you write makes it your application: the desk the sheets lie on, the typography of the
document, and any value below you would rather set differently.

## Changing what it looks like

```css
.my-editor {
  /* the paper */
  --tt-page-paper: #fdfdfb;
  --tt-page-sheet-shadow: 0 1px 2px rgba(0, 0, 0, 0.1);
  --tt-page-sheet-gap: 40px;

  /* a selection the engine had to draw across a boundary */
  --tt-page-selection-fill: #b4d5fe;

  /* Word's line between columns */
  --tt-page-column-rule-color: #d4d4d8;
  --tt-page-column-rule-width: 1px;

  /* a colleague's caret, where collaboration is wired up */
  --tt-remote-caret-width: 2px;

  /* the labeled line that stands in for a break where there are no pages */
  --tt-page-break-line-color: rgba(15, 23, 42, 0.28);
  --tt-page-break-label-color: rgba(15, 23, 42, 0.45);
  --tt-page-break-label-size: 8px;
  --tt-page-break-line-space: 1.75rem;

  /* how far past the edge of the text an outline or a handle stays visible */
  --tt-page-clip-margin: 8px;
}
```

| Custom property               | Default                                                                | Description                                                                                |
| ----------------------------- | ---------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| `--tt-page-paper`             | `white`                                                                | The paper                                                                                  |
| `--tt-page-sheet-shadow`      | `0 1px 2px rgba(15, 23, 42, 0.14), 0 10px 24px rgba(15, 23, 42, 0.08)` | The shadow under a sheet                                                                   |
| `--tt-page-sheet-gap`         | `24px`                                                                 | The space between two sheets, in pixels                                                    |
| `--tt-page-selection-fill`    | `Highlight`                                                            | A selection the engine draws across a boundary                                             |
| `--tt-page-column-rule-color` | `rgba(15, 23, 42, 0.22)`                                               | The line between columns                                                                   |
| `--tt-page-column-rule-width` | `1px`                                                                  | Its width                                                                                  |
| `--tt-remote-caret-width`     | `2px`                                                                  | A colleague's caret. See [Collaboration](/page-layout/guides/collaboration#remote-cursors) |
| `--tt-page-break-line-color`  | `rgba(15, 23, 42, 0.28)`                                               | The line that stands in for a break where there are no pages                               |
| `--tt-page-break-label-color` | `rgba(15, 23, 42, 0.45)`                                               | Its label                                                                                  |
| `--tt-page-break-label-size`  | `8px`                                                                  | The label's font size                                                                      |
| `--tt-page-break-line-space`  | `1.75rem`                                                              | The room above and below the line                                                          |
| `--tt-page-clip-margin`       | `8px`                                                                  | How far past the text area content still paints                                            |

- **Document colors win.** Where a document carries colors of its own, paper and text per
  section, those win over `--tt-page-paper`, because they are content. See
  [Page colors](/page-layout/features/page-colors).
- **Sheets are centered.** A sheet narrower than its scroller sits in the middle.

### Clipping

The text area of a page clips what does not fit in it, so nothing is painted over a footer.

- **The clip margin.** `--tt-page-clip-margin` is how far outside that edge content still paints:
  enough for the outline of a selected image as wide as the text, and the handles beside it.
- **Too large is still cut.** Content that is too wide or too tall is cut off at the clip margin.
- **Older browsers.** A browser without `overflow-clip-margin` clips at the edge itself.

### More than color

Three of the properties are more than color, and the engine keeps that part:

- **The selection** is drawn over the words, because a sheet is opaque and a layer beneath it
  would not be seen. It multiplies, so the letters stay as dark as they were.
- **A fill behind the text.** Your color is used, but the blending is the engine's. A surface that
  wants a fill behind the text draws the selection itself.
- **The line between columns** is painted, never laid out. A border would take width from the
  column every block was measured to, and the page count would change when an author switches
  the line on.
- **A caret** takes no horizontal room, and the room it gives back is worked out from
  `--tt-remote-caret-width`. A `border-left` of yours would push the words behind it and
  repaginate the document whenever a colleague moves.

## Turning it off

```js
PageLayout.configure({ sheetAppearance: 'none' })
```

| Option            | Type                | Default   | Description                        |
| ----------------- | ------------------- | --------- | ---------------------------------- |
| `sheetAppearance` | `'paper' \| 'none'` | `'paper'` | Whether the engine draws the paper |

- **Nothing visible is drawn.** No paper, no shadow, no gap, no selection fill, no column rule,
  and no peer's caret.
- **The attributes stay.** Every element still carries the attributes below. This is the mode
  for a surface with a design of its own, before overriding rule after rule.
- **The geometry of a sheet stays.** A content box a few pixels out would have every block in it
  measured at a width the paper was never divided into.
- **A peer's caret still takes no room.** A caret that took horizontal space would push words
  along, break the line earlier, and repaginate the document whenever a colleague moves.

## What the engine writes either way

| Part                     | What the engine sets                                                                                                                                 |
| ------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| The sheet                | Its width and height from the paper, the padding from the margins, a fixed height so it cannot grow, and clipping                                    |
| The space between blocks | Whichever of the two margins is larger, the way a browser shows it. None above the half of a paragraph a boundary continues                          |
| The tiers inside it      | One section's slice of the sheet, as a grid of the section's columns and their gaps. The last tier shrinks to what is left, which makes a sheet clip |
| The text box             | Fills the tier's track, clips, and never stretches past the width its content was measured at                                                        |
| Headers and footers      | Where the band sits, how tall it is, and that its content carries no margins of its own                                                              |
| The note area            | Its box at the foot of the sheet or under the text, and the height the notes were given                                                              |
| Break markers            | The marker that made a cut is not drawn where it made it                                                                                             |
| Selection                | Where the pieces of a drawn selection sit, that the mouse goes through them, and that a header being edited makes the body unselectable              |
| Print                    | One sheet per page at its planned size, no sheet split in two, no margin around a page, and no shadow                                                |

### Margins between blocks

- **Write the rhythm on either edge.** `margin: 0 0 14px`, `margin: 14px 0 0` and `margin: 14px 0`
  all give 14 pixels between two paragraphs and the same number of pages. Two margins between
  blocks collapse to the larger of them, on the sheet as anywhere else.
- **At the top of a page.** A heading with `margin: 2em 0 0.5em` gets its two em at the top of a
  page too, as in Word.
- **A split paragraph.** The lower half of a paragraph split across a page boundary starts flush
  at the top of the next page. The space before a paragraph belongs to the paragraph, not to each
  half.
- **Styling the lower half.** `[data-tt-split-continuation]` is that half, for anything else of
  yours that should not repeat at a seam, such as a first-line indent.

### The boxes are the engine's

- **A page is exactly as tall as its paper.** Content the engine could not fit is clipped, and the
  page carries `data-tt-overflow`. Hang a warning in your UI there.
- **Your stylesheet cannot take them by accident.** A `height: auto` on a page or a `column-count`
  of your own has no effect, however specific the selector. The pages are measured against these
  boxes, and a page 40 pixels taller than its paper breaks in places nothing on screen explains.
- **Appearance goes through the custom properties**, which need no specificity at all.

## A Content Security Policy

The rules go into the page as a `style` element, the way Tiptap's own do, and they follow the same
two Editor options:

```js
createPageLayoutEditor({ element, extensions, content, injectNonce: nonce })
```

| Editor option | Description                                                                                     |
| ------------- | ----------------------------------------------------------------------------------------------- |
| `injectNonce` | Puts the nonce on the element, which a policy without `'unsafe-inline'` lets through            |
| `injectCSS`   | `false` leaves the element out, for a policy that admits none. The rules are then yours to load |

With `injectCSS: false`, load the rules from a file:

```js
import { layoutStyleRules } from '@tiptap-pro/extension-page-layout'

const css = layoutStyleRules({ sheetAppearance: 'paper' }) // the options you configured
```

- **The same options.** Pass the same `breaksWithoutPages` and `sheetAppearance` you gave
  `PageLayout`.
- **Not optional.** Without these rules the pages are measured wrong: a sheet grows with its
  content and the breaks land in the wrong places.
- **Column layouts** follow both options as well, with `columnStyleRules()`.
- **Other packages.** The stylesheets of footnotes, outline numbering, cross-references and
  bookmarks are mounted by you and take a nonce the same way.

## What the engine publishes

Every measurement is a custom property on the element that owns it. Your stylesheet never
computes geometry, and a panel, a ruler or an overlay of yours can read the same numbers.

On `[data-tt-page]`, the sheet:

| Custom property                                                                                      | Description                                                                    |
| ---------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| `--tt-page-width`, `--tt-page-height`                                                                | The sheet                                                                      |
| `--tt-page-margin-top`, `--tt-page-margin-right`, `--tt-page-margin-bottom`, `--tt-page-margin-left` | The margins                                                                    |
| `--tt-page-content-top`, `--tt-page-content-bottom`                                                  | Where the text begins and ends once a header or footer has outgrown its margin |
| `--tt-page-header-offset`, `--tt-page-footer-offset`                                                 | How far a band sits from the edge                                              |
| `--tt-page-background`, `--tt-page-text`, `--tt-page-accent`                                         | The document's colors, where it carries any                                    |

On `[data-tt-page-tier]`, one section's slice of a sheet:

| Custom property                                       | Description                                                                |
| ----------------------------------------------------- | -------------------------------------------------------------------------- |
| `--tt-page-columns`                                   | How many columns this section has                                          |
| `--tt-page-column-tracks`                             | The grid tracks, columns and gaps together                                 |
| `--tt-page-column-rule-1` … `--tt-page-column-rule-5` | Where a line between columns goes, measured from the left of the text area |

On `[data-tt-page-notes]`, the note area:

| Custom property          | Description                                                                                     |
| ------------------------ | ----------------------------------------------------------------------------------------------- |
| `--tt-page-notes-height` | The height of the note area                                                                     |
| `--tt-page-notes-top`    | Where the notes sit, when they sit directly below the text rather than at the foot of the sheet |

## The room around the pages

The desk the sheets lie on is yours. The element you passed as `element` holds the pages. What
surrounds it, such as its background, its padding and how far the sheets sit from the edge, is a
stylesheet of yours. `--tt-page-sheet-gap` is the space between two sheets.

- **No markup is required.** Nothing is needed around that element for the pages to appear.
- **The window scrolls by default.** It scrolls the document if nothing closer to it does.
- **A scrolling pane.** Give the element a scrolling ancestor, `overflow: auto` on the box the
  pages should scroll inside, when the sheets should scroll within a pane rather than with the
  page.
- **The fit.** That box is also what a [fit to width](/page-layout/features/zoom#fit-to-width) is measured
  against.

```css
.my-desk {
  background: #f3f4f6;
  overflow: auto;
  padding: 40px;
}
```

### A toolbar over the pages

The engine scrolls things into view: the caret, a header the reader just opened, and the note
area the caret was carried into. It cannot see that the top of your scroller is covered by a
toolbar of yours, so tell it how much room to leave:

```js
PageLayout.configure({ scrollMargin: { top: 96, bottom: 24 } })
```

| Field    | Type     | Default | Description                                   |
| -------- | -------- | ------- | --------------------------------------------- |
| `top`    | `number` | `48`    | Room at the top of the viewport, in pixels    |
| `bottom` | `number` | `48`    | Room at the bottom of the viewport, in pixels |

- **The default** of 48 pixels is about three lines of body text.
- **Set `top`** to the height of anything drawn over the pages. Otherwise the caret can end up
  scrolled to exactly where your toolbar is, which reads as the editor scrolling to the wrong
  place.

### Scaling the sheets

Scaling the sheets is not a stylesheet's job. A transform the engine has not been told about is
measured as part of every height, and the document paginates at the scaled size. One call does it.
See [Zoom](/page-layout/features/zoom).
