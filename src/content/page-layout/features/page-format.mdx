## Quick start

Pass a setup to `PageLayout`. `pageSetup` builds one from a size and fills in the rest.

```js
import { createPageLayoutEditor, PageLayout, pageSetup } from '@tiptap-pro/extension-page-layout'
import StarterKit from '@tiptap/starter-kit'

const editor = createPageLayoutEditor({
  element: document.querySelector('#editor'),
  extensions: [
    StarterKit,
    PageLayout.configure({ setup: pageSetup('A4', { orientation: 'landscape' }) }),
  ],
})
```

Without `setup`, the editor has no pages: one continuous column. See [Pageless](/page-layout/features/page-format#pageless).

- `PAGE_FORMATS` holds them by id, as `PageFormat` objects.
- `PAGE_FORMAT_ORDER` lists the ids in the order a size picker offers them: A4, Letter and Legal
  first, then the rest.
- Sizes are portrait. `orientation: 'landscape'` swaps width and height.

## A size of your own

`pageFormat` builds a `PageFormat` from the unit you measure in.

```js
import { pageFormat, pageSetup } from '@tiptap-pro/extension-page-layout'

const square = pageFormat({ id: 'square', label: 'Square', width: 20, height: 20, unit: 'cm' })

PageLayout.configure({ setup: pageSetup(square) })
```

| Option    | Type       | Description                                                           |
| --------- | ---------- | --------------------------------------------------------------------- |
| `width`   | `number`   | The width in `unit`                                                   |
| `height`  | `number`   | The height in `unit`                                                  |
| `unit`    | `PageUnit` | `'px'`, `'mm'`, `'cm'`, `'in'` or `'pt'`. Default `'px'`              |
| `id`      | `string`   | Stored with the section. Default `custom-` and the measurements       |
| `label`   | `string`   | What a size picker shows. Default the measurements, such as `20×20cm` |
| `margins` | `Margins`  | The margins a setup on this size gets when it names none              |

- **Stored with the document.** A section stores the size's `id`, `width` and `height`, so
  another editor opens the document on the same paper without knowing the size.
- **The label is not stored.** Read back from the document, a built-in size gets its label from
  its id, and a size of your own is labeled with its measurements in pixels, such as
  `756×756`. Look the label up by `id` where you show it.

## Margins

`margins` holds `top`, `right`, `bottom` and `left` in CSS pixels. `MARGIN_PRESETS` has three
sets to offer in a picker:

| Label  | Top and bottom | Left and right  |
| ------ | -------------- | --------------- |
| Normal | 1 in (96 px)   | 1 in (96 px)    |
| Narrow | 0.5 in (48 px) | 0.5 in (48 px)  |
| Wide   | 1 in (96 px)   | 1.5 in (144 px) |

```js
import { MARGIN_PRESETS } from '@tiptap-pro/extension-page-layout'

const narrow = MARGIN_PRESETS.find((preset) => preset.label === 'Narrow')
const setup = editor.storage.pageLayout.engine.getSetup()

editor.commands.setSectionSetup(0, { ...setup, margins: narrow.margins })
```

- **A setup without margins** takes the size's own margins, and else Normal.
- **A header or footer taller than its margin** pushes the text down instead of overlapping
  it. See [Header and footer](/page-layout/features/header-and-footer#how-far-from-the-edge).

## Units

The engine measures in CSS pixels, 96 to the inch. These functions convert, without rounding:

| Function       | Arguments                | Returns                     |
| -------------- | ------------------------ | --------------------------- |
| `toPixels`     | `value`, `unit`, `dpi?`  | `value` in `unit` as pixels |
| `fromPixels`   | `pixels`, `unit`, `dpi?` | `pixels` in `unit`          |
| `cmToPixels`   | `cm`, `dpi?`             | Centimeters as pixels       |
| `inchToPixels` | `inches`, `dpi?`         | Inches as pixels            |
| `pixelsToCm`   | `pixels`, `dpi?`         | Pixels as centimeters       |
| `pixelsToInch` | `pixels`, `dpi?`         | Pixels as inches            |

`dpi` defaults to 96. Round where you show a number, not where you store one.

## What a setup holds

`pageSetup(format, options)` returns a `PageSetup`. `format` is an id from
[Paper sizes](/page-layout/features/page-format#paper-sizes) or a `PageFormat`. Every option is the field of the same name.

| Field           | Type              | Default                                        | Description                                                                                          |
| --------------- | ----------------- | ---------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| `format`        | `PageFormat`      | —                                              | The paper size                                                                                       |
| `orientation`   | `PageOrientation` | `'portrait'`                                   | `'portrait'` or `'landscape'`                                                                        |
| `margins`       | `Margins`         | The size's margins, else Normal                | In CSS pixels                                                                                        |
| `theme`         | `PageTheme`       | Page `#ffffff`, text and accent `#18202f`      | See [Page colors](/page-layout/features/page-colors)                                                 |
| `columns`       | `PageColumns`     | One column                                     | See [Section columns](/page-layout/features/section-columns)                                         |
| `notePlacement` | `NotePlacement`   | `'bottomOfPage'`                               | `'bottomOfPage'` or `'belowText'`. See [Footnotes on pages](/page-layout/other-extensions/footnotes) |
| `noteNumbering` | `NoteNumbering`   | Footnotes `1, 2, 3`, endnotes `i, ii, iii`     | How notes are counted and marked                                                                     |
| `pageNumbering` | `PageNumbering`   | `1, 2, 3`, counting on from the section before | See [Numbering the pages](/page-layout/features/page-numbers#numbering-the-pages)                    |

Pass a whole setup to `PageLayout.configure`. A partial `margins` there keeps the values it
leaves out from before.

## Where the paper is stored

- **In the document.** A document stores its paper in a section break before its first block.
  A server, an export or another editor reads it from the JSON.
- **The `setup` option** is the paper of a new, empty document. A document that stores its own
  paper keeps it when it is loaded.
- **`setPageSetup`** changes the paper this editor shows a document in that stores none. It is
  not saved.
- **`setSectionSetup`** changes the paper of one section and is saved. Section `0` is the
  document's own paper. See [Sections](/page-layout/features/sections).

Read the stored paper without an editor:

```js
import { documentPageSetup, sectionsDeclaredBy } from '@tiptap-pro/extension-page-layout'

const setup = documentPageSetup(doc) // the document's paper, or null
const sections = sectionsDeclaredBy(doc) // every section, or null
```

## Pageless

`setPageSetup(null)` shows the document as one continuous column, without pages.

```js
editor.commands.setPageSetup(null)
```

- **The document does not change.** Pass a setup again to get the pages back.
- **Manual breaks stay visible.** See [Breaks](/page-layout/features/breaks#breaks-without-pages).

## Commands

### setPageSetup

Sets the paper this editor shows a document in that stores none, or `null` for no pages.

```js
editor.commands.setPageSetup(pageSetup('Letter'))
editor.commands.setPageSetup(null)
```

| Option  | Type                | Description                       |
| ------- | ------------------- | --------------------------------- |
| `setup` | `PageSetup \| null` | The paper, or `null` for pageless |

Returns `false` for a setup when the document stores its own paper. Change that paper with
`setSectionSetup(0, setup)`. `null`, and a setup while pageless, always work.

### setSectionSetup

Sets the paper of one section, by index, and saves it in the document.

```js
const engine = editor.storage.pageLayout.engine
const index = engine.getActiveSectionIndex()
const current = engine.getSections()[index].setup

editor.commands.setSectionSetup(index, { ...current, orientation: 'landscape' })
```

| Option         | Type        | Description                                                                   |
| -------------- | ----------- | ----------------------------------------------------------------------------- |
| `sectionIndex` | `number`    | An index of `engine.getSections()`. `0` is the document's own paper           |
| `setup`        | `PageSetup` | The whole setup. Spread the current one to keep its colors, columns and notes |

Returns `false` while pageless, for an index with no section, and when `sectionBreak` is
switched off.
