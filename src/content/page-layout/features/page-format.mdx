## Quick start

To choose the paper, pass `PageLayout.configure()` a setup from `pageSetup()`, which fills in the margins and every other field you leave out:

```js
import { createPageLayoutEditor, PageLayout, pageSetup } from '@tiptap-pro/extension-page-layout'
import StarterKit from '@tiptap/starter-kit'

const editor = createPageLayoutEditor({
  element: document.querySelector('#editor'),
  content: { type: 'doc', content: [{ type: 'paragraph' }] },
  extensions: [
    StarterKit,
    PageLayout.configure({ setup: pageSetup('Letter', { orientation: 'landscape' }) }),
  ],
})
```

Build the editor with `createPageLayoutEditor()`. An editor from `new Editor()` draws no pages and warns on the console, and every Page Layout command in it returns `false`.

To change the paper of the open document, call `setSectionSetup()` on section `0`, the first [section](/page-layout/features/sections), which holds the paper of the whole document. Spread `engine.getSetup()`, the setup in force, to keep the fields you do not change:

```js
import { MARGIN_PRESETS, PAGE_FORMATS } from '@tiptap-pro/extension-page-layout'

// The engine is the object that lays out the pages.
const engine = editor.storage.pageLayout.engine
const narrow = MARGIN_PRESETS.find((preset) => preset.label === 'Narrow')

// Letter paper, then Narrow margins
editor.commands.setSectionSetup(0, { ...engine.getSetup(), format: PAGE_FORMATS.Letter })
editor.commands.setSectionSetup(0, { ...engine.getSetup(), margins: narrow.margins })
```

Without `setup`, the editor is [pageless](/page-layout/features/page-format#pageless), which means it shows the document as one continuous column without pages.

## Paper sizes

`PAGE_FORMATS` holds the built-in sizes by id, as `PageFormat` objects: an `id`, the `label` a size picker shows, and a `width` and `height` in CSS pixels. All are portrait:

| Id                | Label                     | Size           |
| ----------------- | ------------------------- | -------------- |
| `A3`              | A3                        | 297 × 420 mm   |
| `A4`              | A4                        | 210 × 297 mm   |
| `A5`              | A5                        | 148 × 210 mm   |
| `A6`              | A6                        | 105 × 148 mm   |
| `B5ISO`           | ISO B5                    | 176 × 250 mm   |
| `B5JIS`           | JIS B5                    | 182 × 257 mm   |
| `Book184x260`     | 184 × 260 mm              | 184 × 260 mm   |
| `Book195x270`     | 195 × 270 mm              | 195 × 270 mm   |
| `EnvelopeC5`      | Envelope C5               | 162 × 229 mm   |
| `EnvelopeDL`      | Envelope DL               | 110 × 220 mm   |
| `EnvelopeMonarch` | Envelope Monarch          | 3.875 × 7.5 in |
| `EnvelopeNo10`    | Envelope #10              | 4.125 × 9.5 in |

| `Folio`           | 8.5 × 13                  | 8.5 × 13 in    |

`PAGE_FORMAT_ORDER` lists the ids, of type `BuiltInPageFormatId`, in the order a picker offers them: A4, Letter and Legal first.

## Orientation

`orientation: 'landscape'` turns the paper by swapping its width and height. The default is `'portrait'`. To turn only part of a document, see [Sections](/page-layout/features/sections).

## Margins

`margins` is the space around the text in CSS pixels, such as `{ top: 96, right: 72, bottom: 96, left: 72 }`.

When you leave `margins` out of `pageSetup()`, the setup takes the margins of its paper size. Only a [size of your own](/page-layout/features/page-format#a-size-of-your-own) can have margins, so a built-in size gets Normal.

`MARGIN_PRESETS` holds these sets for a picker, each a `label` and `margins`:

| Label  | Top and bottom | Left and right  |
| ------ | -------------- | --------------- |
| Normal | 1 in (96 px)   | 1 in (96 px)    |
| Narrow | 0.5 in (48 px) | 0.5 in (48 px)  |
| Wide   | 1 in (96 px)   | 1.5 in (144 px) |

## A size of your own

`pageFormat()` builds a `PageFormat` in the unit you measure in, for `pageSetup()`:

```js
import { PageLayout, pageFormat, pageSetup } from '@tiptap-pro/extension-page-layout'

const square = pageFormat({ id: 'square', label: 'Square', width: 20, height: 20, unit: 'cm' })

PageLayout.configure({ setup: pageSetup(square) })
```

`pageFormat()` takes these options:

| Option            | Type                                                 | Default                             | Description                        |
| ----------------- | ---------------------------------------------------- | ----------------------------------- | ---------------------------------- |
| `width`, `height` | `number`                                             | Required                            | In `unit`.                         |
| `unit`            | `PageUnit`: `'px'`, `'mm'`, `'cm'`, `'in'` or `'pt'` | `'px'`                              |                                    |
| `id`              | `string`                                             | `custom-` and the measurements      | Saved in the document.             |
| `label`           | `string`                                             | The measurements, such as `20×20cm` | What a picker shows.               |
| `margins`         | `Margins`                                            | None                                | For a setup that names no margins. |

The document saves the size and its label, so another editor shows both without knowing your size. A built-in size gets its label from its id.

## Pageless

Pageless shows the document as one continuous column, without pages. `editor.commands.setPageSetup(null)` switches to it, and [setPageSetup()](/page-layout/features/page-format#setpagesetup) with a setup switches back. The document does not change, and the breaks you inserted stay visible as lines, see [Breaks without pages](/page-layout/features/breaks#breaks-without-pages). While pageless, `engine.getSetup()` returns `null`.

## Where the setup is stored

`setSectionSetup()` stores the paper in the document, in a section break, the block that starts a section, in front of the first block.

A document keeps its stored paper when it loads. So the `setup` option and `setPageSetup()` apply only to a document that stores none. [The document's own format](/page-layout/features/sections#the-documents-own-format) lists the other edits that store it.

`documentPageSetup(doc)` returns the stored paper, or `null` for a document that stores none. It takes the document as a node, such as the one `engine.getSourceDocument()` returns, not as JSON:

```js
import { documentPageSetup } from '@tiptap-pro/extension-page-layout'

const stored = documentPageSetup(editor.storage.pageLayout.engine.getSourceDocument())
```

To read the paper and the sections from saved JSON, see [On a server](/page-layout/guides/on-a-server).

## What a setup holds

`pageSetup(format, options)` returns a `PageSetup`. `format` is a built-in id or a `PageFormat`, and each option sets the field of the same name:

| Field           | Type                              | Default                                    | Description                                                       |
| --------------- | --------------------------------- | ------------------------------------------ | ----------------------------------------------------------------- |
| `format`        | `PageFormat`                      | Required                                   | The paper size.                                                   |
| `orientation`   | `'portrait'` or `'landscape'`     | `'portrait'`                               | See [Orientation](/page-layout/features/page-format#orientation). |
| `margins`       | `Margins`                         | The size's margins, else Normal            | See [Margins](/page-layout/features/page-format#margins).         |
| `theme`         | `PageTheme`                       | No colors, `null` for all three            | See [Page colors](/page-layout/features/page-colors).             |
| `columns`       | `PageColumns`                     | One column                                 | See [Section columns](/page-layout/features/section-columns).     |
| `notePlacement` | `'bottomOfPage'` or `'belowText'` | `'bottomOfPage'`                           | See [Footnotes](/page-layout/extension-behavior/footnotes).       |
| `noteNumbering` | `NoteNumbering`                   | Footnotes `1, 2, 3`, endnotes `i, ii, iii` | How notes are counted and marked.                                 |
| `pageNumbering` | `PageNumbering`                   | `1, 2, 3`, on from the section before      | See [Numbering](/page-layout/features/page-numbers/numbering).    |

`pageSetup()` fills a partial `theme`, `columns` or `pageNumbering` from the defaults. A `footnote` or `endnote` entry of `noteNumbering` replaces the default entry whole, with its `format`, `start` and `restart`. `DEFAULT_PAGE_SETUP` is A4 with every default.

The `setup` option of `PageLayout.configure()` takes only a whole `PageSetup`, so build it with `pageSetup()`. `configure()` does not fill in the fields you leave out.

When you configure `PageLayout` a second time, it merges the new `setup` into the old one, so a partial `margins` keeps the other margin values of the first call.

## Units

Page Layout measures in CSS pixels, 96 to the inch. `toPixels(value, unit, dpi?)` turns a value in a `PageUnit` into pixels, and `fromPixels(pixels, unit, dpi?)` turns pixels back.

`cmToPixels`, `inchToPixels`, `pixelsToCm` and `pixelsToInch` take the value and `dpi?`. `dpi` defaults to 96. They do not round, so round where you show a number, not where you store one.

## Commands

Both commands set the paper. They chain and answer `can()`.

### setPageSetup()

`setPageSetup()` sets the paper of this editor. The editor uses it for a document that stores no paper of its own. `null` switches the editor to pageless:

```js
import { pageSetup } from '@tiptap-pro/extension-page-layout'

editor.commands.setPageSetup(pageSetup('Letter'))
editor.commands.setPageSetup(null)
```

Takes a `PageSetup`, or `null` for pageless, as the type `PageLayoutSetup`. Nothing is saved in the document.

Returns `false` when the editor shows pages and the document stores its own paper. Call `setSectionSetup(0, setup)` then. `setPageSetup(null)` always works.

### setSectionSetup()

`setSectionSetup()` sets the setup of one section and saves it in the document. This turns the section at the cursor landscape:

```js
const engine = editor.storage.pageLayout.engine
const index = engine.getActiveSectionIndex()
const current = engine.getSections()[index].setup

editor.commands.setSectionSetup(index, { ...current, orientation: 'landscape' })
```

Takes `sectionIndex`, an index of `engine.getSections()`, and `setup`, the whole `PageSetup`, so spread the current one to keep its colors, columns and notes. The section keeps its headers and footers.

Returns `false` while pageless and for an index with no section. It also returns `false` with [`sectionBreak: false`](/page-layout/features/breaks#switching-them-off), which turns sections and section breaks off.
