## Quick start

The colors are the `theme` of a section's page setup, and the first section, `0`, holds the colors of the whole document. [`setSectionSetup()`](/page-layout/features/page-format#setsectionsetup) sets them:

```js
import { createPageLayoutEditor, PageLayout, pageSetup } from '@tiptap-pro/extension-page-layout'
import StarterKit from '@tiptap/starter-kit'

const editor = createPageLayoutEditor({
  element: document.querySelector('#editor'),
  content: { type: 'doc', content: [{ type: 'paragraph' }] },
  extensions: [StarterKit, PageLayout.configure({ setup: pageSetup('A4') })],
})

const engine = editor.storage.pageLayout.engine

editor.commands.setSectionSetup(0, {
  ...engine.getSetup(),
  theme: { page: '#fdf6e3', text: '#33302a', accent: '#b5341c' },
})
```

A [section](/page-layout/features/sections) is a run of the document with its own page setup. `engine`, the object that lays out the pages, returns the first section's setup from `getSetup()`, so the spread keeps its paper and margins.

`page`, a string like the other two, is the paper of the sheet, the element a page is drawn on. `text` colors text that names no color of its own.

`accent` is for your stylesheet, and nothing uses it until a rule of yours does. Anything finer, such as the color of a heading, belongs in marks and styles.

## One section in colors of its own

Every section after the first follows the colors of the document until it names its own. This example gives the section at the cursor its own accent:

```js
const engine = editor.storage.pageLayout.engine
const index = engine.getActiveSectionIndex()
const section = engine.getSections()[index].setup

editor.commands.setSectionSetup(index, {
  ...section,
  theme: { ...section.theme, accent: '#1f8a52' },
})
```

The section follows the document color by color. A color it shares with the document is not stored in the section, so a later change to the document's color reaches it. A color it names stays its own.

To follow one document color again, pass the document's value for it. To follow all three, pass the document's theme, `engine.getSections()[0].setup.theme`.

`setup.theme` is always complete, so a section that follows the document reports the document's colors. To find the sections with colors of their own, compare each with section `0`:

```js
import { pageThemeEquals } from '@tiptap-pro/extension-page-layout'

const engine = editor.storage.pageLayout.engine
const [document, ...rest] = engine.getSections()
const own = rest.filter((section) => !pageThemeEquals(section.setup.theme, document.setup.theme))
```

## Valid colors

A color is `#rrggbb`, and a three-digit `#rgb` reads as its six-digit form. Any other value is ignored and not drawn, so a document from elsewhere cannot put a string of its own into the page's style.

An invalid color in a stored section falls back to the color it would inherit: the document's, or the default for section `0`.

`normalizePageColor(value)` returns the color Page Layout will use, trimmed and in lowercase, or `null` for a value it ignores, such as one that is not a string.

## How colors are stored

The colors are stored in the document, so they reach collaborators and undo takes them back like any other edit. They never move a page boundary.

A document nobody gave colors uses `DEFAULT_PAGE_THEME`: `page: '#ffffff'`, `text: '#18202f'`, and an `accent` equal to the text. It looks exactly as it would without colors.

## A default for this editor only

A theme in the configured `setup` sets how this editor shows a document that names no colors. It is not written into the document, so other editors and exports do not see it:

```js
import { PageLayout, pageSetup } from '@tiptap-pro/extension-page-layout'

PageLayout.configure({
  setup: pageSetup('A4', { theme: { page: '#fdf6e3' } }),
})
```

`pageSetup()` takes some of the colors and fills the rest from `DEFAULT_PAGE_THEME`. This theme applies only to a document without a setup of its own.

Once `setSectionSetup(0, …)` has written one, a color the document does not name comes from `DEFAULT_PAGE_THEME`, not from this editor. So an editor configured with cream paper shows such a document on white paper, until you set the document's colors with `setSectionSetup(0, …)`.

## Drawing with them

Each sheet carries the colors of its section as CSS custom properties, so a rule that uses them follows the section. Page Layout paints the sheet with `--tt-page-background` and sets its text color from `--tt-page-text`.

`--tt-page-accent` is for your own rules. The sheet has the class `tiptap-page-layout-page`, so this rule gives first-level headings the accent:

```css
.tiptap .tiptap-page-layout-page h1 {
  color: var(--tt-page-accent);
}
```

These colors win over `--tt-page-paper`, the paper color your stylesheet can set for every sheet. Page Layout paints the sheet only with the default `sheetAppearance: 'paper'`, and `'none'` turns that off. See [Styling the pages](/page-layout/guides/styling).

## Word and .docx

A Word document has one page color, so only the colors of section `0` fit in a .docx file. A converter loses the colors of a section of its own.

In .docx, `page` is the document's `w:background`, `background.color` in `docx.js`, as six digits without `#`. `text` is the default run color of the document's styles. `accent` is a theme color such as `accent1`, which needs a theme part in the file.

## Without pages and on paper

Pageless, the view of the document without sheets, draws no colors. They stay in the document and come back with the pages. While pageless, the colors cannot change: `setSectionSetup()` returns `false`, under `can()` too.

The browser prints the paper color only when "Background graphics" is on in its print dialog. A PDF from a headless browser has the paper color when the driver is asked to print backgrounds, or with this stylesheet:

```css
@media print {
  .tiptap .tiptap-page-layout-page {
    print-color-adjust: exact;
  }
}
```

See [A PDF from your own headless browser](/page-layout/features/printing#a-pdf-from-your-own-headless-browser).
