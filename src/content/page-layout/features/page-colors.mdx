## Quick start

Colors are the `theme` of a [section's](/page-layout/features/sections) setup, and section `0` is the
document:

```js
const engine = editor.storage.pageLayout.engine

editor.commands.setSectionSetup(0, {
  ...engine.getSetup(),
  theme: { page: '#fdf6e3', text: '#33302a', accent: '#b5341c' },
})
```

| Field    | Type     | Description                                                       |
| -------- | -------- | ----------------------------------------------------------------- |
| `page`   | `string` | The sheet itself                                                  |
| `text`   | `string` | Text that names no color of its own                               |
| `accent` | `string` | What a template tints. Nothing uses it until your stylesheet does |

Anything finer than these three belongs in Marks and styles.

## How colors are stored

- **In the document.** Colors are saved with it, reach everybody editing it with
  [collaboration](/page-layout/guides/collaboration), and an undo takes them back like any other edit.
- **They never move a page boundary.** A page is the same size in any color, so changing them
  changes nothing about where the text breaks.
- **`DEFAULT_PAGE_THEME`** is white paper (`#ffffff`) and dark text (`#18202f`), with the accent
  the same as the text. A document nobody gave colors looks exactly as it would without them.

## Valid colors

- **Colors are `#rrggbb`.**
- **A three-digit `#rgb`** is read as its six-digit form.
- **Anything else is ignored**, not drawn. A document from somewhere else cannot put an
  arbitrary string into the page's style.
- **`normalizePageColor(value)`** returns the color the engine will use, or `null`.

## A default for this editor only

A theme in the setup `PageLayout` is configured with is how this editor shows a document that
names no colors:

```js
PageLayout.configure({
  setup: pageSetup('A4', { theme: { page: '#fdf6e3' } }),
})
```

- **It is not written into the document.** Another editor opening the same document shows it in
  its own default, and an export does not see it.
- **It applies only to a document with no setup of its own.** Once `setSectionSetup(0, …)` has
  written one, with a format, margins or colors, the document is shown in its own colors.
- **A color that document does not name** is the one in `DEFAULT_PAGE_THEME`, not this
  editor's. White paper an author chose stays white in an editor configured with cream.

## One section in colors of its own

Every later section follows the document's colors until it names its own:

```js
const index = engine.getActiveSectionIndex()
const section = engine.getSections()[index].setup

editor.commands.setSectionSetup(index, {
  ...section,
  theme: { ...section.theme, accent: '#1f8a52' },
})
```

- **Per color.** A color the section shares with the document is not stored in the section.
  A later change to the document's color reaches it.
- **A color the section names** stays its own. The section above keeps following the document's
  paper and text.
- **To follow all three again**, pass the document's theme.

### Reading which sections have their own

`setup.theme` is always complete: a section that follows the document reports the document's
colors. Whether it has its own is a comparison with section `0`:

```js
import { pageThemeEquals } from '@tiptap-pro/extension-page-layout'

const [document, ...rest] = engine.getSections()
const own = rest.filter((section) => !pageThemeEquals(section.setup.theme, document.setup.theme))
```

A section that names exactly the document's colors is stored as following them, so the two
cannot disagree.

## Word and DOCX

A Word document has one page color, for the whole document. Section `0`'s colors are what a
DOCX file can hold:

| Field    | In DOCX                                                                                                         |
| -------- | --------------------------------------------------------------------------------------------------------------- |
| `page`   | The document's background, `w:background`, which is `background.color` in `docx.js`. Six digits without the `#` |
| `text`   | The default run color of the document's styles                                                                  |
| `accent` | A theme color such as `accent1`, which needs a theme part in the file                                           |

A section with colors of its own has no counterpart there. A converter writes the document's
colors and loses the section's. Offer it as a choice the author makes, and say so where they
make it.

## Drawing with them

Each sheet carries its section's colors as custom properties:

| Property               | Description                                                  |
| ---------------------- | ------------------------------------------------------------ |
| `--tt-page-background` | The paper. The engine's stylesheet paints the sheet with it  |
| `--tt-page-text`       | The text color. The engine's stylesheet sets it on the sheet |
| `--tt-page-accent`     | The accent, for your own rules                               |

```css
.tiptap .tiptap-page-layout-page h1 {
  color: var(--tt-page-accent);
}
```

- **The properties are set per sheet**, so a rule like this one follows the section. A heading
  on a page of the green section is green, and the one after the next section break is not.
- **They win over `--tt-page-paper`.** See the
  [CSS reference](/page-layout/reference/css#what-the-engine-publishes) for the other
  properties a page publishes.

## Without pages, and on paper

- **Pageless** has no sheets, so the colors are not drawn there. They stay in the document, and
  are back on the pages when pages are.
- **They cannot be changed while pageless.** `setSectionSetup` returns `false`, also under
  `can()`. See [Page format](/page-layout/features/page-format#setsectionsetup).
- **Printing from the browser** prints the paper color only with _Background graphics_ turned on
  in the print dialog. A stylesheet of yours can ask for it instead, as below.
- **A [PDF from a headless browser](/page-layout/features/printing#a-pdf-from-a-headless-browser)**
  prints the paper color when the driver is asked to print backgrounds, or with the stylesheet
  below.

```css
@media print {
  .tiptap .tiptap-page-layout-page {
    print-color-adjust: exact;
  }
}
```
