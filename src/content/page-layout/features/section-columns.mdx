Use them for a two-column article, a glossary in three columns, or a narrow column of notes beside a wide one.

## Quick start

To put the selected paragraphs in two equal columns, call `setSectionColumns()`. `editor` is an editor from `createPageLayoutEditor`, as in [Page format](/page-layout/features/page-format#quick-start):

```js
editor.commands.setSectionColumns({ count: 2, gaps: null, rule: false, widths: null })
```

A toolbar button works on what the user selected. To select paragraphs from your own code first, find their positions in the document and select them with `revealSourcePosition(from, to)`. This example puts the paragraphs from `One.` to `Three.` in two columns:

```js
const engine = editor.storage.pageLayout.engine
let from = 0
let to = 0

engine.getSourceDocument().descendants((node, pos) => {
  if (node.textContent === 'One.') from = pos + 1
  if (node.textContent === 'Three.') to = pos + node.nodeSize - 1
})

editor.commands.revealSourcePosition(from, to)
editor.commands.setSectionColumns({ count: 2, gaps: null, rule: false, widths: null })
```

The positions come from the document, not from `editor.state`, which holds the pages. See [The document and the pages](/page-layout/getting-started/document-and-pages).

Side-by-side boxes, such as a picture beside its caption, are a different feature: a column layout from the [Columns extension](/editor/extensions/functionality/columns), see [Columns in Page Layout](/page-layout/extension-behavior/columns).

## Setting columns

`setSectionColumns()` gives columns to the blocks the selection covers, so three selected paragraphs are exactly the three in columns. Columns belong to a [section](/page-layout/features/sections), a run of blocks with its own page setup.

To make that section, the command adds continuous section breaks around the selection where needed, so the text does not move to a new page. Only a section that starts at the first block of the document opens with a next-page break.

The selection decides which blocks change:

- **It starts or ends inside a block.** The whole block changes. Nothing is divided.
- **It crosses a section break.** Each section it covers keeps its paper, and only the columns change.
- **Nothing is selected.** The section the cursor is in changes.
- **It already lines up with a section.** No break is added, so a second click is safe.

## The four fields

`setSectionColumns()` takes a `PageColumns` with these fields:

| Field    | Type                 | Description                                                                                |
| -------- | -------------------- | ------------------------------------------------------------------------------------------ |
| `count`  | `number`             | How many columns the text flows through. `1`, the least, is an undivided page.             |
| `gaps`   | `number[]` or `null` | The space after each column but the last, in CSS pixels. `null` while all are the default. |
| `rule`   | `boolean`            | A vertical line in each gap.                                                               |
| `widths` | `number[]` or `null` | Each column's share of the text area. `null` for equal columns.                            |

`widths` takes any ratio, so `[1, 2]` makes the second column twice as wide as the first, in landscape or with wider margins too.

`gaps` has one entry fewer than there are columns, so three columns take two gaps. A gap is a fixed measure, the same on A5 as on A4, and defaults to half an inch (48 px), exported as `DEFAULT_COLUMN_GAP`.

The `rule` line sits inside the gap and takes no width, so it does not move the text.

## Widths without the arithmetic

`NARROW_COLUMN_FIRST` (1:2) and `NARROW_COLUMN_LAST` (2:1) are values for `widths`. `SINGLE_COLUMN` is a whole `PageColumns` with one column, the way back:

```js
import { NARROW_COLUMN_FIRST, SINGLE_COLUMN } from '@tiptap-pro/extension-page-layout'

editor.commands.setSectionColumns({ count: 2, gaps: null, rule: true, widths: NARROW_COLUMN_FIRST })
editor.commands.setSectionColumns(SINGLE_COLUMN)
```

`columnSharesFromWidths()` turns widths in any unit into shares. It returns `null`, equal columns, for an empty list or a number that is not positive and finite, so its result goes into `widths` as it is:

```js
import { columnSharesFromWidths } from '@tiptap-pro/extension-page-layout'

// Two fields in centimeters, from a dialog.
const widths = columnSharesFromWidths([4.5, 11.5])

editor.commands.setSectionColumns({ count: 2, gaps: null, rule: false, widths })
```

## A column break

A column break ends the column at the cursor, and the text continues at the top of the next. Like a page break, it stays where the user put it, see [insertColumnBreak()](/page-layout/features/breaks#insertcolumnbreak).

## Reading what is in force

Read a section's columns with these functions, not from its fields, because `widths` and `gaps` are `null` for the defaults. They may also hold a list from an earlier count, such as three widths after a switch to two columns.

Each function takes a `PageColumns`, except `columnWidths`, which takes a `PageSetup`:

| Function          | Returns                                                                                                                                                |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `columnShares`    | Each column's share, adding up to 1. A list of the wrong length gives equal shares.                                                                    |
| `columnGaps`      | Each gap in pixels. A list of the wrong length gives the defaults, and one column gives `[]`.                                                          |
| `hasEqualGaps`    | Whether all gaps are the same.                                                                                                                         |
| `hasEqualColumns` | Whether all columns are the same width.                                                                                                                |
| `columnWidths`    | Each column's width in pixels: the text area less the gaps, divided by the shares. For `null`, the pageless setup without pages, one column of 816 px. |

This reads the section the cursor is in:

```js
import { columnGaps, columnShares, hasEqualGaps } from '@tiptap-pro/extension-page-layout'

const engine = editor.storage.pageLayout.engine
const { columns } = engine.getSections()[engine.getActiveSectionIndex()].setup

columnShares(columns) // for example [0.3333, 0.6666]
columnGaps(columns) // for example [48]
hasEqualGaps(columns) // whether one gap field can show them
```

## Balanced columns

A continuous section break at the end of a passage in columns gives its columns even lengths, so the passage is as short as possible.

A section that runs to the end of the document, or to a next-page break, fills its first column to the bottom of the page first. To even out the last page, insert the break with the cursor at the end:

```js
editor.commands.insertSectionBreak('continuous')
```

Even lengths are exact for equal columns. Unequal columns can end a line or two longer than they need to, and no text is lost.

## What columns do to the pages

A paragraph too tall for the rest of a column continues at the top of the next one on the same page. A table breaks between rows inside its column, and a row can be divided between two columns.

A page break ends the page, not the column. A footnote goes at the bottom of the page, not of its column.

Every page of the section has its count of columns, so a two-column page whose text ran out halfway shows one filled column and the empty space of the second.

The text stays one sequence in the document, and only how it is shown is divided. So a selection across columns selects the text between its ends, and the clipboard gets one passage. A search over the document finds a phrase broken across two columns.

## What is not supported

Columns in the footnote area are not supported: the notes fill one box across the text area. No handle drags a column edge, so set widths with `setSectionColumns()`.

## Commands

The column command chains and answers `can()`.

### setSectionColumns()

`setSectionColumns()` gives the blocks the selection covers these columns, adding section breaks where the selection does not line up with a section:

```js
editor.commands.setSectionColumns({ count: 3, gaps: null, rule: false, widths: null })
```

Takes a whole `PageColumns`, see [The four fields](/page-layout/features/section-columns#the-four-fields).

Returns `false`, under `can()` too, while [pageless](/page-layout/features/page-format#pageless). It also returns `false` with [`sectionBreak: false`](/page-layout/features/breaks#switching-them-off), which turns sections and section breaks off.
