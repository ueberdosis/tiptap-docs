## Quick start

Install `@tiptap-pro/extension-page-layout` from Tiptap's registry, as
[Installing](/page-layout/getting-started/install#installing) shows. Then build the editor with
`createPageLayoutEditor`:

```js
import { createPageLayoutEditor, PageLayout, pageSetup } from '@tiptap-pro/extension-page-layout'
import StarterKit from '@tiptap/starter-kit'

const editor = createPageLayoutEditor({
  element: document.querySelector('#editor'),
  content: { type: 'doc', content: [{ type: 'paragraph' }] },
  extensions: [StarterKit, PageLayout.configure({ setup: pageSetup('A4') })],
  onUpdate: ({ editor }) => save(editor.getJSON()),
})
```

- **It is a Tiptap `Editor`.** It takes the options of one, such as `onUpdate`,
  `onSelectionUpdate` and `editable`. Commands at the cursor, extensions and events work as they
  do without pages.
- **Editing works as in any Tiptap editor.** The caret, text selection, clipboard, IME composition
  and screen readers behave the same, because the pages are made of the same editable content.
- **Saving works as before.** Save what `getJSON()` or `getHTML()` returns. Neither has a page in
  it. Never save `editor.state.doc`: it holds the pages the reader sees. See
  [Saving the document](/page-layout/getting-started/install#saving-the-document).
- **Nothing of the pages is stored.** The document holds no page Nodes, no automatic page breaks
  and no continuation rows. The pages are worked out from it each time it is opened.
- **`update` is emitted once per change to the document**, and not when only the pages are laid
  out again.
- **Undo and redo** are this package's `editor.commands.undo()` and `editor.commands.redo()`. They
  take back the reader's edit, never the pagination that followed it. See
  [Undo and redo](/page-layout/getting-started/install#undo-and-redo).
- **Positions and collaboration change.** Anything that works with a position in the document
  changes, and collaboration is set up through `PageLayout`. See
  [An editor you already have](/page-layout/getting-started/install#an-editor-you-already-have).

## What you get

- **Paper, margins and orientation.** 21 built-in sizes and any size of your own. See
  [Page format](/page-layout/core-concepts/page-format).
- **Sections.** Their own paper for a run of blocks, such as a landscape table in an upright
  report. See [Sections](/page-layout/core-concepts/sections).
- **Page colors.** The paper, the text and an accent, for the document or one section. See
  [Page colors](/page-layout/core-concepts/page-colors).
- **Headers and footers** per section, on every page, with a different first page and different odd
  and even pages if you want them. See [Header and footer](/page-layout/core-concepts/header-and-footer).
- **Page numbers.** How each section numbers its pages, and a number in a header or footer. See
  [Page numbers](/page-layout/core-concepts/page-numbers).
- **Tables across pages.** A row cut at the boundary and continued on the next page, a repeated
  header row, and per-row control over whether a row may be cut. See
  [Tables across pages](/page-layout/extensions/tables).
- **Footnotes and endnotes.** A note's text at the foot of the page its reference is on,
  renumbered as the text moves. See [Footnotes on pages](/page-layout/extensions/footnotes/on-pages).
- **Section columns.** Text that fills one column to the bottom of the page and carries on at the
  top of the next, with gaps, widths and a line between. See
  [Section columns](/page-layout/core-concepts/section-columns).
- **Manual breaks.** Page, column and section breaks at the cursor. See [Breaks](/page-layout/core-concepts/breaks).
- **Pageless.** The same document as one continuous column, switchable at runtime. See
  [Pageless](/page-layout/core-concepts/page-format#pageless).
- **Zoom.** At a factor or fitted to the window, without the pagination changing. See
  [Zoom](/page-layout/core-concepts/zoom).
- **Printing** from the browser's print dialog, with the sheets the reader saw. See
  [Printing and PDF](/page-layout/guides/printing-and-pdf).
- **Collaboration.** Only the document is shared. Two people can see different page counts of the
  same text, and each sees the other's cursor where it lands in their own pages. See
  [Collaboration](/page-layout/guides/collaboration).

## Commands

Every Command of Page Layout, and of the packages that go with it, works as any Tiptap Command:

- **It chains**, also with Commands of your own: `editor.chain().focus().insertPageBreak().run()`.
- **It answers `can()`** without changing anything: `editor.can().insertPageBreak()` asks whether
  a page may end here.
- **It returns `true`** when it did something.
- **It returns `false` and changes nothing** when it cannot act. It does not throw.

A Command returns `false` in three cases:

- **The cursor is in the wrong place.** `setRepeatHeaderRow` needs a table, `setListKeepTogether` a
  list. A Command's own page says where it needs the cursor.
- **The document says no.** A page break cannot go inside a code block. Section `0` cannot be
  removed, because it is the document's own paper.
- **The feature is switched off.** See [Switching features off](/page-layout/getting-started/overview#switching-features-off).

That is what a toolbar needs: a button disabled by `can()` is disabled exactly where its Command
would do nothing, and stays correct in an editor that offers fewer features. See
[A toolbar and a status bar](/page-layout/getting-started/toolbar). Every Command is listed in
[Commands](/page-layout/api/commands).

## Common tasks

`engine` is `editor.storage.pageLayout.engine`.

| Task                                         | Call                                                                              | Page                                                                                      |
| -------------------------------------------- | --------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| A landscape table in an upright report       | `insertSectionBreak('nextPage')`, then `setSectionSetup` on the new section       | [Sections](/page-layout/core-concepts/sections)                                           |
| Narrower margins                             | `setSectionSetup(0, …)` with `margins` from `MARGIN_PRESETS`                      | [Margins](/page-layout/core-concepts/page-format#margins)                                 |
| A different header on the first page         | `setFurnitureFlags(0, { differentFirstPage: true, differentOddEven: false })`     | [Header and footer](/page-layout/core-concepts/header-and-footer)                         |
| A chapter on a fresh sheet                   | `insertPageBreak()`                                                               | [Breaks](/page-layout/core-concepts/breaks)                                               |
| A table row that is not cut in half          | `setRowBreakAcrossPages(false)`                                                   | [Tables across pages](/page-layout/extensions/tables)                                     |
| A header row on every page                   | `setRepeatHeaderRow(true)`                                                        | [Tables across pages](/page-layout/extensions/tables)                                     |
| Two columns for a few paragraphs             | `setSectionColumns({ count: 2, gaps: null, rule: true, widths: null })`           | [Section columns](/page-layout/core-concepts/section-columns)                             |
| A list that stays on one page                | `setListKeepTogether(true)`                                                       | [Keeping a list on one page](/page-layout/extensions/overview#keeping-a-list-on-one-page) |
| A Node of yours that is not cut in half      | `defineNodeLayout('card', { splitDepth: 'betweenChildren', keepTogether: true })` | [Keeping a Node whole](/page-layout/guides/custom-nodes#keeping-a-node-whole)             |
| A footnote at the foot of its page           | `insertFootnote()`, or `insertFootnote({ placement: 'endnote' })`                 | [Footnotes on pages](/page-layout/extensions/footnotes/on-pages)                          |
| The page the cursor is on                    | `pageAt(engine.getPageMap(), engine.getSourceState().selection.from)`             | [Page numbers](/page-layout/core-concepts/page-numbers)                                   |
| A jump to a heading from a table of contents | `revealSourcePosition(pos)`                                                       | [Going to a position](/page-layout/core-concepts/page-numbers#going-to-a-position)        |
| Print what the reader sees                   | `window.print()`                                                                  | [Printing and PDF](/page-layout/guides/printing-and-pdf#quick-start)                      |
| One endless column                           | `setPageSetup(null)`                                                              | [Pageless](/page-layout/core-concepts/page-format#pageless)                               |
| Pages fitted to the window                   | `engine.setZoom('fit')`                                                           | [Zoom](/page-layout/core-concepts/zoom)                                                   |
| Two people editing one document              | The `source` option, with `createSourceCollaboration`                             | [Collaboration](/page-layout/guides/collaboration)                                        |

## Switching features off

Every feature that adds to the document can be switched off:

```js
PageLayout.configure({
  setup: pageSetup('A4'),
  sectionBreak: false, // no section breaks
  columnBreak: false,
  pageBreak: false,
  pageFurniture: false, // no headers and footers
  tablePagination: false, // no per-row and per-table settings
  listPagination: false, // no keep-together on a list
})
```

- **Its Commands stay.** A feature that brings a Node, such as `pageBreak` or `pageFurniture`,
  leaves its Commands in place, and they return `false`, under `can()` too.
- **Its Node leaves the schema.** JSON holding one no longer loads:
  `editor.commands.setContent()` with a `pageBreak` in it fails with
  `Unknown node type: pageBreak`.
- **Switch a feature off** only in editors whose documents never had it, or strip its Nodes from
  the content first.

Every switch is in [Options](/page-layout/api/options#features).
