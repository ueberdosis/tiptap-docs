## Installing

React needs one more package, `@tiptap-pro/extension-page-layout-react`, with the hook
`usePageLayoutEditor`:

```bash
npm install @tiptap-pro/extension-page-layout-react @tiptap-pro/extension-page-layout @tiptap/react
```

Both Pro packages come from [the Pro registry](/page-layout/getting-started/install#the-pro-registry), and the engine needs
[its peer dependencies](/page-layout/getting-started/install#peer-dependencies).
The hook's package has these:

| Peer dependency                     | Version                |
| ----------------------------------- | ---------------------- |
| `@tiptap-pro/extension-page-layout` | the same release       |
| `@tiptap/core`                      | `^3.29.2`              |
| `@tiptap/react`                     | `^3.29.2`              |
| `react`                             | `^18.0.0 \|\| ^19.0.0` |

## A first editor

`usePageLayoutEditor` builds an editor on pages and destroys it when the component that shows it
unmounts. It takes the place of `useEditor` and `EditorContent`, which build an editor of their
own and cannot draw pages.

Replace `useEditor` with `usePageLayoutEditor`, put `ref` on an element, and render `nodeViews`:

```jsx
// Before
import { EditorContent, useEditor } from '@tiptap/react'
import StarterKit from '@tiptap/starter-kit'

function MyEditor({ content, onSave }) {
  const editor = useEditor({
    content,
    extensions: [StarterKit],
    onUpdate: ({ editor }) => onSave(editor.getJSON()),
  })

  return <EditorContent editor={editor} />
}
```

```jsx
// After
import { PageLayout, pageSetup } from '@tiptap-pro/extension-page-layout'
import { usePageLayoutEditor } from '@tiptap-pro/extension-page-layout-react'
import StarterKit from '@tiptap/starter-kit'

function MyEditor({ content, onSave }) {
  const { editor, ref, nodeViews } = usePageLayoutEditor({
    content,
    extensions: [StarterKit, PageLayout.configure({ setup: pageSetup('A4') })],
    onUpdate: ({ editor }) => onSave(editor.getJSON()),
  })

  return (
    <>
      {editor && <Toolbar editor={editor} />}
      <div ref={ref} />
      {nodeViews}
    </>
  )
}
```

`Toolbar` is your own component. See [A toolbar](/page-layout/reference/commands#a-toolbar). What the hook returns
is in [The hook](/page-layout/getting-started/install/react#the-hook).

Go on with [Page format](/page-layout/features/page-format) for the paper and the margins, and
[Styling the pages](/page-layout/guides/styling) for how the sheets look.

## The hook

`usePageLayoutEditor(options, deps)` takes the options of `createPageLayoutEditor` without
`element`, and an optional list of dependencies. See [Options of the editor](/page-layout/getting-started/install#options-of-the-editor).
It returns:

| Field       | Type                       | Description                                                                                                                                           |
| ----------- | -------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ref`       | `RefCallback<HTMLElement>` | Goes on the element the pages are drawn into                                                                                                          |
| `editor`    | `Editor \| null`           | The editor, or `null` until that element is mounted                                                                                                   |
| `nodeViews` | `ReactElement`             | The components of the editor's React NodeViews. Render it once, anywhere in the component. See [React NodeViews](/page-layout/guides/react-nodeviews) |

The package also exports the types `UsePageLayoutEditorOptions` and `UsePageLayoutEditorResult`.

- **Building.** The editor is built once the element is mounted, and destroyed when it is
  unmounted. It is drawn into an element of its own inside the one `ref` is on.
- **Rebuilding.** `content` and `extensions` are read when the editor is built. A change to them
  rebuilds it only when a value in the dependency list changes, as with `useEditor`.
- **Callbacks** are always those of the latest render, so `onUpdate` sees current props.
- **`editable`** is applied without rebuilding the editor.
- **Under `StrictMode`**, the editor built by the first of the two mounts is destroyed, and one
  editor remains.
- **A toolbar** that re-renders on the editor's `transaction` event, as `useEditorState` from
  `@tiptap/react` does, stays current.
