## Install

Install the hook's own package with Page Layout and the example's packages from [the Pro registry](/page-layout/getting-started/install#the-pro-registry):

```bash
npm install @tiptap-pro/extension-page-layout-react @tiptap-pro/extension-page-layout @tiptap/react @tiptap/core @tiptap/pm @tiptap/starter-kit
```

This covers every required package except React, with Page Layout's [peer dependencies](/page-layout/getting-started/install#what-you-need). The hook needs `@tiptap-pro/extension-page-layout` of the same release, `@tiptap/core` and `@tiptap/react` at `^3.29.2`, and `react` at `^18.0.0 || ^19.0.0`.

## A first editor

Here, `onSave` stands for your function that stores the document, and `Toolbar` for your own component:

```jsx
import { PageLayout, pageSetup } from '@tiptap-pro/extension-page-layout'
import { usePageLayoutEditor } from '@tiptap-pro/extension-page-layout-react'
import StarterKit from '@tiptap/starter-kit'

function MyEditor({ content, onSave }) {
  const { editor, ref, nodeViews } = usePageLayoutEditor({
    content,
    extensions: [StarterKit, PageLayout.configure({ setup: pageSetup('A4') })],
    onUpdate: ({ editor }) => onSave(editor.getJSON()),
  })

  return (
    <>
      {editor && <Toolbar editor={editor} />}
      <div ref={ref} />
      {nodeViews}
    </>
  )
}
```

When it works, the document shows on A4 pages. To move a component from `useEditor`, replace `useEditor` with `usePageLayoutEditor`, put `ref` on an element, and render `nodeViews`.

## The hook

`usePageLayoutEditor(options, deps)` takes the [options of `createPageLayoutEditor`](/page-layout/getting-started/install#options-of-the-editor) without `element`, and an optional dependency list `deps`, `[]` by default. Its types are `UsePageLayoutEditorOptions` and `UsePageLayoutEditorResult`. It returns:

| Field       | Type                       | Description                                                                                                                                              |
| ----------- | -------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ref`       | `RefCallback<HTMLElement>` | A React ref for the element the pages are drawn into.                                                                                                    |
| `editor`    | `Editor \| null`           | `null` until that element is mounted.                                                                                                                    |
| `nodeViews` | `ReactElement`             | The components of your [React NodeViews](/page-layout/extension-behavior/your-own-extension/react-nodeviews). Render it once, anywhere in the component. |

The hook builds the editor in an element of its own inside the `ref` element when that mounts. It destroys the editor with that element. As with `useEditor`, `content` and `extensions` are read once, so to rebuild with changed ones, list a changing value in `deps`.

Callbacks such as `onUpdate` see the current props. A change of `editable` needs no rebuild and emits no `update`. Under `StrictMode`, one editor remains.

A toolbar stays current when it re-renders on the editor's `transaction` event, as `useEditorState` from `@tiptap/react` does. See [A toolbar](/page-layout/reference/commands#a-toolbar).

## A React NodeView is drawn empty

A node with a React NodeView is drawn empty when nothing renders `nodeViews`, as [A first editor](/page-layout/getting-started/install/react#a-first-editor) does. The console then says:

```text
[extension-page-layout-react] A React NodeView was built, and nothing renders the nodeViews usePageLayoutEditor returned; the Node is drawn empty. Render {nodeViews} in the component that holds the editor.
```
