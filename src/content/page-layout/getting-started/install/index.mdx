## Install

1. [Contact our team](https://tiptap.dev/contact-sales?form=pilot-program) to join the Tiptap Page Layout pilot program.
2. Configure your package manager for Tiptap's private registry, as [The Pro registry](/page-layout/getting-started/install#the-pro-registry) shows.
3. Install Page Layout with its peer dependencies and the content extensions of the example:

```bash
npm install @tiptap-pro/extension-page-layout @tiptap/core @tiptap/pm @tiptap/starter-kit
```

Page Layout brings no content types of its own. Paragraphs, headings, lists and tables come from the extensions you register, such as `@tiptap/starter-kit`.

## The Pro registry

The Page Layout packages come from Tiptap's private registry, not from npm's. Your account can install them once you are in the pilot program. The [private registry guide](https://tiptap.dev/docs/guides/pro-extensions) explains the setup. In short, add these lines to the `.npmrc` file in the project's root:

```ini
@tiptap-pro:registry=https://registry.tiptap.dev/
//registry.tiptap.dev/:_authToken=${TIPTAP_PRO_TOKEN}
```

`TIPTAP_PRO_TOKEN` is an environment variable that holds your registry token. Set it in your shell and on your CI, and never commit the token itself. You find the token in your Tiptap account.

## A first editor

`createPageLayoutEditor` builds a Tiptap editor that shows its document on pages. `element` is the element the pages are drawn into, and `setup` is the paper:

```js
import { createPageLayoutEditor, PageLayout, pageSetup } from '@tiptap-pro/extension-page-layout'
import StarterKit from '@tiptap/starter-kit'

const editor = createPageLayoutEditor({
  element: document.querySelector('#editor'),
  content: { type: 'doc', content: [{ type: 'paragraph' }] },
  extensions: [StarterKit, PageLayout.configure({ setup: pageSetup('A4') })],
})
```

When it works, you see one empty A4 sheet. Text you type past its bottom margin continues on a second sheet.

You need no stylesheet for this, because Page Layout adds the styles of the sheets itself. The space around the sheets is yours to style, and the window scrolls the pages unless an element closer to them scrolls. See [Styling the pages](/page-layout/guides/styling).

Without a `setup`, the editor is pageless, where the document is one continuous column without pages. `createPageLayoutEditor` adds `PageLayout` to the extensions when they do not hold it, so you pass `PageLayout.configure()` only to set the paper or another [option](/page-layout/reference/options).

Leave out `yjs` and `y-prosemirror` until you set up [collaboration](/page-layout/guides/collaboration). Only the `@tiptap-pro/extension-page-layout/collaboration` entry loads them, and the main package works without them.

## Options of the editor

`createPageLayoutEditor` returns a Tiptap `Editor`, and takes the options of `new Editor` with the differences in this table. The engine named in it is the object that lays out the pages, at `editor.storage.pageLayout.engine`:

| Option                                                                | Default          | Description                                                                                                                                                                    |
| --------------------------------------------------------------------- | ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `element`, `content`, `extensions`                                    | Required         | `content` is Tiptap JSON.                                                                                                                                                      |
| `editable`, `autofocus`                                               | As on any editor | As on any editor.                                                                                                                                                              |
| `injectCSS`, `injectNonce`                                            | As on any editor | They apply to the layout rules of the sheets too, not to the paper sizes for printing. See [A Content Security Policy](/page-layout/guides/styling#a-content-security-policy). |
| `onBeforeCreate`, `onCreate`, `onDestroy`                             | None             | In `onBeforeCreate`, `editor.storage.pageLayout.engine` is still `null`.                                                                                                       |
| `onUpdate`, `onSelectionUpdate`, `onTransaction`, `onFocus`, `onBlur` | None             | `update` fires only when the document changes. See [When you hear about a change](/page-layout/getting-started/document-and-pages#when-you-hear-about-a-change).               |
| `onChange`                                                            | None             | Called with the editor once the pages are in the DOM after a change, also after a change of the pages alone. Use it for a page counter.                                        |
| `editorProps`                                                         | Not accepted     | See [Building the editor](/page-layout/getting-started/install/existing-editor#building-the-editor).                                                                           |

Use `onUpdate` to save the document, and `onChange` for anything that shows the pages. `onChange` also runs when only the cursor moves, so a page counter follows the cursor.

It runs, too, when a [long document](/page-layout/guides/long-documents) draws other pages in full. And it runs when pages [fitted to the window](/page-layout/features/zoom) get a new scale after a resize. For these last two, it runs at most once per JavaScript task.

When the editor is destroyed, Page Layout sets `editor.storage.pageLayout.engine` back to `null`. Everything about the pages themselves is an option of `PageLayout`, listed in [Options](/page-layout/reference/options).

## The packages

Page Layout comes in two packages, both from the private registry:

| Package                                   | What it holds                                                                                                                       |
| ----------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| `@tiptap-pro/extension-page-layout`       | The engine: pages, sections, breaks, headers and footers, and how tables and lists behave at the end of a page.                     |
| `@tiptap-pro/extension-page-layout-react` | `usePageLayoutEditor`, the editor on pages as a React hook. See [Page Layout in React](/page-layout/getting-started/install/react). |

Footnotes, cross-references and the other extensions Page Layout supports are packages of their own, each installed and documented on its own page. What Page Layout does with them is on [Extension behavior](/page-layout/extension-behavior).

A PDF of the pages made on a server comes from Tiptap's Conversion service, see [A PDF from a server](/page-layout/features/printing#a-pdf-from-a-server).
