## The Pro registry

Every package of Page Layout comes from Tiptap's registry rather than from npm's. Point the project
at it once:

```ini
; .npmrc
@tiptap-pro:registry=https://registry.tiptap.dev/
//registry.tiptap.dev/:_authToken=${TIPTAP_PRO_TOKEN}
```

- **Keep the token in the environment.** Set `TIPTAP_PRO_TOKEN` in your shell and on CI. Never
  commit it.
- **Your token** is in your Tiptap account. See
  [Pro extensions](https://tiptap.dev/docs/guides/pro-extensions).

## Installing

```bash
npm install @tiptap-pro/extension-page-layout @tiptap/core @tiptap/pm yjs y-prosemirror
```

The engine brings no content types of its own. Paragraphs, headings, lists and tables are the
Extensions you already register, such as `@tiptap/starter-kit`.

### Peer dependencies

| Package         | Version    |
| --------------- | ---------- |
| `@tiptap/core`  | `^3.29.2`  |
| `@tiptap/pm`    | `^3.29.2`  |
| `yjs`           | `^13.6.31` |
| `y-prosemirror` | `^1.3.7`   |

- **Install all four.** `yjs` and `y-prosemirror` are marked optional, so no package manager
  installs them for you.
- **They are needed without collaboration too.** The package imports them when it loads.
- **`@tiptap-pro/extension-number-formats`** is a dependency, and is installed with it.

### For React

React needs one more package, `@tiptap-pro/extension-page-layout-react`, with the hook
`usePageLayoutEditor`:

```bash
npm install @tiptap-pro/extension-page-layout-react @tiptap-pro/extension-page-layout @tiptap/react
```

Both Pro packages come from the registry above, and the engine needs the peer dependencies above.
The hook's package has these:

| Peer dependency                     | Version                |
| ----------------------------------- | ---------------------- |
| `@tiptap-pro/extension-page-layout` | the same release       |
| `@tiptap/core`                      | `^3.29.2`              |
| `@tiptap/react`                     | `^3.29.2`              |
| `react`                             | `^18.0.0 \|\| ^19.0.0` |

## A first editor

### In JavaScript

```js
import { createPageLayoutEditor, PageLayout, pageSetup } from '@tiptap-pro/extension-page-layout'
import StarterKit from '@tiptap/starter-kit'

const editor = createPageLayoutEditor({
  element: document.querySelector('#editor'),
  content: { type: 'doc', content: [{ type: 'paragraph' }] },
  extensions: [StarterKit, PageLayout.configure({ setup: pageSetup('A4') })],
})
```

That is an editor on A4 pages.

### In React

`usePageLayoutEditor` builds an editor on pages and destroys it when the component that shows it
unmounts. It takes the place of `useEditor` and `EditorContent`, which build an editor of their
own and cannot draw pages.

Replace `useEditor` with `usePageLayoutEditor`, put `ref` on an element, and render `nodeViews`:

```jsx
// Before
import { EditorContent, useEditor } from '@tiptap/react'
import StarterKit from '@tiptap/starter-kit'

function MyEditor({ content, onSave }) {
  const editor = useEditor({
    content,
    extensions: [StarterKit],
    onUpdate: ({ editor }) => onSave(editor.getJSON()),
  })

  return <EditorContent editor={editor} />
}
```

```jsx
// After
import { PageLayout, pageSetup } from '@tiptap-pro/extension-page-layout'
import { usePageLayoutEditor } from '@tiptap-pro/extension-page-layout-react'
import StarterKit from '@tiptap/starter-kit'

function MyEditor({ content, onSave }) {
  const { editor, ref, nodeViews } = usePageLayoutEditor({
    content,
    extensions: [StarterKit, PageLayout.configure({ setup: pageSetup('A4') })],
    onUpdate: ({ editor }) => onSave(editor.getJSON()),
  })

  return (
    <>
      {editor && <Toolbar editor={editor} />}
      <div ref={ref} />
      {nodeViews}
    </>
  )
}
```

`Toolbar` is your own component. See [A toolbar](/page-layout/reference/commands#a-toolbar). What the hook returns
is in [The React hook](/page-layout/getting-started/install#the-react-hook).

Go on with [Page format](/page-layout/features/page-format) for the paper and the margins, and
[Styling the pages](/page-layout/guides/styling) for how the sheets look.

## Options of the editor

`createPageLayoutEditor` returns a Tiptap `Editor`. It takes these options, and they mean what they
mean on `new Editor` unless the table says otherwise:

| Option                                                                | Description                                                                                                                                                          |
| --------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `element`, `content`, `extensions`                                    | Required. `content` is Tiptap JSON                                                                                                                                   |
| `editable`, `autofocus`                                               | As on any editor                                                                                                                                                     |
| `injectCSS`, `injectNonce`                                            | As on any editor, and for the page rules too. See [A Content Security Policy](/page-layout/guides/styling#a-content-security-policy)                                 |
| `onBeforeCreate`, `onCreate`, `onDestroy`                             | As on any editor                                                                                                                                                     |
| `onUpdate`, `onSelectionUpdate`, `onTransaction`, `onFocus`, `onBlur` | `update` is emitted only when the document changes. See [When you hear about a change](/page-layout/getting-started/document-and-pages#when-you-hear-about-a-change) |
| `onChange`                                                            | Called with the editor after every change once the pages are drawn, including a change of the pages alone                                                            |

`editorProps` is not accepted. What a Tiptap editor built with `new Editor` does with `PageLayout` is
in [Building the editor](/page-layout/getting-started/existing-editor#building-the-editor). Everything about the pages is an option of
`PageLayout`; see [Options](/page-layout/reference/options).

## The React hook

`usePageLayoutEditor(options, deps)` takes the options of `createPageLayoutEditor` without
`element`, and an optional list of dependencies. See [Options of the editor](/page-layout/getting-started/install#options-of-the-editor).
It returns:

| Field       | Type                       | Description                                                                                                                                           |
| ----------- | -------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ref`       | `RefCallback<HTMLElement>` | Goes on the element the pages are drawn into                                                                                                          |
| `editor`    | `Editor \| null`           | The editor, or `null` until that element is mounted                                                                                                   |
| `nodeViews` | `ReactElement`             | The components of the editor's React NodeViews. Render it once, anywhere in the component. See [React NodeViews](/page-layout/guides/react-nodeviews) |

The package also exports the types `UsePageLayoutEditorOptions` and `UsePageLayoutEditorResult`.

- **Building.** The editor is built once the element is mounted, and destroyed when it is
  unmounted. It is drawn into an element of its own inside the one `ref` is on.
- **Rebuilding.** `content` and `extensions` are read when the editor is built. A change to them
  rebuilds it only when a value in the dependency list changes, as with `useEditor`.
- **Callbacks** are always those of the latest render, so `onUpdate` sees current props.
- **`editable`** is applied without rebuilding the editor.
- **Under `StrictMode`**, the editor built by the first of the two mounts is destroyed, and one
  editor remains.
- **A toolbar** that re-renders on the editor's `transaction` event, as `useEditorState` from
  `@tiptap/react` does, stays current.

## The packages

| Package                                   | What it is                                                                                                                            |
| ----------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| `@tiptap-pro/extension-page-layout`       | The engine: pages, sections, breaks, headers and footers, and how tables and lists behave at a page boundary                          |
| `@tiptap-pro/extension-page-layout-react` | `usePageLayoutEditor`, the editor on pages as a React hook. See [The React hook](/page-layout/getting-started/install#the-react-hook) |

- **Both are Pro**, and come from the registry above.
- **Footnotes, Cross-references and the other extensions Page Layout supports are packages of
  their own**, each installed and documented on its own page. What Page Layout does with them is in
  [Supported extensions](/page-layout/supported-extensions).
- **A PDF of the pages made on a server** comes from Tiptap's Conversion service. See
  [A PDF from a server](/page-layout/features/printing#a-pdf-from-a-server).
