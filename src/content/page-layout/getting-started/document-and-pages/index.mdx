## What is stored and what is drawn

The document is the only thing Page Layout stores: the JSON you load into `createPageLayoutEditor` and save. Page Layout draws the pages from it again after every change, and each time the document opens.

So you save what `getJSON()` or `getHTML()` returns, as with any Tiptap document. The stored document has no page nodes, no automatic page breaks and no parts of a table row cut off at the end of a page. `getText()` and `onUpdate` answer for the document too.

`editor.state` holds the pages, so do not save `editor.state.doc`. See [Saving the document](/page-layout/getting-started/install/existing-editor#saving-the-document). To make `editor.state` hold the document instead, see [editor.state as the document](/page-layout/getting-started/document-and-pages/writing#editorstate-as-the-document).

The pages are made of ordinary editable content. So typing, selecting, the clipboard, IME composition (the input of Chinese, Japanese and Korean text) and screen readers work as in any Tiptap editor. In a [long document](/page-layout/guides/long-documents#what-only-sees-the-drawn-sheets), a screen reader reaches only the pages near the one in view.

## Where to read

A position read from `editor.state` is a position in the pages, not in the document. Your code reads the document through the engine, the object at `editor.storage.pageLayout.engine` that lays out the pages:

```js
const engine = editor.storage.pageLayout.engine

engine.getSourceDocument() // the document's node
engine.getSourceState() // its state, with the selection in the document
```

A position you keep, such as a comment anchor, is a position in the document. To find its page or its place on the screen, see [Reading the pages](/page-layout/getting-started/document-and-pages/reading).

## Where to write

Code that changes the document, such as a table menu or a NodeView (the code that renders a node), writes to the document, not to the pages. The commands of Tiptap extensions, your own included, already do that. For anything else:

- **A function `(state, dispatch) => boolean`**, the shape a ProseMirror command has: pass it to `editor.commands.onSourceDocument(command)`.
- **A transaction of your own**: build it on `engine.getSourceState()` and pass it to `engine.dispatchSourceTransaction(tr)`.

A transaction built on `editor.state` holds positions in the pages, so `dispatchSourceTransaction` throws for it. See [Writing to the document](/page-layout/getting-started/document-and-pages/writing).

## Undo and redo

`editor.commands.undo()` and `editor.commands.redo()` are Page Layout's own commands, and Page Layout takes the history of StarterKit out of the editor for you. They undo a change to the document. They never undo the new page layout that followed it. See [Undo and redo](/page-layout/getting-started/install/existing-editor#undo-and-redo).

## Collaboration

Only the document is shared, never the pages. You pass the shared document to the `source` option of `PageLayout`, not to Tiptap's Collaboration extension. `createPageLayoutEditor` throws an error when the extensions hold that extension. See [Collaboration](/page-layout/guides/collaboration).

## editorProps

`createPageLayoutEditor` does not accept `editorProps`, because Page Layout handles the editor's transactions itself. See [Building the editor](/page-layout/getting-started/install/existing-editor#building-the-editor).

## When you hear about a change

The `update` event and `onUpdate` come once for every change to the document, also a collaborator's. They do not come when only the pages change, such as after a resize, a zoom or a font load.

A transaction marked with `tr.setMeta('preventUpdate', true)` emits no `update` either, such as that of `setContent(content, { emitUpdate: false })`.

`selectionUpdate` is emitted before `update` when the selection moves in the document. Both pass a transaction on the document, so its positions are positions in `getJSON()`.

Both events wait until the pages of the change are drawn, so a page number read in them belongs to that change. In a long document, the number can still change for a few seconds, see [Right after opening or pasting](/page-layout/guides/long-documents#right-after-opening-or-pasting).

`transaction` is emitted for every change of the editor's state, also when the pages are drawn again. It can come first, so a page number read there may be the old one. `beforeTransaction`, `focus`, `blur`, `create` and `destroy` work as on any editor.

To read the pages after every change, use the `onChange` option of `createPageLayoutEditor`, as [Where the cursor is](/page-layout/getting-started/document-and-pages/reading#where-the-cursor-is) shows. It also runs after a change of the pages alone, and when only the cursor moves.
