## Swapping the packages

Pages 1 is an Extension in an ordinary editor:

```js
import { Editor } from '@tiptap/core'
import StarterKit from '@tiptap/starter-kit'
import { Pages } from '@tiptap-pro/extension-pages'
import { TableKit } from '@tiptap-pro/extension-pages-tablekit'
// and PageBreak from @tiptap-pro/extension-pagebreak

const editor = new Editor({
  element: document.querySelector('#editor'),
  extensions: [StarterKit, TableKit, PageBreak, Pages.configure({ pageFormat: 'A4' })],
})
```

Page Layout builds the editor with `createPageLayoutEditor`. Page breaks are part of it, and tables
come from the open source table extension:

```js
import StarterKit from '@tiptap/starter-kit'
import { TableKit } from '@tiptap/extension-table'
import { createPageLayoutEditor, PageLayout, pageSetup } from '@tiptap-pro/extension-page-layout'

const editor = createPageLayoutEditor({
  element: document.querySelector('#editor'),
  content: { type: 'doc', content: [{ type: 'paragraph' }] },
  extensions: [StarterKit, TableKit, PageLayout.configure({ setup: pageSetup('A4') })],
})
```

- **Uninstall** `@tiptap-pro/extension-pages`, `@tiptap-pro/extension-pagebreak`,
  `@tiptap-pro/extension-pages-tablekit` and `@tiptap-pro/extension-pages-pagekit`.
- **Install** `@tiptap-pro/extension-page-layout` and its peer dependencies. See
  [Install Page Layout](/page-layout/getting-started/install).
- **`PageKit` has no replacement.** `PageLayout` does what it bundled.
- **In React**, use `usePageLayoutEditor` instead of `useEditor`. See
  [Page Layout in React](/page-layout/getting-started/react).
- **`PageLayout` in an editor built with `new Editor`** draws no pages, and its Commands return
  `false`.
- **Save what `getJSON()` returns**, and read positions through the engine rather than
  `editor.state`. See [An editor you already have](/page-layout/getting-started/existing-editor).

## Page format

Pages 1 took a format name or an object, and a Command changed it:

```js
Pages.configure({ pageFormat: 'Letter' })

editor.commands.setPageFormat({
  id: 'wide',
  width: 1056,
  height: 816,
  margins: { top: 96, right: 96, bottom: 96, left: 96 },
})
```

In Page Layout, `pageSetup` builds the paper, with the orientation and the margins in it.
`pageFormat` defines a size of your own:

```js
import { pageFormat, pageSetup } from '@tiptap-pro/extension-page-layout'

PageLayout.configure({ setup: pageSetup('Letter') })

const wide = pageFormat({ id: 'wide', width: 1056, height: 816 })

editor.commands.setPageSetup(
  pageSetup(wide, { margins: { top: 96, right: 96, bottom: 96, left: 96 } }),
)
```

The built-in formats of Pages 1 had margins: `A4` had 2.5 cm at the top and bottom and 2 cm at the
sides. The built-in formats of Page Layout have none, so a setup falls back to 1 in on every side.
To keep the old margins, pass them:

```js
import { cmToPixels, pageSetup } from '@tiptap-pro/extension-page-layout'

pageSetup('A4', {
  margins: {
    top: cmToPixels(2.5),
    right: cmToPixels(2),
    bottom: cmToPixels(2.5),
    left: cmToPixels(2),
  },
})
```

- **`setPageSetup` is not saved** with the document. `setSectionSetup` saves a setup in it. See
  [Page format](/page-layout/features/page-format).
- **`pageGap` is gone.** The space between sheets is the CSS custom property `--tt-page-sheet-gap`.
- **`pageGapBackground` is gone.** Style the element that holds the pages. See
  [Styling the pages](/page-layout/features/styling).

## Header and footer

Pages 1 took the content as an option, or set it with a Command:

```js
Pages.configure({
  header: 'Company report',
  footer: 'Page {page} of {total}',
  differentFirstPage: true,
  headerFirstPage: '',
  headerTopMargin: 48,
})

editor.commands.setFooter('Confidential')
```

Page Layout has no option for the content:

- **A header and a footer are content in the document**, one set per section.
- **The reader double-clicks a band** to edit it. Your code opens one with `openFurniture`.
- **A page number is a field**, not a `{page}` token.

```js
editor.commands.openFurniture({ zone: 'footer', reveal: true })
editor
  .chain()
  .insertContent('Page ')
  .insertPageNumber('page')
  .insertContent(' of ')
  .insertPageNumber('pages')
  .run()
editor.commands.closeFurniture()
```

A different first page, different odd and even pages and the distance from the edge are settings
of a section:

```js
editor.commands.setFurnitureFlags(0, { differentFirstPage: true, differentOddEven: false })
editor.commands.setFurnitureOffsets(0, { header: 48, footer: 48 })
```

The `placeholders` option is gone, and so is the overlay that opened for editing. See
[Header and footer](/page-layout/features/header-and-footer) and [Page numbers](/page-layout/features/page-numbers).

## Page breaks

Pages 1 had a `pageBreak` block Node from `@tiptap-pro/extension-pagebreak`. Page Layout's Command
has the same name, `insertPageBreak()`, but the Node has changed:

- **It is inline**, inside a paragraph, where the reader put it. It can sit between two words.
- **`Mod-Enter`** inserts it.
- **Column and section breaks** are new.

```js
editor.commands.insertPageBreak()
editor.commands.insertColumnBreak()
editor.commands.insertSectionBreak('nextPage')
```

See [Breaks](/page-layout/features/breaks). For documents saved with the block Node, see
[Saved documents](/page-layout/getting-started/migrate-from-pages-1#saved-documents).

## Footnotes and endnotes

In Pages 1, notes were options of `Pages`, with a Command for each kind:

```js
Pages.configure({
  footnotes: { enabled: true },
  endnotes: { enabled: true },
})

editor.commands.insertFootnote()
editor.commands.insertEndnote()
```

In Page Layout, notes come from `@tiptap-pro/extension-footnotes`. A note is a footnote or an
endnote by its placement:

```js
import { Footnotes, mountFootnoteStyles } from '@tiptap-pro/extension-footnotes'

mountFootnoteStyles(document)

const editor = createPageLayoutEditor({
  element,
  content,
  extensions: [
    StarterKit,
    Footnotes.configure({ defaultPlacement: 'footnote' }),
    PageLayout.configure({ setup: pageSetup('A4') }),
  ],
})

editor.commands.insertFootnote()
editor.commands.insertFootnote({ placement: 'endnote' })
```

- **Without `defaultPlacement`**, `insertFootnote()` inserts an endnote.
- **Without `mountFootnoteStyles`**, no note numbers are drawn.
- **Numbering is a setting of each section**, and footnotes can restart on every page.
- **`footnotes.enabled`, `footnotes.initialContent` and `setFootnotes` are gone.** The text of a
  note is part of the document.

See [Footnotes on pages](/page-layout/other-extensions/footnotes).

## Zoom

Pages 1 had an option and a Command:

```js
Pages.configure({ zoom: 0.75 })

editor.commands.setZoom(1.5)
```

Page Layout has an engine method instead, because zoom changes nothing in the document. There is no
option, so call it once the editor is built:

```js
const engine = editor.storage.pageLayout.engine

engine.setZoom(0.75)
engine.setZoom('fit')
```

`'fit'` keeps the pages fitted to the width as the window changes. `engine.getZoom()` and
`engine.getScale()` read it back. See [Zoom](/page-layout/features/zoom).

## Tables

Pages 1 needed its own table kit:

```js
import { TableKit } from '@tiptap-pro/extension-pages-tablekit'

const kit = TableKit.configure({ experimentalRowFragmentation: true })
```

Page Layout uses `@tiptap/extension-table` as it is, and a row breaks across pages by default. Two
settings of the table and its rows replace the experiment:

```js
editor.commands.setRowBreakAcrossPages(false)
editor.commands.setRepeatHeaderRow(true)
```

The Commands of the table extension keep working. See
[Tables across pages](/page-layout/other-extensions/tables).

## Collaboration

Pages 1 used the `Collaboration` extension, and gave each header and footer editor a field of its
own in the shared document:

```js
const extensions = [
  StarterKit,
  Collaboration.configure({ document: ydoc }),
  Pages.configure({
    headerFooterExtensions: (ctx) => [
      StarterKit,
      Collaboration.configure({ document: ctx.ydoc, field: ctx.field }),
    ],
  }),
]
```

Page Layout takes no collaboration extension, and `createPageLayoutEditor` throws if it is given
one. The shared document goes through the `source` option:

```js
import { createSourceCollaboration } from '@tiptap-pro/extension-page-layout'

const collaboration = createSourceCollaboration({
  document: ydoc,
  awareness: provider.awareness,
  user: { name: 'Ada', color: '#e11d48' },
})

PageLayout.configure({ setup: pageSetup('A4'), source: collaboration })
```

- **`headerFooterExtensions` has no use.** Headers, footers and notes are in the shared content.
- **One field is shared**, `default` unless `field` says otherwise.
- **Content Pages 1 kept in other fields is not read.** Write headers and footers into the document
  as [Header and footer](/page-layout/getting-started/migrate-from-pages-1#header-and-footer) shows. There is no helper for the notes.

See [Collaboration](/page-layout/guides/collaboration).

## Saved documents

Pages 1 wrote three Nodes of its own into the JSON of `getJSON()`:

- `pageBreak`, as a block.
- `footnoteReference`, with a `noteId` attribute.
- `endnoteReference`, with a `noteId` attribute.

Headers, footers and the text of every note were not in it. They sat in `editor.storage.pages`,
and the app saved them beside the document. The page format and the zoom were options.

Page Layout stores all of it in the document:

- **`pageBreak`** is inline, inside a paragraph.
- **`footnoteReference`** has a `footnoteId` attribute, and reads no `noteId`.
- **There is no `endnoteReference`.** An endnote is a `footnoteReference` whose note has the
  `endnote` placement.
- **The text of a note** is a `footnote` Node in a `footnoteCollection`.
- **There is one `footnoteCollection` per placement and numbering scope**, at the end of its
  scope. A scope ends only where a section starts the note numbering again, so a document whose
  sections count on has one per placement, at its end.
- **Headers and footers** are inside the section break of their section.

An old document does not load as it is. The editor throws `Unknown node type: endnoteReference`
when it is built. Convert the saved JSON before loading it:

- A block `pageBreak` becomes an inline `pageBreak` inside a paragraph.
- `noteId` becomes `footnoteId`.
- `endnoteReference` becomes `footnoteReference`, and its note gets `placement: 'endnote'`.
- The saved text of each note becomes a `footnote` Node in a `footnoteCollection`.
- Headers and footers are written into the document with the Commands in
  [Header and footer](/page-layout/getting-started/migrate-from-pages-1#header-and-footer).

There is no helper for this. Test every kind of saved document you have before you ship. Tables
keep the standard table Nodes; check a few for their column widths and cell attributes.

## Word files

Import and export of .docx are separate packages, with migration guides of their own. What Page

## What has no replacement

These options of Pages 1 have no counterpart in [Options](/page-layout/reference/options):

- **The overlay editors** and their options: `accentColor`, `headerAccentColor`,
  `footerAccentColor`, `toolbarGradient`, `overlayLabels`, `renderOverlayActions` and the
  `onDblClick*PreventClose` callbacks. Headers and footers are edited in place.
- **`placeholders`**, because a page number is a field.
- **`headerFooterExtensions` and `headerFooterParseOptions`.** A header uses the extensions of the
  editor.
- **`editableHeader` and `editableFooter`.** No option locks a header. `furnitureClicks: false`
  only stops the double-click from opening one.
- **`onPageFormatChange` and `onZoomChange`.** Read the setup and the zoom from the engine when
  you need them.
- **`PageKit`.**

## Limitations

These matter most coming from Pages 1:

- **No widow and orphan control**, and a heading has no keep-with-next rule of its own by default.
- **The note area has no columns**, and a single note cannot have a mark of its own.
- **Safari prints every sheet on the paper of the first page.**

See [Limitations](/page-layout/reference/limitations) for all of them.
