Most editors set the paper with `setup` and, under a toolbar, the room it covers with `scrollMargin`:

```js
import { createPageLayoutEditor, PageLayout, pageSetup } from '@tiptap-pro/extension-page-layout'
import StarterKit from '@tiptap/starter-kit'

const editor = createPageLayoutEditor({
  element: document.querySelector('#editor'),
  content: { type: 'doc', content: [{ type: 'paragraph' }] },
  extensions: [
    StarterKit,
    PageLayout.configure({ setup: pageSetup('A4'), scrollMargin: { top: 64 } }),
  ],
})
```

`PageLayout` works only in an editor that `createPageLayoutEditor` builds. In a plain `new Editor` with an element, it warns on the console, draws no pages, and its commands do nothing.

The options of `createPageLayoutEditor` itself, such as `element`, are in [Options of the editor](/page-layout/getting-started/install#options-of-the-editor). The Page Layout types on this page, such as `PageSetup` and `ScrollMargin`, are exported from `@tiptap-pro/extension-page-layout`.

## The page

These options set the paper and how blocks meet the end of a page:

| Option            | Type                                      | Default                                 | Description                                                                                                                   |
| ----------------- | ----------------------------------------- | --------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| `setup`           | `PageSetup` or `null` (`PageLayoutSetup`) | None, so pageless: one column, no pages | The setup a document starts on, see [Page format](/page-layout/features/page-format). A document that saved its own keeps it. |
| `sections`        | `readonly PageSection[]`                  | None                                    | Section breaks written into the document when the editor is created.                                                          |
| `chapterNumberOf` | `ChapterNumberOf`                         | `chapterNumbersFromHeadings()`          | The chapter number in front of a page number.                                                                                 |
| `blockBreaksOf`   | `BlockBreaksOf`                           | None                                    | How a block meets a page boundary, beyond the rule of its node type.                                                          |

Pass `setup` whole, as `pageSetup()` builds it, because `configure` merges deeply, so a partial `margins` keeps the other sides configured before.

### sections

`sections` writes section breaks into the document when the editor is created, if `setup` is not `null`. A section is a run of blocks with its own page setup, see [Sections](/page-layout/features/sections). Each entry is a `PageSection`:

| Field             | Type                         | Default      | Description                                               |
| ----------------- | ---------------------------- | ------------ | --------------------------------------------------------- |
| `startBlockIndex` | `number`                     | Required     | The section's first top-level block.                      |
| `setup`           | `PageSetup`                  | Required     | The section's page setup.                                 |
| `kind`            | `'nextPage' \| 'continuous'` | `'nextPage'` | Whether the section starts on a new page or the same one. |

### chapterNumberOf

`chapterNumberOf` is a function that returns the chapter number in front of a page number, such as the 2 in 2-1, as a string, or `null` for none. Left out, Page Layout counts the headings with `chapterNumbersFromHeadings()`.

`chapterNumbersFromHeadings({ label })` uses the numbers your headings carry. [Chapter numbers](/page-layout/features/page-numbers/chapter-numbers) shows both, the fields of a function of your own, and when `setPageNumbering()` with a `chapter` returns `false`.

### blockBreaksOf

`blockBreaksOf` is a function `(block, doc) => BlockBreaks | null` that sets `keepWithNext`, `keepTogether` or `pageBreakBefore` for one block, such as a paragraph with a `keepWithNext` attribute. It can only add to the rule of the block's node type, never switch it off.

Only top-level blocks are asked, so a paragraph in a list item breaks as the list does. [Deciding per block](/page-layout/extension-behavior/your-own-extension/when-no-rule-fits#deciding-per-block) has an example and the rules.

## Features

Each feature is on by default. `false` switches it off and removes its node or attributes from the schema:

| Option              | Type    | Default | Description                                         |
| ------------------- | ------- | ------- | --------------------------------------------------- |
| `pageBreak`         | `false` | On      | Page breaks inserted by hand.                       |
| `columnBreak`       | `false` | On      | Column breaks inserted by hand.                     |
| `sectionBreak`      | `false` | On      | Sections and section breaks.                        |
| `pageFurniture`     | `false` | On      | Headers and footers.                                |
| `pageNumber`        | `false` | On      | The page number a header or footer can hold.        |
| `tablePagination`   | `false` | On      | `breakAcrossPages` and `repeatHeaderRow` on tables. |
| `columnsPagination` | `false` | On      | `keepTogether` on a column layout.                  |
| `listPagination`    | `false` | On      | `keepTogether` on a list.                           |

### Switching features off

Switch a feature off only where documents never had it, or remove its nodes first. Its node leaves the schema, so content with a `pageBreak` in it is invalid, and `createPageLayoutEditor` throws `Unknown node type: pageBreak` for it.

The feature's commands stay and return `false`, under `can()` too. `pageFurniture: false` also switches the header and footer [clicks](/page-layout/reference/options#clicks) off.

This editor has pages, but no breaks, headers or footers, and no page options on tables and lists:

```js
import { PageLayout, pageSetup } from '@tiptap-pro/extension-page-layout'

PageLayout.configure({
  setup: pageSetup('A4'),
  sectionBreak: false,
  columnBreak: false,
  pageBreak: false,
  pageFurniture: false,
  tablePagination: false,
  listPagination: false,
})
```

## Drawing

These options decide what Page Layout draws:

| Option               | Type                                          | Default                   | Description                                                                                                                                                                                 |
| -------------------- | --------------------------------------------- | ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `sheetAppearance`    | `'paper' \| 'none'`                           | `'paper'`                 | Whether the white paper, shadow and gap are painted. See [Turning it off](/page-layout/guides/styling#turning-it-off).                                                                      |
| `breaksWithoutPages` | `'lines' \| 'none'`                           | `'lines'`                 | How breaks show in a pageless document, with `setup: null`. `'none'` draws nothing. See [Breaks](/page-layout/features/breaks).                                                             |
| `breakLabels`        | `Partial<BreakLabels>`                        | Word's English names      | The labels beside those lines, see [Labels in another language](/page-layout/features/breaks#labels-in-another-language).                                                                   |
| `scrollMargin`       | `ScrollMargin`, `{ top?, bottom? }` in pixels | `{ top: 48, bottom: 48 }` | The room above and below the caret when Page Layout scrolls it into view. A side left out keeps `48`. See [A toolbar over the pages](/page-layout/guides/styling#a-toolbar-over-the-pages). |
| `virtualization`     | `boolean`                                     | `true`                    | Draws only the pages near the user's view. `false` draws all, all the time. Printing draws all either way. See [Long documents](/page-layout/guides/long-documents).                        |
| `layoutHint`         | `LayoutHintStore`                             | None                      | Saved measurements, so a long document opens laid out instead of on estimates. See [Opening on the same pages](/page-layout/guides/long-documents#opening-on-the-same-pages).               |

## Clicks

`furnitureClicks` controls Word's clicks for a header or footer: double-click one to edit it, and double-click the text or press Escape to go back:

| Option            | Type    | Default                               | Description                                                         |
| ----------------- | ------- | ------------------------------------- | ------------------------------------------------------------------- |
| `furnitureClicks` | `false` | On, unless `pageFurniture` is `false` | `false` turns the clicks off, for an interface with its own way in. |

`openFurniture()` and `closeFurniture()` work either way. See [Header and footer](/page-layout/features/header-and-footer).

## The document

You need these options only for collaboration, or to learn when a command's edit on the pages could not be copied to the document. For collaboration, set `source` to what `createSourceCollaboration()` returns, see [Setting it up](/page-layout/guides/collaboration#setting-it-up):

| Option                    | Type                               | Default                             | Description                                                                                                                                                                       |
| ------------------------- | ---------------------------------- | ----------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `source`                  | `SourceDocumentOptions`            | A local history                     | The plugins, history and remote cursors of the document.                                                                                                                          |
| `onCommandOnPages`        | `(report: CommandOnPages) => void` | A console warning, once per command | Called when a command's edit on the pages could not be copied to the document.                                                                                                    |
| `experimentalSourceState` | `boolean`                          | `false`                             | `editor.state` holds the document rather than the pages. See [editor.state as the document](/page-layout/getting-started/document-and-pages/writing#editorstate-as-the-document). |

The document is what you save and what `getJSON()` returns. The editor shows the pages, a copy of the document cut into pages. So `editor.state` holds the pages, not the document, see [The document and the pages](/page-layout/getting-started/document-and-pages).

The code calls the document the source document, which is why the option is named `source`.

### source

`source` sets up the document's plugins and history. `SourceDocumentOptions` has these fields, each optional. `createSourceCollaboration()` fills them, the last three included, so you do not write those yourself:

| Field                 | Type                       | Description                                                                                      |
| --------------------- | -------------------------- | ------------------------------------------------------------------------------------------------ |
| `plugins`             | `readonly Plugin[]`        | ProseMirror plugins of the document. Those your extensions bring are added without listing them. |
| `undo`, `redo`        | `Command`                  | The undo and redo commands, the local history's when left out.                                   |
| `keepsLocalSelection` | `(transaction) => boolean` | Whether an incoming transaction keeps the local selection.                                       |
| `bookmarkSelection`   | `BookmarkSourceSelection`  | Keeps the selection in an open header or footer across a colleague's change.                     |
| `carets`              | `RemoteCaretChannel`       | The cursors of the other people.                                                                 |

### onCommandOnPages

Most commands run on the document. A view command is one an extension marks to run on the pages instead, see [View commands](/page-layout/extension-behavior/your-own-extension/when-no-rule-fits#view-commands). When a view command's edit on the pages cannot be copied to the document as it was written, `onCommandOnPages` gets a report:

```js
import { PageLayout } from '@tiptap-pro/extension-page-layout'

PageLayout.configure({
  onCommandOnPages: (report) => console.info(report),
})
```

`command` is the command's name, `extension` the extension that brought it, and `reason` why the edit could not be copied.

`refused` is `true` when Page Layout dropped the edit, and `false` when it worked the edit out again from the change on the pages, which the warning calls "recomputed".

A function that does nothing silences the warning. Without the option, the editor warns once per command:

```text
[page-layout] The command "<command>" of the Extension "<extension>" wrote to the pages what could not be carried back to the document as written (<reason>); the edit was refused. It is named a view command, so it runs on the pages: take it out of viewCommands, or run it with editor.commands.onSourceDocument().
```

To fix the cause, see [Running a command on the document](/page-layout/getting-started/document-and-pages/writing#running-a-command-on-the-document).
