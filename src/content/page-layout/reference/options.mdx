```js
PageLayout.configure({
  setup: pageSetup('A4'),
  scrollMargin: { top: 64 },
})
```

Pass a whole setup. `configure` merges what it is given into the options, so a partial `margins`
keeps the values it leaves out from before. `pageSetup` builds a whole one; see
[Page format](/page-layout/features/page-format#what-a-setup-holds).

The options of `createPageLayoutEditor` itself, such as `element` and `content`, are in
[Options of the editor](/page-layout/getting-started/install#options-of-the-editor).

## The page

| Option            | Type                     | Default                        | Description                                                                                                                                                                                                                                            |
| ----------------- | ------------------------ | ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `setup`           | `PageSetup \| null`      | None: no pages                 | The paper, margins and colors a new document starts on. A document that stores its own paper keeps it. See [Page format](/page-layout/features/page-format)                                                                                            |
| `sections`        | `readonly PageSection[]` | None                           | Section breaks written into the document when the editor is created: the block from which another setup applies, and that setup. See [Sections](/page-layout/features/sections)                                                                        |
| `chapterNumberOf` | `ChapterNumberOf`        | `chapterNumbersFromHeadings()` | The chapter a page number is written with, as in 2-1, 2-2. See [Chapter numbers](/page-layout/features/page-numbers/chapter-numbers)                                                                                                                   |
| `blockBreaksOf`   | `BlockBreaksOf`          | None: only the Node type rules | Per top-level block: keep it with the next one, keep it together, start a page in front of it, as a paragraph style says in Word. See [Deciding per block](/page-layout/paginating-extensions/your-own-extension/when-no-rule-fits#deciding-per-block) |

### A section

Each entry of `sections` is a `PageSection`:

| Field             | Type                         | Default      | Description                                                                                                |
| ----------------- | ---------------------------- | ------------ | ---------------------------------------------------------------------------------------------------------- |
| `startBlockIndex` | `number`                     | Required     | The first top-level block of the section. See [Sections](/page-layout/features/sections) for how it counts |
| `setup`           | `PageSetup`                  | Required     | The paper of the section                                                                                   |
| `kind`            | `'nextPage' \| 'continuous'` | `'nextPage'` | Whether the section starts on a new sheet or below the one before it                                       |

`sections` is written into the document only when `setup` is not `null`.

### The chapter of a page number

`ChapterNumberOf` is a function from one argument to the chapter's number as a string, or `null`:

| Field   | Type              | Description                                                  |
| ------- | ----------------- | ------------------------------------------------------------ |
| `doc`   | `ProseMirrorNode` | The document                                                 |
| `from`  | `number`          | Where the sheet's text begins, as a position in the document |
| `to`    | `number`          | Where it ends. Equal to `from` on a sheet with no text       |
| `level` | `number`          | The heading level a chapter begins with, 1 to 9              |

`chapterNumbersFromHeadings({ label })` builds one that writes the number your headings carry. See
[Chapter numbers](/page-layout/features/page-numbers/chapter-numbers).

### How a block meets a page boundary

`BlockBreaksOf` is `(block, doc) => BlockBreaks | null`, asked for every top-level block:

| Field             | Type      | Description                                    |
| ----------------- | --------- | ---------------------------------------------- |
| `keepWithNext`    | `boolean` | Keep the block on the page of the one after it |
| `keepTogether`    | `boolean` | Move the block to the next page whole          |
| `pageBreakBefore` | `boolean` | Start a page in front of the block             |

- **`null`, or a field left out,** leaves the block to its Node type's rule.
- **Only top-level blocks are asked.** A paragraph inside a list item breaks as the list does.
- **It is asked again for every layout**, so it has to be quick, and answer the same for the same
  block in the same document.

## Features

Each feature is on by default. `false` switches it off and takes its Node or attributes out of the
schema; see [Switching features off](/page-layout/reference/options#switching-features-off).

| Option              | Type    | Default | Description                                                                                                                             |
| ------------------- | ------- | ------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| `pageBreak`         | `false` | On      | Manual page breaks. See [Breaks](/page-layout/features/breaks)                                                                          |
| `columnBreak`       | `false` | On      | Manual column breaks. See [Breaks](/page-layout/features/breaks)                                                                        |
| `sectionBreak`      | `false` | On      | Section breaks. See [Breaks](/page-layout/features/breaks)                                                                              |
| `pageFurniture`     | `false` | On      | Headers and footers. See [Header and footer](/page-layout/features/header-and-footer)                                                   |
| `pageNumber`        | `false` | On      | The page number a header or footer can hold. See [Page numbers](/page-layout/features/page-numbers)                                     |
| `tablePagination`   | `false` | On      | Whether a row may break across pages, and a repeated header row. See [Tables in Page Layout](/page-layout/paginating-extensions/tables) |
| `columnsPagination` | `false` | On      | Keeping a column layout on one page. See [Columns in Page Layout](/page-layout/paginating-extensions/columns)                           |
| `listPagination`    | `false` | On      | Keeping a list on one page. See [Keeping a list on one page](/page-layout/paginating-extensions#keeping-a-list-on-one-page)             |

### Switching features off

Switch off what an editor should not offer:

```js
PageLayout.configure({
  setup: pageSetup('A4'),
  sectionBreak: false, // no section breaks
  columnBreak: false,
  pageBreak: false,
  pageFurniture: false, // no headers and footers
  tablePagination: false, // no per-row and per-table settings
  listPagination: false, // no keep-together on a list
})
```

- **Its Commands stay.** A feature that brings a Node, such as `pageBreak` or `pageFurniture`,
  leaves its Commands in place, and they return `false`, under `can()` too.
- **Its Node leaves the schema.** JSON holding one no longer loads:
  `editor.commands.setContent()` with a `pageBreak` in it fails with
  `Unknown node type: pageBreak`.
- **Switch a feature off** only in editors whose documents never had it, or strip its Nodes from
  the content first.
- **`pageFurniture: false`** also switches `furnitureClicks` off.

## Drawing

| Option               | Type                   | Default                   | Description                                                                                                                                                                                                   |
| -------------------- | ---------------------- | ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `sheetAppearance`    | `'paper' \| 'none'`    | `'paper'`                 | Whether the engine draws the paper. `'none'` leaves the appearance to your own CSS. See [Styling the pages](/page-layout/guides/styling)                                                                      |
| `breaksWithoutPages` | `'lines' \| 'none'`    | `'lines'`                 | Whether a break is drawn in an editor without pages. `'none'` draws nothing. See [Breaks without pages](/page-layout/features/breaks#breaks-without-pages)                                                    |
| `breakLabels`        | `Partial<BreakLabels>` | Word's names, in English  | What each break is called beside its line, for a document in another language. See [Breaks](/page-layout/features/breaks)                                                                                     |
| `scrollMargin`       | `ScrollMargin`         | `{ top: 48, bottom: 48 }` | Room in pixels left at the edges of the viewport whenever something is scrolled into view, for a toolbar over the pages. See [A toolbar over the pages](/page-layout/guides/styling#a-toolbar-over-the-pages) |
| `virtualization`     | `boolean`              | `true`                    | Whether only the sheets near the reader are drawn. See [Long documents](/page-layout/guides/long-documents)                                                                                                   |
| `layoutHint`         | `LayoutHintStore`      | None                      | Where what was measured last time is kept, so a long document opens on its pages. See [Opening on the same pages](/page-layout/guides/long-documents#opening-on-the-same-pages)                               |

### Break labels

`breakLabels` takes any of four keys. Name only the labels you change:

| Key              | Default                           |
| ---------------- | --------------------------------- |
| `page`           | `Page break`                      |
| `region`         | `Column break`                    |
| `section`        | `Section break`                   |
| `sectionColumns` | `Section break · {count} columns` |

`{count}` stands for the number of columns, anywhere in the string. `DEFAULT_BREAK_LABELS` holds
the defaults. See [Breaks](/page-layout/features/breaks).

### The scroll margin

`ScrollMargin` is `{ top?, bottom? }`, in pixels. A side left out keeps its default of 48. Set
`top` higher when a toolbar covers the top of the viewport, since the engine cannot see it.

### Virtualization

`virtualization: false` draws every sheet all the time. Printing draws every sheet either way.

### The layout hint

A `LayoutHintStore` has two methods:

| Method | Takes                             | Returns                       | Description                             |
| ------ | --------------------------------- | ----------------------------- | --------------------------------------- |
| `load` | `key: string`                     | `Promise<LayoutHint \| null>` | The hint saved under the key, or `null` |
| `save` | `key: string`, `hint: LayoutHint` | `void`                        | Keeps a hint under the key              |

- **Without a store**, a long document opens on estimates, and its pages move while the text is
  measured.
- **With one**, the engine asks for the hint when the document opens. It saves a new one after
  measuring, once the document has been still for a second.
- **A hint is a first guess.** Every block is still measured, and a hint for another document,
  paper or font is ignored.
- **The document never holds it.**

See [Opening on the same pages](/page-layout/guides/long-documents#opening-on-the-same-pages).

## Clicks

| Option            | Type    | Default                               | Description                                                                                                                                                                                                   |
| ----------------- | ------- | ------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `furnitureClicks` | `false` | On, unless `pageFurniture` is `false` | Double-click a header or footer to edit it, and the text or Escape to go back. `false` leaves the way in to your own UI. See [Getting in and out](/page-layout/features/header-and-footer#getting-in-and-out) |

`openFurniture` and `closeFurniture` work with or without it.

## The document

| Option                    | Type                               | Default                            | Description                                                                                                                                                                                                                                                                     |
| ------------------------- | ---------------------------------- | ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `source`                  | `SourceDocumentOptions`            | A local history                    | Collaboration, history and plugins for the document. See [Collaboration](/page-layout/guides/collaboration)                                                                                                                                                                     |
| `onCommandOnPages`        | `(report: CommandOnPages) => void` | A console warning once per command | Told when a command of an extension wrote something to the pages that could not be carried back to the document. See [A view command that writes to the pages](/page-layout/paginating-extensions/your-own-extension/when-no-rule-fits#a-view-command-that-writes-to-the-pages) |
| `experimentalSourceState` | `boolean`                          | `false`                            | Experimental. `editor.state` holds the document rather than the pages. See [editor.state as the document](/page-layout/getting-started/document-and-pages/writing#editorstate-as-the-document)                                                                                  |

### The source of the document

`SourceDocumentOptions` holds the plugins and the history of the document. Collaboration replaces
both through it; see [Collaboration](/page-layout/guides/collaboration).

| Field                 | Type                       | Description                                                                                       |
| --------------------- | -------------------------- | ------------------------------------------------------------------------------------------------- |
| `plugins`             | `readonly Plugin[]`        | Plugins of the document. Those an Extension brings are added without being listed here            |
| `undo`, `redo`        | `Command`                  | The Commands `undo` and `redo` run. The local history's when left out                             |
| `keepsLocalSelection` | `(transaction) => boolean` | Whether a change from outside the editor view keeps the local Selection. Set by collaboration     |
| `bookmarkSelection`   | `BookmarkSourceSelection`  | Keeps the Selection in an open header or footer across a change from a peer. Set by collaboration |
| `carets`              | `RemoteCaretChannel`       | Where the other people in the document are. Set by collaboration                                  |

### A command on the pages

`onCommandOnPages` receives a `CommandOnPages`:

| Field       | Type      | Description                                                           |
| ----------- | --------- | --------------------------------------------------------------------- |
| `command`   | `string`  | The name of the command                                               |
| `extension` | `string`  | The name of the Extension that brought it                             |
| `reason`    | `string`  | Why it could not be carried back as it was written                    |
| `refused`   | `boolean` | `true` when nothing was written, `false` when the edit was recomputed |

Pass a function that does nothing to silence the console warning. See
[Commands of your own Extension](/page-layout/paginating-extensions/your-own-extension/when-no-rule-fits#commands-of-your-own-extension).
