## Quick start

Lists come from StarterKit or `@tiptap/extension-list`, added as in any Tiptap editor. With the cursor in a list, `setListKeepTogether(true)` keeps it on one page:

```js
import { createPageLayoutEditor, PageLayout, pageSetup } from '@tiptap-pro/extension-page-layout'
import StarterKit from '@tiptap/starter-kit'

const editor = createPageLayoutEditor({
  element: document.querySelector('#editor'),
  content: { type: 'doc', content: [{ type: 'paragraph' }] },
  extensions: [StarterKit, PageLayout.configure({ setup: pageSetup('A4') })],
})

editor.commands.setListKeepTogether(true)
```

Your list configuration stays as it is, and list commands, such as `sinkListItem`, work as before, also in a list a page cuts.

## At the bottom of a page

By default, a page ends between two items, or between two paragraphs of one item, and not inside a paragraph. A paragraph the page would cut moves to the next page whole. Only a paragraph taller than a page is cut.

A line break made with `Shift+Enter` stays inside its paragraph, so a page does not end there. To let a page cut a paragraph, use `setListBreakItems(true)`.

The document keeps one list, so an ordered list goes on counting: item eight follows item seven on the next page. A nested list breaks where its outermost list breaks.

The part of an item that goes on at the top of the next page draws no bullet or number. To mark it another way, such as "10. (continued)", write a rule in your stylesheet with the selector that [Styling the pages](/page-layout/guides/styling) gives for it.

With `list-style-position: inside`, the first line of that part is longer by the missing marker's width, so allow for it in your styles.

## Keeping a list on one page

`setListKeepTogether(true)` moves the list at the cursor to the next page whole instead of cutting it.

`setListBreakItems(true)` lets a page cut a paragraph of an item between two lines, instead of moving it on whole. That suits long items, where moving a whole item on can leave much of a page empty:

```js
editor.commands.setListKeepTogether(true)
editor.commands.setListBreakItems(true)
```

The two settings are independent: a list kept together can still have items cut where it is finally broken. In a nested item, both commands set the outermost list.

## The list at the cursor

`editor.storage.pageLayout.engine.getListContext()` returns `null` outside a list. In a list, it returns `{ list, listPosition, keepTogether, breakItemsAcrossPages, itemCount }`: the outermost list around the cursor, where it starts in the document, the two settings, and how many items it has. With one item, neither setting makes a difference.

## A list taller than a page

A list kept together that does not fit on a page of its own is cut anyway, between its items, starting on the page it was moved to. See [Keep together is a preference](/page-layout/extension-behavior#keep-together-is-a-preference). To tell the user, ask `isDividedInView`:

```js
const engine = editor.storage.pageLayout.engine
const context = engine.getListContext()

if (context?.keepTogether) {
  const { listPosition, list } = context
  const cutAnyway = engine.isDividedInView(listPosition, listPosition + list.nodeSize)
  // If cutAnyway is true, tell the user
}
```

## What is stored

Both settings are attributes of the list node, so a copied list keeps them. `keepTogether` is written as `data-tt-keep-together="true"` and `breakItemsAcrossPages` as `data-tt-break-items="true"`. Both are `false` by default and written only when on. `PageLayout.configure({ listPagination: false })` removes both.

A .docx has no list element, so both are written per paragraph. `keepTogether` becomes Word's "Keep with next" on every paragraph but the last. `breakItemsAcrossPages: false` becomes "Keep lines together". See [Word documents](/page-layout/guides/word#lists).

## Commands

Both commands also return `false` in an editor without a Page Layout engine, such as one made with `new Editor`, so `editor.can()` tells a toolbar when to enable its switches.

### setListKeepTogether()

Keeps the list at the cursor on one page, or lets it break again.

```js
editor.commands.setListKeepTogether(true)
```

Takes one argument, `kept` (`boolean`). Returns `false` outside a list.

### setListBreakItems()

Lets a page cut a paragraph of an item in the list at the cursor, or keeps each paragraph whole again.

```js
editor.commands.setListBreakItems(true)
```

Takes one argument, `allowed` (`boolean`). Returns `false` outside a list.

The engine has the same methods. To make these changes without an editor, see [On a server](/page-layout/guides/on-a-server).
