## Quick start

Register `DocumentStyles` next to `PageLayout`, and pass `PageLayout` the option `blockBreaksOf: styleBlockBreaks({ types, libraries })` with the same `types` and `libraries`. Then pages follow what a style says about page breaks. This library holds one style [definition](/editor/extensions/functionality/document-styles/definitions), which keeps a level-one heading with the paragraph after it:

```js
import {
  DocumentStyles,
  styleBlockBreaks,
  styleLibrary,
} from '@tiptap-pro/extension-document-styles'
import { createPageLayoutEditor, PageLayout, pageSetup } from '@tiptap-pro/extension-page-layout'
import StarterKit from '@tiptap/starter-kit'

const types = ['paragraph', 'heading']
const libraries = [
  styleLibrary([
    {
      id: 'heading-1',
      name: 'Heading 1',
      kind: 'paragraph',
      defaultFor: [{ type: 'heading', attrs: { level: 1 } }],
      pagination: { keepWithNext: true },
    },
  ]),
]

const editor = createPageLayoutEditor({
  element: document.querySelector('#editor'),
  content: { type: 'doc', content: [{ type: 'paragraph' }] },
  extensions: [
    StarterKit,
    DocumentStyles.configure({ types, libraries }),
    PageLayout.configure({
      setup: pageSetup('A4'),
      blockBreaksOf: styleBlockBreaks({ types, libraries }),
    }),
  ],
})
```

## Line and page breaks

A style's `pagination` says how its paragraphs meet the end of a page, with these fields:

- **`keepWithNext`** moves the paragraph to the next page with the first line of the paragraph after it.
- **`keepLinesTogether`** keeps the paragraph from being cut between pages.
- **`pageBreakBefore`** makes the paragraph start a page.

A paragraph without a style of its own follows its type's default style.

`styleBlockBreaks` takes `types`, every block when left out, `libraries`, `[]` by default, and `precedence`, `'document'` by default. Pass `precedence` where `DocumentStyles` has one, because it says whether the document's own definition of a style wins over a library's.

A style can add to a node type's rule but not turn it off, see `blockBreaksOf` in [Options](/page-layout/reference/options). Keep with next is a preference, so a run of such blocks longer than a page is cut anyway.

## Text moves with a style

A change to the style definitions, or to the theme with `setDocumentTheme`, lays the pages out again, because both are stored in the document. Making the body style larger lays out the whole document again, as a change of paper width does.

A style library is not part of the document, so changing one lays out nothing until you call `engine.refresh()`. Here `house` is a library from `styleLibrary()`, and `next` its changed definitions:

```js
house.setStyles(next)
editor.storage.pageLayout.engine.refresh()
```

`refresh()` measures every block again, and `refresh({ remeasure: false })` lays out without measuring.

## Reading the styles of the document

Pass the document, `engine.getSourceDocument()`, to the functions that read styles, because `editor.state` holds the pages, where a cut paragraph is two pieces. [Cleaning up](/editor/extensions/functionality/document-styles/cleanup) says what they return:

```js
import { analyzeStyleUsage, discoverStyles } from '@tiptap-pro/extension-document-styles'

const doc = editor.storage.pageLayout.engine.getSourceDocument()
const styles = editor.storage.documentStyles.stylesOf(doc)

analyzeStyleUsage(doc, styles)
discoverStyles(doc)
```

`discoverStyles` finds formatting used often enough to be a style. Each candidate it returns is what the `createStyleFromCandidate` command takes.

## Writing styles

Document styles commands need no setup on pages. They write the document, and a style applied to a cut paragraph applies to both parts. The [options](/editor/extensions/functionality/document-styles#options) `followNextStyle` and `repair` act on the document too.

To write a definition without a command, pass `setStyleDefinitionTransaction(engine.getSourceState().tr, definition)` to `engine.applySourceTransaction`, as [Number formats](/page-layout/extension-behavior#number-formats) shows for its own transaction.

## Table styles across pages

A table style counts a table cut across pages as one table. Odd and even rows (`oddRows`, `evenRows`) go on counting on the next page, and the total row is only on the last page.

A repeated header row is drawn in the style's header row format. A row cut across two pages is one row on both.

A change to a table's look or table style lays the pages out again, because a bold header row can be taller.
