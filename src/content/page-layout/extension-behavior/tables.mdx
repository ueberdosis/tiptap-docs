## Quick start

Add tables from `@tiptap/extension-table` as in any Tiptap editor. Then, with the cursor in a table, `setRepeatHeaderRow(true)` repeats its header row on each page the table continues onto:

```js
import { createPageLayoutEditor, PageLayout, pageSetup } from '@tiptap-pro/extension-page-layout'
import { TableKit } from '@tiptap/extension-table'
import StarterKit from '@tiptap/starter-kit'

const editor = createPageLayoutEditor({
  element: document.querySelector('#editor'),
  content: { type: 'doc', content: [{ type: 'paragraph' }] },
  extensions: [StarterKit, TableKit, PageLayout.configure({ setup: pageSetup('A4') })],
})

editor.commands.setRepeatHeaderRow(true)
```

Table commands, such as `mergeCells`, work as before, also in a row a page cuts. Of your table options, Page Layout changes only `View`, to `null`, so a table node view of your own is not used.

## Repeating the header row

`setRepeatHeaderRow(true)` draws the header rows at the top of every page the table continues onto. Header rows are the first rows made only of header cells, as `toggleHeaderRow` makes them, so two such rows both repeat. A first row that mixes header and body cells repeats nothing.

The repeated rows are drawn, not stored in the document. You cannot edit them, but editing the header row changes them all. Style them by the attribute `data-tt-repeated-header` or the class `tiptap-page-layout-repeated-header`.

Page Layout draws a copy with the same elements as the header row, so it looks the same. A color you give `[data-tt-repeated-header]` makes the copy look different from the row it copies.

They take room on each page, so a table with a tall header fits fewer rows per page. A repeated header row taller than the space left shows only the part that fits.

## Letting a row break, or not

A page may cut a row by default. `setRowBreakAcrossPages(false)` moves the row at the cursor to the next page whole instead, as turning off Word's "Allow row to break across pages" does.

A row that does not fit there either is cut anyway, see [Keep together is a preference](/page-layout/extension-behavior#keep-together-is-a-preference). If Page Layout finds no line to cut it at, it runs off its page until the next edit.

To tell the user that a row was cut anyway, ask [`isDividedInView`](/page-layout/extension-behavior#keep-together-is-a-preference):

```js
const engine = editor.storage.pageLayout.engine
const context = engine.getTableContext()

if (context && !context.breakAcrossPages) {
  const { rowPosition, row } = context
  const cutAnyway = engine.isDividedInView(rowPosition, rowPosition + row.nodeSize)
  // If cutAnyway is true, tell the user
}
```

## The table at the cursor

`engine.getTableContext()` returns `null` outside a table. In a table, it returns `{ table, tablePosition, row, rowPosition, breakAcrossPages, repeatHeaderRow }`: the innermost table around the cursor, the row the cursor is in, where each starts, and the two settings.

The positions are in the document, also in the lower part of a cut row. `getTableContext()` reads the document on each call, so a toolbar stays up to date.

A table menu of your own reads and writes the whole table in the document too, because `editor.state` holds only one page's rows. See [Example: a table menu](/page-layout/getting-started/document-and-pages/writing#example-a-table-menu).

## A row cut in two

When a page cuts a row, both parts keep every cell, so the columns line up. A cell is empty in the part its content does not reach.

Editing works as in an uncut row. An edit in the lower part edits that row. A text or cell selection may start in either part and cross the cut. Copied cells paste as a table into another table or document.

## Dragging a column width

With `TableKit.configure({ table: { resizable: true } })`, users drag column widths. A width changes the column on every page, because it is stored on the table in the document. While a user drags, a table that grows pushes what follows it to the next page.

## What is stored

Where a table breaks is not stored, because Page Layout works it out again each time. Page Layout adds two attributes, which a copied table keeps:

- `breakAcrossPages` on `tableRow`, `true` by default, in HTML `data-tt-break-across-pages="false"` only when off.
- `repeatHeaderRow` on `table`, `false` by default, in HTML `data-tt-repeat-header-row="true"` only when on.

`PageLayout.configure({ tablePagination: false })` removes both. For a .docx, see [Word documents](/page-layout/guides/word#table-rows).

## What is not supported

A table inside a table cell is not laid out across the end of a page, because Page Layout cannot cut a row whose cell holds a cut table.

## Commands

Both commands also return `false` in an editor without a Page Layout engine, such as one made with `new Editor`, so `editor.can()` tells a toolbar when to enable its switches.

### setRowBreakAcrossPages()

Lets a page cut the row at the cursor, or moves the row to the next page whole.

```js
editor.commands.setRowBreakAcrossPages(false)
```

Takes one argument, `allowed` (`boolean`). Returns `false` outside a table.

### setRepeatHeaderRow()

Repeats the header rows of the table at the cursor on each page the table continues onto, or stops it.

```js
editor.commands.setRepeatHeaderRow(true)
```

Takes one argument, `repeated` (`boolean`). Returns `false` outside a table.

The engine has the same methods. To make these changes without an editor, see [On a server](/page-layout/guides/on-a-server).
