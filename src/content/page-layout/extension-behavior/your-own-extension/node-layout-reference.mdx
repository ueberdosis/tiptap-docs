`defineNodeLayout(typeName, layout)` takes a `NodeLayout`. Every field is optional. `Rule<T>`
below is `NodeLayoutRule<T>`: `T`, or a function of the Node returning `T`.

| Field                 | Type                                                        | Default          | Description                                                                                                                                                                                             |
| --------------------- | ----------------------------------------------------------- | ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `splitDepth`          | `Rule<SplitDepth>`                                          | `'none'`         | How deep a page may cut. See [How deep a page may cut](/page-layout/extension-behavior/your-own-extension/layout-rules#how-deep-a-page-may-cut)                                                         |
| `keepTogether`        | `Rule<boolean>`                                             | `false`          | Move the Node whole wherever that is possible. See [Keeping a Node whole](/page-layout/extension-behavior/your-own-extension/layout-rules#keeping-a-node-whole)                                         |
| `keepWithNext`        | `Rule<boolean>`                                             | `false`          | Stay on the page of the next block's first line. See [Keeping a block with the next](/page-layout/extension-behavior/your-own-extension/layout-rules#keeping-a-block-with-the-next)                     |
| `parallelChildren`    | `Rule<boolean>`                                             | `false`          | The children sit side by side. See [Children side by side](/page-layout/extension-behavior/your-own-extension/layout-rules#children-side-by-side)                                                       |
| `parallelCutRank`     | `Rule<ParallelCutRank>`                                     | `'equal'`        | What a cut through side-by-side children is worth                                                                                                                                                       |
| `parallelCutNode`     | `boolean`                                                   | `false`          | A type a side-by-side cut reopens. Read while the schemas are built                                                                                                                                     |
| `parallelChildKeys`   | `Rule<(string \| number \| null)[]>`                        | —                | Stable identities of the children, where generated children shift their indexes                                                                                                                         |
| `viewContent`         | `string`                                                    | The schema's own | The content expression a divided Node takes while a cut is open. Read while the schemas are built                                                                                                       |
| `childSpans`          | `Rule<NodeChildSpan[]>`                                     | `[]`             | Content that extends down through later children. See [Content that spans several children](/page-layout/extension-behavior/your-own-extension/layout-rules#content-that-spans-several-children)        |
| `repeatedLead`        | `Rule<number>`                                              | `0`              | Leading children every continuation repeats. See [Repeating something on every continuation](/page-layout/extension-behavior/your-own-extension/layout-rules#repeating-something-on-every-continuation) |
| `breakMarker`         | `Rule<boolean>`                                             | `false`          | A block that adds no height to the page it starts. See [Breaks of your own](/page-layout/extension-behavior/your-own-extension/layout-rules#breaks-of-your-own)                                         |
| `startsPage`          | `Rule<boolean>`                                             | `false`          | The page ends in front of the block                                                                                                                                                                     |
| `forcedCut`           | `Rule<'page' \| 'region' \| null>`                          | `null`           | What an inline marker ends where it sits                                                                                                                                                                |
| `chapterLevel`        | `Rule<number \| null>`                                      | `null`           | The level at which the Node begins a chapter. See [Chapters](/page-layout/extension-behavior/your-own-extension/layout-rules#chapters)                                                                  |
| `remeasuresDocument`  | `Rule<boolean>`                                             | `false`          | A change to the block remeasures every block. See [Blocks that restyle the others](/page-layout/extension-behavior/your-own-extension/layout-rules#blocks-that-restyle-the-others)                      |
| `isWellFormed`        | `Rule<boolean>`                                             | `true`           | Whether the Node is consistent. See [Nodes that must stay consistent](/page-layout/extension-behavior/your-own-extension/when-no-rule-fits#nodes-that-must-stay-consistent)                             |
| `completeEdit`        | `(edit: NodeEdit) => Transaction \| null`                   | —                | What an edit from the pages meant for the whole Node. See [Completing an edit](/page-layout/extension-behavior/your-own-extension/when-no-rule-fits#completing-an-edit)                                 |
| `sourcePlugins`       | `() => Plugin[]`                                            | —                | Plugins that run on the document. See [A plugin that keeps the Node consistent](/page-layout/extension-behavior/your-own-extension/when-no-rule-fits#a-plugin-that-keeps-the-node-consistent)           |
| `viewCommands`        | `string[]`                                                  | —                | Commands of the Extension that run on the pages. See [Commands of your own Extension](/page-layout/extension-behavior/your-own-extension/when-no-rule-fits#commands-of-your-own-extension)              |
| `sourceCommands`      | `string[]`                                                  | —                | Commands that run on the document even where a view list names them                                                                                                                                     |
| `labelAttribute`      | `string`                                                    | —                | The attribute a Decoration writes a label into. See [Labels drawn by a Decoration](/page-layout/extension-behavior/your-own-extension/when-no-rule-fits#labels-drawn-by-a-decoration)                   |
| `pageText`            | `(node, page: PageContext) => string \| null`               | —                | A value per page, in a header or footer. See [Values per page](/page-layout/extension-behavior/your-own-extension/when-no-rule-fits#values-per-page)                                                    |
| `ignoredMutation`     | `(mutation: ViewMutationRecord) => boolean`                 | —                | DOM changes of yours that every NodeView of the type lets pass. Read while the schemas are built                                                                                                        |
| `optionOverrides`     | `Record<string, unknown>`                                   | —                | Options set on the type's Extension in both schemas                                                                                                                                                     |
| `viewOptionOverrides` | `Record<string, unknown>`                                   | —                | Options set on the type's Extension in the editor that holds the pages only                                                                                                                             |
| `viewOptionDefaults`  | `Record<string, (editor: () => Editor \| null) => unknown>` | —                | Options filled in on that Extension where the integration left them `null`                                                                                                                              |
| `viewAttributes`      | `Record<string, unknown>`                                   | —                | Defaults for generated attributes, in the schema of the pages only                                                                                                                                      |
| `fragmentAdapter`     | `NodeFragmentAdapter`                                       | —                | Builds and rejoins fragments that need generated children at a page cut                                                                                                                                 |

- **Read while the schemas are built.** `parallelCutNode`, `viewContent`, `ignoredMutation`,
  `viewCommands`, `sourceCommands` and the option fields take a value, not a function of the
  Node. There is no Node to ask yet.
- **Functions of their own.** `pageText`, `ignoredMutation`, `completeEdit` and `sourcePlugins`
  are always functions, with the arguments in the table.
- **Without `isWellFormed`**, a Node counts as consistent, and an edit from the pages is never
  refused for leaving it inconsistent.
- **Named by Extension.** `viewCommands`, `sourceCommands`, `ignoredMutation` and the option
  fields are looked up by the Extension's name, which for a Node is its type name.
