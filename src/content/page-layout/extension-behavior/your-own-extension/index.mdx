You register it with `defineNodeLayout`, and your extension keeps its schema, attributes, NodeView and commands as they are.

## Quick start

Call `defineNodeLayout` with your node's type name and its rule, at module level, before you create the editor. This rule lets a page end between two lines of a `callout`, unless the user set its `keepWhole` attribute:

```js
import { defineNodeLayout } from '@tiptap-pro/extension-page-layout'

defineNodeLayout('callout', {
  splitDepth: 'intoText',
  keepTogether: (node) => node.attrs.keepWhole,
})
```

Each field takes a value when the answer belongs to the type, or a function of the node when it depends on an attribute, as `keepTogether` does here. [Layout rules](/page-layout/extension-behavior/your-own-extension/layout-rules) explains each field.

Page Layout reads some fields, such as `viewContent`, only while it builds the editor, so a later rule changes where pages end but not those fields. The [NodeLayout reference](/page-layout/extension-behavior/your-own-extension/node-layout-reference) lists them.

A later call for the same type changes only the fields it names. So `defineNodeLayout('listItem', { splitDepth: 'intoText' })` lets a page end inside an item of the built-in list, not only between items.

Rules are shared by every editor on a web page, so two editors cannot have different rules for one type.

## The default

A node type without a rule is moved whole: if it does not fit in the space left on the page, all of it goes to the next page. So:

- A block that holds other blocks is never cut between its children.
- A textblock, a block that holds only text such as a caption, is never cut between its lines. `paragraph`, `heading` and `codeBlock` have rules that allow it.
- A block atom, a block without editable content such as an image, moves whole.
- Inside a node that may be cut, a child without a rule moves to the next page whole, and the page ends in front of it.
- An inline node with content is never cut. An inline atom, such as a mention, stays in its line, and that line is cut like any other.

A node that may not be cut and is taller than a page is clipped: the part below the foot of the page it starts on is not shown. The sheet, the element that page is drawn on, then carries `data-tt-overflow="true"`. To avoid it, give the type a `splitDepth`.

The default stops being right when:

- **The node can be taller than a page**, so moving it does not help: [How deep a page may cut](/page-layout/extension-behavior/your-own-extension/layout-rules#how-deep-a-page-may-cut).
- **Its parts belong together**, such as a card's image and heading: [Keeping a node whole](/page-layout/extension-behavior/your-own-extension/layout-rules#keeping-a-node-whole).
- **Its children sit beside each other**, as table cells do: [Children side by side](/page-layout/extension-behavior/your-own-extension/layout-rules#children-side-by-side).

## Which tool for what

The document is what the user writes and you save, without pages. The pages are the copy of it that the editor shows and edits. So a node cut by a page end is one node in the document and two on the pages.

Most nodes need only the first of these pages:

- [Layout rules](/page-layout/extension-behavior/your-own-extension/layout-rules): where a page may end inside a type, and what stays together.
- [When no rule fits](/page-layout/extension-behavior/your-own-extension/when-no-rule-fits): a decision per block, a node that must stay valid as a whole, commands, NodeViews, and values per page in a header or footer.
- [React NodeViews](/page-layout/extension-behavior/your-own-extension/react-nodeviews): a node rendered by a React component.
- [NodeLayout reference](/page-layout/extension-behavior/your-own-extension/node-layout-reference): the type and default of every field.
