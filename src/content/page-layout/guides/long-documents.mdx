Page Layout does this because a browser that holds the text of hundreds of sheets at once scrolls and types slowly, Safari most of all.

## Quick start

Virtualization, drawing only the sheets near the user, is on by default, so a long document needs no setup. Switch it off when the browser's find or a screen reader must reach every sheet, see [What only sees the drawn sheets](/page-layout/guides/long-documents#what-only-sees-the-drawn-sheets):

```js
import { PageLayout, pageSetup } from '@tiptap-pro/extension-page-layout'

PageLayout.configure({
  setup: pageSetup('A4'),
  virtualization: false, // every sheet drawn, all the time
})
```

These options of `PageLayout` are about long documents:

| Option           | Type              | Default | Description                                                                                                                                                      |
| ---------------- | ----------------- | ------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `virtualization` | `boolean`         | `true`  | Whether only the sheets near the user are drawn.                                                                                                                 |
| `layoutHint`     | `LayoutHintStore` | None    | Where Page Layout keeps a document's layout between two openings. See [Opening on the same pages](/page-layout/guides/long-documents#opening-on-the-same-pages). |

## Which sheets are drawn

With virtualization on, Page Layout draws the sheets in view with their text. While you scroll, it also draws a few sheets ahead and one behind. A fast scroll gets up to 12 ahead. Once you stop, it draws two on either side.

Page Layout also draws the sheets where the caret and the selection start and end, and the sheet whose header or footer is open.

The other sheets are paper of the right size and carry `data-tt-page-placeholder`. Page Layout fills up to three of them per animation frame, so a fast scroll can show an empty sheet for a moment, but never a gap.

A click on an empty sheet fills it and puts the caret where you clicked.

`engine.getDrawnPageIndices()` returns the pages drawn with their text, in order. It returns every page while `virtualization` is off, and none in [Pageless](/page-layout/features/page-format#pageless) mode, where the document is one column without sheets:

```js
const engine = editor.storage.pageLayout.engine

engine.getDrawnPageIndices() // [3, 4, 5, 6]
```

When the drawn sheets change, Page Layout calls the `onChange` option of `createPageLayoutEditor`, see [Options of the editor](/page-layout/getting-started/install#options-of-the-editor). So an overlay or a list of thumbnails reads `getDrawnPageIndices()` there, because no event tells it when `data-tt-page-placeholder` changes.

## What stays the same

With virtualization, every sheet is still there: the scrollbar is as long as the document, and a sheet stands where it would stand without virtualization. Page numbers, the [page map](/page-layout/getting-started/document-and-pages/reading#the-page-map) and [`pageAt`](/page-layout/getting-started/document-and-pages/reading#the-page-a-position-is-on) answer for every page. What is saved, shared or exported is the same with virtualization on or off.

## Selecting

Selecting everything, moving the caret to the end or setting the selection from a command draws the sheets the selection lands on first.

An empty sheet inside the selection carries `data-tt-page-selected` and is filled with `--tt-page-selection-fill`, `Highlight` unless you set it. The fill uses `mix-blend-mode: multiply`, so a colored page shows through.

## Typing and pasting

While you type, Page Layout lays out only the sheets around the caret. Once you pause, it lays out the rest and measures far sheets in the background, away from where you look.

A line typed into a header or footer costs what a line of text costs, and sheets off screen take the changed header or footer when you scroll to them.

Pasting a long text puts the caret at the end of the paste and scrolls there. The pages behind it are placed from estimates, see [Right after opening or pasting](/page-layout/guides/long-documents#right-after-opening-or-pasting).

## Right after opening or pasting

Page Layout places a long document's pages from estimates, guessed heights of the blocks, then measures a slice at a time over the following seconds.

The 146 pages of the demo take about a second and a half on a desktop, and a book of several hundred pages pasted at once can take minutes.

Sheets you scroll to before they are measured are measured first. Where an estimate was off, text on them can move to the page before or after for a moment, and their page numbers can change. The page count and the page map settle as the measuring goes on.

`engine.getDiagnostics().measurementPending` is `true` while any block is still on its estimate. Read it in `onChange`, which Page Layout calls as the measuring moves on, and wait for `false` before code jumps far into the document. In this `onChange` function, `status` is an element of your own:

```js
function onChange(editor) {
  const { measurementPending } = editor.storage.pageLayout.engine.getDiagnostics()

  status.textContent = measurementPending ? 'Laying out the pages…' : ''
}
```

## Opening on the same pages

With a `layoutHint` store, a document opens on the pages it was closed on instead of on estimates. A layout hint is the measurements of the document's last layout. This store keeps hints in `localStorage`:

```js
import { PageLayout, pageSetup } from '@tiptap-pro/extension-page-layout'

PageLayout.configure({
  setup: pageSetup('A4'),
  layoutHint: {
    load: async (key) => {
      const stored = localStorage.getItem(key)
      return stored === null ? null : JSON.parse(stored)
    },
    save: (key, hint) => localStorage.setItem(key, JSON.stringify(hint)),
  },
})
```

Page Layout makes the key from the document, the paper and the font, and passes it to both methods:

| Method | Returns                       | Called                                                                                                   |
| ------ | ----------------------------- | -------------------------------------------------------------------------------------------------------- |
| `load` | `Promise<LayoutHint \| null>` | Once when the document opens.                                                                            |
| `save` | `void`                        | Once the document is measured and has been still for a second, then after every later edit that settles. |

If the content arrived after the editor opened empty, `load` is called once more with that content's key. That happens at the first sync of Tiptap Collaboration, or with `setContent` after a fetch.

A store may skip saving a hint, and `load` may return `null`. A hint for a book-length document is about a megabyte of JSON, so choose a store with room for it.

Page Layout uses a hint only for the document it was saved from, on the same paper, in a browser that sets text the same way. Otherwise the document opens on estimates, as it does when `load` rejects.

Page Layout still measures every block and corrects a wrong hint the way it corrects an estimate. Nothing of a hint is in the document, so the document opens the same with or without one.

`engine.getLayoutHint()` returns the current hint, or `null` while the document is still being measured, for a host that keeps hints itself. A `LayoutHint` is `{ version, key, blocks }`. In Pageless mode, Page Layout does not ask the store, and `getLayoutHint()` returns `null`.

## Printing

`window.print()` draws every sheet from `beforeprint` to `afterprint`, so the printout has the text of every page. Code that shows the pages in a scroll area of its own can report which pages are in view with `engine.setVisiblePageRange(first, last)`, and Page Layout draws those sheets at once.

## What only sees the drawn sheets

The browser's own find (Cmd+F or Ctrl+F) reaches the text of the drawn sheets only. Screen readers read the DOM too, with the same limit. Switch `virtualization` off where they must reach every sheet. A search of your own over `editor.state` or the document JSON is not affected.
