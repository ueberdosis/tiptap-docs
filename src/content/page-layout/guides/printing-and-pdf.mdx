## Quick start

The engine ships its own print rules, so this is the whole of it:

```js
window.print()
```

## What comes out

- **One sheet per page.** Each page becomes one sheet, at the size it was planned for.
- **Mixed paper.** A document whose sections use different paper prints each page on its own
  paper size.
- **Every sheet is drawn.** With [virtualization](/page-layout/guides/long-documents#printing) on, every
  sheet is drawn from `beforeprint` to `afterprint`, so the printout is the whole document.
- **The zoom comes off.** A [zoom](/page-layout/features/zoom) the reader had set is taken off for the print
  and put back afterwards.
- **No screen marks.** The sheet's shadow, the lines of breaks, the selection the engine draws,
  and remote carets and selections are not printed.

## Printing in Safari

Safari prints every sheet on the paper of the first page. A page in another format is fitted onto
that paper instead:

- **Landscape on portrait paper.** A landscape page is turned to lie upright, with its top to the
  left edge.
- **A larger page** is scaled down to fit.
- **The other pages** keep their size.
- **The text is the same.** Every page still holds the same text as on screen.

## One format per print job

A print job has one paper size, so a printer that addresses one format at a time prints a document
of mixed formats once per format. `printSheetName(size)` is the name the engine writes on each
sheet of that size, such as `pl-sheet-794x1123` for A4.

```js
import { printSheetName } from '@tiptap-pro/extension-page-layout'

const name = printSheetName({ width: 794, height: 1123 })
```

- **Shared by size.** Two sections of the same format share one name.
- **Whole pixels.** The size is rounded to whole pixels.

## A PDF from a headless browser

A page you print to PDF with a headless browser of your own gets the same sheets.

- **The zoom.** The engine's print rules take the zoom off without a print event, which a driver
  does not fire.
- **Every sheet.** Without a print event, virtualization draws only the sheets near the reader.
  Pass `virtualization: false`, or call `engine.setVisiblePageRange(0, engine.getPageCount() - 1)` before
  printing.

Server-side pagination and PDF output are not available as a package yet.

## Pagination without a browser

`paginate` is the layout pass without a browser, for a caller that already has measurements from
somewhere else. It is DOM-free.

```js
import { paginate } from '@tiptap-pro/extension-page-layout'

const { pages, setup, sections } = paginate({
  sourceDoc,
  extensions,
  measure: {
    blockHeight: (block, index, contentWidth) => /* … */,
  },
})
```

| Option            | Type              | Description                                                                                 |
| ----------------- | ----------------- | ------------------------------------------------------------------------------------------- |
| `sourceDoc`       | `Node`            | The document. Build it with `createSourceSchema(extensions).nodeFromJSON(json)`             |
| `extensions`      | `Extensions`      | The same list the client builds its editor from                                             |
| `measure`         | `PageMeasurement` | The measurements, below                                                                     |
| `setup`           | `PageLayoutSetup` | The paper of a document that stores none. `null` for no pages, which wins over the document |
| `chapterNumberOf` | `ChapterNumberOf` | As the [option](/page-layout/reference/options) of the same name                            |
| `blockBreaksOf`   | `BlockBreaksOf`   | As the [option](/page-layout/reference/options) of the same name                            |

It returns a `PaginatedDocument`:

| Field        | Type                     | Description                                                                 |
| ------------ | ------------------------ | --------------------------------------------------------------------------- |
| `pages`      | `readonly MappedPage[]`  | The [page map](/page-layout/features/page-numbers): what is on which page   |
| `projection` | `Projection`             | The paginated document and its position mapping, for rendering the pages    |
| `setup`      | `PageLayoutSetup`        | The setup the pages were laid out with: the document's own where it has one |
| `sections`   | `readonly PageSection[]` | The document's sections                                                     |

### Measurements

`blockHeight` is the only measurement `paginate` cannot do without. Each one left out is a thing
the pages then do not know.

| Measurement    | Required | Description                                                                                                        |
| -------------- | -------- | ------------------------------------------------------------------------------------------------------------------ |
| `blockHeight`  | Yes      | How tall a top-level block is at a content width. Without anything else, pages are filled with whole blocks        |
| `blockLines`   | No       | Where a block may be cut. Without it no paragraph continues on the next page and no table row is divided           |
| `blockMargins` | No       | The room a block asks for above and below itself                                                                   |
| `bandHeight`   | No       | How tall a header or footer is. Without it every band is assumed to fit inside its margin                          |
| `notes`        | No       | What notes cost the page they are referred from. Without it a note is paginated where it is kept, as an endnote is |

- **Margins.** A height carries the room below the block only, because two margins between blocks
  collapse to the larger of them. A stylesheet that writes its spacing above each block needs
  `blockMargins`, or the pages come out that much too full.
- **The same pages as a client.** The numbers a client measures come out of a browser. To get the
  same pagination, measure the way the client does.
