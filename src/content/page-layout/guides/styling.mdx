## What you change, and what Page Layout draws

Page Layout draws each page on a sheet, the element a page is shown on. A sheet has the size of its paper. It holds a text area, the box inside the margins that the text fills.

Page Layout also draws the paper, the line between columns and a few selections. Most values it draws are CSS custom properties with a fallback. So a plain declaration on the editor, or on an element around it, changes one without a specificity fight.

Your CSS supplies the space around the sheets, the typography and any value you want different.

## The paper

A sheet is white paper with a shadow and a gap to the next sheet. `--tt-page-paper` sets the color, `--tt-page-sheet-shadow` the shadow, and `--tt-page-sheet-gap` the gap:

```css
.my-editor {
  --tt-page-paper: #fdfdfb;
  --tt-page-sheet-shadow: 0 1px 2px rgba(0, 0, 0, 0.1);
  --tt-page-sheet-gap: 40px;
}
```

A paper or text color saved in the document for a section, with the commands of [Page colors](/page-layout/features/page-colors), wins over `--tt-page-paper`. Page Layout centers a sheet that is narrower than its scrolling element.

## Selection, column lines and carets

These properties change the other things Page Layout draws:

```css
.my-editor {
  --tt-page-selection-fill: #b4d5fe;
  --tt-page-column-rule-color: #d4d4d8;
  --tt-page-column-rule-width: 1px;
  --tt-remote-caret-width: 2px;
}
```

`--tt-page-selection-fill` colors a selection that Page Layout draws itself. It does that where a page boundary runs through a table row: it hides the browser's selection there and fills rectangles instead.

The rectangles lie over the words, because a sheet is opaque. They use `mix-blend-mode: multiply`, so the letters stay dark. You choose the color, but not the blending. For a fill behind the text, draw the selection yourself, as [Turning it off](/page-layout/guides/styling#turning-it-off) explains.

`--tt-page-column-rule-color` and `--tt-page-column-rule-width` style the line a section asks for between its columns, Word's "Line between". The line takes no room, so it does not change the page count.

`--tt-remote-caret-width` is the width of the caret of another person who edits with you, see [Styling remote cursors](/page-layout/guides/collaboration#styling-remote-cursors).

## Breaks where there are no pages

In a pageless document, one continuous column without pages, a labeled line shows each page, column or section break. These properties change the line, its label, and the room around it:

```css
.my-editor {
  --tt-page-break-line-color: rgba(15, 23, 42, 0.28);
  --tt-page-break-label-color: rgba(15, 23, 42, 0.45);
  --tt-page-break-label-size: 8px;
  --tt-page-break-line-space: 1.75rem;
}
```

To hide the line or change the labels, see [Breaks](/page-layout/features/breaks).

## Clipping

The text area of a page clips what does not fit, so nothing paints over a footer. `--tt-page-clip-margin` is how far outside it content still paints, such as the resize handles of a full-width image. Content wider or taller than that is cut off:

```css
.my-editor {
  --tt-page-clip-margin: 8px;
}
```

A browser without `overflow-clip-margin` clips at the edge of the text area.

## A theme

One class can hold your custom properties, so a dark theme is a class you switch on. Text on a sheet takes your `color`, unless the document saves its own text color. The space around the sheets is yours to darken too:

```css
.my-editor.is-dark {
  color: #e4e4e7;
  --tt-page-paper: #1f1f23;
  --tt-page-sheet-shadow: 0 1px 2px rgba(0, 0, 0, 0.6);
  --tt-page-column-rule-color: rgba(255, 255, 255, 0.2);
  --tt-page-break-line-color: rgba(255, 255, 255, 0.3);
  --tt-page-break-label-color: rgba(255, 255, 255, 0.5);
}
```

## Turning it off

`sheetAppearance: 'none'` turns off the paper Page Layout paints, for a design of your own. That is the color, shadow and gap of a sheet, the selection fill, the line between columns and the look of a colleague's caret. The other value, `'paper'`, is the default:

```js
import { PageLayout } from '@tiptap-pro/extension-page-layout'

PageLayout.configure({ sheetAppearance: 'none' })
```

With `'none'`, style the sheets through `[data-tt-page]` and the other attributes in the [CSS reference](/page-layout/reference/css#attributes), which stay on the elements. A sheet keeps its size and margins, because Page Layout measures the pages with them. A colleague's caret still takes no room.

The break lines of a pageless document stay with `'none'`. `breaksWithoutPages: 'none'` turns them off, see [Breaks](/page-layout/features/breaks).

Style the selection yourself too. `[data-tt-native-selection-hidden]` marks the editor while the browser's selection should be hidden, and `[data-tt-drawn-selection]` marks the rectangles to fill.

With `'none'`, Page Layout no longer makes the browser's selection transparent. A selected sheet that is not drawn yet, in a [long document](/page-layout/guides/long-documents), gets no fill either.

## Margins between blocks

Write the margins between blocks the way you like: `margin: 0 0 14px`, `14px 0 0` and `14px 0` give the same gap and page count. Two margins collapse to the larger one, as anywhere.

A block at the top of a page keeps its top margin, as in Word. So a heading with `margin: 2em 0 0.5em` keeps its `2em` there.

When a page boundary splits a paragraph, its lower half starts the next page with no top margin. `[data-tt-split-continuation]` marks that half, for styles that should not repeat there, such as a first-line indent.

The lower half of a list item draws no bullet or number. That rule, `[data-tt-page-region] li[data-tt-split-continuation]` with `list-style: none`, has no `!important`. To show a marker there, write a rule of yours with the same or a more specific selector.

## The boxes are the engine's

The engine, the part of Page Layout that lays out the pages, sets the size of the boxes it measures. A page is exactly as tall as its paper, and content that did not fit is clipped, with `data-tt-overflow` on the page.

These rules are `!important`, so your `height: auto` on a page or `column-count` has no effect, however specific the selector. Only your own `!important` wins. A flex or grid row of yours that lays sheets side by side cannot shrink a sheet either.

Change the look through the custom properties on this page instead. See [What the engine writes either way](/page-layout/reference/css#what-the-engine-writes-either-way).

## A Content Security Policy

Page Layout adds its rules as a `style` element, which follows the options `injectNonce` and `injectCSS` of `createPageLayoutEditor`. `injectNonce` puts the nonce on the element, so a policy without `'unsafe-inline'` lets it through. Here, `nonce` is the nonce your server wrote into the policy:

```js
import { createPageLayoutEditor, PageLayout, pageSetup } from '@tiptap-pro/extension-page-layout'
import StarterKit from '@tiptap/starter-kit'

const editor = createPageLayoutEditor({
  element: document.querySelector('#editor'),
  content: { type: 'doc', content: [{ type: 'paragraph' }] },
  extensions: [StarterKit, PageLayout.configure({ setup: pageSetup('A4') })],
  injectNonce: nonce,
})
```

`injectCSS: false` in the same options leaves the element out, and you load the rules yourself. `layoutStyleRules()` returns them as a string. Pass it the `breaksWithoutPages` and `sheetAppearance` you gave `PageLayout`, see [Options](/page-layout/reference/options#drawing):

```js
import { layoutStyleRules } from '@tiptap-pro/extension-page-layout'

const css = layoutStyleRules({ breaksWithoutPages: 'lines', sheetAppearance: 'paper' })
```

Without these rules the pages are measured wrong: a sheet grows with its content, and breaks land in the wrong places.

Page Layout puts its `style` element first in `head`, once per document. So a second editor on the same web page uses the first editor's `sheetAppearance` and `breaksWithoutPages`, see [Two editors on one web page](/page-layout/reference/limitations#two-editors-on-one-web-page).

`injectCSS: false` covers only the layout rules. The paper sizes for printing (`@page`) go into a second element, `style[data-tt-page-layout-sheets]`. Page Layout always writes it, because the sizes change with the page setup and are data, not styling.

That element gets no nonce. So a policy without `'unsafe-inline'` blocks it, and a print does not get the paper size of the pages. No option changes that.

Column layouts of `@tiptap-pro/extension-columns` follow `injectNonce` and `injectCSS` too. With `injectCSS: false`, load that package's `columnStyleRules()`, which takes no arguments.

Footnotes, Outline numbering, Cross-references and Bookmarks need their stylesheets added by you, each with a nonce: `mountFootnoteStyles(document, { nonce })`, `mountOutlineStyles`, `mountCrossReferenceStyles` and `mountBookmarkStyles` take the same arguments.

## The room around the pages

The element you pass as `element` holds the sheets, and needs no markup around it. The space around the sheets, with its background, padding and distance from the edge, comes from your stylesheet.

By default the browser window scrolls the pages. To scroll them inside a pane, give `element` an ancestor with `overflow: auto`. [Fit to width](/page-layout/features/zoom#fit-to-width) then fits the pages to that pane:

```css
.my-desk {
  background: #f3f4f6;
  overflow: auto;
  padding: 40px;
}
```

To scale the sheets, use [Zoom](/page-layout/features/zoom), not a CSS `transform`. With a `transform`, the pages break at the scaled size.

## A toolbar over the pages

Set `scrollMargin.top` to the height of anything drawn over the pages, or the caret can be scrolled under your toolbar.

Page Layout scrolls the caret, an opened header or footer, or a note area into view. `scrollMargin` is the room in pixels it leaves at the top and bottom of the viewport. Each side defaults to `48`, about three lines of text. Under a toolbar 96 pixels tall, write:

```js
import { PageLayout } from '@tiptap-pro/extension-page-layout'

PageLayout.configure({ scrollMargin: { top: 96, bottom: 24 } })
```
