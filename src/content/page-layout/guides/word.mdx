The page options a .docx carries:

- the paper of each section, with its margins and columns,
- how its pages and notes are numbered,
- which table rows repeat at the top of a page,
- which rows and lists stay on one page.

Lengths in a .docx are twentieths of a point (twips). The functions convert them, and everything
they hand you is in the units the rest of this package takes.

## Functions

| Function                     | Arguments                     | Returns                                         | See                                                       |
| ---------------------------- | ----------------------------- | ----------------------------------------------- | --------------------------------------------------------- |
| `sectionBreaksFromOoxml`     | `sections, nameDefinition?`   | A section break to put in front of each section | [Sections](/page-layout/guides/word#sections)             |
| `toOoxmlSections`            | `doc, setup`                  | Every section with its `w:sectPr` and its range | [Sections](/page-layout/guides/word#sections)             |
| `fromOoxmlSectionProperties` | `properties, nameDefinition?` | `{ setup, kind }` of one section                | [Sections](/page-layout/guides/word#sections)             |
| `toOoxmlSectionProperties`   | `setup, kind?`                | The `w:sectPr` of one section                   | [Sections](/page-layout/guides/word#sections)             |
| `fromOoxmlRowProperties`     | `rows`                        | The attributes of a table and each row          | [Table rows](/page-layout/guides/word#table-rows)         |
| `toOoxmlRowProperties`       | `table`                       | `{ tblHeader, cantSplit }` for every row        | [Table rows](/page-layout/guides/word#table-rows)         |
| `fromOoxmlListParagraphs`    | `paragraphs`                  | The attributes of a list                        | [Lists](/page-layout/guides/word#lists)                   |
| `toOoxmlListParagraphs`      | `list`                        | `{ keepNext, keepLines }` for every paragraph   | [Lists](/page-layout/guides/word#lists)                   |
| `fromOoxmlColumnLayoutRow`   | `row`                         | The attributes of a column layout               | [Column layouts](/page-layout/guides/word#column-layouts) |
| `toOoxmlColumnLayoutRow`     | `layout`                      | `{ cantSplit }`                                 | [Column layouts](/page-layout/guides/word#column-layouts) |

## Sections

A section's setup is `w:sectPr` in the file.

- **Where Word keeps it.** Word keeps `w:sectPr` at the end of the section, in the paragraph
  properties of its last paragraph. The last section's is the final child of `w:body`.
- **Where a section break stands.** Here a section break stands in front of its section.

### Reading sections

`sectionBreaksFromOoxml` takes the `w:sectPr` elements in the order of the file. It returns the
section break to put in front of each section, the first one at the very start of the document:

```js
import { sectionBreaksFromOoxml } from '@tiptap-pro/extension-page-layout'

// One entry per section, read from the file in order.
const breaks = sectionBreaksFromOoxml([
  {
    pgSz: { w: 11906, h: 16838 },
    pgMar: { top: 1440, right: 1440, bottom: 1440, left: 1440 },
  },
  {
    type: 'nextPage',
    pgSz: { w: 16838, h: 11906, orient: 'landscape' },
    pgMar: { top: 1440, right: 1440, bottom: 1440, left: 1440 },
    cols: { num: 2, space: 720, sep: true },
  },
])

const content = [breaks[0], ...firstSectionBlocks, breaks[1], ...secondSectionBlocks]
```

Always put the first break in. A document without one is shown in the format of whichever editor
opens it, so the same file comes out on different paper in two places. See
[The document's own format](/page-layout/core-concepts/sections#the-documents-own-format).

### Writing sections

`toOoxmlSections(doc, setup)` returns every section with its `w:sectPr` and the range of
top-level blocks it covers.

```js
import { toOoxmlSections } from '@tiptap-pro/extension-page-layout'

for (const section of toOoxmlSections(editor.state.doc, setup)) {
  writeSectionProperties(section.properties, section.endBlockIndex - 1)
}
```

| Field             | Type                     | Description                                                            |
| ----------------- | ------------------------ | ---------------------------------------------------------------------- |
| `properties`      | `OoxmlSectionProperties` | The section's `w:sectPr`                                               |
| `startBlockIndex` | `number`                 | The section's first top-level block, the break in front of it included |
| `endBlockIndex`   | `number`                 | One past its last top-level block                                      |

- **Where the properties go.** On the last paragraph of the range. The last section's go into
  `w:body`.
- **`setup`** is the format of a first section the document names none for: the setup your
  editor is configured with.
- **Each `w:sectPr` is complete.** Colors and everything a section inherits are resolved.

### One section at a time

`toOoxmlSectionProperties(setup, kind)` writes one `w:sectPr`. `kind` defaults to `'nextPage'`.
`fromOoxmlSectionProperties(properties)` reads one and returns `{ setup, kind }`.

### What a section property becomes

| `w:sectPr`     | Setup                                                                                                                               |
| -------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| `w:type`       | `kind`. `continuous` starts the section on the same sheet. `nextPage`, `evenPage`, `oddPage` and `nextColumn` start it on a new one |
| `w:pgSz`       | `format` and `orientation`. Word writes the turned sheet, so a landscape page has `w` above `h`                                     |
| `w:pgMar`      | `margins`. A negative top or bottom, Word's "at least", reads as its size                                                           |
| `w:cols`       | `columns`: `num` is `count`, `sep` is `rule`, `space` or the `w:col` list are `gaps` and `widths`                                   |
| `w:pgNumType`  | `pageNumbering`: `fmt`, `start`, and `chapStyle` with `chapSep` for a chapter number                                                |
| `w:footnotePr` | `notePlacement` from `pos`, and the footnote numbering from `numFmt`, `numStart` and `numRestart`                                   |
| `w:endnotePr`  | The endnote numbering                                                                                                               |

- **Built-in sizes.** A size within a pixel of a [built-in format](/page-layout/core-concepts/page-format)
  reads as that format.
- **Left out.** Anything a `w:sectPr` leaves out is the default, as in Word.
- **The page color** is `w:background` of the whole document, and is the theme of the first
  section.
- **Headers and footers**, `w:titlePg` among them, are content of the section break. Write them
  as any other content.

### Number formats

Number formats are converted with `toOoxmlNumberFormat` and `fromOoxmlNumberFormat` of
[number formats](/page-layout/extensions/number-formats#docx).

A `custom` format such as `001, 002, 003, ...` reads as decimal, unless you pass a second argument
that stores the definition and returns its name. `sectionBreaksFromOoxml` takes the same second
argument.

```js
fromOoxmlSectionProperties(properties, (definition) => {
  editor.commands.setNumberFormat('imported-1', definition)
  return 'imported-1'
})
```

## Table rows

Both table options are on the row in a .docx, in `w:trPr`:

| `w:trPr`      | Row                                                     |
| ------------- | ------------------------------------------------------- |
| `w:cantSplit` | Moves to the next page whole: `breakAcrossPages: false` |
| `w:tblHeader` | Repeated at the top of each page                        |

- **Writing.** `toOoxmlRowProperties(table)` returns `{ tblHeader, cantSplit }` for every row in
  order. `tblHeader` is set on the leading rows of header cells while the table repeats its
  header.
- **Reading.** `fromOoxmlRowProperties(rows)` returns the attributes for the table and for each
  row.
- **Header cells.** A row it marks `headerCells: true` has to be made of `tableHeader` cells,
  because the rows that repeat are the leading rows of header cells.
- **Only the top rows repeat.** A row marked further down does not, in Word or here.

```js
import { fromOoxmlRowProperties } from '@tiptap-pro/extension-page-layout'

const read = fromOoxmlRowProperties(
  rows.map((row) => ({
    tblHeader: row.hasTblHeader,
    cantSplit: row.hasCantSplit,
  })),
)

const table = {
  type: 'table',
  attrs: read.table,
  content: rows.map((row, index) => ({
    type: 'tableRow',
    attrs: read.rows[index].attrs,
    content: row.cells.map((cell) => ({
      type: read.rows[index].headerCells ? 'tableHeader' : 'tableCell',
      content: cell.content,
    })),
  })),
}
```

## Lists

A .docx has no list element: a list is a run of paragraphs with the same numbering. So the two
list options are written paragraph by paragraph, as Word's _Keep with next_ (`w:keepNext`) and
_Keep lines together_ (`w:keepLines`).

`toOoxmlListParagraphs(list)` returns `{ keepNext, keepLines }` for every paragraph of the list in
document order, nested lists included:

- **A list kept together** (`keepTogether: true`) keeps every paragraph with the next but the
  last.
- **An item that may not be cut**, which is the default, keeps its own paragraphs with each other
  and their lines together.

`fromOoxmlListParagraphs(paragraphs)` reads the list's attributes back:

- **Kept together.** A run where every paragraph but the last keeps with the next is a list kept
  together.
- **Cutting items.** Whether an item may be cut keeps its default, since Word has no setting for
  it.

## Column layouts

A [column layout](/page-layout/extensions/overview#column-layout) is written to a .docx as a table
of one row without borders, with a cell per column.

- **Keep together.** `keepTogether` is the `w:cantSplit` of that row.
- **Writing.** `toOoxmlColumnLayoutRow(layout)` returns `{ cantSplit }`.
- **Reading.** `fromOoxmlColumnLayoutRow(row)` returns the attributes.

## Pasting from Word

Text copied in Word and pasted into the editor keeps its page options. Nothing needs to be
configured: `PageLayout` reads them whenever the clipboard holds Word's HTML.

| Copied in Word                                           | Pasted as                                                |
| -------------------------------------------------------- | -------------------------------------------------------- |
| A page break                                             | A [page break](/page-layout/core-concepts/breaks)        |
| A column break                                           | A column break                                           |
| A section break, _Next Page_ or _Continuous_             | A section break of that kind                             |
| A table row with _Allow row to break across pages_ off   | A row with `breakAcrossPages: false`                     |
| Rows marked _Repeat as header row_ at the top of a table | Header cells, and the table with `repeatHeaderRow: true` |

- **A pasted section break** starts its section in the format in force where you paste it.
- **The section's paper is not taken.** Its paper, margins and columns in Word are left behind: a
  paste adds text to a document and does not change what it is printed on.
- **A second section.** A paste that gives the document its second section writes the first
  section's format too, as
  [inserting a section break](/page-layout/core-concepts/sections#the-documents-own-format) does.
- **Notes and bookmarks.** Footnotes, endnotes and bookmarks pasted from Word are read by their
  own packages. See [Footnotes](/page-layout/extensions/footnotes#pasting-from-word) and
  [Bookmarks](/page-layout/extensions/bookmarks#word).
- **Fields** are pasted as the text Word last showed for them. A page number in the text is `1`
  and stays `1`, and a cross-reference to a heading is the heading's number as plain text.
