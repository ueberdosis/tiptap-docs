## Setting it up

Lists come from StarterKit, or from `@tiptap/extension-list`. Add them as in any Tiptap editor:

```js
import StarterKit from '@tiptap/starter-kit'

createPageLayoutEditor({
  element,
  content,
  extensions: [StarterKit, PageLayout.configure({ setup: pageSetup('A4') })],
})
```

- **Nothing else to set up.** Page Layout recognizes `bulletList` and `orderedList` by type name
  and adds two attributes to them. Your configuration of the extension stays as it is.
- **The list commands** work unchanged, such as `toggleBulletList`, `sinkListItem` and
  `liftListItem`, also in a list cut across a boundary.

## At the bottom of a page

- **Between two items.** The item the boundary landed in moves to the next page whole.
- **One list.** The document keeps one list. The two halves on screen are two views of it.
- **Counting goes on.** An ordered list that carries on over a page counts on: item eight follows
  item seven across the boundary.
- **The outermost list decides.** A nested list breaks as the list around it does.

## What is stored

| Attribute               | Default | In HTML                        |
| ----------------------- | ------- | ------------------------------ |
| `keepTogether`          | `false` | `data-tt-keep-together="true"` |
| `breakItemsAcrossPages` | `false` | `data-tt-break-items="true"`   |

- **Stored on the list Node**, on `bulletList` and `orderedList`. A copied list keeps them.
- **`PageLayout.configure({ listPagination: false })`** takes both attributes away.

## Keeping a list on one page

Two settings on the list, both Word's:

```js
// Word's "Keep lines together": the list is never cut, and moves to the next page whole.
editor.commands.setListKeepTogether(true)

// Word's "Allow row to break across pages", for a list: an item may itself be cut
// between two of its lines, rather than moving on whole.
editor.commands.setListBreakItems(true)
```

- **A caret in a nested item** sets the outermost list. That is the block the page boundary
  meets: holding a sub-list together is no use while the list around it may break anywhere.
- **In a .docx** both are written paragraph by paragraph, as Word's _Keep with next_ and _Keep
  lines together_. See [Lists in Word](/page-layout/guides/word#lists).

## The list at the cursor

```js
const context = editor.storage.pageLayout.engine.getListContext()
```

`null` when the cursor is not in a list, otherwise:

| Field                   | Type      | Description                                                       |
| ----------------------- | --------- | ----------------------------------------------------------------- |
| `list`                  | `Node`    | The outermost list around the cursor                              |
| `listPosition`          | `number`  | Where it starts                                                   |
| `keepTogether`          | `boolean` | Whether it is held on one page                                    |
| `breakItemsAcrossPages` | `boolean` | Whether an item may be cut                                        |
| `itemCount`             | `number`  | How many items it has. With one, both settings make no difference |

## A list taller than a page

A list kept together that does not fit on a page of its own is cut anyway. See
[Keep together is a preference](/page-layout/supported-extensions#keep-together-is-a-preference).

- **An item taller than a page** is cut at its lines, whatever `breakItemsAcrossPages` says.
- **A manual page break inside a list** is always honored. An author who put a break in the
  middle of a list has said where it ends.

A toolbar that offers the switch can find out and say so:

```js
const engine = editor.storage.pageLayout.engine
const context = engine.getListContext()

if (context?.keepTogether) {
  const cut = engine.isDividedInView(
    context.listPosition,
    context.listPosition + context.list.nodeSize,
  )

  if (cut) {
    // Taller than a page: tell the author, so the switch does not look broken.
  }
}
```

## Commands

### setListKeepTogether

Keeps the list at the cursor on one page, or lets it break again.

```js
editor.commands.setListKeepTogether(true)
```

| Argument | Type      | Description                                  |
| -------- | --------- | -------------------------------------------- |
| `kept`   | `boolean` | `true` moves the list to the next page whole |

Returns `false` when the cursor is not in a list.

### setListBreakItems

Lets a page cut through an item of the list at the cursor, or moves the item on whole again.

```js
editor.commands.setListBreakItems(true)
```

| Argument  | Type      | Description                                  |
| --------- | --------- | -------------------------------------------- |
| `allowed` | `boolean` | `true` cuts an item between two of its lines |

Returns `false` when the cursor is not in a list.
