Composable Documents starts with **Slots**: editable fields inside ordinary Tiptap documents. A Slot can hold blocks, sit inside a sentence, or contain individually addressable nested fields.

Each Slot stores its ID and configuration in the document. Developers can insert, fill, clear and dissolve fields, validate a submission, and render fields with their own HTML or NodeViews. Invalid drafts remain editable.

## Install

```bash
npm install @tiptap-pro/extension-slot
```

```ts
import { Slot } from '@tiptap-pro/extension-slot'

const editor = new Editor({
  extensions: [StarterKit, Slot],
  content: {
    type: 'doc',
    content: [
      {
        type: 'blockSlot',
        attrs: {
          id: 'summary',
          config: { version: 1, label: 'Summary', required: true },
        },
        content: [{ type: 'paragraph' }],
      },
    ],
  },
})
```

`Slot` installs both `blockSlot` and `inlineSlot`. Add it once; pass customized Node extensions through its options.

## Build your workflow

- [Create document fields](/composable-documents/slots/guides/create-fields): author fields, wrap existing text and dissolve wrappers.
- [Validate a submission](/composable-documents/slots/guides/validate-submission): combine embedded rules, application validators and cross-field checks.
- [Allow filling only](/composable-documents/slots/guides/fill-only): protect the template and assign individual fields.
- [Build a field sidebar](/composable-documents/slots/guides/field-sidebar): list fields, show completion and navigate the document.

Slots do not restrict permissions by themselves. Add [Content Protection](/content-protection/getting-started/overview) when your workflow needs it. Variables bound to external data are separate from Slots and are not part of this package.

See the [API reference](/composable-documents/slots/api-reference) and [rendering customization](/composable-documents/slots/rendering).
