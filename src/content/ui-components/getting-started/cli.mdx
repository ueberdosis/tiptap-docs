The Tiptap CLI helps you scaffold editors, install UI components or primitives, and configure Tiptap faster. It removes much of the manual work so you can start building editor features faster.

It’s designed for Vite or Next.js projects. If you use another framework, you’ll need to integrate Tiptap manually from the [open-source repository](https://github.com/ueberdosis/tiptap-ui-components).

## Usage

```bash
npx @tiptap/cli@latest [command] [options]
```

Run `--help` or `-h` to list commands. For help with one command, use `help add` or `add --help`. Run `--version` or `-v` to print the CLI version.

```bash
npx @tiptap/cli@latest help add
npx @tiptap/cli@latest --version
```

## Commands

### `init`

Initialize your project and install dependencies. This command sets up your project configuration and adds any specified components as editable source files.

Run in an empty directory, it scaffolds a new Vite or Next.js project; run in an existing project, it configures it. Either way, the components are copied into your `components/` folder — you then import and render them in your own page. They are not wired into a page for you, so a freshly scaffolded app still shows the framework's default starter page until you render a component. See the [Next.js](/ui-components/install/next) or [Vite](/ui-components/install/vite) guide for the full flow.

```bash
npx @tiptap/cli@latest init
```

Pass `--with <id>` to install one optional feature with a template. This example starts a Simple Editor project with Collaboration.

```bash
npx @tiptap/cli@latest init simple-editor --with collaboration
```

#### Arguments

- components: the components to add

#### Options

```bash
Usage: @tiptap/cli@latest init [options] [components...]

Options:
-f, --framework <framework>   The framework to use (next, vite)
-c, --cwd <cwd>               The working directory (defaults to current directory)
--name <name>                 Name the new project
--defaults                    Use the scaffold defaults and install the requested items
-s, --silent                  Mute output
--verbose                     List file paths and show detailed feature setup instructions
--src-dir                     Use the src directory in a new Next.js project
--react-compiler              Enable React Compiler in a new Next.js project
--with <id>                   Install one registry feature
--editor <path>               Connect the feature to an editor file in an existing project
```

### `add`

Add a Tiptap UI component or template to your project.

```bash
npx @tiptap/cli@latest add [components...]
```

#### Example

```bash
npx @tiptap/cli@latest add button
```

To add a feature to an existing React editor, pass its ID to `add --with`. Pass one feature ID per command.

```bash
npx @tiptap/cli@latest add --with collaboration
```

If your project has several editors, pass `--editor` to select a file that imports `useEditor` from `@tiptap/react`. Both `init` and `add` accept `--editor` with `--with` in an existing project. Omit template and component names when you specify an editor. Replace the path below with your editor's path to preview the changes.

```bash
npx @tiptap/cli@latest add --with collaboration --editor src/ArticleEditor.tsx --diff src/ArticleEditor.tsx
```

#### Preview an installation

Run `add` with `--dry-run` in your project to list the destination files and package changes. Use `--diff` to see line-by-line changes. Both previews leave your project files and dependencies untouched.

```bash
npx @tiptap/cli@latest add simple-editor --dry-run
npx @tiptap/cli@latest add simple-editor --diff
```

To inspect one file, copy its path from the dry run and pass it after `--diff`. This example uses a Next.js project with a root `app` directory.

```bash
npx @tiptap/cli@latest add simple-editor --diff app/simple/page.tsx
```

#### Options

```bash
Usage: @tiptap/cli@latest add [options] [components...]

Arguments:
  components                    The components to add

Options:
  -o, --overwrite              Overwrite existing files
  -c, --cwd <cwd>              The working directory (defaults to current directory)
  -p, --path <path>            The path to add the component to
  -s, --silent                 Mute output
  --verbose                    List file paths and show detailed feature setup instructions
  --with <id>                  Install one registry feature
  --editor <path>              Connect the feature to an existing editor file
  --dry-run                    List planned file and package changes
  --diff [path]                Show file changes for all destinations or one path
```

### `search`

Use `search [query...]` to find public registry items by name or description. Pass `--type <type>` to filter by a registry type such as `node` or `template`.

```bash
npx @tiptap/cli@latest search image --type node
```

Use `--limit <count>` to cap the number of results and `--offset <count>` to skip matches. Both take nonnegative integers. The offset defaults to zero. This example skips the first five nodes and returns up to five more as JSON.

```bash
npx @tiptap/cli@latest search --type node --limit 5 --offset 5 --json
```

### `view`

Use `view <name>` to inspect a registry item before installing it. For a template, the CLI lists its files, routes, direct dependencies, and any optional or built-in features. Pass `--json` for structured output or `--source` to read the item's source files. Paid source requires an account with access and an accepted license.

```bash
npx @tiptap/cli@latest view simple-editor
npx @tiptap/cli@latest view --features
npx @tiptap/cli@latest view collaboration
```

`view --features` lists feature IDs. Pass an ID to `view` to see what the feature installs and how to set it up. To inspect the file changes for a feature in your project, run `add --with <id> --diff`.

### `info`

Get information about your project configuration and setup.

```bash
npx @tiptap/cli@latest info
```

#### Options

```bash
Usage: @tiptap/cli@latest info [options]

Options:
  -c, --cwd <cwd>              The working directory (defaults to current directory)
  --json                       Print project diagnostics as JSON
```

### `login`

To sign in from your terminal, run this command in your project.

```bash
npx @tiptap/cli@latest login
```

1. At `Email:`, enter your Tiptap Cloud account email and press Enter.
2. At `Password:`, type your Tiptap Cloud password and press Enter. The terminal shows `*` for each character you type.
3. The CLI asks whether to save a registry token to your package manager configuration. Choose **Yes** if this project needs to download private Tiptap packages.

If you only need access to private packages, use `--registry-only`. Add `--write-config` to save the token without the confirmation question.

```bash
npx @tiptap/cli@latest login --registry-only --write-config
```

#### Supply the password in a script

`TIPTAP_CLI_PASSWORD` is an environment variable. When a script runs `login`, the CLI can read your Tiptap Cloud account password from that variable and skip the password question.

To try this in Bash or Zsh, replace `you@example.com` with your email and run the block below. Type your password when asked and press Enter. The shell hides your input and keeps the variable only for this block.

```bash
(
  printf 'Tiptap Cloud password: '
  IFS= read -rs TIPTAP_CLI_PASSWORD
  printf '\n'
  export TIPTAP_CLI_PASSWORD
  npx @tiptap/cli@latest login --email you@example.com --write-config
)
```

In GitHub Actions, open your repository's **Settings → Secrets and variables → Actions** and choose **New repository secret**. Create `TIPTAP_CLI_PASSWORD` with your Tiptap Cloud password as its value. Create a second secret named `TIPTAP_EMAIL` with your account email. Add this step after checkout and before installing private packages.

```yaml
- name: Sign in to the Tiptap package registry
  env:
    TIPTAP_EMAIL: ${{ secrets.TIPTAP_EMAIL }}
    TIPTAP_CLI_PASSWORD: ${{ secrets.TIPTAP_CLI_PASSWORD }}
  run: npx --yes @tiptap/cli@latest login --email "$TIPTAP_EMAIL" --registry-only --write-config
```

#### Options

```bash
Usage: @tiptap/cli@latest login [options]

Options:
  -e, --email <email>          Your account email
  -p, --password <password>    Deprecated. Enter your password when the CLI asks
  --registry-only              Authenticate private package downloads
  --write-config               Write the auth token to your package manager config
  -c, --cwd <cwd>              The working directory (defaults to current directory)
```

### `logout`

Log out from your Tiptap Cloud account.

```bash
npx @tiptap/cli@latest logout
```

### `status`

Review your Tiptap Cloud authentication status and active plans.

```bash
npx @tiptap/cli@latest status
```

#### Options

```bash
Usage: @tiptap/cli@latest status [options]

Options:
  -c, --cwd <cwd>              The working directory (defaults to current directory)
```

### `license`

Run `license` to read the Tiptap Pro license information and check whether you've accepted it on this machine.

```bash
npx @tiptap/cli@latest license
```

To clear your local acceptance, run `license forget me` and confirm the prompt. The CLI will ask you to accept the license the next time you install a paid item.

```bash
npx @tiptap/cli@latest license forget me
```
