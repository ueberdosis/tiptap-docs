## Overview

[Tiptap Pages](/pages/getting-started/overview) controls the page layout. The editor uses the [DOCX importer](/conversion/import/docx/editor-extension) to open Word files, the [DOCX exporter](/conversion/export/docx/editor-extension) to download them, and the [PDF exporter](/conversion/export/pdf/editor-extension) for previews and PDF downloads. [Tiptap Collaboration](/collaboration/getting-started/overview) synchronizes the document between participants.

## Installation

Use a Next.js App Router project. The supplied routes use Next.js navigation and load the editor in the browser. Sign in with a Tiptap account that has access to the template.

```bash
npx @tiptap/cli@latest login
```

### For existing projects

```bash
npx @tiptap/cli@latest add docx
```

### For new projects

```bash
npx @tiptap/cli@latest init docx
```

Choose Next.js when the CLI asks which framework to use.

### Styling

The template uses SCSS. Load its shared style imports in your application's global stylesheet. If the installed template references local files under `/fonts/carlito/` or `/images/`, provide the files in `public/` or change those URLs to your own assets. The installed `SETUP.md` lists the font weights and sample logo. [Style setup](/ui-components/getting-started/style)

### Environment variables

The editor requires a Collaboration room. Set the following variables in your Next.js project.

| Variable | Value |
| --- | --- |
| `NEXT_PUBLIC_TIPTAP_COLLAB_APP_ID` | Your Collaboration app ID. |
| `NEXT_PUBLIC_TIPTAP_COLLAB_TOKEN` | An example Collaboration JWT for local development. |
| `NEXT_PUBLIC_TIPTAP_COLLAB_DOC_PREFIX` | An optional prefix for document names. |
| `NEXT_PUBLIC_USE_JWT_TOKEN_API_ENDPOINT` | Set to `true` to fetch Collaboration tokens from your server. Leave unset for the local example token. |
| `TIPTAP_COLLAB_SECRET` | Your server-side signing secret for Collaboration tokens, used by `POST /api/collaboration`. |
| `NEXT_PUBLIC_TIPTAP_CONVERSION_APP_ID` | Your Conversion app ID for DOCX import, PDF downloads, and previews. |
| `TIPTAP_CONVERSION_SECRET` | Your server-side signing secret for Conversion tokens. |
| `NEXT_PUBLIC_TIPTAP_DOCX_IMAGE_UPLOAD_URL` | An optional absolute URL where the Conversion service can upload embedded images from an imported Word document. |

### Token routes

Implement these routes in your app. Check the user's session and access before signing each short-lived JWT. Return JSON with a `token` field. Keep both signing secrets on the server. [JWT authentication](/guides/authentication)

- `POST /api/collaboration` supplies the Collaboration token when `NEXT_PUBLIC_USE_JWT_TOKEN_API_ENDPOINT` is set.
- `GET /api/convert/token` supplies the Conversion token for DOCX import, PDF download, and the preview.

To keep embedded DOCX images, configure the optional upload URL. The service posts the image bytes to that URL with a bearer token. Verify the token, store the bytes, and return JSON with an absolute `url`. [DOCX image handling](/conversion/import/docx/image-handling)

## Usage

To add the editor to another Next.js page, import the installed client wrapper. It loads the editor in the browser and supplies the sample document. Use a stable room ID for each document.

```tsx
import { PageDocxClientPage } from '@/components/tiptap-templates/page-docx/page-docx-client'

export default function Page() {
  return <PageDocxClientPage room="contract-123" />
}
```

### Routing

Open `/docx` to start a room. The route redirects to `/docx/<room-id>`. Reopen that URL to continue editing, or share it with another user who has access to the document.

### Props

You can pass these props to `PageDocxEditor` inside `page-docx-client.tsx`.

| Prop              | Type              | Description                                                                                                                                                                               |
| ----------------- | ----------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `room`            | `string`          | Collaboration room ID. Each document should use a unique room. If omitted, a random room is created.                                                                                      |
| `initialContent`  | `JSONContent`     | Tiptap JSON seeded into the document the first time the room is opened. The template ships a sample NDA. Seeding is guarded so it never duplicates.                                       |
| `invertMenu`      | `boolean`         | Renders the toolbar at the bottom of the screen instead of the top. Can also be toggled with the `?menu=invert` query parameter. Defaults to `false`.                                     |
| `settingsStorage` | `SettingsStorage` | Persistence backend for sidebar UI settings (page format, header/footer settings, preview toggle). Defaults to a localStorage adapter. See [Settings persistence](#settings-persistence). |

## Features

The toolbar includes document import and export, text formatting, links, lists, tables, and image controls. The font picker uses Carlito by default, and the DOCX exporter embeds the regular font when it can load the font file. You can choose decimal, alphabetic, or Roman numbering for ordered lists. The sidebar controls page layout. The preview can open alongside the document or fill the screen on mobile.

### Pagination and page format

Use the document settings sidebar to set the paper size, orientation, margins, page gap, and background color. Choose a preset such as A4 or US Letter, or enter a custom width and height. The sidebar accepts `cm`, `in`, `mm`, and `px`.

### Headers and footers

Double-click a header or footer, or open **Headers & footers** in the sidebar. You can edit the first page separately, alternate odd and even pages, adjust the distance to the page edge, and insert current-page and total-page fields. The sidebar lets you switch between the active variants. The sample footer uses `{page}` and `{pages}` fields. The DOCX exporter turns these into Word page-number fields.

### Footnotes

Insert a footnote to place a numbered reference in the body and a note above the page footer. The editor also supports endnotes. The DOCX exporter includes the notes in the Word file.

### Page breaks

Insert a break from the toolbar or press `Mod-Enter`. The editor moves the following paragraph to the next page.

### Zoom

Choose a zoom preset from 40% to 200%, or select **Fit to page** to scale the document to the available width.

### Export and preview

- **Import DOCX** opens a Word file through the Conversion API.
- **Download DOCX** creates a Word file in the browser. The file includes page settings, numbering, headers, footers, and notes.
- **Download PDF** and the side-by-side preview use the Conversion API. Open the preview to see the PDF and select **Update preview** after editing.

### Real-time collaboration

The body, header and footer variants, and notes share a Collaboration room. Presence carets show collaborators' positions in the body. The editor waits for the provider to sync before it seeds a new room with the sample content.

### Settings persistence

Sidebar UI settings (page format, header/footer settings, and the preview toggle) are persisted per room. By default they are stored in `localStorage` under room-scoped keys. The backend is pluggable via the `settingsStorage` prop and a `SettingsStorage` adapter interface:

```ts
interface SettingsStorage {
  get<T = unknown>(key: string): T | null
  set<T = unknown>(key: string, value: T): void
  remove(key: string): void
}
```

Pass `noopStorage` to disable persistence entirely, or implement the interface to persist settings to your own backend (for example, a database keyed by document).

## Component breakdown

The CLI installs the template-specific files under `components/tiptap-templates/page-docx/`. It installs shared controls under the UI component aliases.

### Template components

- `page-docx-client` loads the editor in the browser. `page-docx-editor` configures the editor instance, providers, and layout.
- `page-docx-main-toolbar` and `page-docx-file-menu` expose editing and file actions.
- `page-docx-header-footer-overlay` opens the editor for a header or footer. `page-docx-pdf-preview` displays the PDF.
- `sidebar/` contains document settings and the controls for header and footer variants.

### Hooks

- `hooks/use-page-editor-state` reads the current page and editor from Pages storage.
- `hooks/use-zoom` and `hooks/use-auto-export` manage the zoom level and preview updates.
- `hooks/use-page-docx-file-actions` and `hooks/use-page-docx-export` handle document import and downloads.

### Lib

- `lib/page-docx-utils` and `lib/page-docx-pages` convert units and synchronize page settings.
- `lib/page-docx-export` and `lib/page-docx-fonts` configure export styles and fonts.
- `lib/settings-storage` and `lib/settings-storage-context` provide the persistence adapter and React context.

### Extensions and workarounds

The template includes a page-number field with a DOCX adapter in `extensions/extension-page-token-highlight`. The files under `workaround/` handle caret placement around page breaks, header and footer focus, and scrolling to notes.

### Tiptap Pro extensions

- `@tiptap-pro/extension-pages`
- `@tiptap-pro/extension-convert-kit`
- `@tiptap-pro/extension-import-docx`
- `@tiptap-pro/extension-comments`
- `@tiptap-pro/extension-export-docx`
- `@tiptap-pro/extension-export-pdf`
- `@tiptap-pro/extension-pagebreak`
- `@tiptap-pro/provider`

### Reused UI components

The toolbar and sidebar reuse the open-source UI components, including `mark-button`, `list-button`, `heading-button` / `heading-dropdown-menu`, `text-button`, `font-size-dropdown-menu`, `line-spacing-dropdown-menu`, `text-align-dropdown-menu`, `color-text-popover`, and `link-popover`, plus the `button`, `card`, `combobox`, `dropdown-menu`, `popover`, `sidebar`, and `toolbar` primitives.
