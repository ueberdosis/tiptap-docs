## Quick start

```ts
import { Diagrams } from '@tiptap-pro/extension-diagrams'
import { d3Renderer } from '@tiptap-pro/extension-diagrams/d3'
import { echartsRenderer } from '@tiptap-pro/extension-diagrams/echarts'

Diagrams.configure({
  renderers: [echartsRenderer(), d3Renderer()],
  defaultRenderer: 'echarts',
})
```

The extension bundles no chart library. Each library is a peer dependency or a script you serve,
and you use it under its own license. To draw with a library that is not listed here, write a
[Renderer of your own](/diagrams/renderers/custom).

## Which Renderer to use

There are two kinds of Renderer. A chart Renderer draws charts, and you pass it in `renderers`.
A Diagram Renderer draws one diagram format, such as Mermaid or BPMN, and you pass it in
`diagramRenderers`. You can register several chart Renderers. Register one Diagram Renderer per
diagram format.

| Renderer                               | Draws                                                                                | Use it for                                                                 |
| -------------------------------------- | ------------------------------------------------------------------------------------ | -------------------------------------------------------------------------- |
| [ECharts](/diagrams/renderers/echarts) | Charts: every built-in type                                                          | The most chart types, and SVG files on a server                            |
| [D3](/diagrams/renderers/d3)           | Charts: most types, and sankey with `d3-sankey`                                      | Charts you change in code, and SVG files on a server with a DOM            |
| [Mermaid](/diagrams/renderers/mermaid) | Charts: pie, line, upright bar, sankey, radar, treemap. Diagrams: every Mermaid kind | The Mermaid look, for charts and diagrams alike                            |
| [Pele](/diagrams/renderers/pele)       | Diagrams: every Mermaid kind                                                         | Mermaid diagrams without an iframe, much smaller to load, also on a server |
| [draw.io](/diagrams/renderers/drawio)  | Diagrams: draw.io XML                                                                | Diagrams you draw and change in the draw.io editor                         |
| [BPMN](/diagrams/renderers/bpmn)       | Diagrams: BPMN 2.0 XML                                                               | Process models that BPMN tools read                                        |

Each Renderer's page lists the chart types or diagram kinds it draws, and its limits.

## Which Renderer draws a chart

A chart can name a Renderer by its id. You set it with
[`setChartRenderer`](/diagrams/charts/appearance#setchartrenderer). The extension then picks one of
the registered chart Renderers in this order:

1. The Renderer the chart names, if it is registered and draws the chart's type.
2. Otherwise the `defaultRenderer`, if it draws the type.
3. Otherwise the first registered Renderer that draws the type.

The chart's root element names the Renderer that drew it in `data-tt-chart-renderer`.

### When a Renderer declines a chart

A Renderer can decline a chart of a type it draws, through its `draws` function. For example, the
[Mermaid Renderer](/diagrams/renderers/mermaid) declines a bar chart with several series and a line chart
with line styles.

- **Another Renderer draws the type.** The next Renderer in the order above draws the chart.
- **No other Renderer draws the type.** The declining Renderer draws the chart after all.
- **The chart keeps its choice.** It still names the Renderer it named before.
- **An export with a `renderer` option** uses that Renderer as it is, even if it declines.

### When no Renderer draws the type

The chart shows what [`unavailable`](/diagrams/api-reference/options#unavailable) returns. Its data stays in the
document.

### When the Renderer changes

- **Only the drawing changes.** The Chart Data and the Chart Spec stay as they are.
- **Options for one Renderer** that a chart stores under `spec.renderer[id]` are ignored by the
  other Renderers.
- **Colors and fonts** come from the same `--tt-chart-*` custom properties for every Renderer, so
  charts look alike whichever library draws them. See [Styling](/diagrams/guides/styling).

A diagram goes to the first Diagram Renderer for its format that does not decline it. See
[Which Renderer draws a diagram](/diagrams/renderers/custom-diagrams#which-renderer-draws-a-diagram).

## Your own Renderer

A chart Renderer is an object with an id, the chart types it draws, `mount` to draw in the
editor, and `toSVG` or `toImage` to make files. It receives the Chart Data and the Chart Spec,
never the document. So it works with every way data gets into a chart.

- [Your own Renderer](/diagrams/renderers/custom) has a complete chart Renderer, its members and what it
  receives.
- [Chart types](/diagrams/renderers/custom-chart-types) adds a chart type.
- [A Diagram Renderer](/diagrams/renderers/custom-diagrams) draws a diagram format.
