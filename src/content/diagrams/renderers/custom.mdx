## A chart Renderer

This Renderer draws bar charts as plain SVG, with no library. It reads the colors from
`theme` and the size from `size`, and writes every label as text.

```ts
import type { ChartRenderer, ChartRenderInput } from '@tiptap-pro/extension-diagrams'

const SVG = 'http://www.w3.org/2000/svg'

function escapeXml(text: string): string {
  return text
    .replace(/&/g, '&amp;')
    .replace(/</g, '&lt;')
    .replace(/>/g, '&gt;')
    .replace(/"/g, '&quot;')
}

function barsSvg({ data, spec, theme, size }: ChartRenderInput): string {
  const series = data.columns.flatMap((column, index) =>
    column.role === 'series' ? [{ ...column, index }] : [],
  )
  const colors = spec.palette ?? theme.series
  const values = data.rows
    .flatMap((row) => series.map((column) => row[column.index]))
    .filter((cell): cell is number => typeof cell === 'number')
  const max = Math.max(1, ...values)
  const band = size.width / Math.max(1, data.rows.length)
  const bar = band / (series.length + 1)
  const plot = size.height - 24

  const bars = data.rows.flatMap((row, rowIndex) => [
    ...series.map((column, seriesIndex) => {
      const value = typeof row[column.index] === 'number' ? (row[column.index] as number) : 0
      const height = (value / max) * plot
      const x = rowIndex * band + bar * (seriesIndex + 0.5)
      return `<rect x="${x}" y="${plot - height}" width="${bar}" height="${height}" fill="${colors[seriesIndex % colors.length]}"/>`
    }),
    `<text x="${rowIndex * band + band / 2}" y="${size.height - 6}" text-anchor="middle" fill="${theme.labelColor}" font-family="${escapeXml(theme.fontFamily)}" font-size="${theme.fontSize}">${escapeXml(String(row[0] ?? ''))}</text>`,
  ])

  return `<svg xmlns="${SVG}" width="${size.width}" height="${size.height}" viewBox="0 0 ${size.width} ${size.height}">${bars.join('')}</svg>`
}

export const plainBarsRenderer: ChartRenderer = {
  id: 'plain-bars',
  label: 'Plain bars',
  types: ['bar'],
  // Leaves stacked bars to the next Renderer that draws bar charts
  draws: ({ spec }) => !spec.stacked,
  mount(target, input) {
    const draw = (next: ChartRenderInput) => {
      const svg = new DOMParser().parseFromString(barsSvg(next), 'image/svg+xml').documentElement
      target.replaceChildren(target.ownerDocument.importNode(svg, true))
    }
    draw(input)
    return { update: draw, destroy: () => target.replaceChildren() }
  },
  async toSVG(input) {
    return barsSvg(input)
  },
}
```

### Registering it

Register it next to the Renderers you already use:

```ts
import { Diagrams } from '@tiptap-pro/extension-diagrams'
import { echartsRenderer } from '@tiptap-pro/extension-diagrams/echarts'

Diagrams.configure({
  renderers: [echartsRenderer(), plainBarsRenderer],
})

editor.commands.setChartRenderer({ renderer: 'plain-bars' })
```

- A chart that names `plain-bars` is drawn by it.
- Every other chart keeps its Renderer.

### What to honor in the spec

What `mount`, `update`, `toSVG` and `toImage` receive is described in
[the Renderer overview](/diagrams/renderers/overview#writing-a-renderer).

| Spec field                  | What to draw                                                                                                                |
| --------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| `type`                      | Only the types in `types`. Return `false` from `draws` for a variant you cannot draw                                        |
| `palette`                   | Use it instead of `theme.series`                                                                                            |
| `stacked`                   | Stack the series of a bar or area chart                                                                                     |
| `orientation`               | `'horizontal'`: lay the bars of a bar chart on their side                                                                   |
| `axes.y.step`, `references` | Ticks at every step, and lines and bands at values. Decline through `draws` if you cannot draw them                         |
| `range`                     | `{ min, max }` of a gauge                                                                                                   |
| `legend`, `title`           | Show or hide the legend and the title                                                                                       |
| `series`                    | Line style, width, marker and smoothing per series of a line or area chart. Decline through `draws` if you cannot draw them |
| `renderer[id]`              | Options a chart stores for your Renderer only, under your `id`                                                              |

- `valueAxisScale` works out the axis for `axes.y.step` and `references`.
- `data` arrives with the columns the spec selected.
- `theme` holds resolved colors, also in a dark color scheme.
- `toSVG` and `toImage` receive the light colors unless the caller asked for `scheme: 'dark'`.

### Text in the picture

A double click renames a chart's text ([Text in the picture](/diagrams/charts/editing))
when the handle `mount` returns has `onTextDoubleClick`. It takes a listener and returns a
function that removes it. Call the listener while the double click is handled, with a
`ChartTextHit`:

| Field    | Type              | Description                                                                    |
| -------- | ----------------- | ------------------------------------------------------------------------------ |
| `target` | `ChartTextTarget` | Which text was hit, see below                                                  |
| `text`   | `string`          | The text as drawn                                                              |
| `box`    | `ChartTextBox`    | `x`, `y`, `width`, `height` in the page's pixels, from `getBoundingClientRect` |

| Target                               | Text                                                       |
| ------------------------------------ | ---------------------------------------------------------- |
| `{ kind: 'title' }`                  | The title                                                  |
| `{ kind: 'axis', axis: 'x' \| 'y' }` | An axis title. `x` is the category axis, also on its side  |
| `{ kind: 'series', column }`         | A series name, by the column id in `input.data`            |
| `{ kind: 'category', row }`          | A category label or a pie part, by the row in `input.data` |

```ts
mount(target, input) {
  const svg = draw(input)
  target.append(svg)
  const listeners = new Set<(hit: ChartTextHit) => void>()
  svg.addEventListener('dblclick', event => {
    const title = event.target instanceof Element ? event.target.closest('.title') : null
    if (!title) return
    const { x, y, width, height } = title.getBoundingClientRect()
    const hit: ChartTextHit = {
      target: { kind: 'title' },
      text: title.textContent ?? '',
      box: { x, y, width, height },
    }
    listeners.forEach(listener => listener(hit))
  })
  return {
    update: next => {},
    destroy: () => svg.remove(),
    onTextDoubleClick: listener => {
      listeners.add(listener)
      return () => listeners.delete(listener)
    },
  }
}
```

- **Without `onTextDoubleClick`** a double click opens nothing.
- **The editor decides** whether a field opens: not in a read-only editor, and not for a series
  or a category of read-only data.

## A Renderer that draws on a canvas

Draw the chart with Chart.js, switch its type, and download it as PNG or SVG:

<CodeDemo isPro path="/Extensions/DiagramsChartJs" />

A library that draws pixels, such as Chart.js, has no SVG to give. Its Renderer has `toImage`
instead of `toSVG` and returns a PNG at `input.size`:

```ts
import type { RasterChartRenderer } from '@tiptap-pro/extension-diagrams'
import { Chart, registerables } from 'chart.js'

Chart.register(...registerables)

export const chartJsRenderer: RasterChartRenderer = {
  id: 'chartjs',
  label: 'Chart.js',
  types: ['bar', 'line', 'pie', 'doughnut'],
  mount(target, input) {
    const canvas = document.createElement('canvas')
    target.replaceChildren(canvas)
    const chart = new Chart(canvas, toChartJsConfig(input))
    return {
      update: (next) => {
        const config = toChartJsConfig(next)
        chart.data = config.data
        chart.options = config.options
        chart.update('none')
      },
      destroy: () => chart.destroy(),
    }
  },
  toImage(input) {
    const canvas = document.createElement('canvas')
    canvas.width = input.size.width
    canvas.height = input.size.height
    const chart = new Chart(canvas, { ...toChartJsConfig(input), options: { animation: false } })
    return new Promise((resolve, reject) =>
      canvas.toBlob((blob) => {
        chart.destroy()
        blob ? resolve(blob) : reject(new Error('No picture.'))
      }, 'image/png'),
    )
  },
}
```

`toChartJsConfig` turns the Chart Data and Spec into a Chart.js configuration, in the colors of
`input.theme`. The demo has a complete one.

- **PNG, WebP, JPEG and Word** use the picture.
- **An SVG file** holds the picture, not shapes, and `export` returns `raster: true`.
- **The frame and the attribution** are added as for any Renderer.
- **Draw without animation** in `toImage`, and pass `responsive: false` with a fixed
  `devicePixelRatio`, so the picture has exactly the size it was asked for.
- **A server** has no canvas, so `toImage` runs only in a browser, or with a canvas library of
  your own.

## Rules of your Renderer

A chart library's licence may ask for a visible credit, or limit the files its pictures may
be exported to. A Renderer declares this in `rules`, and the extension applies it everywhere
the Renderer's pictures appear:

```ts
import type { DiagramRenderer } from '@tiptap-pro/extension-diagrams'

export const creditedRenderer: DiagramRenderer = {
  id: 'credited',
  label: 'Credited',
  formats: ['mermaid'],
  rules: {
    attribution: {
      label: 'Drawn with Example',
      href: 'https://example.com',
      logo: '<svg viewBox="0 0 16 16">…</svg>',
    },
    exports: ['svg', 'png', 'docx'],
  },
  async render(input) {
    // …
  },
}
```

| Rule          | Type                                                        | Description                                                      |
| ------------- | ----------------------------------------------------------- | ---------------------------------------------------------------- |
| `attribution` | `{ label: string, href: string, logo?: string }`            | A credit shown with every picture, described below               |
| `exports`     | `readonly ('svg' \| 'png' \| 'webp' \| 'jpeg' \| 'docx')[]` | The formats `export` may produce. Without the list, every format |

### What attribution does

- **In the editor** it is a link below the picture (`tiptap-chart-attribution`,
  `tiptap-flow-diagram-attribution`).
- **In every exported SVG, PNG, WebP, JPEG and Word picture** its label is drawn into the lower
  right corner.
- **`logo`** is standalone SVG markup, shown 16 pixels high.

### What exports does

- **Any other format** throws.
- **Without `docx`**, `exportDocx` leaves the diagram out with a note, and writes a chart as a
  native Word chart.

### Adding rules

Rules only grow.

- `withRendererRules(renderer, rules)` returns the Renderer with rules added.
- The `rendererRules` option adds rules by Renderer id.

```ts
import { Diagrams, withRendererRules } from '@tiptap-pro/extension-diagrams'

Diagrams.configure({
  renderers: [withRendererRules(plainBarsRenderer, { exports: ['svg', 'png'] })],
  rendererRules: {
    drawio: { attribution: { label: 'draw.io', href: 'https://www.drawio.com' } },
  },
})
```

- **An attribution the Renderer declares** stays.
- **An attribution you add** applies only where the Renderer declares none.
- **The allowed formats** are those both lists allow.
- **`editor.storage.diagrams.rulesFor(renderer)`** returns the rules in effect.
- **The built-in Renderers** for ECharts, d3, Mermaid and draw.io declare no attribution and
  allow every format.

## Register your own chart type

A chart type is an id in `spec.type`. Register one with the `chartTypes` option, and list it
in the `types` of the Renderer that draws it.

### Quick start

```ts
import { Diagrams, chartLinks, type ChartRenderer } from '@tiptap-pro/extension-diagrams'

const chordRenderer: ChartRenderer = {
  id: 'chord',
  label: 'Chord',
  types: ['chord'],
  mount(target, input) {
    // chartLinks(input.data) gives { nodes, links }, read the way sankey and network read them
  },
  async toSVG(input) {
    // ...
  },
}

Diagrams.configure({
  renderers: [echartsRenderer(), chordRenderer],
  chartTypes: [
    {
      id: 'chord',
      label: 'Chord',
      shape: 'graph',
      word: 'image',
      description: 'Flows between groups drawn around a circle: from, to and how much.',
    },
  ],
})
```

### Fields of a chart type

| Field         | Type                                                                        | Description                                                                                                          |
| ------------- | --------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| `id`          | `string`                                                                    | What the chart stores in `spec.type`: letters, digits, `_` and `-`, at most 64 characters                            |
| `label`       | `string`                                                                    | For a menu                                                                                                           |
| `shape`       | `'cartesian' \| 'radial' \| 'single' \| 'hierarchy' \| 'matrix' \| 'graph'` | How the type reads its rows. The Quick Input shows example rows of that shape                                        |
| `word`        | `'chart' \| 'table' \| 'image'`                                             | `'image'`: a Word document gets a picture of the chart. Only the built-in types are written as Word charts or tables |
| `description` | `string`                                                                    | Optional. One sentence for a model choosing a type                                                                   |

### Where a registered type appears

- **The Quick Input:** it can be typed after `:::`.
- **`setDiagramInputType`** can choose it.
- **A model** is offered it by the tools and by `describeCapabilities()`.
- **An entry with the id of a built-in type** replaces that type's label and description.

### Reading rows like the built-in types

| Function               | Reads rows the way                | Returns                                                                                   |
| ---------------------- | --------------------------------- | ----------------------------------------------------------------------------------------- |
| `chartHierarchy(data)` | the built-in `hierarchy` types do | A tree of `{ name, path, value, total, children }`, from paths such as `Europe / Germany` |
| `chartLinks(data)`     | the built-in `graph` types do     | `{ nodes, links }`, one link per row                                                      |

## A Diagram Renderer of your own

A Diagram Renderer turns the source text of one format into an SVG string. The editor shows
the result as an image, so its SVG never runs script in the page.

### Quick start

This one sends Mermaid source to a rendering service you host and returns what it answers:

```ts
import type { DiagramRenderer } from '@tiptap-pro/extension-diagrams'

export function serviceDiagramRenderer(endpoint: string): DiagramRenderer {
  return {
    id: 'mermaid-service',
    label: 'Mermaid (service)',
    formats: ['mermaid'],
    async render({ source, theme, raster }) {
      const response = await fetch(endpoint, {
        method: 'POST',
        headers: { 'content-type': 'application/json' },
        body: JSON.stringify({ source, theme, htmlLabels: !raster }),
      })
      if (!response.ok) throw new Error(`The diagram service answered ${response.status}`)
      const svg = await response.text()
      const root = new DOMParser().parseFromString(svg, 'image/svg+xml').documentElement
      const width = Number.parseFloat(root.getAttribute('width') ?? '') || 600
      const height = Number.parseFloat(root.getAttribute('height') ?? '') || 400
      return { svg, width, height }
    },
  }
}
```

```ts
Diagrams.configure({
  diagramRenderers: [serviceDiagramRenderer('https://diagrams.example.com/mermaid/svg')],
})
```

### Members

A Diagram Renderer is `{ id, label?, formats, draws?, render, editing? }`.

| Member    | Type                                         | Description                                                                                                                      |
| --------- | -------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `id`      | `string`                                     | Names the Renderer                                                                                                               |
| `label`   | `string`                                     | Optional. For a menu                                                                                                             |
| `formats` | `readonly FlowDiagramFormat[]`               | The diagram formats it draws                                                                                                     |
| `draws`   | `(source: string) => boolean`                | Optional. Whether it draws this source, such as only some Mermaid kinds. Without it, every source                                |
| `render`  | `(input) => Promise<{ svg, width, height }>` | Draws the source, described below                                                                                                |
| `editing` | `DiagramEditing`                             | Optional. Finds text and shapes in its pictures, see [Editing in the picture](/diagrams/renderers/custom#editing-in-the-picture) |

### Which Renderer draws a diagram

- **The first registered Diagram Renderer** whose `formats` include the diagram's format, and
  whose `draws` does not decline the source, draws the diagram.
- **A kind no Renderer draws** shows what [`unavailable`](/diagrams/api-reference/options#unavailable) returns,
  with the reason `'unsupported-kind'`. The source stays in the document.
- **A format of your own** needs no other registration. See
  [Other formats](/diagrams/flow-diagrams/formats#other-formats).

### What render receives

| Input    | Type                | Description                                                                                                                               |
| -------- | ------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| `format` | `FlowDiagramFormat` | `mermaid`, `drawio`, `bpmn` or a format of your own, one of the Renderer's `formats`                                                      |
| `source` | `string`            | The diagram source text, as the document stores it                                                                                        |
| `theme`  | `DiagramTheme`      | Resolved colors and fonts, read from the `--tt-flow-diagram-*` custom properties ([Diagrams](/diagrams/api-reference/selectors#diagrams)) |
| `raster` | `boolean`           | `true` when the SVG becomes a PNG, a WebP, a JPEG or a picture in Word                                                                    |

When `raster` is `true`, labels must be SVG text: the SVG must hold no `foreignObject`, which
the browser does not let a canvas export.

### What render returns

| Result            | Type     | Description                                           |
| ----------------- | -------- | ----------------------------------------------------- |
| `svg`             | `string` | A standalone SVG string with a `width` and a `height` |
| `width`, `height` | `number` | The size of the drawing in pixels                     |

### Editing in the picture

A double click on a text and dragging a shape need to know where things are in the picture. Only
the Renderer knows its markup, so it says so through `editing`. Every function receives the SVG
it returned, as a string, and the diagram's source.

| Member          | Signature                                         | Without it                                            |
| --------------- | ------------------------------------------------- | ----------------------------------------------------- |
| `labelAt`       | `(svg, point, source) => DiagramLabelHit \| null` | A double click opens nothing                          |
| `nodeAt`        | `(svg, point, source) => DiagramNodeHit \| null`  | No shape can be dragged                               |
| `movePositions` | `(svg, positions, source) => string \| null`      | No shape can be dragged; stored offsets are not drawn |

- **`point`** is in the SVG's own units, through its `viewBox`.
- **`DiagramLabelHit`** is `{ target, label, box }`. `target` names the text in the source, such
  as `{ kind: 'node', id: 'A' }`, and the extension writes the new text there.
- **`DiagramNodeHit`** is `{ id, label, box }`, `id` as the source names the shape.
- **`movePositions`** returns the picture with each shape moved by its offset, `null` when
  nothing moved.
- **Return `null`** for a kind your Renderer does not handle.

A Renderer that draws with mermaid.js reuses the built-in one:

```ts
import { mermaidDiagramEditing } from '@tiptap-pro/extension-diagrams/mermaid'

const renderer = { id: 'my-mermaid', formats: ['mermaid'], render, editing: mermaidDiagramEditing }
```

### Keeping the page safe

- **The SVG** is shown in an `<img>`, so scripts and outside resources in it never run or load
  in the editor.
- **The source** must not be evaluated in the page. Render it on a server or in a sandboxed
  iframe, as the built-in Renderers do.
- **A library that only parses text** and needs no DOM can draw in a Web Worker instead, as
  the Pele Renderer does.
