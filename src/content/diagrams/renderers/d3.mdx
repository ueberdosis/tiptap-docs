## Quick start

Install D3 (`^7.9.0`) and register the Renderer:

```bash
npm install d3
```

```ts
import { Diagrams } from '@tiptap-pro/extension-diagrams'
import { d3Renderer } from '@tiptap-pro/extension-diagrams/d3'

Diagrams.configure({ renderers: [d3Renderer()] })
```

[Install Diagrams](/diagrams/getting-started/install) has the complete editor around these lines.

## Chart types

The D3 Renderer draws line, bar, area, scatter, pie, doughnut, radar, combo, tree and network
charts, and [sankey charts](/diagrams/renderers/d3#sankey-charts). It does not draw matrix, funnel, gauge or treemap.

- **Network** is laid out the same way every time for the same data.
- **`orientation: 'horizontal'`** lays bars on their side, except in a combo chart.

It draws every field of [series line styles](/diagrams/charts/appearance#series-line-styles),
[axes](/diagrams/charts/axes) and [reference lines](/diagrams/charts/references), and renames a text
on a double click ([Editing in the chart](/diagrams/charts/editing)).

## Options

| Option           | Type                           | Default | Description                                                                                      |
| ---------------- | ------------------------------ | ------- | ------------------------------------------------------------------------------------------------ |
| `id`             | `string`                       | `'d3'`  | The id charts store                                                                              |
| `label`          | `string`                       | `'d3'`  | The name for a menu                                                                              |
| `customizers`    | `Record<string, D3Customizer>` | None    | [Customizers](/diagrams/renderers/d3#customizers) by name                                                              |
| `measureText`    | `(text, fontSize) => number`   | None    | A label's width in pixels, for exact layout. Without it, estimated from the number of characters |
| `createDocument` | `() => Document`               | None    | The `Document` for `toSVG` without a global one                                                  |
| `sankey`         | the `d3-sankey` module         | None    | Draws sankey charts                                                                              |

## Sankey charts

Install `d3-sankey` (`^0.12.3`) and pass it as `sankey`. Without it, the D3 Renderer does not draw
sankey charts: another registered Renderer that draws them does, and with none a sankey chart
shows [no picture](/diagrams/renderers/overview#when-no-renderer-draws-the-type).

```ts
import * as sankey from 'd3-sankey'

d3Renderer({ sankey })
```

## Customizers

A customizer is a function you register under a name, which a chart refers to:

```ts
d3Renderer({
  customizers: {
    highlightMax(svg, { data }) {
      // change the drawn SVG element: add marks, reorder, restyle
    },
  },
})

editor.commands.updateChartSpec({ spec: { renderer: { d3: { customizer: 'highlightMax' } } } })
```

It gets the drawn `SVGSVGElement` and the [render input](/diagrams/renderers/custom#what-a-renderer-receives)
after every draw, in the editor and in exports, and returns nothing. The document stores only the name, so a chart naming a customizer this
editor lacks is drawn without one.

## Export and servers

On a server, call `toSVG` as the [ECharts Renderer](/diagrams/renderers/echarts#export-and-servers)
shows, and pass `createDocument`, such as from the DOM library linkedom:

```ts
import { parseHTML } from 'linkedom'

d3Renderer({
  createDocument: () => parseHTML('<!doctype html><html><body></body></html>').document,
})
```

Without it, `toSVG` throws "The d3 Renderer needs `createDocument` to export without a browser."
