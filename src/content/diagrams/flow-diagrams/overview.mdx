A diagram shows steps, states or things and the links between them, such as a flowchart, a
sequence diagram or a mind map. You write it as text, and the extension draws it. The
`flowDiagram` node stores that text, called the source, in one of three formats:

- Mermaid text, for a flowchart, a sequence diagram, a state machine, a class or entity
  relationship diagram, a Gantt chart, a mind map, a timeline, a Git graph and
  [every other Mermaid kind](/diagrams/flow-diagrams/overview#mermaid-kinds).
- draw.io XML, for a diagram drawn with shapes in the draw.io editor.
- BPMN XML, for a business process model.

## Quick start

Install the package and mermaid.js, the library that draws Mermaid diagrams:

```bash
npm install @tiptap-pro/extension-diagrams mermaid
```

Then register a Diagram Renderer for Mermaid and insert a first diagram:

```ts
import { Editor } from '@tiptap/core'
import StarterKit from '@tiptap/starter-kit'
import { Diagrams, chartStyleRules, flowDiagramStyleRules } from '@tiptap-pro/extension-diagrams'
import { mermaidDiagramRenderer } from '@tiptap-pro/extension-diagrams/mermaid'
import rendererUrl from '@tiptap-pro/extension-diagrams/mermaid-renderer?url&no-inline'
import mermaidUrl from 'mermaid/dist/mermaid.min.js?url'

const style = document.createElement('style')
style.textContent = chartStyleRules() + flowDiagramStyleRules()
document.head.append(style)

const editor = new Editor({
  element: document.querySelector('#editor'),
  extensions: [
    StarterKit,
    Diagrams.configure({
      diagramRenderers: [mermaidDiagramRenderer({ mermaidUrl, rendererUrl })],
    }),
  ],
})

editor.commands.insertFlowDiagram({
  source: 'flowchart LR\n  A[Order] --> B{Paid?}\n  B -->|yes| C[Ship]',
  title: 'How an order moves',
})
```

A Diagram Renderer draws diagrams with one library, as a [Renderer](/diagrams/renderers/overview) draws
charts. You pass it in the `diagramRenderers` option.

mermaid.js draws in a sandboxed iframe. It loads two files there: `mermaidUrl` is mermaid.js
itself, and `rendererUrl` is the script that draws inside the iframe. Both must be URLs of
files.

The `?url` and `?url&no-inline` suffixes are Vite imports. `?url` gives you the URL of the file.
`no-inline` keeps Vite from turning a small file into a `data:` URL, which the iframe cannot
load. With another bundler, serve both files yourself and pass their URLs.

Mermaid charts and Mermaid diagrams share one iframe. See [Mermaid](/diagrams/renderers/mermaid).

## Mermaid kinds

The first line of Mermaid source names its kind, such as `flowchart` or `sequenceDiagram`. A
Mermaid diagram can be any kind that Mermaid 11.17 knows, except five kinds that become
[charts](/diagrams/flow-diagrams/overview#diagram-or-chart). `MERMAID_DIAGRAM_KINDS` lists the kinds, and
`mermaidDiagramKind(source)` returns the kind of a source.

| Kind            | First line                                                                       |
| --------------- | -------------------------------------------------------------------------------- |
| `flowchart`     | `flowchart`, `graph`                                                             |
| `sequence`      | `sequenceDiagram`                                                                |
| `state`         | `stateDiagram-v2`, `stateDiagram`                                                |
| `class`         | `classDiagram`, `classDiagram-v2`                                                |
| `er`            | `erDiagram`                                                                      |
| `journey`       | `journey`                                                                        |
| `gantt`         | `gantt`                                                                          |
| `mindmap`       | `mindmap`                                                                        |
| `timeline`      | `timeline`                                                                       |
| `quadrant`      | `quadrantChart`                                                                  |
| `git`           | `gitGraph`                                                                       |
| `kanban`        | `kanban`                                                                         |
| `architecture`  | `architecture-beta`, `architecture`                                              |
| `block`         | `block-beta`, `block`                                                            |
| `c4`            | `C4Context`, `C4Container`, `C4Component`, `C4Dynamic`, `C4Deployment`           |
| `requirement`   | `requirementDiagram`, `requirement`                                              |
| `packet`        | `packet-beta`, `packet`                                                          |
| `venn`          | `venn-beta`                                                                      |
| `ishikawa`      | `ishikawa-beta`, `ishikawa`                                                      |
| `treeView`      | `treeView-beta`                                                                  |
| `wardley`       | `wardley-beta`                                                                   |
| `cynefin`       | `cynefin-beta`                                                                   |
| `swimlane`      | `swimlane-beta`                                                                  |
| `railroad`      | `railroad-beta`, `railroad-ebnf-beta`, `railroad-abnf-beta`, `railroad-peg-beta` |
| `eventModeling` | `eventmodeling`                                                                  |

The Diagram Renderer decides which kinds are drawn. Both Diagram Renderers for Mermaid, the one
for mermaid.js and the one for [Pele](/diagrams/renderers/pele), draw every kind in this list.

A kind that no registered Diagram Renderer draws shows what
[`unavailable`](/diagrams/api-reference/options#unavailable) returns, with the reason `'unsupported-kind'`. Its
source stays in the document.

You can change the text of some kinds right in the diagram. [Editing in the diagram](/diagrams/flow-diagrams/editing)
lists them. The other kinds are only shown.

## Diagram or chart

Mermaid `pie`, `xychart`, `sankey`, `radar` and `treemap` are charts. They become a `chart` node
with data you can edit. See [`importMermaidChart`](/diagrams/charts/overview#importmermaidchart). Every
other kind in [the list](/diagrams/flow-diagrams/overview#mermaid-kinds) becomes a diagram.

`insertFlowDiagram` and `updateFlowDiagram` return `false` for chart source and for a kind that
is not in the list, such as `zenuml`. Empty source is allowed, for a diagram you still have to
write.

## How a diagram is stored

| Attribute     | Content                                                                          |
| ------------- | -------------------------------------------------------------------------------- |
| `format`      | `'mermaid'`, `'drawio'`, `'bpmn'` or the id of a format a Diagram Renderer draws |
| `source`      | The Mermaid text, at most 50,000 characters, or the XML                          |
| `title`       | Shown as a caption below the diagram, or `null`                                  |
| `description` | Alt text and accessible description, or `null`                                   |
| `view`        | `'diagram'` shows the drawn diagram, `'code'` shows the source                   |
| `options`     | Settings beyond the source, in the table below. Anything else is kept as it is   |

| Key in `options` | Content                                                                                         |
| ---------------- | ----------------------------------------------------------------------------------------------- |
| `size`           | The diagram's size, see [setDiagramSize](/diagrams/guides/size-and-view#setdiagramsize)         |
| `link`           | The table the diagram is drawn from                                                             |
| `positions`      | The offsets of moved shapes, see [Moving shapes](/diagrams/flow-diagrams/editing#moving-shapes) |

The document never stores the drawn diagram, its size on screen or its loading state.

### Source is data

The source is data. It never runs as code in your app's web page. When a diagram is written, the
extension removes:

- `%%{init: …}%%` directives,
- the `config` of a frontmatter block, so a document cannot change how Mermaid runs.

A `title` in the frontmatter becomes the diagram's title, unless you give one. The colors come
from your page's CSS, not from the source.

### In HTML and plain text

In HTML, a diagram is a `<figure data-type="flow-diagram">`. It holds its source in
`<pre><code class="language-mermaid">` and its title in a `<figcaption>`. A draw.io diagram uses
`language-drawio`, and a BPMN diagram uses `language-bpmn`.

An HTML or Markdown export made without the extension keeps the source as a code block. If you
paste that HTML into an editor that has the extension, you get the diagram back.

As plain text, a Mermaid diagram is `[diagram: title]` followed by its source. A diagram in any
other format is only `[diagram: title]`, or `[diagram]` without a title.

## Changing a diagram

You change a diagram with a [command](/diagrams/flow-diagrams/overview#commands):

```ts
editor.commands.updateFlowDiagram({ source: 'sequenceDiagram\n  A->>B: Hello' })
editor.commands.setFlowDiagramView({ view: 'code' })
```

A form of your own can call `updateFlowDiagram` on every input, while someone types. Each call is
one undo step.

The diagram is drawn again after every change. When a drawing finishes after a newer change, it
is dropped. Mermaid source with a syntax error shows the error state and its message until the
source is valid again.

### Diagram or source for every diagram

Each diagram has its own view. To switch the whole document at once, as the Mermaid demo does,
call `setFlowDiagramView` for every diagram in one chain:

```ts
const chain = editor.chain()
for (const { pos } of editor.storage.diagrams.listDiagrams()) {
  chain.setFlowDiagramView({ pos, view: 'code' })
}
chain.run()
```

## Listing, zooming and exporting diagrams

### Listing diagrams

`editor.storage.diagrams.listDiagrams()` returns every diagram with:

| Field      | Content                                                                                           |
| ---------- | ------------------------------------------------------------------------------------------------- |
| `pos`      | Its position                                                                                      |
| Attributes | Its attributes                                                                                    |
| `kind`     | The kind of Mermaid diagram, or `null` when the source is empty, not a kind that is drawn, or XML |
| `drawable` | Whether a Diagram Renderer for its format can draw the source                                     |

### Zoom and maximize

Zoom and maximize work on a diagram as on a chart. `setZoom`, `getZoom`, `setMaximized` and
`getMaximized` take its position. See [Size and view](/diagrams/guides/size-and-view).

### Export

You export diagrams as you export charts. [Export](/diagrams/export) has the options and what comes
back.

- `export({ pos })` draws a diagram as an SVG, PNG, WebP or JPEG file.
- `exportAll()` includes diagrams, in document order.
- `exportDocx()` puts a diagram into the Word document as a PNG image, with its title as caption.
  See [Word](/diagrams/export#word).

The mermaid.js, draw.io and BPMN Diagram Renderers draw only in a browser. On a server, `export`
throws for a diagram, and `exportDocx` leaves the diagram out with a note. Pele's
[`renderPeleDiagram`](/diagrams/renderers/pele#on-a-server) can still draw Mermaid source on a
server.

## Commands

### insertFlowDiagram

Inserts a diagram at the selection, or at `pos`, and selects it unless `select` is `false`.

```ts
editor.commands.insertFlowDiagram({
  source: 'flowchart LR\n  order[Order placed] --> ship[Shipped]',
  title: 'Order flow',
})
```

| Option        | Type             | Description                                                                                                         |
| ------------- | ---------------- | ------------------------------------------------------------------------------------------------------------------- |
| `source`      | `string`         | Mermaid source, draw.io XML with `format: 'drawio'`, or BPMN 2.0 XML with `format: 'bpmn'`. Empty source is allowed |
| `format`      | `string`         | `'mermaid'` (default), `'drawio'`, `'bpmn'`, or another format when a registered Diagram Renderer lists it          |
| `title`       | `string \| null` | The diagram's title                                                                                                 |
| `description` | `string \| null` | Alt text and accessible description                                                                                 |
| `pos`         | `number`         | The position to insert at. Defaults to the selection                                                                |
| `select`      | `boolean`        | `false` leaves the selection where it is. Default `true`                                                            |

An empty paragraph at the selection is replaced. When you paste Mermaid diagram source, draw.io
XML or BPMN XML, the extension calls this command. See [Pasting](/diagrams/data/pasting).

Returns `false` for Mermaid chart source (`pie`, `xychart`, `sankey`, `radar`, `treemap`), for a
kind not in [the list](/diagrams/flow-diagrams/overview#mermaid-kinds), and, with `format: 'drawio'` or `'bpmn'`, for source that
is not that XML.

### updateFlowDiagram

Changes the source, the format, the title or the description of the selected diagram, or the one
at `pos`. A field you leave out keeps its value.

```ts
editor.commands.updateFlowDiagram({ title: 'Order flow, revised' })
```

| Option        | Type             | Description                                                                                           |
| ------------- | ---------------- | ----------------------------------------------------------------------------------------------------- |
| `source`      | `string`         | The new source. On a diagram drawn from a table, the diagram keeps it and no longer follows the table |
| `format`      | `string`         | The new format. Needs `source` in that format                                                         |
| `title`       | `string \| null` | The new title. `null` removes it                                                                      |
| `description` | `string \| null` | The new description. `null` removes it                                                                |
| `pos`         | `number`         | The diagram's position. Defaults to the selected diagram                                              |

Returns `false` and changes nothing when the new source is not a kind that is drawn in the
diagram's format, or when `format` changes without `source`.

### setFlowDiagramView

Shows the drawn diagram or its source.

```ts
editor.commands.setFlowDiagramView({ view: 'code' })
```

| Option | Type                  | Description                                                    |
| ------ | --------------------- | -------------------------------------------------------------- |
| `view` | `'diagram' \| 'code'` | `'diagram'` shows the drawn diagram, `'code'` shows the source |
| `pos`  | `number`              | The diagram's position. Defaults to the selected diagram       |

The view is stored in the document, so everyone who opens the document sees the same view.

### convertCodeBlockToDiagram

Replaces the code block at the selection, or at `pos`, with a diagram of its Mermaid source and
selects the diagram.

```ts
if (editor.can().convertCodeBlockToDiagram()) editor.commands.convertCodeBlockToDiagram()
```

| Option | Type     | Description                                                 |
| ------ | -------- | ----------------------------------------------------------- |
| `pos`  | `number` | A position inside the code block. Defaults to the selection |

Use `editor.can().convertCodeBlockToDiagram()` to decide whether to offer it. Mod-Enter in the
code block runs it too, unless [`codeBlockShortcut`](/diagrams/api-reference/options#codeblockshortcut) says
otherwise. See [Quick Input](/diagrams/data/quick-input).

Returns `false` for a code block that holds chart source or anything that is not a Mermaid
diagram.
