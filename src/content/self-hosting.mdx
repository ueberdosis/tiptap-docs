## Which one to use

| | Hocuspocus | Document Server |
| --- | --- | --- |
| What it is | Open source WebSocket server for Yjs, MIT licensed | Tiptap's managed document backend, in the cloud or on your own servers |
| Real-time sync and awareness | Yes | Yes, built on Hocuspocus |
| Storage | You add it with the [Database](/hocuspocus/server/extensions/database), [SQLite](/hocuspocus/server/extensions/sqlite), or [S3](/hocuspocus/server/extensions/s3) extension | Included |
| Authentication | You write an [`onAuthenticate` hook](/hocuspocus/guides/authentication) | [Tiptap authentication](/collaboration/getting-started/authenticate) with JWTs |
| Read and change documents from your backend | You build it | [REST API](/collaboration/documents/rest-api) with JSON, batch import, and [content injection](/collaboration/documents/content-injection) |
| Webhooks | [Webhook extension](/hocuspocus/server/extensions/webhook) | [Webhooks](/collaboration/core-concepts/webhooks) |
| Version history | You build it | [Snapshots](/collaboration/documents/snapshot) |
| Comments | Not available | [Comments](/comments/getting-started/overview) |
| Scaling and operations | You run it; scale with the [Redis extension](/hocuspocus/server/extensions/redis) | Run by Tiptap, or on your servers with Docker |
| Cost | Free | Paid [plan](https://tiptap.dev/pricing) |

**Choose Hocuspocus** when real-time sync is what you need, and your team wants to own storage, authentication, and operations.

**Choose the Document Server** when documents are central to your product, and you want storage, APIs, history, and comments without building them.

## Switch between them

The editor setup stays the same. Only the provider changes:

- `HocuspocusProvider` connects to a Hocuspocus server.
- `TiptapCollabProvider` connects to the Document Server.

To move documents to the Document Server, import them with the [batch import endpoint](/collaboration/documents/rest-api#batch-import-documents).
